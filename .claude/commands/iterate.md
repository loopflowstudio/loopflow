Explore the current implementation and consider alternatives, extensions, or refinements.

This is an interactive conversation—think out loud, ask questions, propose ideas. The goal is to surface opportunities, not to fix bugs or ship code.

## What to explore

**Alternative approaches.** Is there a simpler way to do this? A more idiomatic pattern? Something that would scale better or be easier to extend?

**Missing abstractions.** Are there concepts in the code that should be named? Patterns that repeat and could be unified?

**Edge cases and limitations.** What doesn't this handle? What assumptions might break? What would users expect that isn't there?

**Future directions.** What's the natural next step? What would make this more useful? What's awkward that could be smoothed out?

## How to engage

Ask clarifying questions. Propose specific alternatives with trade-offs. Reference the diff and existing code.

Don't make changes unless asked. This is for thinking, not doing.

If you see something that should definitely be fixed, note it—but the main goal is exploration, not review.
