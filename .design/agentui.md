# Agent UI: Live Output & Loop-Centric View

## What to build

Transform the bottom half of the worktree sidebar into a loop-focused view with live output streaming, treating worktrees as loop-generated artifacts rather than standalone entities.

## User's words

> "Focus on agent-centric rather than worktree-centric view, understanding most workspaces will have been generated by agents"

> "for now not creating or configuring so much, but add a button to do a merge squash, and streaming their output"

> "add a live output stream to the worktree view. this needs to be configured around lfd being running, but its time to start experimenting with that scenario"

## Current state

**Two agent systems exist:**

1. **Old system** (`Agent` model): Reads `~/.lf/agents/*.md` files with YAML frontmatter
2. **New system** (`Loop` model): Uses `~/.lf/lfd.db` tables (`loops`, `loop_runs`)

The new `lfd loop` system is the path forward. The AGENTS section in Maestro currently shows the old Agent model.

**WorktreeSidebar layout:**
- Worktree list (main content)
- PIPELINES section (beta, collapsed)
- AGENTS section (beta, collapsed) — uses old Agent model

**Branch naming (lfd loop):**
- `loop-<goal>` — accumulation branch (e.g., `loop-coverage`)
- `<goal>/001`, `<goal>/002` — iteration branches (ephemeral, deleted after merge)

**Existing infrastructure:**
- `LFDEventService` — socket to `~/.lf/lfd.sock`, subscribes to `session.*`, `output.line`, `loop.*`
- `AppState.liveOutputBySession` — maps session ID → output lines (capped at 1000)
- `AppState.activeSessionIds` — tracks running sessions
- `OutputPanel` — existing view for streaming output with color coding

## Data structures

```swift
// New Loop model for Maestro (mirrors Python lfd.models.Loop)
struct Loop: Identifiable, Hashable {
    let id: String
    let type: LoopType          // loop, flow, subscribe, schedule
    let goalName: String
    let repo: String
    let loopMain: String        // e.g., "loop-coverage"
    var status: LoopStatus      // idle, running, waiting, error
    var iteration: Int
    var prLimit: Int
    var mergeMode: MergeMode    // pr, land
    var pid: Int?
    var createdAt: Date

    // Computed
    var shortId: String { String(id.prefix(7)) }
    var currentRunId: String?   // Active loop_run for output tracking
}

enum LoopType: String, Codable {
    case loop, flow, subscribe, schedule
}

enum LoopStatus: String, Codable {
    case idle, running, waiting, error
}

enum MergeMode: String, Codable {
    case pr, land
}

// Track which loop owns which worktree
extension Worktree {
    var owningLoop: Loop? { ... }  // Infer from branch: loop-<goal> or <goal>/NNN
}
```

## UI changes

Clicking "Connect lfd" runs `lfd install` or opens setup instructions.

### Loop row states

| Status | Visual | Description |
|--------|--------|-------------|
| `running` | Green dot + spinner | Currently executing an iteration |
| `waiting` | Blue dot + "N PRs" | Paused at PR limit, has work to land |
| `idle` | Gray dot | Not running |
| `error` | Red dot | Last iteration failed |

### Live output panel

- Reuses `OutputPanel` styling: monospace, color-coded (→ blue, ✓ green, ✗ red)
- Compact: ~100-150px, shows last ~20 lines
- Auto-scrolls to bottom
- Header shows current step (e.g., "implement" or "polish")

### Squash & Land flow

Visible when `loop-<goal>` branch is ahead of main.

1. Button: "Squash & Land"
2. Confirm: "Land N commits from coverage loop to main?"
3. Execute:
   ```bash
   git checkout main
   git merge --squash loop-coverage
   git commit -m "loop(coverage): <generated summary>"
   git push
   ```
4. Notify user on success/failure

## Constraints

- **lfd disconnected state** — show "Connect lfd" button, not "lfd not connected". Give affordances, not status messages.
- **LOOPS replaces AGENTS** — delete old Agent model, AgentService, and `~/.lf/agents/` support
- **No loop creation/config in this scope** — users run `lfd loop <goal>` from terminal
- **Output buffering** — reuse existing 1000-line cap per session in AppState
- **Read from lfd.db directly** — don't add new socket methods, just query SQLite

## Implementation notes

**LoopService reads from SQLite:**
```swift
// Direct DB read, no socket call needed
func listLoops(repo: URL) async throws -> [Loop] {
    let db = try Connection("~/.lf/lfd.db")
    // SELECT * FROM loops WHERE repo = ?
}
```

**Output tracking:** Loop iterations use `loop_runs.id` as the session ID for output. The collector already sends `output.line` events with this ID.

**Hiding iteration worktrees:** Filter worktrees where branch matches `<goal>/\d{3}` pattern — these are ephemeral loop iterations.
