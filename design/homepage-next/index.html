Your agent can drive it.

Everything in Loopflow is an lf command, so the coding agent you already talk to can file Tasks, run them through your workflow, steer them and land them. One line teaches it how.

Then you can just ask it: “Split the auth cleanup into Tasks and run them with lf.”

lf: the workflow CLI for shipping software with coding agents.

Underneath Loopflow’s work-centered API is lf: a universal interface for agent sessions across providers, and the software engineering process between the sessions.

$ lf wt create cpu-pods       # a worktree and a branch

$ lf --machine mini \         # where it runs
     --account claude=you@ \  # whose login pays
     -a claude:opus \         # which agent and model
     --wt cpu-pods \          # in which worktree
     --docs docs/runpod.md \  # what it reads first
     -b \                     # headless, or -i to talk
     graph pursue             # Skills in sequence: a Graph

$ lf pr open                  # a draft PR, opened for you
$ lf land --wait-and-fix      # merge when checks pass; fix if not

$ lf account
  claude  you@      78% left
  claude  work@     21% left
  codex   you@      52% left

$ lf usage --wt cpu-pods
  3 sessions · 2 agents · 412k tokens · $4.18

$ lf --machine mini monitor
  6 sessions running · 2 available

It scales across your machines and your subscriptions: private, secure remote jobs and telemetry made easy through ssh, and multi-subscription balancing that moves to the next login when one runs out.

The CLI ↗Accounts and usage ↗

Shipping code is no longer the hard part. Scaling your attention and vision is.

Coding agents can do amazing things for you, but they ask amazing focus of you. How can you, a human with a single locus of attention, stay in sync with an entire parallel agent swarm? Shipping tens of thousands of lines is the easy part. Making them lines worth keeping — lines you don’t revert next month — is the hard part.

Loopflow helps you do that by arranging your agent sessions around clear work boundaries: long-lived areas of responsibility and objectives and concrete outcomes.

Craft and intentionality, at scale.

Your process, as code.

Your work has defined workflows — how an idea gets researched, designed, implemented, validated, shipped, etc. — and the points at which you want to get involved: be that early on in design, later on in trying it out, both, or neither. Each wave and task has an associated workflow that is used to drive work forward and ensures that each session you come to in Loopflow is one where your input really matters.

Loopflow ships reasonable workflows for software engineering, and they are templates. Change them, or write down the way you work and share it.

A Wave is an area of work with its own goal, memory and plan, and its own setup for every Task in it: the Graph, the agent, the machine and the login that pays.

You don’t have to keep every session window open for fear of it disappearing, or remember why you wanted to do this massive change in the first place. Each Task keeps one conversation; runs do the work beside it and report back.

Write a workflow ↗Tasks and Waves ↗

  • feature

    starttask-design →designpursue →demoship →end

    The default. You jam on the design, and you try every change before it ships.
  • code

    startpursue →demoship →end

    One stop. Your agent builds straight from the task, and you try the change.
  • research

    startresearch →findingsend

    No pull request. Your agent investigates, and the task ends when you accept the findings.

Three workflows that ship with Loopflow. The highlighted stops are where you come in; everything between them runs on its own.

What you can do with it.

  • Run Tasks in parallel

    Each Task gets its own worktree, branch and pull request, so a dozen can run at once without writing over each other.

    lf task create "fix the flaky retry test" --run

  • Steer a running Task

    Leave a comment. It reaches the next step, in the Task’s own context.

    lf comment ETU-14 "keep the retry budget at 3"

  • Get pinged when it needs you

    Loopflow for Mac and your phone tell you the moment a Task reaches a step that’s yours.

    lf task status

  • Pick up any conversation

    Close the window and come back next week, from any terminal.

    lf resume --task ETU-14

  • Review and land

    Each Task ends in a pull request. It merges when checks pass, fixing them first if they fail.

    lf land --wait-and-fix

  • Bring your Conductor workspaces

    Every worktree becomes a Task, with its branch, uncommitted files and setup scripts.

    lf import conductor

  • Use every login you pay for

    Claude and Codex logins, routed to whichever has room.

    lf account

  • Any agent, per run or per step

    Claude Code, Codex, OpenCode or Pi. A workflow step can name its own.

    lf -a codex : "fix the flaky retry test"

  • Your machines, or rented ones

    Run on your own box over SSH, or rent one for a single Task and give it back.

    lf --machine mini -b task run ETU-14

  • Know what it cost

    Tokens and dollars by Task, Wave or week.

    lf history usage --weekly

  • Check in from your phone

    Answer a design question, try a demo or say ship from Loopflow for iPhone.

    lf phone pair

  • Open it where you work

    A fresh tab with its splits in Rex, cmux, Herdr or tmux, or in Loopflow for Mac.

    lf open --task ETU-14

Get started ↗Every command ↗

Your terminal, your Mac, your phone.

Loopflow opens each Task in Rex, cmux, Herdr, tmux or a plain terminal: a fresh tab with its splits. Watch every Task at once in Loopflow for Mac, and answer the ones waiting on you from your phone.

Together, with your team.

Each task has one owner, one working copy and one pull request, so your agents and a friend’s agents can work in the same project without taking the same task or writing over each other.

The plan is shared: your tasks live on a shared ref in your project’s GitHub repository, or in Linear, with Asana and Notion coming. Comment on someone’s task, and their agents read it before their next step. Your conversations stay on your computer; only the plan travels.
