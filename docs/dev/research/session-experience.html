LOO-812 · Source and test review · 9 November 2026

Make starting, following and returning to work feel continuous.

The strongest common lesson is consistency across transitions: a launch stays visible while it becomes real; a return keeps the reading position; progress stays attached to the correct work; a broken connection never silently changes the destination or repeats an action.

Loopflow already has detached execution owners, retained screens, replay bounds, input/geometry ownership and explicit takeover. Many opportunities below are missing end-to-end tests or presentation polish, rather than missing transport infrastructure.

This comparison covers 43 source-backed findings across the three codebases, consolidated into 20 opportunities. It examines commits, repair diffs, test assertions and documentation. Upstream apps and suites were not run, so “test-backed” means assertions inspected, not independently demonstrated polish. The Loopflow baseline is draft 6394e4e900; the current 1a implementation addresses the first area and status-channel failure handling.

The final code passed 62 transport unit tests, seven real repaint/attachment regressions, and the mounted native Session input/recovery check. The expanded optional native run executed 69 tests and reported five failing tests with 11 assertions, all in GhosttyTerminalInputTests. The connection, cache, stable-layout, mounted Session and workspace suites passed in that same run. This is not an all-green native suite.

T3 Code: session experience compared with Loopflow

Research: 2026-11-09. Official pingdotgg/t3code main at 077fd62222a94b2264ad4525aa4e25bdb29d5029 (Nov 9, 19:26 UTC); 200 commits plus path history and repair diffs. Latest published release when checked: v0.1.7, Nov 4, commit 322f6544dfad0a3c8a0c8cbecf2c7f7874b14268. Nov 5–9 fixes below are main-branch findings, not claims about that release. Tests were read, not run; no T3 app was installed. Loopflow comparison uses draft 6394e4e900 and its local transport/Desktop code. “Gap” means observed missing coverage or presentation, not proof that Loopflow lacks every equivalent implementation.

Most useful differences

1. Returning from suspension tests actual socket life

T3's shared connection supervisor handles foregrounding, network changes and long suspension. It preserves a socket that still delivers frames, probes a silent one, and can replace it despite an inaccurate OS offline report. Remote routes get a short silence allowance; local/LAN routes can recover sooner. The Oct 27 repair replaced indiscriminate reconnect-on-resume; the Nov 6 repair further reduced delay after long suspension. Tests cover a frame arriving during a slow host check, stale offline state, and restarting the retry ladder. Oct 27 repair and tests, Nov 6 follow-up.

Loopflow: the owner/viewer heartbeat and bounded reconnect exist. The Desktop tests reviewed do not exercise OS suspension plus a socket that remains open but stops delivering. Add live-socket-preserved and silent-socket-replaced scenarios before tuning timers. Copy the distinction, not T3's timeout constants.

2. A loaded screen and a synchronized conversation are separate

T3 retains cached thread content while reconnecting and resumes using an applied sequence cursor. Its tests prevent cancellation from advancing the cursor beyond applied data, old scopes overwriting successor caches, and delayed disk reads replacing live state. Replayed events stay in a synchronizing state until a completion marker arrives; request-resolution notifications wait for that marker. Thread synchronization tests.

Loopflow: retained terminal screens, byte-counted replay and attachment acknowledgement already exist. The gap is an end-to-end presentation contract: cached pixels, native readiness and input claims currently arrive through different paths. Test old-ready callbacks after replacement, not merely correct values in a connection-state enum. Do not import a chat-projection lifecycle into the terminal protocol just to match T3's types.

3. Replacement subscriptions preserve visible output and selection

T3's drawer test starts with visible selected text, creates an empty replacement subscription, and verifies that it neither resets the terminal nor clears the selection. The replacement snapshot is the point that updates content. Separate surface tests preserve selection through unchanged redraws and keep a drag anchored while output scrolls. This followed an Oct 30 selection repair. Drawer regression, selection repair.

Loopflow: the current patch stabilizes geometry and paints the first snapshot at the new size. It does not establish selection/scroll preservation through a connection replacement. Add a mounted Ghostty scenario: select text, reconnect slowly, keep copying it while paused, then verify live handoff without a blank screen. This maps directly to the requested experience.

4. Geometry is restored per attachment, without replaying startup input

T3 tests re-sending the measured grid on each attachment generation, ignoring identical measurements, and sending initial launch input only once after the first snapshot. Resize precedes launch input. One retained driver per mode prevents a brief unmount/remount from resetting its successor's state. Terminal session tests, driver simplification.

Loopflow: mostly parity: geometry ownership, stale claims and no-replay are already tested. Add rapid hide/show plus a changed size during reconnect at the actual surface; assert final geometry and exactly-once initial command input. Do not add another manager: ownership outside transient views is the lesson.

5. Recovery errors identify the failing part and the right next action

T3 distinguishes this device, relay, host tunnel and host server, and attaches diagnostic detail to that route. A Nov 2 fix stopped blaming the host while the local device's sign-in was still loading. Tests also avoid declaring unspecified hops healthy and distinguish a relay error from a device network failure. Diagnosis tests, repair.

Loopflow: failure messages preserve causes, but the relay's unavailable copy can broadly recommend installation/Background Items even when another failure is responsible. Test actionable categories: owner ended, bridge unavailable, local setup failure, remote transport loss, input held elsewhere. Preserve the underlying diagnosis without displaying a wall of internal transport detail.

6. Cold and warm opens avoid redundant work

T3 keeps thread-cache lifetime separate from live-subscription lifetime. The Nov 9 change uses a bounded socket snapshot for cold opening, with one HTTP fallback on failure or session loss; warm cached opens use an event cursor. Tests cover both normal opening and the socket dying before first data. Nov 9 opening repair.

Loopflow: warm surfaces and saved terminal previews already provide part of this. Measure click-to-first-screen and click-to-input across cold, warm and recovery paths. Avoid adding an HTTP-style fallback to a terminal path that does not need one. The transferable win is removing duplicate preparation or round trips without broadening what Retry may execute.

7. Structured drafts and delivery survive more than screen restoration

T3's mobile composer owns persisted drafts, carets, attachment bytes and queued messages. Outbox tests preserve edits racing with delivery; after acknowledged delivery, failed local removal retries cleanup rather than resending. Other tests prevent delivered messages reappearing in reopened long threads, a bug repaired twice in October/November. Outbox tests, Nov 5 repair, draft/caret tests.

Loopflow: native providers own their editor drafts; a saved terminal screen cannot restore those drafts after provider death. This is a real product-model difference, not a missing buffer to add to raw terminal input. For future mobile structured input, adopt explicit draft/delivery IDs and cleanup-only retry tests. For current terminals, prove drafts survive viewer loss while the same provider lives, and never promise restoration after that process is gone.

8. Heavy output recovery has bounded work

T3 tests bounded output windows, UTF-8 byte accounting, cancellation during recovery, and listener cleanup during acquisition. The mobile writer appends across history rollover without re-sending retained history; a failed append recovers from the latest queued snapshot. These followed an October repair for unbounded output queued behind slow clients. Output protocol tests, mobile writer tests, slow-client repair.

Loopflow: bounded queues, replay spool and slow-observer isolation already exist. Add surface-level long-output/reconnect checks for repaint count, retained scroll position and input latency. This is added UX coverage, not a justification to replace the existing owner transport.

Beyond recovery: launch, attention and moving between devices

9. New-thread setup survives asynchronous arrival order

An Oct 26 repair prevented early detail reads from caching a not-yet-created thread as deleted. Tests retain setup and the original prompt until both the message and its first run arrive; a prompt echo alone does not dismiss setup. Rejected creation remains recoverable, and selecting another thread drops the old setup presentation. Repair and tests.

Transfer: test Loopflow's first Session creation with inventory, surface and native-ready arriving in every order. Preserve original context through failure; never show an existing conversation's startup UI merely because a delayed event arrives. This is a useful extension of the current presentation work, not a claim that Loopflow currently caches missing Sessions as deleted.

10. Progress belongs to the current work, not the newest row

T3 tests keep running activity attached to its executing run when a newer run is queued, preserve a subscription-limit explanation while messages queue, and avoid showing queued-only work as interruptible. Status from an old provider session cannot leak into its replacement; a child's failure is not inherited as the root's current failure. Execution presentation tests.

Transfer: Loopflow already has Program Status and Graph projections. Verify the visible combination when provider replacement, queued work and a stale completion race. Check that Stop targets running work and that quota failure stays visible; do not mistake a quiet native terminal for idle. This is mostly a cross-layer testing opportunity, especially alongside LOO-813.

11. Attention survives navigation and sends people to the right thread

T3 records opening after delayed shell hydration, immediately marks newly seen completion, throttles streaming visits, and keeps a deliberate unread mark until new activity. A Nov 3 fix made unread stick when rapidly reopening a thread. Repair. Mobile notification tests retain a failed navigation for retry, deduplicate initial-response/listener delivery, and route with environment plus thread IDs. Notification tests.

Transfer: test opening a progress notification before Session inventory is loaded, then receiving the same event again. Reach the exact conversation once, without restarting it or consuming an unread marker before it is visible. These mobile attention behaviors are not demonstrated by Loopflow's current terminal attachment tests.

12. Device continuity is route continuity, not moving the process

T3 documents pairing a phone/browser/desktop to the same host, learning its LAN routes, and falling back to a relay away from home. The host must remain running. Remote access. Tests exercise cellular transition away from a dead LAN socket, returning to LAN, sharing one head start across several slow routes, and renewing HTTP credentials without replacing a healthy conversation socket. Supervisor tests.

Transfer: Loopflow's remote transport already keeps execution on its Machine. The additional product polish is a discoverable device/route handoff with continuous selection, readable state and no accidental local successor. Test same-named conversations on two Machines, delayed route resolution, and changing networks while viewing. No evidence here establishes live process migration between T3 hosts; that would be a different product promise.

Counterexamples: T3 is not a flawless reference

An October reconnect bug resurrected closed or exited terminals through retained subscriptions. The repair tests close-before-seen, eviction, exit, explicit reopening and first-response vs resubscription semantics. Loopflow already has stronger explicit no-provider-restart rules on Retry; preserve those. Repair and regression tests.

T3's connection presentation test labels attempt 2 with a previous transport failure as reconnecting; it does not prove a previous successful attachment. It therefore is not a model for Loopflow's newly selected stricter Opening semantics. Presentation test.

Open reports at research time include chat lurch on terminal drawer opening #32778, stale terminal width #31013, and missing native conversation on resume #31689. These are reports, not reproduced findings. They limit any claim of universal polish even with extensive tests.

Paradev session, recovery and terminal UX · 2026-11-09

Reviewed official ParadevAI/Paradev at 2764273b198d46b1e39d8ed954ee3eb0141b82cc (2026-11-09 16:25 UTC): git history and named test bodies. Latest desktop release: 2.0.6, November 8, tag commit 7c13c14eb3616d39d9d9021df61caab9f7251fba. “Released” means ancestor of that tag. Tests and packaged UX were not run. Loopflow comparison: 6394e4e900 and transport/Swift tests, before the ongoing 1a implementation.

The most useful differences

1. Restore terminal modes in both directions, without moving the cursor. Released. A reconnecting viewer can retain a hidden cursor, mouse tracking or bracketed-paste mode that the current program no longer wants. Paradev explicitly asserts defaults as well as enabled modes. It rebuilds its tracker from daemon output after host-service restart, even when that output should not be repainted. The repair, #6582 reports a real Cursor-agent reproduction: focused input with an invisible cursor after restart, previously healed by switching tabs. Current mode tests cover cursor visibility, SGR mouse, paste, focus, Kitty keyboard flags, fragmented sequences, fixpoint resync and a default preamble that leaves the cursor untouched. DECOM reset is specially excluded because it homes the cursor. Loopflow: Ghostty repaint and cleanup already cover many modes; much coverage restores into a fresh viewer. Add a dirty-viewer/default-owner case plus actual focused typing after service restart. This is an audit/test gap, not proof Ghostty has Paradev’s bug.

2. A resize invalidates old output positions. Released. Paradev found a phone restoring a 45-column buffer while receiving missed output laid out at 120 columns. It records the stream position of the latest resize and reanchors clients whose position precedes it. Hidden clients keep receiving output while dimensions agree; once dimensions diverge, output is withheld until resync. The #7423 repair includes the failed initial design: withholding *all* hidden output lost hours of scrollback after its ring overflowed. Its real-PTY sequence suite tests resize-before-reattach and hidden-client silence. Loopflow: terminal recovery already uses a fresh snapshot, byte-stream recovery uses offsets, and the draft fixes first-snapshot sizing. Do not copy its protocol: test desktop-width → phone-width → hidden → desktop-width → return, including focus/cursor and long output. Also test attached passive viewers after the geometry owner changes.

3. Snapshot and stream position are one coherent checkpoint. Released. #6298 only persists an anchor with a successfully written snapshot after the parser drains; failed anchor writes remove old anchors. The sequence suite exercises gapless reconnect (zero content), in-ring gaps (exact missing bytes), ring overflow, and host restart, checking against daemon output and forbidding terminal reset. Registry tests keep runtimes alive if persistence fails and defer eviction during parsing. Loopflow: its owner snapshot and in-memory replay token differ, and it already tests offset catch-up/overflow. Useful extra cases are failure between saving screen and retirement, partial escape/image decoding during surface eviction, and repaint from an inconsistent checkpoint. Do not introduce a redundant client checkpoint solely to match Paradev.

4. Explicit handling of sockets that look open after sleep. Released. Its transport tests advance wall time two minutes while a fake socket remains OPEN and emits no close; a watchdog redials it. Tests also distinguish transient attach errors from session death, retry without replacing the socket, avoid accumulating offline diagnosis while hidden, and clear diagnosis after stable attachment. Loopflow: heartbeats protect owner claims, but the examined viewer loop does not impose a response deadline after attachment; Reply::Controlled is ignored. A server bridge that accepts writes but never delivers replies deserves a dedicated test. An unanswered heartbeat must pause input/recover the viewer without restarting its provider.

5. Fast return without a reconnect storm. Main only, after 2.0.6. #9503 keeps a healthy hidden remote terminal socket open so returning reuses it. Hidden socket failure or sleep instead parks it until visible, and a capacity cap still permits eviction. Its transport tests check all four cases. The commit reports ~1.2 seconds of remote redial latency per terminal, with multiple panes serialized by browser connection limits. Paseo · 15 findings: commits, tests, Loopflow gaps and limits

Paseo recovery and transport UX · 2026-11-09

Inspected official getpaseo/paseo, main e0f545fed485d244fcd3e6308c36e5a6397eaa2e (2026-11-09), its last 150 commits, relevant patches, production code and tests. Latest stable is v0.15.3, published November 6, release commit d91ae138cb931447635e94296023414a58bedcc5. Several strongest findings landed November 8–9 and are main implementation, not claims about the released app. Tests/application were not run; “test-backed” means inspected assertions.

Comparison baseline is Loopflow draft 6394e4e900: transport/README.md, transport_tests.rs, ServerConnection.swift, WorkspacePanesView.swift and Desktop connection tests. Its detached owners, snapshot replay, no uncertain input replay, and explicit input takeover already provide much of the transport foundation.

Concrete improvements to learn from

1. Returning to an unchanged conversation should do almost nothing

Main, November 9; browser and unit tests. 9a5b4ae sends the cached timeline cursor with subscription, letting the daemon answer current/behind in one round trip. Unchanged chats avoid another history fetch and an Updating toast. Subscription is installed before comparing the cursor, avoiding a missing-event interval.

The browser resume spec checks background return, dropped connection and reload: no Updating toast, no unnecessary fetch, unchanged reading position. Changed history stays visible until catch-up lands.

Loopflow: the current patch improves geometry but still has preparation and relay status owners. Transfer the visible invariant—no redundant opening flashes or scroll movement when the conversation is unchanged—rather than transplanting structured-history RPCs into its terminal relay.

2. Paint cached content without pretending it is current

Main, test-backed. The replica tests cover immediate cached paint without synchronization authority, a late cache read losing to newer network state, and live output arriving during cache loading without duplicate text. The screen-state tests keep previously painted history readable through reconnect, overlapping revalidation and failed catch-up; first-load failure is distinguished from later nonblocking failure.

Loopflow: saved terminal preview is already history, not input permission. Missing coverage is the complete visual handoff across workspace preparation, surface mounting and relay readiness, including late callbacks and an unavailable status channel. This supports the chosen opening experience.

3. Show completion together with the output that explains it

Main, November 9. b2b82e5 prevents a completed footer appearing under stale messages when the agent directory updates before transcript catch-up. The old running footer and original elapsed start time remain until the corresponding messages are committed. They deliberately removed a new “catching up” footer because it added another transient state.

The browser turn-end tests delay catch-up under both prompt-only and partial-reply screens, and assert footer geometry on completion.

Loopflow: provider terminal output and Program Status/work projections are separate. Test their ordering during reconnect before concluding this exact defect exists.

4. Measure recovery after suspension, not merely socket reconnection

Main, November 8. f539ccf documents a transport measurement of approximately 41.5 seconds before reconnect when an OS-suspended socket still appeared OPEN and accepted writes. Foreground recovery now uses two fresh five-second evidence windows and immediate reconnect after teardown. Repeated foreground events share the cycle. Any validated inbound progress keeps slow transfers alive; stale pre-suspension activity does not.

Client tests exercise second suspension during verification, timer-before-AppState ordering, delayed pong behind megabytes of chunks, and healthy socket retention. They explicitly acknowledge a single frame delayed beyond both windows can still be disconnected.

Loopflow: existing heartbeat/bridge tests cover failure and retry, but no comparable Desktop foreground verification was found in the inspected files. Adopt wall-clock suspension tests and measure time to usable input, not just the connected label.

5. A recovered connection must not be replaced by stale failover results

Main implementation with regression tests. b0a8a5d fixes a second reconnect: the selected connection recovered while a slower alternative probe was pending, but the old unavailable verdict still switched routes and rejected timeline catch-up. Tests cover a recovered primary with and without heartbeat RTT, and required failover.

Loopflow: not evidence of a missing multi-route feature. Apply the race to existing owner/location preparation and surface generations: late lookup or failed old attachment must not tear down a newly working pane. Do not add competing reconnect owners.

6. Preserve unsent drafts across navigation and reload

Main, November 8. 22f50d4 preserves local composer drafts when closing/archiving a root agent tab, clearing only on explicit entity deletion. Its browser test types an unsent draft, closes the tab, reloads and restores the conversation, then checks the text.

Loopflow: native provider editors own drafts; a saved terminal image cannot reconstruct them. Loopflow protects live drafts against owner retirement, which is useful parity. A client-owned persisted composer would be a product/architecture change, not a small relay fix. Test draft survival in surviving providers separately from crash restoration; never replay raw keys to simulate draft recovery.

7. Distinguish request failure from a message already accepted

Main, unit tests. Submission tests track concurrent sends independently, keep activity until canonical acknowledgment, and refuse to roll back a provider-acknowledged prompt after a later RPC error. This avoids “my message vanished” and duplicate resend pressure.

Loopflow: native clients already own prompt acceptance. Its no-uncertain-byte-replay rule is correct. Transfer these tests to structured inputs, native correlation and receipt UI where identity exists; this does not justify buffering terminal typing during disconnection.

8. Keep long catch-up from looking frozen or breaking transport

Main, unit/browser/integration tests. Viewed timeline tests distinguish live gap recovery (page fully to current) from first return after many missed pages (one bounded catch-up then latest complete-turn tail). Older history remains accessible. They retain the old subscription until its replacement is acknowledged, preventing hidden chats dropping events during route replacement.

01888dc adds end-to-end routed flow control after the final recipient drains, while concurrent small sends remain possible. Integration tests slow one consumer and verify sibling routes continue.

Loopflow: its bounded spool, fresh snapshots and slow-viewer isolation already cover equivalent terminal needs. Add end-to-end tests where a huge replay and control/status traffic share a remote path; unit queue bounds alone do not establish responsive input.

9. Terminal restoration preserves behavior, not just text

Main, serializer and PTY tests. 28c01ea restores mouse encoding as well as tracking after Copilot scrolling broke on conversation switches. Terminal tests check emitted wheel encoding, client cursor defaults, program cursor presentation, full-width pending-wrap and primary/alternate-screen replay.

The mobile rendering guide specifies measuring grid size before attach; its reattach harness changes keyboard/fold geometry and compares actual client rows against terminal capture. It also documents Unicode-width agreement and known bidi limits.

Loopflow: correct-size snapshot and rich-mode replay are already present. Add physical wheel, pending-wrap, emoji-width/cursor and viewport-scroll restoration checks.

Launching, following work and moving across devices

10. The first prompt gets a usable pane before creation finishes

Main, browser tests. Title/handoff tests delay authoritative creation and history responses: the submitted prompt and optimistic tab stay visible, no history overlay appears during handoff, and the temporary prompt title becomes the generated title in place. Navigation tests ensure a delayed launch cannot pull someone back after they select another workspace or replace a newer draft.

Loopflow opportunity: test first launch as a continuous interaction, including navigating away mid-launch. Its native composer limits optimistic rendering; navigation intent still transfers.

11. Creation progress survives its observing connection

Main, code and tests. The daemon keeps cumulative creation milestones and permanent IDs under an idempotency key. The client can reobserve that operation after losing its socket. Creation tests make duplicate submissions join and prohibit progress regression; first-prompt rejection leaves an existing agent with a turn error rather than reporting creation failed and inviting another agent. Uncertain side effects are not blindly repeated.

Loopflow: Task/Session identity already survives; do not add another execution identity. Audit whether Desktop can distinguish “creation admitted, observation lost” from “nothing created,” then test reconnect without duplicate Session/provider launch. Paseo's journal is a different product architecture, not a drop-in requirement.

12. Progress remains discoverable without stealing focus

Main, browser tests. Unread-work tests preserve manual unread on departure, keep another agent unread when reopening a multi-agent workspace, and retain a completion across reconnect until another click acknowledges it.

Loopflow: Program Status and attention already exist. Transfer the invariants: reconnect/focus restoration must not count as reading; one Session's selection must not clear another's attention. The completion/footer ordering tests above add the visual half of this behavior.

13. Notification taps work through cold startup

Main, model tests plus documented native verification. Notification-open tests wait for navigation readiness, handle launch taps once across remounts, reject replayed launch events and handle distinct taps separately. Navigation resolves current host/agent placement instead of trusting an old workspace hint.

Loopflow opportunity: verify cold/warm deep links to an exact Session while inventory is loading, including moved workspaces and a second tap. This is especially useful for phone-to-desktop continuity; no claim that Loopflow's existing deep links are absent or broken.

14. One destination identity across direct and routed connections

Main, integration tests. Connected-host tests retain unreachable saved hosts until they become available, isolate sibling logical sessions, preserve destination identity on lost mutation responses and refuse automatic mutation replay. The app can open a remote child using its destination-qualified identity through direct or routed transport.

Loopflow: explicit Machine routing/no local fallback is parity. Test stable conversation identity across route changes, errors naming the Machine, and intact sibling panes. This is access to the same remote execution, not live migration of provider memory between machines.

15. Mobile navigation preserves the work under motion and resizing

Main, interaction tests. Panel tests keep the old panel active until motion settles, ignore a stale gesture finishing after a newer command, and preserve the latest rapid navigation. 67628b4 adds a compact-screen test so overflowing plugin navigation cannot shrink the workspace list to zero.

Loopflow mobile direction: stable session identity and presentation should survive keyboard, rotation, swipe cancellation and navigation. Reuse ownership and projection models; do not let transient animation states attach/detach providers. These are future-client tests rather than current desktop defects.

Recovery limits worth preserving

Paseo's terminal worker survives daemon loss and retains PTYs; Loopflow already has detached owners, so this is parity rather than a reason for another daemon. Worker replay failure is viewer-scoped, and terminal stream tests distinguish failed observation from actual PTY exit.

Agent recovery is opt-in, reopening history and sending a continuation prompt. It documents possible loss/repetition across crashes and no exactly-once guarantee. The v0.15.3 config also defaults recovery off. Copying this would change Loopflow's no-replay contract.
