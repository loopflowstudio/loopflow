# v0.15.3

<!-- loopflow:release-notes=narrative;gate=safe -->

v0.15.3 keeps work reachable when capacity runs out, a connection drops or a reply gets lost. Desktop moves from its embedded Rust bridge to a shared local server, with saved creation receipts and reconnectable watches. Sessions gain account and model recovery, while shared observation and cheaper recording reduce the work Loopflow does around them. This follows v0.15.2's upgrade-continuity work; physical sleep/wake and some native input recovery still need installed-app verification. (#1813, #1828, #1854, #1868, #1874, #1876)

## Return to the work already running

A disconnected pane should not require a new conversation. This release keeps execution separate from history recording, makes exact Session links reliable and adds recovery that respects the viewer already in control. (#1858, #1863, #1876)

- **Local terminals can reconnect to the same execution.** Heartbeat deadlines no longer count laptop sleep. An acknowledged local terminal recovers without restarting the provider, replaying outage input or taking another viewer's input and size claims. If automatic recovery fails, Ctrl+R retries and Ctrl+] closes. Initial attachment and command pipes still fail within bounded waits; detached Session retention still counts wall time. (#1876)
- **Opening keeps a readable screen.** Desktop shows **Opening… Input paused** until the connection is ready. Feedback overlays the terminal without resizing it, and a private Unix connection carries connection status. Status loss pauses input while the terminal relay continues; recovery sends current status without replaying actions. (#1858)
- **Recording failures do not erase runtime identity.** Provider attachment, retry identity and cleanup belong to the running invocation; history recording is best-effort. Stale callbacks cannot stop a replacement provider. A failed terminal receipt can still return an error to a headless caller after cleanup. (#1858)
- **Exact Session links open the saved conversation.** Repository and Wave links retain their Session selector, including taskless conversations. Location reads use the selected repository instead of Desktop's working directory, and unpaged inventory reads no longer stop at 100 Sessions. **Refresh session** remains available for a single stale pane. (#1863)
- **Provider switches keep the Session open.** A Claude-to-Codex handoff no longer prematurely completes a disposable Session. Terminal titles follow renames and reattachment; bare `lf` starts with the directory name. (#1857)
- **Input already sent survives viewer closure.** Queued keystrokes are drained in order while that viewer still holds control. This does not replay uncertain input after an outage. (#1839)
- **Task conversations start before you return.** Task run, ship and explicit checkout start an unopened conversation in the background when a configured agent is available, up to sixteen running Task conversations. Preparation alone stays quiet, existing conversations retain their identity, and a running Graph keeps its conversation alive. Startup reads local Task state before syncing tracker comments. (#1844)

## Keep going when an account fills up

Usage limits no longer have to end a Graph step while another permitted account or model has capacity. Interactive Sessions get a move action; unattended Graphs can recover within their current step. (#1828)

- **Graph recovery follows the configured choices.** Steps try another eligible account, then permitted models and configured providers, before waiting for a reset. An explicit `harness:model` keeps that model; crossing providers requires an ordered `default_agent` preference. Capacity waits have no upper bound. (#1828)
- **Move blocked Sessions together.** `lf session move --blocked` and Desktop's **Move Blocked Sessions…** action move interactive conversations. Model/provider changes seed a new thread with history; busy Sessions queue the move until their turn ends. Moves leave preferences alone and cannot detect unsent drafts. Automatic interactive quota handoff is not included. (#1828, #1863)
- **Account selection is visible and controllable.** `lf account` shows capacity and active, held or paused state. `lf account next` explains selection; pause and unpause manage rotation. `lf account use <login>` holds launches on that login until it fills up or `lf account use auto` releases it. Eligible logins rank by plan and weekly quota remaining per hour until reset. (#1828)
- **Choose Codex speed through settings.** `codex.service_tier` accepts `default`/`standard` or `priority`/`fast`, globally, per repository or for one invocation. With no preference, Codex decides. Launches and restarts apply it, native child threads inherit it, and reattaching to a running conversation keeps its current tier. Replay records the launch preference. (#1870)

## Desktop recovers results and shares the work of watching

Desktop now reads, edits and watches Work through an independent local server using the CLI's operations. The embedded `loopflow-ffi` bridge is removed. Terminal traffic has separate connections, and ordinary CLI commands still work without the server. (#1813)

- **Lost creation replies have a recovery path.** Desktop saves Task and new-Session submissions before sending them, retaining their Machine, repository and payload across reconnects and app restarts. Identical retries recover the original creation; changed content conflicts, and removed resources stay removed. An uncertain launch remains inspectable without starting it again. (#1854)
- **Late results respect later navigation.** A delayed New Task reply cannot close a newer draft or pull you away after navigation changes. Its successful result remains available for recovery even when automatic opening is suppressed. (#1872)
- **Watches resume from checkpoints.** An unchanged reading need not be resent after reconnect. Changed or unknown checkpoints, including after server restart, receive current state rather than a replay of intermediate changes. Repeated observation failures back off from one second to at most thirty seconds; the delay resets after thirty healthy seconds. (#1865, #1852)
- **Live Task views follow external changes.** A shared observation cache refreshes local files and processes every second, Git every three seconds and GitHub every minute, and tracks activity deadlines. Subscriptions emit when their selected answer changes. Served reads use the latest observation and can briefly show a pre-mutation value; ordinary CLI reads and mutations remain direct. These intervals are not latency guarantees. (#1871)
- **Identical watches share a reader.** Consumers keep independent checkpoints, cancellation and final delivery. Settled Task-update checks use a dedicated revision counter, and viewer-retention queries do less work under the store's write lock. This reduces repeated observation; it does not establish near-zero total Loopflow CPU. (#1868)
- **Session status no longer needs a process per pane.** Desktop sends provider status over its existing server connection, retaining only the latest pending update so slow writes do not stall terminal traffic. Store access is not yet consolidated: each status write still opens the store. (#1875)
- **Recording takes less SQLite preparation work.** Rewritten identity triggers retain the validation rules and stored data. In an isolated SQLite experiment, event INSERT preparation fell from 41,743 compiled instructions to 687; this is not a measurement of total live contention. (#1874)

## Operational notes

The server cutover changes installation and scripting contracts. Install matching Desktop and server builds, and inspect uncertain launches before repeating them. (#1813, #1854, #1859, #1875)

- **Server installation and compatibility.** Installation registers and updates the local server through macOS SMAppService or Linux user systemd. `lf server status` inspects it and `lf server describe` publishes operations and schemas. The final protocol is revision 4, requiring matching clients and server. The later `session.status` operation did not bump that revision, so an earlier revision-4 server can still report status observation unavailable until `lf install`. (#1813, #1854, #1875)
- **Command namespaces.** The `lf ops` parent is removed: commit, sync, account, PR, worktree and Machine operations move directly under `lf`. Repository CI, people, tokens and release operations live under `lf repo`; planning configuration moves to `lf repo plan`. Canonical settings commands are `lf config settings`, `lf config get`, `lf config set` and `lf config unset`. Update scripts using the removed paths. (#1813)
- **Creation receipts and JSON.** `lf task create` and `lf session new` accept `--request-id`; `lf server receipt REQUEST_ID --json` inspects recovery. Task creation JSON consistently returns `{task, graph, session_id, milestone}`, including without `--run`; read the identifier at `.task.identifier`. Automatic creation recovery covers `task.create` and `session.new`, not arbitrary mutations. Receipts have no age-based pruning. (#1854)
- **Launch uncertainty has a deadline.** Five seconds of continuously unknown process status returns `outcome_unknown`; seeing a live execution owner resets that grace. Known-live launches have no overall deadline. Returning uncertainty neither stops nor repeats the work; use Task status and run history to inspect it. (#1859)
- **Task runs disclose shipping approval.** Detached `lf task run` output now says when the run may merge its PR and names `lf task hold <issue>` to withdraw approval. The running response adds a required `ships` boolean. Shipping behavior is unchanged: plain run approves Auto-Ship when no interactive step remains ahead, including continuation from the last interactive step. (#1866)
- **Shared provider logins and rentals.** Each Machine uses one home per provider. Existing `isolate:` configuration remains readable but is ignored; `--isolate`, `--shared`, `lf account route` and `lf account token` are removed. Account verbs take `provider=login` or an unambiguous login prefix. Owned Machines receive independent full logins; rentals receive Claude access tokens renewed from the laptop every two hours through the install schedule. `lf machine credentials renew` renews them manually. (#1828)
- **Status scripts take one snapshot.** `lf session observe-status` now reads one JSON snapshot from stdin and exits, requiring `--stream` and `--sequence`. It is no longer a resident streaming process. (#1875)
- **Recovery limits remain.** Restarting a process that died during a capacity wait keeps its checkout and recorded agent choice, but not that step's conversation; repeated skill labels can restart at their first occurrence. Physical invisible typing is not established as fixed, and the sleep-recovery regression simulates a paused relay and closed socket rather than suspending a laptop. Installed native input, remote recovery and physical sleep/wake acceptance remain incomplete. (#1828, #1863, #1858, #1876)
- **Launch and quit hangs fail PR checks.** The shared Desktop launch check requires a fresh non-empty snapshot and exit 0, samples stacks after thirty seconds and terminates a hung process group. Release packaging uses the same check. Its empty-workspaces fixture does not validate live Sessions or screenshot content. (#1850)

## Small changes

- `lf plan board`, `lf task detail` and `lf session card` provide complete typed one-shot reads, from compact board rows to recorded Session state, without attaching to a provider. (#1869)
- Subscription APIs add `task.shipped`, `task.steer` and `graph.step_finished` events. A shipped event means a recorded PR merge; a finished step may have failed or been interrupted. Reconnect restores current state without historical notifications. Desktop animations and thread UI consumers are not included. (#1873)
- `lf task view` retains the full Task pane data through live updates, fixing unknown fields and missing conversations. (#1876)
- Desktop Wave conversations resolve by ID, preventing repeated preparation when one Wave's name matches another's ID. Agents launched in Desktop panes no longer inherit relay variables that break Task attachment. (#1874, #1866)
- Server request IDs become reusable when the final reply is delivered, removing false unanswered-request conflicts. Rust and Swift operation names match the wire, and served write schemas come from their declared Rust result types. (#1856, #1855, #1867)
- Deterministic chapter rotation and Desktop's Project realignment dialog are removed; planning skills work in place. (#1813)
- The next homepage draft lives under `design/homepage-next/`, outside the deployed website. It is not a live-site change. (#1849)
