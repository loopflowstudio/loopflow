Prior art, and how the preview compares

“One selected opens in place; several selected stay closed” is an established Mac pattern. OmniFocus 4 does exactly this, and Things 3 does it with one extra step. The preview matches them on the model and trails all of the references on keyboard and undo.

Read from product documentation and reviews on November 19, 2026. I did not use these apps for this comparison. Claims marked from memory were not confirmed in a source today. “The preview” is the native build in Loopflow Backlog Preview.app.

The closest relatives

OmniFocus 4 same model

Selecting a row lets you edit its fields and its note in the outline; a second set of fields is “only displayed while editing”. With several rows selected, the Inspector edits them all at once and shows “Multiple Values” where they differ. The manual's own advice: quick edits in the outline, bulk edits in the Inspector.

OmniFocus 4 manual: the outline · review, Feb 2024

Things 3 same model, one more step

A to-do opens in place in its list, with notes and checklist, and the release notes call this an “expanded to-do”. The difference: selecting does not open. Return opens the selected to-do and ⌘Return closes it. Several selected to-dos stay as rows and drag together.

Double-click also opens, and opening one closes the other (from memory).

Cultured Code: keyboard shortcuts · release notes · MacStories on keyboard flow

Linear different reading, same bulk model

Linear never expands a row. Space shows a peek of the issue without opening it, and holding Space keeps it only while held. For bulk work it is the reference: x or the checkbox selects, Shift extends a range, common actions appear at the bottom, the rest are behind ⌘K or right-click, and Esc clears.

Linear: peek · Linear changelog: issue selection

Also relevant

Apple Mail. One message selected shows it; several selected show a stack in the reader, not their contents (a 2018 user report; Apple's guide does not describe it). Same rule, with a side reader.

GitHub Projects. Bulk edits in the table show an undo right after the change.

Notion. A row opens as a side peek, center peek or full page, chosen per view. No expand in place.

Point by point

Reading one item

Preview
Click a row: it is selected and its whole brief opens under it. matches OmniFocus
Others
Things opens on Return or double-click, not on select. Linear peeks on Space. Notion and Mail use a separate surface.
What differs
A to-do's note is a few lines. A Loopflow brief runs to 8,000 characters. No reference expands that much text into a list on a single click. untested ground

Selecting several

Preview
⌘-click, ⇧-click, or a checkbox that appears on hover. No brief shows. matches all four
Others
Linear adds x and Shift with arrow keys. Things and OmniFocus use standard Mac list selection.
What differs
The preview has no keyboard selection at all. behind

Where actions live

Preview
Inside the opened brief for one Task; a floating bar at the bottom for several; right-click for either. matches Linear
Others
Linear: bottom bar, ⌘K, right-click. OmniFocus: the Inspector. Things: menus, keys and drag.
What differs
No command palette or shortcut reaches the actions. behind

Undo

Preview
None, and none is designed. behind
Others
GitHub offers undo after a bulk change. The Mac apps have ⌘Z (from memory).
What differs
Start and Abandon launch agents or close PRs; they cannot simply be undone. That argues for the preview-before-apply the design already has, and for undo on the cheap ones: reorder, claim, move.

Reordering

Preview
Drag one row, or Move up, Move down, Move to top. matches
Others
Things and Linear drag several selected rows at once.
What differs
Dragging a multi-selection is not built. behind

Ownership filters

Preview
All, Mine, Available. ours
Others
Linear and GitHub filter by assignee through a general filter builder. None has “Available” as a first-class word.
What differs
Claiming without starting is specific to work that agents run. The references have assignment only.

What I would change, in order

  1. Keyboard. ↑ and ↓ move the selection, ⇧ with arrows extends it, Esc clears. Every reference has this; a list without it does not feel like a Mac list.
  2. Decide whether selecting opens. With arrow keys, select-opens means every keypress unfolds a brief and the list jumps. Things avoids this by opening on Return. Two ways through: open on Return or Space as Things and Linear do, or keep select-opens for clicks and let arrows move without opening.
  3. Long briefs. No reference shows this much text in a row. Either cap the opened height with “Show all”, or let Return on an open brief take the full page.
  4. Undo for reorder, claim and move. Keep the preview-then-confirm for Start and Abandon.
  5. Drag a multi-selection to reorder several at once.

None of these is decided. Number 2 is the one that changes the model you just chose.
