Four ways to hold work that hasn't started

Linear and Notion keep a backlog as records you sort and read. Agent Orchestrator has no backlog: work exists only once an agent is on it. The preview sits between the two, as a ranked list whose rows can launch agents.

What the comparison shows

The gap is about planning, not selection. Linear and Notion are better at holding a large pile: views, grouping, properties and saved filters. Agent Orchestrator skips the pile and is better at showing running work. Neither kind lets someone read a long brief and then launch agents on several items from the same list.

Grouping is where the references split. Linear groups by project, cycle or parent issue. Notion groups by any property. Orchestrator groups only by lane, and its “main agent” plans and splits work, which is the grouping-with-an-agent idea from round 8. KanBots, a smaller board, also splits parent issues into subtasks.

Peek against expand. Linear and Notion read a row on a separate surface and never push the list down. The preview is the only one of the four that opens in place, which works because the brief is capped.

T3 Code and Paseo

T3 Code: no backlog

Each thread starts from a prompt and runs. The nearest things to planned work are queued follow-ups inside a thread (“survive restarts. You can edit, reorder, or steer them”), scheduled tasks that run once or repeat, and snooze. The sidebar is an inbox of threads by project, with Settle for finished ones; threads also settle after seven idle days or a merged PR.
