The lf command line, top down

Built from lf help --all on branch jack/loo-953…: 234 commands under 27 roots. Facts here come from help text; I didn't run any command beyond --help.

Area taken: the whole lf surface, read by what a person is trying to do. The lf graph confusion is where this started: is it for running Graphs, listing the Graphs you can run, or seeing the ones that are running? It's one case of a wider pattern. Nouns a person knows (Task, Run, Definition) are split across roots, and roots mix things a person does with plumbing that only Desktop and the server call.

The biggest mismatch: lf graph is three things

lf graph's own help says "Run or inspect authored graphs", but it holds three nouns:

  • a definition you can run: lf graph code, lf graph list, lf graph show code, lf graph customize;
  • a run that happened: lf graph list --runs, lf graph show 8a132276…;
  • a run that's live now: lf graph list --runs --state current.

show decides which noun you meant from whether the argument looks like an id. Runs are also listed under lf task runs and shown in lf task status, so one record has three homes. lf skill has the definition half and nothing else. A skill run is a Session, and those are listed under lf session list.

Today

lf graph code               run a definition
lf graph list               definitions
lf graph list --runs        runs (all, any state)
lf graph show code          a definition
lf graph show <run-id>      a run
lf task runs LOO-953        that Task's runs
lf session list             live conversations

Sketch (one noun per root)

lf graph code               run a definition
lf graph list | show code   definitions only
lf run list                 runs; --task, --live
lf run show <id>            one run and its steps
lf session list             live conversations
lf ps                       what's live: Sessions + runs

This is only a sketch. A lf run root collides with "run" as a verb (lf task run), so the noun may want another name. lf ps was deleted on this branch ("i thikn we delete lf ps?"); it shows up here only as one possible "is anything running" answer.

The same pattern elsewhere

  • Plumbing in the person's namespace. About 65 commands are a client protocol. Hiding them from lf help (Clap hide), or putting them under one root, would cut the visible surface by roughly a quarter without changing behavior.
  • Reads with no single owner. A Task has three whole reads and a plan has eight. One show per noun, with --json for the Desktop shape, is the usual fix; which shape wins is a product choice.
  • Two spellings for one action. lf ship and lf -b task run; lf open and lf resume (LOO-958's).

What this would take

It's bigger than LOO-953. Each row is a CLI change that also touches docs (documented_commands checks examples), the operate skills, Desktop's action registry and saved-Graph translations. It splits into Tasks naturally: runs as a noun, hiding plumbing, one read per noun, and the end-a-Task verbs. Only the first relates to this branch: LOO-953 already renamed --processes to --runs, and the internal GraphProcess* → GraphRun* rename is queued.
