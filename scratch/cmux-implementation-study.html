What cmux does beneath the surface

Jack Heart requested a deep implementation study, following the Work-first demo’s loading flashes. Reviewed upstream source is pinned to 321d7d4458abb4005584f8459cf98ade967b38ad, downloaded without modifying either repository. This is not a claim about the exact build Jack is running.

Main finding: persistent terminal owners, deterministic first-render selection, and independent readiness instrumentation matter more than a new reactive framework. cmux also has substantial migration and lifecycle complexity; it is evidence to learn from, not a template to transplant.

Retain terminals; do not retain every mounted workspace

Observed in source. Workspace owns panels; TerminalPanel owns a TerminalSurface. Separately, WorkspaceMountPlan normally retains one mounted workspace, with explicit pinning exceptions. ContentView renders only the resolved mount set. The important distinction is terminal lifetime versus SwiftUI tree lifetime.

Application to Loopflow. Loopflow already has a per-window GhosttySurfacePool and retained workspace registry. Keep them. Do not interpret “keep cached” as mounting every Task forever, and do not adopt renderer reclamation or hibernation merely to copy cmux.

Resolve selection on the first render

Observed in source. ContentView.terminalContent computes a mount plan from the current selected workspace when its cached mount IDs lag behind. Its source explicitly explains that waiting for onChange otherwise hides the old content before the destination mounts. This is a direct match to our asynchronous handoff concern.

Application to Loopflow. Our WorkModel publishes linkedSession, clears preparation, and then SessionsContentView.onChange installs the pane. Replace that ordinary-opening mailbox with a model-owned synchronous install of the resolved record and pane. Keep one opening presentation until that handoff. Do not use a delayed callback to decide what the first selected render contains.

Readiness measures the experience; it does not choose the destination

Observed in source. WorkspaceSwitchCoordinator separates selection commit, portal presentation, first terminal frame, and interaction readiness. Terminal presentation requires portal plus frame; interaction is independent. The coordinator documents these as diagnostics, not mount authority. A cold-destination test verifies that source retirement does not wait for destination readiness.

Application to Loopflow. Instrument our click → model/pane installation → native mount → first frame → responder → provider accepts input separately. A surface handle or prepared command is not agent readiness. Do not keep the previous Task live on screen as a loading cover: selection, displayed content and keyboard destination would disagree. Do not build an all-data-ready barrier.

SwiftUI positions a native host; a separate owner preserves the terminal

Observed in source. GhosttyTerminalView.makeNSView creates a lightweight host. The terminal is hosted through a window-level AppKit portal. Dismantling cancels pending reconciliation and removes host callbacks while preserving the terminal lease across transient rebuilds. Host identity and surface generation fence late teardown from affecting a replacement.

Application to Loopflow. Our GhosttyTerminalMount already retains/reparents a pool-owned GhosttyMetalView and adopts it only when attached to a window. That is substantially aligned. A portal rewrite is not justified by a loading-placeholder bug. Capture actual mount/unmount and frame evidence before changing this lower layer.

Focus, visibility, and lifetime are separate

Observed in source. WorkspaceContentView derives visible panels from workspace visibility and the selected panel in each pane. ContentView separately sets opacity, hit testing, accessibility visibility, and layer order. WorkspaceHandoffRetirementGate associates retirement with a selection generation and completion of its focus pass, rather than a generic elapsed delay.

Application to Loopflow. Keep explicit input revocation when Work changes. A hidden retained terminal must not receive typing. Preserve the last pane per Work, but do not mistake keyboard focus for navigation identity. Tests should include rapid A → B → A and late callbacks, not only one successful switch.

Observe only the facts that affect the view

Observed in source. WorkspacesModel separates workspace list/order/selection from the legacy TabManager composition root. Its observation adapter avoids generic key-path overhead documented in that code. WorkspaceContentView deliberately reads a selected-panel ID instead of a richer tab object, avoiding a dependency on title metadata for portal ownership.

Application to Loopflow. Keep Work title/status refreshes from invalidating terminal placement. Compute compact immutable row/header inputs and preserve stable identities. Do not introduce a custom ObservationRegistrar to imitate their measured runtime workaround; profile our dependency fan-out first.

Reactive does not mean every update must move the UI immediately

Observed in source. SidebarWorkspaceSnapshotRefreshPolicy compares snapshots. While a context menu is open, immediate action-related fields can change, while telemetry-heavy details are deferred. Closing the menu applies the pending snapshot. This is selective update policy, not a global debounce.

Application to Loopflow. Keep last-known Workflow and stable row geometry during refresh. Avoid rewriting equal values. Only defer nonessential presentation updates when an interaction needs stability; never defer a safety-relevant owner change or hide a failure. A universal animation or debounce would conceal symptoms rather than repair ownership.

Recovery belongs to the terminal, not a replacement workspace

Observed in source. AgentRestoreRecoveryPresentation is terminal-owned, with explicit checking, existing-owner and writer-lock states. SessionPersistence defines layout/scrollback snapshot limits and restoration data. These are different from retaining a live process across app exit.

Application to Loopflow. Keep our errors and explicit Move here in the pane, without replacing the Work header/sidebar. Preserve our Rust ownership and provider-history rules. Do not infer usable cloned execution or authorize takeover from a saved layout.

The revised implementation cut

  1. Opening handoff: return the resolved destination to a workspace-owned operation; synchronously install record + pane before finishing preparation. Keep generation/location checks and reuse this installer for explicit links.
  2. Stable presentation: keep the terminal container and cached header content. Show preparation/connect/recovery inside that pane. Native terminal mounts when prepared, not after a fabricated “agent ready” state.
  3. Narrow dependencies: separate metadata observation from pane identity, terminal placement and focus. No broad Work snapshot should recreate a terminal.
  4. Measure transitions: preserve first-frame and input endpoints independently, with request IDs and a trace of every visible pane state. Use the data to decide whether a lower-level mount change is needed.
  5. Only then delete: remove redundant opening flags/mailboxes and obsolete view callbacks after their effects have one surviving owner. The separate exhaustive Swift audit supplies the broader inventory.

What not to import

No wholesale portal, generic observation workaround, renderer-reclamation system, new datastore, or new global state machine. No copying of implementation code. Loopflow’s Work/Workflow/planning authority stays in Rust; cmux’s terminal-centric workspace model cannot replace it.

Test scenarios worth adapting

The inspected cmux tests cover a non-null surface that has not presented, frame arrival before portal attachment, stale frame callbacks on a later switch to the same surface, coalesced rapid selections, cold-source retirement, bounded background mounts, and portal reentrancy/geometry repair. They are source evidence, not test passes from this study.

Limits and open decisions

  • No cmux build, tests, benchmark or native process manipulation was performed. No claim that cmux is universally faster or smaller.
  • This is a focused cross-layer trace, not an exhaustive audit of cmux. CLI/server, browser internals and full restoration policy were not audited.
  • We have not captured the precise native frame sequence behind Jack’s flashing report. The handoff gap is visible in source; other contributing causes remain possible.
  • Initial Workflow graph geometry still needs a product choice: reserve space, or keep it in expandable Overview. cmux’s terminal selection does not settle that Work-specific question.
