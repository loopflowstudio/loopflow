# Complete journeys before expanding machinery

## Problem and outcome

LOO-915 changes how large rewrites are planned, implemented and reviewed. A
representative journey must reach its actual consumers, state changes, recovery
and observable result early; the full intended change still defines completion.
Internal layers and successful step exits cannot substitute for that result.
This is one coherent skill change, not a runtime redesign or a pass quota.

## Chosen approach

Replace conflicting guidance at its existing owners. Keep skills standalone
and useful for small work; apply the migration table to substantial migrations,
not every small edit. A journey is an action through real consumers, its source
of truth and recovery to a visible result. It may cover one command across
several surfaces without completing every command in the final design.

Design retains the whole target and selects an early journey that challenges
the hardest assumption. Kickoff maintains one finite table: responsibility,
production callers/surfaces, test consumers, replacement/deletion, exit check
and remaining status. Discovery changes named rows with a reason; repeated
“final dependency” inventories are not closure. Compile production and test
consumers early or run a bounded migration spike before elaborating machinery.

Implement completes that journey before generalizing. Delete its replaced
consumer decisions in the same cut and keep required behavior tests on the
surviving path. No arbitrary per-function stopping point. Necessary shared
foundations are allowed, but their exit is the consumer journey they enable.
An indivisible migration stays one PR; no adapters, flags or duplicate owners
to manufacture independently shippable pieces.

Concept-review begins with changed contracts and concrete regressions against
the existing design. Whole-system review is warranted when an experience,
ownership, persistence or recovery decision changes, or a counterexample
invalidates the design. Implementation details alone do not reopen product
choices. A first review establishes the reference design; subsequent unchanged
reviews say so and finish. Real product choices remain open and reach the
caller through the existing Blocked protocol, rather than being recopied into
another implementation pass. No Graph runtime changes are needed.

Implement/realign report completed behavior, remaining migration, repairs,
newly discovered scope and next bounded outcome in the existing plan.
Loop-or-next checks these against actual results. Learning can justify a
bounded next experiment, but repeated inventories with no closed behavior,
new finding or changed approach do not justify another identical iteration.
Later gate obligations remain later obligations; a deferred check is never a
successful check.

## Delete — do not maintain

Remove deepest-first sequencing from builtin design, kickoff, implement and
compress, and per-function stopping from both implement sources. Replace the
unconditional repeat review in concept-review. Keep deletion obligations,
full-target acceptance, Graph decisions and source precedence; no runtime
symbols or exclusive tests are retired by this prose change.

## Alternatives, risks and exclusions

Keeping layer-first ordering and adding more end-to-end warnings leaves the
conflict intact. Removing review/refresh steps changes Graph semantics and
loses regression checks; bounded review gives the needed reduction without
that change. Pass limits, tiny-PR quotas and a new migration engine are rejected.

Wild success: the first difficult journey exposes ownership and recovery
mistakes while most of the migration remains cheap to change. Wild failure:
“journey” becomes a synonym for a mock demonstration, the table becomes a
second ledger, or review misses an architectural change. Real entry points,
explicit remaining consumers and changed-contract review address those risks.

No changes to LOO-650/906 product code, launch state, publishing or merging;
no LOO-759 reflection/versioning framework; no telemetry, memory backend,
remote monitoring authority, schema, wire DTO or provider-routing changes.
