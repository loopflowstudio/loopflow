One interaction, walked

Someone has the Session list open. An agent stops calling tools and says nothing for 120 seconds; its Session becomes available without anything being written. Another agent's process is killed; its Session stops reading as running. A third finished yesterday and reads Dead forever.

To draw that list, a read collects what SQL cannot know (SessionProjectionInputs), asks the OS, checks nothing moved (pin), then projects. On main the collecting step read 20,732 activity rows and 772 Sessions to end up asking the OS about 37 processes and registering one wakeup.

The finding from this pass: the plan promised a changed reading that no read can show

The plan, scratch/questions.md and the earlier version of this page said one reading changes: a finished Session whose agent ended reads Dead in the list where it read Unknown. QA could not reach it and filed it as unreached.

It cannot be reached. read_summary has two callers. The list (session_summaries_in, also behind Task selections) builds its page with inventory_query, whose first clause is s.completed_at IS NULL: a finished Session is never in any list. The single read said Dead on main through the evidence map and says Dead here from the row.

What the plan said

  1. Every summary reads the same, except one.
  2. Finished Session, ended agent, in the list: Unknown becomes Dead.
  3. QA: not reached.

What the plan says now

  1. Every summary reads the same. No exception.
  2. The PR body claims no change in what anyone reads.
  3. Nothing left for QA to reach on this point.

No code moves. docs/dev/reference-models.md says an ended agent is dead by its row "in every read and for a finished Session too", which is true of the single read and stays.
