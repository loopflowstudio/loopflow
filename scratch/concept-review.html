What changed

Built: stable terminal dimensions, a correctly sized first snapshot, an initial Opening label, cursor-preserving cleanup. The runtime/recorder split keeps process control out of history recording.

Removed: the independent workspace “Connecting…” overlay, file-based status and action mailboxes, and retry-derived opening labels. A private stream now carries status and deliberate Retry/Move actions.

Failure behavior: losing the status stream revokes Desktop input; reporting failure leaves the relay running. Recovery publishes the current reading, without replaying actions. Saved pixels never grant input.

Model, counterexamples and docs

LfSession identifies the conversation. LfProcess owns an invocation; AgentProcess identifies each provider attempt. A viewer is temporary. LfProcessRuntime owns live resources; SessionRecorder records facts. Derive the pane’s display without a new persisted lifecycle.

Normal: return at a different pane size, then type without a layout jump. Failure: lose the connection mid-turn; read the last screen with input paused. Recovery: reconnect to that owner; stay read-only if another viewer acquired input.

No compatible snapshot means an empty stable pane. An unreachable owner may still be working. An old surface’s ready callback cannot enable its replacement. Failed status publication must leave the relay alive while stale permission remains unusable; real socket failure and recovery tests cover that path.

Usage: Open a conversation to see its last available screen immediately. Opening… Input paused stays in the same place until you can type. You can still read, select and copy. Retry connection tries the same owner; it sends no saved keystrokes.

Next QA: exercise opening, leaving, returning, loss and recovery in the actual app; type physically, test two viewers and fail a status write. Run ordinary commands inline and check scrollback and the final cursor. Existing Task-session and general QA guidance need no rewrite.
