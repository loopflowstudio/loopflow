Against the steers

Built. "Do it from the server when the update is recorded, with no process per Session and no timer": one watcher thread on store::changes; its only clock is the 60 s missed-signal fallback, Machine-wide. "Don't keep a waiting async Stop hook per Session": none. "Deliver at the next boundary only for bare or unreachable conversations": as built. "Try each with a short spike": channels refused without a development-channels dialog; the socket-waiting hook measured 2.8 MB RSS per Session and is ruled out by the first steer; typing through Rex was not run (holder not on this branch). The inbox holds up: an idle session ran the turn 2.9 s after the write.

What would break it

Claude's inbox, <pid>.json and key file are Claude's own files, not a published API. If a Claude release moves them, open_inbox returns None or an error, the conversation hears the update at its next turn, and logs/lf.log says why. That degrades to the steer's fallback, so it is no reason to choose differently now.
