The split, caller by caller

The earlier proposal named three ownership callers. QA on 71feca7d found a fourth: delivery (lf commit, lf pr open) still went through the launch selection, so in a nested worktree it acted for the outer Task and refused on its branch. a8627a30 moved it to the owner. A grep of every caller of both answers and of select_work/select_execution_work finds no fifth.

Delivery's fallback is still a Declared selection (LF_AS or --task), as on main: a Session that names a Task can commit for it from a directory no Task owns.

What's left that's small

One word. rust/loopflow/src/lf/commands/run.rs:285, the comment on implicit_binding, says "checkout ownership wins over an ancestor's explicit declaration". The code asks task_holding, which is membership. "Ownership" now names the other answer, so the comment should say "the checkout holding the directory". That's a gate fix, not a design change.

What else holds

The slices match the product: one completion fact, one order, the primary in its released home, work recorded once at start, the leaving guard. Nothing is left over from replaced designs. The adoption special case is gone, so are the primary mark nothing wrote and 'inherited', and compress merged TaskOverviewRecords/TaskWorkRecords.
