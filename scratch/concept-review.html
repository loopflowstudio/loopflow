Concept review: Antigravity and the Harness contract

Do the product's concepts and the code's concepts line up?

Antigravity as a fifth harness, with failure classification on the Harness API. Third review after the build: f077eceeac against its base c7f2724ab4. The earlier two are at 1b2963cc96 and 5def1466b9.

Area taken: a conversation lf launched on antigravity, from launch through switching, quitting and resuming, and the Harness contract behind it (hook_callback, the thread file, the store's provider start, classify_failure). The last pass built slice 6, which the second review wrote: lf follows the conversation a person switches to. This pass read that as built and as run on real agy.

One interaction, walked

lf -a antigravity in a Task's worktree. The person works a while, types /new, keeps working, quits, and later runs lf resume.

first promptexists PreInvocation finds the thread file empty, writes 9fabb8b0: Start. Context block delivered.
/new, a promptexists the callback names b87dfb22, which is not the file's: the file moves, Start again. The new conversation gets its block.
lf steerexists arrives at the next model call of the conversation the person is in.
quit, lf resumeexists the file and the Session's resume reference both name b87dfb22; that one reopens.

Failure: the conversation starts a subagent. Its callbacks carry an empty lastUserInput; lf answers {}, records no boundary and claims no steer. The thread file stays on the parent.

Recovery: /resume <first id> inside lf resume moves the file back; the first conversation gets a new block and is the Session's thread again.

Seen on real agy 1.5.13 (scratch/qa.html, scenarios 7 to 10): /new, /fork, /resume <id>, a subagent in the TUI, and a Task's conversation that took a steer 13 s after /new. Not driven: choosing a row in the /resume picker, and /fork into another project.

The biggest mismatch left: "revoked" for a login that never was

It is small, and it is the largest one. Every structural pairing reads yes.

exists Before

// agent/mod.rs
"The {provider} login was revoked; sign in
 again on this Machine: {sign_in}"

A person who installed agy a minute ago and never signed in reads that their login was revoked. AgentFailure::CredentialInvalidated covers both, correctly: what happens next is the same.

proposed After

"{provider} is not signed in on this
 Machine: {sign_in}"

True in both cases, on every harness, with no second failure kind. Not built: the sentence is shared by Claude and Codex, whose tests and docs quote it, so it changes four harnesses' wording and is its own small outcome.

Tested against the build

Normal path: one conversation. The file is written once, at the first model call; every later call compares and moves nothing.

Headless: each turn is a new agy process with a new delivery file, so its first callback finds no thread file and is Start, which is what lets that process report turns and claim steers.

Counterexamples kept:

  • A subagent whose lastUserInput is not empty would be read as a switch. Seen empty headless and in the TUI; not seen in every mode.
  • A prompt with no text (an attachment alone) would be read as a subagent and get nothing from lf until the next prompt with text. Not tried.
  • The thread file cannot be written: every model call reads as a Start and gets the context block again. A warning in logs/lf.log says so. It costs tokens and loses nothing.

Looked at and left

  • hook_callback writes the thread file, and at a Start emit_block writes the same id into it again (the write that fills bare Codex's file). Two writers, one value. A pure hook_callback that only compares would need emit_block to create the file for Antigravity, where "the file exists" means "Codex was asked". Chosen earlier; still the smaller shape.
  • A headless turn makes a new launch folder under .lf/prompts/ each time, as other harnesses write a prompt file per launch. It goes with the worktree.
  • classify_failure on Launcher, and a provider start publishing the resume reference on every harness: as chosen.

Outside this work

  • A session grant that lets lf through agy's sandbox (permissions in its settings; unexplored).
  • Subagent tokens in lf history usage: read each subagent's transcript, named in the parent's invoke_subagent result row.
  • Listing plain agy conversations for adoption, from conversation_summaries.db.

Questions

  1. The sign-in sentence.
    1. Leave "was revoked" on every harness.
    2. One truer sentence for all five ("is not signed in on this Machine"), as a separate small change.
  2. A Task's conversation on Antigravity and agy's sandbox.
    1. Keep agy's own prompt and the docs that explain it (built).
    2. Launch Task conversations on Antigravity with yolo.
    3. Explore a session grant for lf alone.
  3. Usage that leaves out subagents.
    1. Keep the parent's number; the docs say what it leaves out (built).
    2. Count subagents' transcripts, as a separate change.
  4. Following /new, /fork and /resume.
    1. Keep it (built, run on real agy).
    2. Go back to the first conversation for the life of the launch and document the limit.
