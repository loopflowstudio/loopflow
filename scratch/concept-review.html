The biggest mismatch: a finished Task kept open by its children is only recognised when it has a merged PR

The person's idea is one standing: "this Task has done its own part and is open because follow-ups are." There are two ways to get there, a PR that merged and a Graph that reached end with no PR, and slice 4 built the staying-open for both. The words for it exist for the first only, so the second falls through to the line for a Task that has work left.

Built

  action: no_action (Merged · 4 children open)

$ lf task status a32d33      # no PR, Graph at end

After proposed

$ lf task status f5a0f9      # PR merged
  action: no_action (Merged · 4 children open)

$ lf task status a32d33      # no PR, Graph at end
  action: no_action (Finished · 1 child open)

$ lf task status a32d33

  next: lf task complete a32d33

One definition, "its own work is over": its PR merged, or it has no PR and stands at end. conducting_reason and the complete nudge both read it; the step is already in TaskDetailFacts.steps.

Tested against the cases. Normal: a childless Task reaching end is completed there and never shows this line. Failure: a Task at end with an open PR is not finished; it keeps today's lf land line. Recovery: the last child closes on its own and the parent is pointed at lf task complete, which nothing does today. Counterexample kept: a person may want to run another Graph on a Task that stands at end; lf task run <ID> <graph> still works, only the suggestion changes.

Choices made for review

  1. A Task with no PR whose Graph reached end with children open.
    1. Chosen: the same standing as a merged parent: "Finished · N children open", then "Finished; complete the Task".
    2. As built: "run the next work with lf task run".
    3. Complete it at end anyway and settle its children there, which abandons never-started follow-ups the moment a planning Graph finishes.
  2. How far a parent's completion reaches.
    1. Chosen: into every child it closes, done or abandoned; lf task abandon typed directly stays one Task.
    2. Into done children only, as built.
    3. Closing by either command settles children: lf task abandon <parent> finishes merged children and abandons never-started ones too. Needs a result on task.abandon like task.complete's.
  3. A child whose last run failed prints idle on its parent's status.
    1. Chosen: as built; the notice and the child's own status say it failed.
    2. The child line carries the failure.
  4. Served task.create with an unknown parent answers outcome_unknown though nothing was written.
    1. Chosen: as built; how the served request classes its other refusals was not read.
    2. A refusal kind of its own for input that names nothing.
  5. The closed parent's own reopened conversation files a follow-up.
    1. Chosen: under the closed parent, as built: that conversation is open and hears.
    2. Top-level.
  6. The word for the filing link, given "parent" already means the stack parent in the docs.
    1. Parent for filing; the stack is always "stack".
