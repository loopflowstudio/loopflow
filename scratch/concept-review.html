2. Biggest mismatch & the fix (Before vs. After)

Biggest mismatch Pretending a conversation moved to another directory

lf session bind rewrote agent_sessions.cwd to the Task's worktree without moving the running process, the files on disk, or directory-keyed provider transcripts — and admit_scope_workspace kept a second path that could do the same thing whenever an already-assigned conversation was made primary. Every downstream failure (missing conversation on lf resume -a, recovery restarting in the wrong worktree, broken Claude --resume) came from that single fiction.

Proposed model One invariant for conversation location

Binding changes what a conversation belongs to, never where it runs. And admit_scope_workspace / admit_session_workspace only places an unstarted, unbound primary placeholder (current_capture IS NULL AND bound_at IS NULL) into its scope's checkout. Once a conversation has started or been bound, its directory is settled — only a missing directory on disk (leave_gone_directory) or an explicit Machine move (lf session receive) changes it.

3. Stress-testing the model: normal path, failure, recovery & counterexamples

Normal path

Unowned worktree Y has a live agy conversation. Bound to Task T (which owns worktree X). lf resume -a claude:fable in Y finds the Session via checkout_conversation, seeds the Claude thread from agy's log, and runs in Y. lf resume T from anywhere opens the same Session in Y.

Failure & recovery

Provider exits or crashes → server recovery pass restarts it in Y (its actual files). If Y itself is later deleted on disk (e.g. a retired Task checkout), leave_gone_directory falls back to the repo's main checkout on next open so history remains reachable.

Brand-new Task / Wave / Repo primary

lf task create --run or lf resume LOO-12 creates a placeholder with captured = NULL and bound_at = NULL. admit_workspace still places it into task.worktree (or the persistent Wave/repo worktree) before its first launch. Once launched, cwd never drifts.

Counterexamples kept visible (what this design trades off)
  1. Already-assigned conversation made primary from another directory (fixed in this plan): Someone runs lf --task LOO-12 from main or repo.research (task_id = LOO-12, work_source = 'declared', bound_at = NULL, current_capture IS NOT NULL), then clicks Make primary Task conversation. Under kickoff's plan (which kept the work_source = 'bound' guard), the next idle lf resume would still overwrite cwd to task.worktree. Replacing that guard with current_capture IS NULL AND bound_at IS NULL closes the hole and drops two production reads of leaving work_source.
  2. Split checkout between conversation (Y) and Task workers (X): When you bind a conversation in Y to a Task that already owns X, the Task's Graph workers, lf task changes, and PR commands run in X, while the primary conversation runs in Y. Printing the one-line factual note on bind (“Conversation stays in Y; TASK's checkout is X.”) makes the split visible immediately instead of hiding it.
  3. Machine move of a split Task (lf task move / lf --machine M resume <session>): moves::send_task checkpoints task.worktree (X) and moves the conversation's transcript from Y. Uncommitted edits sitting in Y do not travel with X. Noted as a separate outcome below — rare enough not to block LOO-1101, but real.
  4. Conversations moved by an earlier bind: Already-rewritten rows in ~/.lf/loopflow.db (like session_94d9963b… → manabot.mtg-388-getting-into-a) stay as stored; lf resume <session> still reaches them. No automatic DB rewrite is planned.

6. Open questions for review

Choices marked Chosen for build are written into scratch/plan.md and built for review; reply with e.g. 1b or 2b to flip any of them.

1. When you bind a conversation to a Task that already has a different worktree, where should the conversation run?

Applies both when binding from another linked worktree (like manabot.academy-test-drive) and when binding from main or a Wave checkout.

  • 1a. Chosen for build Always stay where it started. The conversation, its edits, lf resume in that worktree, and crash recovery all agree. The Task's own worktree stays where Graph workers and PRs run; lf session bind prints one line noting the two paths when they differ.
  • 1b. Stay in linked worktrees, but move out of main and Wave checkouts. Keeps a shared checkout cleaner after binding, at the cost of a second rule and the same live-process vs. stored-directory split whenever you bind a running chat from main (plus breaking Claude Code resume until a new thread starts).
2. When you bind a conversation in directory Y to a Task whose checkout is X, should lf session bind mention the two directories?

Matters because Graph workers and lf task changes will look at X while your bound chat edits Y.

  • 2a. Chosen for build Print one factual line only when they differ: “Conversation stays in <Y>; <TASK>'s checkout is <X>.” Silent when they match or the Task has no checkout.
  • 2b. Say nothing about directories. Print only the Task it bound to; rely on lf task status if someone checks where the conversation runs.
3. What about lf resume with no arguments in an unowned linked worktree that has no conversation yet?

Today it refuses and tells you to run lf to start a new conversation there, even though lf resume --help says “With none for this scope, it starts one and says so.”

  • 3a. Chosen for build Keep the refusal out of this Task. An unowned worktree has no primary scope; lf starts a chat there and lf resume continues one once it exists.
  • 3b. Have lf resume start a conversation in an empty unowned worktree too. Drops the refusal so lf resume works in every worktree; would be a small follow-up Task.
4. Should we leave previously moved conversations alone in your local store?

session_94d9963b7fd74dacbe01b65c99f7deb5 already had its directory rewritten to manabot.mtg-388-getting-into-a by the old bind.

  • 4a. Chosen for build No automatic repair. Leave existing rows as recorded; lf resume <session> reaches them from anywhere.
  • 4b. Repair that row by hand afterwards so session_94d9963b… points back to manabot.academy-test-drive.
