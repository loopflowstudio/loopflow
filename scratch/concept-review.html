Biggest mismatch: "plan" still names a Wave's Project

Walk it. Someone reads the glossary, learns "the plan is the shared Waves, Projects and Tasks", then runs:

existing, and kept by the plan
$ lf wave plan product        # Projects and Tasks: the plan ✓
$ lf wave edit-plan product --name "2026-10"
                              # edits… the Project
$ lf wave update-plan --wave product --plan p.json
                              # replaces the Project's KRs

Within two commands "plan" means two different things. The error text for update-plan says "Project", and docs/dev/reference.md:84 says "one selected plan per Wave".

proposed
$ lf wave plan product        # unchanged
$ lf wave edit-project product --name "2026-10"
$ lf wave update-project --wave product --file p.json

"plan" is the whole structure and "Project" is the thing you edit. bind, connect and reteam stay under lf wave plan because they bind the Wave's plan to the tracker. The glossary row and AGENTS.md change to match. No alias.

Passed over: an lf wave project edit|update|bind group. It would pull bind out of the plan group and move three commands to fix two.

Config: one canonical key, and dotted keys that follow it

plan as written
reads: planning · plan · repo.plan · linear.team · tracker
docs:  repo.plan: {provider: linear, team}
set:   repo.tracker.linear.team → ?
proposed
canonical: repo.tracker   shorthand: tracker
  tracker: {linear: {team: X}}   # or git, {asana: …}, {git: {shared: team}}
read-only folds (LOO-784 marker): planning, plan, repo.plan, linear.team
writes: planning: {provider: linear, team: X}   # released shape
lf config set repo.tracker.asana.team Y  → replaces the block
lf config get repo.tracker               → canonical shape

Failure path: a repository on Linear sets an Asana team. With merge semantics both tags survive and the fold has to pick one silently. Replacing the block makes "one repository, one tracker" true in the file. Recovery: setting the Linear team again restores it.

What did not move

  • Staged table renames with mirror triggers. The probe is sound. Its risk only touches the table section, and it stays slice 1.
  • lf repo tracker over lf repo sync.
  • The wire: tracker_id and tracker_state {state, synced_at}, with LOO-942 folded in.
  • The scope rule that leaves observe::, metric observations and Swift *Observation services alone.

Questions

  1. Wave Project commands: (a) edit-project / update-project, as written into the plan; (b) one lf wave project … group; (c) leave them as "plan".
  2. Config dotted keys: (a) a different tracker name replaces the block, as written; (b) a mismatched tag is an error.
  3. LinearIssueEvidence: (a) LinearIssueState, as written; (b) keep "evidence".
  4. Authored Wave files that say "chapter" (.lf/wave/infrastructure/GOAL.md:38,49 and others): (a) leave them as written, as planned; (b) their authors reword them in this PR.
