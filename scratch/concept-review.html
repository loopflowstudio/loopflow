2. The Biggest Mismatch

Biggest Mismatch Chats are unheld only because pre-holder Loopflow leaked per-session processes

Direct lf launches became unheld in #1877 when every held conversation spawned its own lf session serve process (281 lf processes / 11.6 GB RAM on one Machine) and had no cleanup for closed tabs. Today Loopflow has one shared lf holder run per build, exec_native leaves zero lf process beside the provider, and held_terminals.viewer_hold already drives 15-minute unviewed retirement for done Tasks.

Keeping lf -a agy outside the holder forces people to hit TakeOver whenever they move between Rex and Desktop—which is why the creator saw agy close and assumed agy wasn't wired into the holder.

Why the earlier kickoff plan is a patch on the wrong concept Superseded Plan

The first plan left chats unheld and tried to hide the seam when a second viewer opened them: kill the chat's provider, restart it in the holder, make the old pane follow-attach, and relabel Take over to Open here.

Existing HEAD
Kill & drop to shell
  • Rex pane 1: lf -a agy runs unheld in pane 1's PTY.
  • Desktop clicks Take over (or Rex pane 2 runs lf resume).
  • stop_session_agent sends SIGTERM → SIGKILL. Active turn aborted; draft lost.
  • Pane 1 prints “This conversation moved to Desktop” and exits to zsh.
  • Rex-to-Rex stays unheld, so a third open kills it again.
Superseded Plan
Kill, cold-restart, & follow
  • Rex pane 1: lf -a agy still runs unheld.
  • Desktop clicks Open here — same label as a lossless view, hiding a kill.
  • stop_session_agent still sends SIGTERM → SIGKILL! Mid-turn work & drafts still destroyed; agy cold-restarts.
  • Pane 1 waits on lock & execs relay (foreground::Drop doesn't reset raw termios after SIGKILL).
  • Quit + lf resume in Rex flips it back to unheld Chat; next Desktop open kills it again.
Proposed
Held from the start (fallback if no server)
  • Rex pane 1: lf -a agy sees lf server running → starts in lf holder run, pane 1 relays it.
  • Desktop clicks Open here (or Rex pane 2 runs lf resume) → View.
  • agy never stops. Mid-turn tools, streaming output, and unsent drafts stay intact. Both views type.
  • lf install never interrupts it; live status & idle steers work.
  • Close all views → stays warm 15 min, then retires cleanly when idle (no zombie leak).

4. Counterexamples & Failure / Recovery Tests

Scenario / Counterexample How the proposed model handles it
Closed-tab zombie leak
Observed: 37 of 58 chats over 4 days ended via closed tab without /exit		 When the last viewer closes, the server marks viewer_hold = Absent(now). If a viewer returns within 15 minutes (e.g., closed Rex tab, switched to Desktop), it attaches live with zero restart. If unviewed for 15 minutes and no turn/request is active, the 1-minute sweep closes the held terminal cleanly, freeing PTY and RAM while preserving transcript and saved screen.
Mid-turn viewer close or switch Opening a second viewer mid-turn attaches a View without touching the provider. Closing the only viewer mid-turn leaves the turn running; terminal_retention holds off retirement until the turn finishes, then starts the 15-minute grace.
lf server is stopped / CI / container Connection::open() fails in <1 ms without spawning a surprise daemon. Direct lf and bare lf resume immediately fall back to foreground Chat. Loopflow never refuses to let you talk to your agent because its server is down.
lf install / server restart mid-chat lf holder run keeps the provider running. The new server takes up the terminal, reads session from meta.json / exit-record.json, rebuilds Registry::live, and all views reconnect from their byte offset.
Bind a running chat to a Task
lf session bind <id> --task		 bound_at is now set, so the Session automatically leaves the bare-retirement set and keeps open-Task lifetime with zero restart.
Piped stdin / headless batch
echo … | lf -i, lf -b		 lf -b is Batch (never held). Piped stdin (!stdin.is_terminal()) stays direct so piped prompts aren't lost before parsing.
Tradeoff: Rex foreground icon & Ctrl+Z In Rex, a held session's foreground process is the lf session attach relay (identical to every Task, Wave, and Repository session today), so Rex shows lf instead of agy/claude, and Ctrl+] detaches instead of Ctrl+Z suspending. OSC titles and OSC 7501 Program Status still pass through unchanged.
Choice Made for Review Written into scratch/plan.md

Chosen: Hold every interactive lf launch when the Machine server is running, with automatic 15-minute idle-unviewed retirement for standalone chats and automatic direct-foreground fallback when the server is unreachable. This is fully reversible (no schema migration, no protocol break) and fixes the root concept mismatch rather than patching over a mid-turn kill.

Passed over: (1) Promote-on-second-open + follower attaches — still kills the provider mid-turn on first cross-viewer open, hides a kill behind Open here, and flips Sessions back to unheld on next Rex resume. (2) Hold forever without unviewed cleanup — would leak dozens of idle providers and PTYs from closed tabs. (3) Hard-require the server for bare lf — breaks bare CLI in containers, CI, and stopped-server setups.

5. Open Questions for Review

Reply with a number and letter (for example, 1a 2a). Highlighted options are what scratch/plan.md is building for review.

Question 1 — What should happen when you run lf -a agy (or lf <skill>) in a terminal and later open it in Desktop or another Rex pane?
  • 1a. Always held when the server is running (chosen). Opening it in Desktop or another Rex pane always attaches a second live view without closing or restarting the agent. Tradeoff: Rex sees lf instead of agy as the foreground program (same as Task sessions), and Ctrl+] detaches instead of Ctrl+Z suspending.
  • 1b. Keep chats directly in your terminal, promote on second open. Rex keeps showing agy and Ctrl+Z works while only one pane is open. Tradeoff: the first time you open it in Desktop or another Rex pane, Loopflow stops and restarts the agent (aborting any active turn and losing unsent input), and the original pane reconnects to the restarted session.
  • 1c. Keep chats directly in your terminal and keep “Take over” as today. Direct chats stay completely separate from held work sessions; moving one to Desktop closes the original pane with a notice.
Question 2 — When you close the last tab/window showing a standalone chat (not bound to a Task, Wave, or Repo), how long should its agent stay alive in the holder?
  • 2a. 15 minutes after it goes idle with no viewer (chosen). Matches completed-Task cleanup: closing Rex and opening Desktop a few minutes later attaches with zero restart, active turns finish instead of being killed on tab close, and forgotten tabs don't pile up idle agents or exhaust PTYs.
  • 2b. Stay alive indefinitely until you type /exit (same as Wave and Repository sessions). Tradeoff: closing chat tabs with Cmd+W leaves live agents running in the background until reboot or manual quit.
  • 2c. Close immediately when the last viewer closes (once any active turn finishes). Tradeoff: closing Rex and then opening Desktop 10 seconds later has to restart the agent from history.
Question 3 — If you start a direct lf chat while the Machine server is stopped, should it start the server or run directly in your terminal?
  • 3a. Fall back to running directly in your terminal (chosen). Instant startup when the server isn't running (containers, CI, stopped server) and never refuses to let you talk to an agent; on any Machine where the server is already running, it uses the holder automatically.
  • 3b. Auto-start the installed server first, then fall back only if unavailable. Even right after manually stopping the server, lf -a agy brings the server back up so the chat is held from turn one.
