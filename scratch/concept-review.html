The mismatch: the restart says one thing, the contract another

Now, in AGENTS.md and the architecture reference:

A stopped run leaves the Task on it, and the next
`lf task run` starts it again from where it began.

Now, in the code:

(None, Some((cursor, _))) => limit_recovery::held(&store.sqlite, &task.id)
    .and_then(|(step, _)| graph.find(&step))
    .or_else(|| graph.place_of(cursor)),

Proposed contract text:

… starts it again from where it began, or from the step
a usage limit held when its Process ended.

This exception only. Restarting at any failed step is LOO-435's work.

Two smaller corrections

One name. The person sees Waiting; the code says held. Proposed: waiting_step, restart_waiting_runs.

Status claims only what will happen. A step that ended mid-wait reads the run starts again at it after 14:00. The sweep skips unowned, finished and blocked Tasks, so on an unassigned Task nothing restarts it. Proposed: the sweep and the status text share one predicate. When it fails, the status says the next lf task run starts at that step.
