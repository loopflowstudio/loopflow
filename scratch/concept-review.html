Iterate to implement: three commands take the Session caller as a value; title repair takes none.

Biggest mismatch. The plan was to thread the caller through every command that can repair a Session title: binding, attachment and every planning write. The caller check only reaches those commands because automatic repair reuses the rename function. Repair computes a title from saved facts; no caller is acting on the conversation.

No open product choice. No schema, wire shape or command changes. A green bar marks what is proposed; the rest is what the code does now.

What changes for people

  • A replaced provider can no longer bind or resume its former Session when a person named it. It already could not when the name was generated.
  • When a Task gets its Linear identifier, every open generated Session name picks up the new label, including the Session of the agent that made the edit.
  • An identifier update no longer fails with “capture does not belong to a recorded Session in this Machine” because the process carried another store’s LF_CAPTURE_KEY.
  • Served requests see no agent caller and read the server’s environment for the capture key. Unchanged in this cut.

Normal → failure → recovery

An agent renames its own Session: the facade reads the caller once, SQL finds it is the current attached provider, the name is saved. The provider is replaced and the old process tries again: SQL finds a different current provider and answers “Session provider was replaced”; nothing is written. The old process then edits its Task’s identifier: the edit succeeds and the live conversation’s name follows.

Neither refusal string has a test today. Add: rename, bind and attach by a replaced provider, generated and human title; a capture owned by another Session refused on rename; an identifier update that repairs every open generated title and succeeds with a foreign capture key.

Also settled

  • Storage stamps its own writes (now_unix(), unixepoch()). Only a time that decides membership arrives as a value. No clock parameter on every write.
  • Down with storage: store::{steer_markers,instrumentation,linear_records}. Stay application: store::{admission,retention,task_work}.
  • Production SQL names no application facade module. journal::agent_caller, twice in require_current_actor_in, is the last production name from SQL into application code that is not a saved record.

Order

  1. The caller value for rename, bind and attach; repair without a caller; the regressions above.
  2. Upgrade preflights: saved read → act above → compare in the exclusive transaction.
  3. Classify store/, split store/mod.rs.
  4. Move synchronous storage with records, its own files, migrations and schema generation.
  5. Measure, then choose the next cut.

Questions

None blocks this pass. A different answer would change the direction:

  1. Caller check on bind and attach: (a) always, as proposed; (b) exactly as today, only when the title is generated, which needs the caller threaded through planning writes too.
  2. If the storage measurement shows an ops/task edit’s cost sits in ops + lf: (a) split the application next; (b) continue with definitions, providers and runtime.
