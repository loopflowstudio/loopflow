Product concepts vs built code concepts

Inspect work vs choose file

  • Yes · Rust config.scope (Scope { settings, files }, ScopeTarget, Destination) separates inspected work from editable declarations.
  • Yes · Swift ScopedSettingsModel separates checkout/wave/target from destination; Save in only offers My/Shared at the active scope; editableFile(for:) routes applicability == "personal" directly to .personalGlobal without mutating destination.
  • Yes · scopeTitle names the active Skill or Graph step with an “Inspect general work” reset button; unnamed Graph steps show an explicit read-only banner; Git & Release at Wave scope shows one repository banner.

Browse & edit settings

  • Yes · SettingsSection organizes native grouped forms per pane; Agent Policy groups agent, default_agent, and agents with one shared Effective agent order provenance disclosure.
  • Yes · ConfigurationScope.Authored (absent vs present(JSONValue)) and strict JSON null validation in settings::validate_value preserve absent, explicit null, and authored values across Pickers (chrome, merge_method, codex.service_tier, auto) and TextFields.
  • Yes · LandMethod is a typed enum; user.name, logs.linear_requests, and automation.retries use native controls; inactive compatibility keys (isolate, summaries, summary_tokens) and internal/account keys (portfolio, auth_browsers) sit in collapsed Advanced sections and stay searchable.

Save, preview & undo

  • Yes · config::files::edit (Entry, Change::{Set, Reset, Restore}, Applied) owns checked edits, comment preservation, alias normalization, and Undo receipts.
  • Yes · observe::invalidate_path fires synchronously inside config::files::atomic_write and promotion::remove_journal (with a stale-poll check in Cache::refresh) and wakes read_stream::wake_file_readers(); confirmReading() coordinates rapid consecutive edits.
  • Yes · ScopedSettingsModel.errors is keyed by RowAddress(file, key) with targeted recovery (refresh / dismissMove); editsDisabled gates only on saving || reading.failure != nil.

Move (Promote) a declaration

  • Yes · engine::config::promotion locks files in path order, previews patches and projected effective values via observe::preview_files, names the new audience, flags a refreshed preview before confirming, and supports inverse-move Undo.
  • Yes · Pending moves appear directly on the row; Action::Resume finishes matching partial moves, while diverged conflicts offer idempotent Action::Dismiss under file locks without modifying either YAML file.

Search & jump to a row

  • Yes · SettingsMatch indexes panes, App controls, and all non-container catalog keys/shorthands/descriptions (with exact key/title matches ranked first and Inactive tags shown); boolean search rows share ScopedBooleanToggle, Undo, and inline row errors.
  • Yes · settingsForm(highlighted:) mounts ScrollViewReader inside each pane’s Form, waits until scrollTarget is present in the reading, auto-expands Advanced when needed, scrolls to .settingsRow(key), and keeps ScopedSettingRow’s draft keyed by RowAddress(file, key).

Appearance, Shortcuts, Mobile & Machines

  • Yes · AutosaveToggle, shared KeyboardShortcutsView, lifted MobileSetup (one live status for sidebar dot and QR), ThemeChooser (all controls and top-mounted errors inside Sections), and ThemeEditor drafts line up with native macOS Settings.
  • Yes · MachineConnections reads machines directly from config.scope, preserves prior reachability across 30s probes, and provides Refresh connections.
  • Yes · Intentional boundary: AppearanceStore writes theme through checked config.edit with Undo, while keeping config.theme + local file-stat watching for app-wide theme updates (when Settings is closed), local Ghostty theme files, iPhone parity, and older server reads.
