The mismatch

The comment in harness/codex.rs keeps configuration per thread because "the app-server can host another conversation" and it must not lend that configuration to "a newly admitted sibling." That reason dates from the relay. Today each Session's app-server is private to it (execution.md, "Connect and transfer attachment"), so every thread on it is that Session's thread.

Evidence

CODEX_HOME=<private> codex -c 'developer_instructions="LFMARK"' app-server --listen unix://…/a.sock
client: config/read {includeLayers: true}
  → config.developer_instructions = "LFMARK"
  → set in layer {type: sessionFlags}   (lf already reads the wrapper's hooks from this layer)

Still to check during implementation: that a thread the TUI starts actually sends the sessionFlags instructions to the model. Use the --new-thread fixture with a marker. If it doesn't, the Codex limit stands and the plan says so.

What changes, what survives

  • Changes: open_thread sends no config. The native launch puts it on the server, before the subcommand. The "sibling" comment goes.
  • Survives: lf still opens the first thread so it has the thread id and the first input before the TUI starts. Following /new and /fork stays as is. Codex's codex_tui dynamic tools stay out.
  • Becomes unnecessary: option (b), the observer interjection. lf never starts a turn the person didn't send.
