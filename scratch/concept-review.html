Biggest mismatch: the move record lives on the wrong Machine

The brief: a half-finished move "is a row you can see and retry". Today the row is written by whichever Machine ran lf task move, after the send answers.

laptop$ lf task move LOO-9 --machine mini     # LOO-9 is owned on rental
  rental: stop Graph, push, complete conversation
  rental → laptop reply lost
  laptop: no task_moves row; rental: no row
laptop$ lf task move LOO-9 --machine mini     # repeat
  arrives on mini without its conversation

Proposed: moves::send_task on the leaving Machine writes sent with the payload before replying, and a repeat to the same target returns it. relay_task loses its own lookup; the local case is the same call.
