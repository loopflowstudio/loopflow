Why a turn failed

LOO-977 asks for a curly apostrophe in one phrase list. The area reviewed is the whole route a provider's failure takes: what the provider says, what the harness decoder keeps, what the recovery loop acts on, and what a person reads in lf task status. The apostrophe is one sentence on that route; the question is whether the route should be reading sentences.

One interaction, walked

A Graph has agents: [codex:gpt-6.2-astra, claude:fable]. The Codex account runs out during implement.

What a person expects

The step goes on under Claude. Status says it moved, and why, in Codex's own words. Nothing to do.

What happened on 2026-11-18

The step exited 1 and the Graph stopped. Recovery was lf task run by hand, into the same refusal, until the account reset.

What Codex wrote for that turn, from ~/.codex/sessions/2026/11/18/:

"error":{"message":"You’ve hit your usage limit. Upgrade to Pro (https://chatgpt.com/explore/pro), visit https://chatgpt.com/settings/usage to purchase more credits or try again at 3:36 PM.","codex_error_info":"usage_limit_exceeded"}

Codex named the cause. lf kept the sentence, threw away the name, and then failed to recognise the sentence.

Codex states the cause of every failed turn as a typed value. lf discards it at the decoder and guesses it back from the sentence. The sentence is the part Codex changes.

No app-server payload of a real limit was captured. The fold covers the gap; the first slice's test shows it either way.

What changed in the plan

  • The typed read moved from an optional second slice to the first, and from one kind to four.
  • "Not confirmed: that the failure carried usageLimitExceeded" is gone. It did; the record is quoted above.
  • The demo was wrong. task_graph_launch_tests.rs:2031 inserts the reason string into agent_limit_recoveries and never classifies it, so swapping its apostrophe would have shown nothing. The demo is now a scripted Codex app-server in agent_tests.rs that fails with the recorded error and finishes under Claude.
  • drive.rs's limited flag goes; a stale doc comment on subscription_limit_text goes.

Larger than this work

  • ops/release.rs classifies a failed agent by reading its words again, because CommandError carries no AgentFailure. Carrying the type through would delete that classifier's quota and credential lists.
  • Error.code as a typed field instead of a string with two meanings is a wire change mirrored in Swift, with its fixtures.
  • Once Codex is typed, the phrase lists serve Claude's headless path and untyped Codex errors. Which phrases are still reachable can't be told from this Machine's records alone.

Questions

  1. How much of Codex's type to read?
    1. All four observed kinds chosen for review
    2. Only usageLimitExceeded; the rest stay with the phrase lists
    3. None; ship the apostrophe fold alone, as the brief says
  2. When Codex says the model doesn't exist:
    1. Move to the next agent, like any unavailable model chosen for review
    2. Stop the Graph; a model that doesn't exist is a config mistake to fix
  3. Keep the apostrophe fold once the type is read?
    1. Keep it, as the fallback for an untyped sentence chosen for review
    2. Drop it; the type is the fix and one fewer thing reads sentences
  4. The string code on error events:
    1. Leave it; add the three new provider_* codes chosen for review
    2. File a Task for a typed failure field on the wire event
