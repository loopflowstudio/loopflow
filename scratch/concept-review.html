The decision is already implied by this change: the person's words are data, never shell. The published skill follows it. The builtin guidance that every Loopflow-launched run reads does not.

The mismatch

Handing off is taught three ways today:

skills/loopflow/SKILL.md (this change)
lf task create <<'EOF'
<outcome in the person's words: the first line is the title>
EOF
lf comment <ID> '<direction>'
skills/loopflow/README.md (this change)
lf task create 'validate session tokens on refresh'
rust/loopflow/src/builtins/LOOPFLOW.md (existing, every run)
lf task create --title "<outcome>"
lf comment <ID> "<direction>"

The last is the pattern Gen named INDIRECT_PROMPT_INJECTION. skills.sh never scans LOOPFLOW.md, so the rating doesn't move. The behavior does: a person's $(…) or " still expands in every launched agent's handoff.

Proposed

LOOPFLOW.md, proposed
hand it off: `lf task create '<outcome>'`, then `lf task run <ID>` …
steer with `lf comment <ID> '<direction>'`.

The positional REQUEST is the CLI's own concept ("what you want, in your words; its first line the title"), so --title drops out of the guidance. The alignment test asserts no <…> placeholder sits inside double quotes in SKILL.md or LOOPFLOW.md. Literal doc examples stay.

Not changing: the skill's heredoc (robust for any text), and the single-quote rule for lf comment, which has no stdin form.

Questions

  1. LOOPFLOW.md handoff form: (a) single-quoted positional, proposed; (b) quoted heredoc, matching the skill at more tokens per run.
  2. README one-liner: (a) keep -y dropped, so the installer shows its assessments and asks; (b) restore -y for a one-shot install and accept the harmless PromptScript failure line.
