Where a conversation's environment comes from

Area taken: everything LOO-986 covers, as it stands with #1992 merged and this branch's tmux repair on top (eb24a5d83c against origin/main). That is: what a provider's PATH is when a conversation is opened into a pane, what a person is told when it does not start, and which harness it runs on. The branch's own diff is one file, open/tmux.rs; the review is of the rule that diff completes.

Outcome: nothing to change in the code. The concepts line up. One sentence the product says is no longer always true, and it is a product choice (question 1).

The interaction, walked

An agent in a tmux pane has put its own shim directory first on PATH. It runs lf open --task ee1206 --tab.

tmux server's PATH→ new window→ lf session resume adds the tool directories→ holder→ provider
  • Normal. The provider's PATH is the tmux server's plus ~/.local/bin, ~/.opencode/bin, Homebrew, /usr/local, ~/.cargo/bin. The shim directory is absent (qa scenario 1; Rex and Herdr scenarios 7 and 8).
  • Failure. The provider is in none of those. The open exits 1 with the reason in --json, the pane keeps the error until Enter, and logs/lf.log has a line from each side (qa scenario 6).
  • Recovery. Install the provider, or start the host from a shell that can see it, and repeat the same command. Nothing is left to clean up: the failed pane closes on Enter and the Session is unchanged.

Counterexample tried against the rule "the window keeps the server's PATH": a caller pane whose own PATH has no tmux. lf resolves tmux on its repaired PATH before dropping PATH from the client, so the open still works (qa scenario 4).

The biggest mismatch: "not installed"

Before this branch, a tmux window took the caller's PATH, so a provider installed somewhere unusual (an nvm directory, say) was found whenever the caller could find it. That was the leak the acceptance line forbids. With it closed, a tmux server started by launchd or long ago can fail to find a provider the person runs every day, and the message tells them to install it.

Existing

'claude' is not installed. Install it with
`npm install -g @anthropic-ai/claude-code`,
then open `claude` to sign in; retry the
same command

Proposed, not built

lf can't find 'claude' from this pane.
If it is installed, restart tmux from a
shell where `which claude` answers.
Otherwise install it with `npm install …`

The proposed text needs no new state: the process already knows it searched PATH and failed. It touches every harness's hint and the tests and Swift strings that match "is not installed", which is why it is a question here and not a line in this plan. The case needs both an unusual install directory and a host server with a thin PATH; a server started from a login shell has the full one.

Passed over: letting the caller's PATH through when the server's cannot find the provider. It would make the message rarer and bring back exactly what verify failed, an agent's shims in front of the conversation.

Larger than this work

  • --focus and views. A conversation can have several views; focus knows one. Lining them up means recording each open view and choosing a live one, or asking the host which panes show the Session.
  • cmux was not driven: not installed on this Machine. Its request names a command and no environment; whether its client adds its own is unseen.
