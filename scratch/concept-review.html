Closing a query must release its answer

Next direction: iterate to implement. Bound reusable query answers and replace closed-query effects with persisted reload requirements. The existing design implies this; no product choice is open.

Biggest mismatch: query navigation now uses the shared projection, but every visited expression remains in its prepared set. Retired completions can leave exact effects in closed saved queries until those queries receive covering reads.

Existing → proposed

Existing in the working tree: destinations hold query identity; stamped subscriptions publish projected membership; Complete publishes before discovery/disk and follows the origin's displayed order. Recorded focused Desktop and iOS checks passed. This review ran no builds or latency trials.

Proposed: a mount pins a query entry, not every answer ever visited. Evict unused prepared entries. Resolved effects leave compact reload requirements for closed bases. Reconcile suspended prepared entries before reuse. Keep pending commands, navigation and native workspaces under their existing owners.

Proposed usage: Return to a recent view: usable projected content appears while refreshing. Return to an evicted or invalidated view: the same destination selects immediately and loads there. Retry stays in place. Closing never cancels the saved action.

Follow ownership through storage and execution

One shared working set serves both hosts. Live leases pin entries; closed entries may be evicted. Publication work follows that set, not navigation history. Keep confirmed bases, outbox, incorporation and scoped reload requirements in the existing SQLite transaction owner. Compact requirements by Machine/epoch/schema, repository, effect and declared domains, rather than retaining one per completion.

Do not remove the current retirement transfer before transactional invalidation replaces it. Preserve unresolved recovery and unseen creation results independently. Closing or eviction never infers refusal, releases an unresolved execution lane, acknowledges a result, resends a command or disposes a native workspace. Existing broad requirements keep their conservative meaning.
