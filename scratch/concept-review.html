Do the concepts line up? Auto-Ship as built

Area: how a Task gets taken the rest of the way without a person: lf ship, lf -b task run, lf task hold, the run reading Auto-Ship at each step, recovery, and the state labels every surface shows. Reviewed at HEAD 4c0481cb6e against the LOO-959 base 89943efba2 (89 files, +1,141 / −2,478).

One interaction, with its failure and recovery

lf ship LOO-12          # LOO-12 · code from human-review running as Graph process …  ships: yes
lf task status LOO-12   # shipping · Auto-Ship: on by Maya, 09:04
  (the run is killed)   # recovery starts `lf task run LOO-12`, under RUN_RESTARTS; it stands in at human-review
lf task hold LOO-12     # LOO-12 stopped shipping   (nothing killed)
  (run reaches pr land) # Waiting at pr land: not approved to merge (Maya stopped shipping). `lf ship` lands it.
lf ship LOO-12          # on again; same run path; lands

One carrier, one recovery loop, one restart rule. The run decides at each step by reading the mark, so a turn-on or a stop mid-run counts without restarting anything. The code matches: RunningGraph::stands_in and stopped_landing are the only two readers that change behavior, task_state_sql the only one that changes a label.

Biggest mismatch: the stop has five names

Existing
lf task hold LOO-12 → "LOO-12 stopped shipping"
Desktop: Stop Auto-Ship
Run: "not approved to merge (Maya stopped shipping)"
Status: "Auto-Ship: stopped by Maya"
Proposed (not built)
Output says what changed: "LOO-12: Auto-Ship stopped" / "Auto-Ship was not on"; the run says "Waiting at pr land: Auto-Ship stopped by Maya. `lf ship` lands it." Tests call task hold, not the alias. Whether the command stays hold is question 1.

This is copy, not model. The model under it is right: one mark, one writer per action, two readers. Nothing here needs another implement pass; gate can take the test alias swap.

What would break it

  • A released lf ship dying across the upgrade is not carried again (its pid lived on task_ship_events). Recorded in questions.md; lf task run recovers it.
  • A graph with no land step and a hand-merged PR now finishes its steps before completing. Recorded as a decision.

Questions

  1. The stop command: (a) keep lf task hold, change only the printed words to "Auto-Ship stopped"; (b) rename to lf task auto-ship off-style pair with lf ship; (c) leave as is.
  2. lf -b task run writing Auto-Ship on: (a) keep (recovery and later bare runs stand in); (b) -b stands in for its own run only and writes nothing, so only lf ship turns it on.
  3. The board's words: (a) keep shipping/Autonomous; (b) rename the state and section to Auto-Ship so one word runs through (separate Task, wire change).
