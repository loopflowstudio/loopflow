Proposed source contract

Application acquisition and policy → synchronous storage → saved records. The same direction holds in tests. Split mixed tests by behavior before relocating them; a single function can contain both owners. Keep the full application recovery scenario through public operations and test private SQL separately with prepared facts. Shared setup does not determine ownership.

Keep raw-schema and private transaction checks in storage. Keep CLI execution, repository/Wave bootstrap and process attachment in application tests. Storage fixtures use the prepared opener with explicit build, upgrade and key inputs. A dev-only inspection feature must not reconstruct application modules inside storage. Historical SQL fixtures retain one source; includes use each consuming crate’s manifest path. Generated schema fixtures follow the catalogue owner.

Keep non-exhaustive enums and the planned owner operations. Dispatch, recommendation and uncertain-receipt handling remain application decisions; unsupported values never invent a launch or completion.

Normal → failure → recovery

Proposed, not measured: a shipping edit should reuse storage; a Task-record edit rebuilds storage and application. A fresh root should reuse unchanged libraries. Measure these three cases separately, including CPU, memory and cache receipts.

A shell’s lost acknowledgment leaves its consumed receipt discoverable. The current application regression replaces an attachment and input and keeps once-only native usage on the original input with its original attribution; the replacement inherits neither, and native completion invents no command outcome. Private summary selection is checked separately beside SQL. Stale hand-back leaves both claims unchanged; the public retry returns both Tasks. Retain these scenarios during relocation. Fixtures must admit stale and contradictory facts so failure paths remain testable.

An interrupted upgrade keeps its transaction, export fences and existing refusal policy. A migration move retains ordered SQL bytes and staging age; refreshing only origin/main updates the catalogue. No new recovery lifecycle is proposed.
