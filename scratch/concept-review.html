2. Biggest remaining mismatch: origin-blind readers of unified collected history

What is wrong at HEAD (8fee50765d): SessionHistory now carries origin: Option<SessionOrigin> and machine_records already copies captures (context.json), provider turns (with Turn.context), and full agent_sessions rows (with start_failure). Yet three readers downstream of that unified model still treat every row as if it ran locally: (1) Desktop TelemetryDashboardView puts remote Linux repo paths (/home/lf/src/manabot) in the Mac Repo Picker and filters Modal rows out whenever the Mac repo (/Users/jack/src/manabot) is selected; (2) context_usage::step_context (used by lf session usage --context and Desktop TaskHistoryView) looks only in local <home>/runs and local history.turns, reporting context not recorded for every Modal step; (3) CopiedSession drops start_failure, hiding why a copied Session failed to start on the lost sandbox.

Before · Origin ignored after projection

Built at HEAD
SessionHistory (origin: Some(modal-1), repo: "/home/lf/src/manabot") ├─ TelemetryDashboardView.repos ──► ["/Users/jack/src/manabot", "/home/lf/src/manabot"] │ ├─ default Mac repo selected ──► Modal rows filtered out ($0.repo != Mac path) │ └─ Linux repo selected ──► loadCodebase() fails on macOS ├─ lf usage --task ID --context ──► reads <home>/runs & local turns → "no context.json" ├─ Desktop TaskHistoryView ──► rows show, context lines say "context not recorded" └─ lf session list (copied) ──► "unknown qa from modal-1" (drops start_failure)
  • Desktop Telemetry either hides Modal Task runs or tries to run lf repo tokens on a Linux path that doesn’t exist on macOS.
  • Capture files copied to <home>/machines/<origin>/runs go unread by --context and TaskHistoryView.
  • QA Run 2’s #1 remaining finding: a copied Session’s start_failure is already in machine_records but never shown.

After · Every consumer respects origin

Proposed in Plan §4.2
SessionHistory (origin: Some(modal-1)) ├─ store/sessions.rs ──► task_id/wave_id → local repository_plans.repo │ (fallback: origin repo string when unmapped) ├─ TelemetryDashboardView ──► local repos picker from origin == nil only; │ Modal Task rows match Mac repo; bare Modal rows stay visible ├─ context_usage::step_context ──► origin → copies_home + machine_records turn context │ (same for lf usage --context & Desktop TaskHistoryView) └─ CopiedSession + session list ──► extracts start_failure → "could not start: …"
  • Zero wire/DTO changes and zero migrations: reuses existing SessionHistory.origin, repository_plans, and machine_record_session index.
  • Local repo identity without losing origin path: worktree still shows where on Modal it ran; repo maps to this Machine’s repository when its Task/Wave lives here, fixing both Telemetry filtering and context_usage::budgets.
  • Truthful context & failure visibility: copied context.json, Turn.context, and start_failure surface everywhere local ones do.

4. Choices made for review

Both choices are reversible with zero wire-format or schema changes and are written into scratch/plan.md §4.2 for the next implement pass. Reply with a number and letter (e.g. 1b) to override.

1. How should a collected rental’s SessionHistory.repo relate to this Machine’s local repositories?
  • 1aChosen in plan §4.2 Resolve copied rows’ repo to this Machine’s repository_plans.repo when their Task or Wave lives here (keeping worktree as the origin’s working directory, and falling back to the origin’s repo string for bare runs), while building Desktop Telemetry’s local codebase picker strictly from origin == nil rows.
  • 1b Always keep SessionHistory.repo as the raw Linux path from the sandbox and add a separate repository-matching field to the DTO so Swift and Rust can map them independently.
2. Should lf session usage --context (and Desktop TaskHistoryView) read copied captures and turn contexts from machines/<origin>/runs and machine_records?
  • 2aChosen in plan §4.2 Yes — honor SessionHistory.origin in context_usage::step_context (and copied silences in context_cost.rs) so Modal steps show their real assembled/carried/tool-output breakdown instead of bogus missing-capture gaps.
  • 2b Leave --context local-only and report every copied rental step as missing its capture.
