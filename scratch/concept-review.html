Existing → proposed

Existing workspace: shared persisted receipt ordering and read-only planning observation, Desktop recovery presentation and both-target receipt tests. Shared Work projection and mobile recovery presentation remain unbuilt.

Start A → attachment fails → planning finishes → select B → restart.
Proposed: A keeps Retry opening for the same Session; its planning warning clears; B stays selected; lagging lists retain A’s pending effects.

Proposed usage: “Planning delivery and opening your conversation recover separately. Retry opening returns to the same conversation. If confirmation is unavailable, the saved request stays available to inspect.” Existing recovery skill instructions remain valid.

Follow the interaction through recovery

Model: use the existing effect/stage registry to distinguish unresolved, confirmed resolved and unavailable evidence for each applicable effect. Inapplicable comes from the registry, never from a missing reading. Keep original results and diagnostics.

APIs: live receipt status can update only its correlated obligation. A delivered planning change cannot resolve attachment, Graph or filesystem recovery. Unclassified failures stay inspectable until their owner establishes resolution.

Persistence: presentation acknowledgment, domain recovery and query incorporation remain independent. Retire only after their applicable obligations resolve. Cache replacement and per-query incorporation persist with the outbox; no second lifecycle ledger.

Failure: losing planning evidence or replacing the epoch retains inspection/recovery. Missing evidence is not an all-clear. Old receipt ordering cannot authorize replay.

Counterexample: reverse attachment and planning resolution, then restart with an older saved reply, a current status and a lagging list/count in each order. Clear only the covered recovery action; apply each query effect once. No reply changes later selection or submits another command.

Test gap: the current live-order test compares a lagging stamp with a fence; it does not send Work through a projection or prove navigation. Add actual reducer and production presentation checks on Desktop and mobile.

Native latency remains unmeasured. This concept-review changes design guidance and this page only; interrupted source edits are retained.
