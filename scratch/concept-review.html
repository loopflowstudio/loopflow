Seeding a new worktree's Rust target

LOO-922, full post-build concept review against base f4b74bc8eb at head c675ac0b77 (2026-11-22). Area taken: the whole life of a worktree's Rust build outputs for a Loopflow developer and Machine agents — cache install, worktree creation (cold or seeded), source selection and quiescence, first and later builds, benchmark isolation, status readout, and reclaim by lf wt prune --builds.

Outcome: the plan changed. The built implementation matches the first review's seed layout (.fingerprint, build, deps, atomic rename, no knob), but the three follow-up patches (c67fb141a6, 5336a5ebaf, 5e305e63c7) all worked around one missing concept: the code does not distinguish a built target from an unbuilt seed. Its tie-breaker (not .loopflow-seed.exists()) breaks in steady state once active worktrees start seeded, and its lock fix creates Cargo's private lock files inside unbuilt siblings. A second mismatch: test_loop.py creates worktrees through the hook without discarding the seed, violating the "cold target = rm -rf target" contract.

The interaction

You (or lf, preparing loopflow.ready or a Task checkout) run git worktree add ../x main. The installed post-checkout hook fires with a null old OID, finds the most recently built quiet sibling worktree, clones its .fingerprint, build, and deps into target/debug.seeding, and atomically renames it to target/debug. Your first cargo build -p loopflow --bin lf compiles only the workspace crates (7 units instead of 256 when Cargo.lock matches). uv run python scripts/build_cache.py status prints which built sibling and commit produced the seed.

Failure & recovery: every built sibling is mid-build, none exists, or the target volume cannot copy-on-write clone → the hook stays silent, target/ is absent, status prints seed none, and Cargo builds cold as before. Partial clone failure deletes debug.seeding and never exposes a half target. To force a cold build in a seeded checkout: rm -rf target.

Biggest mismatch: "built target" vs "unbuilt seed"

Live state observed on this Machine during review (16 worktrees with target/debug/.fingerprint):

1795415951  built    loopflow.534d53-at-least-in         locks=[all 3]   .loopflow-seed=absent

Every one of the 14 built worktrees holds Cargo's three lock files; both unbuilt seeds hold none. Meanwhile, loopflow.loo-1068 is already both built and seeded — which is the steady state for every active worktree once the hook is installed.

After PROPOSED

# Only targets Cargo has built can seed another worktree
def _is_built(debug: Path) -> bool:
    return (
        all((debug / e).is_dir() for e in SEED_ENTRIES)
        and any((debug / lock).exists() for lock in CARGO_LOCKS)
    )

# One rank, no fake tie-breaker
key = lambda t: (t / "target/debug/.fingerprint").stat().st_mtime_ns

loo-1068 (built)   -> eligible, locks exist, truthful commit
ready    (unbuilt) -> skipped, untouched, never false provenance

One concept, one predicate. An unbuilt seed is never selected, never mutated with lock files, and never recorded in another checkout's .loopflow-seed. copystat on .fingerprint stays so that a seeded worktree, once built, still ranks by when it last gained a unit. _quiescent still locks all three CARGO_LOCKS on the built candidate, closing any race with Cargo's first lock creation or across Cargo versions.

Counterexamples checked

  • Cargo starts its first build in an unbuilt seed at the exact moment another worktree runs seed: before Cargo creates a lock file, the unbuilt seed is excluded by _seed_sources; once Cargo creates its first lock file, Cargo holds a lock on it before touching .fingerprint/build/deps, and _quiescent takes all three CARGO_LOCKS non-blocking, hits EWOULDBLOCK, and skips it. Neither side can race.
  • Only built worktree is deleted (or busy), leaving only an unbuilt seed: the new worktree falls back to a cold build (with sccache still warm). Giving up chaining off an unbuilt seed in that corner case is the right trade to keep siblings read-only and provenance truthful.
  • Older Cargo without fine-grained locking (creates only .cargo-lock): checking any((debug / lock).exists() for lock in CARGO_LOCKS) accepts it as built while still excluding every unbuilt seed (which has none).
  • Aborted partial build ranked newest (observed live): loopflow.8cb300-get-rid-of stopped after 11 .rlibs (342 .fingerprint dirs) and seeded loopflow.ready because its .fingerprint mtime was newest. Cargo still builds the missing ~245 crates safely. Avoiding a repo-specific crate-count threshold keeps ranking simple and portable; flagged as Question 3 below.
  • Benchmark isolation (test_loop.py): without removing tree / "target" after git worktree add, rerunning LOO-921's private-cache benchmark with the seeding hook installed silently seeds targets from random siblings. Removing tree / "target" keeps one "cold target" mechanism across docs and benchmarks.

Questions

Choices made for review are marked (chosen). None are irreversible once shipped.

  1. Can an unbuilt seed (such as loopflow.ready) be used as a seed source for another worktree?
    1. No — only targets Cargo has actually built (holding a Cargo lock file) are seed sources. Unbuilt seeds are untouched and provenance always names a built sibling.
    2. Yes — allow chaining off unbuilt seeds, create Cargo lock files inside them during cloning, and copy the original built source's provenance record forward.
  2. How should test_loop.py get cold targets now that the installed hook seeds new worktrees?
    1. Delete tree / "target" right after git worktree add, matching seed_probe.py and the no-knob contract.
    2. Add an opt-out environment variable (e.g. LOOPFLOW_SEED_TARGET=0) to skip the 2–5 s clone in benchmarks and scripts.
  3. Ranking built siblings when an aborted partial build has the newest .fingerprint mtime:
    1. Keep newest .fingerprint mtime; Cargo compiles whatever units the partial build lacked.
    2. Add a completeness heuristic (e.g. require a built binary or minimum artifact count) to skip aborted builds.
