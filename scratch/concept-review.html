Concept review: links in Loopflow Sessions and Desktop

Task LOO-1126 Stage: post-implementation review (Passes 1–5 built) Base: fd8dce986d · HEAD: 7a40103e6a

Area reviewed: clickable links across Loopflow Sessions and Desktop — from held-terminal identity (transport/registry.rs), through Ghostty hover, cursor, focus, and click callbacks (GhosttyManager, GhosttyTerminalView), hyperlink parsing and file/Work routing (TerminalHyperlink, ops/task/snapshot.rs, work/link.rs), into Desktop's pane, Files, Dashboard tile, and Work surfaces (WorkspacePanesView, SessionsView, MultiplexerStore, TaskFilesStore, FilesBrowserState, TaskFilesView, DashboardView, LoopflowApp, TaskBriefView, MarkdownBlocks, TaskHTMLView, and LoopflowiOS). Reviewing the whole area on 7a40103e6a against base fd8dce986d confirms Pass 5 closed all four seams from the previous review; one cross-surface router split (deferred) and three edge-case mismatches in the built code remain.

What is built vs. what waits

  • Built and committed across Passes 1–5 (a12082957b, 0552209e91, e507237447, 04c2f98af7, 98c1057421, 75d691696a, 7a40103e6a): Ghostty intercepts OPEN_URL (always returning true), MOUSE_SHAPE, and MOUSE_OVER_LINK with link-previews = true; paused and unfocused terminals support ⌘-hover; hover preview, cursor shape (.pointingHand vs. .operationNotAllowed), and click routing share TerminalHyperlink; Rust's WorkUrl::parse is the single parser for loopflow:// links (Swift's duplicate isWorkAddress was removed in Pass 5); web and mail links open in default apps; custom schemes confirm in TerminalExternalLinkSheet; Task checkout files open in Files at #L<n> locally and remotely in one read (with snapshot.rs distinguishing directories from missing files); zoomed terminals and Dashboard tiles both restore Session + Files side-by-side with keyboard focus on the terminal; non-Task panes and pre-move local shells fall back to safe local documents/folders; held terminals set TERM_PROGRAM=ghostty and drop TERM_PROGRAM_VERSION.
  • Product choices implemented headless, still awaiting confirmation: side-by-side unzoom on file click (Q1), Files pane for active Task checkouts + safe default-app fallback elsewhere (Q2), unconditional TERM_PROGRAM=ghostty on held terminals (Q3), accepting any remote file:// hostname inside the remote Task's checkout (Q4), and shipping terminal links ahead of Brief/Markdown/review-page unification (Q5).
  • Remaining mismatches on 7a40103e6a: Desktop still has three incompatible in-app link routers outside terminals; the terminal hover pill sticks whenever Desktop loses key focus (including right after ⌘-clicking an https:// link to Safari, ⌘-Tabbing away, or opening the external-scheme confirmation sheet); Pass 5's selectionHasSnapshot flag can leak across Task switches when the clicked remote file was already open in Read mode; and a remote shell opened before its Session refuses checkout links even when Files already learned the remote checkout path.

Questions

None of these choices lock in an irreversible data format; all can be adjusted later in Desktop or server code.

1. Built today: when your Session is zoomed full-screen (or you click from a Dashboard tile) and you ⌘-click a checkout file link, Desktop clears zoom so the terminal and Files appear side-by-side and keeps keyboard focus in the terminal. Keep this?

Showing both panes keeps the agent output visible beside the file you just jumped to. Replacing zoom with full-screen Files hides the Session while you read; flipping only the tile stays on the Dashboard without entering the Task.

2. Built today: ⌘-clicking a file inside a Task's active checkout opens it in Desktop's Files pane at #L<n> (locally or remotely), while Repository/Wave Sessions and old pre-move local shells open safe local documents and folders in the macOS default app (still blocking scripts and executables). Keep this?

Opening Task files in Files keeps line numbers, safely reads scripts like scripts/test.py, and works on remote Machines. Opening all local files in the default app matches Rex, but drops line numbers, must refuse scripts, and cannot open remote files.

3. Built today: every held terminal reports TERM_PROGRAM=ghostty (and clears TERM_PROGRAM_VERSION), even when started from Rex, Apple Terminal, or tmux. Keep always setting ghostty?

Always advertising ghostty makes clickable links work consistently no matter where the Session started, and Loopflow's Rex host detection uses REX_SESSION/REX_BLOCK rather than TERM_PROGRAM. Preserving caller TERM_PROGRAM keeps rex when launched from Rex, but leaves Sessions started from Apple Terminal or tmux without clickable links.

4. Built today: in a remote Task pane, links like file://mini.local/home/jack/wt/src/lib.rs (from ls --hyperlink or rg) open in Files whenever the path is inside that Task's remote checkout, regardless of the URL's hostname. Keep this?

Files reads only from the Task's owning Machine over Loopflow's server and never connects to the hostname in the URL. Local panes still require this Mac's hostname.

5. Task Briefs, rendered Markdown files, and HTML review pages still handle loopflow:// and file:// links differently from terminals (sending Brief/Markdown links to macOS Launch Services and letting review pages navigate non-web schemes). Ship terminal links first and unify the rest in a follow-up Task?
