The mismatch this change removes

Before: each operation needed a separate clock, checkout or probe policy to describe when its answer might change. Adding a fact to a read could leave its live view asleep.

Implemented: Cache::capture records the facts the reading touches. Dependencies::changed follows their revisions. Bounded workers inherit that reading. The checkout watcher, Git retention and Session probe are replaced by this shared path.

The cache holds answers, including errors; SQLite holds Work. Only SQLite joins share a pinned snapshot. External observations arrive independently. Existing store revisions still wake reads broadly; narrower store subscriptions and screen-shaped reads remain outside this Task.

Normal, failure, recovery

Normal: an external edit changes an observed Git answer, wakes its dependent view and emits a frame only if the selected result changed. No store write is needed.

Failure: an observation can become an error or report a missing checkout. That answer has a revision too. Local observations continue independently of GitHub polling.

Recovery: a later successful observation advances the revision. A surviving reading follows it; a served watch that ended with unavailable follows the existing client reopen path. Restart discards observations, not Work. Commands are never replayed to recover a reading.

What to show next

Pending gate: restore a missing checkout, recover a failed provider and cross a quiet deadline without a store write. Exercise actual reads. Also show that unrelated facts do not rerun them and unselected changes emit no frame. These counterexamples test the existing design; no additional behavior is proposed.
