Counterexamples verified

  • lf task auto off while running before land vs after land: toggling off → on → off during a live build moved the row Active → Shipping → Active without disturbing the build; past land (at verify or end) it stays Shipping.
  • Pause at a landing stop (auto: off): TaskGraph::landing_stop keeps status reading Waiting at land while the Task is paused instead of calling the Graph finished; unpause restores Waiting at land: auto is off ….
  • Paused Task whose open conversation asks a question: condition is Clear (out of Now, no dirty-worktree noise), while TaskRowStatus checks program first and shows Blocked + the question on the sidebar row.
  • Legacy captured Graph with interactive: verify after land: needs_review resets at land, so before landing it reads Shipping and once parked at interactive: verify it returns to Active.

5. Open questions

  1. Clicking Unpause on Mac / iPhone when paused mid-run (or with auto: on):
    a) Built for the Working-groups demo: Unpause sends plain unpause (run: false) everywhere; clicking Run restarts the build.
    b) In the Task bar V4 pass, have Unpause send run: true when paused mid-run without a failure (and run: false when paused at an interactive step), matching V4’s Resume button.
  2. Inferred Available · inferred on paused sidebar rows (spotted in QA):
    a) Built behavior: keep SessionProgramStatus uniform across all Working rows (so an open idle Claude session without a reporter reads Available · inferred under the Paused group header, same as under Active).
    b) When task.lifecycle == .paused, show explicit program reports (Blocked, Error, Busy, reported Available), but let Paused win over inferred availability.
  3. WorkingGroup::Shipping after merge / at end:
    a) Built choice: once past ship-review, a landing Graph stays in Shipping through deliver, automatic verify, and end until Complete.
    b) Move a Task at end (merged & verified, waiting only to be completed) back to Active.
  4. Named PR limits:
    a) Built choice: document Codex 0.171.0 separate-session tools and post-send move retry as PR limits.
    b) Add a Codex PreToolUse wrapper / source-queued move pause before landing.
