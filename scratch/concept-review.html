Keys came in as the stand-in for the deferred contextual controls. Today it is the only software way to send Escape (interrupt an agent) or to arrow through a provider menu. Typing a digit and Return already answers numbered prompts. No recorded review approved it, and the working design had listed it as part of Jack's reduced row. That record is now corrected.

Actions → concepts → APIs

Answer a prompt. Typed input to the Session owner, through the existing input claim. It works without Keys for numbered choices.

Interrupt the agent. Escape byte through the same claim. Without Keys or a Stop control, there is no way to send it from the software keyboard.

Contextual choices and Stop. These need program-state semantics from the backend that don't exist yet (remaining work item 5). No API change follows from any answer below.

Challenge

Normal path: Claude asks to trust a repository. You type 1 and Return, or open Keys and press Return. Failure: the agent runs away mid-task. With (b) below you can't stop it from the phone, only watch. Counterexample to (a): Jack's steer said a generic shell needs the bigger bar and an agent Session doesn't. Keys brings that bar back one tap away.

Questions

  1. Until contextual controls exist: (a) keep Keys in the default row as the interim · (b) remove Keys and answer prompts by typing only, with no software interrupt · (c) remove Keys and add only an Escape/Stop control to the row.
