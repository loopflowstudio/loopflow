2. The Biggest Remaining Mismatch — Base, Built at HEAD, and Recommended

Biggest mismatch lf server already computes both the tab title and the Task workspace name — then throws the workspace name away so every cmux/tmux viewer has to pin its own SQLite connection, poll twice a second, fail permanently on one lock, and stay broken on remote Machines.

At terminal_title.rs:869-873, output_title calls session_title(store, &session), receives both title.names.terminal and title.names.workspace, drops workspace, and sends only OSC 0. Because of that one drop, every open cmux or tmux tab keeps a second title reader alive in the viewer process — holding a pinned SQLite connection, waking every 500 ms to run store.revisions() (unmeasured by server_idle.py), silently disabling itself forever on a single SQLITE_BUSY, and failing completely on lf --machine remote sessions.

4. Counterexamples & Failure Modes Verified Against HEAD 4f201433

1. Streaming text bumps observed_at without moving sessions — VERIFIED FIXED at HEAD. TitleReader overwrites watch.next_deadline on every read even when the title text did not change, and reader_rearms_deadline_when_observed_at_bumps_without_revision_move proves it.
2. Write commits while a sweep is in flight — VERIFIED SAFE at HEAD. run_title_reader reads current_revisions at the start of the sweep (terminal_title.rs:690) and saves it to seen_revisions at the end (L721). A write committed mid-sweep delivers a higher revision from store-observer, which differs from seen_revisions and schedules one follow-up sweep after the 500 ms throttle.
3. Single transient SQLITE_BUSY in cmux/tmux viewer or direct chat — BROKEN at HEAD. TerminalTitle::refresh (terminal_title.rs:352-355) treats any StoreError identically to a broken host command and clears self.host = None. Once tripped during a write spike, that tab stops updating cmux/tmux titles permanently. Fix: retry transient store errors with backoff (never drop self.host for SQLite errors); if Q1a is adopted, held viewers never touch SQLite at all, and direct chats get the retry fix.
4. Remote cmux workspace name vs hand-edited workspace name under Q1a — CHECKED. Under Q1a, the server sends Event::Title { terminal, workspace: Option<{ identifier, name }> }. The viewer runs HostNames::shown_workspace() and WorkspaceName::replaces(&shown, published) locally against the person's cmux — so hand-edited cmux workspace names are preserved identically to today, and the server never needs to know whether a viewer is in cmux, tmux, Ghostty, or Desktop.
5. Replaced attachment on a held terminal under Q1a — CHECKED. When lf resume moves a Session to a new terminal, output_title sees attachment.lf_process_id.is_none() (or terminal_session returns None) and returns Ok(None), so TitleReader sends no further OSC 0 or Event::Title to the old terminal. Hosted also closes the old terminal with CloseReason::Replaced, restoring tmux automatic-rename on viewer drop.
6. Unnecessary SQLite read when last viewer detaches — FOUND at HEAD. RevisionFollow::drop calls entry.waker.wake() (read_stream.rs:929). observe() wakes up and calls read_store_revisions(database) at L1079 before pruning dead entries at L1086-1131 — doing one needless DB read every time the last viewed terminal closes. Pruning dead entries first skips it completely.

6. Open Questions

Every question below can be answered directly (e.g. 1a, 2a). Everything in the server hot path is already built and committed at 4f201433; the TerminalTitle lock-retry bugfix and read_stream dead-listener cleanup apply regardless and do not need a vote.

1. When you view a held terminal in cmux or tmux — locally or on a remote Machine — should lf server send its tab and workspace titles over the terminal stream in this PR, or keep local viewer polling?
  • 1a (Recommended): Send titles from lf server over the terminal stream. Every open cmux/tmux tab stops holding a database connection and stops polling twice a second, and remote lf --machine sessions in cmux/tmux start renaming their tabs, windows, and Task workspaces live just like local ones. Irreversible once released: bumps the held-terminal wire protocol from 4 → 5, so already-open terminal views reconnect/re-exec once cleanly after installing the new build.
  • 1b (Ship current split, defer protocol bump): Keep local cmux/tmux tabs polling the local database's revision counter every 500 ms (after fixing the transient-lock freeze and removing the pinned connection), leave remote lf --machine cmux/tmux tab/workspace renames unsupported for now, and avoid bumping the held-terminal protocol version in this PR.
2. Now that Pass 1 measured the shared title reader at 0.39% CPU under heavy writes (5 open tabs + 25 hidden ones), should we keep that single shared reader or build a separate slim title query?
  • 2a (Recommended — keep what is built): Keep the single shared summary reader. Tab titles and CLI/Desktop Session lists can never disagree on when a Session is Available, and 0.39% CPU under 20 writes/sec leaves huge headroom for typical open-tab counts.
  • 2b (Optimize for 20+ simultaneously visible tabs): Add a dedicated batched query that reads only the four title fields across all open tabs in one pass, trading a second query alongside session_summary for lower CPU if you routinely keep dozens of tabs open and visible at the same time.
