One interaction, including failure

Open a remote Task shell and set a variable. Hide, quit or lose the connection; reconnect attaches to the same execution. A lost startup acknowledgement does not launch a replacement. Close ends ordinary jobs; Undo restores history. A returning Task Session viewer cancels pending cleanup before another sweep; already-ended execution stays ended. Remote failure never opens a local prompt.

Desktop README: “The destination shell runtime carries terminal bytes and Close status; it is not a GUI action and has no Desktop action-result schema.” Existing usage and skill guidance need no change.

Review outcome — no further design change
  1. Is another product decision needed? No. Shell ownership, viewer retention, Close and recovery follow the accepted decisions.
  2. What could invalidate the implementation? Replayed startup, a local prompt after remote failure, or a queued automatic Close surviving renewed Session viewing. Existing focused checks cover these paths; this review inspected source and did not rerun execution suites.
  3. What remains unproved? Native Desktop/Rex and physical remote-Machine behavior. Broader checks and publication remain with the Graph; demonstration stays at interactive demo.
