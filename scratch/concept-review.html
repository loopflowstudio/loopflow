The mismatch

Now — every Claude/Codex Stop hook (timeout: 10) runs:

apply_pending_move_blocking(home, thread)
  tokio::Runtime::new()                    // every Stop, move or not
  open_store(...)                          // 15s busy wait, not open_for_hook's 1s
  take_session_move(id)                    // row deleted here
  new_thread(...)
    stop_session_agent(...)                // SIGTERM, then SIGKILL, the agent running this hook
    append_input(...)                      // never reached if the hook dies first

Failure: the host kills the hook, or its 10s timeout runs out, before append_input. The Session is stopped and has no continuation. The move you asked for is gone, and the only trace is a warning in lf.log.

Proposed — the hook only checks whether a move is pending; the applier runs outside the turn:

Stop hook:  open_for_hook → pending move?  no → return
                                           yes → spawn detached lf applier, return
            store error → recording gap, turn continues
Applier:    wait for the turn to end → new_thread (same path as idle)
            → delete the session_moves row only after append_input succeeds

Recovery: if an apply fails or is killed, the row stays and the next Stop tries again. What carries over: the Session's identity, its history, and the "after their turn" promise in the docs. What changes: a hook never stops its own host.

Small addition: the drain line in docs/subscriptions.md also says how to undo it (lf account set claude jack@ --routing automatic).
