Biggest mismatch: what the restart count counts

Before (built)

starts_since_turn: the pass adds one per start; a finished turn sets it to 0. A person's lf resume leaves it. After a quit and resume, the next deaths have fewer starts left, and the "attempt 3" line describes deaths the person already answered.

Proposed

The count is the pass's starts since the conversation was last vouched for: a finished turn or a start the pass did not make. A start whose request is not recover:… sets it to 0 and clears last_started_at's backoff. The column keeps its name; the rule in docs/sessions.md gains one clause.

Counterexample tried: a person who resumes into a conversation that crashes on start. It dies, the pass starts it up to 5 times, then waits for them — the same as a fresh conversation. Nothing loops.

The two smaller ones

One waker. restart_runs returns its soonest run next_at, and the watcher waits for the earlier of that and the conversations'. Runs come back on time, like conversations.

A promise only when someone keeps it. With no server answering, status prints died 15:31 (exit 137) · starts again when the server runs (lf::commands::session line 472), not "starting again".

Recorded, not acted on here

  • A resume with no transcript (killed before its first turn) fails five times; a fresh start would serve better. Real Claude: unchecked.
  • The SIGTERM quit window and holder_stopping: unbuilt until real Claude is seen exiting 0 on TERM.
  • Delivery still waits on LOO-953's Session columns; two reads join processes until then.

Questions

  1. A person's lf resume of a died conversation: (a) resets the restart count (chosen) · (b) keeps it.
  2. With no server running, the line says: (a) "starts again when the server runs" (chosen) · (b) "starting again" as now · (c) nothing about starting.
  3. A died conversation with no transcript: (a) leave as is, recorded (chosen) · (b) start it fresh instead of resuming.
