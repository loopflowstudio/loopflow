The mismatch

Step through a Task that edits README.md and a PNG. The README reads as a redline, so its line hunks aren't drawn, but they are still the stops. ] sets the scroll anchor to a hunk id the redline doesn't carry, and scrollPosition(id:) doesn't move. The image has no hunks, so a change that touches only the image reads "0 changes in 1 file", "No changes", "+0 −0".

Recommendation, chosen for review

A rendered file is one change. The stops come from what the stream shows: a file the store renders is exactly one stop, path#rendered, carried by its rendered view; with Source on, its hunks are the stops. A binary header drops "+0 −0". Swift only: ReviewDiff.stops stays the patch's, and the store gets the one function that turns a shown diff into stops, read by the title, position, step and the sidebar.

Passed over: one stop per changed redline block. It is finer, but it needs both sides read before the count is known, so the count would jump as files near the view — what theChangeCountWaitsForEveryFile just removed.

Written into scratch/plan.md under "Concept review after the build", with its test.

Questions
