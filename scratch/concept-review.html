The server now wakes idle managed conversations with Task updates and leaves steers for the next turn. A person's Task comment is both, so it arrives twice under two names. Question 1 decides which one wakes.

Concepts

Built. Steer = direction, delivered at a boundary. Task update = progress, delivered at a boundary or pushed by the server's wake. A direction comment is saved as a steer and read as a Task update.

Proposed. Each thing a person or Graph does has one kind. Comments with a steer are direction only; Task updates are runs, steps and non-direction comments. The wake delivers whatever the conversation has pending.

Questions

  1. Do steers wake an idle managed conversation?
    1. Yes, through the same server path; a comment wakes as direction. docs/sessions.md drops "A steer starts no turn".
    2. No; a comment on an idle Task conversation waits for its next turn (less waking than before this branch).
    3. Task comments wake; lf session steer and lf task steer wait.
  2. Bare conversations: the steer says "Deliver at the next boundary only for bare or unreachable conversations"; the brief says "Bare Sessions get none of this".
    1. Bare get nothing (built).
    2. Bare get next-boundary updates; their hooks ask the server again.
