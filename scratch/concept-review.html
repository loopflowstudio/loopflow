6. Open questions for review

Answer with a number and letter (for example, 1a 4b). All chosen options are already built on HEAD.

1. When lf land hits a real merge conflict, should your scratch/ notes stay in the checkout until the conflict is resolved?

  • 1a (Built): Yes — notes stay on disk so the conflict resolver can read your plan, and aborting the conflict leaves your branch and notes untouched. Notes clear only when the merge finishes and is about to push.
  • 1b: No — clear notes before attempting the merge, then clear again after conflict resolution. The resolver cannot read scratch/plan.md on disk and an aborted land leaves a "Clear added scratch files" commit behind.

2. Should lf scratch clear stay as a command you can run by hand?

  • 2a (Built): Keep it — useful if you want to trigger full CI on a manual lf pr publish without arming auto-merge or submitting.
  • 2b: Remove the command — only lf land, lf arm, and lf pr submit clear working notes.

3. Should the unused queue Graph disappear with gate?

  • 3a (Built): Delete queue (and .lf/graphs/finish-queue.yaml) — without gate it is only compress + refresh and nothing runs it.
  • 3b: Keep queue as compress → refresh.

4. Should the 3-line "Spend compute deliberately" principle stay in LOOPFLOW.md (included on every agent run), or live only in the individual skills that run tests?

  • 4a (Built): Keep it in LOOPFLOW.md — every agent run (including ad-hoc sessions) gets the reminder to run narrow checks and leave broad suites to CI.
  • 4b: Remove it from LOOPFLOW.md and skills/loopflow/SKILL.md (and their goldens) — keep the rule only in implement, compress, debug, qa, and ci-fix so LOOPFLOW.md stays leaner on every run.
