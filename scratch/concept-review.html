The biggest mismatch: the Task workspace block

The qa finding that settled this Task was that a cheap model handed line counts and a command reads the right file. A worker on a Task is the agent lf launches most, and it is handed neither. This is the block this review's own run received, for this branch:

What it would take. A fourth ChangeRange, the recorded base against the worktree: git diff --numstat -z <base> plus the untracked listing Change already has. task_workspace_context keeps its missing-base message and renders the section; its own list, its sentence and the diff_snapshot call for the prompt go. A worker with diff: true is then shown one change, not two.

Tested againstWhat happens
NormalThe worker sees which files carry the change and reads those.
FailureThe recorded base is gone: the existing sentence ("do not treat the missing diff as an empty change") stays as it is.
RecoveryThe block is rebuilt on the next turn from Git; nothing is stored.
Counterexample keptThe per-file state (committed, staged, unstaged, untracked) is lost unless it becomes a mark on the line. Untracked already is one. Whether an agent uses the other three is not known; the plan's exclusion gave this as a reason to leave the block alone.
Counterexample keptThe comparison today goes through diff_snapshot, which is also what Desktop and lf task diff read, with its 1 MB cap. The prompt would stop sharing that read, which is the point: the cap is why a large Task says "truncated" today.

Also larger than this work

  • --diff files. Removing it means dropping the diff_files setting, DocumentSource::Diff, the gather pass that reads every changed file, and the changes branch in ContextDelivery::prepare. .lf/config.yaml is read by the released lf too, so the key stays readable for a release.
  • The default branch in gather_branch_change. Ask Git before comparing the name, and decide whether an unreadable base is "no change" or something the agent is told.
  • The list has no ceiling. 237 KB at 3,001 files, about 80,000 tokens. Complete, as the Task asked. A bound would collapse a directory of several hundred files to one line with a count.
  • lf task diff's 1 MB whole-comparison cap: a person-facing read; its fix is a per-file read in the served API.

Questions

  1. The Task workspace block.
    1. Its own Task: a fourth range on Change, the block renders the section. Recommended, not filed.
    2. The same, with committed / staged / unstaged kept as a mark on each line.
    3. Leave it; workers have the checkout and find their way.
  2. --diff files.
    1. Its own Task: remove it, --diff becomes on or off. Recommended, not filed.
    2. Keep it as the path-only option.
  3. The read command for a renamed file.
    1. A second command line with both paths, only when the change holds a rename. Built.
    2. List and read with --no-renames, so one path always works and a move shows as a delete and an add.
  4. The list has no ceiling.
    1. Leave it complete. Built.
    2. Collapse large directories to one line with a count.
  5. The PR writer follows yolo; the commit writer always skips permission prompts.
    1. Leave both. Built.
    2. Give the PR writer the same floor.
  6. docs/config.md used to say "Point to Git inspection commands rather than inlining a frozen patch". Did that sentence mean:
    1. never put patch text in a Skill's prompt, in which case the block should carry only the list and the command;
    2. don't rely on it staying current, which the read command covers. Assumed.
  7. Untracked files in an uncommitted change are listed with "no patch: read the file".
    1. Keep. Built.
    2. Inline small ones as added-file patches.
