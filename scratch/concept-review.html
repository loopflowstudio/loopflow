Who to wake now survives a restart. What to tell them does not: the watcher's first reading is a baseline, so news recorded while no server ran waits for the person to type. The baseline guards against nothing. Claims already skip what a conversation heard. Deleting it is the change.

The watcher

Built.

Ok(revision) if seen.is_none() => seen = Some(revision),   // baseline
Ok(revision) if seen != Some(revision) => { seen = Some(revision); wake_idle(open, None); }

wake: open Claude's inbox → claim steers → claim update → send if any text.

Proposed. Every reading that differs from the last, the first included, wakes. wake: read steers and update → nothing, return → open inbox → claim → send. The concepts don't change: an idle conversation is a managed Session on a live AgentProcess whose last turn yielded, reached by its recorded endpoint or inbox key.

Why the baseline can go

task_updates::claim compares the Task's state with the last update recorded for that Session and records dispatched before sending; pending steers stay pending until a batch is confirmed. A start-time wake therefore carries only undelivered news. Conversations launched before this build have no inbox key or endpoint recorded and aren't candidates until their next managed boundary, so an upgrade wakes nobody spuriously.

"Keep idle waking: a Task update that lands while a managed conversation is idle should still wake it, as today" (Jack Heart, Task comment 164b4dd8)

--moment task-updates stays a no-op for hooks in live conversations; its comment should name the Task that deletes it, filed at delivery.
