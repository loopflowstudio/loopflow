The experience, before → proposed

Existing sequencing; launch has a partial Desktop implementation

Command → wait → refresh → change screen. Cached selection still performs preparation; Wave navigation delays selection by 120 ms. Mobile has separate submission and view-owned conversation lifetimes.

Start → submitted words appear in the conversation immediately → persist/send → bind real Task and Session → attach in place.
Complete → row disappears and next Task opens, or an empty view → confirm in background.
Select recent Task → highlight + retained content → refresh.
Expand Wave → arrow + cached children, or local loading → populate.

Completion navigation is answered. Neither a failed command nor a late refresh changes a later deliberate selection.

Try to break it

Normal: a receipt binds the operation to real IDs. Each affected query keeps its overlay until a complete reading covers the commit fence. A current no-Graph result restores ordinary Task controls.

Failure: completion refusal removes only its overlay and restores membership from the latest base. Success followed by refresh failure keeps pending confirmation. Attachment failure shows Retry opening beside Inspect, using the same Session.

Recovery: save before send; restart loads outbox layers before cached lists. Lost replies look up the same operation on its original Machine. Uncertain execution is never blindly replayed.

Counterexamples: A completes, then is reopened; A→B→A replies reorder; expand→collapse finishes loading late. Preserve the later intent. Unrelated revisions, partial pages, native readiness and old Task frames cannot retire an operation.

What changes underneath

Proposed; the cross-platform rewrite is unbuilt

One store in swift/Loopflow owns normalized facts, ordered projections and transactional persistence. Rust supplies durable command receipts, commit fences and complete query stamps. Desktop and mobile share reconciliation and membership semantics; routes keep selection and drafts; native owners retain execution and input control.

Delete creation-only ledgers, per-action pending maps and duplicate cache/freshness owners as consumers move. Preserve saved requests, exact Session identity and domain recovery. Validate one membership vocabulary and GRDB support on both toolchains before adoption.

Source checkpoint: immediate Desktop launch, exact attachment, request-scoped Task reconciliation and attachment-retry cases exist. The latest focused Swift run was stopped before tests finished. Native latency and SQL costs remain unmeasured.
