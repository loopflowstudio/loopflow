What happens when a provider refuses a launch

Concept review for LOO-983, before anything is built. Area taken: every headless launch through run_agent and what it does on a usage limit, an unavailable model or a revoked login, because the Task changes that rule for commands and the rule is one idea spread over several pieces of code. Dashed blue marks what is proposed; everything else exists today.

The biggest mismatch

A person holds one rule: when the provider says no, the next agent in my order takes it. The code holds that rule in three loops and two order calculations, behind a flag named for something else, and recognises the refusal by an apostrophe. Each piece was reasonable alone. Together they mean the rule a person configured has only ever applied to Claude refusals inside a Graph step.

Larger than this work

  • The stop advice reads a pin from an empty fallback_agents (_limit_stop_advice). A bare pinned harness gets its models as fallbacks from resolve_agents, so -a claude spent may be told to “add another agent to agents”, which the pin would ignore. Not run; read from the code. It would take the launch knowing whether its agent was chosen.
  • Moving only on three failures is a rule people have to learn. “My order is tried in order” would also cover a timeout or a missing CLI. Changing it belongs in the shared loop for every caller and changes Graph steps too.
  • Pi and OpenCode never move. Classifying their failures is its own Task.

Questions

  1. A commit-message agent that times out or returns no message:
    1. stop there, as the plan now has it (step commits fall back to checkpoint);
    2. move to the next agent, for every caller of the shared loop;
    3. move to the next agent for one-shot copy only.
  2. A turn refused before any reply, moving to another provider:
    1. restart from the original prompt (chosen);
    2. import the transcript as a Graph step does today.
  3. On a usage limit, the same provider's other models:
    1. try them, as now (Claude's limits can be per model);
    2. skip to the next provider for Codex, whose limit is account-wide.
  4. lf replay when its recorded agent is refused:
    1. stop (chosen; it replays one recorded launch);
    2. follow the current order.
