Concept review: links in Loopflow Sessions and Desktop

Task LOO-1126 Stage: post-implementation review (Passes 1–3 built) Base: fd8dce986d · HEAD: ec8ae076ce

Area reviewed: clickable links across Loopflow Sessions and Desktop — from held-terminal identity (transport/registry.rs), through Ghostty's hover, cursor, and click callbacks (GhosttyManager, GhosttyTerminalView), link parsing and destination resolution (TerminalLink, ops/task/directory.rs, ops/task/snapshot.rs), into Desktop's pane, Files, Dashboard tile, and Work routers (WorkspacePanesView, SessionsView, TaskFilesStore, LoopflowApp, TaskBriefView, TaskHTMLView, and LoopflowiOS). Reviewing the whole area on ec8ae076ce against base fd8dce986d shows that the core experience works, while one inverted server probe and three smaller conceptual seams remain.

What is built vs. what waits

  • Built and committed across Passes 1–3 (a12082957b, 0552209e91, e507237447, 04c2f98af7, ec8ae076ce): Ghostty intercepts OPEN_URL (always returning true), MOUSE_SHAPE, and MOUSE_OVER_LINK with link-previews = true; paused Sessions support ⌘-hover via flagsChanged; all link previews and click errors share one bottom-corner linkFeedback pill; web and mail links open in default apps; custom schemes confirm in TerminalExternalLinkSheet; loopflow:// Work addresses resolve via query.workLink and open in-app without dispatching app-control routes; Task checkout files open in Files at #L<n> using the Task's active filesPlace with safe default-app fallbacks for non-Task panes and old local shells; held terminals set TERM_PROGRAM=ghostty and drop TERM_PROGRAM_VERSION.
  • Product choices implemented headless, awaiting confirmation: all five recommendations from the prior headless review were built (Files pane for Task checkouts + safe fallback, remote file:// hostnames, unconditional TERM_PROGRAM=ghostty, direct in-app Work links), plus Dashboard tile file clicks flipping the tile via zoomedPaneId.
  • Still misaligned in the built code: remote file clicks probe the directory-listing endpoint (task.files) hoping for a special error instead of reading the file with task.file; hover cursor and bare-path acceptance disagree with click validation; Dashboard tile clicks overwrite the Task's saved zoom state; and macOS's TerminalLink collides with iOS's TerminalLink connection class.

Before

Built today (probe via task.files directory listing)

  1. Remote file click calls task.files(directory: relative, showIgnored: true).
  2. Server canonicalizes, stats, and fails with Invalid { "reason": "file" } — caught by Swift as success.
  3. files.openPresentation opens the tab and makes a second server call (task.file) to fetch the file.
  4. Clicking a remote folder runs read_dir, sorts up to 500 entries, serializes them, sends them over SSH, and Swift discards the response to throw remoteDirectory.
  5. Clicking a missing remote file throws raw "io error: No such file or directory (os error 2)"; an escaped symlink throws "Directory must remain inside the Task worktree"; an un-upgraded remote Machine fails every file click.
  6. directory.rs carries custom error-data plumbing and a reordered .git guard solely for terminal links.
After

Recommended (read via task.file directly)

  1. Revert the directory.rs changes completely — task.files stays a pure directory listing.
  2. Remote file click calls query.taskFile(issue: files.taskId, path: relative).
  3. If snapshot.state == .missing → throw OpenError.missing ("File is missing or unreadable.", matching local panes).
  4. If snapshot is a file (.text, .binary, .truncated, .unsupportedEncoding) → return .checkout(path: relative, line: line, snapshot: snapshot) and seed TaskFilesStore so Files renders in one round-trip with no second read.
  5. In snapshot.rs, when absolute.is_dir(), return a clear directory refusal (and map is_dir → OpenError.remoteDirectory). Older remote servers still open every regular and missing file without breaking.
  6. Keep the existing place == activeFilesPlace guard after await so a concurrent Task move still leaves Files closed.

Counterexamples tested

  • Remote folder click (file://mini.local/home/jack/wt/node_modules): file_snapshot checks absolute.is_dir() in O(1) and refuses immediately — zero read_dir, zero 500-entry JSON payload over SSH.
  • Remote missing file (file://mini.local/home/jack/wt/deleted.rs): file_snapshot returns TaskFileSnapshot(state: .missing); Swift throws OpenError.missing so local and remote panes show the exact same "File is missing or unreadable." message and never open an empty tab.
  • Large remote binary or multi-megabyte log file: file_snapshot already bounds text reads at 1 MB (sniffing a short prefix first) and binary reads at MAX_BINARY_DATA_BYTES — the exact same work TaskFilesStore.loadFile performs anyway when opening the file.
  • Remote symlink pointing outside the checkout: file_snapshot checks !absolute.starts_with(&root) before reading any bytes and refuses with a file-scoped message instead of saying "Directory must remain inside the Task worktree".
  • Remote .git/config vs .git: file_snapshot already marks .git/config read-only ("Git metadata is read-only.") and rejects .git as a directory — no special ordering needed in directory.rs.
  • Mixed-version remote Machine (older lf on mini): task.file already returns Ok(TaskFileSnapshot) for regular files and Missing for missing files on older builds, whereas task.files with {"reason": "file"} fails every remote file click until mini is upgraded.
  • Task moves during the remote read: guard let place, place == activeFilesPlace still runs after await before touching the browser pane or TaskFilesStore, so a move cancels the reveal cleanly.

Questions

1. When you are on the Working Tasks Dashboard and ⌘-click a checkout file inside a Task tile, what should happen?

Today the tile replaces its Session terminal with Files by setting zoom on that Task's layout — which also means clicking into the Task later opens Files zoomed full-screen instead of the Session + Files split. Entering the Task shows Session and Files side by side immediately without changing the tile; keeping the file inside the tile lets you stay on the Dashboard.

2. Built today: ⌘-clicking a file inside a Task's active checkout opens it in Desktop's Files pane at #L<n> (locally or remotely), while Repository/Wave Sessions and old pre-move local shells open safe local documents and folders in the macOS default app (still blocking scripts and executables). Keep this?

Opening Task files in Files preserves line numbers, safely reads scripts like scripts/test.py, and works on remote Machines. Opening all local files in the default app matches Rex, but drops line numbers, must refuse scripts, and cannot open remote files.

3. Built today: every held terminal reports TERM_PROGRAM=ghostty (and clears TERM_PROGRAM_VERSION), even when started from Rex, Apple Terminal, or tmux. Keep always setting ghostty?

Always advertising ghostty makes clickable links work consistently no matter where the Session started, and Loopflow's Rex host detection uses REX_SESSION/REX_BLOCK rather than TERM_PROGRAM. Preserving caller TERM_PROGRAM keeps rex when launched from Rex, but leaves Sessions started from Apple Terminal or tmux without clickable links.

4. Built today: in a remote Task pane, links like file://mini.local/home/jack/wt/src/lib.rs (from ls --hyperlink or rg) open in Files whenever the path is inside that Task's remote checkout, regardless of the URL's hostname. Keep this?

Files reads only from the Task's owning Machine over Loopflow's server and never connects to the hostname in the URL. Local panes still require this Mac's hostname.
