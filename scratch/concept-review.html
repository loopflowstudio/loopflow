Pause a Task without giving it up

Post-build review of the whole Task-pause area at d042c945c4 against base 2aa9964894: the hold, worker teardown, Session closure, recovery and wakes, moves, served writes, and the CLI/Mac/iPhone surfaces. Everything below marked built is committed; proposed is not.

Verdict: the model lines up. One fact (a task_pauses row) drives state, section, sentence, run refusal and the operator recommendation; nothing writes paused-ness twice. The mismatches left are names for the transient “still stopping” phase, small enough for gate.

2. Biggest mismatch: the “still stopping” phase has no single name

People see one thing: a Task that is Pausing. It disables Unpause and is shown as “Task is pausing; land is still running”. The code spells it five ways, and the stored name is wrong about what it holds. Nothing is broken. A reader of SCHEMA.md just meets “processes” and then finds sessions.

StoppingSession { session, members }
capture_worker_jobs / settle_worker_jobs

TaskRunControl { unavailable, pausing }
proposed (gate, no behavior change) 
task_pauses.stopping_sessions    -- draft migration, edit in place
StoppingSession { session, members }
capture_worker_sessions / settle_worker_session
PauseCleanup { worker_session }   -- unchanged
TaskRunControl { unavailable, pausing }   -- unchanged

TaskRunControl.pausing stays. Run control is the one legality reading both apps already take, and the flag says “cleanup still running”, which is the run refusal's own subject. Splitting a separate pause-control DTO would add a second legality type for one boolean. The rename is the whole recommendation: task_pauses.sql has not merged, so it can still be edited in place.
