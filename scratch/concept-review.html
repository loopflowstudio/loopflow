The phone should see the same repositories Desktop does.

Outcome: the design changed; it iterates to implement. No open product choice. Each change follows from accepted decisions: Jack Heart's “existing open Tasks, like Desktop's working-task sidebar” and one shared server for Desktop and phone.

The mismatch

Today existing behavior 
Desktop sidebar   view.list {directory}  for each portfolio repository
Phone Task list   view.select "kind:task state:open"   every repository in the store
Phone New Task    desktop.portfolio   portfolio repositories as destinations

Task in a repository outside the portfolio:
  Desktop   hidden
  Phone     listed, but its repository is not a destination
Next proposed 
Portfolio (Machine-local repository membership)
  ├─ Desktop sidebar     Tasks in portfolio repositories
  ├─ Phone Task list     view.select scoped to the portfolio, server-side
  └─ Phone New Task      portfolio.get   destinations

Actions → concepts → APIs

  • See my open Tasks. Open Tasks with primary Sessions, in the portfolio → view.select subscription over portfolio repositories. Scope changes; reading stays one subscription.
  • Choose where a new Task goes. Portfolio repository → portfolio.get, renamed from desktop.portfolio. The README's claim that desktop.* is never offered to a phone is false today. The rename makes it accurate.
  • Create & start. task.start. The Rust variant is renamed TaskCreate → TaskStart, so it no longer collides with the wire's task.create (promote a Session).
  • Open, observe, Use keyboard, Reconnect. Unchanged. The Task acceptance says “distinguish viewing from control”.

The server README's operation table also gains this Task's operations: task.start, session.start, view.select, mobile.status, mobile.configure, request.upload.

Challenge

Normal path: scan the QR code, see the same open Tasks as Desktop's sidebar, then tap one to observe its Session. Failure: you remove a repository from the portfolio while the phone watches. The watch re-reads, and that repository's Tasks leave both clients together. Counterexample that would invalidate it: you want the phone to reach Tasks Desktop deliberately hides. Nothing on record asks for that. If you do, it becomes a product choice.

Questions

  1. Phone Task list scope: (a) portfolio repositories, matching Desktop (recorded direction) · (b) every repository in the store.
  2. Repository membership read: (a) portfolio.get/portfolio.set (recorded) · (b) a new repository.list while Desktop keeps desktop.portfolio.
