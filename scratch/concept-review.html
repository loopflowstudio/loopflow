The mismatch that remains

Opening a conversation now spends a turn, and that turn ends in the same state as a conversation waiting on a person. After a load, up to eight Tasks read as Available though nobody asked them anything. The sidebar's Available filter and the Wave board both count them. The report is real, so the default keeps them; question 5 asks whether that reads right.

Counterexamples that held

  • Two repository windows cannot refill each other's evicted Tasks: prefetch skips existing workspaces.
  • A failed Machine read shows the window's error, not an endless spinner.
  • Start always returns a launch command, so the queue cannot spin on .pending.
  • Every moveHere reader separates Try again from Take back.

Next proof

Hidden panes launching the provider off-screen has never been rendered. The candidate must show it from fresh data: an absent Session and a Session with no history both open with no click, an idle Task with a stopped run reports without a new Graph, and identity survives relaunch.

For the demo

  1. A claimed working Task opens by itself. An unassigned one keeps Claim and Start. (a) keep, (b) open those too.
  2. A fresh lf resume --task with no request reads first. (a) keep, (b) operate on that explicit path.
  3. A comment written just before load waits for your first message in that conversation. (a) keep, (b) act on fresh steers, which needs a rule separating them from history.
  4. A provider that dies before any history costs one Try again click. (a) keep, (b) retry once per Desktop run, automatically.
  5. A conversation that only finished its automatic reading pass counts as Available. (a) keep, (b) leave it out of Available until a person has engaged it.
