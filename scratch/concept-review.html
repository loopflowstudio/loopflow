How the single Rust predicate works

try_start_task_run in rust/loopflow-execution/src/ops/task.rs already receives merges: fn(&[String]) -> bool (command_merges). Replace TaskRunSelection::reaches_end (one caller) with CapturedGraph::reaches_landing(&self, place: &Place, through: bool, merges: fn(&[String]) -> bool) -> bool in task_graph.rs:

  • Walks forward from place, returning true on any step where landing_name(step, merges).is_some() (land, pr land, pr arm, pr-land).
  • When through == false (bare lf task run with auto unset), stops a path at any interactive step.
  • Descends into xor: branches independently: returns true if any path can merge before stopping, and continues past the xor: unless every path stops interactively.
  • Follows loop back-edges (ConcreteSkill.returns) when passing a deciding step so a run starting inside a loop (for example loop: [deliver, interactive: check] with auto on at check) still sees the deliver it can return to.
  • Used for both TaskRunStart::Run and TaskRunStart::Live (when auto == Off, merges is always false). Zero DTO or wire change.

Outside this work · Desktop StartFlow.merges

Separate outcome: Replace Swift’s StartFlow.merges prefix check (swift/LoopflowMac/Views/BacklogView.swift:128-130) with a required boolean on WorkflowOutline (for example merges_before_stop) computed in Rust by reaches_landing(&start, false, command_merges). Left out of LOO-1108 because adding a required DTO field touches the wire schema, golden fixtures, and Desktop-against-installed-server decoding compatibility. LOO-1108 puts reaches_landing in place so that follow-up is mechanical.

6. Choices made for review & open questions

Running headless inside the plan Graph: the bold, reversible choices below are written into scratch/plan.md so implementation proceeds in one pass. Answer by number and letter (for example 1a or 2b) when reviewing.

1. Post-merge checking once verify is removed

Without verify, a Task finishes as soon as its PR merges — nobody is called back to check post-merge CI for the merge SHA or re-check claims against main.

  • 1a (chosen) Complete on merge, no post-merge step. Trust qa, ship-review, and gate before merge; use lf task reopen, a new Task, or lf incident if main breaks. Repositories that want a post-merge stop add their own interactive: step after deliver.
  • 1b Add a headless post-merge check inside deliver after land (checks post-merge CI on the merge SHA before completing, adding one headless agent run after every merge).
  • 1c Remove verify from code and feature, but keep lf verify as a standalone builtin skill people or repo Graphs can still invoke or extend.

2. When lf task run prints the merges: warning

Today, lf task run prints merges: this run may merge the PR whenever no interactive step lies ahead — so non-merging workflows like pursue and deep-clean warn that they may merge, while a custom workflow with a post-merge stop stays silent before merging.

  • 2a (chosen) Warn only when the run can actually reach a merging step (land, pr land, pr arm, or pr-land) before stopping. Honest for code, feature, quick, pursue, research, and custom post-merge-stop workflows.
  • 2b Keep the current rule (warn whenever the run has no interactive stop ahead or auto is on, even if the workflow has no merging step) and leave ops/task.rs untouched in LOO-1108.

3. Consolidating Desktop’s “merges without asking” label onto the same Rust predicate

Desktop’s Start menu currently scans compiled step labels in Swift for land and pr land prefixes, which misses pr arm, pr-land, and xor paths.

  • 3a (chosen) File as a separate follow-up Task after LOO-1108 so this PR makes no DTO/wire schema break against installed servers.
  • 3b Include the wire field in LOO-1108 by adding merges_before_stop to WorkflowOutline and deleting Swift’s prefix check in the same PR.
