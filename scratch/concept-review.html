Existing: server supersession resolves exact withdrawn completion requests. Client creation uses the SQLite outbox; shared completion projection and both-client migration remain unfinished.

Complete A → hide A and select B → open another cached list → A stays hidden → each covering reading replaces its own effect exactly once.

Failure / recovery: Reopen can supersede the exact request. Covering replacement facts restore A without selecting it. A committed completion survives later output failure. Restart restores saved intent and cache obligations without resending uncertain work.

Follow the rule through storage and both clients

Applicability: derive it from operation resources/fact dependencies and the query plan. Store plan identity/version with membership; changed filters or plans cannot borrow another query's acknowledgment. Unknown membership remains unknown.

Retirement: incorporate each affected stored query or invalidate its base with its required confirmation fence in the cache/outbox transaction. Future queries evaluate retained effects. After operation retirement, cache provenance still prevents reuse of an invalidated base before a covering read. No need to open every possible view.

Counts: a fresh count covering settlement receives no extra decrement; a held older list retains its removal. Delivery finished and showing a result cannot discharge either obligation.

Epoch: old fences cannot certify a replacement database or authorize replay. Preserve submitted content and recover on the original Machine. Native owners retain input readiness.

Proposed usage: “Opening another list or window shows the same pending changes; an older cached list never brings a completed Task back while confirmation is pending.” Existing recovery skill instructions need no change.
