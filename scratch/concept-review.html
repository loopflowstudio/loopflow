Placing the app binary and embedding its frameworks should be one call, not two that every builder has to remember.

Outcome: iterate. Accepted decisions already settle this. No product question is open.

Action → concept → API

The user's action: build Loopflow.app any way the repo offers, then open it. The one concept: the app executable in a bundle, meaning the binary plus the frameworks it links.

Existing, after pass 2

# five builders, each:
name = <their own way of reading CFBundleExecutable>
shutil.copy(build_dir / "LoopflowMac", macos / name)
embed_frameworks(build_dir, macos / name)   # forget this → dyld abort

There are five ways of naming the executable: plistlib in release, PlistBuddy in dev, inline plistlib in rebuild, APP_NAME in install, and a literal "Loopflow" in the launch benchmark.

Proposed

executable = app_bundle.install_app_executable(build_dir, info_plist, contents)
# reads CFBundleExecutable, copies LoopflowMac, embeds, verifies rpaths

Each builder still owns what genuinely differs between them: plist stamping, bundle-id overrides, the icon, resource bundles, strip and signing.

The mismatch

The incident happened because a builder did the copy without the embed. Pass 2 fixed the two remaining builders by adding the same call in two more places. The next builder, or the next linked framework, can repeat the incident, because nothing joins the two steps. Merging them makes the mistake impossible to write, and it deletes four helpers.

Checked

  • The shipped third-party rebuild.py already gets app_bundle.py beside it, so recipients need nothing new.
  • Dev reuses its bundle, so its stale-LoopflowMac cleanup stays in loopflow-dev.py.
  • install.py removes the app directory before building, so the app binary needs no atomic swap. lf keeps _atomic_install.

Questions

Nothing blocks. These are only for overriding the agent's call:

  1. Merge the copy and the embed: (a) yes, as recorded; (b) no, ship pass 2 as it is.
  2. Should signing also move into app_bundle? (a) no, builders sign differently; (b) yes.
