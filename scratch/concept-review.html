Getting back to a Session: one idea, how many spellings?

The area: every command, flag and argument that reaches an existing Session, to look at it, type into it, send it text, change what runs it, or move it. Read from lf help on the installed build and from main's docs. No code changed. This is wider than LOO-924; it explains the resume special cases that Task keeps running into.

A person has five things they want to do with a Session they already have. The CLI has about twenty spellings for them, and three words (resume, move, send) each mean more than one thing.

One interaction

A Graph step asked for JSON and the agent answered with something invalid. The Graph wants to say "fix that" to the same conversation.

  1. lf steer SESSION 'fix it' is the command for sending text to a Session. But a steer is read at the agent's next tool call, and this agent has stopped. Nothing would read it.
  2. So the Graph runs lf --batch --output-schema … session resume ID --message '…' (graph.rs). resume, the command for getting back to a conversation, is used here to send one turn and exit.
  3. Failure: the answer is invalid again. The Graph repeats step 2, at most twice, then fails.
  4. Recovery: a person runs lf resume ID to look. Same command, same ID, entirely different behavior: it opens a terminal, and whether the server holds it depends on --task or the Session row.

That is why --message exists: there is no way to send a turn to a Session that has stopped, so the flag was added to the nearest command.

The biggest mismatch: resume does five jobs

Existing

lf resume ID              # connect and type
lf resume ID --prepare    # return connection data
lf -b resume ID --message # one headless turn
lf resume ID --fork       # copy, then connect
lf resume -a codex        # switch harness
lf resume ID --task X     # connect, and make managed

Each flag changes what kind of launch it is. In LOO-924 this is the one place where "the command alone decides the state" needed exceptions.

proposed

lf resume [SESSION|TASK]   # connect. Nothing else.
lf steer SESSION 'text'    # send text, running or not
lf session restart [-a H]  # fresh thread, same Session
lf session fork ID         # a copy
lf session bind ID --task  # make it the Task's

One verb per want. resume never changes a Session's state, harness or Task: "resume connects to existing sessions".

Where the proposal has to be tested: sending text.

  • Normal: the agent is mid-turn. lf steer saves the text and the agent reads it at its next tool call. Same as today.
  • Stopped Session: lf steer starts its next turn with that text. This replaces --message. The server already does this for an idle held conversation ("waking an idle conversation").
  • Counterexample, kept: the Graph correction needs to wait for the answer and pass --output-schema. A steer returns as soon as it is saved. So "send and wait for the reply" is a real second thing, and it needs either a flag on steer or its own command. See question 2.
  • Recovery: a steer to a stopped Session whose provider can't start stays unread, and lf session steers shows it waiting. Nothing is lost.

Smaller ones, same pattern

  • open and resume. If resume only connects, the remaining difference is where: this terminal, a sibling tab, or a host such as Desktop or tmux. That is a placement option on one verb.
  • One selector. A positional that takes a Session ID, a Task identifier or a URL already covers every case; with none, the directory decides. --task, --wave and --session on these commands then have nothing left to do.
  • move. Changing the agent is not moving. With session restart -a covering one Session, session move --on X -a Y is its bulk form and could carry the same verb.

Questions

  1. Should resume only connect, with every other job moved to its own verb?
    1. Yes.
    2. Yes, except --prepare, which is Desktop asking for the same connection as data.
    3. No, keep the flags.
  2. Sending text to a Session that has stopped:
    1. lf steer does it, and lf -b steer waits for the reply (Graph correction uses that).
    2. lf steer stays "read at the next tool call"; a new lf session turn ID 'text' sends one turn and waits.
    3. Keep resume --message.
  3. open and resume:
    1. One verb, resume, with --tab / --host for where.
    2. One verb, open; resume becomes its short form for "here".
    3. Keep both, and state the difference in each help text: open shows, resume takes input.
  4. Fresh thread on the same Session, today session new and resume -a:
    1. lf session restart [-a]; remove resume -a.
    2. Keep session new; remove resume -a.
    3. Leave both.
  5. Selecting the Session:
    1. One positional (Session, Task or URL); drop --task, --wave, --session from these commands.
    2. Keep the flags as selectors only; none may change state.
  6. Where does this go?
    1. A new Task, designed first, after #1966.
    2. Question 1 and 2 join LOO-924; the rest is a new Task.
