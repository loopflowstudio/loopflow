Concept review: links in Loopflow Sessions and Desktop

Task LOO-1126 Stage: post-implementation review (Passes 1–4 built) Base: fd8dce986d · HEAD: bba5ff2138

Reviewing the whole area on bba5ff2138 against base fd8dce986d confirms Pass 4 closed all four earlier implementation mismatches; one cross-surface link-ownership split and three concrete seams in the built code remain.

What is built vs. what waits

  • Built and committed across Passes 1–4 (a12082957b, 0552209e91, e507237447, 04c2f98af7, 98c1057421, bba5ff2138): Ghostty intercepts OPEN_URL (always returning true), MOUSE_SHAPE, and MOUSE_OVER_LINK with link-previews = true; paused Sessions support ⌘-hover via flagsChanged; hover preview, cursor shape (.pointingHand vs. .operationNotAllowed), and click routing share one TerminalHyperlink classifier (renamed to clear LoopflowiOS.TerminalLink); web and mail links open in default apps; custom schemes confirm in TerminalExternalLinkSheet; loopflow:// Work links resolve via query.workLink and open in-app without touching app-control routes; Task checkout files open in Files at #L<n> locally and remotely via task.file (with snapshot.rs distinguishing directories from missing files and directory.rs reverted); non-Task panes and pre-move local shells fall back to safe local documents/folders; Dashboard tile clicks enter the Task with Files beside its Session; held terminals set TERM_PROGRAM=ghostty and drop TERM_PROGRAM_VERSION.
  • Product choices implemented headless, still awaiting human confirmation: Files pane for active Task checkouts + safe default-app fallback elsewhere (Q2), unconditional TERM_PROGRAM=ghostty on held terminals (Q3), accepting any remote file:// hostname inside the remote Task's checkout (Q4), and Dashboard tile + zoomed-terminal behavior (Q1).
  • Remaining mismatches on bba5ff2138: Desktop still has four different link routers and two parsers for loopflow:// Work addresses; remote file clicks fetch and discard the full file body before Files fetches it a second time over SSH; clicking a checkout file inside a zoomed terminal behaves opposite to clicking it from a zoomed Task's Dashboard tile; and ⌘-hover over an unfocused terminal pane misses flagsChanged.

Before

Today across Desktop (four routes, two Work parsers)

  1. Terminal panes: Swift's isWorkAddress parses loopflow:// (rejecting syntax errors like #frag with a misleading "only Work" notice, while accepting invalid IDs like ?repository=bad and control names like loopflow://update), then clicks go to query.workLink → openResolvedWorkLink.
  2. Task Brief & Markdown readers (TaskBriefView, TaskFilesView, WorkSurfaceView, TaskChangesView, TaskCommentsView): loopflow:// and file:// go to .systemAction (Launch Services), which can wake the Release app from Dev, pop the open-work error window, dispatch app-control URLs like loopflow://update, and launch local files without executable checks.
  3. Review pages (TaskHTMLView): only http/https/mailto leave the page; loopflow:// and file:// return .allow and navigate inside the offline WKWebView.
  4. OS deep links (LoopflowApp.handleDeepLink): the only surface that legitimately handles app-control routes (open, portfolio, sessions, update) before falling back to workLink.
After

Recommended (one Desktop link router; Rust owns Work grammar)

  1. One Desktop router handles in-app clicks from terminals, Task Brief, rendered Markdown, and review pages: web/mail → default app, loopflow:// → query.workLink → openResolvedWorkLink (never handleDeepLink), file:// → active Task Files or safe localDocument(), unknown schemes → confirmation sheet.
  2. One WorkUrl parser (Rust): because in-app clicks never enter handleDeepLink, Swift does not need a 28-line copy of WorkUrl::parse to stay safe. Either keep a minimal shape check in Swift for hover (rejecting only obvious app-control queries like ?repo=/?view=, or letting query.workLink return Rust's exact syntax error on click) or expose one shared validator.
  3. OS deep links stay the sole entry point for Desktop control routes (loopflow://update, loopflow://open?repo=…&view=…).

  • loopflow://update or loopflow://sessions printed by an agent: Passes isWorkAddress today, goes to query.workLink (not handleDeepLink), and only opens if a registered repository is literally named update or sessions; otherwise reports not found in the pane notice.   • loopflow://loopflow/task/LOO-1#section printed by an agent: With isWorkAddress, hover and click say "Terminal links can only open Work in Loopflow." instead of Rust's actual reason ("Work links do not accept a fragment").
  • Related Task link in TaskBriefView while running Loopflow Dev: .systemAction hands loopflow://loopflow/task/LOO-99 to macOS Launch Services, which can focus the installed Release build instead of the Dev window.
  • Remote file with unsaved edits in Files: If openTerminalFile seeds the fetched TaskFileSnapshot through TaskFileDocument.reconcile(_:), dirty drafts run 3-way merge (TaskTextEdit.merge) and in-flight saves defer cleanly — the exact path TaskFilesStore.loadFile() already uses.

  • Package bundle inside a local checkout (e.g. Fixture.app): kind.isRegularFile is false and kind.isDirectory is true, so it falls through to localDocument(), which checks info.isPackage != true and refuses it as unsafe.
  • Pointer rests on a link in an unfocused Session (Files focused) and user presses or releases ⌘: mouseMoved never fires without pointer movement, and AppKit sends flagsChanged only to Files, so the preview/cursor fails to appear on press or stays stuck after release.

Findings

Pass the fetched remote TaskFileSnapshot into TaskFilesStore instead of reading twice Recommended: Fix here

This work. Carry the already-fetched TaskFileSnapshot from TerminalHyperlink.File.destination into openTerminalFile and reconcile it via await files.document(path).reconcile(snapshot) before openPresentation (letting loadFile() skip a redundant immediate fetch or revalidate quietly). Cuts remote clicks from two full file transfers over SSH to one, removes the loading flash on remote file links, and reuses TaskFileDocument's existing 3-way draft merge and concurrent-save guard. Passed over: discarding the lookup snapshot and re-reading on mount, which pays double SSH bandwidth and latency on every remote file link.

Make zoomed-terminal file clicks behave consistently and separate unzoom from focus in showBrowser Recommended: Fix here

This work (depends on Q1). Stop overloading MultiplexerStore.showBrowser(..., focus: Bool) so focus: false secretly means "also unzoom". When a person ⌘-clicks a checkout file in a zoomed terminal — whether inside the Task view or from a Dashboard tile — unzooming so Files opens beside the Session makes one gesture do one predictable thing everywhere. Passed over: keeping focus: onEnter == nil, which splits zoomed Task clicks (full-screen Files hiding Session) from zoomed tile clicks (Session + Files side-by-side).

Forward flagsChanged to hovered unfocused terminal panes so ⌘-hover never sticks Recommended: Fix here

This work. Observe flagsChanged in the key window (like WorkPalette already does with a local event monitor) while the pointer is inside a GhosttyMetalView that is not first responder, so pressing ⌘ previews links immediately over unfocused panes/tiles and releasing ⌘ always clears the pill and cursor. Passed over: relying only on NSResponder.flagsChanged, which leaves unfocused panes stale until the mouse moves.

Drop or simplify Swift's WorkUrl::parse duplicate (isWorkAddress) in TerminalHyperlink Recommended: Fix here

This work (small cleanup). openTerminalLink already sends every .work link exclusively to query.workLink (never handleDeepLink), so isWorkAddress is not a security boundary — it only pre-screens hover feedback while diverging from Rust's WorkUrl::parse on error text and ID validation. Either keep a minimal hover check (scheme + non-empty host + reject known control-query keys, letting Rust report syntax errors cleanly) or document it as a temporary hover heuristic until the shared router lands.
