One request, through recovery

New operation: show submitted words → save exact typed content → acknowledge → discover repository and validate → claim execution → bind real Task/Session. Same ID/content returns the saved receipt; changed content conflicts. Input waits for native readiness.

Released creation: preserve its canonical fingerprint and outcome → save one adoption candidate → validate off the admission path → bind the first verified envelope. Equivalent symlink/subdirectory spelling can adopt the old creation. Later retries use that saved envelope.

Mismatch: release only the invalid candidate; keep the old creation and its recovery available. An unavailable repository leaves validation pending. A held worker cannot release or replace a newer candidate.

Restart: repeat effect-free validation; recover an existing creation through Complete/Continue/Inspect. Never generically dispatch a released or uncertain creation. Racing CLI and served requests share the same domain claim.

Counterexample to test: hold Git, receive acknowledgment, disconnect, restart, then release validation. Recover the same operation and Session exactly once. Try wrong content before valid legacy adoption, and reorder their replies.

Shared-cache requirements remain: a fresh count must not apply Complete twice while another list is held. Newer facts cannot regress under older detail replies. Filtered absence removes membership, not a retained workspace. Epoch replacement never permits uncertain replay.
