One interaction, walked

A Task's implement runs on OpenCode with Gemini 4 Carbon and the model asks which database to target. Seen in QA round 2 on the real CLI (scratch/qa.html, scenarios 8-14).

Built

$ lf task run LOO-12 -a opencode:opencode/gemini-4-carbon
the run of code stopped at implement: Which database
should the migration target?; answer with
`lf steer LOO-12 "…"`, then `lf task run LOO-12`
$ lf task status LOO-12
implement stopped: Which database …; answer with …
$ lf steer LOO-12 "the staging replica"
$ lf task run LOO-12
implement settles; the Graph stands at review

One attempt. The stop and the status read the same sentence through harness::asked_question. The next run is a new conversation that hears the steer.

The biggest mismatch left: a question is read from prose

Built

decoder   ConversationEvent::Error { code: "unanswered_question", message }
session   TurnEnd::Error { code, message }        structured
step      error = "unanswered_question: OpenCode asked …: Which database …"
graph.rs  asked_question(cause)  // split_once("unanswered_question: ")
status    asked_question(step.error)

Works, is tested on both harnesses and on the real CLI. The code is stored once as a field and once as a string prefix; two readers depend on the prefix surviving every layer that formats a step's error.

Proposed, its own small change

graph.rs  last turn of the failed step → TurnEnd::Error.code
status    same read
asked_question  deleted

The question would come from the recorded turn, where the code already is. Not planned here: it changes no behavior a person sees, and demo is next. Larger than a nit only if a third reader appears.
