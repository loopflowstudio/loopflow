Seeing a result must not discard pending reconciliation

Decision for the next implementation: record that the result was shown; retain the operation until recovery and query obligations also finish. No open product choice stops this work.

Biggest mismatch: both creation clients now use Git-free admission and the shared SQLite outbox, but presented(id) still deletes the saved command. Mounting one result says nothing about another window’s list or count.

Start, before → proposed

Existing: save → admit → recover result → mount → delete submission. Confirmed cache and shared projection are unfinished.

Start → show submitted words → save/admit → bind exact Task and Session → open in place → acknowledge shown result → each covering query incorporates its effect → retire when nothing remains.

Failure / restart: attachment failure retains Retry opening for that Session. Opening Inspect clears no uncertainty. A held list keeps its effect after the conversation mounts and after restart; a fresh count never applies it twice.

Follow the model through recovery and both clients

Proposed persistence: keep domain recovery, effect/query incorporation and creation-result presentation as independent obligations in one operation record. Persist acknowledgment; atomically replace confirmed cache and incorporation records. Closing a query requires saved invalidation and a reload fence. Convergence alone cannot discard an unseen creation result.

Domain stages: task.completion_requested cannot confirm completed membership; task.completed plus a covering read can. task.filed binds identity without proving Graph admission or input readiness. Partial failure retains committed facts.

Deletion: replace the interim presentation deletion, creation presentation map, launch checkpoint exception, duplicate caches and per-action pending owners as consumers migrate. Extend system SQLite3 on both targets; no GRDB adoption is planned.

Proposed usage: “Opening a finished result clears its Show result prompt. List and count updates continue in the background; leaving the result does not cancel them. Unresolved failures keep their recovery actions.” Complete still removes its row and opens the next Task, or an empty view. A later reply never changes a newer selection.

Epoch replacement: keep the submitted command and the local acknowledgment that it was shown. Neither old fences nor that acknowledgment certify the replacement database or authorize replay.
