2. Biggest mismatch solved on HEAD (Before → After)

Conflated review, plan mutation, and premature polish — resolved and verified on HEAD

Previously, build ran compress and qa on every outer-loop pass before concept-review decided whether to rework, while concept-review carried a second headless mode that mutated scratch/plan.md and decided loops directly. Every skill now has one role across both plan and build:

Before (base 23ce1a69f9) 
plan:
  kickoff → concept-review (edits plan!) → write-docs

build:
  loop:
    loop: [implement → cmd: sync → realign]
    compress          # invalidated on rework
    qa                # invalidated on rework
    concept-review    # edits plan + decides loop
  pr-publish

realign:
  owned plan + Wave MEMORY.md curation
After (built on HEAD 684bbae383) 
plan:
  kickoff → concept-review (HTML only) → realign → write-docs

build:
  loop:
    loop: [cmd: sync → implement]   # counts down passes
    concept-review                  # read-only HTML critique
    realign                         # owns plan + decides loop
  compress                          # runs once, after design settles
  qa                                # runs once, after design settles
  pr-publish

wave-session:
  sole owner of Wave MEMORY.md curation

Failure & recovery counterexamples checked

  • Counterexample breaks the plan mid-build: implement records what broke in scratch/plan.md and returns advance (instead of iterating onto a broken plan), handing directly to concept-review → realign to replan and iterate back to sync.
  • Oversized or contradicted brief on quick: With no scratch/plan.md, implement judges scope before building and returns blocked (exit 3, zero files/commits) rather than writing a multi-pass plan and auto-merging.
  • Irreversible vs. reversible design choice after headless review: concept-review flags irreversible choices and recommends reversible ones on the page. In a loop (build), realign returns blocked on irreversible choices and adopts reversible recommendations into scratch/plan.md marked made for review with what was passed over; outside a loop (plan, refresh), realign records any irreversible choice in scratch/questions.md and scratch/plan.md.
  • ship-review iterates back to build: realign tracks finding dispositions by substance, replaces settled review notes when a fresh scratch/concept-review.html arrives, and keeps ## Deferred findings intact.
  • gate or sync edits code after qa: verify diffs <qa head> (the branch's lf qa: commit) against <merge SHA> excluding scratch/; any shipped file change forces the full rebuild check on main.
