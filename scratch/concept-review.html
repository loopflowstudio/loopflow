Docs open automatically in Desktop.

Accepted November 4. Jack Heart selected Desktop-only automatic presentation in the primary conversation. The workflow presents original docs in an already attached Desktop Files view; elsewhere it reports their paths and continues. Explicit terminal file opening remains supported.

Opening an editable file does not guarantee a rendered reading view. Rex's observed creators provide terminals. Desktop renders Markdown and HTML, but full remote asset behavior remains unproved and its client is macOS.

Accepted automatic workflow

Write the real docs → attached Desktop: show Files
                    → elsewhere: report paths
                    → implementation continues

Usage:

Review and edit the original docs while work continues. In an attached Desktop, they open in Files. Elsewhere, the conversation lists their paths. Save corrections for implementation; discuss urgent changes in the Task conversation.

Skill policy:

Present the original docs only in an already attached Desktop Files view; otherwise report their paths and continue. Never launch a host to show them.

This changes automatic presentation in the workflow. It does not authorize removing explicit terminal file opening or building a universal rendered viewer. Both alternatives preserve the original files, drafts, saved corrections, existing Sessions, implementation loop and LOO-498 stack.

The workflow presentation policy and its usage/skill wording now follow this decision. Keep explicit lf open --file, Desktop's existing files(path) action and current-viewer transport ownership. A failed or absent Desktop leaves paths available without launching another host. No new review record, file store or viewer service follows from this decision.

Proof that still matters

In an attached Desktop, present the original Markdown/HTML, preserve an active unsaved draft on repeat, save and read the correction from the original file, and recover a failed presentation while continuing the same conversation. Elsewhere, report paths without automatically launching a terminal editor, host, browser or conversation. Configured Rex automatic presentation is no longer an acceptance requirement.

The earlier direct CLI and isolated Rex probes remain evidence for explicit file opening. Headless Files tests cover rendering and draft preservation; configured Desktop experience remains for demo/review after compatible installation.
