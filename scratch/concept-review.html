Seeding a new worktree's Rust target

LOO-922, full post-build concept review against base 3578f78f6d at head 6dbc23b366 (2026-11-22). Area taken: the whole life of a worktree's Rust build outputs for a Loopflow developer and Machine agents — cache install, worktree creation (cold or seeded), source selection across Cargo target layouts, quiescence, first and later builds, benchmark isolation, status readout, and reclaim by lf wt prune --builds.

Outcome: nothing to change. The product concepts and code concepts now line up across the whole area. Both mismatches from the earlier pass are resolved in the built tree: only targets Cargo has actually built can seed a new worktree (unbuilt seeds stay untouched and never supply false provenance), and test_loop.py shares seed_probe.py's single cold-target contract (add_worktree(..., cold=True) removes target/). QA run 3's Cargo 1.100 layout support (SEED_LAYOUTS) fits the same seed model without introducing a second concept: Cargo 1.100 unifies .fingerprint, build, and deps into build/<package>/<hash>/ while keeping binaries, incremental/, and Cargo locks outside it. No proposed changes remain.

The interaction

You (or lf, preparing loopflow.ready or a Task checkout) run git worktree add ../x main. The installed post-checkout hook fires on a null old OID ($3=1, $1 all zeros), finds the newest idle sibling worktree that Cargo has actually built, clones its reusable Cargo state into target/debug.seeding while holding Cargo's locks on the source, preserves the ranking directory's mtime, and atomically renames debug.seeding to target/debug. Your first cargo build -p loopflow --bin lf compiles only the workspace crates (7 units instead of 256 when Cargo.lock matches). uv run python scripts/build_cache.py status prints which built sibling and commit produced the seed.

Failure & recovery: every built sibling is mid-build, none exists, or the target volume cannot copy-on-write clone → the hook stays silent, target/ is absent, status prints seed none, and Cargo builds cold as before. Partial clone failure deletes debug.seeding and removes empty target/ without touching any concurrent Cargo build. To force a cold build in a seeded checkout: rm -rf target (which removes target/.loopflow-seed with it).

Counterexamples checked

  • Cargo 1.100 unit-directory layout (probed live against Cargo 1.100.0): target/debug/ holds build/<pkg>/<hash>/{fingerprint,out,run}, examples/, incremental/, uplifted binaries, and all three .cargo*lock files. Cloning build alone carries fingerprints, build-script outputs, and compiled units while leaving uplifted binaries, incremental/, and locks behind — the exact same boundary as Cargo 1.98.
  • Cargo 1.100 ranking when an existing package updates version: in Cargo 1.100, a new hash for an already-present package writes under build/<pkg>/ rather than directly under build/, so build/'s mtime only advances when a new package directory appears (for instance, adding dev-dependencies or a new crate). Walking build/*/ would hit macOS clonefile(2) resetting every cloned subdirectory's mtime to clone time unless every subdir were copystated. Keeping single-directory entries[0] mtime is simple and safe: stale units compile on demand.
  • Mixed Cargo 1.98 and Cargo 1.100 siblings on one Machine: if a checkout seeded from one layout runs the other Cargo version, the two layouts do not collide (build/<pkg>-<hash> vs build/<pkg>/<hash>); Cargo compiles cold safely, and stale files are reaped by lf wt prune --builds.
  • First build racing a concurrent seed on an unbuilt seed: before Cargo creates its lock file, _seed_sources excludes the unbuilt seed; once Cargo creates and locks it before writing units, _quiescent gets EWOULDBLOCK and skips it.
  • Concurrent Cargo creating target/ during _clone_debug: target.mkdir() runs outside the cleanup try block, so a FileExistsError never deletes a concurrent Cargo's target/; cleanup only removes debug.seeding and an empty target/ that the seeder created.
  • Only built sibling is busy or deleted, leaving only an unbuilt seed: the new worktree falls back to a cold build (with sccache still warm), keeping unbuilt siblings read-only and provenance truthful.
  • Benchmark isolation: test_loop.py and seed_probe.py share add_worktree(..., cold=...) so cold measurements remove any hook-seeded target/ immediately after checkout; seed_probe.py deduplicates hard-linked Cargo artifacts by (inode, mtime_ns).

Questions

Choices made for review are marked (chosen). None are irreversible once shipped.

  1. Can an unbuilt seed (such as loopflow.ready) be used as a seed source for another worktree?
    1. No — only targets Cargo has actually built (holding a Cargo lock file) are seed sources. Unbuilt seeds are untouched and provenance always names a built sibling.
    2. Yes — allow chaining off unbuilt seeds, create Cargo lock files inside them during cloning, and copy the original built source's provenance record forward.
  2. How should a developer or benchmark get a cold target once the hook is installed?
    1. Delete target/ right after git worktree add (no env-var opt-out knob), shared by docs, seed_probe.py, and test_loop.py.
    2. Add an opt-out environment variable (e.g. LOOPFLOW_SEED_TARGET=0) to skip the 2–5 s clone in benchmarks and scripts.
  3. Ranking built siblings when an aborted partial build or Cargo 1.100 version bump has a non-monotonic top-level mtime:
    1. Keep single-directory entries[0] mtime (.fingerprint or build); Cargo compiles whatever units are missing or stale.
    2. Add a completeness heuristic or recursive mtime walk (with recursive copystat on clones) to rank partial builds and Cargo 1.100 package updates finer.
