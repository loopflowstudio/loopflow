One Wave, one Project, one tracker Project

LOO-995 · Concept review after slice 11 · 24 November 2026 · Branch a8dbab4b17 against 62a368e5cc

Area taken: the whole Wave–Project model with every slice in it: lf wave create, Task create and move, connect, upgrade of a released store, sync, rename, removal. I looked hardest at multi-Machine tracker delivery, the one row the last review marked no. Slice 11 changed it.

Walk: two Machines, one Wave, an outage

# Machine A
lf wave create ledger            # Project proj_<wave uuid> (local)
lf task create --wave ledger 'x' # Task in ledger's Project
# Machine B pulls; the Wave and its Project arrive over Git
# repo.tracker.linear.team set, pushed, pulled on both
# A and B each queue one Project create for proj_<wave uuid>
# Linear down on A; B sends first: Linear Project id = wave uuid
# A comes back: create refused (id taken) → look up by id → bind → x follows into it
lf wave sync ledger              # on A: linked, x in the Project, no duplicate
lf wave rename ledger journal    # Project name follows; linked → project_name action
lf wave remove journal           # queued actions retire; completed Tasks stay readable

Every step names one Project. The tracker Project's identity is the Wave's UUID, on every Machine. Whichever Machine creates it first wins, and the others bind to it.
