A Session and the view someone is at, as built

Area taken: everything that decides whose terminal a running Session is shaped for when several views show it, with the whole branch in it (base e804e652f5 to a68d682a73): the holder's sizing rule, the relay, the lf commands that start a view, Desktop's panes and Loopflow Dev. Anything marked proposed is not built; everything else is in the branch.

The answer

The model holds. A person knows one thing, "the Session fits the window I'm using", and the code now has one thing for it: Sizing.owner, moved only by focus, typing, or the owner leaving. QA's agent log shows it on a normal path, on departure and across a server restart.

One pairing fails, and it fails for the case the Task was filed about. Desktop tells the relay "this pane starts in the background" by writing --unfocused into a command the server authored, and Loopflow Dev runs that command with the installed lf:

$ lf --version
lf 0.16.0+7127b9d0d
$ lf session resume <id> --unfocused
error: unexpected argument '--unfocused' found

A Dev build from this branch, beside today's installed Loopflow, cannot open a Session pane. QA ran Dev against the branch lf on a private Machine and did not meet it.

The biggest mismatch: Desktop edits a command it doesn't own

Before (built)

  1. Server returns open_argv: lf session resume S, or lf session attach -- ssh …
  2. Desktop parses it and inserts --unfocused
  3. The pane runs it with the installed lf
  4. Installed lf predates the flag: usage error, no pane. Dev is in this state from the day this merges until the next lf install.

After proposed

  1. Server returns open_argv; Desktop runs it as given
  2. Desktop sets LF_RELAY_FOCUSED=0 in the pane's environment, beside LF_SERVER_STATUS, which already marks a Desktop pane's relay
  3. The relay reads it in initial_focus, the one place that decides starting focus
  4. An lf from before this change ignores the variable. The pane opens as it does today, and Dev still starts nothing for Sessions nobody visited.

The first review passed over a variable because it "doesn't cross ssh" and "reaches every child of a pane". The build removed both objections. Starting focus turned out to belong to the relay beside the viewer's terminal, which for an SSH pane is the local lf session attach --, so nothing needs to cross. A Session pane's only child is that relay; the one inheritor that matters is the holder, and start_held drops the variable so an agent's own lf calls never see it.

--unfocused stays for a person at a terminal. What Desktop alone used goes: the Swift argv parser and the test expectations that pin it.

Not reached

Mounted Ghostty focus (clicking a pane, key window changes) needs an unlocked display; QA's screen was locked. Release Desktop's warm set and SSH relays were not run. These belong to QA after the next build, gate or a person.

Questions

  1. How Desktop says a pane starts in the background.
    1. The pane's environment, LF_RELAY_FOCUSED=0 (plan).
    2. Keep --unfocused in argv and accept that Dev needs lf install first.
    3. Have the server put the flag in open_argv when Desktop asks for one.
  2. --unfocused for people.
    1. Keep it on lf resume and lf session new (plan).
    2. Remove it; the variable is the only spelling.
  3. A restart with no focused view.
    1. First to reattach owns until someone focuses (built).
    2. Relays send their recency on attach so the last-used view keeps the size.
  4. owner meaning both the Session's process and the sizing view.
    1. Leave it (built).
    2. File a Task to rename the sizing view on the wire and in the README.
