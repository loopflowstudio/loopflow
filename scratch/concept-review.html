The caller's session

Area reviewed: what a conversation lf starts inherits from the conversation whose shell ran lf, across every launch path, not only the Claude Code marker in the ticket. Base f2d6ce65; nothing built yet.

What a person sees

An agent in Claude Code runs lf -b implement. The Claude lf starts says "Transcript saving is off — inherited CLAUDE_CODE_CHILD_SESSION marker". The Session records a thread with no transcript, and lf resume has nothing to reopen. Failure shows up later, at recovery, far from its cause.

The person's model is simple: a Session lf starts is a new conversation. It keeps my settings (config dir, login, API keys) and none of the caller's identity.

Biggest mismatch: two lists for one concept

Before (plan as written)

EXECUTION_IDENTITY_ENV  // lf markers
  agent/mod.rs   loop
  harness/mod.rs loop
  codex.rs       loop
  native_session  —

PROVIDER_SESSION_ENV    // new
  harness/mod.rs  fn, after envs
  native_session  fn
  start_held      fn

After (proposed, chosen for review)

CALLER_SESSION_ENV      // lf + provider
remove_caller_session_env(&mut Command)
  harness/mod.rs   configure_agent_env
  codex.rs         app-server
  native_session   NativeClient::new
  transport.rs:384 start_held inherit
agent/mod.rs:960   strips launch.env map

One list, one function, applied to the inherited environment before .envs(&config.env). The plan said "after", which would delete the fresh lf markers the new conversation gets through config.env once the lists merge. Before is safe for provider markers too: launch.env is stripped at assembly and conversation_environment records only config.env keys.

The test follows the concept: set every name to caller, assert no stand-in provider sees the value caller. lf markers set fresh pass; any inherited marker, of either kind, fails.

What could break it

  • NativeClient::new starts removing lf markers it used to inherit. If a native work session read one from the held lf's environment instead of config.env, its turn hooks go quiet. The launch matrix's work-session rows show it in slice 1.
  • A Codex-only list entry (CODEX_SANDBOX) removed from a Claude launch: harmless, the names are vendor-unique.
  • New provider markers in a future release: they leak until added. A name list accepts that cost to keep the person's settings.
