Review result: nothing to change and no open product choice. Jack Heart's accepted direction removes retained processes while preserving the conversation and command results. The earlier review's JSON and exit-result gaps are repaired. No additional implementation direction is proposed here.

Same actions, fewer retained processes

Action                 Concept                     API
Open a conversation    Session                     lf resume SESSION
Close its pane         viewer leaves; owner stays  detach / disconnect
Open another pane      same Session, new control   lf resume SESSION
Recover after reboot   saved Session and history   lf resume --all

Before this change: the viewer retained launch state; inner connect and lf -i waited beside Claude.

viewer ⇄ owner → connect → lf -i → Claude

Implemented: connect becomes the launcher, which becomes Claude. The viewer becomes a store-free relay.

relay ⇄ owner → Claude
          └─ terminal, wait, capture and exit settlement

Session and AgentProcess identities survive. Attachment tokens retain exact provider authority; viewer tokens govern terminal control. The relay has no independent durable lifecycle. Graph steps retain their launcher to settle each step before continuing; Codex and OpenCode retain their required relay clients.

The consequential mismatch is resolved

Exec discards the caller's remaining work. Removing a waiter had also removed post-return JSON and changed the interpretation of native exits.

Implemented repair: the resulting Session ID carries the JSON continuation to the relay. Fork and thread replacement prepare once, then open that identity. The owner and returning launcher share SessionCommandOutcome; NativeExit carries settlement data and record_process remains the writer. No new table or public command is needed.

lf resume SESSION --prepare --json  # Desktop's prepared command
lf resume SESSION --json            # one Session record after successful return
lf resume SESSION --fork --json     # one fork; return the new Session

The live relay opens no store. After success it reads the final Session record; failure produces no success JSON. Native exits 7 and 130 remain command failure 1 unless interruption or attachment loss changes the command outcome.

Failure and recovery retain the same conversation

Failed startup retains prepared input for an explicit retry. Failed provider exec withdraws the handoff so the launcher settles failure. A previous owner cannot settle a replacement attachment. After an unrecorded owner loss, lf resume --all restores saved history without replaying the interrupted turn. Closing a viewer does not complete the Session.

Counterexamples remain explicit: replaying fork would create another Session; letting stale settlement overwrite an attachment would end the replacement; replaying relay argv after owner replacement would target a dead owner. The first two have fixture coverage here. LOO-705 supplies the successor; LOO-712 owns its wire encoding. Integration with LOO-710 must also preserve terminal preview cleanup across exec.

Questions for the remaining proof

  1. Does final Desktop/Claude acceptance show one owner, one relay and no retained Claude launcher? The prepared-command stand-in proves the code path, not the configured Desktop experience.
  2. Does final-tree footprint remain a few MB per viewer? The earlier stand-in measurement was owner 20 MB and relay 2.5 MB, before compression.
  3. Do the affected gate suites pass, and does later integration retain the explicit successor, preview cleanup and JSON continuation?

These are verification obligations, not unresolved product choices. This pass inspected source and fixtures, changed review documents only, and ran no lifecycle tests or provider turns. The working design holds the decision; loop-or-next owns routing.
