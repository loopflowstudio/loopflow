The hold is right. The place it's shown is wrong.

You don't need to decide anything for work to continue. The first pass settled the evidence for a hold, a Task occurrence present in a Rex inventory, and the branch implemented it. This pass checks who reads it.

What you do

existing
lf open → Rex Task tabs appear → you work, leave, return, close a tab when you're finished with it. Cleanup of a Task happens later, while you're away.

The mismatch

existing
Every receipt from lf open prints:

  Rex views: held (a retained view keeps this Task)
  • It almost always reads held, because opening just made or reused the view.
  • It claims a protection nothing enforces yet. No cleanup reads it, and docs/workspaces.md says retention integration is not delivered.
  • A receipt covers one destination, but the hold covers the whole Task, across copies and servers. Each opened Task also adds a Rex inventory read.

The reader that matters is the shared lifetime owner (LOO-717), when the person is away. Accepted contract: the Rex adapter reports and LOO-717 decides.

Next implement pass

  1. proposed Text output reports the inventory: present · confirmed closed · unreadable. It makes no keep or cleanup claim.
  2. JSON rex_hold keeps held · released · unknown for the shared owner and the demo. Its doc comment says it is Task-wide.
  3. hold::task_hold stays the one adapter read. No task status field or new command yet: that would pick LOO-717's API for it.

Counterexample still open

A restored, forgotten tab keeps a completed Task's checkout until you close it. That follows from “retaining a view is the reason to keep.” If the demo shows you don't want it, that is a product choice for you, not something to solve with away detection.

For the demo

  1. Should a restored, unfocused Rex tab keep a completed Task's checkout? (a) yes, until you close it, which is the current reading; (b) no, a host restart releases it.
  2. Where should you read why a Task wasn't cleaned up? (a) lf task status; (b) wherever LOO-717 reports cleanup decisions; (c) lf open --json is enough.
