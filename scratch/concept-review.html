Hashimoto-inspired review

Simulated analysis grounded in public writing. Mitchell Hashimoto did not review this change; the judgments below are ours.

  • Keep the shared core. Reuse the existing owner, Rust reads and CLI commands. Let Desktop and iOS exercise the contract before expanding it. This applies the consumer-driven extraction described in Libghostty Is Coming.
  • Make the next proof usable. Replace the installed helper while a draft and Graph are live, then keep editing. Separate registration and restart tests leave that composition unproved. This applies the tangible-progress approach in Building Large Technical Projects.
  • Judge the interruption in context. A recovery shortcut can be correct and still break the editing flow. Native status is a proposal to evaluate with actual use, applying You Have to Feel It.
  • Force failures. Keep takeover, expired-output and ended-owner tests; finish update, cancellation, uncertain-command and usage proofs. The principle comes from Testing Error Recovery, not a recommendation to add Zig or Tripwire here.
What must survive—and what remains unproved

Held drafts, active turns, pending requests and running Graphs already protect their owners. The default two-minute detached quiet expiry applies to unheld Sessions. Headless Runs do not expire because viewers leave. Keep this existing policy.

Automatic recovery must become passive when another viewer owns control, stop when the pane closes, report disabled/incompatible service or an ended owner explicitly, and never resubmit commands or uncertain input. A replacement provider would violate this recovery contract.

Native quit/reopen, installed-helper replacement, unchanged provider usage, affected suites and Linux acceptance remain open. This review adds no passed checks. “Standalone” means the UI can close; the selected signed app still supplies the Mac helper.

PR #1813 is published; the Task remains at demo. Implementation is requested; Auto-Ship remains unapproved. The accepted direction is recorded in mobile-backend.md.
