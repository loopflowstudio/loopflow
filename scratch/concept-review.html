Themes, round 2 as built: do the concepts line up?

Area taken: Choose Theme and the catalogue behind it, with the whole branch in it against base 621fb0926d: 13 families, the card grid, retired names, import, and the title bar role from round 1. The earlier version of this page reviewed round 1 only (title bar role, found nothing to change); that finding still holds and is summarised in the table.

One interaction, walked

System mode, Mac dark. A person opens Choose Theme to try Fig.

  1. They see a mode control, then two buttons, Light theme: Loopflow Light and Dark theme: Loopflow Dark, then a Light themes section of 13 cards and a Dark themes section of 13. The ringed card in each section already says what each side uses. The buttons say it again.
  2. They click Fig. The window turns plum; Fig is ringed; Customize appears under it. Clicking the Dark button would have done nothing visible except move Customize to whichever dark card is ringed.
  3. Failure. They have a dark Ghostty file and click Import file… under the light section, the one nearest the top. The chooser answers in red: “Midnight” is a dark theme. Import it from the Dark picker. Apply goes grey. There is no thing called the Dark picker on screen; there is a button labelled “Dark theme” and a second Import tile further down. The app read the file, knew it was dark, and refused to put it there.
  4. Recovery. They scroll, find the second tile, import again. Two tries for one file.
  5. Old setting. Their theme: said Linen. The window opens in Loopflow Light with: “Linen” is no longer built in, so Loopflow Light is showing; to keep it, import its Ghostty theme file under Yours in Choose Theme. Linen was Loopflow's own design; no Ghostty file named Linen exists. Clay's upstream was Desert Morning. Even for Gruvbox Dark, the upstream file has none of the app roles the built-in carried, so “keep it” is not what import gives.

Biggest mismatch

The grid replaced the per-side list, and the per-side list's machinery stayed: the side buttons, the picker they drive, and an import that only works from the side you pre-picked. Each was right for a chooser that showed one side's list at a time. With both sides on screen as rings, they are a second way to say the same thing, and the import refusal is the place where the second way breaks.

Recommendation (in scratch/plan.md, Remaining 1–3): delete the side buttons and put each side's chosen name in its section heading; import files a theme on the side its colors say and previews it there; the retired-name sentence drops the import advice. The store gets smaller (no refusal, no refusal branch in canApply), the view loses a row, nothing a person relies on goes away except seeing the other side's name in Light-only mode.

// today
guard file.theme.isDark == dark else { draft?.refusal = "… Import it from the \(other) picker."; return }
// proposed
let dark = file.theme.isDark
if current.mode != .system { draft?.selection.mode = dark ? .dark : .light }
picker = dark ? .dark : .light
stage(file.theme, for: file.theme.name)   // then assign that side, as today

Questions

  1. The side buttons. (a) delete, names move into section headings chosen for review; (b) keep them as read-only labels; (c) keep as built.
  2. A dark file imported in Light mode. (a) preview switches to Dark mode, Cancel undoes chosen for review; (b) switch to System; (c) file it under dark Yours without previewing.
  3. The retired-name sentence. (a) ““Linen” is no longer built in, so Loopflow Light is showing.” chosen for review; (b) also name the closest new family (“try Tannin Light”), which needs a 22-entry mapping kept by hand.
  4. Families. (a) stay a naming convention; pick each side as built; (b) a separate Task makes a family a thing the app reads, so System mode picks once.
