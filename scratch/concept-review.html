Where is the Task I just filed?

New Task on Mac has two destinations. File opens the brief in its backlog. Start opens the Task’s conversation. Both actions begin with an editable draft and end with a Task the Machine has saved.

This review follows both actions from the sheet to the Task and through refusal, reconnect and recovery. The branch already makes the workflow picker a choice for Start.

File shows the result from the answer

You write “Make the Task brief easier to scan” in the repository and click File to backlog. The Machine commits the Task and replies while Desktop’s planning subscription is still reconnecting.

One draft until the Machine answers

Keep the sheet visible for File and Start while the Machine answers. Show which action is in progress. A confirmed refusal leaves the same request, scope and workflow available to edit. A Wave that is known to be gone stays named in In until you choose another destination. A saved submission with an uncertain outcome hands off to recovery under its original identity.

On successful File, use the existing RoadmapTask from TaskCreated.row as temporary evidence for the open brief in its recorded backlog. Render it once. A current row for the same ID takes precedence, including a change of scope or backlog membership. Release the temporary evidence when the selection leaves it or a current Task read establishes that it has moved or gone. An absent row in stale or partial planning is inconclusive.

On successful Start, close the sheet as soon as admission answers and open the returned Task and Session. Its conversation runs checkout and Graph setup. A filed Task has no Graph preference to persist. Both outcomes already fit the existing write, receipt and Work rows. The changes belong in Desktop’s draft and presentation.

Choice for review. Keep the form through admission and remove the separate read-only Start failure screen. That leaves one place to correct the request and keeps checkout and launch off the submission’s wait. Current Start screen · Admission milestones

Walk the proposed handoff

Normal

Pick review in Ops and File with planning paused. The response opens the brief immediately. After planning catches up there is one row, and first Start offers the current Ops default. Opening New Task and clicking Start with review instead opens the admitted conversation.

Refusal

Choose review, then remove that definition before Start. Once the Machine refuses and confirms no receipt, the sheet still has the text and the named choice. Pick Use default to start, or File the same brief. If the selected Wave disappears, pick where the Task should go.

Lost answer

Drop the connection after commit. Recovery reads the receipt for the saved request on the original Machine, finds the same Task and presents it. Before commit, recovery can resend the saved payload under that ID if the Machine confirms absence. An unavailable lookup leaves the submission saved.

Counterexamples. A planning frame can arrive before the create reply and already have a newer row. Use that row once, even if the Task has moved or started. If the person changes windows, scope or Machine while the reply is in flight, leave the result recoverable without taking over a newer destination. Existing New Task tests · Start after a lost reply
