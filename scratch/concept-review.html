Before → implemented in this checkout

Before: addressed actions used the last warm store; Refresh could prepare while its paused predecessor still lived; unchanged selection could leave recovering focus unreconciled.

Implemented, awaiting mounted acceptance: addressed Work selects its repository store; the pool owns viewer retirement; Refresh waits for it; launchId excludes replaced failure callbacks. A transition to usable input reconciles selected focus while leaving Find, IME and other editors alone.

The holder and provider keep the editor and running work. No new database state, readiness flag, protocol or recovery service. No submitted input is replayed.

Walk through recovery

Open the same Task → read its surviving conversation → type when ready. If status disappears, input pauses. Refresh retires the old viewer and reveals that same Session. Another controller keeps input until Take back. If the provider ended, resume its history; its lost editor is not promised.

Still to show: in a disposable mounted Desktop, keep an unsent draft, kill only Desktop, reopen the Task, edit the draft and submit one new marker. Repeat Refresh with another controller. Headless checks cover routing, retirement and transport continuity separately. They do not establish mounted focus, real pending-request preservation or the original crash cause.

  1. Does Refresh take input from another view? No. Take back is deliberate.
