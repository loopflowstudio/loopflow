The decision: the diff deletes lf process rollover and leaves every running conversation on the build that started it. Is quitting and resuming each one by hand the upgrade story you want, or does a smaller bulk move come back before this lands? The other four questions are smaller.

The concepts

BeforeAfter this diff
Owner: a process that hosted one conversation, shell or headless run, relayed its viewers and settled its exit. Holder beside it for Task and Wave conversations. Rollover to move owners across builds. A launch runs in one of three places. Here: the command's child. Held: a terminal the holder keeps, seen through views. Detached: a plain process with a log. Separately, a launch is Work or bare, which decides its hooks and whether it needs the server.
The whole rule, from transport::delegate
held      not -b, and (opened in a Desktop pane or framed view, or Work at a terminal)
detached  otherwise Work, unless a Graph is already running it as a step
here      everything else

The biggest mismatch

The deletion is clean; the thing it deleted was also the upgrade path. A conversation now stays on its build until someone quits it, and each build with a live conversation keeps a holder.

  • On this Machine lf ps lists live processes on 17 superseded builds, 0.14.19 through 0.15.3, beside the selected one. With stream: dev and frequent installs, that is the normal case here, not an edge.
  • A conversation on an old build keeps the hooks that build wrote. When a newer lf no longer understands one, the hook prints "ignoring …, a hook from an earlier lf; restart the Session to refresh its hooks" and the turn goes on. So after enough installs a long-lived conversation can stop receiving what that hook delivered, and the notice is inside the agent's context, not somewhere you look.
  • Nothing lists which conversations are on old builds, and nothing moves them. LOO-879 would list them; it does not move them.

One smaller shape for a bulk move, as a sketch: because lf resume already continues any conversation from history, moving one only needs its old terminal to end. "End idle conversations on superseded builds" is one action with no state of its own; each resumes on the current build the next time it is opened. Unsent input is lost, as with the old rollover.

Things a person now has to learn

  • -b has two lifetimes. lf -b review dies with its caller; lf -b --task LOO-12 review does not. An agent whose tool call times out leaves the second one editing the checkout with nobody reading its output. A rule that would be easier to say: a Graph outlives whoever started it; a single run never does.
  • A bare conversation's lifetime depends on where it was last opened. Opened in a Desktop pane it is held and survives the pane. Quit and resumed from a terminal, the same Session runs in that terminal and ends with it.
  • "Detached" now means two things. A Session in state detached is a held conversation no terminal is showing. A Detached launch is headless work with no terminal at all. Both are in docs/sessions.md.
  • "Owner" still appears. The process is gone; the word remains for which view may type and set the size (OwnerProtocol in Swift, the owner wire events, "Take back"). That is the control model, left for its own Task.

Questions

  1. Upgrading with conversations running.
    1. As built: each stays on its build; quit and lf resume to move one.
    2. Add the small bulk action before landing: end idle conversations on superseded builds; each resumes on the current build when next opened.
    3. Land as built and make the bulk action part of LOO-879.
  2. -b Work commands.
    1. As built: a -b run that names a Task outlives its caller.
    2. Only Graphs, landing watchers and lf ship detach; every single -b run ends with its caller, Work or not.
  3. A bare conversation an earlier build is running, resumed from a terminal. You said "ideally it would just restart the session".
    1. As built: it restarts in that terminal and ends with it.
    2. It restarts held, so it keeps outliving the terminal as it did under its owner. The worker's note: this is a special case in delegate.
  4. The two meanings of "detached".
    1. Leave it; LOO-879 already asks whether viewing leaves the Session state.
    2. Rename the place before landing (for example "background") so only the Session state uses the word.
  5. Desktop shells.
    1. As built: Close ends the shell at once, and shells need the Machine server, including under systemd on headless Linux.
    2. Something here should behave differently; say which.
