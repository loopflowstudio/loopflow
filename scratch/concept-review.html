Reading, copy, Find and scrolling stay available. Only this explicit action requests input and geometry from the same owner.

Surface presence and input permission are separate. The native connection reading is disposable presentation, not persistent Session state. A generation-bound mailbox action reaches the existing relay. The owner grants input and geometry; existing Session and Graph records retain execution identity. Closing the pane removes its mailbox and cancels recovery.

Move here sends Attach { control: true, replace: true, own: Take, … } once, consuming the action before transmission. Input waits for acknowledgement. The fresh screen and parser replace the retained display together while the stream offset stays intact. Recovery never repeats the takeover or uncertain typing.

Normal use, failure and recovery

  1. Normal: recovery returns read-only because a newer viewer controls the owner. Keep reading; choose Move here to edit the same draft. The other viewer loses its claim, while the provider and Graph remain.
  2. Failure: the takeover reply is lost. The claim may have changed; do not infer failure or queue typing. Show reconnecting outside terminal bytes.
  3. Recovery: reconnect non-replacing to the same owner. If another viewer obtained control meanwhile, remain read-only. A fresh deliberate action is required to replace it. Closing the pane cancels pending presentation/action state.

Counterexample: if a lost reply causes recovery to resend Move here and revoke a newer viewer, this design has failed. Likewise, closing and reopening a healthy viewer just to expose its action is not the intended interaction.
