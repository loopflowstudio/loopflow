One owner for each fact

The client retains request identity, original destination, exact versioned payload and submission time. The server retains the receipt and derives its recovery disposition. The presentation owner removes the client record only after showing the result. Neither side gains another lifecycle ledger.

A lookup stays read-only. A continuation rechecks the same request under its existing lock. Failed lookup is not absence; a removed resource is not a new creation. Work readings, exact-owner terminal recovery and provider history remain separate. Showing any of them grants no launch, input or resize authority.

Counterexamples to retain: failed removal repeats presentation safely; newer Session input prevents an older unpublished change from continuing; another viewer keeps its input and geometry when a sleeping viewer returns.

Next demo checks

  1. Do ordinary creation and promotion finish without a recovery chore? Required: show the result and remove only that submission.
  2. Does quitting after the reply but before presentation recover the original? Required: retain the request until its result is shown.
  3. Do an interrupted launch and stop remain inspectable without another effect? Required: truthful operation-specific text and no automatic replay.
  4. Does sleep/wake recover the original terminal without repeated input or changed claims? Required: keep display recovery separate from provider launch.
