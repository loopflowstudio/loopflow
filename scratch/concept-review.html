Biggest mismatch: a Task clock nobody reads

As built

The plan's inventory says: planning_revision, keep, "the peer exchange's clock (planning_peers.rs)". That file no longer exists. #1983 replaced the exchange with per-field stamps, and each local save writes three records of "this changed": a stamp per field, a plan_changes seq, and updated_at. It also does planning_revision+1, which nobody reads.

It's small, but it's exactly the kind of duplicate this Task exists to remove, and it appeared while the PR sat in review.

Proposedproposed

Add -- leaving: tasks.planning_revision LOO-877 to task_facts_once.sql. Delete the increment and the dead column from TASK_COLUMNS, and move the plan's inventory row to leaving. The leaving guard then fails any read that comes back.

What survives: released lf keeps writing the column until the staging window ends, which is harmless. What changes: nothing a person sees. What would break it: a reader outside Rust, and the search found none.

Plan text the merge made wrong

  • The tasks inventory keeps paused and shipped_at as lifecycle. Both are now leaving, under LOO-938 and LOO-971.
  • "URL, branch and team keep travelling with the peer exchange": they now travel as stamped fields through plan carriers. The verdict holds; the reason has changed.
  • The rule "tasks holds every Task fact a person sees on any Machine" can now be tested in code: a column is shared if and only if a WorkValue carries it.
