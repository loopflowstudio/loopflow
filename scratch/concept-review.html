A launch that ends before Claude's first turn

LOO-984 · concept review of the change as built (origin/main..0882c821ee) · 2026-11-19, after the second qa pass · blue marks what is proposed, everything else exists

Area taken: opening a conversation again: who decides resume or start again, what a person is told, and every other reader of the thread lf recorded. That is open, open_waiting_locked, resume_native_session, new_thread, saved_thread, the Session projection behind the action label, the headless turn, and the lines lf resume prints. Wider than the deleted guards, because the change gave the recorded thread a new meaning: named by lf, not yet a conversation.

The interaction

Base (origin/main)

$ lf -a claude resume     # Esc at Claude's first screen
claude exited with 1.
$ lf resume
(fresh thread via lost_thread on the open path;
 "No conversation found" on openers that skip it;
 two guards ahead of the record for a missing
 CLI and a stopped server)

This branch (qa E, real Claude 2.1.329)

$ lf -a claude resume     # Esc at Claude's first screen
claude exited with 1.
$ lf resume
This conversation has no saved claude transcript;
starting it again from its first request.
╭─ Claude ─…              # new --session-id

Failure and recovery are the same act: open it again. Nothing to learn, no second command. A saved thread reopens with --resume (qa R); a provider that refuses that resume leaves the Session as it was (qa P).

Biggest mismatch: "has a thread" has two meanings

lf names Claude's thread and records it before Claude starts. This change made the interactive open path stop trusting that record and ask the provider's files instead. Every other reader still trusts it: the Session projection (has_provider_history), the headless turn, the conversation log, the provider switch run headless.

As built

record        = the thread lf chose
saved_thread  = record ∧ transcript exists
                (interactive open only)
has_provider_history, headless turn,
moves, conversation_log
              = record

Proposed, larger than this work

record        = a thread the provider saved
                (written when a turn is saved)
every reader  = record
thread_lost   = only "transcript deleted since"

Recording on a saved turn makes the label, the headless turn and the opener agree with no file read per listed Session. What it takes: the launch carries its chosen --session-id somewhere other than the resumable record until the first turn hook reports; Codex already records this way. SessionStart is too early (it fires before Claude writes anything).

Choice made for review. This work keeps the record as written and filters at the one place that turns it into --resume. Passed over: moving the record now (hook delivery and every reader above, against four open PRs in the same files); having the projection read Claude's files (ruled out at 10,000 Tasks). The filter is what any later design still needs for a transcript deleted after it was saved, so nothing built here is thrown away.

Larger than this work

Record the thread when the provider saved it (above). Fixes the label and makes c2ed1c's two readers correct without touching them.

c2ed1c as filed is the narrower step: the headless readers go through the same decider. It also has to answer what that turn carries: the first request and then the message, or the message alone.

Outcome

Nothing to change. The built concepts hold on the normal path, the failure and the recovery; the two "no" rows are the same mismatch and both sit outside this work.

Questions

  1. "Has a thread": a) leave the record as written and filter at open (built) · b) file a Task to record the thread only once the provider saved a turn.
  2. c2ed1c, the headless turn: a) route its readers through saved_thread · b) wait for 1b, which makes them right as they are.
  3. What a headless turn to a never-saved conversation carries: a) first request, then the message · b) the message alone.
