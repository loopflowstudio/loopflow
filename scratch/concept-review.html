Quit releases the view.
Cleanup must not need it back.

Design changed; next implement direction. Separate the reason a host releases retention from evidence that its native resources have settled. Jack Heart's accepted quit, Close and grace rules already imply this distinction. No new product approval is needed; runtime implementation remains pending.

The consequential mismatch

Existing: closed both skips the fifteen-minute grace and acknowledges native cleanup. away keeps the grace, but retirement then waits for that host to report closed.

Leave a completed Task → quit Desktop → grace expires.
An away report still requires another Desktop acknowledgement. A closed report would skip the grace. Neither expresses the accepted interaction.

Source inspection finds a window-Close hook but no explicit acknowledged quit-release path. Installed AppKit ordering has not been demonstrated. Crashes and unacknowledged releases must continue to leave cleanup pending.

Actions → concepts → APIs

Leave or quit Desktop
Proposed implementation: release retention and settle native presentation; preserve destination execution. task presence records away plus native settlement in the same revision. The existing deadline runs; Desktop need not stay open to acknowledge it later.
Explicitly close the last Task workspace
Use closed as Close intent; record settlement independently. Skip grace after requested work settles. Session and shell owners retain their own execution checks.
Return before retirement
A newer retained observation revokes pending retirement. Reconnect checks the same shell receipt. Delayed settlement cannot override the return.
Leave a Rex Task with native shells
away releases retention but does not prove settlement. LOO-498's adapter closes that Task's resources and acknowledges them; other Tasks survive.

Keep the existing Task, Session, shell receipt, host occurrence and retirement intent. Add one settlement fact to the occurrence and presence write. Reuse the destination executor and current revision fencing; no new lifecycle service.

Proposed usage copy

Quit Desktop to leave shells running. Completed Tasks retain their shells and checkout through the fifteen-minute absence grace; eligible idle agents follow the two-minute policy. Cleanup can finish while Desktop stays quit. Explicit Close skips grace after work settles. Failed release leaves cleanup pending. Reconnect reuses surviving execution; New Shell starts fresh.

Proof before acceptance

Use the same PID and jobs through acknowledged quit, then retire the completed checkout without relaunching Desktop. Kill the app or lose SSH before acknowledgement: retain the checkout. Return after settlement: cancel cleanup. Repeat with active work, another retaining occurrence and Rex-owned resources. Existing loopback SSH tests do not establish these installed host behaviors.
