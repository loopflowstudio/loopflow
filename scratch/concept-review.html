The consequential distinction

Superseded proposal: requested cwd, pending movement and provider confirmation formed a separate lifecycle.

Accepted and implemented: Session cwd records selection. Process cwd records where execution began. An already-running client may continue in its original directory. Binding leaves its transport, drafts and files alone; later connection uses the selected directory.

The running-client counterexample prevents a claim that binding moves a live process. Jack accepted this limit. No pending-directory state, reconnect gate, implicit interruption, input replay or conversation fork is required.

Failure and recovery

A conflicting permanent assignment or failed reservation leaves adoption unapplied. Retrying an explicit source recovers its Task. If OpenCode rejects a native directory move during later connection, that connection fails; the same Session identity and selected directory remain available for retry. An opening prepared before binding cannot overwrite the explicit directory choice.

Same-checkout subdirectories survive. Main and Wave checkouts remain shared. Open unplaced Tasks can adopt an unowned linked checkout; done unplaced Tasks bind in place without acquiring one. Done placed Tasks retain their checkout and stay done. Closed Sessions and headless Runs cannot become primary.

Remaining proof, not an open design choice

  1. Demonstrate the immediate-directory candidate through the configured path, preserving the distinction between selection and live execution.
  2. Demonstrate Desktop creation with an unsent composer draft. Existing native CLI continuity does not establish Desktop composer retention.
