Do the concepts line up? A Session and the view someone is at

Area taken: everything that decides whose terminal a running Session is shaped for when more than one view shows it. That is the transport's sizing rule, the relay, Desktop's warm panes and Loopflow Dev. The Task names resizing; the same rule also decides colors, who answers the agent's terminal queries and what the agent hears about focus, so the review covers all four.

Nothing is built yet. Marked proposed is what the plan now says; everything else exists today.

The answer in one picture

The biggest mismatch: attaching is not using

Before

  • You, in Desktoptyping to an agent at 120 columns
  • Dev launchesstarts relays for ~20 Sessions; each attaches at Dev's width
  • Each Sessionresized, SIGWINCH, colors swapped, agent told "focus lost"
  • Youclick back into the pane to get your width again, one Session at a time

After proposed

  • You, in Desktoptyping to an agent at 120 columns
  • Dev launchesshows placeholders; starts nothing
  • You click a Task in Devits pane attaches focused:false, Ghostty reports focus gained, that one Session takes Dev's size
  • You click back in Desktopfocus gained there; the Session is yours at 120 again

Questions

  1. Dev's restored selection at launch.
    1. Waits behind the placeholder until clicked (plan).
    2. Opens that one Session; it is on screen and focused, so it takes Dev's size.
  2. Release Desktop's warm panes.
    1. Keep warming, attached unfocused (plan).
    2. Lazy everywhere: a pane's relay starts when the pane is first shown.
  3. A view that isn't in use reports focus lost.
    1. Dropped before the agent (plan).
    2. Forwarded, as today.
  4. --unfocused on lf session resume.
    1. An ordinary documented flag (plan).
    2. Hidden; only Desktop passes it.
  5. owner meaning both the Session's process and the sizing view.
    1. Leave it; note only (plan).
    2. File a Task to rename the sizing view on the wire and in the README.
  6. A remote lf older than the flag.
    1. The pane fails with the remote's usage error (plan).
    2. Desktop omits the flag for remote Machines until they report a new enough lf.
