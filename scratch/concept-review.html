3. Concrete interaction walk & counterexamples (Pass 3)

Scenario What happens under Pass 3 Counterexample tested & caught
Reopen Antigravity with waiting steers or Task update
lf resume --task <id>		 PreInvocation runs as Start. emit_block builds reference context via block_reserving and claims steers via steer::claim. Antigravity::hook_reply emits two injectSteps: collapsed context first, then steers with metadata.user_markdown. The person sees the steer/update inline right above the reply. Reference context leakage: if metadata.user_markdown were placed on the combined block, 9 KB of file listings and scratch files would dump into the TUI. Separate injectSteps guarantees reference context never gets metadata.user_markdown.
Fresh Antigravity start or reopen with nothing waiting
steers == None		 On fresh start, emit_block emits 1 injectSteps entry (collapsed reference context, no metadata). On reopen with nothing waiting, -i is omitted and no turn runs. Empty inline box: Antigravity::hook_reply only pushes the steers step when steers.is_some(), so no blank markdown block can ever appear.
Mid-session Antigravity turn / post-tool steer
Tool or Steer moment		 context is None. Antigravity::hook_reply emits 1 injectSteps entry with systemMessage (model XML) and metadata.user_markdown (clean human markdown). Escaping & long bodies: model-facing text escapes $ to &#36; and caps at 400 B with a prompt-log path; display renders raw unescaped markdown (so $PATH reads as $PATH) and truncates only very large bodies (> 2 KB) on a char boundary.
Claude / Codex / OpenCode / Pi Start or Compact with steers
Single-string additionalContext		 delivery.block_reserving(moment, steers.text.len()) reserves the exact steer byte count inside HOOK_CONTEXT_BYTES (10,000 B). Default Launcher::hook_reply concatenates steers.text + context into hookSpecificOutput.additionalContext. 10 KB hook overflow: generating a full 10 KB context block and appending steers afterward would exceed Claude's 10,000-character hook limit and Codex's 2,500-token budget. Reserving steers.text.len() inside block_reserving keeps the combined output ≤ 10,000 bytes.
Headless Antigravity worker
agy --output-format stream-json		 PreInvocation emits the same valid injectSteps with metadata.user_markdown on mid-turn steers; the model still reads only systemMessage. Worker protocol break: verified both in agy_cli.py fixtures (task_graph_launch_tests) and live against real agy 1.5.16 in QA.

5. Open questions for review

Reversible choices made for Pass 3 so it can be reviewed as built. Reply with a number and letter (e.g. 1b) to reverse any of them.

1. When a steer or Task update displays inline in Antigravity, how much detail should appear on screen?

The model still gets the full machine metadata (steer ID, source, revision, prompt-log path). This choice is only what the person sees in the terminal.

  • 1a (chosen for Pass 3): Clean label + body only — e.g. **Steer** (Jack Heart) or **Task update** followed by the message text (plus a short "N more waiting" line if more steers remain queued), hiding internal IDs and .lf/prompts/ paths.
  • 1b: Include the steer ID and source/revision header inline as well, matching the model-facing <lf:steers> text verbatim.
2. When you reopen a closed Antigravity Task conversation with waiting steers, what should appear as the opening user line above the inline steer?

Antigravity needs an opening prompt to trigger the hook that loads waiting steers before you type, so that line still appears above the newly visible inline steer.

  • 2a (chosen, built in Pass 1): Keep the short generic line "Read the waiting steers and Task updates for this Session." and display the actual steers inline right below it via user_markdown — nothing is marked delivered until the hook runs, so a failed launch never loses a steer.
  • 2b: Put the actual steer text directly as the opening prompt (no generic line, at the cost of marking steers read before Antigravity starts and losing Task updates that exceed prompt size).
