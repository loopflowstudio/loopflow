What decides that a reopened conversation is held?

LOO-821 now decides "managed" by the command typed. Desktop reopens a conversation with lf session resume <id>, which names no Task. The branch holds that reopen anyway by reading the conversation's recorded row. That keeps a second rule, a store read, beside LOO-821's command rule.

Built from scratch/questions.md ("Open: holding a conversation reopened by id"); transport.rs::held; harness/agent_process.rs::require_server_for; lf/mod.rs::Cli::names_work; session.rs::WorkSource::is_managed; swift/LoopflowTests/RegistryQueryTests.swift (the argv Desktop sends). Orange rules are proposed. Everything else is built.

The biggest mismatch is that a Task conversation is held or not depending on which door it came in through. The row read exists so that the door doesn't matter.

The two hold together only if "the command" for a reopen means the conversation it reopens. That is what the row read does.

The two ways

a · the conversation decides (built)A fresh launch is managed by its command. A reopen is managed by what was recorded when the conversation began: declared or bound. A Task conversation is held from every door, including a typed lf resume <id> and a pane reopened after a restart. The cost is one store read on reopen, and WorkSource::is_managed stays, used only there. If the store can't be read, the reopen starts unheld, as before holders.
b · the target decideshuman_session::open carries the resume target: --task, --wave or the repository conversation is held, and a reopen by id is bare. That is one rule with no store read, and is_managed is deleted. For a Task pane reopened by id to stay held, Desktop would have to send --task on every reopen. Today it sends the id once the conversation exists (RegistryQueryTests.swift:603), so that is a Desktop change too. A typed lf resume <id> of a Task conversation would end that conversation's view at the next install.

One check covers both: under (b), a Desktop pane for a Task, reopened after a Desktop restart, has to come back on the holder. If Desktop reopens it by id, (b) breaks it without the Desktop change.
