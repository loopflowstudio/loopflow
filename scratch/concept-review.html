Concept Review · LOO-1069 · Pre-implementation

Loopflow Desktop keyboard input & shortcut ownership for terminal panes

Area reviewed: All keyboard routing and key translation for Desktop terminal panes (Sessions and Shells), from macOS AppKit event monitors and menu equivalents through GhosttyMetalView and GhosttyManager to the held-terminal relay. Why this area: Modifier-key failures in Sessions are not isolated to one key handler — they sit at the seam between AppKit composition, Ghostty's key encoder, Ghostty's standalone-app default keybinds, and Desktop's own shortcut layers.

1. Do the product's concepts and the code's concepts line up?

Product concept Code concept Existing Aligned? What is wrong (where No)
One physical keystroke
A key press, repeat, or release with held modifiers reaches the program or composes text.		 GhosttyMetalView splits one keystroke across 4 paths: performKeyEquivalent, ghosttyShouldHandleKeyDownDirectly, interpretKeyEvents → insertText → ghostty_surface_text, and flagsChanged. No One action with no single owner. insertText pastes via ghostty_surface_text, dropping Option before Ghostty sees macos-option-as-alt. translateKey hardcodes PRESS (never REPEAT), sets consumed_mods = NONE, strips left/right modifier bits, and passes charactersIgnoringModifiers (which still applies Shift!) as unshifted_codepoint. The direct-bypass heuristic skips interpretKeyEvents for layouts whose ID lacks "inputmethod", breaking dead keys on US-International / ABC-Extended / European layouts.

Desktop owns app, window, and pane shortcuts; Ghostty owns terminal-surface bindings; the running program gets the rest. Same keyboard behavior in Sessions and Shells; disconnected panes accept no PTY input; exited children still dismiss locally. 2. The biggest mismatch — and the hidden trap in the kickoff plan

Biggest mismatch: One keystroke is split across four disagreeing translators, and Ghostty's standalone-app bindings collide with Loopflow Desktop

Today, GhosttyMetalView tries to classify keys itself before Ghostty sees them (direct bypass vs. interpretKeyEvents → raw paste vs. unconditional performKeyEquivalent). Meanwhile, GhosttyManager loads Ghostty's entire standalone-app keybind table even though Loopflow Desktop owns Quit, Settings, Windows, Tabs, and Splits and its action_cb ignores them.

The kickoff plan fixed the Option-B paste bug, but kept two contradictions: (1) it kept ghosttyShouldHandleKeyDownDirectly alongside the unified interpretKeyEvents path, and (2) it routed ghostty_surface_key_is_binding to keyDown in performKeyEquivalent without unbinding Ghostty's dead app-level bindings (⌘Q, ⌘,, ⌘⇧W, ⌘D, ⌘↩).

3. Concrete walkthroughs & counterexamples that shaped the design

⌥B on US layout (normal + config toggle)

  • macos-option-as-alt = true (or US default): key_translation_mods strips Option → AppKit translates "b" → Ghostty receives ALT + key B + text "b" → emits 1b 62 (or Kitty Alt+b).
  • macos-option-as-alt = false: key_translation_mods keeps Option → original NSEvent goes to AppKit → insertText("∫") accumulated with consumed_mods = ALT → emits UTF-8 ∫.
  • macos-option-as-alt = left: Left Option sends 1b 62; Right Option types ∫ because GHOSTTY_MODS_ALT_RIGHT is preserved.

⌘Q, ⌘,, ⌘⇧W, ⌘D in a Kitty Session

  • Counterexample caught: Ghostty defaults bind super+q=quit, super+comma=open_config, super+shift+w=close_window, super+d=new_split, super+enter=toggle_fullscreen.
  • Loopflow's action_cb returns false for all of them. Unbinding unimplemented standalone-app defaults in GhosttyManager makes key_is_binding return false, so Loopflow menus receive ⌘Q/⌘,/⌘⇧W and ⌘↩/⌘D aren't eaten into a no-op.
  • Surface-owned bindings (⌘↑/⌘↓, ⌘A, ⌘+/⌘-/⌘0, user text: bindings) still match and run once.

Dead keys & IME cancel (counterexamples)

  • Plain dead key on US-International: Typing ' then e must produce é. Deleting ghosttyShouldHandleKeyDownDirectly ensures non-IME dead-key layouts go through interpretKeyEvents.
  • IME cancel via setMarkedText(""): Clearing _markedRange to NSNotFound and calling ghostty_surface_preedit(surface, nil, 0) prevents stuck hasMarkedText() == true and sends zero bytes to the PTY.
  • Mid-composition shortcut: Checking NSTextInputClient.hasMarkedText() in both monitors stops Desktop shortcuts from interrupting composition.

⇧↩, ⌃↩, ⇧/ & Session reopen

  • ⌃↩ is claimed in performKeyEquivalent and routed to keyDown before macOS turns it into a context-menu shortcut.
  • ⇧/ (?) sends unshifted_codepoint = '/' (via characters(byApplyingModifiers: [])) and consumed_mods = SHIFT, matching Kitty disambiguation.
  • Closing and reopening the Session pane replays Kitty modes through repaint.rs; the same chords emit identical provider bytes before and after reattach.
  • While disconnected (!connectionAcceptsInput), PTY input stays blocked while ⌘C, ⌘F, ⌘`, and Desktop menus still work; an exited child still accepts its local dismiss key.

4. Choices made for review & what is outside this work

Choices written into scratch/plan.md (all reversible)

1. Delete the direct printable-key bypass (ghosttyShouldHandleKeyDownDirectly) instead of keeping two keyDown paths. Passed over keeping the bypass for ASCII because it breaks dead keys on non-IME international layouts and creates a second key-translation path that drifts from interpretKeyEvents. Matches upstream Ghostty's single-path responder.

2. Unbind Ghostty's unimplemented standalone-app default keybinds in GhosttyManager. Passed over leaving Ghostty's full default keybind table active because GhosttyManager.action_cb returns false for quit, open_config, close_window, new_split, toggle_fullscreen, toggle_command_palette, etc. — leaving them bound causes ghostty_surface_key_is_binding to swallow ⌘Q, ⌘,, ⌘⇧W, ⌘D, and ⌘↩.

3. Keep Ghostty's effective macos-option-as-alt setting (layout-dependent default + user ~/.config/ghostty/config) and sync layout switches via ghostty_app_keyboard_changed. Passed over forcing macos-option-as-alt = true globally in Desktop, which would break Option character entry on non-US keyboards and override explicit user config.

Outside this work (separate outcomes)

  • Unifying Desktop's two local shortcut monitors (DesktopActionMonitor + WorkPaletteShortcut) into one responder/registry layer: Fixing their NSTextInputClient guard is in scope here; merging palette focus restoration and slot-hint tracking into DesktopActions is a separate UI architecture cleanup.
  • Modifier support in lf desktop send-key (DesktopKey DTO): Extending the CLI/socket wire format for modified synthetic keys is a separate feature.
  • iOS hardware keyboard (LoopflowiOS/GhosttySurface.swift) and Rex: Separate platforms with their own key translation.
