Resolve one installation destination before acquiring an update.

Headless outcome: design changed. Preserving custom app locations already follows from the accepted coherent-installation requirement. The next implementation should use that location for download, freshness and promotion. No new product approval is needed.

The mismatch

The public CLI can point into /Volumes/Tools/Loopflow.app, while the scheduled installer chooses /Applications/Loopflow.app. Promotion knows how to discover the first app, but acquisition has already supplied the second as an explicit target. One installation has two location decisions.

Established by source inspection; no installed reproduction or rollout is claimed.

Current branch behavior

Scheduled lf install
  → LF_APPLICATIONS_DIR absent
  → download / freshness choose /Applications
  → promote receives an explicit /Applications target
  → custom app can remain on the old build

With CLI-only and no default app, acquisition can omit the bundle instead; promotion then refuses because the custom app's helper differs from the candidate.

Proposed next implementation

LF_APPLICATIONS_DIR=/Volumes/Tools lf install --preview
lf install
# The schedule follows the same installed bundle.

Without an explicit destination, updates follow the app reached by the public CLI. An explicit destination still selects the target; the default location serves initial setup. CLI-only skips first setup and keeps an existing app paired.

Action: lf install / scheduled install
  → one resolved destination + complete signed candidate
Concept: PromotionArtifacts
  → promote validates the app/helper pair
Record: SwitchReceipt.activation
  → activate app, public link and gate
Recovery: finish the same receipt at its recorded paths

Reuse the public link and existing receipt. Carry the chosen target into older downloaded installers; make the standalone shell entry follow the same rule. No destination registry or new schema is needed.

Failure and return

A failed download or preflight leaves the existing installation usable. After store advancement, retry completes the recorded custom app, public link and gate. Only Desktop is replaced; Session owners and Graphs retain their running images, and live retired bundles remain available.

The next proof exercises a custom location without its original environment, CLI-only, explicit destination with a detached link, scheduled and shell entry, then interrupted activation and retry. Signed desktop/mini rollout and usable existing Sessions remain required after delivery.
