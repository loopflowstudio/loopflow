Actions → concepts → APIs

Choose My project preferences
One edit destination → shared Rust destination resolution → main-checkout private file, Personal source, Repository scope. A Wave selection adds its stable ID and Wave scope. Shared destinations select the committed files.
Apply an implementation choice
Typed setting address and authored value → catalogue validation → existing files::edit/update. CLI and Desktop use that same address; file comments and unrelated keys survive.
Explain and launch implementation
Selected repository, Wave and target → settings::resolve → value and provenance for inspection and prepare_process_prompt. No independent inspection repository to keep synchronized.
Unset and recover
Remove the declaration at the selected destination → common writer → next resolution reveals lower declarations. The existing configuration observer updates subscriptions. No new persistent settings record is needed.

Keep the distinctions that carry behavior

agent choices still beat every default_agent fallback; within each class, source → scope → target decides. A personal skill choice beats a shared occurrence choice. A personal fallback yields to a shared choice.

Independent clones keep independent private preferences, including account order. Linked Task worktrees share their main checkout's file. Wave identity survives rename; reusing an old name does not inherit its preferences.

Remote execution still uses the initiating profile. Retention is a separate outcome: independent remote edits survive, forwarded work uses incoming declarations, and later direct remote work uses the saved file. This review proposes no new synchronization or recovery authority.

Failure, recovery, counterexamples

Normal: save a project implementation choice from a Task checkout; CLI inspection, Desktop explanation and launch preparation agree. Another clone retains its own choice.

Failure: select a global-only preference for a repository. The catalogue explains why it cannot apply before any write. A concurrent hand edit survives; retry reloads the latest file.

Recovery: unset the project choice. The lower declaration becomes effective while global settings and other Waves remain unchanged.

Preserve as tests: changing the scope picker must never save a broader global preference. A personal-global user.name request cannot be validated as personal then written into shared repository configuration, where its real reader would reject it. Today's fixture supplies a matching path and scope and misses both cases.

  3. What proves the change? Actual Desktop/FFI and CLI requests, then inspection and launch preparation across global, repository and Wave settings, including unset, linked worktrees and invalid destinations.
