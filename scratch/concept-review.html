Concept Review: Harness Parity & Waking Idle Work Sessions

Area reviewed: How Loopflow defines, enforces, and wakes interactive work sessions across all five harnesses (Claude, Codex, OpenCode, Pi, Antigravity) — covering the Harness / Launcher / Capabilities contract, storage idle-candidate selection, server wake & boundary follow-up, VT-guarded held-terminal prompt injection, reopen steer delivery, and cross-harness contract suites.

What is built & verified at 771d2d2967

The core architecture across Passes 1–4 holds together cleanly and has been verified live against real agy 1.5.16/1.5.17, Claude Code, and Codex 0.172.0 (scratch/qa.html): harness/parity.rs and the prose README parity table are gone; Harness and Launcher require full capabilities, caller markers, driver recognition, sign-in advice, and idle_reach; storage returns raw IdleCandidate rows and each launcher chooses its own wake endpoint; all five harnesses in HarnessKind::ALL pass idle wake unconditionally; Antigravity wakes both on reopen (-i WAKE_PROMPT) and when already open and idle via VT-guarded bracketed paste (preserving drafts, slash menus, dialogs, and unviewed sessions).

Why one more pass (Pass 5) is needed before gate

Reviewing the whole built change against 989b41c3bb surfaced two concrete mismatches introduced in Pass 4:

  1. Provider logic leaked into provider-agnostic terminal transport: Hosted::wake_idle_prompt in transport/hosted.rs hardcodes crate::harness::antigravity::prompt_ready — the only provider-specific import in all of transport/. Any future harness returning IdleReach::Terminal would silently test its screen against Antigravity's box/footer strings and never wake.
  2. Deferred turn-end wakes can stall up to 60 seconds: When a steer arrives during an Antigravity turn and the person has a draft open (or agy redraws past 600 ms after Stop), boundary::wake flips a process-global static DEFERRED: AtomicBool without waking StoreChanges::wait(60s) on macOS. Clearing the draft can sit quiet for up to a full minute.

2. Biggest mismatches — Before & After

Mismatch A: Harness readiness hardcoded inside generic terminal transport

Built at HEAD Transport depends on Antigravity

Launcher::idle_reach → IdleReach::Terminal(id) → Hosted::wake_idle_prompt → antigravity::prompt_ready 
// transport/hosted.rs (HEAD)
!self.output.terminal()
    .is_some_and(crate::harness::antigravity::prompt_ready)

Only place in transport/ that imports a specific provider. A new harness returning IdleReach::Terminal compiles and silently checks Antigravity's screen layout.

Pass 5 Harness supplies its own readiness predicate

Antigravity::idle_reach → IdleReach::Terminal { terminal, prompt_ready } → Hosted checks prompt_ready(vt) 
// steer.rs (Pass 5)
IdleReach::Terminal {
    terminal: TerminalId,
    prompt_ready: fn(&Terminal) -> bool,
}
// transport/hosted.rs (Pass 5)
!self.output.terminal().is_some_and(prompt_ready)

Zero provider imports in transport/. Compiler forces any terminal-woken harness to supply its own VT screen check beside idle_reach.

Mismatch B: Deferred turn-end wake cannot wake the sleeping watcher

Built at HEAD Up to 60 s stall after clearing a draft

t=0.0s agy turn running; steer saved; person types draft t=1.0s Stop hook writes session_activity (no rev bump) t=1.0s Watcher wakes on WAL, !moved && !deferred → kqueue sleep 60s t=1.6s boundary::wake exhausts 3×300ms → DEFERRED = true t=3.0s person clears draft (empty prompt ready) t=3–61s Watcher still asleep in kqueue(60s) — silent! t=61.0s timeout expires → finally wakes agy

Also uses a process-global static DEFERRED: AtomicBool that leaks across parallel tests.

Pass 5 Instance-owned WakeNudge wakes kqueue

t=0.0s agy turn running; steer saved; person types draft t=1.0s Stop hook runs → Watcher asleep in kqueue(60s) t=1.6s boundary::wake defers → nudge.retry_deferred() t=1.6s EVFILT_USER wakes kqueue immediately → 2s retry cadence t=3.0s person clears draft (empty prompt ready) t=3.6s Watcher retries on 2s tick → wakes agy

StoreChanges::waker() uses EVFILT_USER on macOS (same persistent kqueue) and Condvar elsewhere. No global static.

5. Open choices for review

Reversible choices carried into Pass 5 so the branch can be reviewed as built. Reply with a number and letter (e.g. 1b) to reverse any of them.

1. When an Antigravity work session wakes automatically, what should appear on the prompt line in the terminal?

Both reopen and already-open idle wake trigger Antigravity's turn hook by submitting a short prompt so steers are never marked read before Antigravity actually starts the turn.

  • 1a (chosen, built across Passes 1–4): Keep the fixed prompt "Read the waiting steers and Task updates for this Session." on both reopen and idle wake, keeping steers unstamped until Antigravity's hook runs (no steer loss on crash or dropped paste, and inline display stays cleanly tracked in LOO-1103).
  • 1b: Paste the full steer text directly into the prompt box instead of the generic trigger line (shows the steer text immediately, at the cost of either marking steers read before Antigravity confirms receipt or risking duplicate delivery if the paste fails).
2. How long should Loopflow pause after your last keypress before waking an idle Antigravity terminal?

Mouse clicks, scroll wheel, and window focus changes never reset this timer; only actual keystrokes do, and any text left in the prompt box blocks wake indefinitely until cleared.

  • 2a (chosen, built in Pass 4): 2 seconds quiet time after a real keystroke, retried every 2 seconds (and woken immediately after a turn ends once Pass 5 lands) — fast enough to feel live once you backspace a draft, long enough not to race mid-shortcut.
  • 2b: Longer quiet window (e.g. 5 seconds) to give more breathing room between clearing a draft and starting a new sentence.
