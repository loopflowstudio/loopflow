The interaction

A visitor lands on /, clicks Docs, reads, clicks Install, copies the command, mistypes a URL. Built: the bar and footer are the same element on every page (SitePage → SiteHeader · Main · SiteFooter); Install goes to /download from everywhere; the command there comes from the one install block and the copy button says "Copied"; a bad URL lands on a 404 inside the same frame with Home · Docs, which is the recovery path. test_faces.py fails if any page's header or footer differs.

The biggest mismatch

None at the concept level. The frame, install, palette and ramp each have one owner, and the old second system is gone rather than wrapped. What is left is small:

existing
@rt("/favicon.ico") async def favicon() declared after fast_app's /{fname}.{ext:static} route, so /favicon.ico answers 404.
proposed
Register it with the other front-inserted routes (app.routes.insert(0, Route("/favicon.ico", …))) so it works, or delete it. Working is the smaller-system answer: one place where routes that must win are registered.

Recorded in scratch/plan.md under "Left for gate"; it does not change the model.

Counterexamples tried

  • A future page that builds its own Title/Header: the identical-frame test covers four pages, not all routes, so it would pass. Acceptable: the only builder is SitePage, and there is nothing else to call.
  • /static/fonts/../main.py: Starlette's {name} does not match /, so the font route cannot leave the directory.
  • OS dark mode: data-theme="light" keeps Pico from recoloring; a test fails without it.
