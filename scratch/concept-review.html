Keep the watch recovery model

No design change or open product choice. This is the implemented branch behavior; composed Desktop recovery remains for QA.

The biggest mismatch was treating a received reading as already applied. Recovery now retains the same stream and its queued frames alongside the token. A token alone cannot restore the caller’s view.

Actions → concepts → APIs

ActionBeforeImplemented
Keep a Task list open through a dropThe stream ends; a new watch sends the whole list.The observation survives. subscribe.resume omits an unchanged baseline.

Close the viewCancel the watch.cancel also stops recovery. No disconnected watch is retained on the server.

An unchanged reconnect

Retained client state: reading + opaque token + queued frames
→ hello / welcome
→ subscribe { operation: same read, select: same fields, resume: token }
← response { result: null }
  No reading until a change or confirmation.

Unknown token or new server incarnation:
← reading { checkpoint: new token, frame: complete current state }

The token fingerprints the server incarnation, read, arguments, selection and reading identity. It creates no database record, history buffer or retention setting. Revision 3 makes the wire change explicit.

Recovery counterexamples

A → B → A during an outage resumes A without replaying B. An unavailable reading is always sent. A terminal task.wait still sends ended when its final reading is omitted. Overflow or failed reconnect ends the stream so the existing window retry path starts fresh.

The saved checks cover socket loss with a queued baseline and confirmation replay. They do not establish mounted Desktop or phone recovery.
