Remote Task workspaces: post-build concept review

LOO-1083 review at HEAD (e348359e59) against base 62a368e5cc, 2026-11-24. Area taken: opening, watching, and acting on a Task's workspace (Files, Changes, Diff, Save, Shell, Session) when another Machine owns it across CLI, Desktop, Mobile, and lf server. All four planned slices and QA have run; this review inspects the whole built area as someone seeing it for the first time.

built at HEAD marks behavior already committed on this branch. proposed marks what the revised scratch/plan.md (Slice 5) changes before gate and release, while protocol revision 10 is still unshipped.

What already holds at HEAD: "The Task is the address" proved out cleanly across all four slices. One local/paired lf server routes Task reads, task.save, task.get/task.status subscriptions, and bridged Session + Shell terminal tickets over pooled SSH pipes (PeerPool). Desktop's client-side SSH stack (onMachine, pinTaskLocation, LocalLineObservation, placement guard) and lf task watch-files are gone. Stale local checkouts are hidden from plan rows and Task status. Mobile has Session, Files, Changes, and Shell over one pairing.

Two concrete interactions where HEAD still breaks the model

1. Watching Files across unstarted, move, and local server restart

A Task starts unstarted on mini, gets a checkout, moves back to laptop, and the local server restarts while Desktop and the phone have Files open.

built at HEAD task.files.watch watches a directory

subscribe task.files.watch { issue } unstarted on mini → not_found{not_started} → subscription DIES permanently → Mobile: 5s client while-loop polls until checkout exists → Desktop: stays dead until task.get calls relocate() move laptop → mini (before mini's checkout exists): → not_found{not_started} → subscription DIES mid-move move mini → laptop: → TaskFilesRevision has no machine_label; TaskFilesStore has no localMachineId → store.machine = laptop.id (non-nil!) → stays "remote", shows raw home_… local server restarts: → ServerSubscription retries once after 100 ms, then throws → Desktop Files stuck on "Live file observation unavailable"

Because the server subscription cannot live without a checkout, both clients grew ad-hoc workarounds and Desktop's local/remote state drifts.

proposed task.files.watch follows the Task

subscribe task.files.watch { issue } unstarted on mini → reading { machine_id: mini, machine_label: "mini", checkout: null, revision: null } → subscription STAYS OPEN watching store_revisions → Mobile deletes its 5s while-loop; shows Not started checkout created on mini → reading { …, checkout: "/…/wt", revision: "…" } → same subscription id; Files & Changes load immediately move mini → laptop (even before laptop's checkout): → Producer::follow swaps to laptop under the same id → TaskFilesStore sees machineID == localMachineId → switches cleanly to local local server restarts: → Desktop observeServedFiles reconnects with bounded backoff, clears error

One Task-scoped subscription matches task.get and task.status. No client polling loop; no raw Machine IDs; no stuck banner.

2. Opening or switching a remote Session's harness, then leaving it

mini has no default_agent. Jack runs lf open --task LOO-12 -a claude from the laptop (or picks Codex in Desktop's pane menu), works, and detaches.

built at HEAD agent dropped; peer prints its own command

lf open --task LOO-12 -a claude 1. Write::SessionResume { task, agent: Some("claude") } → mini → ensure_task() calls prepare() without agent → "No agent selected" (fails) 2. Even with a default on mini: lf -a codex open --task LOO-12 (or Desktop switchProvider): → routed_terminal calls session.attach first → re-attaches to old claude! → SessionContinue has NO agent field → always drops -a 3. Detach / exit: → mini's native_session prints "Continue with: lf resume session_9f2" → running that on laptop: "Session session_9f2 was not found"

proposed Caller intent survives the route

lf open --task LOO-12 -a claude 1. Write::SessionResume { task, agent: Some("claude") } → mini → ensure_task() / prepare() honors agent → succeeds without default_agent 2. ServerOperation::SessionContinue carries agent: Option<String> (rev 10) → continuing() passes --agent <agent> to lf session resume → when caller's -a differs from current provider, routed_terminal calls SessionContinue instead of blindly re-attaching to the old harness 3. Detach / exit: → routed_terminal passes its own fallback_argv to relay_socket → prints "Continue with: lf open --task LOO-12" (works on this Machine)

The biggest mismatch: task.files.watch watches a checkout, not a Task

Every other Task subscription (task.get, task.status) is addressed to the Task: it starts before the Task has a checkout, stays open through a move's intermediate null-workspace reading, and reports what Machine answers. task.files.watch is the sole holdout: it opens a filesystem watcher directly, dies with not_found { reason: "not_started" } whenever no checkout exists, and carries no machine_label. That single mismatch forced Mobile to build a 5-second client polling loop, left Desktop's remote watch dead after a server restart, and broke Desktop's local/remote state when a Task moves back to this Mac.

Before (HEAD at e348359e59)

  • TaskFilesRevision { task_id, machine_id, checkout, revision } — non-null checkout/revision, no machine_label
  • Producer::files fails with not_started → subscription terminates on unstarted Tasks and mid-move
  • Mobile TaskFilesTree.follow() loops while !Task.isCancelled { await watch(); sleep(5s) }
  • Desktop TaskFilesStore.observeServedFiles() dies permanently on local server restart (QA #2)
  • Desktop TaskFilesStore lacks localMachineId → moving mini → laptop leaves store.machine non-nil
  • Desktop SessionsWorkspace.newShell refuses until workspace.location != nil
  • SessionContinue has no agent; ensure_task ignores agent; farewell prints peer's lf resume <id>

proposed After (Slice 5, still rev 10)

  • TaskFilesRevision { task_id, machine_id, machine_label, checkout: Option, revision: Option }
  • Producer::files emits { checkout: null, revision: null } while unstarted/mid-move and wakes on store_revisions when task_checkouts appears — same subscription ID throughout
  • Mobile TaskFilesTree.follow() deletes its 5s polling loop; one observeTaskFiles stream handles every transition
  • Desktop observeServedFiles() reconnects across local server restarts with bounded backoff and clears error on recovery
  • Desktop TaskFilesStore knows localMachineId (clean move-back-to-Mac) and reads machine_label from the revision
  • Desktop newShell falls back to task.runtime.owner, matching files(for:)
  • SessionContinue carries agent; ensure_task + routed_terminal honor it; bridged relay prints local lf open command

Outside this review (noted from QA, separate scope)

  • Git observation lag on peer reads (QA #5): lf task changes right after an edit reads mini's shared observe.rs cache (a few seconds). Existing server-wide observation design, not specific to remote routing.
  • Skewed peer executable message (QA #6): when a peer's server runs a different binary, Connection::open_peer times out at 10s instead of surfacing lf server connect's stderr. General peer-handshake diagnostic, independent of the workspace model.
