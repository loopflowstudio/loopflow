The biggest mismatch: who starts the server is answered three times

The branch's promise is "Dev leaves the installed server alone". That promise is one bit, and the code works it out in three places from three sets of inputs. They agree on every path the launcher produces today. They are free to disagree the next time one of them is edited.

As built

controlLfPath(bundled, environment) -> String
  LF_HOME + LF_BIN        -> LF_BIN
  executable helper       -> helper
  ~/.local/bin/lf         -> entry

ServerLocation.init(bundledHelper, privateHome, query)
  preparesServer = bundledHelper != nil || privateHome != nil
  -> "install server" or "server status"

GUIProcessEnvironment.enriched
  try? controlLfPath -> LF_BIN, PATH
  else if LF_HOME == nil -> drop LF_BIN

Proposed

enum MachineLf {            // what this app runs
  case privateHome(String)  // starts its own server
  case bundled(String)      // the installation; starts it
  case installed(String)    // a visitor; only looks
  var path: String
  var startsServer: Bool
}
LocalWaveAgentLauncher.machineLf(bundled:, environment:)

ServerLocation.init(startsServer:, query:)
  shared = machineLf().startsServer
GUIProcessEnvironment.enriched: reads the same value

The resolver already makes this three-way choice; it throws the answer away by returning a string. Keeping it removes ServerLocation's two environment parameters and gives the visitor case a place for its own sentence: "Loopflow's server isn't running. Open Loopflow, or run lf install server." On the three paths: normal (installed → status only, as the peer fixture already asserts), failure (a visitor with no server gets the sentence and makes no install attempt), recovery (the next read asks status again and connects).

Outside this work

Run in Xcode still bundles a branch lf and launch agents (cmd_bundle_control_tools), so that build acts as an installation and asks to be the server. Ending that needs debug builds to stop bundling while release and CI keep it.

Opening any Desktop on the Machine attaches a viewer to each retained workspace's Session, and a narrower viewer resizes the shared terminal (QA: a 160-column tmux view went stale at Dev's 120). The release app does the same; a Dev window makes it more likely. A view that doesn't size the terminal is its own outcome.
