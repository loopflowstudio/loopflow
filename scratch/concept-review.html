Accepted clarification: follow the LF process viewing the Task Session. When its last viewer exits, release that hold. A Rex tab remaining after the viewer exits is not a separate hold.

This removes the need to track Rex workspaces in LF or identify old native blocks. LF never closes Rex shells. Active requested work and other open viewers still protect the Task.

The mismatch in the published change

Current implementation

Stores generic host occurrences, leases and native settlement. It observes a supplied host process identity. That does not express the intended boundary of an LF Task Session viewer, and external-host persistence conflicts with the accepted ownership decision.

Accepted next implementation

Reuse LF Session/viewer attachment and Process identity. Confirmed last-viewer exit releases the hold. Remove the external-host records and the Rex native-settlement contract. Keep Desktop shell ownership and the one Task cleanup executor.

The existing transport already observes live viewers. The implementation still needs to connect that evidence to Task checkout retention, including multiple viewers, stale exits and remote uncertainty. Agent process exit is not viewer exit.

Usage copy for the revised design

Keep a Task Session viewer open to retain its worktree. Hidden or unfocused viewers count. Closing the last viewer lets a completed Task follow its normal cleanup grace once requested work finishes. An ordinary shell in that directory does not retain the worktree. Loopflow cleans up its Desktop shells; Rex shells remain yours to manage in Rex.

History survives. Eligible uncommitted checkout files can be discarded under the accepted policy; existing committed-ref safeguards remain. No automatic checkout recreation.

Review questions, resolved

  1. What retains the worktree? An open LF viewer of an associated Task Session, including a passive viewer. A shell's cwd or editable title does not.
  2. Must a leftover Rex tab keep the hold? No. The latest clarification selects the LF viewer process lifetime.
  3. Does LF need a Rex occurrence registry? No. External-host persistence and automated Rex shell closure remain excluded.
