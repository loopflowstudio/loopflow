The consequential mismatch

Forwarded work replaces the executor's personal config values, but still admits its personal skill settings. An executor skill can therefore change the selected agent even when the origin supplied a choice.

Actions → concepts → APIs

Start work from the laptop
One initiating personal profile → remote::outgoing → portable LF declarations from config and applicable personal definition metadata. Preserve source, scope, target, locator and choice/fallback strength.
Prepare the remote step
Selected profile plus executor-local facts plus repository conventions → shared candidate collection and settings::resolve_layers → inspection and launch preparation agree. Executor portable metadata cannot enter through a second path.
Retain preferences for later
Authored preferences → common writer and existing retention comparison → saved file or preserved conflict. Delivery receipts describe the outcome; they do not become another preference source.
Recover from a retention conflict
Forwarded work uses the origin profile; the executor keeps independent edits. Later direct work reads its saved files. Explicit adoption preserves fallback strength and target identity.

Keep the boundaries already accepted

The earlier Desktop repair stands: one destination derives file, source, scope and prefix for save, unset and explanation. Independent clones retain separate private preferences; linked Task worktrees share their main checkout's file.

Definition instructions and topology remain distinct from preference authority. Preserve repository definition selection, native provider-owned fields, host-local settings and captured instructions. This repair does not introduce whole-bundle synchronization or change which skill body runs.

Every applicable agent still beats every default_agent; within each class, source → scope → target decides. Carrying a profile must never promote it to CLI authority.

Normal path, failure, recovery

Normal: the origin selects Codex; an executor personal skill cannot silently select Claude. Origin-authored skill preferences must travel too.

Failure: the executor independently edits or deletes a retained preference. Forwarded work continues with the incoming profile while retention reports the conflict. Missing referenced assets still report their existing error.

Recovery: keep the executor's edits or explicitly adopt the incoming declarations. Direct work uses the saved result. Unset reveals lower settings without rewriting history or promoting fallbacks.

Counterexamples to preserve: direct executor work still uses its personal skill choice; a repository choice still beats an origin fallback; non-agent portable settings and personal Graph occurrences obey the same ownership. Blanket removal of definition metadata would fail these requirements.
