Do the Settings concepts line up?

The sidebar makes the first choice straightforward. Personal defaults live in six panes. Project & Wave Config asks which work to inspect and where to save. Two controls lose that distinction between inspecting a value and changing it.

Open the file behind a Wave preference

Choose the scan Wave and Shared Wave preferences. Its goal already declares agent: codex in frontmatter. Reading through to that declaration should take one click, even before the first Settings edit.

Where the distinction disappears. Rust’s settings_source already reads a path and text together. config.scope returns the declared slots with only the destination path. Swift’s prepareForOpening() uses that path. Carry the read path from the same Rust reading alongside the save path. Keep checked edits, Reset, Undo and moves addressed by destination and key.

What the run showed. The branch CLI reported a present codex slot, selected candidate GOAL.md, and a missing shared Wave config.yaml. After setting yolo: true, the slot still held codex, the YAML file existed, and the selected candidate moved to it. The Open outcome above follows the Swift file-opening code. This pass exercised the CLI and inspected the view source.

  • No-op. Saving the same agent leaves the Wave in frontmatter. Open must still lead there. QA round 6 saw exactly one file after this save.
  • Competing edit. Keep the writer’s source recheck. If another editor changes the source during the write, refresh before retrying. An external edit that creates the YAML file changes the next reading’s Open target.
  • Empty private destination. A value inherited from the shared file cannot make that file the source of a private slot. Keep the missing-file behavior for that destination. Only the file that supplied the selected destination’s document counts.
  • Restart. Both scopes retain their last reading and pause edits until a fresh frame. Round 6 saw an external edit reach the open project pane after restart and a subsequent Reset reach disk.

A picker value can conceal a Reset

ScopedSettingRow always tags unsetText as .absent, even when the selected file supplies the effective value. The CLI returned rebase from the private file before unset and squash from shared afterwards. Show the sourced label in the picker only when the slot is already absent. Keep a hand-authored null visible and resettable. A shared declaration shadowed by a private one still shows its own selection and the separate In effect reading.
