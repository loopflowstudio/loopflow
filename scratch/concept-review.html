Task pause, Working groups, and workflow controls

Area reviewed: the whole Task-pause lifecycle, Working-list grouping (Active / Shipping / Paused), automatic verify, and V4c Task workflow controls + smart unpause across Rust, CLI, server wire, Mac, and iPhone — at 06bf0c058d against stack base 3d57e2cdf1 (LOO-1063). built is committed at HEAD; mismatch is built at HEAD with a conceptual break; proposed is written into scratch/plan.md for the next pass.

Verdict — plan updated, iterate one pass before gate: The pause hold, worker OS-session stop, open primary conversation, Working groups, automatic verify, and conflict refusals hold up end to end. The newly built V4c workflow bar and smart-unpause layer has four concrete mismatches where Rust and Swift split ownership of the same decision: (1) smart unpause is decided in Swift (forcing an extra taskPane RPC on unselected sidebar rows, leaving a stale-client race that can skip ship-review, and sending run: true at auto: off landing stops); (2) Swift overwrites Rust’s Run: verify to Done whenever a PR is merged, hiding failed/interrupted post-merge verify; (3) in-flight pauses say Paused: land while lf land is still draining, and every Pause/Unpause click flashes ▶ | Reading…; (4) composed-Graph sentences drop the concrete inner step (Paused at build vs Paused: implement). All four shrink the client and return single ownership to Rust.

2. Biggest mismatch: split ownership of smart unpause & workflow pill

Rust already owns the Task’s saved Graph position in SQLite, yet 06bf0c058d splits the decision across two machines and two languages: task.unpause takes a blind run: bool, so Swift has to decide whether clicking Unpause should run — even on sidebar rows whose Graph hasn’t been loaded yet. Meanwhile Swift overrides Rust’s WorkflowControl in two places (blanking it to Reading… on pending pause/unpause, and rewriting Run: verify to Done after merge).

4. Choices made for review & scope notes

  • Choice made for review — position-aware task.unpause { run: true }: Chose making existing run: true (lf task unpause --run and app Unpause) resume only when the saved Graph position is runnable automatic work, keeping the wire shape unchanged and deleting WorkModel.unpause’s pre-fetch. Passed over: adding a third wire mode (lift | resume | run) so --run could still force-advance past ship-review. Explicit lf task unpause && lf task run already does that without creating a stale-client review-skip hazard.
  • Choice made for review — WorkflowAction::Wait for auto: off landing stops: Chose a dedicated waiting action (disabled primary button, enabled Start from… and Auto toggle) over overloading run_control.unavailable (which would also disable Start from…) or leaving ▶ | Run: land as a dead bounce.
  • Outside LOO-1078 (named PR limits, unchanged): Separate-session Codex 0.171.0 tool jobs (osPid: null in app-server); a pause first issued in the narrow window after a move payload is sent and before the destination checkout exists.
