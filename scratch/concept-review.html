The mismatch that remains

Two defaults recorded on November 4 now take effect at load, for every working Task, instead of at selection for one. A quit or reboot during the load window can leave several Tasks on Try again rather than one. And every load ends with up to eight reading passes nobody asked for, each counting as Available in the sidebar filter and on the Wave board. The questions do not change; their reach does. Questions 4 and 5 ask whether the defaults still read right at that scale.

Counterexamples that held

  • A store without a runtime prepares and shows but launches nothing, so a headless registry or test never spawns lf.
  • Prefetch skips a Closed Task and a completed one; Close still outlives refresh.
  • An unassigned started Task keeps Claim and Start; nothing moves it.
  • Loading started no Graph: the Stopped run's Graph IDs matched before and after, and its conversation reported the recorded comment without acting on it.
  • Start always returns a launch command, so the queue cannot spin on .pending.

Settled here

The Task description's acceptance line “no new agent turn starts merely from opening, prefetching or resuming a view” is superseded for history-less working Tasks by Jack's November 4 and 5 direction. The current acceptance is one reading pass per Task lifetime and none for existing history; publication states that. One compress note, no design change: the .initializing return in GhosttySurfacePool.start is unreachable because the runtime initializes synchronously.

For the demo

  1. A claimed working Task opens by itself. An unassigned one keeps Claim and Start. (a) keep, (b) open those too.
  2. A fresh lf resume --task with no request reads first. (a) keep, (b) operate on that explicit path.
  3. A comment written just before load waits for your first message in that conversation. (a) keep, (b) act on fresh steers, which needs a rule separating them from history.
  4. A provider that dies before any history costs one Try again click, now for each Task caught by the quit. (a) keep, (b) retry once per Desktop run, automatically.
  5. Every load's reading passes count as Available. (a) keep, (b) leave a conversation out of Available until a person has engaged it.
