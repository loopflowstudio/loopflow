A stack parent is a Task, not a PR attempt

Area: Task stacking end to end — how a child names its parent, and the four readers of that record (sync, owned-sync recording, landing, publication). Taken because the refusal sits in the one resolver all four share, not in sync.

The interaction

What happened on LOO-995

$ lf checkout LOO-995 --stack-on LOO-938
  # records parent = LOO-938's PR row #1971
  ... #1971 closed unmerged; LOO-938 opens #1983
$ lf sync
error: stack parent … closed without merging;
       re-place the child deliberately
$ lf sync main      # same error
$ lf sync LOO-938   # stacks, then the same read dies (installed build)

The Graph sync step fails three times and the Task stops.

Proposed

$ lf sync
Synced onto origin/<LOO-938 branch>.
  # task_stack followed LOO-938 to #1983;
  # the sync recorded #1983 as the parent
$ lf task status LOO-995 --json | jq .stack_parent.pr_number
1983

No successor: one sentence, lf sync LOO-938 or lf sync main; the latter works because the read no longer errors.

Biggest mismatch: the parent's identity

Earlier plan (existing in scratch/plan.md before this review)

task_stack returns Closed; a new restack_closed_parent in run_sync_in calls stack_existing_task, then reads task_stack again. Passed over following in task_stack because "re-placing there turns a read into a write".

Leaves two re-placement paths, and landing and publication still refuse a parent that is open on GitHub.

Proposed: follow on read, record on sync

Following needs no write. task_stack resolves the parent Task's current row with the same rule select_stack_parent uses (one function, current_parent_pr). The sync's existing write, record_stack_sync, records the row it merged along with the base it reached.

All four readers see the live parent. A successor that already merged becomes the ordinary merged-parent path. Closed means nothing left to follow, and one sentence covers it.

proposed
pub enum StackParentPr { Open, Merged, Closed { number: Option<u64> } }
StackedSync { fork_base, child, parent_identifier, parent_branch,
              parent_pr: TaskPrId,   // resolved row, may differ from the recorded one
              parent: StackParentPr } // replaces parent_merged

Outcome

The plan changed: restack_closed_parent and the second task_stack read are gone; current_parent_pr is shared by stacking and every read; record_stack_sync records the followed row. Slice 1 is the same fixture.
