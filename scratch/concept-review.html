Loopflow Desktop terminal keyboard input & shortcut ownership

Area reviewed: All keyboard routing, shortcut ownership, and key translation for Desktop terminal panes (Sessions and Shells), from Desktop's local monitors and NSApp.mainMenu through GhosttyMetalView and GhosttyManager to the held-terminal relay (repaint.rs, transport/input.rs). Why this area: Modifier-key behavior in Sessions lives at the seam between AppKit menus/equivalents, Ghostty's embedded keybind set, AppKit text composition, and held-Session mode replay. Reviewing the whole built diff exposes three places where the implementation still falls short of the product model.

2. The biggest remaining mismatch — before and after

Biggest mismatch: Loopflow Desktop tries to subtract Ghostty's standalone app one keybind at a time, and stops halfway through Ghostty's AppKit responder contract

Ghostty's default keybind table is written for a standalone terminal emulator with its own windows, tabs, splits, inspector, command palette, and file-export chrome. Listing 49 keys to unbind in GhosttyManager.standaloneShortcuts already missed 4 unimplemented macOS defaults (⇧⌘J, ⌃⇧⌘J, ⌥⇧⌘J, ⇧⌘V) and must be re-audited on every Ghostty bump. Meanwhile, Ghostty's config parser natively supports keybind = clear.

On the responder side, GhosttyMetalView adopted performKeyEquivalent binding checks and keyText accumulation, but left out ⌃/ handling, the lastPerformKeyEvent / doCommand(by:) round-trip for ⌘., 4-modifier key_translation_mods, and enabled/visible filtering in shadowedByShiftedMenuItem.

3. Counterexamples tested against the recommendation

⇧⌘J, ⇧⌘V, and user Ghostty bindings

  • Built code: write_screen_file and paste_from_selection were missed by standaloneShortcuts; key_is_binding swallows them into action_cb no-ops.
  • After keybind = clear: They are unbound by construction. User bindings in ~/.config/ghostty/config (e.g. unconsumed:super+d=text:split) still load afterward and work.
  • Surface defaults kept: ⌘←/⌘→/⌘⌫ line editing, ⌘↑/↓ prompt jump, ⌘A, ⇧←→↑↓ selection, scrollback, font size, and search nav remain active.

⌃/ and ⌘. in a focused terminal

  • ⌃/: Intercepted in performKeyEquivalent when only Control is held, sent to keyDown without beeping (emits 0x1f in legacy mode, CSI 47;5u in Kitty mode).
  • ⌘.: First pass returns false so any menu item wins; if AppKit redirects to doCommand(by: cancelOperation:), lastPerformKeyEvent matches NSApp.currentEvent.timestamp and re-dispatches to keyDown. Synthetic timestamp == 0 events are ignored.

AppKit Shift-menu misfiring (⌘↩, ⌘E, ⌘T)

  • Verified with live AppKit probe: NSMenuItem with "\r" + [.command, .shift] fires on both ⌘↩ and ⇧⌘↩ even with localization off; lowercase "e" + [.command, .shift] fires on ⌘E.
  • Enabled/visible guard: Ignoring hidden and disabled items in shadowedByShiftedMenuItem ensures a disabled exact item (⌘T in Repo/Wave Sessions, ⌘R in any terminal) does not mask an enabled Shift sibling (⇧⌘T), and disabled Shift items never claim chords.

key-remap & Korean/Japanese IME

  • translationEvent: When ghostty_surface_key_translation_mods equals the incoming flags (ordinary typing, Korean IME, Option-as-text), the original NSEvent object is reused unchanged.
  • When mods differ (macos-option-as-alt or user key-remap), all four modifier flags are updated from Ghostty's answer.

4. Choices made for review & what stays outside this work

Choices written into scratch/plan.md (all reversible)

1. Use keybind = clear + positive surface-owned defaults in GhosttyManager.loopflowConfig instead of a negative unbind blacklist. Passed over patching the 4 missed entries into standaloneShortcuts because a negative list drifts on every Ghostty upgrade and hides which terminal bindings Loopflow Desktop actually intends to ship.

2. Complete Ghostty's AppKit responder contract (⌃/, lastPerformKeyEvent / doCommand(by:) for ⌘., 4-modifier translationEvent) and guard shadowedByShiftedMenuItem on visible, enabled menu items. Passed over leaving ⌃/ and ⌘. for later because both are standard terminal modifier chords inside the exact responder being rewritten.

3. Keep previous reversible choices unchanged: no direct printable-key bypass; keep Ghostty's effective macos-option-as-alt setting with ghostty_app_keyboard_changed; keep NSTextInputClient.hasMarkedText() on both existing monitors.

Outside this work (separate outcomes)

  • Fixing AppKit's Shift-menu misfiring outside focused terminals (Sidebar, Brief, Files): SwiftUI's CommandMenu / ConsoleCommands menu items (⇧⌘↩, ⇧⌘E, ⇧⌘O) also fire on unshifted chords when focus is outside a terminal. Fixing app-wide menu shortcut dispatch (uppercase letter equivalents and/or custom NSMenu matching) is a broader Desktop menu outcome outside terminal input.
  • Consolidating DesktopActionMonitor, WorkPaletteShortcut, and hidden view .keyboardShortcut buttons (⌘/): Separate Desktop shortcut-architecture cleanup.
  • Modifier support in lf desktop send-key, iOS hardware keyboard, and Rex: Separate surfaces.
