The mismatch checked

Could probe and checkouts be one concept? No. A probe is polled on the clock and must cost much less than the reading it skips. Checkouts are woken by FSEvents and then ask Git. Merging them would either poll Git every tick or put file events behind the clock.

The dead set isn't a second record of death. It's a cache of a permanent derived fact, kept for one watch's lifetime, with no store write. That matches the October 29 decision that the read-only library loses nothing.

Normal, failure, recovery

  • Normal: idle readers are now 0.1–1.9% of one core (done-when: under 2%).
  • Failure: if the probe errors, it returns no answer. The clock then reads as before, so a probe can't hide a change.
  • Recovery: if a provider dies, the Agent evidence in the probe changes, and the list rereads (session_list_watch).
