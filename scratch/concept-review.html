LOO-1066 · Post-build concept review · macOS Settings & Configuration Scope

Do the product’s concepts and the code’s concepts line up?

Not yet — four UI/row concepts still carry the old raw-file editor inside Policy B. Reviewed across the full macOS Settings & Configuration Scope area against base 2656258a through adaf72ba. The Rust infrastructure (config.scope, checked YAML writes, synchronous observe invalidation, 2-file move + recovery) and the Policy B shell (6 personal panes + 1 Project & Wave Config pane, monochrome sidebar, dividers, capsule search) line up cleanly. Inside the rows themselves, however, four mismatches break the experience on live screens (qa.html).

Failure, recovery & counterexamples checked

Hand-written chrome: null

Survives. Because Authored.present(.null) stays in the wire and Swift models, an existing chrome: null in .lf/config.yaml still renders selected as Explicit null with a working Reset button. Once replaced or reset, Explicit null disappears from the Picker menu.

Concurrent hand edit before instant Reset

Safe. Instant Reset still calls checked config.edit with expected: slot.entries. If someone edited the file on disk since the last frame, Rust refuses with Conflict, leaves the file untouched, and shows the inline row error + Refresh.

Search while targeting a Skill or Wave

Recovers cleanly. Selecting a non-Launch result (e.g. Landing method or Default Graph) clears project.target = .general (and clears wave for repository keys) so the revealed control is always present and editable.

Choices written into the plan for review

All choices below are reversible, written into scratch/plan.md and scratch/questions.md for the next implement pass. Reply with e.g. 1b or 2b to steer.

  1. Reset behavior on simple controls (toggles, pickers, text/integer fields, ordered lists)
    • 1a · Chosen Reset immediately with checked write + ⌘Z Undo notice (matching Picker (Default) and clearing a text field). Keep previewed Reset… + live YAML diff only for raw .yaml disclosures.
    • 1b. Keep 2-step YAML diff confirmation on Reset… in Project & Wave Config, and make Reset immediate only on personal panes.
  2. Explicit null in nullable Pickers (auto, chrome, codex.service_tier, merge_method)
    • 2a · Chosen Show Explicit null only when the file already declares null (declared == .present(.null)), never as a selectable choice to author a no-op null.
    • 2b. Keep Explicit null permanently selectable in every nullable Picker.
  3. When Project & Wave Config shows the expandable In effect precedence row
    • 3a · Chosen Show In effect only when this file declares the setting or any non-builtin layer participates (declared != .absent || candidates.contains { $0.source != "builtin" }), and display the selected file path once beside Open file….
    • 3b. Keep In effect visible under every row in Project & Wave Config, including pure defaults.
  4. Non-Launch settings while inspecting a Skill or Graph step
    • 4a · Chosen Hide non-Launch sections/rows while targeting a Skill or Graph step and show one note + Inspect general work button (mirroring how Wave scope handles Git & Release).
    • 4b. Keep all repository and general sections visible as read-only disclosures when targeting a Skill or Graph step.
