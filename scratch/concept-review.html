The biggest mismatch: the line's one command doesn't work

Before (built)

crash → transcript gone
pass: resume → "cannot resume claude
  conversation X: its transcript is missing"
  … ×5, backoff 1→16 min
status: died · started 5 times;
  `lf resume --task X` opens it
lf resume --task X → same error

Eleven Tasks, each needing a person who then hits an error.

After (proposed, slice 6)

crash → transcript gone
pass: thread_lost? → new_thread(same Session,
  seeded with lf's log) → continuing()
  request recover:<s>:<agent>:fresh
status: running (fresh thread; the old
  one's transcript was gone)
lf resume --task X → same rule, opens fresh

One rule in the start path both starters share. adopt_native's ensure! becomes the branch, not the error.

Counterexample checked: a transcript that is only in an account's home, not the native one, is found by conversation_home and copied, as today; only "no home holds it" starts fresh. A fresh thread that dies again is an ordinary death on the same count.

Chosen for review: 1b. Passed over: 1a keeps 3a and changes the give-up line to lf session new. Honest, but every Task the crash hit still waits for a person.

Questions

  2. The fresh start's status line: (a) text only, while no turn has finished (chosen) · (b) a start.fresh_thread wire field Desktop shows.
