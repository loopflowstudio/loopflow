The plan opens with "work the way they do for Claude, Codex, OpenCode and Pi: chat, work session, batch and worker". Three of the four do. The work session opens, hears lf and resumes, and then cannot call lf back without a person approving it, and the only record of that is a scratch note.

proposed After

docs/config.md, Antigravity, one paragraph: in the terminal agy runs commands in its own sandbox, so the first lf command asks "Run this command?"; allow it for the conversation, or launch with yolo. Headless steps are not sandboxed.

docs/troubleshooting.md: one row, the prompt and the two answers.

harness/README.md: the Antigravity launch row says the same in a clause.

Chosen for review: say it, and leave the launch as it is. Passed over: turning yolo on for every Task conversation on Antigravity (the docs promise "Interactive sessions use each vendor's own permission settings and prompts", and this would break that for one harness), and granting lf through agy's permissions settings (the keys are in the binary and were not explored; --add-dir ~/.lf is ruled out because a folder that sorts before the checkout becomes where commands run).

Counterexample tried: a checkout under /tmp. The sandbox reaches /tmp, so nothing fails there, which is why the stand-in tests and the first live runs never saw it. A person's repository is under their home directory, so the docs state it as what happens, with no /tmp exception.

proposed After

No new type and no moved code. The comment in emit_block says what is true: a launch whose provider names the conversation keeps it in the file beside its delivery; Codex's launch creates the file to ask, and Antigravity's first callback claims it. hook_callback's doc on the trait says an implementation may claim the file.

Passed over: making hook_callback pure and having emit_block own every write. It needs a "this harness always claims" answer on the trait, which is one more method to save one fs::write.

Looked at and left

The store's provider start now publishes a resume reference for any harness whose input has none (it used to leave that to the launch). Claude and OpenCode name their thread before launch and Codex work sessions open theirs first, so only a provider-named terminal reaches the new branch; a_start_names_what_reconnect_resumes_when_the_launch_named_nothing covers it. The reference is published with no account id.

classify_failure lives on Launcher (execution), not Harness (loopflow-harness), because AgentFailure is execution's. A provider's refusal words are something it writes, so the split crate is their truer home. Moving the type is a change with no behavior in it.

--harness absent means Claude's shape, which Codex, Pi and OpenCode also send. Naming it on every hook would change the declarations Codex asks a person to trust.
