Should cleanup end a done Task's conversation itself, instead of leaving it a note?

The last pass moved the "is this Task closed?" judgment out of each owner, as the simplification asked. It did that by storing a close request on the owner and keeping it true with seven database triggers. A stored judgment has to be un-made whenever anything it depended on changes. That is where most of the new code went.

What is built

  1. Every minute, cleanup finds done or abandoned Tasks with running conversations and decides which may end.
  2. It writes close_requested='completed' (or 'abandoned') on each owner's process row, but only if no write anywhere in the store happened since it started reading.
  3. Seven triggers clear that request if the Task reopens, a Graph starts, a turn begins, the Session moves, and so on.
  4. Each owner polls every two seconds and ends when it finds a request.

Three things this costs

What happens
A done Task may not close for a long timeStep 2's guard compares one sum over all of store_revisions. At rest it moved 8 times in one second (11346900 → 11346908). Any write in between, including another owner recording its viewer, cancels the pass, and the next try is a minute later.
The conversations holding your disk today stayOwners started by the installed lf never read the new column. The done Tasks still holding builds (LOO-723, 775, 800, 810, 812, 813, MTG-180, 241, 244, 245, 249, 252, 268) keep running after this ships, until someone runs rollover.
A stored judgment to maintainFive request states, a Task column on every process row, seven triggers, an upgrade fixture, and a staged removal of the old shell column.

Proposed

Proposed, not built. Cleanup ends the conversation in the same pass that decides it. It verifies the owner's PID and start time and signals it, as lf process rollover already does for owners of any build. The owner saves its screen and exits with "Task completed".

Counterexample kept: you open the conversation in the instant between cleanup's last read and its signal. It ends in front of you with "Task completed", and resuming continues from history. Under the built design the same instant is covered by a trigger.

Questions

1. How does cleanup end a done Task's conversation?

1a
As built: a stored close request on the owner, kept valid by triggers, consumed on the owner's next poll.
1b
Cleanup signals the verified owner in the pass that decides it; nothing stored. Shell Close stays on desktop_shells.

2. The done-Task conversations already running on the installed build

2a
End them at the first cleanup pass after this ships. That follows from 1b; under 1a it needs its own path.
2b
Leave them until someone runs lf process rollover.
2c
End them now, by hand and by PID, before this ships.
