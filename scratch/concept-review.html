Biggest mismatch: heldStatusGroup has split ownership across WorkNavigation and WorkModel

Mismatch · Built at 5317225dbe Both mismatches from the 14f44821e8 review (integer slot pinning and repository-only Wave sorting) are fixed, and 8 of 9 product-to-code pairings now line up cleanly. One pairing — holding the open Task’s status group while Sort by status is On — still has no single owner in code:

  1. Changing sidebarFilter clears heldStatusGroup without capturing the open Task’s group before its next turn.
    WorkNavigation.sidebarFilter.didSet sets heldStatusGroup = nil, and nothing calls holdSelectedStatusGroup() until the next applyTaskList arrives. Because applyTaskList calls holdSelectedStatusGroup() after overwriting taskListReadings[key], switching filters (e.g. Working tasks → Available → Working tasks, or clicking Show working Tasks) leaves heldStatusGroup == nil; pressing Enter in the open Task then latches .busy and drops the open Task straight to the bottom.
  2. Direct selection writes leave an unselected Task pinned in its old status group.
    commitSessionBinding (WorkModel.swift:3087) and createTaskFromSession (WorkModel.swift:3110) assign owner.selection = .task(...) directly, bypassing setSelection. WorkNavigation.destination.didSet (WorkProjection.swift:356–362) only clears heldStatusGroup when selection?.kind != .task || !sidebarScope.isWorkingList, and sidebarRows (WorkModel.swift:2226–2231) applies held without checking whether held.taskID is still selected — so the previous Busy Task remains pinned in Available after selection moved to another Task.

Doc consistency note: two sentences in swift/README.md:153 (“its board badge shows Available”) and swift/README.md:302 (“Done for a reported result”) still carry the pre-LOO-1063 labels instead of Busy-over-Available and Finished/Available.

Recommendation: one invariant for the held status group

Proposed for next implement pass

  • Clear on any selection change in WorkNavigation.destination.didSet.
    Move the selection: WorkReference? switch onto WorkNavigation.Destination and clear heldStatusGroup = nil whenever selection?.kind != .task || !sidebarScope.isWorkingList || selection != oldValue.selection. Re-entering the same Task (.work(.task(id)) ↔ .entered(from:, work: .task(id))) keeps selection == oldValue.selection and keeps the hold; switching Tasks through any path clears the old Task immediately.
  • Capture the open Task’s pre-turn group before replacing taskListReadings.
    In WorkModel.applyTaskList, call if previous?.wave == wave { holdSelectedStatusGroup() } before overwriting taskListReadings[key], then keep the post-update holdSelectedStatusGroup() for cold-start first readings. After any filter switch, the open Task’s current live group is captured right before a turn changes it, so pressing Enter never drops it to the bottom.
  • Guard sidebarRows on the active selection.
    Only apply held in WorkModel.sidebarRows when held.taskID matches the currently selected Task ID, so an unselected row can never appear held.
  • Align the two stale sentences in swift/README.md (lines 153 and 302) with docs/surfaces.md and the built behavior.
