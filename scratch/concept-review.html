The biggest mismatch: an empty repository

The Task's own demo says: open an empty repository and read “No planned Work in this repository” with New Task ⌘N and Open the repository conversation. The view exists and has a test. Opening an empty repository shows something else, because a repository opens on its page (conversation, backlog, tiles) and NoPlannedWork is mounted only where no Wave view is shown. Its second button calls jump(to: .repository), which selects the page the person would already be on; it opens nothing.

Outside this work

A Start that failed after the request reached the Machine. QA broke Start two ways and both times the sheet closed, the words left the screen, and a notice at the bottom read “Creation 3E68…: … It may have happened; refresh before retrying.”, cut off at the window's edge. The prototype's “Not started.” with Try again was never seen. That is CreationRecovery, which exists so a lost answer cannot file a Task twice, and it treats a plain refusal from Rust the same as a lost answer. Making it tell the two apart (a refusal keeps the words and Try again; only a lost answer goes to recovery), and drawing recovery's notice as a failure with its message readable, would take a change to SubmittedCreationError's cases and the notice. It is a separate outcome with its own risk; nothing in this change made it worse. The “Task created · Show result” notice that stayed up across repositories is the same subsystem.

Smaller, seen at QA and left: the chevron between a menu's name and its comma in the sheet; “No Graph has run.” under “Waiting for you at explore.”, which is true of Graph processes and reads oddly beside the bar.
