The model as built: one concrete journey (normal, failure, move, recovery)

A Task LOO-7 is owned by mini (whose local repo is /workspace/app and whose tracker-backed local UUID may differ from laptop's task_laptop). A stale checkout from an earlier run still sits on laptop.

built at HEAD Failure, move, and recovery

1. Unstarted Task (no checkout on mini yet): • task.files / changes / diff / file → not_found { reason: "not_started" } • task.files.watch stays open with { checkout: null, revision: null }, waits for .git, and wakes on store_revisions when checkout appears. • CLI / Desktop / Mobile show Not started (never empty diff or local shell). 2. mini unreachable / SSH drops: • One-shot & subscriptions emit unavailable naming "mini" + ssh check. • Subscriptions retry every 5 s or immediately on planning revision change. • Zero local checkout / local shell fallback. 3. Task moves (laptop ↔ mini): • task.get / task.status / task.files.watch re-route under the same sub ID. • Desktop follows owner: retires old Session viewer, re-opens moved Session, relocates TaskFilesStore. Running ShellTabs stay labelled on starting Machine; Close passes --started-on. • Unsaved draft keyed by (Task, path, base revision): saves on new owner if base revision matches; otherwise held whole as external conflict (arrive). 4. Reset session loses reply mid-flight: • Desktop CreationSubmissions saved payload's task → creation.get { task } routes to mini, recovers Complete/Inspect receipt (localized open_argv), and RecoveredCreationInspector reads routed task.get to retire the file.

Before vs after (base 62a368e5cc → HEAD f042ba20bb)

Before (at base 62a368e5cc)

  • Desktop ran its own client-side SSH subprocess stack (RegistryQuery.onMachine, pinTaskLocation, LocalLineObservation) and rejected remote Sessions with MTG-421's placement guard or opened local Mac shells.
  • Stale local task_checkouts leaked into RoadmapTask and TaskSnapshot after a Task moved elsewhere.
  • No server peer pool, no routed terminal tickets, no task.shell.*, no server-routed task.files.watch.
  • Mobile had no remote Files tree or Shell viewer.
  • lf open --task attached to stale local checkouts, dropped --task when --session was passed, and had no --machine selector for remote-only Sessions.

built at HEAD After (Slices 1–8)

  • One router (lf server, rev 10) with pooled peer SSH pipes, portable Task selectors, and one peer-reading localization boundary.
  • Desktop's client-side SSH routing and location guard are deleted; Files, Changes, Diff, Save, Shell, Session, Reset, and New conversation all route by Task and follow moves.
  • Mobile exposes Session, Files (including unchanged files), Changes, and Shell over the existing single Tailscale pairing.
  • lf open always presents locally, supports --task, --task --session, --machine --session (both flag orders), and -a <harness>, and prints calling-Machine lf open return commands.
  • Unstarted Tasks show Not started; unreachable owners name the Machine with retry; zero local fallback.

Minor non-conceptual leftovers noted (not a redesign)

None of these break the model or require another architecture pass; listed plainly so nothing is hidden at gate or PR review:
  • Bare CLI lf task status <id> --json / --subscribe (waves.rs::print_remote_task_status) opens a one-shot peer connection directly without calling Read::localize_peer_reading (human output is unaffected; served task.status is localized).
  • lf server receipt <id> --task nope returns null instead of reporting an unknown Task because CreationGet::read_here ignores task when remote_task finds no local Task.
  • graph_processes[].entry.repo in routed Task readings carries the peer's repo path; no surface reads it.
  • docs/surfaces.md move-table row still says "Shells and Sessions already open stay on mini" while Desktop now auto-follows moved Sessions to the new owner (Slice 6B).
  • Cold-restart draft reconciliation after a move (SessionsView.swift::loadPaneIntent) calls reconcile rather than arrive if the Task moved while Desktop was closed; live moves call arrive and preserve conflicting drafts whole.
  • Separate scope (by design): sidebar listing reads local SQLite only (no list/board SSH fanout); remote lf session list --task carries only --task, --headless, and paging; desktop_shells table/CLI naming stays as-is while wire says task.shell.*.

Open product choices (built for review)

Every choice below is built at HEAD and reversible before release; answer with e.g. 2b if you want any of them changed.

  1. Recovering a remote Reset session (session.new) whose reply was lost:
    1. route creation.get by the saved payload's task selector (rev 10, zero SQLite migration; handles lost reply, mid-reset crash, and peer outage) built at HEAD
    2. add a local SQLite table mapping request_id → machine_id so recovery still targets the original peer even if the Task moved during the 5 s outage
  2. When a Task moves to another Machine while open in Desktop, its Session pane:
    1. retires the old Machine's viewer and automatically re-opens the moved Session on the new owner when the Task is visible built at HEAD
    2. retires the old Machine's viewer and shows an explicit "Open conversation" placeholder until clicked
  3. Clicking New conversation on a Task owned by another Machine:
    1. starts lf --interactive --task … in a routed shell tab on the owning Machine (zero local checkout) built at HEAD
    2. disables the action for remote Tasks until a dedicated remote secondary-Session operation exists
  4. When a Task moves, a Shell already running on the old Machine:
    1. keeps running, labelled with its Machine, until closed (reattach on new owner → ended → New shell) built at HEAD
    2. is closed by the move
  5. An unsaved draft after a move:
    1. saves to the new owner when the base revision matches, else held whole as an external conflict built at HEAD
    2. always asks before saving to a different Machine
  6. desktop_shells table and lf desktop shell naming (while wire says task.shell.*):
    1. leave as-is (avoids a staged migration with no user-visible change) built at HEAD
    2. file a separate Task to rename to task_shells
