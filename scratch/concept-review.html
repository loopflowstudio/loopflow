No new product decision is needed

The implemented change matches Jack Heart’s accepted contract: reclaim finished checkouts while preserving unpublished, unfinished, live, and uncertain work. No redesign is proposed. Gate and installed acceptance remain pending.

A remote branch being absent says where work is stored. It does not say that the work can be discarded.

Actions → concepts → APIs

lf wt prune --dry-run   # preview eligible finished checkouts
lf wt prune             # remove them and their local branch refs

Hourly cleanup calls the same operation. Deliberate disposal remains lf wt delete <name> --force.

Before, installed behavior: clean checkout + missing remote branch or old activity → prune candidate → forced Git removal.

After, implemented on this branch: clean, unprotected checkout + merged or closed PR at its exact head → WorktreePruneTarget → lease, branch/head/cleanliness recheck → non-force Git removal → conditional local-ref deletion.

prune_repo_worktrees supplies ownership and process protections; prune_worktrees owns the single classification; remove_worktree_target applies it. Listing’s remote_gone remains an observation. No new persisted state or wire model is needed.

Normal use, failure, recovery

  • A clean checkout with an exact-head merged PR can go. A closed PR is the accepted abandonment signal, not a claim of delivery.
  • A never-pushed branch, a new commit after delivery, or an open PR stays. Missing provider facts cannot manufacture permission; failed ownership or process inspection stops cleanup.
  • A candidate changed before removal stays. A branch advanced after removal keeps its new ref. Retrying reads fresh facts.
  • Later branch cleanup respects remaining checkouts. Idle ignored build output keeps its existing separate cleanup rules.

MTG-193’s preserved ref and verified bundle establish committed-history recovery only. Unknown uncommitted or ignored data remains unknown. Its active checkout and Task stay untouched; the operator coordinates restoration and installed verification before restoring the hourly entry.
