The interaction

Open Product → find its existing Task tabs or launch templates → rearrange them in Rex → return to the same tabs. Newly started Tasks appear passively without taking focus. Backlog stays explicitly selectable.

After a Rex restart, reuse what Rex restored. An explicit open can create a missing tab from LF’s template. Leave a surviving tab alone; its old ID does not prove its programs survived.

The consequential mismatch: an initial-template launcher has grown into a manager of native workspace lifetime. Jack Heart revised that boundary explicitly: observe retained Task Session terminals, leave Rex shells alone.

A small locator may still earn its place

The database contains IDs and observations, not Rex’s live split tree. Remembering Work → native ID can preserve reopening after a rename. The current fallback is a visible title marker; rename it away and stateless discovery can fail. Hidden native metadata has not been established.

A locator answers “where did this open?” It must not decide what is running, restore tools or authorize cleanup. Moving the existing state machine to a file would leave the same design intact.

Failure without repair machinery

If Rex is unavailable, report it. If creation returns an uncertain result, inspect native state before retrying and keep the minimum receipt necessary to avoid duplicates. Preserve partial work. Following adds missing Tasks; it never repairs programs or rearranges existing panes.

Correct Task worktrees, later native splits, remote placement and bare lf open from an LLM remain requirements. This proposal does not waive their outstanding evidence. Passive arrivals and explicit tool opening also remain; their implementation still needs safe one-time creation.
