Biggest mismatch: resume asks the Session, not the Task

The brief: "where does this Task run" has one answer, the ownership log. work_route::forward checks moved_session first, which reads agent_sessions.moved_to_machine_id, and send_task still writes it.

laptop$ lf task move LOO-9 --machine rental
  laptop: LOO-9 conversation moved_to = rental
rental ends → hand_back_in: ownership says laptop
laptop$ lf task status LOO-9      # Runs on laptop
laptop$ lf resume <its session>   # forwards to rental (gone)

Proposed: a Session that belongs to a Task resumes where the Task runs. send_task stops writing the marker; moved_session skips Task conversations, which route like resume --task and reopen here when the Task runs here. The migration clears the marker on Task conversations.
