The biggest mismatch: where the Task stands

This Task, right now: Graph code, running concept-review.

As planned
codeplanbuild👤 ship-reviewdeliver👤 verifyplan is running. You are next needed at ship-review.

Correct here by luck. When build's own concept-review runs after qa, the same name finds plan first and lights the wrong step. Swift would be choosing a place from a name.

Proposed
codeplanbuild👤 ship-reviewdeliver👤 verifybuild is running concept-review. You are next needed at ship-review.

read_task_graph already holds the cursor. It writes current_step (index into steps, null at start/end) and the sentence from the same place_of(cursor). Swift draws; it reads no step names to place the Task.

Normal path: running → strong working colour, earlier steps done. Failure: the carrier dies → running:false, the same index in waiting ink, "Stopped at build. lf task run starts it again." Recovery: the next run starts at at; the index is recomputed from the new cursor. Counterexample tried: a cursor whose place no longer exists in the captured Graph → place_of is None → current_step null and the sentence falls back to at by name, which is today's behaviour.
