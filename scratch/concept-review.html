What you want

“I want to be able to use multiple accounts in order to load balance across different Max accounts. I don't want to have to worry or think about which account I'm using.”

One afternoon, as built

Two Claude Max accounts. jack@ is active at 60% of its weekly window, which resets in 5 days. work@ is at 30%, and its weekly window resets in 3 hours.

  • 14:00 A Graph step launches. select_shared_account puts the active login first, and jack@ has room, so it stays on jack@.
  • 14:00–17:00 Every launch and every open Session uses jack@.
  • 17:00 work@ resets with 70% of its week never used. Soonest reset never came into play, because jack@ never filled up.
  • Thursday jack@ fills up. Now soonest reset picks work@. The Claude login switches, and every open Session follows at its next request without a restart. That part works.

Recovery works: a full account moves everyone over. Using the quota well doesn't: an account whose reset is near isn't used first unless the active one runs out before then.

The second way this goes wrong: scoped routes

lf set account.claude jack@,work@
lf --wave billing set account.claude work@

A billing step switches the Machine to work@. The next launch outside that Wave doesn't need to switch back, because the active login comes first while it has room. But if work@ is only explicit-only, or isn't on the other route, it switches back. Two routes that disagree can switch the Machine back and forth, and every open Session switches with it. Per-repository and per-Wave orders made sense when each launch could have its own home. With isolation deleted, the account is shared by the whole Machine, so a scope can't own it.

When to switch: three rules

RuleUnused quotaSwitches
aStay on the active login until it can't take a launch, then go to the soonest reset. builtLost when another account resets firstFewest
bAt every launch, go to the soonest-reset account that has room.LeastMost; every open Session follows each one
cStay on the active login, but switch early to an account that resets within a few hours with quota left. Switch back after it resets.LittleAbout two per reset

Unverified: Claude's prompt cache is probably kept per account. If it is, every switch makes open conversations re-send their context and spend more quota, which weighs against (b). Not checked; checking it would spend real quota.

Usage doc as proposed

lf account connect claude jack@ --chrome-profile jack@
lf account connect claude work@ --chrome-profile work@
lf account                     # active login, room and resets per account

One Claude login per Machine at a time. lf switches the Machine when an account fills up and at each launch, to the account with the most quota to lose before its reset. Open Sessions follow at their next message without a restart. lf account claude use work@ switches now. lf account set claude jack@ --routing explicit-only stops using an account. lf set account.claude jack@,work@ orders the accounts; repository and Wave orders still apply.
