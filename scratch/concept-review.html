Start keeps control explicit.

No further design change or open product choice. The implementation now preserves Jack Heart’s accepted distinction through launch: Start creates or continues; only Take back transfers another client’s input.

The accepted experience stays intact

Selected Task first, then recent working Tasks and other fresh idle, active and moving Tasks. Saved unfinished Tasks fill spare capacity. Eight warm conversations and two concurrent preparations remain provisional engineering limits; visible panes and protected work retain their existing exceptions.

Close survives refresh and cancels late preparation. Deliberate return may reopen. Completed departure releases through LOO-717. Local retention now reaches the local owner. Take back has no Fork button; independent CLI fork remains available.

Existing usage text: “If another client takes input while Start is opening, the pane offers Take back; Start leaves that client in control.” swift/README.md already records it. No usage-doc or skill change is proposed.

Review questions, settled against the accepted design

  1. Must Start ever transfer input? No. Jack Heart’s explicit Take back decision already settles the competing-client case; no new approval is inferred.
  2. Does recovery need another lifecycle? No. Shared Session actions, existing history, launch locking, transport claims and LOO-717 retention provide the required distinctions.
  3. Is the experience ready to accept? Native proof is still open. Gate, regenerate matching app/CLI demo artifacts, and publish for review before interactive re-demo. Demonstrate Claude/Codex draft and input continuity, Rex takeover, reboot recovery, and the twenty-Task private footprint. Eight is not a measured memory budget.
