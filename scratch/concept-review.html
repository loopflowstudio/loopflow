Keep the accepted model.

No further design change and no open product choice emerged from this headless review. Jack Heart's accepted contract separates viewing, typing, and whose size and colors the terminal follows.

The consequential mismatch is resolved.

Before the correction, colors lived in an owner-wide cache and reports from waiting viewers were discarded. Now each viewer retains its report; selecting that viewer applies its size and known colors together.

A connection can recover output without taking either input control or appearance ownership. The stream token is temporary; Session identity survives the owner process.

Actions → concepts → APIs

Open the conversation here. Existing CLI behavior

lf resume SESSION

Session → controlling viewer → attach {control:true, replace:true, own:"take"}.

The snapshot precedes live output. The former CLI controller receives a notice and leaves; losing appearance ownership alone does not detach it.

Watch the same output; queue this pane's appearance. Implemented wire capability

attach {control:false, own:"request", rows:30, cols:90, …}
theme {theme:{…}}

Viewer → remembered size and colors → queued ownership. The current owner's appearance stays effective. When it leaves, the queued viewer's reports reach all viewers through resize, theme, and owner events. Typing authority does not move.

Recover a dropped connection. Implemented wire capability

resume {reconnect:token, received:N, control:false, own:null, …}

Retained stream → exact byte offset → output continues without a new snapshot. Connection loss releases claims immediately; only the bounded stream and viewer reports remain for 60 seconds.

If the offset is unavailable: reconnect_required → fresh attach → snapshot. No input is replayed. Automatic CLI socket reconnection is not implemented by this change.

Continue after the owner's executable retires. Handoff implemented; dependency policy integration pending

control {held:false,
  successor:[entry,"session","resume",session_id], …}

Durable Session and provider history → restore the viewer's terminal → run the supplied command → preserve its exit or launch error. Replaying the old viewer command would target the ended owner.

Before and after

Before this Task: JSON byte arrays, a repaint on fresh connection, and no retained byte-offset stream to resume.

Implemented: binary snapshot/output frames; nonce-tagged events share stream order and byte accounting; replies name the last queued event sequence. One in-memory viewer record owns its spool, reports and connection state. Session persistence and provider identity remain separate.

Proposed: no additional product behavior. Desktop's shared viewing presentation remains LOO-672's decision. Unknown colors supply no override, the recorded reversible assumption; this does not invent a palette.

Keep the proof boundary visible

The saved checks use shell fixtures. They do not prove two viewers of a live Claude conversation or installed executable rollover. LOO-705's retirement policy and LOO-708/LOO-709 integration remain pending in the accepted order. Snapshot storage and format stay with LOO-709/LOO-710.

Existing usage and agent guidance need no rewrite:

Review questions — settled against the accepted contract

  1. Should recovering output recover authority?
    No. Another viewer may have taken over during the disconnect; claims must be requested again. The retained colors become effective only when their viewer owns appearance.
  2. Can a stream token replace Session recovery?
    No. The owner may have ended. Session identity and provider history must survive after the in-memory stream is gone.
  3. Is another design iteration required?
    No new direction or unresolved product choice. Dependency integration, affected-suite checks and live acceptance remain required evidence.
