2. Before and after — what changed from base to built

Pass 2 outcome: No remaining conceptual mismatch in scope

Every mismatch identified in Pass 1 is resolved in 909fd45bad: standaloneShortcuts is replaced by keybind = clear + a positive surface binding list; key translation is extracted into GhosttyKeyEvent.swift across all four modifiers; performKeyEquivalent + doCommand(by:) complete Ghostty's responder contract; and Registry::start supplies TERM=xterm-256color and COLORTERM=truecolor when missing or empty.

One Pass 1 recommendation was reversed by live QA evidence: filtering shadowedByShiftedMenuItem on !isHidden && isEnabled broke ⌘↩ because SwiftUI menu items read isEnabled == false before lazy validation and AppKit still consumes chords on disabled or hidden items. Removing that filter aligned the code with AppKit's real dispatch rule.

3. Concrete paths tested (normal, failure, recovery)

Normal typing & modified chords

  • Shifted printables in agy (modifyOtherKeys 2 + Kitty 5): q, ⇧/, ⇧A, x produce q?Ax before and q?Axq?Ax after pane reattachment.
  • Modified Return/Tab/Option: Legacy and Kitty bytes verified for ↩, ⇧↩, ⌃↩, ⌥↩, ⇧⇥, left/right ⌥B across all four macos-option-as-alt settings.
  • AppKit edge chords: ⌃/ emits 0x1f / CSI 47;5u; ⌘. round-trips once to CSI 46;9u; ⌘↩ emits CSI 13;9u instead of firing Zoom Pane.

Failure & disconnected states

  • Paused / reconnecting Session: performKeyEquivalent still serves Copy, Find, and window cycling before guard connectionAcceptsInput; app menus remain reachable; terminal bytes are blocked.
  • Exited child: keyDown allows connectionAcceptsInput || exited so a keypress can still dismiss Ghostty's exited surface.
  • Disabled / hidden Shift menu items: Live NSMenu probe proved AppKit consumes the unshifted chord in all 4 states (auto-disabled, manual-disabled, enabled, hidden); keeping them in shadowedByShiftedMenuItem prevents silent swallowing.

Recovery & persistence

  • Pane release / reopen & app relaunch: Held provider keeps its PTY and keyboard mode stack; repaint.rs restores Kitty/modifyOtherKeys on attach so modified keys keep working immediately.
  • Cancelled IME / dead-key composition: Empty setMarkedText("") clears preedit and emits zero bytes; Desktop shortcuts resume once hasMarkedText() returns false.
  • GUI / launchd startup: Stripped launcher TERM/COLORTERM are filled at Registry::start; Rex/CLI callers keep their own nonempty values.

4. Choices made for review & what stays outside this work

Reversible choices built into this branch (all ready for review)

1. Positive surface keybinds (keybind = clear + 30 explicit bindings in GhosttyManager.loopflowConfig) instead of a negative unbind blacklist that drifts on Ghostty upgrades.

2. Focused-terminal Shift-menu guard (shadowedByShiftedMenuItem counting all menu items) instead of re-architecting menu-bar Shift matching across non-terminal panes in this Task.

3. Ghostty's layout-dependent macos-option-as-alt default + personal ~/.config/ghostty/config (refreshed via ghostty_app_keyboard_changed) instead of forcing Desktop-wide Alt.

4. Default TERM=xterm-256color and COLORTERM=truecolor in Registry::start only when missing or empty, preserving every nonempty caller setting.

Outside this work (separate outcomes) Future

  • App-wide Shift-menu matching outside focused terminals (Sidebar, Brief, Files): SwiftUI menu items (⇧⌘↩, ⇧⌘E, ⇧⌘O) still match unshifted chords in AppKit when focus is outside a terminal. Fixing app-wide menu shortcut matching is a separate Desktop menu outcome.
  • Consolidating shortcut monitors & hidden view shortcuts: Merging DesktopActionMonitor, WorkPaletteShortcut, and hidden .keyboardShortcut buttons (⌘/, ⌘P, ⌃⌘B) is separate Desktop shortcut cleanup.
  • Physical-keyboard / unlocked-Mac QA: Physical keys, key-window menu dispatch, ⌘K palette focus, input-source switching, and live IME composition remain in scratch/plan.md for unlocked-Mac verification.
