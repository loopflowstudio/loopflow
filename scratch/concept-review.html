Task c9fbcb · concept review, headless, November 21 · reviewed against scratch/plan.md as kickoff left it and the LOO-515 Diff it builds on.

Area taken: the Diff's reading of one changed file, start to finish: which bytes it reads, how it colors them, how it opens skipped lines, and how it shows a file rendered. Highlighting and rendered diffs both hang off "read this file at this side of the comparison", which is also what skipped lines already do, so the review covers all three rather than the two the Task names. The grammar build (xcframework, queries, inks) is sound as planned and gets one line here.

One interaction, walked

Jack picks the implement step of a Task in the Diff. TaskFileDocument.swift is in it with three hunks, and scratch/plan.md changed.

  1. The Python docstring hunk colors from the hunk alone, then recolors when the whole file is read. Good.
  2. He clicks "49 unchanged lines" between hunks. Nothing opens. canOpenGaps is comparison.head == nil: skipped lines read the working tree, and a step has a head. The plan's new --at read of that very file, at that head, sits one store over and isn't used.
  3. plan.md opens rendered with a header control Rendered · Side by side · Source, while the toolbar above already says New code · Unified · Side by side. Two "Side by side" buttons, one per file and one for the stream, can say different things.
  4. A paragraph got one word changed. The plan matches blocks "by longest common subsequence over each block's plain text", then marks words on "a matched pair whose text differs". An exact-text LCS never matches two blocks that differ, so that paragraph shows as one struck block and one filled block, never as a word edit.
  5. Failure: the head read fails. Rows keep hunk colors, the rendered reader falls back to Source with Retry. Recovery: Retry reads the side again. Both hold as planned.
