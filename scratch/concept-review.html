The biggest mismatch: lf stays with a conversation the person left

exists Before

// antigravity.rs
fn claim_thread(file, id) -> Option<bool> {
  match read(file) {
    owner if owner == id => Some(false),
    owner if !owner.is_empty() => None,   // a subagent… or /new, /fork
    _ => { write(file, id); Some(true) }  // first of the launch
  }
}

Two questions answered by one file: whose callback is this, and which conversation is the launch's. The second answer can never change.

proposed After

// whose: the payload says
if payload["lastUserInput"] is empty { return None }  // a subagent

// which: the file names where the person is
let changed = read(file) != id;
if changed { write(file, id) }
moment = Stop | Start if changed | …as today

A switched conversation is a Start: it gets the context block, the server selects it for the Session and moves the resume reference, as it does for Claude's /clear. Nothing new in the store or in emit_block.

Normal path: one conversation; the file is written once; identical to today. A headless turn: each process's first callback finds the id it was resumed with or an empty file, as today.

Failure: a subagent calls. Empty lastUserInput, None, as today, and no longer dependent on it calling second.

Recovery: /new, work, quit, lf resume: the file names the second conversation, so that is what reopens. /resume <first id> inside agy moves it back.

Counterexample kept: a subagent whose lastUserInput is not empty would be read as a switch, end the worker's turn at its Stop and take its steers. Seen empty in the one subagent run recorded in the plan; not seen across modes. The plan says what to do if the build finds one: keep the first-id rule and state the limit in the docs.

Passed over: telling a switch by SessionStart (/fork does not run it; a subagent does), and documenting the limit without trying (the store already follows a switch for every harness that reports one).
