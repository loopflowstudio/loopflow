The mismatch removed

Before: owners interpreted Task state, an input ledger retained execution, and a count of sixteen skipped new background starts. Now: cleanup decides Task closure; owners report viewing and obey revocable requests. Input is a bounded byte queue. Every eligible Task background start proceeds.

A Session keeps history; its Process owns execution. Checkout retirement is separate: an unmerged checkout can remain after its conversation ends. No new lifecycle record is needed.

One interaction, including recovery

Leave a draft on an open Task and return: the same provider keeps it. Complete the Task, leave, and let work settle: cleanup can end it after the viewing grace. Return afterward: provider history and the saved screen come back; the editor does not, and the Task stays closed.

If the store fails, input continues and failure cannot authorize closure. Viewing writes retry before consuming a request. Output racing a completion request cancels it off the input path. A returning viewer or new work revokes the queued close; cleanup decides again.

Next demo: return before and after closure, recover from a store failure while typing, then count new fixture processes. Earlier test results and demo readings remain historical; this review ran no suites.
