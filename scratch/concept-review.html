The server wakes idle managed conversations, but who to wake lives only in its memory. lf install restarts the server, and every idle conversation goes deaf until someone types in it. The observers this branch deletes outlived a restart. The fix is a deletion: read registrations from what is already recorded.

Concepts

Built. A registration: an in-memory map entry the boundary hook writes (adapter, thread, delivery, Claude inbox or Codex endpoint, idle flag). Lost on restart; dropped on a failed send.

Proposed. No registration concept. A wake target is a managed Session with a live AgentProcess whose recorded turn state is idle. Reach is recorded on the AgentProcess: Codex's endpoint (already there), Claude's inbox key path, saved at its first managed boundary. The key path names the config dir and pid; <pid>.json holds messagingSocketPath and Claude's own status:

10838 idle interactive cli
15357 busy interactive cli
21323 shell interactive cli

APIs that change

Proposed. wake::register, Registration, REGISTRATIONS and the idle flag go. The watcher asks the store for candidates on each revision. A sent wake records the conversation as in a turn, so a second revision doesn't start a second Codex turn. The boundary's inbox field stays; it now writes a record.

Settled by the design

Steers wake (question 1 (a) from the first review). Idle waking "as today" includes a Task comment, which now arrives only as a steer; (c) would split comments from lf task steer for no benefit.
