Decision needed: none. The brief already says "a half-finished move is a row you can see and retry"; one span of the move breaks that. It goes back to implement.

Biggest mismatch: the claim moves before the row exists

send_task writes the claim naming the target, then stops the Graph, commits, pushes and takes the conversation, and only then records sent. A kill anywhere in that span:

laptop$ lf task move LOO-9 --machine mini
  claim → mini         no task_moves row yet
  stop Graph, commit, push …   ^C / laptop sleeps, process killed
laptop$ lf task status LOO-9     # Runs on mini   (mini has nothing)
laptop$ lf task move LOO-9 --machine mini
  LOO-9 already runs on mini
laptop$ lf task claim LOO-9      # the only way back, by hand

Proposed: the claim and a leaving row are one write.

laptop$ lf task move LOO-9 --machine mini
  claim → mini + task_moves leaving      (one transaction)
  stop Graph → row keeps the stopped step
  commit, push, take conversation   ^C
laptop$ lf task status LOO-9
  Leaving for mini since 10:42: not sent
    retry: lf task move LOO-9 --machine mini
laptop$ lf task move LOO-9 --machine mini
  resumes leaving → sent → arrived; Graph continues at the stopped step

Counterexample kept

A repeat finds nothing live to stop. Without the stopped step on the row, the payload says no Graph was running and mini would not continue it. So the row records the stop as soon as stop_graphs returns. Commit, push and taking a stopped agent repeat safely.
