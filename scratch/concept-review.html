2. Biggest mismatch on HEAD (Before → Proposed After)

merge_extension merges raw YAML strings instead of Loopflow's skill metadata concepts

The inheritance feature promises two clear rules: a Loopflow skill can extend any skill (builtin, repo, or native) and child frontmatter wins over parent frontmatter. Because merge_extension joins raw YAML maps without respecting SkillDialect, context normalization, or the agent/default_agent pair, three ordinary skills fail silently or crash at load time.

Counterexample 1 — Extending a real Claude skill (.claude/skills/audit/SKILL.md): Claude skills legitimately use agent: Explore and context: fork (listed in invocation.rs:208-209). On HEAD, a Loopflow file .lf/skills/my-audit.md with extends: audit merges both keys into Loopflow frontmatter: context: fork crashes immediately with LoadError::InvalidSkill, and agent: Explore tries to launch harness "Explore".
Counterexample 2 — Child overrides docs or a sibling context key: Parent .lf/skills/implement.md sets context: { docs: [scripts/testing.md] }. If child card-implement.md sets docs: [docs/cards.md], merged keeps both keys and normalize_context's or_insert keeps the parent's scripts/testing.md and drops the child's docs/cards.md. If child sets context: { diff_files: false }, shallow extend wipes the parent's context.docs.
Counterexample 3 — Child relaxes parent's pinned agent: to default_agent:: Parent sets agent: codex; child sets default_agent: claude:opus. Both keys stay in merged frontmatter, so parent's pinned agent: codex overrides child's default_agent: claude:opus.
Before (HEAD 00c7f89698) 
// catalog.rs — merges raw YAML regardless of dialect or key semantics
let parent_content = self.resolve_parent(...)?; // String only, dialect lost
let mut merged = parse_mapping(parent_frontmatter);
merged.extend(child_meta); // shallow!
// - Claude `context: fork` / `agent: Explore` leak into Loopflow child
// - child `docs:` loses to parent `context.docs`
// - child `context: { diff_files: false }` wipes parent `context.docs`
// - child `default_agent:` loses to parent `agent:`
Proposed (next pass in scratch/plan.md) 
// resolve_parent returns (content, dialect)
// 1. Non-Loopflow parent: carry only `description` (if child omits it) + body
// 2. Loopflow parent: normalize_context on parent & child before merge
//    - deep-merge nested mappings (context, context.budgets, claude, codex)
//    - child scalar/list replaces parent value
//    - if child sets `agent` or `default_agent`, clear parent's opposing key
//    - strip `extends`

Listing & self-extension honesty: report resolved parent and transitive builtin relation

SkillSource::relations() inspects one file in isolation and stores the raw extends: string. Meanwhile listing::discover already has the SkillCatalog in hand. Moving relations(source) onto SkillCatalog makes three user-visible cases honest without changing the wire schema:

Before (HEAD 00c7f89698) 
$ lf list skill
  implement     (.lf/skills/implement.md, extends implement)   # looks circular!
  qa            (.lf/skills/qa.md, extends base-qa, replaces builtin)  # wrong when base-qa extends lf:qa!
  selfie        unavailable: ... skill inheritance cycle: selfie -> selfie
Proposed (next pass in scratch/plan.md) 
$ lf list skill
  implement     (.lf/skills/implement.md, extends lf:implement) # shows real parent
  qa            (.lf/skills/qa.md, extends base-qa)             # transitive builtin -> Extends
  selfie        unavailable: ... no builtin skill is named "selfie"

Note: temporary extends: builtin (0.16.0 compatibility alias) either normalizes to lf:<canonical> or stays builtin—normalizing same-name builtin targets to lf:<canonical> in extends makes every builtin extension consistent across extends: lf:<name>, same-name extends: <name>, and extends: builtin.
