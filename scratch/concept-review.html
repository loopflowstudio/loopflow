The mismatch

The Telemetry section opens: "The provider's transcript is the record of turns, tools and usage for every conversation: managed, bare and raw." Two signals sit beside it for managed Sessions: the agent's status reports, and a hook that says "read the transcript now".

Built today. A managed Session's turn exists twice: as started/completed/usage rows written from the live stream, and as a run in the transcript. They are matched in two places.

  • For the line you read. combine orders the two as same, after or behind, by id or by start and end times with a 2-second allowance. In "same", the stream's state wins unless the transcript shows a question or an end more than 2 seconds old.
  • For the rows. facts::record skips a transcript run when a stream completion has its id, or when covers finds a completion whose time span contains it, same 2 seconds.

What that puts in front of people and other code: turn.source on the wire (stream or transcript), a turn.state of asking, and two shapes of usage row. A stream row is Claude's running total with cost_usd; a transcript row is one turn's tokens with "source":"transcript" and no cost. LOO-732's reader takes differences between consecutive rows, so it has to learn the second shape.

Five of the run's six concept reviews went to edges of this matching: stale stream, question in the same run, a completion that folds a queued prompt, a run cut off, the name of the source. QA then found the question case can't occur: Claude 2.1.322 wrote an AskUserQuestion to its transcript 55 seconds late, with its answer, and Codex never writes one. asking is on the wire and nothing can set it.

The only reader of source is one line: waits() marks a Session available from its turn only when the source is the transcript. Swift decodes the field and does nothing with it.

Two questions were folded into one field

"What did the last turn do?" and "is the ball in my court?" are different questions with different sources. The plan already separates them. The transcript knows the first. The agent's status reports know the second, including a permission prompt or a question, which no transcript shows. asking and the same-run rule tried to answer the second from the first.

Proposed. For Claude and Codex, one rule and one writer.

  • The turn is the transcript's last run. Running, ended or interrupted, with its model and tokens. If lf recorded an end for that same run id and the transcript has none, that end closes it. Matching is by id only.
  • Available is the Session's, not the turn's. From status reports when lf has them; otherwise from a turn that ended. asking and source leave the wire. Neither has shipped.
  • The transcript is the only writer of usage rows. One turn's tokens and model, keyed by the provider's run id, written when a hook says a turn ended and again at exit. Writing the same id twice changes nothing. The stream keeps writing started and completed, which carry state and stop reason.

Where the proposal breaks

Counterexamples kept.

  • Esc before any reply. QA saw the transcript write nothing: the prompt stays last and reads "turn running 4m23s". The stream knows it stopped. The id-only rule covers this while the stream and the transcript name the run the same way.
  • Folded prompts. A prompt dequeued just after end_turn is a new run in the transcript but the same turn in the stream, under the first run's id. Esc on that second run leaves the id rule with no match, and the line reads "running" until the next message. The time rule exists for this case. Removing it needs the stream to record the provider's own id at each end, or this edge stays wrong.
  • Pi and OpenCode. Their transcripts carry no turn ends. For them the stream stays the record of a turn, so the stream writer can't be deleted, only narrowed.
  • Claude cost. cost_usd arrives only in the live result, as a total. With usage rows coming from the transcript, it has to ride on the completed row or go unrecorded. LOO-732's prototype weights Claude quota by it today. Said on November 10: "raw (or uncached?) tokens probably more useful to start. $ is more of a longterm goal".
  • Size. Narrowing the stream writer touches harness/fact_writer.rs and claude_decode.rs, which this PR left alone.

docs/sessions.md would say: "The turn is what the provider's transcript shows: running, ended or interrupted, with its model and tokens. Whether a conversation is waiting on you is separate. lf knows it for Sessions it manages, from the agent's own status; for anything else, a conversation is available once its turn has ended."

Smaller mismatches

"Turn" means two things

lf history show starts a turn at every request, injected ones included. Providers, the store's completed rows and lf session list count a turn from what woke the agent until it hands back. The branch calls the second a Run internally and "turn" on screen. The concept review of 60 transcripts found that input typed mid-turn doesn't split a run, so the two cuts differ mainly at hook and notification injections. One Turn for both would add a line per turn to lf history show and change its --json once.

"Raw" describes a history; people meet a process

A raw conversation is a thread lf never recorded. A thread lf did record, resumed with plain claude --resume after its Session ended, is neither: turns::raw skips recorded threads and turns::read reads only active or detached Sessions. It lists nowhere, against "This works for every conversation on the Machine". If raw meant "a provider process lf isn't holding", that conversation would list, under its Session's title, marked raw.

Rows for bare runs outside any Task or Wave

Said on November 10: "I only really want to do observability tracking on managed work -- tasks and waves basically -- but i do want to include "bare lf" run in those worktrees". The exit read writes rows for every provider lf launched, wherever it ran, as the stream writer already does. Whether "only managed work" is a rule about what gets written, or about what a cost question counts, is not settled by the code.
