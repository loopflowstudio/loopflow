LOO-1066 · Post-build concept review · macOS Settings & Configuration Scope

Do the product’s concepts and the built code’s concepts line up?

The pre-build split between Applies to (inspected work) and Save in (declaration owner) landed cleanly in Rust’s config.scope and config::files::edit. Reviewing the built branch against base reveals one central remaining mismatch: Settings treats the raw 47-key config.catalog and a single window-wide destination/error state as its UI model. That leaks internal/inactive keys, hijacks Save in into ghost destinations, breaks nullable controls, and lets one edit error or 1-second cache lag freeze the entire window.

Product concepts vs built code concepts

Inspect work vs choose file

  • Yes · Rust’s config.scope (Scope { settings, files } + ScopeTarget + Destination) cleanly separates inspected work from editable declarations.
  • No · One name for two ideas in Swift: ScopedSettingsModel.destination holds both the user’s Save in choice (My/Shared) and an escape hatch for non-applicable rows (Edit in My global preferences), creating a ghost Save in item that silently redirects edits on other panes and breaks sidebar override dots.
  • No · Hidden state: When a Skill or Graph step is selected in SettingsTargetPicker, Applies to omits model.target once Advanced is collapsed, so edits look like repository-wide writes. Unnamed Graph steps hide provenance and give no read-only reason.

Browse & edit settings

  • No · Raw schema leaked as UI: ScopedSettings renders every non-container key in config.catalog as its own Section card with a provenance disclosure—putting internal state (portfolio), inactive compatibility keys (isolate, summaries, summary_tokens), and Accounts (auth_browsers) into live main forms, and leaving user/logs as raw YAML while hardcoding automation.
  • No · Absent vs explicit null collapsed: Rust’s Authored::{Absent, Present} is flattened to JSONValue? in Swift (Slot.value), breaking 3-state chrome: Option<bool>, conflating null with Inherited in enum Pickers, and turning null strings into literal "None" in TextFields.
  • No · Coupled policy split: agent, default_agent, and agents appear as three unrelated cards where Starting preference displays the whole fallback array as “In effect”.

Save, preview & undo

  • Yes · config::files::edit (Entry, Change::{Set, Reset, Restore}, Applied) owns checked edits, comment preservation, alias normalization, and Undo receipts.
  • No · Write and cache have no handoff: atomic_write never invalidates observe::Cache (1s poll). Right after a save, config.scope serves the pre-write file; rapid edits hit self-inflicted conflicts, and AppearanceStore kept a parallel config.theme + 1s timer because config.scope lagged behind writes.
  • No · Wrong error scope: ScopedSettingsModel.editError sets editsDisabled window-wide—disabling the text field where you need to fix a typo and locking all 5 panes until manual Refresh.

Move (Promote) a declaration

  • Yes · engine::config::promotion locks files in path order, validates both slots, previews patches and projected effective values via observe::preview_files, and supports inverse-move Undo.
  • No · Unrecoverable failure state: If a 2-file move stops after writing the receiving file and someone edits that file before resuming, there is no Action::Dismiss—the journal in ~/.lf/settings-moves/ stays stuck permanently.
  • No · Silent preview refresh & missing audience: Confirming a move whose effective result changed silently swaps moveReview with no message, and the preview doesn’t name who gains the setting.

Search & jump to a row

  • Yes · SettingsMatch indexes panes, App controls, and config.catalog keys/shorthands/descriptions, and boolean search switches share ScopedBooleanToggle and Undo.
  • No · Broken scroll owner: ScrollViewReader sits outside Form while ScopedSettingRow wraps Section { control.id(key) } in .id(RowAddress(...)), so selecting a search result never scrolled the grouped Form in QA.

Appearance, Shortcuts, Mobile & Machines

  • Yes · AutosaveToggle, shared KeyboardShortcutsView, lifted MobileSetup (sidebar dot + QR agree), and ThemeChooser / ThemeEditor draft separation match user expectations.
  • No · Duplicate read & status wipe: MachineConnections re-fetches machines via config.get instead of reading config.scope, and resets health = [:] every 30s—flashing every reachable Machine back to “Checking…”.
  • No · Loose controls in grouped Form: ThemeChooser places its mode picker, Customize button, and error text outside Sections, with errors at the bottom where they can scroll off-screen.

Audited against base 3578f78f through fff2a763: observe.rs · files.rs · scope.rs · promotion.rs · ScopedSettingsModel.swift · ScopedSettings.swift · ScopedSettingRow.swift · SettingsWindow.swift · MachineConnections.swift

Failure, recovery & counterexamples tested

Normal & rapid edits

Toggle Diff Off, then On 100ms later. With observe::invalidate_path inside atomic_write, the server pushes the updated Scope before the next click lands; both writes preserve comments and register distinct Undos.

Typo vs broken file

Submit an unknown graph name in wave.graph: the error stays on that row, the field stays editable, and Context/Agents remain unlocked. Corrupt .lf/config.yaml externally: reading.failure leads the form, keeps last values visible, and disables writes until repaired or refreshed.

Interrupted move diverges

Stop after writing Shared, then hand-edit Shared. Both files are kept untouched. The row displays the pending move; Resume reports the changed file and offers Dismiss pending move, which clears the journal under locks without touching either YAML file.

Choices made for review

All choices below are reversible and written into scratch/plan.md and scratch/questions.md for the next build pass. Reply with e.g. 1b or 2b to steer.

  1. How should Global-only Machine settings (hub, pools, machines, connections, forward.*) behave when Applies to is a checkout or Wave?
    • 1a · In plan Show them in a clearly labeled This Machine (Global) section that edits ~/.lf/config.yaml directly, without changing Save in for scoped settings.
    • 1b. Keep them read-only in checkout/Wave views with a button that switches Applies to to Global.
  2. Where should inactive compatibility keys (isolate, summaries, summary_tokens) and internal Desktop state (portfolio) live?
    • 2a · In plan Hide them from primary forms; expose authored or advanced catalog entries under a collapsed Advanced disclosure (and searchable with an Inactive label).
    • 2b. Keep all 47 catalog keys visible at top level in the main forms.
  3. When an interrupted 2-file move diverges because a file was hand-edited, how should the pending journal clear?
    • 3a · In plan Keep both files intact and require an explicit Dismiss pending move action (Action::Dismiss) so the person confirms they reconciled both files.
    • 3b. Auto-delete the journal on the next read when slots no longer match.
