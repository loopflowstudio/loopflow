The biggest mismatch: ownership is answered by containment

On main, counted_task compared Git worktree roots: a nested worktree was its own checkout, owned by nobody. Change 4 routed every caller through task_holding, which matches by containment. QA hit one caller (lf task create --worktree refused a nested worktree), and 8896fa90 patched only that caller, by comparing the root inline.

The case is common. Claude Code's isolated subagents and EnterWorktree create .claude/worktrees/<name> inside the current checkout. Three of them sit inside ~/src/loopflow right now. Here is one interaction:

1. A Task agent in loopflow.loo-X/ starts an isolated subagent. Its worktree is loopflow.loo-X/.claude/worktrees/agent-1, on its own branch.

2. The subagent's commands record task_id = LOO-X. Right: it's that Task's work.

3. Someone runs lf land in agent-1. pr_landing.rs:1200 calls task_for_checkout → LOO-X. The landing then checks LOO-X's active PR against the armed PR from agent-1's branch and fails ("Task merge request does not match…"). Wrong. On main this landing had no Task and went through.

4. Bare lf resume in agent-1 opens LOO-X's conversation (seen in QA). Released lf says "This worktree has no associated work conversation". Wrong: the conversation's checkout isn't this one.

5. lf task create --worktree agent-1 works only because of the special case. The same Session without --worktree still sees LOO-X as the checkout's owner.

The ownership answer is one index seek on task_checkouts_root: the Task whose checkout is the Git root, matched as named and as it resolves. This brings back main's behavior for ownership without its O(checkouts) Git subprocess scan, and drops the inline patch. Two Tasks on one root resolve to the lower id, the same as task_holding.

Decided for review: ownership callers are checkout_scope, pr_landing and worktree_task. Rejected: making containment the single rule and deciding a nested worktree belongs to the outer Task everywhere. That would mean lf land in a subagent worktree can't work, and the outer Task's conversation hijacks lf resume.
