A Session ended by a rebuild should say so to the person watching it

LOO-678 · concept-review step · 2026-10-28 · built from scratch/loo-678-5-whys-syspolicyd.md, rust/loopflow/src/transport/lifetime.rs, rust/loopflow/src/transport.rs, scratch/questions.md

Actions → concepts → APIs

A person rebuilds lf or removes a worktree. The Session owner running that build notices its executable is gone (one stat every 2 s), waits for any turn or Graph step to settle, and signals itself. The exit is recorded; lf resume <session> reopens the conversation. One owner, one executable identity, one end path. These concepts hold up.

The mismatch

The design ends idle owners even while someone is attached. Today that person sees:

$ lf resume session_…        # attached, idle
$                            # exit 143, nothing else

The reason and the way back go only to logs/lf.log.

This Session's lf build was replaced; `lf resume session_…` reopens it.
$

The owner sends that line through the existing Response::InputHint before it ends. No new protocol variant, no second thread.

Also noted

The branch condenses four unrelated Wave memory entries but never writes the LOO-678 entry that the condensing was meant to make room for. Realign should do both or neither.

Questions

  1. Should an attached viewer get the one-line reason before an executable-ended Session exits? (a) yes, via InputHint — taken as the next implement direction · (b) no, the log is enough
  2. Should lf resume --all restore executable-ended Sessions under the new build? (a) no, as built · (b) yes, in a follow-up Task
