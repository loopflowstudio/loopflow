Recover the result; observe the remaining work

Next implement direction: keep the original mutation result, but get current recovery status and actions from the owner of each remaining effect. No open product choice stops this work.

Biggest mismatch: recovering a locally committed edit can finish command delivery while planning remains unresolved. Its saved planning status is historical; neither that snapshot nor a transport error can decide what Retry does now.

Existing → proposed

Existing: Task edits and Wave moves save their result with a local commit fence. Recovery preserves that result and later errors. Client creation uses the SQLite outbox; shared confirmed cache, projection and both-client migration remain unfinished.

Edit A → lose output → edit A again elsewhere → restart → show current A, recover the first result, and resolve only its outstanding delivery.

Proposed experience: “Your edit stays visible while delivery is pending. After reconnect, recovery checks the saved change. A later edit stays in place. An unresolved delivery keeps its recovery action; a resolved failure remains historical.”

Follow recovery through storage and both clients

Identity: the effect/stage registry names each domain owner, stable attempt/change identity, confirmation reading and authorized continuation. Reuse existing domain queues; keep correlation in the one receipt owner. A current matching value cannot prove which attempt wrote it.

Failure: a committed local edit survives planning or output failure. Retry targets its domain-owned change, never the original mutation. Missing or unavailable confirmation retains uncertainty and Inspect where no safe continuation exists.

Resolution: saved results and diagnostics stay immutable. Current status comes from fresh domain readings, so a historical error cannot keep a resolved change looking failed. Reading a result cannot settle an external effect.

Queries: keep ordered effects and incorporation per query. A covering count receives no extra decrement while an older list retains its overlay. Future windows evaluate the same dependencies. Persist cache/outbox changes atomically.

Ordering: release a resource lane when its prior writer can no longer mutate that resource. A planning wait does not block every local edit; a live external writer still requires domain ordering.

Epoch: old fences cannot certify a replacement database or authorize replay. Recover the exact command on its original Machine; native owners retain input readiness.

Next: remaining mutation-family recovery and fences → transactional cache and declarative membership → ordered projection → both clients and predecessor removal. Existing recovery skill instructions remain valid. Native latency remains unmeasured after failed host preflight. This review changes design only.
