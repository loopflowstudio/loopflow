A Session and the view someone is at, as built

Area taken: everything that decides whose terminal a running Session is shaped for when several views show it, with the whole branch in it (base e804e652f5 to fb3b075d08): the holder's sizing rule, the relay, the lf commands that start a view, Desktop's panes, Loopflow Dev and the phone. Anything marked proposed is not built; everything else is in the branch.

The answer

The product's concepts and the code's line up. The one mismatch the last review found, a second way for a host to say "this pane starts in the background", is deleted (34ade5b29e): a prepared command is the same argv whatever its focus, and whoever runs it says where it stands. A run over real SSH then showed the rule holding across Machines.

Nothing in the model needs another pass. One sentence of the transport README still describes a type this branch deleted; it is listed for gate.

The biggest mismatch, and what became of it

Before (last review)

  1. Person: lf resume X --unfocused
  2. Host: LF_RELAY_FOCUSED=0 in the pane
  3. Host, second way: --prepare --unfocused wrote the flag into the argv. Run by an lf from before the flag: error: unexpected argument '--unfocused' found, and no pane.
  4. Wire: focused

After (built)

  1. Person: lf resume X --unfocused
  2. Host: LF_RELAY_FOCUSED=0 in the pane
  3. Wire: focused
  4. A prepared argv never mentions focus. remote_session_open_returns_an_owner_pinned_terminal_command passed with the same argv for both focus options.

What remains is three spellings of one fact, each at a different door: a flag for a person, a variable for a host, a field on the wire. Each has one reader, initial_focus for the first two, and none is derived from another by string editing.
