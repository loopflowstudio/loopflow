Themes with the phone and the website in them: do the concepts line up?

Area taken: the theme choice as a whole, now that steer f4ce64ed (“make sure to make ipgone app respecy themes and the website he in loopflow light”) puts two more surfaces on it. Round 4 left the Mac chooser with nothing to change (one assignment, side from the theme's colors). The open question is where “the chosen theme” lives once it is read by something other than the Mac app, and what the website is relative to the catalogue. Branch against base 621fb0926d, HEAD 54bab27109.

One interaction, walked

Normal, as it should be. On the Mac, Choose Theme → Fig, Apply. Config now says theme: light:Fig Leaf,dark:Fig. On the phone, open Loopflow at night: Task list, workspace and terminal in plum and lime. In daylight: Fig Leaf.

Today. The phone ignores all of it. Three views each compute colorScheme == .dark ? .dark : .light (LoopflowiOSApp.swift:61, MachineConnectionView.swift:81, TaskListView.swift:209), and the pickers receive whichever was computed. The website is a third, hand-kept palette: --wine #9B1A4A for buttons next to --burgundy #722f37, a dark terminal block, warm paper greys that match neither default.

Failure. Config names Personal, a file in the Mac's ~/.lf/themes. The phone ships only the 26 built-ins. It draws the Loopflow default for that side; nothing breaks, the phone and Mac differ.

Recovery. Choosing a built-in on the Mac; the phone picks it up the next time it comes to the foreground. Before the phone has ever reached a Machine (pairing screen), it draws the Loopflow pair.

Biggest mismatch: the choice is a Machine fact addressed as a file path

Everything on the phone follows from where the choice lives. It lives in one place already, the Machine's config, and Desktop already reads it through the Machine's server. But the read is config.theme { path, value }: whoever asks names the file. A phone can't name a Mac path, and a second variant without one would be a second way to ask the same question.

Recommendation: drop path. config.theme { value } reads or writes theme: in the serving Machine's own config. Desktop and the phone make the same request over the same connection. A parameter that could disagree with the Machine goes away; nothing is added.

Counterexamples kept

  • A Desktop connected to a remote Machine reads that Machine's theme: but its local ~/.lf/themes. Same as today; dropping path doesn't change it.
  • Theme tests point ThemePaths.config at a temp file. After the change the fixture server's LF_HOME is that temp root instead; ThemePaths loses config.
  • The phone before any Machine: Loopflow pair. Not a theme choice, nothing to read.
