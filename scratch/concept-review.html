The biggest mismatch: this branch and LOO-980 disagree about where a Task's Wave lives

LOO-980's brief, under "Decided":

  • "Wave membership is derived from the link, not stored." This branch stores it in tasks.wave_id, from the direction quoted in the plan: "(b) the Task joins the Wave directly with no Project, which adds a wave_id on the Task".
  • "Nothing Loopflow-only is stored on a tracker item. No Linear attachment." The plan named "a description marker or an Attachment" in LOO-980 as the way to mark the child Wave. LOO-980 rules both out.
  • Under "To design here": "A person's own Machines exchanging through Git on a tracker repository". That is where task_wave would cross Machines on a connected repository.
No code change here. The plan's Trackers section and scratch/questions.md now name LOO-980's Git exchange as the carrier and drop the marker. LOO-980's "derived from the link, not stored" is stale once this merges; that sentence needs changing before LOO-980 is built.

Before: the plan says a marker in LOO-980 fixes cross-Machine Waves. After: the plan says LOO-980's own-Machines Git exchange carries task_wave, and flags the stored-versus-derived contradiction.

Counterexample kept: two people, not one person's two Machines. LOO-980 sends no Loopflow-only data between people, so a teammate always sees y under billing. That follows from child Waves without child Projects and holds under either design.
