Confirmed host exit releases retention.

The current code can keep its shells and checkout indefinitely if Desktop crashes before reporting release. The idle agent can still end.

Accepted · 1a: once lf confirms that the retaining instance is gone, release its hold and allow normal cleanup without reopening the app. Final requested work still finishes first.

A missed heartbeat cannot prove this. A Rex client can disconnect while its server still owns useful shells. That remains retained or unknown until the real owner's state is known.

The occurrence currently records a lease and revision, but no retaining-owner identity. The accepted change will connect it to verifiable owner evidence. A newer host instance must defeat a delayed old-exit report.

Desktop's presentation can be gone while its destination-owned shells still run. Their owners settle those jobs separately. Rex's native server has its own responsibility; closing its client cannot stand in for ending its shells.

Next implementation proof

Kill Desktop and let cleanup finish while it stays closed. Contrast that with a lost connection to a surviving host. Repeat with a final agent turn running past the deadline, another host retaining the Task, and a new Desktop instance racing an old exit report.

Decision recorded

1a · Selected by Jack Heart. Confirmed retaining-host exit releases its hold. Use ordinary cleanup grace and wait for work and resource settlement.

1b · Not selected. Require a fresh release report even after confirmed exit. Shells and checkout can remain pending until the host returns.
