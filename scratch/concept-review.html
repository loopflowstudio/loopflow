Before and after

Previous command shape

lf machine
  connections / pools / rentals
  service run / status / ensure
  remote client access in LOO-718

The mismatch is responsibility: choosing a worker and admitting a phone are independent actions. Server registration is installation machinery, even when its code lives beside the listener.

Implemented local command shape

lf machine       execution destinations
lf --machine …   route a command to one
lf server        client access and availability
lf install       artifacts, registration, updates
lf desktop       windows, panes, app automation

The local executable now uses lf server; installation owns its hidden readiness bridge. LOO-718's existing remote-access verbs will move with their semantics preserved during integration. This page does not claim the rename has shipped.

Keep editing through replacement

  1. Open Desktop. Installation prepares the local server. Desktop connects without a separate setup ritual.
  2. Hold a draft while a Graph runs. Update the installed helper. The server connection drops; the existing execution owners continue.
  3. See “Reconnecting…” in native chrome. The screen stays visible. Copy, Find and scrolling remain available; typing waits for the exact owner's acknowledgement.
  4. Continue on that owner. Automatic recovery preserves a newer viewer's claim. A read-only pane offers Move here for explicit control. Retry repairs connectivity only.

If takeover succeeds but its reply is lost, and another viewer claims control, recovery must leave that newer claim intact. Never replay takeover, typing or an uncertain command.

The composed signed same-build replacement test already retains the owner, provider, draft and Graph. Rendered Desktop continuity and Linux replacement remain proof to complete; the command cutover has focused registration-migration coverage; gate owns the composed installed replacement rerun.

One server, existing owners

Desktop ─ Unix socket ─┐
                      ├─ server ─ shared reads / subscriptions
phone ─ HTTPS / WSS ───┘         ├ complete CLI commands
        (LOO-718)               └ Session owner ─ provider / PTY

The server owns admission and delivery. Session owners retain terminal control and lifetime; Graphs retain execution. Drafts, active turns, pending requests and running Graphs already protect their owners.

A paired phone is a client credential. It does not become a worker, move a Task or own its provider. Remote access has separate authentication; turning it off must leave local access and execution intact.

Migration boundary

Local command routes, supervisor entries, Swift names and fixtures now share the server namespace. The old bundled plist remains only to inspect and retire existing registration. The socket address stays stable for live relays. MachineId, machine_id, SSH routing, credentials and owner protocols stay in place.

LOO-593 owns the local foundation and recovery. LOO-718 owns remote access and the native phone path. This pursuit implements the local cutover in LOO-593 and records the migration LOO-718 needs. It preserves the stop at interactive demo and leaves the other checkout alone.
