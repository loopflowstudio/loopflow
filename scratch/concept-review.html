Two places the branch makes switching cost more than a slower start

The lifetime rule is built as stated: open conversations keep running, and a closed Task ends its own. Two older pieces still assume conversations end on their own, and they now work against your condition: "as long as only cost is slightly slower spin up time next time youj switch to them" (Jack Heart).

What is built

ConversationRuns until
Open Task, Wave, repository, bareYou quit its agent. No idle ending; session.end_detached_after is read and ignored.
Done TaskFifteen minutes unviewed, once live work settles; checkout or none, and again if resumed after cleanup.
Abandoned TaskAt once, even mid-turn, if unviewed.

Typed input is no longer recorded or consulted anywhere.

1 · Resume after an install drops your draft

  1. You type half a prompt in LOO-900's conversation and switch to another Task.
  2. lf install runs (you, or the dev stream).
  3. You come back: lf resume --task LOO-900, or click it in Desktop.
  4. The draft is gone. The conversation's owner runs the old build and nothing is in flight, so resume replaces it and continues from history.
// human_session.rs, attaches()
An idle owner that is superseded or does not answer gives way to native continuation.

Before this branch, the input record kept such a conversation on its old owner, so the draft survived. With the record deleted, every idle conversation qualifies. Resume can attach to an owner on another build; resume_takes_over_an_owner_from_another_build tests it.

Proposed. Resume attaches to a live owner on any build that answers. Only lf process rollover, which you run deliberately, replaces one. Switching back never loses anything; old-build owners stay until rollover or Task close.

2 · The warm-start cap keeps the oldest and starts the newest cold

lf task run starts the Task's conversation in the background so opening it is instant, unless 16 Task conversations already run. Before, idle ending kept that count low. Now open Tasks' conversations never end, and 63 were running at the 01:40 read.
