The mismatch that matters

session_actions already says what an active Session allows:

This Session is active in another terminal; use Take back to transfer it

Transfer control here; unsent text in the previous terminal is not transferred

Resume::Running asks only whether the provider is alive, so it does Take back with no one choosing it. Type half a message in Desktop, run lf open in Rex, and the conversation moves away from your text. Run the open twice and every conversation leaves the first session.

Earlier passes offered two answers, keep moving or never reconnect. Each dropped half the Task: “return people to the right Loopflow Task Sessions” and “without stealing active input”. The Session states satisfy both, and the Task says to reuse those semantics.

What changes

Resume::Running becomes Resume::Detached and provider_running goes. lf open --task keeps moving a conversation, because naming it is the choice. Proposed for docs/workspaces.md:

Opening a repository or Wave starts no agents: it reconnects running conversations no terminal is showing and shows Task & workflow for the rest. Run lf open --task <task> to pick one up. That moves a conversation open in another terminal here; text you typed there and didn't send stays behind.

The cost: opening a Wave no longer gathers conversations from Desktop into Rex. Each takes one lf open --task.
