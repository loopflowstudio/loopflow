4. Reversible product choices built for human review

Everything below is already built and committed at f80b985427. None is irreversible once shipped; reply with a number and letter (for example, 2b) if you want any choice changed before merge.

1. How should a collected rental’s SessionHistory.repo relate to this Machine’s local repositories?
  • 1aBuilt at HEAD Resolve copied rows’ repo to this Machine’s repository_plans.repo when their Task or Wave lives here (keeping worktree as the origin’s working directory, and keeping the origin’s repo string for bare runs), while building Desktop Telemetry’s local codebase picker strictly from origin == nil rows.
  • 1b Always keep SessionHistory.repo as the raw Linux path from the sandbox and add a separate repository-matching field to the DTO so Swift and Rust can map them independently.
2. How should ended rentals appear in Machine listings and respond to lf machine end?
  • 2aBuilt at HEAD Settle provider-terminated sandboxes in lf machine end via refresh() without --force, and hide ended rentals from default lf machine list / status (keeping them resolvable by explicit <label>, in lf ondemand list, in Desktop’s unfiltered machine.list, and as from <label> history labels).
  • 2b Keep ended rentals in default lf machine list until pruned or manually removed.
3. What should Modal’s default burst idle floor be?
  • 3aBuilt at HEAD Modal’s published minimum of 0.125 physical core and 128 MiB RAM, bursting up to --vcpus / --memory-gb, with --reserved pinning floor = ceiling.
  • 3b Raise the idle floor (e.g. 0.25 core / 256–512 MiB) if live Modal idle billing or container responsiveness warrants it.
