2. The Biggest Remaining Mismatch on HEAD

Biggest Mismatch Three distinct endings are collapsed into one integer (agent_exit_code)—and only half the launchers even write it

When an interactive conversation stops running, a person cares about three completely different facts: I quit it, Loopflow closed it (15-minute unviewed cleanup or Task closed), or it died (crash, OOM, reboot). On HEAD, the store only records agent_exit_code—and hosted.rs knows CloseReason::Retired yet throws it away right before SIGKILLing the process group.

Because LOO-1097 moved everyday terminal chats (64% of which end by tab close) and delegated Skills into held terminals, this turns normal daily usage into a wall of false died (exit 137) and died (no exit recorded) errors across lf session list, Desktop status_line, saved screens, and capture outcomes.

4. Counterexamples & Failure / Recovery Checks

Scenario / Counterexample How the model handles it
Resume a retired chat without a server, then it crashes
Counterexample against storing close_reason on held_terminals		 An unheld fallback Chat does not replace agent_sessions.held_terminal_id. Storing agent_end_reason on agent_sessions and clearing it in attach_in alongside agent_ended_at/agent_exit_code ensures a later crash in fallback mode reads died HH:MM (exit 1), never the stale retirement reason.
Server crashes between child.retire() and settlement hosted.rs writes retire-reason.json beside the terminal before sending SIGKILL. The next server's registry::settle reads both exit-record.json and retire-reason.json, settles it as retired (not died), and removes both with the terminal receipt.
Real crash, external kill -9, OOM, or reboot retire_reason is absent. Settlement still records agent_exit_code = 137 (or NULL on reboot/holder death), agent_end_reason = NULL, capture outcome = "failed", and session_ending still reports died HH:MM (exit 137) and triggers Task auto-recovery.
Completed Task retires, then person reopens the Task While closed, it reads closed HH:MM (Task completed); `lf resume --task …` opens it. Reopening the Task keeps that honest status rather than claiming it died with exit 137; lf resume --task … reopens it cleanly.
Delegated Skill quits normally vs. retires unviewed Normal /exit or Ctrl+C runs checkpoint, emits Skill::Completed, writes agent_exit_code = 0|130 → quit HH:MM. 15-minute unviewed retirement writes agent_end_reason = "15 minutes without a viewer" immediately on terminal end → closed HH:MM (15 minutes without a viewer).
Choices Made for Review Written into scratch/plan.md

Built on HEAD: Hold every interactive lf launch (chats, Skills, bare resumes) in lf holder run whenever the Machine server is running, with 15-minute idle-unviewed retirement for standalone conversations and automatic direct-terminal fallback when no server is running.

Proposed for Pass 2: Record intentional retirement as a first-class end reason on agent_sessions (agent_end_reason) and record agent_exit_code on waited native launches (spawn_native) so quit, closed (<reason>), and died stay distinct across CLI, Desktop, saved screens, and captures—with no breaking wire/DTO change. Passed over: (1) Leaving retired chats reading died (exit 137) — makes 64% of everyday chats look crashed. (2) Putting close_reason only on held_terminals — breaks when a retired Session later resumes unheld without a server. (3) Renaming WorkSession/Chat across the whole product — separate scope outside LOO-1097.

5. Open Questions for Review

Reply with a number and letter (for example, 1a 2a 4a). Highlighted options are what this branch builds for review.

Question 1 (Built on HEAD) — When you run lf -a agy or lf <skill> in a terminal and later open it in Desktop or another Rex pane:
  • 1a. Always held when the server is running (built). Opening it elsewhere always attaches a second live view without stopping or restarting the agent. Tradeoff: Rex sees lf instead of agy as the foreground program (same as Task sessions), and Ctrl+] detaches instead of Ctrl+Z suspending.
  • 1b. Keep chats directly in your terminal, restart into the holder on second open. Rex keeps showing agy while only one pane is open, but the first cross-viewer open stops and restarts the agent (aborting active turns and losing unsent input).
Question 2 (Built on HEAD) — After you close the last tab showing a standalone chat (not bound to a Task, Wave, or Repo), how long should its agent stay running?
  • 2a. 15 minutes after it goes idle with no viewer (built). Closing Rex and switching to Desktop attaches with zero restart, active turns finish first, and forgotten tabs don't pile up idle agents.
  • 2b. Stay alive indefinitely until you type /exit (same as Wave and Repo conversations; closing tabs leaves idle agents running).
  • 2c. Close as soon as the last tab closes (once any active turn finishes; switching from Rex to Desktop restarts from history).
Question 3 (Built on HEAD) — When you run lf -a agy while the Machine server is stopped:
  • 3a. Run directly in your terminal (built). Instant fallback in containers, CI, or when the server is intentionally stopped; uses the holder automatically whenever the server is running.
  • 3b. Start the server first so even after stopping the server, direct lf starts it back up and runs held.
Question 4 (Proposed next pass) — After Loopflow closes an idle chat (or a completed Task's conversation) for having no viewer, how should it read in lf session list and Desktop, and what if you later reopen a completed Task?
  • 4a. Show closed HH:MM (15 minutes without a viewer) / closed HH:MM (Task completed) and never auto-restart it as a crash (chosen). Clearly separates intentional cleanup from real crashes (died) and manual exits (quit), and drops the misleading agy exited with 137. line from the saved screen.
  • 4b. Show closed HH:MM (…), but auto-restart a completed Task's conversation if the Task is later reopened so reopening a Task immediately brings its agent back without running lf resume.
