Should bare lf stop starting an owner process in this PR?

Every interactive launch goes through delegate → start, which spawns lf session serve and relays the terminal to it. A bare lf debug gets the same detached owner a Task conversation gets. That owner is the only reason a bare session can outlive its terminal. To "behave like the underlying harness", the owner either has to end with the terminal or not exist.

  • "with bare lf, noting holds its at all"
  • "for a bare session, it jsut does whatever claude or codex would do"
  • "agian, just behaves like the underlying harness woudl"
  • "if its a managed task session, then neither ends the session"

One interaction, three ways

A and B look the same to you. They differ in what exists.

A: keep the owner, give it the terminal's lifetime

Owner and relay stay. The owner learns "if bare, end when the last viewer goes, and don't treat Ctrl+] as detach." That is a per-scope branch inside the owner's lifetime code, which has already gone through idle ending, an input ledger and close requests, and which server-first plans to delete. Bare turn hooks keep working because an owner still holds them. Small diff.

B: bare runs in the terminal's foreground

Proposed, not built. delegate starts an owner only for managed conversations. A bare launch runs the provider as the terminal's own foreground child. There is nothing to end, leak or clean up. This is the server-first piece "Bare launches go direct: no owner, agent in the terminal's foreground", pulled into this PR.

Counterexample: a Graph started from inside bare Claude (lf graph x, no Task) runs its steps under that owner today. Under B, closing the tab ends them with Claude, as for any child of plain claude. A Task's Graph is managed and unaffected.

Where "managed" stops

The line decides who gets an owner. The code has PrimaryScope (repository, Wave, Task) for each scope's ongoing conversation, and separately whether a Session names a Task. They disagree on lf debug typed inside a Task's checkout: it names the Task but isn't the Task's conversation.
