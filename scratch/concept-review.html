2. Biggest mismatch: paused Tasks invade Portfolio’s Now list

You pause a Task specifically to hold it quietly without giving it up — usually mid-build with a dirty checkout. Because rust/loopflow/src/lf/commands/waves.rs::derive_task_condition does not check TaskState::Paused, a paused Task with uncommitted edits gets condition = Blocked("Task has uncommitted work"), and a clean paused Task gets condition = Waiting("Task is paused; run `lf task unpause …`"). TaskRow.swift:53 patched around that locally (task.lifecycle == .paused ? nil : task.need), so the sidebar looks calm — but WaveWorkMap.swift::RoadmapTask.need, NowProjection.swift (Portfolio Now), accessibility labels, and TaskBriefView still read the unpatched condition.

3. Second mismatch: auto == off in flight before landing reads as Shipping

In rust/loopflow-execution/src/task_graph.rs::ships_before_review, auto == Some(AutoState::Off) is checked only when cursor == None (already stopped at land). If someone runs lf task auto off while deliver is still in reflect or gate, cursor is Some(gate), so the check is skipped and the row stays in Shipping — even though auto == off disarmed landing and the run will stop at land for a person.

4. Build blocker found at HEAD

Commit 279b71c8d1 (lf qa: Add empty rust/loopflow/src/main.rs) added a 0-byte rust/loopflow/src/main.rs. Because rust/loopflow/Cargo.toml does not disable autobins, Cargo tries to compile a third binary crate named loopflow from it and fails with error[E0601]: main function not found in crate loopflow. Deleting rust/loopflow/src/main.rs restores the build.
