The biggest mismatch: whether a Task needs someone

Existing

Rust calls a Task waiting whenever its next move is not the Task's own. An unstarted Task waits on a person to press Start, so it is waiting, reason "ready".

TaskStanding disagrees, in a rule private to its initializer: waiting counts only when the Task has started or its recommended action is not Start.

nowGroup never heard. It files by the wire. Heading from one decider, rows from the other.

Proposed. RoadmapTask.need

The same rule, moved beside awaitsStart in the shared model: the condition state when the Task needs someone, nil when it does not.

TaskStanding reads it. nowGroup returns it. The Now list then lists what its rows say needs someone, under the word they say.

Tested on three paths

  • Normal. A Wave of unstarted Tasks: the Now list is empty and says so; the backlog lists them and starts them. Nothing is lost, because Start was never offered better anywhere else.
  • Failure. A Graph stops: blocked is a need whatever the lifecycle, so the Task is under "Blocked" with its reason, as now.
  • Recovery. Click, and the page's two words are one word; the sentence is under it.

Counterexamples kept

  • An unstarted Task waiting on something other than Start (qa's fixture: a merge it depends on). Its recommended action is not Start, so it stays a need and stays on the Now list. The narrower rule qa landed on is the one kept.
  • "ready" is still on the row. Slice 5 does not fix the wording; it only stops the line from hiding the sentence. Filtering the literal word in Swift would be a second guess at the server's meaning. Question 3.
  • Swift still overrides Rust. The repository's rule is one predicate, in Rust. need is one predicate in Swift, which is better than two and still not that. The Rust change alters lf wave show, the plan board and the DTO fixtures; it is named below as its own outcome.
  • "Completed" and "Canceled" have tests. TaskConceptTests and WorkCLISubscriptionTests assert them, so someone chose those words. The row's words win because they are the lifecycle's own and what lf task status prints. Question 2.

What changed in the plan

  • "What the code is today" no longer says nothing remains for build.
  • Two lines added to "Done when": the Now list's headings agree with its rows, and a Task's own page says its row's word.
  • Three subsections under "Where a Task stands, said once": the one predicate, the page's word, and a reason said once.
  • Slice 5, in order: RoadmapTask.need with TaskStanding and nowGroup reading it; TaskWorkflowHeader and the palette printing the standing's word; the tile's sentence yielding only to a program's ask, and the Brief dropping the repeated line. Each with its test, then the two docs.
  • "The standing belongs on the wire" added to what is outside this change.

Outside this change

  • The standing on the wire. task_condition returns clear for a Task that only awaits Start; a parked Task's reason is its Graph's sentence; lf wave show and the plan board follow; RoadmapTask.need is deleted for condition.state. Rust, CLI output and DTO fixtures.
  • One page for a Wave and the workflow sentence on a list row, both as written before the build.
