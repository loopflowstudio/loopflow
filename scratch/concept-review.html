Worktree registration owns cache recovery

Based on scripts/build_cache.py, scripts/dev-lf, scripts/testing.md, python/tests/test_build_cache.py, python/tests/test_dev_lf.py and scripts/benchmarks/crate-rebuild/results/loo-921.json.

Before this change

No, inspect the cache → cache readiness → status. After a checkout skipped its hook, checking status created the inventory and returned 0. Starting a build through dev-lf also wrote the list and left a stale daemon serving the old roots.

Now, after a skipped or failed hook

$ uv run python scripts/build_cache.py status
roots    0 of 0 loaded; this checkout is missing from the root list; run register
$ uv run python scripts/build_cache.py register
$ uv run python scripts/build_cache.py status
roots    0 of 2 loaded; this checkout is listed for the next daemon start
$ cargo test -p loopflow-execution --lib skills::catalog::
  • Yes, inspect → readiness → cache_status. Status reads the configured list and the daemon’s loaded roots. It points to register for a missing Machine root and names the relevant setting for a caller-owned list.
  • Yes, checkout or recover → worktree registration → register. The hook and manual command share the inventory update and conditional stop. Git can finish a checkout after a registration error. Cargo starts the replacement daemon when it next compiles.
  • Yes, build → local target and shared cache → Cargo. Ordinary dev-lf builds use Cargo’s configured cache. dev-lf --isolated-build uses a separate target and bypasses the compiler wrappers.

What the checks showed

The Machine’s installed hook still carries the previous version. Reinstall from the merged checkout to update that copy during verification.

  1. Does the skipped-hook path recover? Status returned 3 with the inventory still absent. Registration listed both linked roots, then status returned 0.
  2. What survives daemon replacement? The focused test passed and Cargo kept the compiled library. One cache write was lost. The caller-owned daemon stayed running in its separate check.
  3. Does the isolated build bypass the cache? The launcher fixture verified the separate target and both compiler wrapper overrides. All 17 focused Python cases passed.
