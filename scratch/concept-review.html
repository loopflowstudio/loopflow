All 96 are --moment task-updates. The Task's Problem cites 62 processes holding 8.3 GB and attributes them to Pi's 1 s poll and OpenCode's per-request render. Those are gone on this branch, but the live table points at the watcher.

As built on this branch

Built. Pi and OpenCode open machine.sock per boundary (hello, one session.boundary, close). They run lf __context-block only at start and after compaction. Claude and Codex register the watcher as an async hook:

"SessionStart": [{"matcher": "startup|resume|clear",
  "hooks": [context("start"), {"command": "… task-updates", "async": true}]}]
"Stop": [… {"command": "… task-updates", "async": true}]

Two shapes for Task updates

Proposed (2a). Keep waking an idle conversation, but the waiter is a /bin/sh blocking on a file the server writes, built like the Pi bash guard: no lf, no held server slot.

Proposed (2b). No waiter. Task updates ride the next session.boundary answer beside steers. An idle agent hears about a Task change on its next turn.

Settled here

server/README.md opens its OpenCode/Pi section with “starts no lf process after launch”, which leaves out the compaction render and Pi's watcher. Next implement step: say both.
