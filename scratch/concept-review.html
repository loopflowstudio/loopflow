Return cancels cleanup before the next sweep.

No further design change or open product choice. The accepted return rule is implemented. Recording renewed viewing revokes queued closure without waiting for the one-minute Machine sweep.

The repaired mismatch

Before: the sweep queued shell closure and exited. A Task Session viewer returned, but a shell owner could still consume the old request before the next sweep. The checkout survived; the shell state was lost.

Now: one transaction records the Process's dated viewing and cancels automatic closes. Ending::confirm uses current Task retention and retirement intent before closing. A stored closing phase alone cannot authorize the effect.

Actions → concepts → APIs

Complete and leave → retirement record → finite sweep
After fifteen minutes absent, task retire queues owned closure. SQLite keeps progress and retry state; later passes finish interrupted work.
Return → Session viewer → record and revoke together
record_owner_viewer_hold records viewing and cancels that Task's queued retirement closes together. Passive viewers count. owner_retiring rechecks before automatic closure.
Reconnect → same shell receipt → attach
Local and SSH connections reattach without replaying startup. Desktop supplies integration resources only on creation. New Shell creates fresh execution.

Recovery stays the same

One surviving passive viewer retains the checkout. A brief return and leave starts a new absence window. Explicit Close still ends the shell; Undo restores identity and history. Already-ended execution cannot be revived by cancellation. Ordinary shells grant no hold, and LF never closes Rex-owned shells.

Current Desktop usage: “⇧⌘T restores the last closed tab's identity and history. Close ends its shell and jobs; New Shell starts fresh execution.” No new host registry, terminal protocol or cleanup worker is needed.
