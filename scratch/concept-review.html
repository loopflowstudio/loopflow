Everything opens. One Task kind still waits for a click it was never meant to need.

Jack Heart said "auto open everything and prefetch everything", and that once something is selected you should see its session. The primaries change delivers that for the repository, every Wave and every owned working Task. A started Task nobody owns still shows the gate, because of a November 4 assumption that borrowed the Wave board's "nothing moves an unassigned Task" rule. Opening a conversation moves nothing: its first turn reads, claims nothing and starts nothing. So the exclusion has no requirement behind it, and the accepted direction already removes it. Marked proposed below; everything else exists in the working tree. These findings come from reading the code, not from running it.

Counterexamples that held

  • Load started no Graph and ran no operator: the primaries' first turn is the reading pass, from Desktop and from lf resume alike.
  • A primary on another Machine is refused by the queue's Machine check; its checkout is Rust's persistent one, which Desktop's navigation never names, so only the Machine is compared.
  • Close on the repository conversation survives refresh and prefetch; a deliberate visit readmits it.
  • A store without a runtime prepares and launches nothing, so headless registries and tests never spawn lf.
  • The Stopped run's untouched conversation reported its recorded comment without acting on it.

Settled here

Three implications of the accepted direction go to the next implement iteration: started unassigned Tasks open like any working Task; an unstarted Task's pane is a Task-start offer in its own words, not the rejected conversation gate; and Task and primary panes share one placeholder with one Retry routed by kind, since the primary branch's "not reported yet" copy cannot render (no pane exists before the Machine is known). None changes a concept or an API shape beyond deleting a term and a duplicate branch. The product rule behind the first-turn change is recorded as a rule, not a limitation: a primary never operates unprompted.
