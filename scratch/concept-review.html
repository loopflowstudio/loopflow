Built → next

Built: synchronous Complete, save-before-send, same-ID adoption, shared-query leases and origin-only navigation on Desktop and phone. Existing checks cover held disk, receipt/list/count permutations, restart and replacement epoch. This review ran no builds or latency trials.

Proposed: remove .view(WorkViewPlan), raw replacePlan publication and the separate refresh reader's authority to draw membership. Keep query identity in history; render its latest projection from the shared owner. Refresh failure retains usable content with its error.

Proposed usage: Open a cached view: it selects immediately with pending changes already applied. Complete removes the Task across affected feeds and counts. Back returns to the current query. Refresh never brings back the captured old list.

Follow the query through

Model: Machine/repository and query identity identify the destination; answers, errors and freshness live outside navigation history. A saved Dashboard retains its identity through expression edits; changed plan coverage is still required. Retained Task/Session destinations stay reachable.

APIs: mount every displayed query through the shared owner, including expressions and post-write refreshes. Reuse served subscriptions for stamped answers. A returned command plan or checkpoint cannot certify membership incorporation; never invent a stamp for a one-shot response.

Persistence and recovery: reuse confirmed cache, outbox and per-query coverage. Opening a cached query applies effects before display. Closing one shared-query window leaves the other's lease intact. Old epochs cannot authorize replay. Finite closed-query invalidation remains required.

Ownership: query freshness does not control selection. Departed readers may warm their own cache under stamp checks, but cannot navigate or present native tiles. Complete takes the originating displayed order, deduplicated by full Work identity; another window keeps its selection.

Both hosts: Desktop removes the alternate readers; mobile exercises the same query-open, refresh and recovery semantics through its existing filters. No new mobile Dashboard or tree is proposed. Native input readiness remains separate.
