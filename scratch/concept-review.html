One payload for both

Move {
  from_machine_id
  session:  { id, name, title_source, task_id, provider, model } | null
  checkout: { repository_id, branch, commit }
  history                                   // carrier: question 2
  task:     { ownership_marker,
              workflow: { graph, node, edge, moves[] } } | null
}

The Workflow's selection already reaches other Machines through planning sync. Its position and history (task_workflows, task_workflow_moves) are rows on the owner's Machine, so the Task move carries them. The process ids in the history are cleared, because those processes stay on the laptop.

Decided

  1. Two moves, layered. The Session move carries one conversation. lf task move --machine carries the Task and uses the Session move underneath. A Task's Session moved on its own takes only the conversation.
  2. A live Graph is stopped by a Task move. The checkpoint commit keeps whatever it had written, and lf task run on the target runs the slice again.
  3. History is the provider's own session file for every move that keeps the same agent harness, across logins and Machines. The rendered log is only for switching agents, and as a fallback when the target can't read the file. A test confirmed that Claude finds a copied file filed under a different working directory.
  4. lf machine use --session carries the conversation for Wave and repository primaries, instead of starting a fresh one.
  5. A login you name that can't launch fails and names it. It never falls back silently.
  6. lf resume --account <email> -a claude works, and -a claude means the Claude login.
