One conversation, three ways to reach it

Stated direction: a direct CLI invocation opens here; an agent invocation opens a sibling tab; Desktop focuses the conversation. Latest proposal: terminal opening reports an existing view and requires --focus to switch to it.

The biggest mismatch: opening a Task can succeed by creating a status pane while leaving its conversation unopened.

Actions → concepts → APIs

open --task → Task's primary Session → resolve or prepare that Session → present Here, Sibling or Focus. open --session starts from the named Session and uses the same presentation path. Neither advances the Graph.

task view → workflow and recorded work → read and subscribe. Workspace arrangements remain a separate product question; their useful panes must remain available.

Proposed usage

Flag names are proposed, not built:

lf open --task LOO-820 --here
lf open --task LOO-820 --tab
lf open --task LOO-820 --focus

Agent guidance: opening a workflow pane does not fulfill a request to open a conversation. Report the actual destination or failure.

Decision

1. How far should “already open” look?
1a. The same terminal.
1b. Any host on this Machine.
1c. Other Machines too.

2. Repository/Wave opening and workspace arrangements still need a separate definition.

The working proposal is in open-design.md. These opening semantics are not implemented. The separate status-update bug is fixed in this checkout and its live-refresh regression passes; the installed app has not been replaced.
