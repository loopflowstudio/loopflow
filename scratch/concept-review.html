One interaction, through failure

  1. Open and edit. Installation prepares access. The server bridges the existing Session owner while a Graph runs independently.
  2. Replace the installed helper. The connection drops. The draft, provider and Graph must survive. Native status says “Reconnecting…”; input pauses while the last screen remains readable.
  3. Reconnect to that owner. Fresh terminal state restores the screen. Uncertain typing is discarded. Newer input and geometry claims remain intact.
  4. Move here explicitly. A connected read-only pane offers control transfer. Its generation-bound action is consumed before sending; typing waits for acknowledgement.

Decisive counterexample: takeover succeeds, its reply is lost, then another viewer claims control. Recovery must preserve that newer claim. Repeating takeover or uncertain typing would invalidate the design.

A connection failure means unavailable, not ended. Only execution evidence establishes exit. Copy, Find, selection and scrolling remain local reading actions; their handlers are reachable, while rendered behavior still needs demonstration.
