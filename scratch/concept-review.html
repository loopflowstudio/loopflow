$ lf wave rename ledger books

$ lf repo tracker                  # books create · queued, books name · queued

                                   # the Task's queued create now names pay's Project

Biggest remaining mismatch: a queued tracker create carries a snapshot of the Task's fields.

The Wave-name copy is closed. What is left has the same shape one layer down: a queued create holds the Task's Project as it was when queued, and a later move adds a field action that sends the same value again. Removal now patches the snapshot (retire_wave_in), which works but is the second place that knows a queued payload's layout.

Larger than this work not proposed here

Now

A create stores its field values at queue time. Each later edit queues a field action. Anything that invalidates a stored value must find and rewrite it.

What it would take

A queued create stores only its owner; the drain reads the Task's current fields when it sends, and edits made before the send queue nothing. That changes the tracker drain and every action kind, and touches retry and conflict handling on sent actions, so it is its own Task, not a fix to this one. The branch is right as it stands: QA's second run showed the patched create reaching pay's Project.

Nothing in this pass changes the plan: slice 3 built the previous page's recommendation, QA ran both paths through the CLI, and the remaining rows are wire or Desktop changes already listed for another pass.
