Area reviewed: the whole Task-pause lifecycle, Working-list grouping (Active / Shipping / Paused), automatic verify, and the Task controls that expose them — at c3af825c35 against stack base 43f6d7fb48 (LOO-1063). Verdict — iterate before demo: the core pause hold, OS-session teardown, live primary conversation, and automatic verify line up cleanly. Three real concept mismatches remain in the built code and show up directly on the Working-groups walkthrough: (1) unpausing a paused build turns an intentional stop into a Blocked exit-130 failure while the Graph sentence promises lf task unpause resumes it; (2) TaskState::Paused is missing from SelectionState, forcing a workingGroup == .paused && !states.contains(.idle) hack and leaving pre-demo status overrides that hide the open conversation's Blocked/Error/Busy/Available reports; (3) WorkingGroup::Shipping puts auto == off (stopped before land) and non-landing Graphs (research, pursue) into Shipping.

2. Biggest mismatch: unpausing turns an intentional pause into a crash

When a person pauses a running build, lf itself stops the Graph with exit code 130. Today task_execution.rs has no concept of an intentional stop (only GraphHeld::EXIT is distinguished from failure), so exit 130 becomes TaskExecutionState::Blocked. To hide that while paused, execution_of_latest_graph bolted on an override keyed on status == TaskState::Paused. The second you click Unpause (Mac and iPhone both send plain unpause, run: false), the task_pauses row is deleted, the mask disappears, and the Task turns into a failure. Meanwhile TaskGraph.sentence claims `lf task unpause` resumes it even though plain unpause does not start a run.

Why this is smaller and cleaner: modeling exit 130 in stopped_execution (right next to GraphHeld::EXIT) fixes pause → plain unpause and lf task interrupt with one rule, deletes the hold-only mask on genuine failures (a step that failed with exit 1 before pause stays Blocked after unpause instead of pretending pause caused it), and aligns TaskExecutionSnapshot, TaskActionModel, and TaskGraph.sentence.

4. Third mismatch: WorkingGroup::Shipping misclassifies auto off and non-landing Graphs

The product rule is: Shipping = auto == on, OR no human step left before landing. In the built code, two things slip into Shipping that shouldn't:

Counterexamples checked against the revised model

  • Real failure before pause: step fails with exit 1 → person pauses → person unpauses. Exit code is 1 (not 130), so after unpause the real failure remains Blocked.
  • lf task auto off before landing: Graph stops before land --wait-and-fix with AutoState::Off → sits in Active (needs person's approval), moves to Shipping only once resumed or re-armed.
  • research / pursue Task: no landing step in Graph → stays in Active while running without auto == on, never falsely labeled Shipping.
  • Unassigned started Task paused in Backlog: has working_group: null, carries SelectionState::Paused in states → shows Paused cleanly on Mac and iPhone instead of blank.

6. Choices made for review & work outside this pass

Choices written into scratch/plan.md for the next pass (all reversible):
  1. Show live conversation status (Blocked/Error/Busy/Available) on paused rows, falling back to Paused when silent, while keeping Graph-level condition.need hidden during pause.
  2. Map exit 130 (intentional stop from pause or lf task interrupt) to TaskExecutionState::Idle instead of Blocked, and align TaskGraph.sentence to say lifts the hold vs --run resumes it.
  3. Keep auto == off (waiting before land) and non-landing Graphs (research, pursue) in Active instead of Shipping.

7. Open questions

  1. Clicking Unpause on Mac / iPhone when paused mid-run:
    a) Built & kept for this pass: plain unpause (run: false) lifts the hold cleanly (now without exit-130 error); clicking Run restarts the build — safe when you want to chat first without launching a heavy compile.
    b) Make Unpause send run: true when paused mid-run (and run: false when paused at an interactive step), matching Round 5 V4's ▶ Resume <step> button.
  2. Row status word on a paused Task with an open conversation:
    a) Proposed for next pass: show what the live conversation reports (Blocked / Error / Busy / Available), falling back to Paused when no conversation reports (the Paused group header already marks the hold).
    b) Always print Paused on the row, suppressing live conversation status.
  3. WorkingGroup::Shipping for research / pursue and auto == off before land:
    a) Proposed for next pass: keep both in Active unless auto == on (only Graphs with a landing step past their last human gate are Shipping).
    b) Keep pursue (stops at published PR) in Shipping too; exclude only research and auto == off.
