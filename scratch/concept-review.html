Model, recovery and counterexamples

One declaration: each command names its effects, confirming stages, query dependencies and domain recovery owners. Planning inapplicability comes from that declaration; missing evidence for an applicable effect stays unavailable. Diagnostic text never establishes its owner.

Independent recovery: planning resolution clears only its correlated action. Attachment failure keeps Retry opening for the same Session. Preserve historical diagnostics; unclassified failures stay inspectable. Native owners retain input readiness.

Persistence: save confirmed bases, per-query incorporation and presentation acknowledgment transactionally with the outbox. Apply removal only to lagging queries. Invalidate closed cached queries with required fences so retirement does not require opening every view.

Failure: epoch replacement invalidates old coverage without deleting the original request or replaying it. Supersession of the exact completion restores A only from covering replacement facts. B stays selected.

Required checks: reorder receipt, count and list; restart between them; replace the epoch; withdraw before settlement; resolve planning and attachment in either order. Assert actual membership/counts, no duplicate send and unchanged later selection through both clients. The existing stamp-only test cannot demonstrate these behaviors.

Docs and skills: usage above remains proposed until both clients consume the shared projection. Existing recovery skill instructions need no change. Native latency remains unmeasured and belongs to later benchmarking.
