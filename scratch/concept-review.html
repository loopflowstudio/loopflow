One interaction, including recovery

Proposed: Start A → editor closes, A’s words are selected. Go to B. A files; its Task appears in the list beside the request row. Open A from either row → its conversation, and the request row is gone, also after restart. If the save had failed instead: Try again sends the same request, Edit request returns the words. If the reply was lost: Check request looks up the original on its Machine. If the Session exists but did not attach: Retry opening. None of these moves you off B.

Three smaller findings

Made-up repository. Desktop beginTask freezes repoPath ?? "/" into a command that can never be edited. Proposed: Start needs a resolved repository; otherwise the editor keeps the words.

Retired phone requests keep their words. Every phone creation stays in the outbox table with its full text after retirement, to stop a surviving editor file from submitting again. Proposed: keep the identity and a digest, drop the text, and drop the row once its source can no longer resurrect it.

Still unexercised on Desktop’s production path: attachment failure and Retry opening for a creation, restart after an uncertain send, held Graph admission after filing. Two clients converging on one closed query, the wider mutation cutover and a native latency baseline also remain open.
