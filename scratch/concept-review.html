Do the product and code concepts line up?

Settings brings app preferences, preferences for new work and live connection status into one window. The largest mismatch is in the override lens. The work you’re inspecting and the file you’re editing are two choices.

What survives the edit

Normal path

Shared is On. Turn My setting Off and the next ordinary launch omits the diff. Save Shared Off, then On. Both edits stick in the shared YAML and the launch stays Off. Reset My and the next launch includes the diff. Undo puts My Off back.

Save fails

Preview the reset of My Off, then a hand edit sets it to On. The expected declaration has changed. Apply keeps the hand edit and the reset draft. Refresh shows On; review the new patch before removing it.

If the connection drops during a save, refresh before replaying it. Offer Undo when the window can confirm its own commit.

Move is interrupted

With Shared empty, preview moving My Off to Shared. If the process stops after installing Shared Off, My Off is still present. Resume only when both slots match the recorded move. If Shared has since changed, keep both and show the file that needs attention.

Two cases defeat a single “effective value” control

Append and clear. A shared context.docs: [README.md] and a private [notes.md] combine. The private editor shows only [notes.md]. Explicit [] clears earlier contributions; Reset removes the private declaration and exposes [README.md] again.

Pin and fallback. A shared agent: claude can beat a private default_agent: codex. The private control shows Codex as its saved starting preference. The Agents pane reports Claude as the effective pin using the same resolver as launch.

What a person does and what owns it

Find a setting

  • Yes · config.catalog owns the key, aliases, schema, and policy. Settings owns its label and pane.
  • No · The existing free-form key field leaves discovery and editing in separate controls. Proposed search indexes the same row descriptors as the forms. Editing a boolean result uses the same address and operation as editing its row.

See what applies

  • Yes · SettingScope, SettingTarget and the resolver describe where work runs and which declarations contribute. EffectiveSetting carries the result and its candidates.
  • No · The earlier plan uses Destination as the identity of an inspection. “Scope” then means both the work and the file. Proposed config.scope reads by checkout, Wave and optional target. The read includes all available edit slots; swapping My and Shared needs no new reading.

Save a value

  • Yes · Destination and the typed key identify a declaration. The Rust writer owns canonical YAML and locators. Shared files follow the selected checkout. The private file follows the clone across linked worktrees.
  • No · The current one-key response uses null for both an absent declaration and a YAML null. The projection carries explicit presence. The editor binds to that slot and separately shows what the resolver uses. The tracker remains one tagged value.

Review, reset, move or undo

  • No · The existing window sends config.set or config.unset, then asks Explain what happened. A preview, commit and Undo need one edit description that identifies the affected declarations and expected values.
  • Yes · files::edit, LockedFile and the canonical YAML patcher already own file replacement. Extend that owner. Keep only a short-lived recovery record for a move involving two physical files. Derive the status and sidebar dots from the resulting readings.

Choose or customize a theme

  • No · AppearanceDraft currently holds a theme pick and edited assets in the same chooser transaction. Proposed theme picks commit through AppearanceStore with Undo. The editor holds the draft for a custom theme or import.
  • Yes · The theme: declaration and the theme assets identify the saved choices. AppearanceStore resolves and publishes them to Desktop, Ghostty and the existing iPhone appearance path.

Set autosave or look up a shortcut

  • Yes · taskFilesAutosave is a Desktop preference. The shortcut rows describe DesktopAction and the window commands. Move the toggle and reuse one reference in both Shortcuts surfaces.

Pair a phone or check a Machine

  • Yes · Mobile setup changes access and reports current status; the Machine probe verifies durable identity and distinguishes an ended rental. These are domain operations with existing owners.
  • No · MobileSetup lives inside the old pane. The new sidebar and QR card need the same current status. Lift that reading to Settings and let the Machines pane load reachability independently from placement preferences.

Choices for review
