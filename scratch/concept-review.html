One Machine selection, shared by both apps

Mobile should open an existing Task and let you work in its Session. The repository selection belongs to the Machine: the phone gets its Tasks and creation destinations through desktop.portfolio. Incoming main described that namespace as Desktop-only; the sync keeps Mobile’s shared selection and documents the exception.

Existing
Desktop repository selection
  → desktop.portfolio → Mobile’s New Task destinations
  → view.select       → Mobile’s Task list

Changing Desktop’s selected repositories changes what Mobile can find. The stored selection lives on the Machine, so Desktop need not be running. Keep this shared set. Removing a repository from the selection does not delete its files or Tasks.

Design — shared Machine selection
Machine repository selection
  ├─ Desktop: Tasks, windows and panes
  └─ Mobile:  Tasks → Session → type

One selection, one store, one engine. A headless Machine can configure the same set. Desktop’s pane layouts stay Desktop-only. Proposed API cleanup: move shared selection and Work reads out of the Desktop API namespace; replace their old names together, without aliases or a second inventory.

Walk through failure and recovery

Scan the QR → open a Task → read → Use keyboard → type. Backgrounding closes the attachment. Returning attaches by Session and observes again; it neither starts a provider nor resends input. If the provider has ended, Open Session is a separate action.

During Create & start, lose the network after the Machine accepts the work. Check status uses the saved creation request, even after an app restart. A normal protocol request ID only correlates a response; it is not this creation receipt. An uncertain start must leave the existing Task available for inspection.

What the protocol sync must keep straight
  • The sync aligns Mobile’s call sites with main’s renamed Swift/Rust operations. Keep wire fixtures and callers together; aliases would hide drift.
  • Incoming main used 32 MiB messages. The combined branch keeps 1 MiB control plus shared bulk tickets. Both advertise revision 2, so revision alone cannot establish that an older server implements Mobile’s extra operations. Installation/version behavior still needs the live compatibility check.
  • session.resume prepares an opening command; Mobile’s session.start actually starts the retained owner. Do not equate them just because both return a Session record.
  • Keep current cancellation, subscription completion and request diagnostics. A disconnected client does not imply an admitted mutation was undone.
  • The phone attaches through its one connected Machine. Tasks whose providers run elsewhere need a routing design or a clear explanation; do not label a remote Session as stopped merely because the local owner is absent.
  • Show the real path next: QR → Task → editable Session → background/foreground → server interruption. Older Simulator checks do not establish the synced build’s phone behavior.

Usage draft — proposed

“Select the repositories available on this Machine. Desktop and Mobile show open Tasks from that same selection. On your phone, scan the Machine’s QR code, open a Task, then choose Use keyboard to work in its Session. Closing Desktop leaves the Machine service and running Sessions available.”

Proposed wording, not a claim that the API names have been changed. No skill-instruction changes are needed for this interaction.
