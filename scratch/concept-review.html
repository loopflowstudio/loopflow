3. Counterexamples & recovery paths verified on HEAD

1. GraphOutcome::Waiting (lf pr land handoff) graph.run exits 3 (GraphHeld::EXIT) with "Graph stopped before its last step; inspect its history and effects" (no GraphHeld::BLOCKED_PREFIX). stopped_execution returns Idle, so snapshot.rs still projects Waiting via waiting_to_land.
2. Interactive stand-in returns blocked, then resumes execute() arrives at the interactive step (At { step: "check" }); lf task status shows Blocked with the stand-in's exact reason and no_action. Once the missing artifact is added, rerunning lf task auto on starts directly at check without re-running earlier steps (QA §6).
3. Exhausted structured-output validation after 3 successful turns All worker turns exited 0 while graph.run exited 1 with the validation error. stopped_execution surfaces Blocked with that exact diagnostic; unfinished_step prevents any earlier step limit-recovery record from masking it (QA §7).
4. Step commit push failure during a Graph RunningGraph::commit_step invokes lf commit --step best-effort (logs a warning and continues). Manual lf commit on an unreachable remote keeps the commit local, prints Git's error once via OpsError::PushFailed (served unavailable), and pushes the same SHA on the next lf commit (QA §1, §5).
5. Graph killed without recording an exit graph.run.result() is not Failed, so stopped_execution stays Idle (preserving existing crash semantics), while task_updates reports unknown once after the process dies.
6. arrive_task_graph("end") written before finish_run settled_task_position holds the prior position while run_in_progress is true, preventing an empty wakeup a second before the settled run update (QA §3). Readings saved mid-run by older builds stay compatible and still deliver new comments immediately.
7. lf commit --no-add, reversed edits, and whitespace filenames --no-add with unstaged edits and nothing staged returns committed: false, pushed: false without pushing; staging a working-tree reversal onto a clean checkout pushes any earlier local branch commit. git::has_staged_changes (git diff --cached --quiet) handles literal filename ' ' across whole, selected, and sync commits (QA §5).
8. Swift Desktop client against older & branch servers checkout.commit keeps push: Bool on the wire and only maps !push to --no-push for CLI argv. Headless Swift probe verified compatibility against both installed server 0.16.0+250e266b4 and branch build 9f863ee93 (QA §4, §5).

4. Outside this work (separate outcomes)

  • Cross-skill provider conversation sharing (LOO-435): Reusing one warm provider thread across skills inside a Graph requires provider-specific transcript and cache-boundary design.
  • External repository custom Graphs (e.g. manabot/.lf/graphs/coverage-working.yaml): Benefit automatically from updated builtin skills and quiet Task wakeups; moving heavy reviews into an outer loop is an edit in those repos.
  • PR-less command Graph auto-completion timing: Observed in QA (scratch/qa.html) — the settled run steer says "At end (Task completion is separate)" and a separate "Task completed." steer arrives ~1 s later inside the same woken turn (one wake total). Pre-existing server completion timing, not introduced by LOO-1082.

5. Choices made for review (all built & committed on HEAD)

Nothing remains unbuilt or blocked on an irreversible decision. Every choice below is reversible after merge; the highlighted option is built on HEAD. Reply with e.g. "2b, 3b" if you want to steer any of them.

  1. 1. Quiet task-session during running Graph steps Built & committed
    • 1a Built: Taking up a Graph at start and passing through steps stay quiet for the Task's own conversation (matching conducted children); wake once when a run settles (finished, blocked, failed, unknown exit, interactive stop), PR merges, Task closes/reopens, or a comment/steer arrives.
    • 1b Wake once when a Graph run starts, silencing only intermediate step ticks.
  2. 2. Default-push lf commit on selected paths & clean checkouts Built & committed
    • 2a Built: Branch push default applies uniformly to whole-tree commits, selected-path commits (lf commit -m "…" path), and clean-checkout retries; default branch and detached HEAD stay local; --no-push opts out.
    • 2b Keep selected-path commits local by default (push only whole-tree lf commit).
  3. 3. Telling a blocked decision from a waiting handoff in Task status Built & committed
    • 3a Built: Keep GraphHeld::EXIT (3) for both, distinguish blocked decisions in ops::task_execution::stopped_execution via shared constant GraphHeld::BLOCKED_PREFIX, and surface non-held post-step failures as Blocked while keeping GraphOutcome::Waiting and unrecorded-exit kills Idle.
    • 3b Allocate a separate exit code for GraphOutcome::Blocked instead of matching GraphHeld::BLOCKED_PREFIX (requires updating every caller matching exit 3).
    • 3c Keep project_execution() returning Idle when the last step exited 0, relying on task-session steers and lf history show for the reason.
