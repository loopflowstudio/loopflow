LF supplies a layout.
The host owns what opens.

Decided with you: templates belong in config; Desktop’s sticky Task layouts stay in the database. LF stores no external-host workspace records, including in sidecar files.

Each lf open launches fresh. Returning to an existing workspace is a host action.

One concrete interaction

lf open --task LOO-498
  → current Desktop Task layout, else config template, else builtin
  → detect the current host
  → create a new Task tab and its splits

Rearrange / rename / return → use the host
lf open --task LOO-498     → another fresh Task tab

The existing conversation is viewed, not restarted. A selected Shell tool gets a fresh shell. The Task’s Machine and checkout stay the same. A new Task tab can use the current native container; it need not create another Rex session.

Detect where the caller is

--host wins. Otherwise use an agent’s current attached viewer or the direct caller’s native terminal context. Nested hosts select the inner host. Native APIs resolve the actual container after moves; stale environment and app focus cannot choose another destination.

LF already recognizes Rex, Herdr, cmux and Desktop. The implementation needs shared routing plus fresh layout renderers, including cmux. A selected host’s failure stays visible; it must not silently launch somewhere else. Outside a known host, use the configured/default route.

A lost reply does not create a lifecycle

If the host creates the tab but the reply is lost, LF reports uncertainty and does not retry automatically. Inspect the host. Running lf open again explicitly requests another view. No provider turn is replayed.

Retained Task terminals still need to protect checkout cleanup. That evidence must come from the host and LF’s Session lifetime owner; the rejected host registry cannot return under another filename. This integration and actual native Split behavior remain unverified.
