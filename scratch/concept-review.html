Consequences and failure checks

Presentation: publish removal and next/empty selection before awaiting the store actor, disk or Machine lookup. Save before send. A save failure removes only its layer and shows its error, without selecting again.

Projection: derive membership, visible/suppressed occurrences, attention and counts from one portable selection/group/sort plan over projected display facts. A composed Dashboard can contain repeated occurrences of a Task; subtracting one guessed count or changing only a member array is insufficient. Retained Task conversations stay reachable. Unknown membership remains unknown.

Retirement: a mounted lagging query keeps its ordered effect until a covering base arrives. Closed queries can be invalidated with persisted requirements, allowing finite retirement without opening every view. Keep these obligations in the existing cache/outbox owner. Replace the conservative Machine-wide floor with declared dependencies so unrelated changes cannot blank an unaffected query.

Recovery: supersession restores A only from covering replacement facts. Replacement epochs invalidate comparisons, retain unanswered commands and never authorize replay. Native attachment continues to own input readiness and Retry opening for the same Session.

Required checks: reorder real receipt/list/count bodies across restart and epoch replacement, while B stays selected on both clients. Resolve planning while the list is held; it must stay B/count 1 without a waiting screen. Repeat with two Dashboard occurrences of A, a newly opened filter, an unrelated mutation, save failure and exact completion withdrawal.

Docs and skills: the usage above remains proposed until both hosts consume the shared projection. Existing recovery skill guidance needs no change. Native latency remains unmeasured.
