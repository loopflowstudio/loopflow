2. The biggest mismatch: blocked loops and post-step failures vanish in lf task status

Biggest Mismatch task_updates tells task-session the Graph blocked (or its step push failed) and says "Read current Task status before acting" — then lf task status reports idle, drops the reason, and recommends lf task run.

Without a hard loop cap, LOO-1082's stopping control for non-converging loops is the decider's blocked verdict in DECISION_CRITERIA. Because the deciding skill step itself exits 0 while graph.run exits 3 with error = "Graph is blocked: …", ops::task_execution::project_execution() sees latest.run.result() == Succeeded and hides the stop as TaskExecutionState::Idle. The exact same gap hides a post-step lf commit --step push failure (graph.run exits 1 with OpsError::PushFailed after the skill exited 0).

3. Counterexamples tested against the built + proposed model

1. GraphOutcome::Waiting (lf pr land handoff) graph.run exits 3 (GraphHeld::EXIT) with "Graph stopped before its last step; inspect its history and effects" (does not start with "Graph is blocked:"). Stays Idle in project_execution, so snapshot.rs turns it into Waiting via waiting_to_land.
2. Interactive stand-in returns blocked execute() calls arrive_task_graph so position is At { step }; project_execution now shows Blocked with the stand-in's exact reason and actions.recommended = no_action; ops/task.rs:3559 still allows lf task run / lf task auto on once resolved.
3. Graph killed with no exit record after a step succeeded graph.run.result() is Running / Unknown (not Failed), so project_execution keeps Idle("Graph stopped after <step>…") (preserving existing test a_graph_runs_while_its_processes_do_and_blocks_on_a_failed_step), while task_updates reports unknown once.
4. Completed or abandoned Task with a historical Blocked Graph task_actions.rs:52 returns NoAction("Task is terminal") and waves.rs:2607 explicitly exempts terminal Tasks with Blocked execution from unresolved_execution, so closed Tasks stay settled.
5. arrive_task_graph("end") written before finish_run Built & verified in QA: settled_task_progress checks whether any Task run lacks an observed outcome before returning At { step: "end" }, preventing an empty wakeup a second before the settled run update.
6. lf commit --no-add with unstaged edits & clean-checkout retry Built & tested: --no-add with nothing staged and unstaged edits present returns committed: false, pushed: false without pushing; a clean checkout (including a reverted staged edit) pushes any earlier local branch commit.

4. Outside this work (separate outcomes)

  • Cross-skill provider conversation sharing (LOO-435): Reusing one warm provider thread across skills inside a Graph requires provider-specific transcript and cache-boundary design.
  • External repository custom Graphs (e.g., manabot/.lf/graphs/coverage-working.yaml): Benefit automatically from updated builtin skills and quiet Task wakeups; moving heavy reviews into an outer loop is an edit in those repos.
  • PR-less command Graph completing ~1 s after At end: Observed in QA (scratch/qa.html) — the settled run steer says "At end (Task completion is separate)" and a second steer says "Task completed." a second later (no second wake). Pre-existing server auto-completion timing, not introduced by LOO-1082.

5. Choices made for review

None of these choices are irreversible once shipped. The highlighted option is built on HEAD (questions 1–2) or queued in scratch/plan.md (question 3); reply with e.g. "2b, 3b" to steer any of them.

  1. 1. Quiet task-session during running Graph steps Built
    • 1a Built for review: Taking up a Graph at start and passing through steps stay quiet for the Task's own conversation (matching conducted children); wake once when a run settles (finished, blocked, failed, crashed, interactive stop), PR merges, Task closes/reopens, or a comment/steer arrives.
    • 1b Wake once when a Graph run starts, silencing only intermediate step ticks.
  2. 2. Default-push lf commit on selected paths & clean checkouts Built
    • 2a Built for review: Branch push default applies uniformly to whole-tree commits, selected-path commits (lf commit -m "…" path), and clean-checkout retries; default branch and detached HEAD stay local; --no-push opts out.
    • 2b Keep selected-path commits local by default (push only whole-tree lf commit).
  3. 3. Surfacing GraphOutcome::Blocked and post-step failures in lf task status Proposed next pass
    • 3a Proposed for next pass: Update ops::task_execution::project_execution() so "Graph is blocked: …" and non-held post-step graph.run failures (such as lf commit --step PushFailed) report TaskExecutionState::Blocked with graph.run.error, aligning lf task status, task_actions, lf wave status, and Desktop with task_updates while keeping GraphOutcome::Waiting and unrecorded-exit kills Idle.
    • 3b Keep project_execution() returning Idle when the last step exited 0, relying on task-session steers and lf history show to surface the reason.
