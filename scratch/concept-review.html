What does “until 18:30” promise?

The decision needed: what DigitalOcean is in this PR, given it is the one provider whose machines can outlive a lost laptop.

The interaction

doppler run -- lf ondemand add box --provider aws --vcpus 4 --memory-gb 16 --max 2 --max-usd-per-hour 0.40
doppler run -- lf task run LOO-xxx --rent box
lf ondemand list
  box-1 · running · LOO-xxx · $0.03 so far · until 18:30
# land; 15 minutes later reconcile copies history up and deletes box-1

Recovery path: the laptop dies at 16:00 and never comes back. Everything people were told rests on until 18:30: by then the machine is gone and the bill stops.

The guardian stays out of the vocabulary. People learn one thing, the deadline, and each provider keeps it its own way:

ProviderWho ends it at the deadline
DaytonaDaytona (ttl_minutes)
ModalModal (timeout)
RunPodguardian deletes the pod with RunPod's pod-scoped key
Flyguardian exits; Fly destroys the Machine (the app's IPv4 lingers until lf reconciles)
AWSguardian powers off; the instance terminates
DigitalOceanonly lf's reconcile

The mismatch

Every surface tells the DigitalOcean user the same thing it tells everyone else. lf ondemand list prints “until 18:30”. The scheduled check says “its provider deletes it at the deadline either way” (rental.rs, check). The docs say “Its provider deletes it at its deadline.”

The counterexample: rentals are Machine-local, and the scheduled check reaches a provider only when its key is in the environment. If the laptop is lost, no lf anywhere looks for the Droplet. It bills until someone opens the DigitalOcean console.

Proposed

green = proposed, not built

Each provider says who holds its deadline. Every line that prints a deadline uses that answer, so the promise is either true or stated as the weaker one. Same command, same list, different words where the guarantee differs:

lf ondemand list
  box-1 · aws · running · LOO-xxx · $0.03 so far · until 18:30
  drop-1 · digitalocean · running · LOO-yyy · $0.02 so far · lf ends it at 18:30 (no hard deadline)
// rental/mod.rs
pub enum DeadlineHolder { Provider, Guardian, Lf }
impl Provider { pub fn deadline_holder(self) -> DeadlineHolder { … } }

Smaller ones that follow from the same question, “is what we print true?”:

  • Region is ambient (AWS_REGION, DIGITALOCEAN_REGION, FLY_ORG), but it sets price: EC2 rates are us-east-1 only, so a quote elsewhere is wrong. --region on the on-demand would make the quote true and let two on-demands differ.
  • GPU sizing: with --gpu on RunPod, --vcpus/--memory-gb are silently dropped. Treat them as floors the GPU shape must meet, or refuse them alongside --gpu.

Questions

  1. What is DigitalOcean in this PR?
    1. Left out until it has a guardian. The code stays on the branch; --provider digitalocean isn't offered.
    2. Offered with the weaker promise stated everywhere it prints: “lf ends it at 18:30 (no hard deadline)”.
    3. A guardian with a droplet:delete token, scoped by putting rentals in their own DigitalOcean team.
  2. Region:
    1. --region on the on-demand, with prices per region.
    2. Stay ambient; the quote names the region it priced.
  3. With --gpu, vCPUs and memory are:
    1. floors the GPU shape must meet,
    2. refused alongside --gpu.
