Slice 1 (minors from main) matches the accepted design: no pairing, prepare hooks run, cycle notes from the preceding .0, no leftovers. Nothing to change there.

The mismatch is in slice 2. Every way into Loopflow today resolves GitHub's Latest marker, and each release sets it. So the URL on the website delivers preview, while Jack decided new installs get stable.

One install, end to end

Today 
curl …/releases/latest/download/install.sh | sh
  → GitHub Latest = newest release
release_publish --finalize
  → gh release edit --draft=false --latest
A new user gets a release that is hours old.
Proposed (recorded as next direction) 
curl …/releases/latest/download/install.sh | sh
  → GitHub Latest = stable pointer
release_publish --finalize
  → gh release edit --draft=false --latest=false
daily release run
  → gh release edit <stable tag> --latest
    (forward only)
Same URL, now soaked 7 days. preview = newest published tag.

Actions → concepts → APIs

install fresh         stable   GitHub Latest marker (existing URLs)
lf install --preview  preview  newest non-draft release tag
lf install --dev      dev      Packages (main) artifact (#1755)
release a version     release  lf release run patch|minor  → preview only
soak passes           stable   daily run moves Latest forward
regression filed      Task     regressed_in holds stable back (slice 3)

Each pointer is only a tag; the package carries its reader catalog. No stream manifest file.
