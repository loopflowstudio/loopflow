Signing Machines in, as built: do the concepts line up?

LOO-957 with the whole change in it (HEAD 6777c85270, against main): four slices, the reach set from the first as-built review, its compress and QA. Area taken: everything a person touches to get any Machine signed in to any provider: lf machine login / logout / logins, approvers.<provider>, ondemands.<name>.logins and rental prepare, the launch check, and --refused. existing is on this branch; nothing here is proposed: this pass changes no plan.

The interaction, walked once

A rental from a template with no --logins. This Machine is signed in to Claude, GitHub, Linear and Doppler.

  1. lf --rent code -a claude implement. Prepare reads lf machine logins here, keeps what reaches another Machine (rental::sign_in_order): GitHub, Claude, Linear. Doppler is skipped, not failed.
  2. GitHub transfers first (the clone needs it), Claude asks for a paste, Linear renews and sends. The step launches; _run_signed_in probes Claude on the rental and finds it signed in.
  3. Failure: the Claude login was revoked later. The next launch there reads signed out before the agent starts and stops with <rental> has no Claude login; run `lf machine login claude <rental>`, named as the launching side calls it.
  4. Recovery: that command, or lf machine login claude --refused for every Machine in the same state. Nothing is recorded; the probe and the refusal rows say who needs it.

The edge from the first as-built review: lf machine login asana mini now refuses before any SSH with "Asana signs in on each Machine itself; run `lf machine login asana` there", and lf ondemand add --logins asana refuses at add, not at rent.

Biggest mismatch: none left in this area

Before (first as-built review)
"Every provider" meant eight in the parser and prepare's default, five in the dispatch, and the true set lived in a stale bail! string. A default rental died before cloning when this Machine had Doppler.
Now
One predicate, one refusal at the command, one filter in prepare, one check at ondemand add. The stale string is gone. Test: machine_commands::services_that_sign_in_here_only_never_reach_another_machine, rental::tests::a_rental_signs_in_once_to_each_provider_that_reaches_it_github_first.

Smaller, not for this change

  • Headless --rent with no command approver fails prepare on Claude's paste (and gives the rental back) even when the step runs on Codex. Recorded behavior; a headless renter sets a command approver or --logins. A check before renting would save the minutes of rental; it is a new precondition, so it is left out.
  • Codex with no approver in a batch run opens this Machine's browser and waits up to 15 minutes for a person who may not be there.
  • Rental prepare's sign-in loop has no end-to-end fixture; the PR says so.
