3 · A dead run keeps the button

Normal: click Update tour, the pane reads "Writing the tour… · its output: …/tour.log", the file lands with a new at, the order switches to Tour.

Failure: the run starts and then dies (no harness selected, a spent limit). The pane reads "Writing the tour…" and offers no button. The store lives as long as the app, so it stays that way until you quit. The same happens when a rewrite lands with the same at, or none.

No served read reports a launched run ending, so the pane cannot know. It stops pretending to: the wait ends when the file's content changes, and once the launch has answered the button is offered again beside the log path. The cost: a second click during a healthy run starts a second run that rewrites the same file.
