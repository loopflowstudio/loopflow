3. Concrete interaction walkthrough (normal, failure & recovery)

  1. 1. Normal Click identifier → gd → return: Open src/main.rs (it remains visible in both Open & Scratch and Changed in Task with +2 −1). Click render_total on line 6: AppKit allows drag-select/copy as before, FileJumps.target records ("src/main.rs", 6, "render_total", range), and render_total shows a subtle accent underline. Type g then d: DesktopActionMonitor sees Files in .read with a non-editable responder, runs task.files.symbols, opens the 2-entry peek, jumps to line 9, and ⌘[ returns to line 6.
  2. 2. Normal Present from a zoomed Session + in-place HTML rewrite: The conversation pane is zoomed full-screen. Agent finishes a report and runs lf desktop files scratch/explore.html. Desktop clears Session zoom while keeping keyboard focus in the terminal, opens explore.html rendered in Read beside the conversation. Agent rewrites explore.html twice: WebKit settles 800 ms, reloads once keeping scroll, and does not nag Updated scratch/explore.html · Open because it is already on screen.
  3. 3. Normal Passive write to another scratch file while editing: Switch to src/main.rs in Edit (editable NSTextView is first responder — typing gd inserts the characters gd into code, never triggering jump!). Agent updates scratch/notes.md: a dismissible layout row Updated scratch/notes.md · Open · × appears above the editor without covering code. Click × to dismiss it; the blue dot stays in Open & Scratch until opened.
  4. 4. Failure Narrow pane (240 pt) or duplicate hits on one line in Grep: Resize the pane to 240 pt: browserTabs scrolls the active Files tab into view instead of clipping it away. Search total in ⇧⌘F Grep: two hits on src/main.rs:6 highlight their distinct matched spans inside each excerpt, and selecting a hit at column 400 on a minified HTML line scrolls the preview to reveal it.
  5. 5. Recovery Presented during Edit, then leaving Edit: While editing src/main.rs, agent runs lf desktop files scratch/report.html. Because the Files pane is visible and in Edit, Desktop adds report.html to Open & Scratch and shows Presented scratch/report.html · Open · ×. When you switch back to Read and open another file (or click ×), the banner clears instead of lingering at the bottom of the window, while report.html stays one click away in Open & Scratch.

4. Choices made for review

All three are reversible and recorded in scratch/plan.md and scratch/questions.md. Reply with e.g. 1b or 2b to steer.

1. Legacy lf open --file command
  • 1a Chosen: Delete lf open --file (open/files.rs, desktop::present_files, old tests). Zero callers remain outside its own test file, every skill uses lf desktop files, and lf open returns to being strictly cross-host conversation opening.
  • 1b Keep lf open --file as a thin compatibility wrapper over lf desktop files.
2. lf desktop files when another pane (Session) is zoomed
  • 2a Chosen: Unzoom the other pane (zoomedPaneId = nil) while keeping focusedPaneId on the terminal so the presented file actually becomes visible beside the conversation without stealing keyboard focus.
  • 2b Leave Session zoomed and silently keep the presentation hidden behind it until the person manually exits zoom.
3. Update & presentation banner lifecycle
  • 3a Chosen: Separate persistent rail dots in Open & Scratch from one ephemeral, ×-dismissible layout banner (never overlaid on bottom lines, suppressed for the file already visible in Files Read, cleared on file switch/Edit exit, shown on Diff only for deferred presentations).
  • 3b Keep the persistent bottom overlay bar without dismissal until the offered path is opened.
