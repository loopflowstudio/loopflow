A Task step on any harness, as built

LOO-974 after six slices and QA on real OpenCode 2.2.1 and Pi 1.3.0, read against its base (e55f40bd) as someone meeting it for the first time. The area is the same one the first review took: how a Task step gets its agent, what that agent may do, what happens when it cannot start or cannot finish, and how anyone can tell the four harnesses behave alike.

Outcome: the plan changed. The design held where it was built: the permission rule has one name and one owner, OpenCode is launched the way Claude is, and a missing harness is passed over or named once. What does not line up yet is the thing the Task exists to deliver. "Parity" is written down as a table whose own rule is "a test or a named gap in every cell", and five cells are neither. One of them, Pi usage, is a deliverable the brief names. The plan gains one slice, 7, with three parts.

One interaction, walked

A Task's implement step runs on OpenCode with Gemini 4 Carbon. Normal path, seen in QA: the step settles with a commit, a steer sent mid-step changes what it writes, usage is in lf history usage --task, and the Graph stands at its next step. The failure worth walking is the one the docs now promise a recovery for: the agent asks a question and nobody is there.

Built

$ lf task run LOO-12 -a opencode:opencode/gemini-4-carbon
OpenCode asked a question with nobody there to answer it:
Which database should the migration target?
The run of code failed (attempt 1 of 3); starting it again at implement.
OpenCode asked a question with nobody there to answer it: …
The run of code failed (attempt 2 of 3); starting it again at implement.
OpenCode asked a question with nobody there to answer it: …
The run of code failed 3 times; this Task run stops here.

Assembled from the message strings in harness/common.rs and commands/graph.rs; the three attempts are what a_question_with_nobody_there_ends_the_step runs (72s for that reason).

Each attempt is a new conversation and a full model turn up to the question. docs/orchestration.md says "answer with lf steer LOO-12 "…" and run again"; the person gets to do that only after the model has asked three times, possibly in three wordings.

Proposed

$ lf task run LOO-12 -a opencode:opencode/gemini-4-carbon
the run of code stopped at implement on a question:
Which database should the migration target?
Answer with `lf steer LOO-12 "…"`, then `lf task run LOO-12`.

$ lf steer LOO-12 "the staging replica"
$ lf task run LOO-12
implement settles; the Graph moves to its next step

One ask. The answer is a steer, which the next run's conversation reads at its start, the way slice 6 already reads one back on every stand-in.

Questions

The marked option is what the plan now does. A number and a letter is a complete answer.

  1. A Pi worker's usage sits on a second turn row.
    1. Join it to the recorded turn that covers it, in the transcript read. (chosen)
    2. Name the Pi turn after the session file's user entry.
    3. Leave the cell "no" and file it.
  2. A worker asks a question with nobody there.
    1. Stop the run after one attempt; the stop prints the question and lf steer / lf task run. (chosen)
    2. Keep three attempts.
    3. Hold the step open and wait for a person (a new Graph stop; not this Task).
  3. The interrupt row on Claude and Codex.
    1. Run the test on all four, fix what it finds, rename it. (chosen)
    2. Leave "not shown" and rename only.
  4. The question row on Claude and Codex.
    1. "no: not read"; the orchestration doc's sentence names OpenCode and Pi. (chosen)
    2. Record both CLIs here and build what they need.
  5. Driver::send_current.
    1. Left alone here. (chosen)
    2. Delete it in this Task.
    3. Keep it: same-turn input is coming back.
  6. The Task's conversation when its first agent is not installed.
    1. Does not move; fails with the install hint. (chosen, unchanged)
    2. Moves down the order like a step.
  7. The "no" cells with no Task (Pi limits, idle wake on OpenCode and Pi).
    1. The cell states the cause; nothing is filed by this Task. (chosen)
    2. File one Task each and name it in the cell.
