The biggest mismatch

Nothing in the product answers "what is this Dev build looking at, and can it read it?" before the window opens. Kickoff answered by removing the question: always a copy. That fixes the empty window and takes away the live path that works for Swift-only branches.

Kickoff's plan

BranchDev opens
Swift onlyRead-only copy. No terminals, no changes.
Changes wire or schemaRead-only copy.

One behavior. Terminal work and anything interactive moves to fake worlds for every branch.

After review

BranchDev opens
Swift onlyThe Machine, as today.
Changes wire or schemaRead-only copy, with the differing types printed.
--copyRead-only copy, on request.
--world dirA fake world.

Two outcomes from one command, told apart in one printed line. The comparison errs toward the copy.

Outside this work

A copy's window does not say it is a copy until a change is refused. A standing label, with change controls off the way they are while the Machine is away, needs the sentence on the wire. welcome and status reject unknown fields, and a field added there breaks the lf inside every running Session at the next install, so it takes a new read instead. Left as question 3.

Questions

  1. What should run open?
    1. The Machine when the branch speaks its wire and schema, a copy otherwise. (in the plan)
    2. Always a copy. One behavior; Swift-only branches lose live terminals and real changes in Dev.
    3. Always the Machine, stopping with the difference printed. Wire-changing branches get fake data only.
  2. Can the copy be changed?
    1. No. Read-only; interactions on a wire-changing branch are tried in a fake world. (in the plan)
    2. Yes, and thrown away at the next run. Drags and creates work on the real backlog. It needs what lf clone had: pids, routes and tokens scrubbed and a sandbox around real worktrees.
  3. Should a copy's window say so all the time?
    1. Not in this work; the sentence appears when a change is refused. (in the plan)
    2. Yes: a standing notice and disabled change controls, through a new read.
  4. Restored windows from another Machine:
    1. The app drops them; a window names its Machine. Saved windows are lost once. (in the plan)
    2. The launcher passes -ApplePersistenceIgnoreState YES; covers launcher starts only.
  5. The word:
    1. Copy. (in the plan)
    2. Snapshot.
  6. lf server status from a branch build:
    1. ready when the server answers; the executable is a fact beside it. (in the plan)
    2. Exec the installed lf to answer, as lf install server does.
