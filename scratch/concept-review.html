Implement one shared interaction model across Desktop and mobile

Next step: confirmed cache + ordered operation overlays + a transactional outbox. This is the headless implementation direction, not a recorded product preference. No unanswered product choice stops implementation.

Decision for implementation: distinguish an operation being retained for recovery from its effect still applying to a query. A fresh count must not subtract a completed Task again while a lagging list still needs the overlay.

Biggest mismatch: each screen currently decides when a command, a refresh and navigation have finished. Stamped reads now exist, but do not yet reconcile shared facts. The proposed store makes local intent visible everywhere before I/O; Machine facts confirm it later. Native readiness still controls input.

Try to break it

Normal: a receipt binds the operation to real IDs. Each affected query keeps its effect until a complete reading covers the commit fence. Stop applying the effect to fresh queries while retaining it for lagging ones. A current no-Graph result restores ordinary Task controls.

Failure: completion refusal removes only its overlay and restores membership from the latest base. Success followed by refresh failure keeps pending confirmation. Attachment failure shows Retry opening beside Inspect, using the same Session.

Recovery: save before send; restart loads outbox layers before cached lists. Lost replies look up the same operation on its original Machine. Uncertain execution is never blindly replayed.

Counterexamples: A completes, then is reopened; A→B→A replies reorder; expand→collapse finishes loading late. Preserve the later intent. Unrelated revisions, partial pages, native readiness and old Task frames cannot retire an operation.

Shared-cache counterexamples: list revision 12 arrives before detail revision 11: keep the newer title. A fresh count incorporates Complete before a held list: do not subtract twice. A filtered list drops a Task: retain its entity and open workspace. An old frame arrives after epoch reset: keep the new base and recover uncertain operations without resending.

What changes underneath

Built: revision-6 stamped reads and immediate Wave/repository selection. Proposed: shared store, receipts and client migration.

One store in swift/Loopflow owns normalized facts, ordered projections and transactional persistence. Rust supplies durable command receipts, commit fences and complete query stamps. Desktop and mobile share reconciliation and membership semantics; routes keep selection and drafts; native owners retain execution and input control.

Delete creation-only ledgers, per-action pending maps and duplicate cache/freshness owners as consumers move. Preserve saved requests, exact Session identity and domain recovery. Validate one membership vocabulary and GRDB support on both toolchains before adoption.

Keep revision provenance on normalized fact groups and incorporation on each affected query. Filtered absence changes membership, not entity existence. Epoch changes invalidate old comparisons; pending operation identities survive for receipt recovery.
