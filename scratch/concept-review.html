The biggest mismatch left: who answered

Before this change a Session never changed provider by itself, so “the provider an input was sent to” and “the provider that answered it” were one fact. A move splits them, and only the first is written down. The built fix reads the second off the Session, which is right for the step that just ran and wrong once the Session has moved again.

Built 
captured row:  payload.provider = codex   (sent to)
               turn_thread      = T2      (answered on)
Session:       provider         = claude
               provider_thread  = T2

answered by = T2 is the Session's thread ? claude : codex

Normal: step 1 moves to Claude, step 2 reads step 1's answer from ~/.claude. Seen live.
Failure: the Session later moves to a third thread. The old input reads as codex again and its transcript “is gone”. Read from the SQL, not run.
Recovery today: history's copy of the answer.

Proposed, not built 
captured row:  turn_thread   = T2
               turn_provider = claude   (written with turn_thread)

answered by = turn_provider

One additive column on session_events, written where turn_thread is. The CASE in input_answered_turn goes; old rows fall back to payload.provider. A migration and its fixtures: its own Task, not this one.

Verdict on the build

The rule a person holds, “when the provider says no, the next agent in my order takes it”, has one order, one loop and one flag behind it, and it was watched working against a refused Codex account on six entry points. Nothing found here asks for a change inside this Task. The plan is left as it stands.

Larger than this work

  • A turn_provider column, above.
  • The stop advice guesses at a pin. True advice needs the launch to carry how its agent was chosen (pinned, ordered, an existing conversation), or one sentence that only lists what was tried.
  • Three refusals move; a timeout or a missing CLI does not. “My order is tried in order” would be a simpler rule. It changes Graph steps too.
  • Pi and OpenCode never move.

Questions

  1. A Graph run in the foreground (lf -b research) with its whole order refused:
    1. waits 5, 15, 30, 60 minutes, as built (and as a Claude-led one did at base);
    2. stops at once; only a Task's Graph waits.
  2. After a move, the Session shows:
    1. the agent it is on, for model moves too;
    2. as built: the new provider and model after a provider move, the first model after a model move;
    3. the agent it was started with, always, and the current one kept elsewhere.
  3. Codex's refusal, now that the field is seen on a live one:
    1. keep both readers, field and folded text (built);
    2. field only for Codex, and read modelNotFound and unauthorized from it too.
  4. lf commit with no agent left to write the message:
    1. prints why and commits as lf commit (built);
    2. stops without committing.
  5. A commit-message agent that times out or returns no message:
    1. stops there (built);
    2. moves to the next agent, for every caller of the loop;
    3. moves for one-shot copy only.
  6. A headless turn sent to an existing conversation that is refused:
    1. stops; a conversation keeps its provider (built), with advice that fits;
    2. moves through the order like a new launch.
