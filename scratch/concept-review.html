Return cancels cleanup before the next sweep.

Design refinement; no open product choice. The accepted return rule already requires this. The proposed repair changes when pending closure loses permission, while keeping the one-minute Machine sweep.

The mismatch

The sweep queues shell closure and exits. A Task Session viewer returns. Before the next sweep, the shell owner can still consume the old request and end its jobs. The checkout survives; the shell state is lost.

Current source: viewer recording updates only the Process. Cancellation lives in retirement reconciliation. The shell owner's Ending::confirm accepts close_requested=2 when owner_retiring still finds closing. Existing return tests reconcile before checking the result.

Actions → concepts → APIs

Complete and leave → retirement record → finite sweep
After fifteen minutes absent, task retire queues owned closure. SQLite keeps progress and retry state; later passes finish interrupted work.
Return → Session viewer → record and revoke together
Proposed repair: recording renewed viewing also cancels that Task's queued retirement closes. Passive viewers count. Owners recheck current Task retention before consuming automatic closure.
Reconnect → same shell receipt → attach
Local and SSH connections reattach without replaying startup. Desktop supplies integration resources only on creation. New Shell creates fresh execution.

Recovery stays the same

One surviving passive viewer retains the checkout. A brief return and leave starts a new absence window. Explicit Close still ends the shell; Undo restores identity and history. Already-ended execution cannot be revived by cancellation. Ordinary shells grant no hold, and LF never closes Rex-owned shells.

Proposed usage correction: “⇧⌘T restores the last closed tab's identity and history. Close ends its shell and jobs; New Shell starts fresh execution.” The old Desktop README sentence promises a still-running shell.
