Evidence, tradeoffs and recovery limits

ViewerTerminal::preview writes terminal bytes; it does not reconstruct the provider’s editor. Native draft persistence has not been demonstrated. TURN_LIVE protects open tools, but pending input without an open tool does not hold an unviewed owner; native callback paths differ.

Two minutes trades memory for startup/auth delay. A preview does not establish input readiness. resume --all selects viewed owners with no recorded exit; clean shutdowns and unviewed work are excluded. Missing work snapshots favor preservation and may retain an agent longer. A failed or incompatible snapshot can omit the preview; provider history remains separate.

Next proof: detach/resume a distinctive unsent draft and a pending native request; edit or answer the same interaction. Check slow/failed startup without replay. Full twenty-return, permission-wait, gate and installed acceptance remain outstanding.

Accepted promise — 1a and 2a

“Closing a Session keeps unfinished input and pending questions intact. Only a fully settled Session releases its agent.”

  1. What happens to an unsent draft? 1a. Preserve it as editable input. Recommended.
    1b. Promise only submitted history; a draft may be lost.
  2. What happens to a pending approval or question? 2a. Keep the same request answerable. Recommended.
    2b. Allow it to expire; returning may require asking again.
