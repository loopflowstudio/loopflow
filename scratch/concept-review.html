One placeholder is still two. The Dashboard tile kept its own.

The seventh pass's residue is gone: a Task's panes follow its state and the person's choice, two tests cover the finished cases, and Rust carries one opening intent end to end. Reading the Dashboard again, the tile for a Task with no conversation attached renders its own view, DashboardConversationOffer, with its own copy and its own opener. The pane for the same Task renders the shared placeholder, whose button is labelled by what Rust can do next. Where the view is chosen should say nothing about what the state is. Marked proposed below; everything else exists in the working tree. These findings come from reading the code, not from running it.

Counterexamples that held

  • A tile must not leave the Dashboard when its button is pressed; the zoom control is the way into the Task. dashboardTileOpensConversationInPlace protects it, and the proposal keeps it: only the button's route changes.

  • An unstarted Task never reaches a conversation placeholder in pane or tile: both render TaskStartOffer.

Settled here

Implemented November 5 (see the plan): the Dashboard tile renders the shared placeholder, note and button; openConversation(in:store:) for a Task workspace that is a visible tile and not the selected Work clears its error and re-enters the warm opener for that key; DashboardConversationOffer and attachTaskConversation go. The two tile tests move to the shared open-conversation identifier and Retry label, plus one case where a finished tile without history shows Rust's Start label after its refused reveal. This is what the sixth pass's “one placeholder serves every Work” and the accepted “preserve explicit Start as recovery” already imply; no new product choice.
