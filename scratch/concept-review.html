LOO-1083 review at HEAD (92a63266e7) against base 62a368e5cc, 2026-11-24. Area taken: opening, watching, acting on, and recovering a Task's workspace (Files, Changes, Diff, Save, Shell, Session, and Task actions) when another Machine owns it across CLI, Desktop, Mobile, and lf server. Slices 1–7 and four QA passes are committed; this review evaluates the whole built area as it stands at HEAD.

built at HEAD marks behavior committed at 92a63266e7. proposed marks Slice 8 in scratch/plan.md, closing the last two cross-Machine boundary leaks before gate.

What holds at HEAD (Slices 1–7 + QA7 fixes): lf server is the single cross-Machine router (PeerPool, protocol rev 10, portable Task selectors). task.files.watch follows the Task record before its checkout exists (waiting for .git) and recovers across moves and server restarts. session.resume and session.new route by Task ahead of moved_session, localize remote SessionRecords (task_ids[0], work.id, workspace.task_id, open_argv, action.help, outlook.command, status_line), and lf session list --task routes to the owner. CLI lf open --task / --machine honors -a <harness> through session.resume and session.continue and rewrites detach/leave lines to lf open …. Desktop Files, Changes, Diff, Save, Shell, and Session follow owner transitions, keep drafts by (Task, path, base revision), keep running shells on their starting Machine, show remote standing via ownerStanding, and omit duplicate Browser strip context. Mobile exposes Session, Files, Changes, and Shell over the existing single pairing.

Two concrete interactions where HEAD still breaks the model

1. Peer-local paths & UUIDs leak out of routed Task readings (breaking Mobile Run/Auto and Desktop completed-Task retention)

A Task runs on mini (whose repo path is /workspace/manabot and whose tracker-backed local Task UUID is task_peer; on laptop the repo is /Users/jack/src/manabot and the Task UUID is task_laptop). The person opens it on the paired iPhone and taps Run or Auto on, or opens a mini-run Task in Desktop.

built at HEAD Only session.list is localized

mini answers task.get / task.status / task.detail: row.task.repo = "/workspace/manabot" (mini's path!) row.task.id = "task_peer" (mini's UUID!) row.runtime.work_id = "task_peer" row.reference.workspace.machine_label = mini's own name detail.current_session = unlocalized SessionRecord (lf resume …) subscriptions.rs patches ONLY task.files.watch's machine_label outside Read::localize_peer_reading(). What breaks: 1. Mobile TaskWorkspaceView.swift:178 reads row.task.repo from task.get → sends task.run { directory: "/workspace/manabot", issue: "MTG-421" } → laptop's Write::Remote::new runs Selection::capture("/workspace/manabot") and forward::read("/workspace/manabot") → doppler current_dir ENOENT! Repo config, participant name, and forward.env secrets fail on laptop. 2. Desktop WorkModel.taskRecords (WorkModel.swift:3179-3180) checks row.id == id && repoIdentity(row.task.repo) == repoIdentity(repoPath) → rejects subscribedTaskRow when a remote Task leaves the plan. 3. Desktop opens a Task only mini ran: openSelectedWorkspace() runs openWarmConversations() while subscribedTaskRow is .loading (awaitsStart=true), then .task arrives (WorkModel.swift:1790) and updates subscribedTaskRow WITHOUT calling openWarmConversations()!

proposed One localization boundary for every peer reading

Read::localize_peer_reading(body, machine, route) owns ALL peer readings (both one-shot read_with and peer subscriptions; delete subscriptions.rs's separate labels_owner patch): • task.get / task.status: /task/id, /row/task/id, /row/runtime/work_id → route.task_id /task/repo, /row/task/repo → local repository_path(&route.repository_id) /row/reference/workspace/machine_label → machine.label (keeps /row/reference/workspace/worktree as mini's checkout path!) • task.detail: /task/id, /task/repo → local; /current_session → localize_remote_session • task.files.watch: /machine_label → machine.label; /task_id → route.task_id • session.list: localize_remote_sessions (already in place) Write::Remote::new (matching read.rs::peer_of): • resolves local_dir = repository_path(&repository).unwrap_or(change.directory()) before Selection::capture(&local_dir) and forward::read(&local_dir) Desktop WorkModel.swift:1790: • calls openWarmConversations() when subscribedTaskRow changes

2. Reset session loses its reply on a remote Task (infinite 5 s recovery loop)

The person clicks Reset session (plus.bubble) on a Task owned by mini. session.new runs on mini and writes mini's creation_receipts, then SSH drops or the laptop server restarts before the reply reaches Desktop.

built at HEAD creation.get & inspector stay local

Desktop ~/.lf/submissions/<id>.json holds: { kind: "session.new", request_id, id, task: "task_laptop", … } Every 5 seconds, CreationRecovery.refresh() runs: 1. CreationSubmissions.reconcile asks laptop: creation.get { request_id } 2. Laptop checks ONLY laptop's creation_receipts → returns null 3. reconcile resends session.new → routed to mini → mini deduplicates and returns the new SessionRecord → reconcile discards the reply 4. reconcile asks laptop creation.get AGAIN → STILL null 5. throws "The Machine has no receipt for creation <id>" → permanent error Notice + SSH resend every 5 s forever! Even if creation.get returned mini's receipt: • session.new writes task_id: null in creation_receipts • RecoveredCreationInspector falls into local-only session.history.get → "Session not found", never calling presented() to retire the file!

proposed Route creation.get by task (rev 10, zero migration)

Read::CreationGet { request_id, task: Option<String> } (still rev 10): • CLI: lf server receipt <request-id> [--task <task>] --json • Read::workspace_task_mut matches CreationGet { task: Some(issue), .. } → routes to the Task's owner through the exact same PeerPool path CreationSubmissions (CreationJournal.swift): • extracts optional "task" from record.payload and passes it to lookup → Desktop calls .creationGet(requestID: id, task: task) • lost reply → mini returns Complete receipt (no infinite resend!) • mini crashed at milestone='stopping' → mini returns Inspect (no resend!) • mini unreachable → unavailable naming mini (no resend!) CreationRecovery (CreationSubmissions.swift): • Resource.task = receipt.taskId ?? (payload?["task"] as? String) • RecoveredCreationInspector reads routed .taskGet, shows the Task & new Session, and calls presented() to retire the saved submission.

The biggest mismatch: the server boundary localizes Sessions, but not Task readings or creation receipts

Slices 6 and 7 established the right rule for SessionRecords: the local server translates peer-private IDs and commands at one boundary so clients never see another Machine's internal coordinates. At HEAD, that rule stopped short of task.get, task.status, task.detail, task.files.watch, and creation.get. Result: Mobile sends mini's filesystem path back to laptop's Write::Remote::new (breaking Doppler/config forwarding on task.run), Desktop discards subscribedTaskRow once a remote Task leaves the plan and misses warm-opening when mini's standing arrives, and a lost reply to remote Reset session loops forever every 5 seconds.

Before (HEAD at 92a63266e7)

  • localize_peer_reading handles only session.list; subscriptions.rs patches task.files.watch separately
  • task.get / task.status / task.detail leak peer repo path, peer Task UUID, peer's own machine_label, and unlocalized current_session
  • Write::Remote::new reads Selection::capture & forward::read from caller's change.directory() instead of local repository_path(&repository)
  • WorkModel updates subscribedTaskRow on .task without calling openWarmConversations()
  • creation.get is local-only → remote Reset recovery loops every 5 s with "The Machine has no receipt", and RecoveredCreationInspector calls local-only session.history.get
  • WorkNavigationTests/retainedRepositoryConversation fails because its mock answers other's Task resume after taskLocation deletion

proposed After (Slice 8, still rev 10, zero migration)

  • localize_peer_reading is the single owner for task.get, task.status, task.detail, task.files.watch, and session.list (mutating only present keys; keeping workspace.worktree as the owner's checkout path)
  • Write::Remote::new captures Selection and forward from local repository_path(&repository) (falling back to change.directory()), matching read.rs::peer_of
  • WorkModel calls openWarmConversations() when subscribedTaskRow changes
  • Read::CreationGet { request_id, task: Option<String> } routes by task via workspace_task_mut; CreationSubmissions passes payload's task; CreationRecovery falls back Resource.task to payload's task so the inspector reads routed task.get and retires the submission
  • WorkNavigationTests/retainedRepositoryConversation mock answers only --repo

    1. route creation.get by the saved payload's task selector (still rev 10, zero SQLite migration; handles lost reply, mid-reset crash, and peer outage) proposed for Slice 8
    2. add a new local SQLite table mapping request_id → machine_id so recovery still targets the original peer even if the Task moved during the 5 s outage
  2. When a Task moves to another Machine while open in Desktop, its Session pane:
    1. retires the old Machine's viewer and automatically re-opens the moved Session on the new owner when the Task is visible built at HEAD
    2. retires the old Machine's viewer and shows an explicit "Open conversation" placeholder until clicked

    1. starts lf --interactive --task … in a routed shell tab on the owning Machine (zero local checkout) built at HEAD
    2. disables the action for remote Tasks until a dedicated remote secondary-Session operation exists
