Biggest mismatch (closed in slice 4): "who a steer wakes" is written twice. The server decides whom to start in read_steer_wakes (a join: COALESCE(p.session_id, task_primary_sessions.session_id), not a Task update). The started conversation decides whether to take its steers in take_steers_to_start, with a second SQL predicate over unread(), which also applies the source-replacement and "shared steer already read before this Session started" rules the first one skips. When they disagree, the server starts a Session that takes nothing: a resumed Claude waits for input, never reaches its Stop hook, so the idle wake never lists it, and it sits at its prompt in a held terminal with the steer still unread. One rule, one place: the start set should be "Sessions a new steer touches, for which take_steers_to_start's rule holds".

One interaction

  1. A person quits lf : after "remember the word mango". S is interactive with no live AgentProcess.
  2. lf steer S 'what word?' prints Saved …; the Machine server starts S to read it and returns.
  3. The watcher's reading moves (steer_revision); read_steer_wakes reads past the cursor, sessions_to_start drops live ones, hold runs continuing(S) in a held terminal.
  4. resume_session_with_env asks take_steers_to_start(S); the steers become the first input; Claude answers. QA saw KIWI, MELON.
  5. lf resume S attaches to that terminal.

Failure. The start never runs a turn (a trust dialog it is killed at; a resume of a thread Claude never wrote, exit 1). The steers read delivered: they were taken when the prompt was built. Nothing starts S again for them. Recorded in questions.md as the same trade -b steer makes.
Recovery. None from lf for those steers; the person reads them in lf session steers S and steers again. A steer saved while S was running that S never read before quitting is recovered by the next lf resume S, which takes it as first input.

The recommendation

Before 
read_steer_wakes:
  steers past cursor
  JOIN agent_sessions ON
    COALESCE(p.session_id, primary(p.task_id))
  WHERE interactive AND not delivered

take_steers_to_start(S):
  EXISTS(unread(S) AND
    (p.session_id=S OR primary-of-task(S)))
Two rules that mean the same thing today and can drift; only the second knows applicable.
Proposed 
fn names_unread(session) -> SQL   // one predicate
  unread(S) AND (p.session_id=S
    OR non-update Task steer AND S is primary)

read_steer_wakes:
  candidate S from steers past cursor
  WHERE interactive AND EXISTS(names_unread(S))

take_steers_to_start(S):
  EXISTS(names_unread(S))
A Session the server starts is, by construction, one that takes a steer. A storage test saves a steer the old join would start for but applicable excludes, and checks nothing starts.

Questions

  1. The start set and the take rule.
    1. One predicate, built in this Task (chosen).
    2. Leave both; they agree today.
  2. A start that never runs a turn leaves its steers delivered.
    1. Keep (chosen; same as -b steer).
    2. Take them claimed and stamp at the first UserPromptSubmit; needs a claim that doesn't lapse in 15 s.
  3. A steer read past while its Session ran, then the Session quit.
    1. Wait for the next lf resume (chosen).
    2. Derive "needs a start" from unread named steers newer than the Session's last AgentProcess start, polled each UNSIGNALLED tick; drops the cursor table but wakes old pending steers on upgrade.
  4. Rename "Run" in this branch's new text to "worker"/"batch" now (built in slice 5), or with LOO-924's rename?
