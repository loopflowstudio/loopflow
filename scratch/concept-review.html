LOO-1067 · Pre-Implementation Concept Review

Do the Task inspector’s concepts and the code’s concepts line up?

Reviewing the proposed redesign before writing code. No code was changed; findings below were written into scratch/plan.md.

Area reviewed: The Task inspector pane (Brief | Diff | Files), its checkout-reading RPCs (lf task files|file|changes|diff), file presentation (lf open --file & watchers), focus/key routing (DesktopActions), and line review (ReviewDiff).
Why this whole area: Files, Diff, and Brief share one 1,811-line store (TaskFilesStore), one comparison slot, one comment queue, one watcher, and one shortcut layer. Redesigning Files without fixing those shared seams would bolt new features onto broken ownership.
Existing Current code on branch base Proposed Revised design now in scratch/plan.md Choice for review Bold call made for headless Graph; reversible before/after build

2. Biggest mismatches — before & after

3. Concrete interaction walkthrough (normal, failure & recovery)

  1. 1. Normal Find & jump on a remote Linux checkout: Press ⌘P (handled by DesktopAction). Desktop calls task.files.find once; checkout has 1,400 files (< 2,000), so Desktop caches paths and fuzzy-filters locally at 0ms. Arrow down previews an unopened Rust file without changing open files or jump stack. Press Return → opens in Read (zero NSTextView allocated). Local Tree-sitter builds outline and updates breadcrumb › render.
  2. 2. Normal Cross-file ⌘-click + comments across Read & Diff: ⌘-click reconcile. Desktop checks open-file AST + calls task.files.symbols (Machine pre-filters via grep-searcher, scans 4 matching files, returns 2 declarations with enclosing names). Inline peek shows both; pick #2 → pushes prior (path, line) onto jump stack, opens file #2 at line 40. Click line 40–41, write comment (Source.file). Switch to Diff, pick Step 2 (DiffReviewState updates; workingChanges, scratch, and the Read comment stay untouched!), comment on a removed line (Source.diff). Press ⌘↩ → one message inserts both with accurate sources into conversation input.
  3. 3. Normal Edit + passive scratch burst + explicit presentation: Return to Files, press ⌃⌘E to enter Edit (lazy NSTextView created), type 5 chars (unsaved draft). Agent rewrites scratch/explore.html 4 times during a turn. Both local/remote watchers pass the gitignored scratch event without running git diff; rail badges explore.html and shows Updated scratch/explore.html · Open; caret, draft, and focus stay untouched. Later, while focus is back in the conversation terminal, agent finishes and runs lf open --host desktop --file scratch/explore.html → opens immediately in Files Read (keyed by .id(path)), pushing prior file onto jump stack, leaving draft & undo intact and terminal focused.
  4. 4. Failure Broken git base or slow/disconnected remote peer:
    • Missing base commit: task.changes fails with changesError, but task.files.find still returns checkout paths and scratch/ — Files stays browsable and scratch pages remain visible.
    • Remote disconnect while editing: Draft stays in TaskFileDocument.text and persists in WorkFileDraft; Files shows Refresh to reconnect without discarding edits or undo.
    • Stale out-of-order search/preview reply: Generation + query + checkout guards discard late replies; typing stays responsive.
  5. 5. Recovery Reconnect & return: Click Refresh → watcher reattaches, reconcile 3-way merges any disk changes into the retained draft (preserving caret if editor exists), and ⌘[ steps back through jump history — then falls through to Desktop window Back once the Files jump stack is empty.

4. Choices made for review

All five are reversible and recorded in scratch/plan.md. Reply with e.g. 1b or 4b to steer.

1. Cross-file symbol declarations on the owning Machine
  • 1a Chosen: Keep one Tree-sitter runtime (Desktop’s 28-grammar XCFramework for open-file outline, enclosing symbol, and live same-file defs). Run cross-file task.files.symbols on the Machine with pure-Rust grep-searcher pre-filtering + comment/string-aware declaration scanner. Keeps lf lean and fast on ARM; wire DTO is identical if AST is ever swapped in later.
  • 1b Compile tree-sitter + 7–8 C/C++ grammar crates into Rust lf for AST-level cross-file lookup on remote Linux peers, accepting ~15–25 MB binary growth, longer non-incremental builds, and dual grammar pins.
2. CLI subcommands for checkout search
  • 2a Chosen: Peer verbs matching lf task file|files|changes|diff: lf task find (task.files.find), lf task grep (task.files.grep), and lf task symbols (task.files.symbols) — one verb, one JSON schema.
  • 2b Overload lf task files with mutually exclusive --index, --grep, and --symbols flags.
3. Read / Edit / Diff mode scope
  • 3a Chosen: Per-file view mode (every newly opened file starts in Read; toggling Edit on one file survives peeking at another file in Read; Read always renders current draft text if dirty; Files’ Diff steps only within that file).
  • 3b One global mode across all open files in Files, resetting to Read on every file switch.
4. ⌘[ / ⌘] when Files owns focus
  • 4a Chosen: Register files-back / files-forward in DesktopAction: pop Files’ jump stack when non-empty, fall through to Desktop window Back/Forward when the jump stack is empty.
  • 4b Keep ⌘[ / ⌘] strictly for Desktop window navigation (matching embedded web pages) and bind Files jump back/forward to ⌃- / ⌃⇧-.
5. Explicit lf open --host desktop --file while actively typing in Files’ Edit editor
  • 5a Chosen: When focus is in the terminal, Brief, Diff, or Files Read, present the file immediately (pushing prior file to jump stack, never stealing terminal focus). Only if the person is actively typing/composing in Files’ Edit editor, add it to Open & Scratch and show a calm Presented <path> · Open bar so keystrokes are never interrupted.
  • 5b Always switch the Files pane immediately on explicit lf open --file, even while typing in Files’ Edit mode (relying on draft retention + ⌘[ to return).
