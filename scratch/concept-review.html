4. Choices made for review, minor edges, and deferred checks

  • choice made Position-aware task.unpause { run: true }: --run and app Unpause resume only runnable automatic positions; at ship-review, land (auto: off), or end they lift the hold and return null. Keeps the wire shape minimal and removes stale-client review-skip hazards. Explicit lf task unpause && lf task run remains the way past a human step.
  • choice made WorkflowAction::Wait for auto: off landing stops: Dedicated waiting action keeps Auto and Start from… enabled while disabling primary ▶ so it never bounces off stopped_landing().
  • minor edge Three small copy/UI rough edges (do not change the model): (1) lf.rs:1445 prints It waits for you at its step; `lf task run <id>` continues past it. for every non-resuming unpause --run, which is exact at ship-review but generic at an auto: off landing stop (where lf task auto on continues) or at end; (2) task_pause.rs:53 run_refusal always names plain lf task unpause <id> even when TaskGraph.sentence names lf task unpause --run; (3) PendingChanges.pauseRequest(for:) checks change.answer == nil, so there is a single-frame gap between RPC reply and the next taskWork frame, and the disabled icon during Pausing… draws play.fill instead of pause.fill.
  • Named PR limits (outside LOO-1078): Separate-session Codex 0.171.0 tool jobs (osPid: null in app-server); a pause first issued in the narrow window after a move payload is sent and before the destination checkout exists.
  • Deferred to walkthrough / gate / CI: Clicking the live Mac Dev bundle’s pill (display was in use during QA); post-merge interrupted verify against a real GitHub merge; five-harness worker matrix, Linux session enumeration, and full Swift/Rust suites in gate/CI.
