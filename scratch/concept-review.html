Does the pane tell you when you can continue?

LOO-1064 reviews Desktop Session opening, resuming and recovery. A Session keeps the conversation. A provider thread can run in a new process. A pane can reconnect to the held terminal while the provider keeps running.

A past resume looks like a live connection state

After a provider resumes its saved thread, the pane prints the same event twice. The strip already names the provider and reports its activity. The terminal can take input, yet one message uses a row and the second covers the first terminal line.

On a later reconnect, the stored event can still say “Resumed in a new process” while the relay says “Same process.” The first describes what the provider did earlier. The second describes what the viewer just reattached to. Put provider changes in lf session history <session>. Use the pane’s message to explain why input is paused and what can bring it back.

Open the Task, lose the connection, rejoin

  1. 1. Resume the saved thread

    Opening… Input paused.

    Desktop prepares the conversation with lf resume --prepare. A retained screen can appear before native readiness. A connected relay still shows Opening during that gap.

  2. 2. Continue typing

    Claude · Available
    The tests are ready.

    Native readiness enables input and restores requested focus. The message clears in place and the terminal keeps its geometry.

  3. 3. The bridge stops answering

    Reconnecting… Input paused; last screen may be stale.

    The pane retains its last screen and pauses input. The relay can reconnect to the held provider, so the draft and buffered output can survive the interruption.

  4. 4. Retry or refresh if it stays paused

    Session unavailable. Input paused; last screen may be stale.

    Retry connection asks a reachable relay to reconnect. If the status channel is gone, Refresh session opens a replacement viewer for the same Session. Once it can accept input, the message clears. A retired or replaced terminal reports why it ended.

A saved screen and an “Available” program report can both appear before native readiness. Keep input paused until the relay confirms both connection and readiness. If a provider transcript is missing, opening can start from the first request. Keep the existing launch diagnostics, the earlier history and the new thread’s recorded transition. A late disconnect after orderly close must leave the ended reason visible.
