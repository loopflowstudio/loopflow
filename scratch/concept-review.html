The biggest mismatch: a checkout's base

A person knows one thing: "this checkout builds on that branch." lf sync and lf pr open should agree on it. They don't:

Asked in orderlf sync (run_sync_in)lf pr open (publication_base → pr_target)
Task stackyesyes
loopflow-baseyes, unless its PR mergedyes, unless its PR merged
upstream naming another branchnoyes
elsemainmain

The upstream clause is the earlier attempt at --stack, and the plan already rejected the upstream as a record ("a branch upstream is overwritten by every push -u"). It is worse than stale: lf's push (push_with_upstream_if_needed) sees an upstream set and runs a bare git push, which with an upstream of origin/parent either refuses (Git's default push.default=simple, names differ) or, with push.default=upstream, pushes the child's commits onto the parent. Its only production reader is pr_target; WorktreeState's Serialize is used by one test.

Now (f07ab065)
git branch --set-upstream-to origin/parent
lf sync        → merges main
lf pr open     → PR targets parent;
                 push goes to origin/parent
                 or is refused
Proposed
one answer, checkout_base(repo):
  Task stack's live parent
  else loopflow-base, unless merged
  else main
lf sync and lf pr open both ask it;
the upstream clause and
WorktreeState.base_branch go

Counterexample checked: someone stacking by hand with --set-upstream-to (only worktree_list_preserves_namespaced_upstream_branch does) loses a publish target whose push was already broken. lf wt create --stack is the way to say it now, and LOOPFLOW.md names it.

Not proposed: putting the taskless base in the store. The checkout has no Task, so task_checkouts can't carry it, and Git config travels with the branch on this Machine, the same as loopflow-persistent. Two records for "a Task's base" and "a branch's base" stay, under one reader.

What holds

Every Task fact has one home, and the leaving guard covers each slice. Membership keeps three path matches, each about what occupies a directory now. --stack writes one Git config key and nothing in the store.
