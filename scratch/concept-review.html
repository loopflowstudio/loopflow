The biggest mismatch: remote Session identity & preparation writes still split across two rules

Slice 6 added localize_remote_session and QA3 added SessionsStore.preparationWork so Desktop could reopen and switch agents on peer-born Sessions. Together they exposed three leaks in the boundary: (1) localize_remote_session appended this Machine's Task ID at the end of task_ids and left work.id and workspace.task_id holding the peer's local SQLite UUID, breaking tracker-backed remote Tasks (like MTG-421) on reopen, switch-agent, and menu actions; (2) work_route::forward matched moved_session ahead of explicit --task, stripping the Task route and downgrading open_argv / help to --machine; and (3) Reset session (Write::SessionNew, sitting right beside Refresh in the Session strip) still calls prepare_session(remote) with remote always None and has no task selector on the unshipped rev 10 wire.

Before (HEAD at 45b450065a)

  • localize_remote_session leaves task_ids[0], work.id, and workspace.task_id as the peer's private Task UUID
  • Write::SessionResume with id: Some + task: Some on a moved Session loses route in work_route::forward → rewrites open_argv / help to --machine instead of --task
  • Write::SessionNew has no task field and is skipped by Write::remote() → clicking Reset session on a remote Task runs locally on the Mac
  • WorkspacePanesView.showsContext prints a duplicate Files title in the Browser strip after a move

proposed After (Slice 7, still rev 10)

  • localize_remote_session puts route.task_id first in task_ids and rewrites work.id (when kind == "task") and workspace.task_id (when non-null) to route.task_id
  • Write::remote_session handles both SessionResume and SessionNew, resolving explicit task first so Task-addressed Session writes always carry route (translating peer_selector in run_here and localizing replies with --task)
  • Write::SessionNew gains required-nullable task: Option<String> in rev 10; Desktop resetSession passes preparationWork just like prepare and switchProvider
  • WorkspacePanesView.showsContext returns false for any Task .browser pane

Outside this review (separate scope)

  • Git observation lag on peer reads: lf task changes right after an edit reads mini's shared observe.rs cache (a few seconds). Existing server-wide observation design.
  • Skewed peer executable message: when a peer's server runs a different binary, Connection::open_peer times out at 10s instead of surfacing lf server connect's stderr. General peer-handshake diagnostic.
  • Two-window sidebar selection highlight: when a stale restored window shares a repository with a live window, sidebar highlight drift is pre-existing Desktop two-window behavior (desktop.md).
