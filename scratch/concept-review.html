Before

The repository itself says one Wave: after a pull both Machines have one .lf/wave/design/. Each store says its own: the laptop's design and mini's design have different ids, and the index allows one. Slice 5 widened the window: it deleted the hub read before a create, and --wave design for a Wave this Machine has not seen makes one (as on main; the second review's page said it would fail until lf task sync, which was wrong).

The last QA pass kept the rest of the plan crossing by skipping what cannot be written. That was right for everything else and wrong for what it skips: no line, no retry.

After (slice 6, in the plan)

Making a Wave looks first. Where a command is about to make a Wave row (lf wave create, --wave on a create), one exchange by each carrier, five seconds at most, the look a claim already makes. Online, the second Machine finds the first one's Wave and uses it.

What was not taken is on the line and is read again. The import returns what it skipped. A carrier that skipped something keeps its read cursor (the ref's tip, the hub's watermark) where it was and records why in plan_carriers; lf repo tracker and Desktop show N not taken with the reason and the command that fixes it; lf task sync exits 1 with it. The next exchange after the rename takes everything.

Passed over for this work, and larger than it: joining the two Waves. One name is one Wave, so the import would make it so: the Wave with the higher id is retired and its Projects and child Waves move to the other, all through fields that are already stamped (WaveRetired, ProjectWave, WaveParent), so every Machine computes the same join; register_authored_waves already rewrites a config.yaml whose id is retired to the live Wave of that name. It would delete "not taken" for Waves outright. What it would take: deciding what a Wave with two first Projects looks like (nobody made the second on purpose), what happens to the retired Wave's Sessions on its Machine, and children of the same name under both (the join recurses). That is a product decision about Waves and Projects, not about carriers. Question 1.
