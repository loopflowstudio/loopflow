The area: the route a provider's refusal takes through a headless Graph step, from what the provider says to what a person reads in lf task status, with the whole LOO-977 change in it (base 7bb879aff4, head 48dd78f7d0). The biggest mismatch

The branch made the cause a typed value everywhere inside, and then the one place a person reads it shows the wire spelling. docs/troubleshooting.md now carries a table teaching five event codes, one of which (provider_rate_limited) means "usage spent" while Codex's own rateLimitExceeded is something else and untyped.

Built

implement went on under claude after: provider_rate_limited: You’ve hit your usage limit. Upgrade to Pro (…) or try again at 3:36 PM.

Names the provider it moved to, not the one that refused. The reader learns provider_rate_limited, provider_model_unavailable, provider_credential_invalidated, provider_capacity, codex_error.

Simpler not built

implement went on under claude after: codex usage limit: You’ve hit your usage limit. Upgrade to Pro (…) or try again at 3:36 PM.

The refusing agent, AgentFailure's own words, then the provider's sentence. The docs table loses its code column.

Recommendation: not in this change. The reason is the step's stderr, and stderr is {code}: {message} because the text classifiers, release.rs and a wide set of tests read that shape. Building the line from the failure and the message means AgentProcessResult carries the provider's message beside failure, which is the first half of the typed-error work below. Before this branch the same slot read codex_error:; the kind of word shown has not changed, only which one. Passed over: stripping the code prefix in _failure_reason, which parses lf's own stderr to undo what drive.rs just wrote.

Smaller, in the order they would bite

  1. Stop advice outside a Graph. _limit_stop_advice tests launch.fallback_agents; it is handed rungs, the order the run could walk, and rungs.len() == 1 is the true case. What it takes: a third wording for "only Graph steps move", or letting other headless work walk the order (docs/config.md says it "stops at once").
  2. A missing Codex login. One more row in error_code, reading an object variant: httpConnectionFailed with 401 → provider_credential_invalidated. It is new behavior on evidence from one qa run with an empty CODEX_HOME.
  3. The Session's agent is written after the replace, not with it. replace_session_agent_process commits, then record_session_agent opens a second transaction. A store failure between them leaves the new AgentProcess under the old provider (the state that failed the demo) and the runtime holding the old attachment. What it takes: transfer.replace_agent takes the provider and model, and record_session_agent goes.
  4. release.rs still reads words. CommandError carries no AgentFailure. It now shares subscription_limit_text and has no list of its own.
  5. From qa, outside this area: a stopped lf -b graph leaves its step waiting out the limit; a failed Codex step prints a second Error: line of raw JSON.
