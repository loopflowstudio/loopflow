The biggest mismatch · before → now

Before, at ee5392a9: a retained Desktop error surface could suppress retry as already open; focus could claim usable.

Implemented now: view identity answers where; its owner answers pending, ready or failed. Failed attachment permits retry. Pending attachment suppresses a competing launch. Receipt revisions keep an old failure from settling a new request. These readings use existing owners, with no new persisted lifecycle.

One command through recovery

lf open --task ENG-123 --host desktop

  1. Normal: resolve → attach → report ready. Later Desktop navigation focuses the pane; terminal opening reports its location and offers --focus.
  2. Failure: return the attachment error and retain diagnostics. Correct the cause and repeat the command: retry the same Session in its retained Desktop pane, without replaying consumed input.
  3. Counterexample retained: a timeout can leave attachment running. Recheck it on retry; pending means wait, ready means report the view. Missing provider history still requires the existing deliberate resume action.
