Lifecycle check: normal, failure, and recovery paths

Before

Before LOO-1109 (base e9a802c003): each review skill hand-wrote its own HTML, CSS, and optional JS; review pages were read-only artifacts in Desktop or static files on disk with no way to comment on prose or diff hunks, no live connection beside Rex, and no shared theming or component overrides.

After

At 94cb44c203: every review skill writes a body-only *.page.html compiled by lf page build with real hunks, checked SHAs, validated data-lf operations, and one runtime that delivers the exact same one-line reply from a loopback browser dock, Loopflow Desktop's ReviewCommentsStrip, or offline clipboard copy.

  • Multi-line diff range + prose note + ⌘↩: Dragging across prose spanning inline <code> opens the floating pill (Comment (c) · Flag · Copy); clicking + on line 6 and Shift+click on line 10 of an <lf-diff> opens a range composer anchored above or below the whole range without obscuring lines 6–10. Both appear in document order in the Comments sidebar and as removable chips in the browser dock (or in Desktop's ReviewCommentsStrip beside Diff comments) and format onto one line on ⌘↩.
  • Server restart mid-review (lf install): The open tab detects WebSocket close, shows Loopflow server disconnected — run lf page open <path>, and switches to Copy reply ⌘↩ while keeping all drafts and receipts. Running lf page open mints a fresh 32-byte token on the same deterministic per-socket port, so the reopened tab lands on the same browser origin and restores every unsent note, line range, choice, overall direction, and Filed … receipt.
  • Confirming a data-lf action, then clearing drafts: File Task now confirms inline, executes with a per-confirm request_id (reused on retry), and turns into Filed <ID> without adding a chip to the dock or an item to Desktop's strip. Clicking Clear calls clearDrafts({ markReported: false }), so [already ran: task.create → <ID>] still rides once on the next ⌘↩ reply.
  • Desktop file switch, rebuild, and peer Machine: Switching from scratch/ship-review.html to a Swift file unmounts TaskHTMLView, while ReviewComments keeps pageStates and items in Swift. Sending from the code file inserts page notes + Diff comments on one line, retains receipts marked reported: true, and bumps pageClearGeneration; returning to the page restores receipts without resurrecting sent notes. Rebuilding the page bumps build_id and drops stale drafts from the prior build.
