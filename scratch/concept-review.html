Biggest mismatch

"Nobody is there to answer" is one product idea implemented as three harness-specific floors plus a Task-checkout override. Under the kickoff plan (keep floors, delete checkout rule) a person who writes yolo: false to keep their prompts in conversations would find headless Codex Task steps in workspace-write with no network: no crate fetch, no PR, no ~/.lf writes. Same setting, different meaning per harness.

before four ideas

  • yolo setting
  • per-harness headless floor, reading vendor config
  • Task-checkout forces yolo when headless
  • commit text forces yolo

~240 lines in agent/mod.rs:420-660 plus run.rs and session.rs branches.

proposed one predicate

  • default flips to true
  • skips = yolo || headless, one function on AgentConfig, asked by every harness
  • floors, vendor-config readers, checkout rule and commit override deleted

Lost on purpose: yolo: false no longer gives headless Codex outside a Task checkout a workspace-write sandbox. A codex.sandbox setting would be its own Task.

First slice

Flip the literal, add the predicate, route every harness through it, and extend harness::launch_matrix and launch_policy_tests.rs to the four cells on every harness. A path that still asks under headless shows a second rule. Deletion and docs follow. Full detail: scratch/plan.md.

Questions

  1. What does yolo: false do to an unattended run?
    1. Nothing: unattended never asks (chosen; in the plan).
    2. Keep per-harness floors; headless Codex gets workspace-write, including Task steps (kickoff plan).
    3. lf sends nothing at all; the vendor's config decides even headless.
  2. The headless Codex sandbox that 1a removes:
    1. Gone; containment is a Machine/VM/container (chosen).
    2. File a codex.sandbox setting as its own Task now.
  3. Turning yolo off for one launch:
    1. --setting yolo=false; --yolo stays as the override for a configured false (chosen).
    2. Add --no-yolo.
    3. Drop --yolo; it is the default now.
  4. Should attended launches say anything about bypass being on?
    1. No; each vendor shows it (chosen).
    2. One line in lf's terminal before handing over.
