A Session and the view someone is at, as built

Area taken: everything that decides whose terminal a running Session is shaped for when several views show it, with the whole branch in it (base e804e652f5 to fe01f87c23): the holder's sizing rule, the relay, the lf commands that start a view, Desktop's panes, Loopflow Dev and the phone. Anything marked proposed is not built; everything else is in the branch.

The answer

The model holds, and the mismatch the last review found is gone. Desktop runs the server's command as given and marks its pane with LF_RELAY_FOCUSED=0; QA opened a Dev pane with the installed 0.16.0 lf, which rendered and took typing.

What is left is the route that fix replaced. --prepare --unfocused still writes the flag into open_argv, the SSH prefix still carries it, and lf session attach --unfocused -- still parses it. Nothing calls it. Its output is the command that failed before:

$ lf --version
lf 0.16.0+7127b9d0d
$ lf session resume <id> --unfocused
error: unexpected argument '--unfocused' found

The biggest mismatch: two ways to say "this pane starts in the background"

Before (built)

  1. Person: lf resume X --unfocused
  2. Host: LF_RELAY_FOCUSED=0 in the pane
  3. Host, second way: ask for --prepare --unfocused and get an argv with the flag inside, as … resume X --unfocused or lf session attach --unfocused -- ssh …. Run by an lf from before the flag, it is a usage error and no pane.
  4. Wire: focused

After proposed

  1. Person: lf resume X --unfocused
  2. Host: LF_RELAY_FOCUSED=0 in the pane
  3. Wire: focused
  4. A prepared argv never mentions focus. Whoever runs it says where it stands, through its environment and its TTY.

What goes: the push in session.rs, the parameter and inserted flag in ssh.rs prepared_remotely, the --unfocused -- arm in lf.rs, and the background assertions in machine_commands.rs. What stays: lf --machine … resume --unfocused for a person, whose local relay reads the flag while the remote command never sees it.
