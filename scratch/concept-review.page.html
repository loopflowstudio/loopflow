Biggest mismatch: Making loop criteria "fallback-only" dropped the non-convergence stop

Walk a failing build run on HEAD where Pass 2 does not cleanly fix Pass 1's review finding:

  1. Pass 1: concept-review flags an API mismatch. realign writes Pass 2 into scratch/plan.md and returns iterate.
  2. Pass 2: implement edits the code, misses an edge case, and advances. concept-review re-reviews the branch and flags the same conceptual mismatch again.
  3. realign runs on Decision pass 2 (or 3, or 4). Because Loopflow intentionally has no pass cap in rust/loopflow-execution/src/graph, the only circuit breaker is the decider returning blocked when passes repeat without converging.

Now read what 7d0554d112 put into DECISION_CRITERIA and realign.md:

Tells any skill with its own loop section (realign, implement, optimize-plan) to skip the defaults below. The only non-convergence stop in the system now lives inside that skipped fallback block. realign's own blocked rule covers only irreversible design choices — nothing stops a spinning fix loop.

docs/orchestration.md mirrors the same mistake, describing the non-convergence stop as default-only:

Why this happened: Two distinct concepts were lumped together in DECISION_CRITERIA:

  • Step-specific progress criteria (what earns advance vs iterate — e.g. "substantial next pass" by default, "any in-scope implementation fix" in realign, "next credible hypothesis" in optimize-plan). A skill's own rules must win here.
  • Universal loop safety (blocked when passes repeat without converging, make no progress, or repeat a failure with nothing learned). Because Loops have no hard pass cap, this invariant must hold for every decider — including realign and implement.

Before (HEAD)

DECISION_CRITERIA puts all three bullets behind "If the skill gives its own loop decision rules, follow those. Otherwise use these defaults."

realign.md lists blocked only for irreversible design choices.

Failure mode: When a small fix fails to converge across passes, neither the runner suffix nor realign.md tells the decider to stop.

After (universal stop + skill-specific progress)

DECISION_CRITERIA splits the two: skill rules govern advance/iterate and skill-specific blockers; blocked on repeating passes without convergence, zero progress, or repeated failure always applies.

realign.md's blocked bullet names both irreversible design choices and repeated passes that fail to resolve the same finding; docs/orchestration.md states the stop applies to every decider.

Result: Pass 1's small fix still iterates cleanly, and a spinning Pass 3+ still stops with a clear reason.

Built today (narrowed Q2 b)

User-doc fixes skip concept-review and documented_commands, leaving stale "No" rows on scratch/concept-review.html.
