Loopflow's Diff beside T3 Code, Kaleidoscope, VS Code and the AI review tools

Loopflow's Diff now reads about as well as the good hand tools on a mid-sized change, and it has one thing most of them lack: your own always-hidden paths. It falls behind in three places. It can't mark what you've read, it sends one selection at a time to the agent, and it shows files in path order when the AI-native tools have started ordering by what matters.

"Loopflow" here means the uncommitted LOO-515 build. The files panel, filter and hidden paths are built and tested headless but have not been seen on screen yet. T3 Code facts come from its source at one commit; Codex app facts come from third-party write-ups.

Three families, three different jobs

Diff readers: Kaleidoscope, VS Code

Built for a person comparing two things carefully. Their craft is in the reading: layouts, word-level emphasis, moved code, stepping change to change. They know nothing about who made the change or how to answer it.

Agent workbenches: T3 Code, Conductor, Codex app, Claude Code desktop, Zed, Rune

The diff sits beside a conversation, and the point is the round trip: read, mark lines, send the marks back to the agent. Reading craft is thinner than the dedicated readers. Loopflow belongs to this family.

AI reviewers: Devin Review, GitClear, and the PR bots

They change what you are shown: related hunks grouped and ordered, files ranked by risk, renames folded into one row, bugs flagged in place. They work on a published PR, not on a working tree that is still changing.

Rune chatreviewchanges gathers what one chat changed, net of anything later undone, into one diff in a floating window. It never consults Git. most original The diff is a real editor buffer. The AI reviewers

Devin Review

Groups related hunks and orders them to read top to bottom, each with an explanation, where GitHub lists files alphabetically. Detects moved and copied code. Flags in three colors: probable bug, warning, FYI. A chat that knows the codebase sits beside it. Opens by swapping github for devinreview in a PR URL.

GitClear

Sorts every file into a tier and offers a depth slider (Essential, Focused, Careful, Complete); at low depth only the risky files open. Folds a rename into "find/replace ×41". Labels moved code with its source. Marks files read as you scroll past them, then shows only what changed since. Labels which lines a model wrote. Its "29% less review time" is the vendor's own number.

CodeRabbit, Cursor Bugbot, Greptile, Graphite's reviewer and Claude Code Review are a different thing: they read the diff for you and post comments on the PR. They leave the diff itself looking as GitHub draws it. Searches turned up nothing on how they present a change, only detection benchmarks run by competitors.

Where Loopflow stands

Ahead, or level with the best

  • Saved hidden paths. None of the four has one for a Git change. GitHub's nearest is linguist-generated, which is shared and committed, not personal.
  • One honest scope. What you read is what the PR will be, uncommitted work included. VS Code makes this hard; Rune and Codex default to something narrower.
  • One key through the whole change, level with Kaleidoscope 7.
  • Delivery state with ages on the same page as the diff.
  • Moved blocks collapsed to a row, level with VS Code and the AI reviewers within a file.

Behind

  • Nothing remembers what you've read. T3 and GitClear both also notice when a read file changes again. With an agent still writing, this is the gap you would feel most.
  • One selection, no comment. T3, Conductor, Codex, Claude Code and Rune all let several remarks collect and go as one message.
  • Path order. The first screen of this Task's diff was Rust settings code and scratch/, with the Swift that mattered last. Hiding helps; ordering is what Devin Review and GitClear do about it.
  • No syntax colors and no way to see more context around a hunk. Every other tool here has both.
  • No pause while the agent writes, and no keep/reject per hunk.

Two things were checked less well than the rest. T3's lack of a path filter is "not found in the files read", not a confirmed absence. Rune's site renders only with JavaScript, so its account comes from the docs in its repository.

Questions

  1. Read marks. (a) Mark a file read when you step past its last change, and show it again as Changed if it moves, as T3 and GitClear do. (b) Leave it; the position counter is enough.
  2. Several remarks, one message. (a) Comments on lines that collect and send together, as T3 and Claude Code do. (b) Rune's way: make the diff editable and send the edited diff. (c) Keep one reference at a time.
  3. Order. (a) Stay with path order plus hiding. (b) A cheap rule with no model: source before tests, tests before generated and lock files, largest real change first. (c) Have an agent group and order the hunks with a line on each, as Devin Review does, and mark it stale when the head moves.
  4. Reading aids. Which first: (a) syntax colors, (b) expand the context around a hunk, (c) neither yet.
  5. Scope. Per-turn was dropped. (a) Keep the single branch scope. (b) Add "since I last read", which read marks would make possible and which answers the same need without tying the diff to a conversation.
