What each order is

  • Tour. A small YAML file in scratch/ that lists files, top first, each with an optional line of why. The Diff puts those files first in that order; every file it doesn't name follows "By kind". The worker writes it, and you can edit it by hand. 
    first:
  - path: swift/LoopflowMac/TaskFileDocument.swift
    why: A change over 1 MB no longer loses its last files
  - path: swift/LoopflowTests/TaskFilesTests.swift
  - path: swift/LoopflowMac/Views/TaskChangesView.swift
    why: Paths you hide stay hidden
  - path: rust/loopflow-execution/src/config/files.rs
    why: The private settings file moves under .lf/
hide:
  - path: docs/
    why: Path literal renamed, nothing else
  - path: rust/loopflow/tests/
    why: Same rename in 4 test files
    first can't lose anything: an unnamed file is only ever lower down, and a file the worker adds later appears after the named ones. hide can, so it is drawn differently from your own hidden paths: the sidebar lists what the worker hid and why, the title still counts those files, and one click shows them. It applies to this change only and never touches your diff_hidden.
  • By kind. A fixed rule, no model: source, then tests, then docs, then generated and lock files; largest change first within each. This is what you get when no tour exists or it is stale.
  • By path. Today's order.

Questions on the combined pane

  1. Stream or one file. The panel keeps the continuous stream beside the sidebar. (a) Keep it. (b) One file at a time, as B showed.
  2. Which order first. (a) Ship "By kind" with comments and the sidebar, add the tour after. (b) Wait for the tour. (c) Tour only, no rule.
  3. Where the tour's words go. The "why" lines are optional in the file. (a) A heading in the stream and a group in the sidebar, as shown. (b) Sidebar only; the stream stays plain. (c) No words at all, only the order.
  4. What the worker's hide does on open. (a) Hidden from the start, listed in the sidebar with its reason, as shown. (b) Shown but folded shut in the stream, so nothing is out of sight. (c) Only suggested: a row offering "Hide docs/ · rename only" that you accept.
  5. The file's name. (a) scratch/diff-order.yaml. (b) A section of scratch/plan.md. Either way it is cleared with the rest of scratch when the PR is submitted.
  6. The parts left out. Any to bring back now: (a) read marks, (b) syntax colors, (c) pause, (d) depth slider, (e) folded renames, (f) none.

The three originals

A. Review, then send once

Borrowed
T3 Code and Claude Code desktop: comments collect on lines and go to the agent as one message. T3's read marks that notice new work.
True here
The Diff is where you write your review. Comments stay pinned to their lines until you send; files you've read fold away and come back when the worker touches them.
Demo
Read three files, leave four comments, press Send. The session's input holds one message with all four, each naming its file and lines. The worker edits a file you'd marked read; it reopens showing only what changed.
Cost
About a week. Comments and read marks need storing per Task and re-anchoring when lines move, which is the hard part: change ids here are line-anchored today. Risk: a comment silently pointing at the wrong line after an edit above it.

C. Shown in the order that explains it radical

Borrowed
Devin Review: related hunks grouped and ordered with a line on each. GitClear: a depth slider, renames folded to one row, lines needing real attention counted.
True here
The worker that made the change also writes its reading order. You open the Diff to chapters, not files: what each one does, which hunks belong to it, and how much is mechanical. Path order is one click away and never goes.
Demo
Open the same 44-file change. Four chapters. "Essential" shows two of them, 9 hunks. The fourth says "Path literal renamed in 9 files ×14" and stays shut. The worker pushes; a banner says the tour is one commit behind and offers to redo it.
Cost
Two weeks or more, and the only one that spends tokens on every change. Needs a Graph step that writes the tour beside the diff, a format for it, and a stale check against the head. Risk: a wrong grouping hides a real change inside "mechanical". The tour has to be checkable against the full diff, with every hunk accounted for by count.
