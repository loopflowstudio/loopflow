Coming back to a Task

LOO-711 · explore, second pass · 2026-11-02. Three imaginations of the return, each with its session side and its pane side.

The scene: at 12:10 you ran lf task run LOO-711 and went to lunch. At 13:40 you come back. The six things you want in the first five seconds:

  • Where is it now?
  • Is there a PR? Is it ready for review?
  • How many loops did it do?
  • Which parts of the design happened?
  • What changed?

Every imagination below draws on the same facts, all of them already in the store or the checkout: each step's outcome, duration and loop iteration; each step Session's turns, tokens and cost; the PR and its phase (open, submitted, merged); the diff against the base commit; the design doc that realign keeps current. The imaginations differ in what organizes those facts.

Highlighted is proposed. Dashed boxes are the pane. The example run is LOO-711's own feature graph, imagined forward: kickoff and explore done this morning, three pursue loops over lunch, a PR submitted at 13:31.

Across all three, the post is the same mechanism (lf posts at a move, the Session reports) and the pane is the same place (the Task pane, minimal by default, expanded on demand). What varies is the organizing principle, and whether the design doc gains structure.
