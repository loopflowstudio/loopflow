Note-taking UI for review pages

Task LOO-1109 Exploration round 1 File: scratch/explore.html
Decision needed: Pick the interaction mechanism for leaving, reading, and editing notes on compiled review pages (runtime.js + base.css). Every vision below keeps the same wire contract (task.steer / session.steer and Desktop's ReviewCommentsStrip) — only how you capture, see, and refine notes changes.
Existing in branch What runtime.js does today
Dragging text pops a 260px box with a single Note button; clicking it opens a textarea; saving dumps notes into a flat Your notes list at the bottom of the page (no edit, no click-to-jump, no diff-line gutter +, and highlights across inline <code> tags silently drop).
A. Google Docs margin rail B. T3 Code / GitHub inline threads C. Notion bubble + sidebar D. Agent steer composer + suggest edit Questions
Proposed · Vision A Inspired by Google Docs / Figma

A. Spatial margin rail (collapses to badges when narrow)

Notes sit directly beside the exact sentence or diff line they belong to — never at the bottom of the page — and fold into inline paragraph badges when the viewport narrows.

Try: drag text then click Comment (or press c) · hover a diff line and click + · click a highlight or margin card

How the loopback listener survives restarts

The loopback carrier in lf server binds a deterministic port per server socket with a fresh 32-byte random in-memory token, so drafts and receipts in browser localStorage survive lf install restarts while old URLs return 404.

Task pages always steer via task.steer, never the building worker's session.steer, because headless Graph workers exit right after building the page.

First slice demo
Open ship-review.html wide beside Rex: drag across a phrase, hit c, type a note, ⌘↩ — the card slides into the right margin aligned to that line with a hairline connector. Resize narrow (or open in Desktop Files): cards fold into inline paragraph badges with zero horizontal scroll.
Appeal
Zero layout shift while reading, immediate spatial memory ("my comment about the token is right beside the token paragraph"), and full inline edit/delete without scrolling away.
Cost & risk
~280 lines of JS/CSS (cross-element range anchoring + vertical collision stacking on resize). In Loopflow Desktop's Files pane (often 650–850px wide), the narrow-mode badge fallback is what Desktop users actually see most of the time.
Proposed · Vision B Inspired by T3 Code / GitHub PR review

B. Inline thread composer (gutter + on every diff line & paragraph)

Comments live right where code reviews put them — inserted directly beneath a diff line range or paragraph — working identically at 600px in Desktop and 1400px in Chrome.

Try: click + on a diff line (or Shift+click a second line for a range) · hover a paragraph for its left + or drag-select text
Tip: Shift+click line numbers for multi-line range

Proposed · Vision C Inspired by Notion

C. Calm reading surface: floating bubble, hover highlights, slide-over sidebar

The page never shifts or splits into columns; selecting text floats a tight action pill, saved notes stay as quiet underlined highlights you hover to read, and a slide-over sidebar shows everything on demand.

Try: hover the highlighted phrase to read/edit · drag any text for the Notion pill (or press c) · toggle the sidebar

Radical success · Vision D Built for steering an agent (T3 Code composer + Docs Suggest-edit)

D. The review is a live steer composer (with inline Suggest-edit)

Stop modeling agent review as human comment threads: every highlight, diff line, and inline text suggestion attaches as a live chip to a T3 Code-style steer box at the bottom of the page.

Try: drag prose → Suggest edit (s) or Note (c) · click diff + with intent chips · edit overall direction below
