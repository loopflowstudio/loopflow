Relaunch after a stop under: 






A · A person's stop outranks the route into end


One approval as #1741 has it, and a person's stop that only a person's lf ship lifts.




    
  
  • tasks.ship_stopped_at plus the stopping Process. A route into end approves only when no stop stands.
    • 
  
  • Explicit lf ship clears the stop. ship_halt records no stop.
    • 
  
  • The runner checks approval when it reaches a landing step. Unapproved: the Task waits at land like an interactive step.
    • 
  
  • process_starter derives "started by" from Process ancestry. Agent reasons are authored by the Session for Jack.
    • 





Cost: one migration (3 columns), the landing check, the Starter DTO in Rust and Swift. Risk: two ship states (approved, stopped) a reader must keep straight; mutual exclusion is enforced on write.
Keeps auto and -b task run landing unattended, as Jack chose on 2026-10-27.



B · Only lf ship ships


Merge authority is one explicit act. A run never grants it.




    
  
  • Delete the ships branch in start_run_in and the ship_in calls in arrive_in/end_task_graph.
    • 
  
  • No stop column: lf ship --stop clears shipped_at and nothing sets it again implicitly.
    • 
  
  • Same landing check: an unapproved run waits at land. lf ship starts from there.
    • 
  
  • Same attribution work.
    • 





Cost: smallest state, net deletion. Risk: reverses #1741 (LOO-648) two days after Jack restored it. auto and every -b task run now park at land until someone ships, which changes the unattended path people use most.



C · A ship ledger: the last word from a person wins


Ship intent is an append-only history of who asked for what; current state is read from it.




    
  
  • Every approve and stop is a task_events row with its Process. No new columns: shipping is derived.
    • 
  
  • Rule: a Route approval counts only if the latest person event is not a stop. Sessions and recovery can never write a person event.
    • 
  
  • Status and Desktop show the ledger: "Jack stopped 09:33 · Session relaunched 09:34 (did not ship) · Jack shipped 11:02".
    • 
  
  • Landing check and attribution as in A.
    • 





Cost: rewrites how shipped_at is read across Task state derivation, projections and store_revisions; much larger diff. Risk: a second source of truth while shipped_at remains, unless it is deleted outright. Appeal: answers "why did it ship?" for every past and future case, not just this one.
