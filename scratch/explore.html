2. Three real traps Vision B has to handle

Trap 1 — Turn 1 is "opening move for a human," NOT "Headless / With nobody there" ship-review.md ("With nobody there: fix small things, file findings, go on to delivery"), verify.md ("Headless, decide and keep moving"), explore.md ("Headless: recommend one"), and demo.md ("With nobody there: say the demo didn't happen and finish") all treat headless execution as nobody is coming. Vision B's Turn 1 runs without a person typing yet, but a person is joining next—so the Graph must frame Turn 1 as "Someone is joining this conversation after your opening turn: do the opening preparation and stop with numbered questions; never auto-decide, edit code, file Tasks, or advance." Only -b / auto on uses the headless auto-decide framing.
Trap 2 — research.yaml has a redundant double step research.yaml currently writes - step: research followed by - interactive: research inside a loop—which only existed because interactive: stopped before doing any work. Under Vision B, either research.yaml collapses to a single - interactive: research (cleaner!), or Turn 1 detects the note already exists and formats the reviewable HTML page without re-researching.
Trap 3 — demo launches live apps & servers (focus stealing + process teardown) .lf/skills/demo.md builds an isolated Loopflow Dev.app bundle and opens a window or runs a disposable server. Running that silently in the background when pursue finishes would pop windows on macOS while you're working elsewhere—and if Turn 1 ran as a short-lived worker, exiting Turn 1 would tear down the demo server before you tried it. Fix: Turn 1 builds the bundle/fixture state and hands back a ready command without popping focus, or demo (or any step with live side effects) opts into running on open / inside a held session.

3. Three concrete ways to build Vision B (vs. Existing A)

B1Step-Owned Thread (Fresh Native Skill Per Step)

Proposed

When the Graph reaches interactive: <skill>, the Graph runs Turn 1 of <skill> as a real provider thread (with <skill>.md as its actual skill, on that step's agent:), pauses after Turn 1, and hands that thread to Desktop / lf open as the Task's active conversation for that step.

Graph reaches interactive: → runs <skill> Turn 1 (any harness) → parks live thread + artifact → you attach directly to it

First slice demo

Start a Task on code and close its pane. When pr-publish succeeds, the Graph runs ship-review Turn 1 on agy or Claude with ship-review.md as its skill, writes scratch/ship-review.html, and marks the step thread ready. Click the Task: you land straight in the ship-review conversation with the questions already printed—zero wait.

Appeal

  • Works on all 5 harnesses today—including agy even while another pane is open—because Turn 1 uses the Graph's worker driver, not idle wake.
  • Cleanest prompt & context: Each interactive step runs with its real skill (explore.md, ship-review.md, verify.md), zero task-session hat-switching, zero lf help.
  • Honors per-step agent:: interactive: { name: ship-review, agent: claude } actually runs on Claude.

Cost & risk

  • Breaks "one continuous Task thread": Each interactive stop starts a fresh provider thread; conversational context from explore doesn't carry into ship-review except via scratch/.
  • Who runs lf task run after you answer? A step-owned thread running ship-review.md isn't task-session—it needs the closing rule (write answers to scratch/, steer, advance Graph) wired into interactive steps or a tiny shared footer.
  • Pane handoff in Desktop: If you left the old conversation open, Desktop has to switch or offer the new step thread.

B2Primary-Thread Turn 1 (One Continuous Conversation, Driven Automatically)

Proposed

Keep the Task's one primary conversation—when the Graph reaches an interactive step, it drives Turn 1 directly onto that primary thread (via headless resume if closed/new, or live wake if open) with the active skill injected inline.

Graph reaches interactive: → primary closed? headless resume Turn 1 / open? wake with inline skill → same thread waits for you

First slice demo

Start a Task on feature, do explore, then quit the terminal while build runs. When pr-publish finishes, the Graph resumes that exact same native thread headlessly for Turn 1 of ship-review (injecting ship-review.md), writes scratch/ship-review.html, and pauses. Reopen the Task: your explore chat is above, and ship-review's opening questions are right at the bottom.

Appeal

  • One continuous Task thread forever: You keep full conversational memory from explore → ship-review → verify, and Desktop never switches threads under you.
  • Zero wait even when you quit the session: Headless resume runs Turn 1 on the primary's native thread while you're away (works on Claude, Codex, OpenCode, Pi, and agy).
  • No lf help round-trip: The captured graph's skill.skill.content is injected straight into the turn prompt.

Cost & risk

  • Two paths (open vs. closed): Closed primary uses headless resume (works on all 5 harnesses); open primary still needs idle wake (so open idle agy depends on LOO-1098).
  • Locking a live TUI: Must strictly verify no interactive client holds the primary's native thread before running a headless resume turn on it (otherwise two processes write the same provider transcript).
  • Context growth: Long Tasks accumulate history across all steps in one thread.

B3Two-Phase Step: Graph Prepares Artifact, Primary Owns the Conversation

Proposed Cleanest seam

Separate preparation from conversation: the Graph runs a fast headless preparation turn for the interactive step (producing scratch/explore.html, scratch/ship-review.html, or verify's headless check note—never popping demo windows), then hands the finished artifact to the Task's primary conversation via PR #2042's step: handoff.

Graph prepares artifact (any harness, even quit) → writes scratch/<step>.html + summary → step: handoff to primary → primary opens straight to questions

First slice demo

Build PR #2042 + one addition: before settling at ship-review (or verify / explore), the Graph runs a single non-mutating prep pass that builds scratch/ship-review.html and extracts the numbered questions. Whether your primary was quit, on agy, or open on Claude, the page is already built; when the primary wakes or opens, it reads the ready summary and presents the questions in ~2 seconds instead of ~50.

Appeal

  • Builds directly on PR #2042 instead of throwing it away: Keeps arrival, step: scoping, and the one continuous primary conversation.
  • Zero locking hazard: Preparation runs in an isolated worker (never touches the primary's live native thread), so it works safely on all 5 harnesses even while an agy TUI is open!
  • Clean opt-out for demo: Interactive steps declare whether they have a background prep turn (explore, ship-review, verify, design, research: yes; demo: build-only or on-open).

Cost & risk

  • Two agents touch the step: The prep worker builds the page, and the primary conversation discusses it—if you ask "why did you propose option 2?", the primary reads scratch/ship-review.html + code rather than remembering having drafted it.
  • Still relies on LOO-1098 for an open idle agy terminal to pop up the summary automatically (though scratch/ship-review.html is already on disk ready to view in Desktop).
