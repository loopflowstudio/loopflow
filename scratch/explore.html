redesigned.

Same pane, same behaviour: one stream for the whole comparison, stepping across files, focus on one file, unified or side by side, word emphasis, collapsed moves, select lines to copy or ask, the delivery card, live updates that keep your place. What changes is how it reads.

The decision: is the right-hand pane what gets built, and which of the twelve changes below would you undo?

Left is the pane as built, redrawn from TaskChangesView.swift and ReviewStreamView.swift: sizes, order and wording come from the source; it is a reconstruction, not a screenshot. Right is proposed and works: step, pick a file, focus, expand the move, drag the line numbers, open the PR pill. Both show the same seven changes in four files at 540 points.

What changed, and why

  1. What you are looking at comes first.Was: "Compared with main at a0548bf · includes uncommitted changes" in 10-point type under the last line of the last file. Now the pane's title, with the size of the change.
  2. The diff starts at the top.Was: the delivery card, then every changed file listed inline, then the first line of code. This branch touches hundreds of files. The file list is a menu on the current file's name; the stream begins under the bar.
  3. Delivery is one pill until you want it.Was: a tinted card with headline, title, checks disclosure and description disclosure, always first in the scroll. A pill with a status dot; click for the same card. Nothing it reports is removed.
  4. The stepper looks like the main control.Was: two bare chevrons and grey 11-point text beside an unstyled "Focus file". One bordered control with the position in the middle and the keys shown next to it, not only in a tooltip.
  5. You always know which file you are in.Was: file headers scroll away, and the toolbar names the file only in Focus. Headers stick while their file is on screen and the bar always names the current file. The name is bold, the directory quiet.
  6. No git plumbing.Was: raw @@ -210,7 +210,11 @@ lines. A dashed rule with what a person wants from it: how many lines were skipped and which function this is.
  7. One column of line numbers.Was: two 42-point gutters in unified, 84 points of a 540-point pane, in 10-point type. One gutter: the new number, or the old one on a removed line. Side by side keeps one per side.
  8. Colour says less, words say more.Was: heavy row fills, and changed words both filled and underlined. A light row tint with a clearly darker word; no underline. + and − stay so it reads without hue.
  9. A move looks like a move.Was: a grey caption row, the same look as "Binary file" and "No textual changes". Its own colour and wording, "Moved here from L164", with the whole row as the expand target.
  10. Selecting lines is something you can find.Was: click a 10-point number, ⇧-click another; only a tooltip says so. The result is a bar docked at the bottom reading path:211-215 · new. Numbers light up on hover and drag to select. The actions float over the code, Ask is the primary one and has a key.
  11. Focus says what it hid.Was: a grey caption, "Showing … · 5 other files hidden", and the button renamed "All files". A tinted strip with a close button; the Focus button stays put and shows as on.
  12. The pane acknowledges you.Was: stepping moved a 3-point bar; live edits appeared silently; the stream just stopped. The change you land on flashes once. A new edit outside the view offers "1 new change below" and never scrolls you. The end says it is the end.
