Confirmed bug: why ⌘F always goes to the main session

Existing bug Fixed in all 4 below

Two concrete causes in the current Swift code:

  • WorkspacePanesView.swift:802–830 attaches PaneFocusTarget(isFocused: isFocused) to .graphLog so AppKit does not bounce firstResponder back to the terminal when the terminal loses focus, but omits PaneFocusTarget on .files, .changes (TaskFilesView). Clicking in rendered Markdown/HTML, Diff, or the file tree leaves GhosttyTerminalNSView as firstResponder.
  • TaskFilesView has no ⌘F handler or find bar of its own. Only NSTextView (usesFindBar = true) answers ⌘F when directly focused, so GhosttyTerminalNSView.performKeyEquivalent (GhosttyTerminalView.swift:1233) captures ⌘F and opens the terminal search bar instead.

Fix baked into the base: attach PaneFocusTarget to TaskFilesView and add a native inline ⌘F find bar across Read, Edit, Markdown, HTML, and Diff (try the ⌘F button inside Direction 1 below).

1. Telescope / fzf --preview + ripgrep

Proposed · Neovim Telescope / fzf / rg

The A↔B file browser paired with a fast two-column fuzzy finder and live ripgrep search with inline syntax-colored preview, plus an in-file ⌘F bar that can promote any query to repo-wide grep.

Brief Diff Files
Try ⌘F (in-file), ⌘P (fzf files), or ⌘⇧F (rg grep with live preview)
Esc
First demo
Press ⌘F inside TaskFilesView.swift: an inline find bar highlights every match inside the file instead of jumping to the terminal. Click in repo → (or press ⌘⇧F): the Telescope modal opens with ripgrep results on the left and a live syntax-colored preview centered on the matching line on the right. Switch to Files (fd/fzf) and type dir to fuzzy-jump straight to directory.rs.
Cost
Medium (~1.5–2 weeks). Pure Rust task.files.index + task.files.grep using the ignore and grep-searcher crates (the exact libraries ripgrep is built on, so remote Machines need zero external installs), plus Swift Telescope picker and in-file ⌘F bar.
Appeal
Instant, language-agnostic, zero setup, works identically on local and remote Machines. Directly satisfies the daily fzf + rg muscle memory without turning Loopflow into a heavy IDE.
Risk
Text grep is literal/regex, not symbol-aware: searching a common name like load returns comments and call sites alongside definitions.

2. Tree-sitter Jump-to-Definition, Outline & References

Proposed · GitHub Blackbird / Zed outline / ctags

Leverage the 28 Tree-sitter grammars Loopflow already bundles for instant ⌘-click / gd jump-to-definition, back/forward history (⌘[ / ⌘]), sticky symbol breadcrumbs, and caller peeks with zero LSP startup delay.

Brief Diff Files
Click any dotted symbol (CheckoutTree, follow, task_files, ReviewCommentsStrip) to jump
First demo
Reading TaskFilesView.swift, click ReviewCommentsStrip or CheckoutTree (or press gd): it jumps straight to the definition in ReviewStreamView.swift or CheckoutTree.swift, updates the breadcrumb to show the enclosing symbol (CheckoutTree › rows), and pushes onto the ⌘[ / ⌘] jump stack. Click a symbol with multiple matches (like follow) or click References to peek definitions and callers inline without losing your scroll spot.
Cost
Medium to High (~2–2.5 weeks). Adds lightweight tags.scm queries on top of existing TreeSitterGrammars (Swift, Rust, TS/JS, Python, Go first; regex fallback for others), a fast Rust worktree symbol index + reference grep RPC, and Swift jump-stack + inline peek UI.
Appeal
The #1 reason people leave a diff/file viewer for an IDE is "where is this defined and who calls it?" Tree-sitter gives ~85% of that in <50 ms per fresh worktree with ~0 MB RAM, unlike spinning up rust-analyzer or sourcekit-lsp in every Task worktree.
Risk
Syntax-based, not type-checked: overloaded method names show a 2–3 item disambiguation peek instead of resolving a single generic type instance.

3. Helix / Vim Read-mode keys + inline step blame + $EDITOR handoff

Proposed · Helix / lazygit / Rune

Because Read mode is not a raw text box, single-key navigation works cleanly without stealing typing: step hunks (]c), toggle inline commit/Graph-step blame (b), leave Diff-style comments (c), or pop the exact line into Neovim/Zed/Cursor (o).

Brief Diff Files
Click inside and press j/k, ]c (next change), b (blame), o ($EDITOR)
READ · L124 j/k move ]c next change b blame c comment o open in $EDITOR
First demo
Open TaskFilesView.swift. Press b: a quiet gutter shows which lines came from this Task's lf build step (highlighted) versus older main commits. Press ]c to jump straight to the next changed hunk, c to drop a Diff-style comment on it, or o to open nvim +124 swift/LoopflowMac/Views/TaskFilesView.swift (or your configured $EDITOR) with zero friction.
Cost
Low to Medium (~1.5 weeks). Swift Read-mode keymap (strictly off in Edit and search inputs), one cached Rust task.file.blame call (git blame --porcelain mapped to Graph step names), and $EDITOR / Copy path:line actions.
Appeal
Respects CLI geeks' real editors instead of rebuilding VS Code; turns Loopflow's Files into the fastest possible keyboard code-reading and blame-checking surface.
Risk
Single-key navigation feels natural to Vim/Helix users and slightly unfamiliar to mouse-first users (solved by making every action also a normal button and keeping Edit plain).

4. UNIX command bar + per-file Graph-step time-travel

Radical · Built on existing --at <rev>

Scrub any file across this Task's Graph steps (base → lf plan → lf build → working tree) using the --at <rev> support already in Rust, and run fast UNIX queries (rg, fd, git log -p %, or shell lf open --file "$(fzf)") right into the reader.

Scrub revisions above the file or run a preset in the ⌘: command bar
Revision

First demo
Click base (main) vs lf build vs Working tree in the revision bar to see how TaskFilesView.swift looked before the agent touched it (reuses lf task file <issue> <path> --at <rev> already implemented in Rust). In the ⌘: bar, run rg "follow", fd swift, or git log % and click any result row to jump straight to that file, line, or commit. From any shell pane, lf open --file "$(fzf)" opens the chosen file here.
Cost
Medium (~1.5–2 weeks). Revision scrubber is almost free (task.file --at and changes.commits exist today). Built-in rg / fd / git log % verbs run safely via Rust RPC (works on remote Machines too), while local shells compose freely via lf open --file.
Appeal
Deeply UNIX and uniquely Loopflow ("a terminal with a memory"): gives you file history by Graph step plus composable CLI verbs without bloating the permanent UI.
Risk
A command bar with open-ended syntax needs crisp discoverability (presets/autocomplete) so it does not become an obscure power-user secret.
