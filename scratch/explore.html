Three implementation traps the exploration found

Reserve producer capacity before dispatch, not just queue space after serialization. Correlate a retry with its own launch attempt, not whichever Graph is current. Record observed provider transitions after IDs are known, rather than declaring success when a process is reserved. Full notes are in the design.

Implementation direction

B covers the five rows with the existing runtime owners. After inspecting the competitors' client recovery code, the recommendation is C limited to immutable submitted creations: save the original request before sending, then reconcile with the server on return. No editable queue, offline creation or arbitrary command replay. Most of the hard server work is already needed by B.

T3 mobile persists a broader outgoing-message queue. Paseo's creation client keeps pending operations in memory over durable server receipts, closer to B. Orca varies by operation; Paradev's inspected retry paths are weaker for creation. Sources and limits are in the design's November 8 comparison. C with simpler records is the implementation direction.
