Which door: Desktop or the CLI installer?

Decided · Jack Heart · 2026-10-28

Streams follow A: one build line from main, with latest and stable pointers. Stable is the newest release that has gone 7 days with no regression, and pointers only move forward. Some of D gets mixed in.

Choose what a new person installs first and what does the updating afterward. All three options below use the same streams. They differ in which door the website leads with and who owns updates.

Several pieces already exist. Loopflow.app ships its own lf at Contents/MacOS/lf and never uses one from PATH. install.sh installs the CLI and the app together. A full lf install restarts Desktop. The bundled helper cannot migrate the store, though: only a published lf install can. The website shows both doors today, with "Download for Mac" first and "or the CLI" second.

1 · CLI door

Loopflow is a launcher you use from a terminal. The app comes with it.

$ curl -fsSL https://loopflow.studio/install.sh | shInstalls lf and Loopflow.app · just the app (.dmg)

lf install owns every update. Desktop gets one thing from D: a line saying "0.14.21 is out on stable" and an Update button that runs the installed lf install.

$ curl -fsSL https://loopflow.studio/install.sh | sh -s -- --stream stable
Installed lf 0.14.14 (stable) and /Applications/Loopflow.app
$ lf install schedule
Weekly at login: follow stable.

Cost: small. Risk: someone who takes the DMG still ends up with an app that has no CLI on PATH and no way to migrate the store. Today's gap remains, just less visible.

2 · Desktop door, the app updates itself

Loopflow is a Mac app. The CLI is something it gives you.

Download for MacLinux or a server? curl … install.sh | sh
Loopflow ▸ Settings ▸ Updates
Stream
Loopflow 0.14.21 is ready on latest.
The lf command comes from this app: ~/.local/bin/lf → Loopflow.app
  • Sparkle reads one appcast per stream (Ghostty's pattern). The appcast for a floor raise marks the update critical for versions below the floor.
  • On first launch the app links its bundled lf onto PATH and performs the store promotion the helper can't do today.
  • lf install stays available for Linux and headless machines.

Cost: large. It needs Sparkle, EdDSA keys in Doppler, appcast hosting, and moving store promotion into the app. Mac would then have two update paths, Sparkle and lf install, which must agree on the stream and the floor.

3 · Two doors, one installer

Either door ends in the same state, and lf install is the only thing that ever updates.

Download for Macor curl -fsSL https://loopflow.studio/install.sh | sh
Welcome to Loopflow
Stream
Finish setup: add lf to your PATH and prepare the store.
Runs the bundled lf install --stream stable, the same steps as curl | sh.

On first launch the app runs its bundled lf install --stream …. That installs the published CLI and promotes the store, exactly as install.sh would. After that, Desktop's Update button and the weekly schedule both run lf install. There's no Sparkle: the part of D you'd keep is that the app can install and update itself, through lf.

Cost: small to medium. It needs a first-run screen, the bundled helper invoking the published install, and a stream setting stored in Home. Risk: the bundled helper starts an install that replaces the app it's running from. That already happens today, since a full lf install restarts Desktop.
