A · Split Motion Button + First-Class Complete

Proposed

Auto-Ship becomes a mode inside the Run split button, freeing the top-right for three equal labeled controls: Motion (Start ▾ / Pause ▾ / Unpause ▾), Pause (when idle/waiting), and Complete.

Demo

While a Rust build runs, top-right reads [Pause ▾] [Complete] ···. Click Pause to stop the worker & builds; button flips to [Unpause ▾]. Click the chevron next to Run or Unpause to pick Auto-Ship or Start from….

Appeal

Zero mystery icons. Every primary Task action (Run, Pause, Complete) is 1 click with an explicit label; Auto-Ship stays 1 extra click away inside the same motion family, like GitHub's merge split button.

Cost & risk

Low–medium cost: SwiftUI split button + updated TaskActions; mirrors cleanly to iOS menu. Risk: on narrow panes (try Narrow pane above), 2–3 labeled buttons squeeze the WorkflowLine sentence sooner.

B · State Pill as the Lifecycle Control (Linear / T3 model)

Proposed

One clickable State pill owns every lifecycle transition (Paused, Complete, Unassign, Auto-Ship switch, Abandon), paired with a single context-smart primary button beside it.

Demo

Top-right shows [● Moving ▾] + [Pause] (while building), [⏸ Paused ▾] + [Unpause], or [✓ PR merged ▾] + [Complete]. Clicking the pill opens a Linear-style transition sheet with keyboard hints and an inline Auto-Ship toggle.

Appeal

Cleanest visual hierarchy: never more than two controls on the right, removes the duplicate state word from the title bar, and makes Paused, Working, and Done feel like peers in one state model.

Cost & risk

Low–medium cost: replaces TaskAutoControl + ··· lifecycle items with one TaskStateMenu; translates 1:1 to iPhone navigation bar. Risk: Complete is 2 clicks (or 1 shortcut) while Moving/Waiting, until PR merges.

C · Quiet Fixed-Slot Icon Strip + Title Breadcrumb Menu (T3 / Codex style)

Proposed

Fixed muscle-memory icon strip (▶/⏸ · ✈ Auto · ✓ Complete) never shifts width or steals space from WorkflowLine; secondary Task actions hang off the Task title in the burgundy bar (click the title above).

Demo

Every open Task has the same compact 3-button segmented control at top-right: Play/Pause, Auto toggle (lights green only when armed), and Checkmark (Complete, accented when PR merged). Clicking LOO-1078 lf task pause ▾ in the titlebar opens Move, Unassign, Start from…, Copy, Abandon.

Appeal

Gives WorkflowLine maximum room (even in narrow splits), eliminates the ··· button completely, and gives Pause, Auto, and Complete permanent 1-click spatial memory.

Cost & risk

Low cost: pure SwiftUI rework across TaskWorkflowBar and TitleBar. Risk: icon-only controls rely on tooltips until learned, and ⏸ (pause Task) vs ✈ (auto-ship) can look ambiguous without labels.

D · Graph Gate Switch + Equal Pause & Complete + Process Strip

Proposed · Radical

Auto-Ship isn't a Task lifecycle action — it's a Graph policy (skip the 👤 stops). Move that toggle onto the WorkflowLine itself so top-right belongs strictly to Pause/Run and Complete, with an expandable live process strip showing what Pause actually stops.

Demo

On the left, clicking 👤 stops: on on the Graph line flips it to Auto: skipping 👤 (the 👤 icons dim/strikethrough). On the right, Pause (with live process count 2 jobs) and Complete sit side-by-side at equal weight. Clicking 2 jobs or pausing reveals the inline process strip (codex, cargo test · 410% CPU, session) and lets you pause everything (default) or keep the conversation open.

Appeal

Fixes the root concept mismatch: Auto-Ship explains itself visually right beside the 👤 steps it skips, Pause and Complete become true peers, and the process strip makes "stop my Rust builds" tangible and verifiable instead of blind faith.

Cost & risk

Medium–high cost: Slice 1 ships the bar split (Graph gate toggle + Pause/Complete) with zero new backend fields; Slice 2 adds owned process/job summary to TaskOverview so the strip shows real live builds. Risk: interactive toggle inside WorkflowLine needs careful truncation on narrow panes and an iPhone equivalent.
