Jack Heart selected 15 minutes after navigating away and accepts ending live Sessions on explicit Close once requested work finishes. Normal shell output alone does not keep a finished, unused Task alive indefinitely.

Equal hosts, shared lifetime rules.

lf retains a Session while Desktop or Rex requests retention. Each host decides when to release; lf does not interpret native tabs or selection. Desktop need not prioritize retaining completed Sessions.

The approved timing is two minutes until eligible idle agent ending, then thirteen more minutes until shell and checkout cleanup. Active requested work finishes first. Returning before full cleanup can resume the conversation in the existing checkout.

Uncommitted checkout changes do not prevent completed-Task cleanup. Eligible deletion discards them. The example’s checkbox demonstrates this choice; it is not a cleanup blocker.

The simulation uses the same release/retain contract for either host. It does not claim to implement Rex’s native tab policy. Explicit Close can end eligible execution sooner; lost host observation is not an observed release.

Recovery, concretely.

  1. Connection lost, shell still running: reconnect to that same shell and its jobs.
  2. Shell ended: show its ended state and offer a new shell. The new shell cannot restore the old shell’s variables or jobs.
  3. Return between minutes two and fifteen: resume the same conversation in the retained checkout. Try Return, then Resume conversation.
  4. After cleanup: conversation history remains recorded. Automatic checkout restoration is outside this requested scope.

Prototype only. Cleanup can fail due to an unavailable host or Git operation; retain accurate partial results and retry remaining work. Uncommitted files alone are not a failure. Approved for implementation; the Graph stops at demo.
