October 16, 2026. Jack Heart's [Arrange brief](arrange-navigation-brief.md) supplies the product direction. **Accepted study choices: 01 A Breadcrumbs, 02 B Attention first, 03 A At the end.** Jack authorized the [UX-independent pane foundation](foundation-scope.md) while away and requested multiple prototype sets, isolating one subproblem at a time. ## Problem and demo

Jack needs to see several Tasks working, enter one to act, and return without reconstructing the arrangement or losing the Session. The current retained workspace registry is useful, but ordinary navigation replaces its visible slot and the sidebar exposes only a narrow working set. October 16 supersedes the October 15 pinned-dashboard/Task-browser proposal.

**Demo:** open a repository containing twelve open Tasks. Its sidebar shows attention first, then the other open Tasks and Waves. Click a Wave: its Tasks appear as live, single-pane tiles. Enter a Task, use its shell or Files, return through the Wave crumb: the tile still shows the primary Session. Explicitly zoom Files and return: Files is now the tile face until unzoomed. Resize/move a tile, receive a new matching Task in the inbox, hide/restore a member, and return through Back. Pin an enumerated query in ⌘K; open another repo in its own window. Layouts and drafts survive navigation. Relaunch and cross-machine layout recovery complete the same experience through LOO-416's owner; they are not proved by a prototype.

The future CLI counterpart uses LOO-497's `lf desktop state --json` before/after `view wave:<name>`, `view task:<ref>`, and arrangement operations. It must describe the same memberships, geometry, focus and hidden members as clicks. These commands are a target contract, not current capability claims.

## Binding decisions and scope

- Repo sidebar: open Tasks, attention first, then Waves and pinned queries. Wave sidebar: its open Tasks. Task: full-width pane tree, no sidebar. Breadcrumbs carry hierarchy; no persistent Find Work field. ⌘K handles search, query entry and repo switching.
- A Wave is a derived multi-Task view. Each tile projects exactly one pane: authoritative primary Session, overridden only by explicit inner zoom. Ordinary focus cannot change its face. Each Task retains exactly one inner layout.
- Selection changes membership; arrangement changes structure, focus and visibility only. Hide is restorable membership, never predicate removal. Enumerated sets use the same query mechanism as dynamic sets; nested queries remain live.
- Containers auto-tile until deliberately arranged. Touched layouts retain positions, put arrivals in an inbox and collapse departing leaves. Layout memory is Work-keyed, including container identity plus canonical query hash, rather than window-keyed.
- One repo per window; titlebar follows the focused workspace. Breadcrumbs sit after native traffic lights; scoped actions and Open Repo sit right. Nonfocused panels retain slim identity headers. Normal app windows remain the implementation choice; literal per-repo Dock icons are unresolved.
- Existing Ink on Paper selection, truthful attention, native input ownership, Task Files drafts, Workflow legality and exact Session actions survive. Navigation cannot start a Flow or implicitly take over another client.

LOO-489 owns presentation and interaction integration. LOO-497 owns shared selection/query/arrangement APIs, inspection and headless plans. LOO-416 owns retained Session lifetime, attachment, relaunch and surface-capacity measurements; shared saved-layout records are coordinated with LOO-497. LOO-498 consumes plans in external multiplexers and is not launched here. LOO-415/422 own transport/status; LOO-453 owns readiness/events. No second driver or new Maestro daemon is implied by the brief. Both design Flows have finished. The Task is at the design node; its pane foundation is locally implemented. Shared live selection and persistence integration remain dependencies.

## Chosen architecture and owner contracts

**Authority:** Rust Work readings own Task/Session identity, membership evidence, status and legal actions. LOO-497 owns the shared query expression/evaluation and selection/arrangement contract. The Desktop registry owns retained workspace objects and the window's native pool. LOO-497 owns shared query/arrangement records; LOO-416 owns Session attachment and retention. No layout record owns execution.

**Selection and placement:** retain one `SessionsWorkspace` per canonical `WorkWorkspaceKey`. Extend existing navigation/history to capture the container selection, query identity and focused member; maintain one active selection owner. Focus is a cursor within that selection and cannot replace its predicate. Visiting a Task suspends the containing arrangement, then crumb/Back restores that arrangement and its focused member. A container holds Work/query references, never copies of Task `PaneState`. The shared split-tree representation belongs to LOO-497; remove the exclusive `WorkLayout` tree if that cut generalizes `LayoutNode`, rather than keeping two geometry engines. Do not generalize inner terminal ownership into a query leaf.

**Shared query boundary:** LOO-497 owns grammar, canonical IDs, evaluation and status mappings. Its October 16 review records Jack Heart selecting started, unfinished Tasks as default membership; repo also includes Waves, with descendant open Tasks and child Waves for future hierarchy. Paused started Tasks remain; unstarted backlog is not a default match. Explicit references can still select it. Unknown evidence remains unknown. No second Swift evaluator or Project destination is introduced here.

**Container reconciliation:** maintain matches separately from hidden member IDs and geometry. Untouched layouts deterministically order attention first, then planning rank, identifier and stable ID. Build a balanced split tree with stable leaves; changes in attention may reorder only auto layouts. On the first structural edit, freeze surviving positions. Jack selected arrivals at the end (03 A). Append new matches after surviving leaves, without reserving a side rail or region above. Attention-first sizing (02 B) applies while automatic; the first arrangement edit freezes order and proportions so later attention changes cannot move surrounding tiles. Departures collapse geometry but retain the Work's workspace and drafts. Hide/restore is represented even when no visible leaf remains. A query edit chooses its own normalized-query arrangement; returning to the previous query restores its saved one. Duplicate query references are finite; cycles/invalid expressions fail before changing selection.

**Tile projection:** resolve `zoomedPaneId` against that Task's own layout; otherwise resolve the unique `taskPrimary` Session to its retained pane. Explicit zoom can project Files, shell or Flow log, with its existing owner. No focused-pane fallback. Unknown primary, absent native surface, attachment elsewhere, failed acquisition, and missing checkout get specific retained placeholders/actions from existing owners. Merely matching a query neither prepares a checkout nor opens every provider. LOO-416 must supply passive viewing of already-running Sessions where the native pool does not yet contain a view; a placeholder does not satisfy the final live-grid demo.

**Overlapping query occurrences:** LOO-497's October 16 review records Jack Heart selecting first-wins presentation. Traverse displayed composition first-child then second-child, skipping hidden occurrences. The first canonical Task occurrence hosts the pane; later occurrences are suppressed without changing membership. Focus cannot change the winner. Hiding/removing it promotes the next occurrence. The alongside prototype places the full Task first, followed by its originating view, whose duplicate tile links to the Task. No mirror or second provider is created.

**Layout persistence integration:** LOO-497's reviewed direction assigns shared lfdb query/arrangement records and its migration draft to that Task; LOO-489 consumes save/restore, and LOO-416 owns Session/process retention. Records express Work/query identity, ordered references, ratios, hidden members, zoom and auto/touched intent, never native handles or inferred liveness. Preserve content Machine/path provenance and resolve availability without retargeting remote content. Cross-machine transport remains engineering integration work; local storage alone does not prove D9. The pane foundation changes none of these owners.

**UI/action audit:** replace sidebar header hierarchy with titlebar crumbs. Repo/Wave sidebar starts visible and remembers width; Task hides it without forgetting that width. Focus in a Wave tile leaves the Wave selection/sidebar intact; Enter/click-to-enter visits the Task. ⌘-click opens beside via shared selection. Palette query results offer Pin; pinned rows expose Unpin and Edit query. File retains Open Repo; Go exposes ancestors, Back/Forward and Find Work; View exposes scoped split/zoom/sidebar actions; Window uses normal per-repo entries. Titlebar Open Repo is one click. Keep secondary Session rename/bind, details and Workflow actions reachable using existing command owners. No duplicate lifecycle row just to retain old chrome.

## Alternatives, failure and exclusions

Keeping one mutable active tree destroys the return-to-Wave arrangement. Copying pane trees into tiles duplicates drafts and surface ownership. A Swift-only query evaluator diverges from `view --plan`. Retaining cache-based layouts loses them on cache invalidation. These routes are rejected.

Jack Heart requested isolated comparisons, choosing navigation first. [Nine interactive studies](arrange-studies/index.html) now cover three alternatives each for returning to place, tile proportions, and arrival-region placement. Each set holds other decisions constant. Jack selected A/B/A; the default study now combines those choices. Query editing and shared API design stay with LOO-497's existing study; these prototypes have sample Work and no production evaluator, native surface or process.

Wild success is moving between twelve Tasks without thinking about terminals. Wild failure is attention churn moving a tile under a click, a new match launching twelve providers, or a duplicate mount stealing input. Stable pinned layout, passive membership and exact native ownership address those failure classes. No per-tile polling/history subscription; one focused Task detail subscription. Navigation among retained work performs zero prepare/open/replace calls. LOO-416 measures the 1/4/12-surface path and usable input/render endpoints; no invented latency/soak target replaces Jack's October 7 decision. Surface eviction that terminates PTYs is forbidden.

Excluded: provider relay/daemon design, automatic takeover, OSC transport, external-host adapters, theming/shaders, live planning/auth repair, literal Dock-icon processes and Project navigation. Cross-launch/cross-machine layout behavior remains an integration requirement with its existing owner, not an exclusion or a claim of current support. Product Wave memory is read-only. This work supports the shared Work experience but establishes no progress KR for Cube, Etude, Kata or Hootro.

- Full-task `workspacePanel` rendering in container tiles, inactive Open-only content and redundant focused workspace header. Keep scoped Files/log/shell rendering, Session toolbar actions and truthful Workflow controls.
- The old dashboard-only `WorkDestination` proposal, fixed Wave Task browser and permanent non-hideable repo-member rule. They are draft artifacts, not production code to modernize. Studies 01–07 stay historical evidence.

Update `swift/DESIGN.md` (actual path), Desktop README, `docs/architecture-reference.md` and CLI docs with the integrated behavior. Do not rewrite unrelated design history. Rust/Swift DTO and fixture changes belong to the shared API cut; no defaults, fallback evaluator, parallel store, duplicate Task layout or dashboard Work kind. iOS and automation continue reading the same Work truth; no execution semantics change here.
