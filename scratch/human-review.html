LOO-984: a launch that ends before Claude's first turn opens again

PR #1991 at 856b570528, level with origin/main, mergeable. 2026-11-19. Written with nobody in the conversation; section 7 says what was decided in your place and what is still yours. Sources: scratch/plan.md, scratch/qa.html, scratch/concept-review.html, scratch/questions.md.

1. What changes

A Claude conversation whose launch died before Claude saved anything (no claude on PATH, a failed login or trust prompt, a crash, quitting at the first screen) used to be able to reopen into "No conversation found". Now every interactive opener starts it again on a new thread with its first request, and says so:

$ lf -a claude resume          # Esc at Claude's first screen
claude exited with 1.
$ lf resume
This conversation has no saved claude transcript; starting it again from its first request.
────────────────────────────────────────────────────────────
 Adding a new directory:
 /private/tmp/lfqa984b/r4
 This session hasn't worked here before. …

A conversation Claude did save still resumes with --resume. A provider that refuses that resume leaves the Session as it was. The same line shows when a transcript was deleted after real turns.

Net code: 86 lines removed, 19 added in rust/loopflow-execution. Two launch guards, record_missing_provider, which_command and lost_thread are deleted; one function decides.

fn saved_thread(store, artifact_key, provider) -> Result<Option<ProviderSessionRef>> {
    let Some(thread) = store.sqlite.input_provider_session(artifact_key)? else {
        return Ok(None);
    };
    if !crate::transcript::thread_lost(&store.sqlite, provider, &thread.agent_session)? {
        return Ok(Some(thread));
    }
    crate::journal::request::diagnostic(format_args!(
        "This conversation has no saved {provider} transcript; starting it again from its first request."
    ));
    Ok(None)
}
