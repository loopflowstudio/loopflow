LOO-968: auto is a setting on the Task

PR #1976, head 2d4708c391, base main at 1a6c9d618a. 213 files, +4,622 / −4,122. Written 2026-11-19 with nobody in the conversation; section 6 says which questions are still open.

1. What changes for the people who use it

  • lf ship and lf task hold are gone. lf task auto on X runs the Task with nobody waited for; lf task auto off X takes the interactive steps and the merge back.
  • There is no shipping state and no Autonomous section. A Task with auto on reads moving in Working, with an Auto badge.
  • An off said before a Task's first run is kept, and outlasts a config default.
  • auto: on in a Wave's, a repository's or your own config makes it the default; the builtin auto graph is gone.
  • -b on lf task run stands in for that run only and writes no auto.
  • The human-review step and skill are named ship-review.
  • One carrier and one recovery path: a died run of any Task comes back as lf task run X. ops/task/ship.rs (1,089 lines) and lf/commands/ship.rs (135) are deleted; ops/task/auto.rs is 194.

The whole of what reads the setting

// rust/loopflow/src/lf/commands/graph.rs
fn stands_in(&self, skill: &ConcreteSkill) -> Result<Option<bool>> {
    if !skill.interactive || self.launcher.interactive {
        return Ok(Some(false));
    }
    if self.launcher.batch {
        return Ok(Some(true));
    }
    let Some(task) = self.task.as_ref().filter(|_| self.task_run.is_some()) else {
        return Ok(Some(false));
    };
    let on = self
        .store
        .sqlite
        .task_auto(task)?
        .is_some_and(|mark| mark.state == AutoState::On);
    Ok(on.then_some(true))
}

// rust/loopflow-execution/src/task_graph.rs
pub fn waiting_to_land(&self, auto: Option<&Auto>, issue: &str) -> Option<String> {
    let off = auto.filter(|mark| mark.state == AutoState::Off)?;
    let TaskGraphPosition::At { step } = &self.position else {
        return None;
    };
    let ends = step == START || step == END;
    let interactive = self.interactive_steps.iter().any(|s| &s.name == step);
    (!ends && !interactive).then(|| crate::ops::task::auto::landing_wait(step, off, issue))
}

Where it is stored

-- rust/loopflow-storage/src/migrations/task_auto.sql
CREATE TABLE task_auto (
    task_id TEXT PRIMARY KEY REFERENCES tasks(id) ON DELETE CASCADE,
    state TEXT NOT NULL CHECK (state IN ('on','off')),
    set_at INTEGER NOT NULL,
    set_by TEXT NOT NULL CHECK (json_valid(set_by))
) STRICT;
-- A finished Task's last auto mark, in place of counting its log.
ALTER TABLE task_summaries ADD COLUMN auto TEXT CHECK (auto IN ('on','off'));

-- Each Task's latest approval or stop becomes its mark, whether or not it
-- took up a Graph. A withdrawal (a failure that ended shipping) reads as off.
INSERT INTO task_auto(task_id,state,set_at,set_by)
SELECT e.task_id,
    CASE e.kind WHEN 'approved' THEN 'on' ELSE 'off' END, …
FROM task_ship_events e …

Biggest mismatch: off is two promises

As built

stands_in:        auto == on  → stand in
waiting_to_land:  auto == off → wait at the merging step
                  never set   → land

lf task auto off X
lf task run X        # you take ship-review yourself
#   Waiting at pr land: auto is off (Maya).
#   `lf task auto on X` lands it.

"Auto on" is how you land a Task you reviewed yourself. The Desktop toggle shows two positions for three values.

What it would take (not built; filed as Task 014b7b)

each interactive step records who took it:
  a person | a stand-in
landing waits only when auto is off
and the last interactive step was stood in for

lf task auto off X
lf task run X        # you take ship-review yourself
#   lands

It changes what Graph steps record and where an off puts a Task. A Graph with no interactive step and auto off still has to wait for auto on. The present rule is safe: an off never lets a merge through.
