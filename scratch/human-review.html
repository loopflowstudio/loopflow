LOO-959: Task conversations and Task runs come back after a kill, a crash or a reboot

PR #1972 on main, head fcfa554e2c, mergeable. 71 files under rust, swift and docs: 3,557 lines added, 533 removed. Written 2026-11-18 with nobody in the conversation; nothing here is a person's reaction. The questions at the end are still open.

1. What changes for the people who use it

  • A Task's conversation that dies (killed, crashed, lost in a reboot) starts again by itself within seconds, on its saved thread. One you quit stays quit.
  • A Task run whose lf task run or lf ship died is carried again from the step it reached. After five deaths in a row it stops and names the command.
  • After a reboot the server brings back what was running, one start at a time, most recently active Task first. No one has to read anything for that to happen.
  • lf task status and Desktop say which of these is the case, in one sentence the server writes.

The rule both callers read:

pub fn server_start(
    conversation: &DownConversation,
    claimed_here: impl FnOnce() -> bool,
    server_runs: impl FnOnce() -> bool,
) -> ServerStart {
    let left = if loopflow_storage::session::quit_by_person(conversation.exit_code) {
        Left::Quit
    } else if conversation.starts_since_turn >= CONVERSATION_STARTS {
        Left::OutOfStarts
    } else if !conversation.here {
        Left::Elsewhere
    } else if !claimed_here() {
        Left::NotClaimedHere
    } else if !server_runs() {
        Left::NoServer
    } else {
        return ServerStart::At(next_start_at(
            conversation.starts_since_turn,
            conversation.last_started_at,
        ));
    };
    ServerStart::Left(left)
}

6. Questions

  1. Should a Wave's or a repository's conversation come back on its own too?
    1. No: Tasks only, as built.
    2. Yes, by the same rule.
  2. On the first pass after upgrade, a conversation that died weeks ago on a still-open Task starts again.
    1. Leave it: an open Task's conversation should be awake.
    2. Start only ones that died since this build first ran; older ones read waiting_for_you.
  3. A conversation killed while no server ran (no end recorded):
    1. Read it as the pass does: died (no end recorded) · no server runs here to start it; `lf resume --task X` opens it.
    2. Leave closed; `lf resume --task X` opens it; a server records the end on its first reading.
  4. The outlook's kind:
    1. Leave as built; clients print status_line.
    2. Split it: by: server | you beside what happened (never_ran | died | quit).
  5. The recovery docs' name for it:
    1. Leave: "work session" in prose, "Conversation:" on the line.
    2. "Task conversation" through the recovery section.
  6. A died run is noticed up to a minute late with the server up.
    1. Leave it until LOO-968 leaves one carrier.
    2. Have the carrier's parent or a held handle report the death, as a holder does for a conversation.
  7. The fresh thread after a lost transcript is said only in the pane.
    1. Leave it.
    2. Add it to status_line ("running on a fresh thread; the old transcript was gone").
