1. What changes

  • lf sync LOO-953 stacks this Task on LOO-953: records the parent, moves the PR's base, merges. lf sync main undoes it.
  • lf pr publish no longer resets an existing PR's base. When GitHub and the record disagree, it keeps GitHub's base and prints the command for each direction.
  • lf task checkout X --stack-on P on a published Task now retargets its PR.
  • lf task status, --json and Desktop name the parent by Task (stacked on LOO-953 (#1974, jack/loo-953-…)), not pr_f3052042….

Biggest mismatch: a detached child still carries the old parent's commits with their changes reverted. If that parent lands with a merge commit and the child runs lf sync main without restacking, the child's PR deletes the parent's work. Squash and rebase landings are unaffected. Fixing it means detach rewrites the child onto main, or records a fork the main merge compares from — its own Task. The detach behaviour predates this branch; this branch teaches lf sync main as the undo.
