LOO-986 fix forward: a tmux window starts on the server's PATH

PR #1994, branch head f6df3cc94b, 2026-11-19. Written with nobody in the conversation; the questions at the bottom are still open.

1. What changes for people

An agent in a tmux pane that runs lf open --task <id> --tab no longer hands its own PATH to the conversation it opens. The provider starts on the tmux server's PATH plus lf's tool directories, as it already did in Rex and Herdr. An agent's shim directory can't end up in front of the installed claude.

The cost: a provider that only the caller's PATH could find (an nvm bin, with a tmux server started by launchd or long ago) now fails to start from that open, and the message says "not installed".

3. How to try it

The branch binary is built at target/debug/lf in /Users/jack/src/loopflow.loo-986-a-pane-s. In a tmux pane:

mkdir -p /tmp/shim && printf '#!/bin/sh\necho SHIM; sleep 60\n' > /tmp/shim/claude && chmod +x /tmp/shim/claude
export PATH=/tmp/shim:$PATH
/Users/jack/src/loopflow.loo-986-a-pane-s/target/debug/lf open --task <id> --host tmux --tab --json

The new window should run the installed provider, not print SHIM. The control, from the same pane, shows what tmux does by itself:

tmux new-window 'echo $PATH; sleep 30'      # /tmp/shim is first

This uses the Machine's real store; the branch adds no migration. If the conversation's provider is already running, an open adds a view and starts nothing: quit it first.
