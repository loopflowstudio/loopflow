1. What changes for people who use it

  • lf task run LOO-12 -a opencode and -a pi run Task Graph steps — they receive Task context and mid-step steers between tools, record answers, native session IDs and usage (lf history usage --task now includes Pi workers), stop cleanly on lf task interrupt, and advance the Graph.
  • OpenCode drops its private server: terminal conversations exec opencode --standalone --session ses_… directly; headless turns run one opencode run --standalone --format json --auto process per turn (`opencode.rs` + decoder: 2,211 → 1,291 lines).
  • Missing CLIs and unanswered questions stop once, with the next command: a Graph step skips an uninstalled CLI in agents (showing the move in lf task status while running) or stops after 1 attempt with the install hint; an OpenCode question tool call or Pi dialog stops after 1 attempt with lf steer LOO-12 "…" + lf task run LOO-12.
  • No new commands, flags, tables or columns. Dead AgentExecutionBoundary / AgentWriteScope types go; every headless run in its Task checkout uses yolo.

5. Choices made on your behalf

  • Deleted AgentExecutionBoundary / AgentWriteScope (per our chat) instead of adding an OpenCode-only tool deny or an OS sandbox.
  • Dropped opencode serve for work sessions too: all terminal OpenCode launches use opencode --standalone because nothing wakes an idle OpenCode TUI today anyway.
  • Stripped inherited OPENCODE_CONFIG_CONTENT in CALLER_SESSION_ENV: prevents a parent OpenCode session's plugin and context from leaking into child workers; OpenCode's config files on disk still apply.
  • Interrupted or question-stopped workers start a fresh conversation on the next lf task run (carrying steers forward) rather than resuming a worker Run's native thread, matching how run_refusal treats Runs on every harness.
  • Left tests/fixtures/dto/work_first_entry.json untouched (still contains the old boundary string inside a fixture reason string) because regenerating it rewrote unrelated drifted keys across Swift/Rust fixtures.
