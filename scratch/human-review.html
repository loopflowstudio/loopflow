Headless commands keep going after a usage limit

A usage limit or unavailable model moves the work to the next configured agent. A revoked login skips that provider’s remaining models. The terminal prints each move. PR and commit copy start with their own skill settings, and only Graph steps wait for capacity after exhausting the order.

Biggest mismatch · who answered an input

CASE WHEN c.turn_thread=s.provider_thread THEN s.provider
     ELSE COALESCE(json_extract(c.payload,'$.provider'),s.provider) END

QA confirmed that the next Graph step reads Claude’s answer after Codex refused. If the Session later switches providers again, this lookup can point to the original provider for the older answer and fall back to history’s copy. That case was read from the SQL. Fixing it would take an additive turn_provider column on session_events, written with turn_thread, plus migration coverage and a fallback for old rows.

Choices made

  • Put movement in the shared launch loop. Commit copy now falls through on the three refusals, retries classified transient failures in place, and uses the existing default message if generation fails. The former commit-only loop also moved on timeouts and unreadable output.
  • Send the original prompt on a move before the first reply or tool call. A one-shot launch flag and a transcript excerpt were considered. The test keeps the full PR diff in the prompt.
  • Record the current provider and model on the Session, and infer the latest answer’s provider from its thread. A separate answering-provider field was deferred because it needs a schema change.
  • Keep the folded-text reader alongside Codex’s structured cause. Keep Replay on its recorded agent and existing Sessions on their own provider. A Codex model move resumes the thread and may cost one extra refused launch on an account-wide limit.
  • Keep waiting tied to Graph steps, including foreground batch Graphs. Keep the successful lf commit with a default message after generation fails, and print why.
