## Existing authorities

- `engine::available_flow_names`, `load_flow`, and `expand_flow` own available
  definitions. `ConcreteStep` has literal skills/ops, authored ids, human flags,
  repeat targets and nested XOR paths. Do not parse YAML or construct Feature
  topology in Swift. Reuse the loader for a thin shared display projection;
  avoid sending whole prompts/account inputs just to draw a node.
- Managed `FlowPosition` owns a pinned `QueuedInvocation` and `ExecutionCursor`.
  `cursor.boundary_key()` includes nested path and traversal identity. Root
  iteration is not an occurrence id. Repeated `loop-decide` names cannot key
  nodes. Ordinary saved Flow invocations have a separate existing owner.
- `FlowProgress.repeats` already counts backward traversals by deciding id;
  nested cursors retain qualified repeat keys. Use these actual counts and
  distinguish completed traversals from the current iteration. Both Feature
  edges target implement; a return after demo revisits it later. Design stays
  outside the repeated span. No second counter/store is needed.
- `ops/task_execution.rs` projects idle/starting/running/human/blocked/unknown
  from saved Flow and verified worker evidence. Idle is not synonymous with
  never-started or user-paused. Read its reason and saved boundary. The Task's
  completed Flow position is removed at settlement; the FlowFinished event
  supplies finished context. Never display today's recommendation as its old
  pinned execution or manufacture a missing historical definition.
- `TaskSnapshot` already has execution, Runs/truncation and actions, but its full
  status read also refreshes PR evidence. Avoid introducing a costly GitHub read
  into every graph repaint. Extend the appropriate existing shared read owner,
  keep Podium reading lifetimes, and use explicit unknown/failure states.
- `task run --flow` selects an authored Flow through existing policy. `task
  restart` currently chooses only the refreshed chapter recommendation; selected
  replacement support belongs on that same command/operation, not a new restart
  writer. Its existing operation checkpoints/pushes before restart, so a real UI
  confirmation must describe the consequence. Tests must isolate those effects.
- `task interrupt` ends the current turn through the durable Work request;
  `task resume` reclaims the saved position. Inspect the controller settlement
  before calling interruption a persistent pause. Use real capabilities/reasons;
  do not paint a successful paused state optimistically or treat help as Advance.
- `LinearClient::observe_issue` already pages comments and fails on missing page
  cursors. Its `IssueObservation`/`IssueComment` are provider ingestion types;
  expose only the appropriate shared comment read contract through PM. Real
  count/body, explicit failure, collapsed by default; no Description splitting.
