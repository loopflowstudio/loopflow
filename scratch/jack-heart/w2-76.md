# W2-76 — retire the ephemeral-rotation path, end to end

## What the task assumed vs. what is true

The directive says: delete `lf op next` / `advance_branch`, remove the
`next_wave_handler` wire endpoint and its Swift callers, update tests and docs.

All of that is **already gone**, removed as collateral by #872 ("architecture:
collapse the runtime to waves, projects, and tasks"), which deleted the entire
`lf op` namespace and the `lfd` HTTP route layer along with it. Evidence, on
this branch's base commit `309575f8`:

- `grep -rI "next_wave|advance_branch|advanceBranch|rotate_worktree|RotationResult"`
  over the whole repo (Rust, Swift, Python, docs) hits **nothing** but
  `wave/infrastructure/MEMORY.md` and `land_tests.rs::submit_does_not_rotate_worktree`
  — the memory entry is stale prose, the test is the invariant guard we want to keep.
- `rust/loopflow/src/lfd/http/routes/` does not exist; there is no `Op` variant in
  the `Commands` enum (`rust/loopflow/src/lf/mod.rs`).
- Land rotation was already killed in stage 3a; nothing renames a live worktree.

So there is no rotation code left to delete. The only mentions of `lf op` are in
`RELEASE_NOTES.md`, which is a shipped record and stays untouched.

## What is actually still broken

The removal stopped at the code and never reached the caller. Every retired
spelling now falls into the skill/flow catch-all:

```
$ lf op next
Error: skill or flow not found: op. Run `lf --list` to see available skills.
```

That is the wrong story. It tells a caller their *skill* is missing when what
happened is that a **command namespace was retired**, and it names no
replacement. The callers are real: older prompts, `.lf/` adaptations on other
machines, docs, agents running an installed `lf` that predates #872, and humans
with a year of muscle memory. This is precisely the wave's tracked
**command-drift** failure — a prompt-recommended command the installed `lf`
can't parse — and Developer Efficiency's KR that avoidable human-in-the-loop
repair steps fall to zero.

`lf sub` already set the precedent: a hidden clap subcommand whose only job is to
fail with the new spelling (`reject_retired_sub`, `lf/mod.rs:451`). The `op`
namespace was retired without one.

## The change

One hidden `op` subcommand that captures the rest of the line and errors with
the mapping. Nothing is executed, nothing is forwarded — it is an error message
with a memory.

- `lf op next` / `lf op advance` → removed with **no replacement**. Say why in
  one line: work is dispatched with `lf task run <issue-id>`, and a worker forks
  from and targets its parent branch, so nothing rotates a branch through a
  worktree any more.
- `lf op rebase|wt|commit|doctor|pm|release|sync-skills` → the top-level verb
  (`lf rebase`, `lf wt`, …).
- `lf op pr` → `lf pr open`; `lf op submit` → `lf pr submit`; `lf op land` → `lf pr land`.
- `lf op dispatch` → `lf task run <issue-id>`.
- bare `lf op`, or any unrecognized sub → the namespace line: the operations are
  top-level now.

The mapping is one `match` in `rust/loopflow/src/lf/mod.rs` next to
`reject_retired_sub`. Hidden from help, so the surface does not grow. This is not
a compatibility shim — it runs nothing; when the mapping stops earning its keep
it is one function to delete.

## Build target

1. `rust/loopflow/src/lf/mod.rs` — hidden `RetiredOp { rest: Vec<String> }` variant
   (`#[command(name = "op", hide = true)]`) plus `retired_op_message(&[String]) -> String`.
2. `rust/loopflow/src/bin/lf.rs` — the variant errors; it never reaches a runtime.
3. Tests (`bin/lf.rs` parse tests): `lf op next` errors and the message states the
   removal rather than a replacement command; `lf op land` names `lf pr land`;
   bare `lf op` names the namespace.

## Verification

- `cargo fmt`, `cargo clippy -- -D warnings`.
- `cargo test` **to completion** (a failing lib target masks bin tests — see wave memory).
- Probe the built binary: `lf op next`, `lf op land`, `lf op`.
- No Swift or Python surface is touched, so no Swift run is needed; the known
  headless UI-runner hang is therefore not in this path and is reported as
  pre-existing if anything invokes it.

## Out of scope

- `RELEASE_NOTES.md` (shipped record, immutable).
- `wave/infrastructure/MEMORY.md`'s stale "still owed" entry — server-owned;
  corrected with `lf memory`, not in this PR.
- Any further worktree/dispatch work from stage 3b: the dispatch rule (fork from
  and target `parent()`) already holds.
