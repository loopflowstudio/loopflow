## Approach and acceptance

Retain full OpenCode stderr in a private append-only file within the existing
capture directory. Announce the path before the TUI starts. Keep stdout/stdin
native, identity discovery on first launch, and all provider UI error reporting.
Return capture/identity errors after the provider exits, naming the log path.
Cover immediate failure, retries, arbitrary subprocess stderr, normal launch,
and resume at the public launch boundary. Exercise installed OpenCode in a PTY
against an isolated local API, retaining raw bytes and screen text; check typed
draft preservation and resize. Never use or change live credentials.

## Implementation and retained proof

Implemented in `lf/commands/util.rs`: native stdout/stdin remain direct; full
stderr goes to a mode-0600 append-only capture file. The path is announced before
spawn. Resumes keep their supplied identity instead of discovering a replacement.
The observer drains after a write failure and reports it after provider exit.
The capture directory and diagnostic handle travel together, so launch and
observer setup share one optional value. The PTY probe uses the existing
process-group cleanup; successful exits are asserted before cleanup.
