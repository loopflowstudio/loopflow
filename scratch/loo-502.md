# LOO-502 — Stop pinning ordinary lf commands

## Accepted direction — October 17, 2026

After PR #1587 review, Jack Heart requested “stop pinning lfs” and clarified
“existings lfs will fail if tey fail”. This supersedes automatic incompatible-client
recovery and its verification plan. Existing processes may continue or fail
naturally; installation must not restart them or delay waiting for their exit.

Jack's governing criterion is to reduce complexity and make errors easier to
recover from. His subsequent steer `d865f2c4-f245-48a7-b4e3-6d7038f09f10` makes
retry in the same Session and checkout central: a new command reaches current
installed lf without environment cleanup, another worktree or a new conversation.
Ordinary failures and existing explicit continuation replace special recovery
state, compatibility negotiation and retries. No product decision remains open.

Task identity, checkout and PR #1587 remain. Delivery is publication for review
only, without merge, auto-merge or Task completion. Published checkpoint
`4ca3bbe3d7b30b8a4bb05d466ad55f5eeb368201` preserves the superseded design and its
checks; neither those checks nor the historical HTML walkthrough proves this design.

## Current implementation

One `os_process::resolve_lf_binary` supplies the stable installed entry to provider
environments, hooks, prepared Session argv and Flow children. It preserves symlinks;
the installation gate selects and verifies the current artifact when executed.
Main-Machine dispatch ignores inherited `LF_BIN`. Implementation choice, October
17: explicit `LF_BIN` remains supported with a private `LF_HOME` for isolated
development and tests. Caller attribution and Machine selection remain intact.

The compatibility dispatcher, installer recovery scheduling, hidden Session recovery
command, replacement terminal presenter and their exclusive tests/CI registration
are deleted. Separate pinned/hook resolvers, launch-time artifact verification
cache and redundant Session environment merging are removed. Artifact integrity,
store validation and explicit Session stop/continuation retain their existing owners.
No installer/schema redesign or LOO-497 product change is included.

Already-running code keeps its code and environment. Pre-fix hooks can retain old
immutable paths; reattachment alone does not refresh them. Explicit same-Session
resume after observed provider exit preserves native history and refreshes hooks.
Flow cursors are not reconstructed. Existing effects, pending/uncertain steers,
process receipts and attachment authority remain intact; no automatic replay or
invented exit is permitted.

## Reconciliation — October 17, 2026

The source agrees with the accepted reduction. Review found one bounded mismatch:
`docs/lf.md` still recommended replacing a conversation after upgrade. It now
explains retry in place and same-Session resume for pre-fix clients. TESTING.md
states what the new installation proof actually exercises.

Upstream #1581 preserves live providers on reattachment, which explains why old
hook environments cannot refresh merely by attaching. #1583's locator enrollment
repair is separate and remains integrated. The merged #1586 waited-landing change
adds no executable-selection requirement. Infrastructure memory now replaces its
superseded automatic-restart claims. The only immediate child Wave, Release, has
been read in full: its operation-entry and stable scheduled-entry lessons reinforce
execution-time selection without establishing native upgrade acceptance. Its files
remain unchanged. Historical MTG observations remain separate from current direction.
