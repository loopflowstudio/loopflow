## Current implementation

Compatibility-aware executable selection precedes repository/Work resolution;
addressed Machine validation still precedes dispatch. Compatible explicit pins
survive; missing/incompatible pins fall back to the installed CLI. Selection uses
the migration validator or released preflight protocol with a five-second deadline.
Exec preserves argv, stdin and caller environment and replaces LF_BIN for nested
calls. Private Home, install/doctor and clone recovery retain their bypasses.
Installed hooks use the stable gate; development hooks keep their explicit binary.
A gate pin resolves at handoff to prevent a dispatch loop.

After promotion releases its lock (including settled reinstall), installation
schedules detached terminal owners
for proven-incompatible native attachments. Each owner repeats eligibility under
the Session launch lock, stops the exact provider under the attachment fence,
observes exit, and releases with an `upgrade` outcome that preserves the Session.
The winning owner presents a viewer using global `session.terminal` and reopens
saved history without input, retaining account, checkout and steer receipts. The
viewer attaches directly to that transport, so it cannot accidentally reconnect
to the old owner before the new attachment is bound. A stale recovery cannot stop
the replacement or present another viewer. Failed launches remain
inspectable and are not automatically retried; installation reports scheduling,
not successful continuation.

Only retained content-addressed launch bytes and an explicit incompatible-schema
verdict authorize restart. Mutable development paths, compatible clients and
unknown evidence stay untouched. Native Codex uses the existing app-server close
path and shared-conversation check. Structured Runs and Flow steps keep their
original execution. Pre-transport Sessions gain an owner, but their original
viewers do not move. This slice adds no migration or steer API change.
