# LOO-516: retained Codex relay failures

Accepted Task directive: Jack Heart requested on 2026-10-18 private durable relay
failure evidence tied to Session and AgentProcess, visible through history after
native logs rotate. Existing Sessions, accounts, drafts and terminal rendering
must survive. Original reset cause is unknown. Parent LOO-512 is merged (#1598).

## Accepted outcome and implemented approach (2026-10-18)

Use observed Session events, with no schema or DTO change. Retain operation,
direction, bounded error chain, input identity and original attachment identity.
Record unexpected renderer resets even when reconnect behavior treats them as a
normal disconnect. Explicit WebSocket close remains quiet. Diagnostics observe;
they never claim an attachment, settle a turn or write to the terminal.

Keep the first 16 diagnostics per captured input, each error at most 2048 UTF-8
bytes. Admission and insertion share a transaction, so reconnect storms cannot
exceed the bound. Preserve the initiating failure; later suppression is documented.
History show prints diagnostics, and --events includes their JSON payloads.
Retention is best-effort when the store is unavailable; a diagnostic write failure
cannot close the reconnect listener or print behind the renderer. No new retention
service, schema, DTO or attachment authority is introduced.

## Delete — do not maintain

- `log_codex_relay_failure` and the unbounded `codex-relay.log` writer in
  commands/util.rs. Preserve private evidence and reconnect listener survival
  on the Session event path.
- Free `client_result` suppression: move its behavior into the connection owner,
  retaining unexpected resets while preserving normal terminal exit semantics.

Both deletion targets are removed; no remaining deletion targets.

## Reconciliation (2026-10-18)

Main already contains LOO-512's fenced startup/reconnect repair (#1598) and
LOO-508's private output boundary (#1595). This change builds on those owners;
it does not replace startup recovery or establish the original reset's cause.

Relay operation context is constructed once per failure site, with direction
explicit at the client read/write boundary. Startup diagnostic assertions live
outside the PTY loop. History inspection reuses the existing input summary query
so a bounded diagnostic does not require loading the whole Session transcript.

The history reader previously derived AgentProcess only from a started native
turn, dropping identity on standalone observations. It now preserves the observed
event's recorded identity; the connection-failure test covers that behavior.

Startup injections can leave native Codex unable to reconnect before completing a
turn. Each startup probe stops after retained diagnostic readback, without
demanding native startup recovery. Cleanup targets only identified disposable
providers; no existing Session was faulted. Gate observed an after-thread reset
retain its diagnostic while Codex 0.163.0 displayed "Reconnect failed" and timed
out. That native startup recovery limit remains unresolved; normal post-turn
reconnect and Unicode draft preservation passed separately.

Review found no bounded implementation mismatch requiring repair. Release's
operation-entry lesson applies: the real-Codex probes exercise launch and both
history outputs, while fixture success establishes no installed-store acceptance.
