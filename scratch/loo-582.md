## Selection and recovery contract

- An unfinished interactive Session selects itself through
  `LF_AGENT_CALLER.session_id`, or looks up its provider-independent Loopflow ID.
  A shell must pass `--session`; `lf session list --json` supplies IDs. The shared
  resolver also accepts recorded provider IDs. Never choose promotion's Session
  by recency, title or provider. Headless Runs do not become primary; finished
  Sessions remain assignable with `session bind`, without being reopened.
- Explicit sources override the invoking Session. An invoking Session in a
  different selected checkout is not implicitly promoted. `--worktree` selects
  an existing linked checkout and never replaces another Task's checkout.
- Repeating creation in an owned checkout or from its bound Session returns the
  same Task. `--new` files independent backlog work. Conflicting permanent binds
  remain intact. Creation, placement/claim, binding and primary selection commit
  together; failed reservation leaves them uncommitted. A lost success reply is
  recoverable through the selected Session or adopted checkout. An unselected
  shell create in a shared checkout has no existing-work identity to recover.
- Main, repository and Wave checkouts stay shared. Promoting a shared primary
  releases its old primary scope and binds it prospectively in the transaction;
  that scope may open another conversation. Ordinary Wave assignments and
  permanent Task binds remain. Creation/retries never schedule a move merely
  because the Task later acquired a separate checkout.
- Remote promotion uses existing paths and Sessions on the target Machine,
  without provider launch preparation; explicit `create --run` still prepares
  launch. Record an open branch PR when `gh` supplies it.
- Desktop distinguishes assignment from primary selection. Already-assigned
  non-primary Sessions expose primary selection in the palette and Task menu.
  Keep the selected terminal and composer.

## Implemented behavior — reconciled 2026-11-03

Checkout admission spans source resolution and commit. Source resolution
reconciles checkout and Session Task IDs before loading their Task. Ordinary
creation uses the same transaction without placement/binding. Placement and
promotion share branch/PR preparation and store writers; no promotion record,
new ownership model or attachment lifecycle is needed. The Task has one migration,
`task_session_promotion.sql`.

Explicit promotion into an already-placed Task stores `requested_cwd` in the
binding transaction. The current cwd and attachment stay intact until the next
idle connection. Workspace admission uses the existing launch lock and Session
summary; provider resume receives that cwd and native identity. OpenCode applies
its native move endpoint. Missing paths and failed moves retain the request,
even after another Session becomes primary. Provider identity confirmation clears
only a request matching the connected process's cwd, through one shared writer.

Directory reports use the execution Machine's OS hostname, existing serialized
transport and snapshot replay. The parser waits for a complete sequence boundary.
Native spawning reports its directory once; the separate OpenCode client reports
on spawn, and exec handoff reports on first provider output. On return, normal
shell integration owns the shell directory report.

No remaining predecessor path was identified. Removed promotion's
recency selector, shared-primary refusal, separate no-source creation path,
implicit different-checkout refusal for Session selection, and OpenCode's reuse
path that ignored changed native location. Removed the one-off requested-workspace
reader, duplicate provider-confirmation SQL and cwd plumbing through
`native_return`; Session summaries, the shared connection writer and launch
reports now carry those responsibilities. Explicit `--worktree` refusal,
permanent binds, shared creation and recorded subdirectories remain.
`checkout_conversation` remains for reopening
existing taskless conversations; SQLite creation retains recovery semantics.

## Concept review — 2026-11-03

Outcome: no design change and no open product choice. The implemented commands,
Desktop actions and shared writes follow Jack Heart's accepted experience.
Assignment and primary selection remain useful distinctions: a Task may have
several conversations while opening one by default. Promotion composes those
existing operations; it needs no separate durable object or workflow.

The consequential boundary remains creation in place versus explicit continuation
in an existing Task's checkout. Keep the requested destination on the Session
until its connection confirms it. Losing primary status must not lose that
request; a missing destination or failed provider move must remain retryable.
Likewise, a second conversation in the same checkout must not become selected
through recency, and later Task placement must not relocate a conversation
promoted in place. These counterexamples fit the accepted model without another
product decision.

Next proof remains the combined gate and configured demo described below,
especially an unsent draft or pending input across idle ending and Task progress.
Source and fixture review cannot establish rendered continuity or Cmd-T behavior.
