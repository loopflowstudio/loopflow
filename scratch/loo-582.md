# LOO-582 — promote existing work

## Accepted design — Jack Heart, 2026-11-03

Upgrade an existing worktree and/or Session into a Task, retaining cwd (including
subdirectories), branch, dirty/untracked files, provider history, live process,
drafts and input attachment. The selected conversation becomes primary without
another agent, replayed turn, implicit Graph or Auto-Ship approval. CLI and
Desktop share the operation. Existing association keeps Task identity; retries
must not duplicate work, and conflicting permanent Task binds remain intact.

Jack Heart resolved Session selection: an unfinished interactive Session may
select itself through `LF_AGENT_CALLER.session_id`, or look up its existing
provider-independent Loopflow ID. A shell must explicitly select `--session`;
`lf session list --json` supplies IDs. The shared resolver also accepts recorded
provider conversation IDs. Never infer permanent assignment from recency,
title or provider. This applies in already-owned checkouts with another primary
and in shared checkouts. Headless Runs retain their lifecycle and never implicitly
take primary. Finished Sessions remain assignable through `session bind`;
promotion does not reopen them. Explicit sources override the invoking Session;
an invoking Session in a different selected checkout is not implicitly promoted.

`task create` adopts an unassociated linked checkout; `--worktree` selects one.
Without an explicit or invoking Session it binds no conversation and chooses no
primary. Repeating creation in an owned checkout returns its Task; `--new` files
independent backlog work. `task promote ISSUE` associates an existing Task.
Record an open GitHub PR on the adopted branch when available through `gh`.

Main, repository and Wave checkouts remain shared. Selecting a shared primary
releases its former primary scope and binds it prospectively to the Task in the
same transaction; the former scope can open another conversation. Its cwd stays
shared even if the Task later gains a separate checkout. Ordinary Wave assignments
and permanent Task bindings remain intact. Remote promotion selects existing
paths and Sessions on the target Machine, without provider launch preparation;
explicit `create --run` still uses launch preparation.

Desktop keeps ordinary assignment distinct from making a conversation primary,
explains permanent assignment and checkout behavior, and retains the terminal
and composer. Already-assigned non-primary Sessions expose primary selection in
the palette and Task menu without creating a Task or offering reassignment.

## Implementation and deletion boundaries

Creation, placement/claim, prospective binding and primary selection share one
SQLite transaction. Checkout admission spans source resolution and commit.
Source resolution reconciles checkout and Session Task IDs before loading their
Task once. Ordinary creation uses the same transaction without placement/binding.
Placement and promotion share branch/PR preparation and store writers; no new
promotion record, ownership model or attachment lifecycle is introduced.

**Delete — do not maintain** (completed):

- `promotion::select_checkout_conversation` and its recency fallback. Retain
  `SqliteStore::checkout_conversation` for reopening taskless conversations only.
- Repository/Wave primary refusal in `resolve_source` and `promote_task`, and the
  ancestry trigger's unconditional Wave-primary permanence. This Task's single
  `task_session_promotion.sql` migration releases shared primary scope while
  preserving ordinary Wave assignments, permanent Task binds and captured history.
- Bound-Session cwd relocation in `primary::admit_workspace`.
- Desktop's “Use Session and checkout as Task home” wording.
- The no-source creation shortcut in `promotion::save`; its transaction already
  handles creation without placement or a selected conversation. Remove the
  unused async `Store::create_task` wrapper; its sole fixture caller now seeds
  through `SqliteStore::create_task`, which retains creation-recovery semantics.

Keep the SSH dispatch and release-guidance fixes. Do not edit the live LOO-718
mobile checkout `/Users/jack/src/loopflow.mobile` or its bootstrap patch.
No Wave is selected and no Wave memory is changed.
