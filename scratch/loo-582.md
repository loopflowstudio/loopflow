# LOO-582 — promote existing work

Jack Heart expanded the accepted outcome on 2026-11-03 to preserve an existing
worktree and/or live Session when making it a Task. Implementation design,
2026-11-03: reuse Task placement, prospective Session binding and the primary
pointer. Creation, placement and binding commit together; a failed reservation
rolls them back. Checkout admission serializes competing source promotions.
No provider launch, input publication, file move, Graph or Auto-Ship approval.

`task create` adopts an unassociated linked checkout and its invoking interactive
Session, otherwise its last conversation. `--session` and `--worktree` select
sources explicitly. `task promote ISSUE` adopts them for an existing Task.
Retries return the existing Task; conflicting ownership fails without moving
work. Creation in an owned checkout returns its Task; `--new` files independent
backlog work. Planning skills and fixture builders now state that intent.

Main/repository/Wave checkouts remain shared. An ordinary create there files a
Task without placement. An explicitly selected unfinished interactive Session
can bind without moving cwd. Repository/Wave primary conversations retain their
scope. Bound Sessions preserve cwd, including subdirectories, on continuation;
an explicit later Task checkout may give a Session-only Task a separate home.
Remote calls use the selected Machine's paths and Sessions, never transfer live
work. PR lookup applies to GitHub repositories and records an existing open PR.

Delete — do not maintain: the inline transaction bodies of
`SqliteStore::place_task`, `bind_session` and `choose_task_primary` now delegate to
one shared writer each. `task_create` no longer unconditionally files work.
`prepare_task_placement` and promotion share branch/PR preparation. No schema
migration or second placement/binding representation was introduced.

Also removed: promotion's synthetic `promoted` WorktreeSegment and new-worktree
planning; the selected checkout already supplies its path and branch.
`TaskPlacement.requested_agent` and `.directive` are gone; checkout execution
reads its existing options. Desktop infers create/promote from its selected Task
instead of a second boolean. No remaining deletion targets.

Remaining: gate the affected boundaries below; configured-provider and rendered
Desktop judgment belongs to demo/review. The live mobile checkout was untouched.

Gate scope: `session_lifecycle_tests`, `work_open_tests`, `task_initialization_tests`,
`task_github_cache_tests`, `ops::task::tests`, CLI dispatch (`binary(lf)`), documented
commands and Wave resolution; provider planning creation callers now pass `new`.
Desktop Session controls already have a headless pass; formatting is applied.
Broader gate and Clippy remain with their Graph steps.
