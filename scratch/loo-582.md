# LOO-582 — promote existing work

## Accepted contract — Jack Heart, November 4, 2026

Jack Heart requested immediate Session directory selection on binding, replacing
all pending-directory and provider-confirmation proposals. Binding is an
irregular explicit operation; live-process rough edges are accepted. Session
`cwd` is its selected directory. Process records retain where execution started.
A running command or unsupported live client may keep its old OS directory.
No move lifecycle, reconnect gate, implicit interruption, draft-transfer
orchestration, input replay or conversation fork is authorized.

- `lf task create --session SESSION --title "Finish prototype"` creates around
  the exact conversation and its existing checkout, retaining subdirectories,
  branch/open PR, dirty/untracked files, native identity, history and input.
  `--worktree PATH` adopts only that checkout; both selectors can be combined.
- Plain creation always files separate work regardless of cwd or caller Session.
  `--run` only starts the created Task; explicit sources also work with `--run`.
  No `--new`, `--primary`, or `task promote`.
- `lf session bind SESSION --task TASK` permanently associates an unfinished
  interactive Session, makes it primary and immediately sets cwd to the Task's
  existing worktree. Same-worktree subdirectories stay intact. Repeating bind
  reselects the same conversation. Other conversations stay associated.
- An open unplaced Task can adopt the selected Session's unowned linked checkout.
  A done unplaced Task binds in place without adopting a checkout or reopening.
  A done placed Task retains its checkout and selects that directory.
- Main and Wave checkouts stay shared. Selecting their primary releases the old
  primary scope atomically. Ordinary Wave assignments and conflicting permanent
  Task bindings stay intact. Closed Sessions and headless Runs cannot be primary.
- Adoption uses explicit Loopflow or recorded provider identity, never recency.
  An agent supplies its own `LF_AGENT_CALLER.session_id` or exact lookup; shells
  also name a Session explicitly. Creation/binding starts no implicit Graph and
  grants no Auto-Ship approval. Task identity survives retries.
- Membership, primary selection and cwd commit together. Capture/history usage
  remains prospective. Native identity and files remain intact; a database cwd
  change does not prove an already-running provider moved.
- Remote commands use the target Machine's Sessions/paths without account setup.
  Explicit create-and-run retains normal launch preparation. The live LOO-718
  mobile checkout/bootstrap patch is outside this Task's modification scope.

Jack Heart authorized publication to existing PR #1807 and a stop at interactive
demo. The active Graph owns publication and the later combined gate. No Auto-Ship

## Implementation and deletion cut

CLI and Desktop share `human_session::bind` → `task::adoption::bind_session` →
`SqliteStore::promote_task`. Explicit creation shares that transaction. The
transaction now writes cwd immediately. Existing connection paths consume that
selected cwd and preserve native identity; OpenCode uses its existing native move
endpoint on connection. Binding leaves the live transport and input alone.
Terminal directory reports still describe execution through the serialized
transport; the verified exact-hostname repair remains intact.

Ordinary primary workspace preparation retains an intervening explicit bind:
retain bound cwd in the write transaction and return the selected directory
instead of overwriting it with a workspace prepared for the old scope.

The pending-directory deletion is complete. Removed
`requested_cwd`/`requestedCwd` from Session models, summary SQL, DTOs,
migration, provider confirmation, workspace admission and Desktop banners;
removed the missing-destination fixture exclusive to that gate. Also removed
`task promote`, optional-primary/public assignment-only binding, implicit
creation adoption and terminal-Task checkout allocation. The private historical
assignment primitive, ordinary unbound workspace preparation and the single
migration's released ancestry/permanent-bind fixture remain necessary.

Compression retains the transactional stale-opening protection while returning
early for Sessions without a primary scope. Adoption reuses its resolved checkout
root to preserve subdirectories without another Git query. Provider-thread writes
no longer pass through a leftover confirmation wrapper. Continuity fixture setup
uses SQLite directly; the exercised CLI/provider path stays unchanged.

## Concept review — November 4, 2026

No design change or open product choice. Jack Heart's accepted single-directory
contract removes a move lifecycle: Task membership, primary selection and the
Session's selected cwd commit together; Process cwd remains execution evidence.
The CLI, Desktop actions, usage docs and work skill express that same contract.
The remaining private historical assignment writer is not a second public bind
mode. Provider connection errors remain connection errors, not pending binding.

The normal path creates around the explicitly selected chat and checkout without
changing their identity or launching work. A conflicting permanent assignment or
failed reservation leaves the transaction unapplied; retry resolves the same
source. Binding to an existing placed Task changes selection immediately while
leaving the live process and files intact. If OpenCode rejects its later native
move, connection fails and can be retried with the same identity and selected
directory. An older workspace opening cannot overwrite the explicit selection.

The retained counterexample is a running client still executing in its original
directory after bind. Jack accepted that behavior; it invalidates a live-move
claim, not this model. Desktop composer continuity still needs configured proof.
No next implementation direction is required; the next proof remains the authored
demo, followed by the combined gate. This review inspected code and existing
tests without rerunning them or changing implementation.
