## Build/cache contract

Each worktree keeps its own mutable Cargo target. Ordinary Cargo builds work
without sccache; failed cache service falls back to direct compilation with
`RUSTC_WRAPPER=`. Do not share targets, clean production targets for a cache hit,
run separate servers against one local cache, or restart a shared daemon from a
rustc wrapper.

Installed sccache 0.19.0 missed identical libraries across roots. The verified
experimental binary is upstream
`ca81ec2a2566efc623692741440d99c710268841`, containing Rust basedir normalization
and verbatim environment dependencies. Each absolute root must be listed before
its daemon starts; their parent alone is insufficient. Keep runtime path inputs
`CARGO_MANIFEST_DIR`, `CARGO_MANIFEST_PATH` and `LOOPFLOW_BUILD_SOURCE_ROOT`
verbatim. Runtime checkout identity must remain correct.

Root inventory comes from `git worktree list --porcelain -z` plus the current
canonical root, preserving spaces and newlines. `scripts/dev-lf` invokes
`scripts/build_cache.py` before Cargo. Under a file lock it atomically refreshes
`XDG_CACHE_HOME/loopflow/sccache.json` (default `~/.cache`), retaining other
repositories and the Machine's default cache settings. The build selects that
file and verbatim identity dependencies; no new scheduler, service or restart
RPC exists. The existing daemon keeps its configuration until natural idle
shutdown. Ordinary Cargo does not refresh the inventory; explicit `SCCACHE_CONF`
and isolated builds remain caller-owned. The Machine's Cargo configuration and
wrapper are untouched. LOO-908 remains historical, not an integration prerequisite.

A cross-root hit retains A's absolute source/debug/generated-source paths in B's
rlib; the November 14 model and definition-content probes observed this despite
correct runtime identity. November 15 direction removes that as an extraction
stop. `scripts/dev-lf --isolated-build <lf args>` uses `target/isolated`, disables
both rustc wrappers and sccache, and leaves normal targets/cache intact. Normal
builds honor CARGO_TARGET_DIR and run its executable. No source remap or retention
service is selected. Binaries/tests still compile/link even on library hits.

**Experience.** Edit a command's arguments or rendering in one checkout, build
normally, and reuse unchanged execution code. Running or resuming the same Task
through a terminal or Desktop reaches the same operation, saved cursor and
provider conversation. A failed reply remains inspectable without replaying the
operation. No new command, Work record or execution approval is needed.

The engine already describes this contract, but shared operations still call
CLI handlers. Start by moving the operation implementations and their result
types below both adapters: account operations currently routed through
`lf::AccountCommand`, launch log/release bookkeeping under `lf::commands::graph`,
and PR sync/retry orchestration under `lf::commands::ops`. Engine call sites
at `630b8a7aae`: `engine/account.rs` builds `lf::AccountCommand` variants
(connect/disconnect/set/use/pause/unpause and their error classification);
`engine/launch.rs` uses `graph::PendingLog`/`release_launcher`; `engine/pr.rs`
uses `ops::with_sync_retry`; `engine/checkout.rs` calls `ops::run_sync_in`;
`engine/wave.rs` calls `ops::planning_wave`. `engine/config.rs` reaches
`graph::EnvVarGuard` only in tests. Keep argv parsing,
interactive confirmation and terminal rendering with the CLI. Both adapters
call the same typed functions; delete the old implementation rather than adding
another forwarding layer. Keep existing wire shapes and error classifications.

This is preparation for a substantial execution/application crate cut, not a
decision to move all of `engine`, `ops` or `lf` as directories. Follow the actual
production dependency closure through launch, settings, observations, storage
and recovery. Provider acquisition stays above storage. Runtime code must not
require a Clap command or construct `Cli::default()` to recover launch settings;
pass the existing resolved values, preserving their source and precedence.
Keep records with their existing owners unless a real independent consumer
requires otherwise. Choose the final crate membership from that closure and
semantic PR co-change, then demonstrate command-only versus runtime rebuilds.

**Normal, failure and recovery.** Preserve these counterexamples in the cut:

- A served request starts a detached execution and returns its registered Process;
  ending the request must not end that Process. Move launch bookkeeping with its
  execution owner, without moving process-wide descriptor redirection into served
  mutations. Directory and `CommandIo` stay request-local.
- A lost launch reply may follow a committed creation. Retain the creation key,
  saved receipt and unknown outcome; never turn an adapter retry into a new launch.
- Account recovery retains native thread, pending input, settings precedence and
  once-only usage. A model or login selection is not a new conversation.
- PR sync/retry retains the exact head, uncertain publication and waited landing;
  moving it cannot replace a live worker or restart completed Graph effects.
- An initial lower-crate edit must refresh application dirty provenance even

### Implemented preparation — contracts extraction carries

The Concept, Resumed, Continuation, Shared-connection and Extraction reviews
that produced these are in `b555f1de54:scratch/loo-650.md`.

The synchronous store owns saved facts and atomic SQL effects; the application
owns observed inputs and policy. The `Store` facade under `store/` is application
code; moving it wholesale would recreate the coupling under a new crate name.
Direction: application policy/runtime → synchronous storage → saved values. No
callback from storage into configuration, catch-all core crate or second resolver.

- Reads: SQL returns scope with batched saved evidence from one savepoint; the
  application observes configuration after the mutex releases, once per
  repository, inside the caller's pinned Work snapshot with external revision
  tracking. No per-Task queries.
- Mutations: acquire outside SQL; the command transaction compares the saved
  inputs acquisition used (repository/Project/ancestry/local person, held set,
  candidate rows) and returns stale for reacquisition. Current saved ownership
  still decides; a configuration change never rewrites an existing claim.
  Applies to ownership, placement, Machines, rentals, peer import, Wave bootstrap,
  repository registration, account selection and Dashboard/Task order.
- A general `Store` connection cannot release its mutex inside a savepoint: read
  in a short local savepoint, observe outside, compare the complete ordered batch
  in the final savepoint. No transaction spans OS/file acquisition.
- Session projection filters availability before limit/cursor paging from batched
  observed identities; a quiet deadline that advances time reruns filtering and
  page membership. Task selections use the same projection.
- `process::attachment` coordinates resume/close/settlement; SQL transfer guards
  keep the fence through atomic claim. Splitting that sequence into independent
  calls would let a replacement interleave with takeover.
- Account selection compares candidates, limits and the newest selection at
  commit, rereads preferences on retry, and keeps an unchanged empty choice read-only.
- A locator written before a rolled-back commit is reused; conflicting retained
  identity is refused. A moved Wave is never renamed back, a retired one never
  resurrected; authored files go to the requested checkout, saved Work to the
  canonical address.
- `run_sqlite` stays an attributed application adapter; write transactions stay
  command-owned.

uncertain/conflicting deliveries; a served watch notices ignored-config and timed

### Storage ownership — implemented November 15

Saved facts, atomic SQL effects and storage's own sidecar files live in storage.
Retention cursors, Session/admission locks and steer markers stay beside their
transactions; touching a steer marker after commit would reopen the hook race.
Configuration, Git, ambient caller, process and provider observations stay above.
Saved records live with storage unless a storage-independent crate needs them;
only then do they belong in `loopflow-model`. This keeps ordinary record edits
from rebuilding terminal. Acquisition module paths stay until measurements
select the next owner.

Token acquisition is lazy and application-owned. An explicit key file never
inspects the keyring; a locked keyring containing encrypted Machine credentials
cannot mint a second key. The migration runner keeps its exclusive transaction,
Session fences and application exporter/process observations through commit or
rollback. Direct rename/bind/attach checks the caller for either title source;
title repair has no caller. Served writes keep request attribution.

Repository registration accepts historical raw spellings. Application lookup
observes canonical aliases outside SQL and compares the complete saved candidate
reading at commit. Display addresses and Graph records sit with storage;
repository/Wave discovery and compilation stay above. Captured Task Graphs and
cursors cross SQL as saved JSON and decode in `store::task_work`.

Capture history selects and reads one input's scoped evidence below storage;
the application validates the complete manifest and projects it. Activity still
checks the settled bound before reading evidence, so an invalid older row
cannot fail the page. No eager page transaction, partial decoder or repair write.
Native input attribution, once-only usage and completion semantics stay intact.
