## Build/cache contract

Each worktree keeps its own mutable Cargo target. Ordinary Cargo builds work
without sccache; failed cache service falls back to direct compilation with
`RUSTC_WRAPPER=`. Do not share targets, clean production targets for a cache hit,
run separate servers against one local cache, or restart a shared daemon from a
rustc wrapper.

Installed sccache 0.19.0 missed identical libraries across roots. The verified
experimental binary is upstream
`ca81ec2a2566efc623692741440d99c710268841`, containing Rust basedir normalization
and verbatim environment dependencies. Each absolute root must be listed before
its daemon starts; their parent alone is insufficient. Keep runtime path inputs
`CARGO_MANIFEST_DIR`, `CARGO_MANIFEST_PATH` and `LOOPFLOW_BUILD_SOURCE_ROOT`
verbatim. Runtime checkout identity must remain correct.

Root inventory comes from `git worktree list --porcelain -z` plus the current
canonical root, preserving spaces. One shared daemon applies refreshed config
only while idle; new roots may compile with misses meanwhile. The November 14
LOO-908 read returned done, no PR, closed Sessions: no live root-refresh
integration was delivered. Do not reopen it or invent a hidden scheduler here.

A cross-root hit retains A's absolute source/debug/generated-source paths in B's
rlib; the November 14 model and definition-content probes observed this despite
correct runtime identity. November 15 direction removes that as an extraction
stop. `scripts/dev-lf --isolated-build <lf args>` uses `target/isolated`, disables
both rustc wrappers and sccache, and leaves normal targets/cache intact. Normal
builds honor CARGO_TARGET_DIR and run its executable. No source remap or retention
service is selected. Binaries/tests still compile/link even on library hits.

### Resumed concept review — November 15

**Design changed; iterate to implement. No open product choice.** The synchronous
store owns saved facts and atomic SQL effects; the application owns observed
inputs and policy. The existing `Store` facade is still application code even
where its files sit under `store/`. Moving that facade wholesale would recreate
the coupling under a new crate name.

Keep these contracts in the extraction:

- Read APIs return scope with batched saved evidence. Observe configuration after
  releasing the local SQL lock, retaining the enclosing request's pinned reading
  and external revision tracking. This supersedes the earlier instruction to
  acquire configuration before every read. Ownership labels and peer imports also
  depend on Machine declarations, participant identity and scope defaults; moving
  only `planning_client::connected` leaves application acquisition inside SQL.
- Account selection must remain one effective decision under concurrent launches.
  Implemented API: read candidate accounts, raw limits and selection state together;
  apply account preferences, alias reconciliation and ranking above storage;
  conditionally record the selection against the saved facts used to choose it.
  If any SQL fact affecting eligibility or ranking changed, re-read and recompute
  before returning a selection. Checking only the chosen account's capacity
  revision is insufficient: another candidate or launch can change the winner.
  Keep monotonic selection ordering and the existing no-candidate result. Do not
  replace the current transaction with an unconditional later timestamp write.
- Process insertion takes the attaching start receipt and transport identity as
  values from the command boundary, preserving their atomic insertion with the
  child. Session projection takes its reading time and returns the information
  needed for application deadline observation; retain the existing recomputation
  when that observation advances time. Removing `observe` imports alone would
  leave quiet Sessions stale until another database write.
- Keep migrations, schema catalogue and generated SQL with synchronous storage;
  move their build inputs together, byte for byte. Keep `run_sqlite`, request
  attribution, observation inheritance and recording-gap behavior above it.

Normal path: a Task watch reads saved receipts once, observes each repository's
configuration, and presents the same delivery state. Failure: the provider is
disconnected or a quota poll races a launch. Recovery: uncertainty/conflicts stay
saved; reconnection invalidates the watch, and a stale selection is recomputed
without discarding quota observations or selecting from old preferences. A served
quiet deadline must update without a store write. These are preservation checks,
not new lifecycle records or schema changes.

Build-tooling ownership is unchanged: Git supplies roots and one coordinated
shared-daemon owner refreshes them only while idle. It is still unbuilt. Do not
claim automatic reuse from the private probe. After storage, continue definitions,
providers and runtime; compare representative rebuild closures and whole-build
cost before the interactive demo/review. Existing usage and skill instructions
already describe the two build actions; no new command is proposed.
