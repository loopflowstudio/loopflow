# LOO-650: rebuild only affected code across worktrees

November 14 status: the model/content prototype and publication retirement are
implemented. The broader split is at review: cached debug sources retain another
checkout's paths, and shared-daemon root upkeep has no delivered integration.
Whole-application savings and the full Task outcome remain unverified.

## Outcome and review scope

An edit to Task shipping recompiles the application crates downstream of that
edit. Unchanged Loopflow libraries come from the shared compilation cache in a
fresh worktree. CLI commands, stored data, provider conversations and native
packages behave as before. This serves Infrastructure's self-hosting objective:
agents can advance Tasks without builds making the Machine unusable.

Keep the original problem: concurrent worktrees repeatedly compile one large
crate. Crate count is not the outcome. Neither splitting a tiny leaf nor lowering
Cargo jobs establishes the requested performance improvement.

Direction updated November 14: private path crates and crates.io retirement are
selected (exact words in publishing-discussion.md). The crate list remains
provisional: merged PR co-change patterns and production dependencies decide the
larger cuts. Prove the small extraction/cache mechanism before a broad split.

The October 27 Task brief reports load 254–277 on 16 cores, about nine concurrent
worktree builds, and 11 sccache hits / 878 compiles during a cold first 15 minutes.
These are historical observations, not a baseline for this checkout. At
`3fbf3d2ca3`, `rust/loopflow/src/**/*.rs` contains 330,396 lines including tests;
the brief's approximately 252k lines no longer describes this source tree.

## Cache finding: installed 0.19.0 is insufficient

On November 14, `uv run --no-sync python scratch/cache_probe.py` compiled the
actual dependency-free `src/command.rs` as a disposable library in two separate
source/target directories. Both absolute roots were in `SCCACHE_BASEDIRS` before
an isolated daemon started. Each build removed only its disposable target.

| Case | Rust hits added | Rust misses added | Wall seconds |
|---|---:|---:|---:|
| Cold A | 0 | 1 | 0.357 |
| Same A, empty target | 1 | 0 | 0.102 |
| Identical B, empty target | 0 | 1 | 0.148 |

This refutes cross-root Rust reuse with the installed binary. It is a cache-key
probe, not an lf speed benchmark or an integrated extraction. The probe used one
job, nice 10, a private cache/socket, and stopped its daemon afterwards.

[Tagged 0.19 Rust hashing](https://github.com/mozilla/sccache/blob/v0.19.0/src/compiler/rust.rs)
hashes cwd and Cargo environment values without basedir normalization.
[Rust cache restrictions](https://github.com/mozilla/sccache/blob/v0.19.0/docs/Rust.md)
also exclude linker invocations and incremental compilation: binaries and test
executables still pay compilation/link costs. Cache hit percentage alone cannot
measure the outcome.

Upstream added Rust basedir support in
[`cfb169c2e261a4a58eb033aadaee05735a123a61`](https://github.com/mozilla/sccache/commit/cfb169c2e261a4a58eb033aadaee05735a123a61).
The inspected successor
[`ca81ec2a2566efc623692741440d99c710268841`](https://github.com/mozilla/sccache/commit/ca81ec2a2566efc623692741440d99c710268841)
adds `SCCACHE_BASEDIRS_VERBATIM_ENV_DEPS`. Use a version containing both changes
for the next isolated probe; no binary containing them was built or installed
here. Prefer an upstream release, otherwise a pinned upstream build for the
experiment, not a Loopflow cache implementation.

Runtime path values must retain their meaning: configure verbatim tracking for
`CARGO_MANIFEST_DIR`, `CARGO_MANIFEST_PATH`, and
`LOOPFLOW_BUILD_SOURCE_ROOT` when read by compiled code. A cached binary reporting
another checkout's source identity is a failure even if it runs. Leaf libraries
should embed no checkout provenance. Debug/source paths and generated includes
need explicit inspection in the prototype; do not erase meaningful paths merely
to force a cache hit.

### Keeping roots current

Git's `worktree list --porcelain -z`, plus the current canonical source root,
owns the root inventory. Recompute it at build entry, preserving spaces, with no
Task/store dependency. List each worktree root: stripping only a shared parent
leaves different worktree names in the key.

Choose one machine-wide sccache server and local cache. Basedirs are startup
configuration, so changing a shell variable under an existing daemon is
insufficient. Refresh the generated root configuration atomically; apply it at
a quiescent server restart, coordinated with LOO-908's build entry/admission work.
While that refresh is pending, a new root may miss; it must still compile. The
prototype must demonstrate adding/removing a root, actual server configuration,
and reuse after refresh before claiming automatic maintenance works. Do not stop
a shared daemon from an arbitrary rustc wrapper.

[Local cache documentation](https://github.com/mozilla/sccache/blob/main/docs/Local.md)
rules out the tempting per-worktree-server shortcut: concurrent servers sharing
one local cache can race and fail builds. A shared Cargo target directory would
instead serialize worktrees and is also excluded. If the LOO-908 integration
cannot provide quiescent refresh, root maintenance remains unresolved; do not
substitute a hidden scheduler in this Task.

## Delete — do not maintain

For every completed extraction, remove its source module definitions and
exclusive tests from `rust/loopflow`; tests live with the one implementation.
Existing public Rust module paths may re-export that implementation where callers
still require them; no forwarding functions or duplicated DTOs. Internal callers
use the new owning crate directly. The binaries retain their names.

When store moves, remove its application-side SQL implementation, not its
transaction/snapshot guarantees. When build generation moves, delete the old
generation branch; retain byte-identical schema/migration order and builtin
content. Never move release schema data independently from its catalogue.
If publishing is retired, delete `_publish_crate`, the crates.io verification
step and their exclusive tests together; do not repair them in parallel.

Forbidden: a catch-all replacement core that still recompiles everything, duplicate
wire models, an internal crate depending on the application, two implemented
publishing mechanisms, a shared mutable target, cache-key normalization that
changes runtime source identity, or cache hits presented as an lf speedup without
whole-build measurements.

Wild success: most Task edits compile only the application and relink; new

failure: type ownership drifts back upward, a common build script invalidates all
libraries, or generated publication code becomes a second architecture. The DAG,
invalidation report and unpacked-archive build must catch those failures.

## Concept review — November 14

**Return to loop-or-next: open product choice.** What source-debugging
experience must a cross-worktree cache hit provide after its producer checkout
is deleted? The publishing decision and staged extraction stand; neither answers
this question. No production code changes belong to this review.

The intended interaction remains `scripts/dev-lf --version` in a fresh worktree:
Cargo builds the changed dependency closure, a shared cache supplies unchanged
libraries, and the executable identifies this checkout. Developers should not
manage a second build lifecycle in Tasks or the store. The implemented prototype
has two private library owners and an isolated cache experiment; automatic
Machine configuration and whole-application savings remain proposed.

| Action | Concept | API or owner |
|---|---|---|
| Edit shipping and build in B | Cargo dependency closure | application → private model/content crates; Cargo owns freshness |
| Reuse an unchanged library | disposable compilation artifact | sccache Rust basedirs; checkout-sensitive environment values stay verbatim |
| Add or remove a worktree | derived source-root inventory | Git worktree listing; one shared daemon applies configuration while idle |
| Debug a cached frame after A disappears | source corresponding to the compiled bytes | unresolved source lookup contract, separate from runtime checkout identity |
| Cache unavailable | ordinary compilation | direct Cargo build with `RUSTC_WRAPPER=`; no Task/store transition |

The source-root list is derived configuration, not another durable Work record.
Cache loss may cost compilation; it must not lose source changes, native history,
stored records or runtime identity. Model records and builtin text keep their
current owners. Discovery, observed reads, request attribution and execution stay
application-owned until their real dependency cuts are designed.

**Open question 1:** (a) must cached frames find the exact compiled source
automatically after A is removed, or (b) is documented manual debugger mapping
to matching source acceptable? Option a needs a source mapping/retention design;
option b adds a developer recovery action. Neither is selected. Mapping blindly
to B is insufficient: B can have different bytes at the same relative path.
Stripping debug information or changing runtime paths is not an answer implied
by the existing design. Keeping reuse experimental is the current state, not
completion of the original outcome.

The existing probe supplies the normal case (B hits; semantic edits miss), the
failure (B retains A's debug paths) and partial recovery (a newly listed root
hits after private-daemon refresh with a fresh target). It does not demonstrate
debugger recovery after deleting A. Once question 1 is resolved, demonstrate
that case with both identical and diverged B source, including generated builtin
source. Preserve the earlier counterexample: existing pre-refresh dependency
artifacts can still miss; never clean production targets to make acceptance pass.

Shared-daemon root upkeep is an engineering gap: the November 14 LOO-908 read
delivered no integration. Its eventual owner must refresh only while idle,
allow unknown roots to compile meanwhile, and retain one daemon/cache with
separate targets. Do not treat the closed Task as an available implementation.

Proposed usage copy after source recovery is designed: “Build and run this
checkout with `scripts/dev-lf --version`. New worktrees reuse unchanged libraries;
pending cache configuration can cost a normal compile. [Document the selected
source-debugging recovery here.]” Existing build guidance remains accurate; no
builtin skill change is needed. Next show source recovery and root upkeep through
the ordinary build entry, then measure the full baseline/candidate builds before
claiming savings or resuming the larger extraction.
