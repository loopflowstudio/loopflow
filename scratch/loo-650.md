## Ownership and invariants

- `loopflow-model`: shared IDs, events and ownership values; definitions owns
  builtin content and portable syntax; terminal owns Ghostty state and its pin.
- `loopflow-storage`: records, SQL transactions, sidecars, migrations, catalogue,
  schema and historical fixtures. Task records stay here so their edits do not
  invalidate terminal/model. All 121 migration SQL files and historical fixture
  bytes remain unchanged; canonical schema is
  `0a506f2e3be6d80483304b52c6eca2b5ab3ce2ca87b66e5fae28bf9b49f4f596`.
- `loopflow-execution`: typed engine operations, domain execution, providers,
  native Sessions, Machine clients, shared readings, acquisition and policy above
  synchronous storage. It has no production or fixture dependency on `loopflow`.
- Application: Clap, CLI/server dispatch, framing, presentation, World and
  executable provenance. Shell/portfolio parser inputs convert to their existing
  operation values. Listing receives the adapter's typed command catalogue.

The application supplies one `BuildIdentity` at entry. Execution embeds no
application checkout/root/revision bytes. Cached lower code must describe the
running application in migration acquisition, provider context and diagnostics.
Landing selection receives the adapter's canonical Clap classifier, retaining
aliases, abbreviations, global flags and explicit definition kinds; a token
prefix classifier changes saved Graph behavior. No saved Graph field was added.

Request directories and `CommandIo` stay request-local. Remote account preparation
uses that directory. Detached work, creation receipts, native thread, pending
input, unknown remote outcome and once-only usage survive a lost reply. Shared
reads keep pinned snapshots, membership during unavailable readings, occurrence
cursors and overflow resync. No eager per-Task evidence loading.

External acquisition stays outside SQL; commands compare their complete reading
at commit and retry stale inputs. Migration preflight/export/process fences stay
inside the exclusive transaction; lazy credential-key acquisition stays above
storage. Retained locator identity survives SQL rollback. Historical aliases,
lease fences, paging past dead/unknown rows and indexed large-store plans remain.

## Cache contract and measurement

Each worktree owns its target. The selected compatible experimental cache has
SHA-256 `9d864b14017a948388011bd36e4ca445ec986d85846aced6d293c8bfd8e4ef67`;
its first verified upstream revision is
`ca81ec2a2566efc623692741440d99c710268841`. Stock 0.19.0 did not supply the tested
cross-root reuse. No Machine wrapper or shared daemon configuration was changed.

`scripts/dev-lf` refreshes the derived root inventory under a file lock, retaining
other repositories and caller cache settings. Existing daemons adopt it after
natural idle shutdown. Ordinary Cargo does not refresh inventory; explicit
`SCCACHE_CONF` remains caller-owned. Direct builds remain available with
`RUSTC_WRAPPER=`. Isolated builds use checkout-local `target/isolated` and bypass
both wrappers/cache. Retrieved execution/storage rlibs retain seed-root debug
paths; correct runtime identity does not make deleted source paths resolvable.

Selected-cache root upkeep passed miss-before-idle/hit-after-observed-idle with
correct identity. The instrumentation wrapper passed a two-root miss/hit check.

Comparison: baseline `3fbf3d2ca3`, source candidate `6b9878ffd8`, Rust 1.98.1,
matched profiles and retained dependency versions, one Cargo job, separate
cold-seeded caches and independent source/target roots. Eight unused registry
packages were removed. Five pairs alternate candidate/base then base/candidate.
Each fresh worktree then receives unique command-help, execution and Task-record
message edits. Links are timed. Two seed builds are calibration, outside medians.

measured tradeoff, not a uniform speedup. The report includes every range/sample.
CPU excludes the cache daemon; RSS is the timed tree's largest process, not
concurrent Machine memory. Two statistics RPCs per workspace compiler are
included. No total-Machine CPU or safe concurrency budget is claimed.

All five candidate fresh roots retrieved model, definitions, terminal, storage
and execution; only the application missed. Command edits compiled application;
execution edits compiled execution/application; record edits compiled
storage/execution/application. Unchanged lower libraries were Cargo-fresh or
cache hits. All 42 builds and twelve runtime identity checks passed; six catalogue
