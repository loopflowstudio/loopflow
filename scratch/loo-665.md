a rejected ordinary Codex credential even though the same account's stored copy
works. Recovery must preserve account choice, both credentials, active clients,
Session/native identity and history, without another login or global isolation change.

completed inference and installed behavior are distinct evidence.

Required cases:

- Native rejected, stored accepted: live status accepted; launch/resume uses valid
  access in the original home and retains displaced bytes.
- Native accepted, stored rejected: retain native; never revert to the stale copy.
- Both rejected: actionable reconnect for the selected account, no replacement.
- Timeout, 403/429/5xx, malformed or transport failure: verification unavailable,
  no fabricated capacity, no replacement, no surviving owned probe process.
- Wrong identity, concurrent replacement or preservation failure: retain newer
  bytes and refuse installation/spawn on stale evidence.
- Custom/shared/isolated homes, scoped selection and cached status keep their
  contracts. An existing client survives repair and completes another request.
- Reset resolves access first, then consumes once with the caller's key.

## Architecture and preservation

Provider files own credentials, provider responses own access evidence, SQLite
owns identity, routing intent, observations and Session associations. No schema,
DTO, health cache, preferred-home record or additional account representation.

`provider_account/codex_access.rs` owns one bounded resolution, used by status,
readiness, activation, save-back and reset. `subscription::codex_usage` owns raw
one-home observation, avoiding recursive polling/activation.

1. Preserve the caller's selected account and preferred home: matching native for
   ordinary status, the command's actual native home for shared launch, profile
   for isolated launch. Never substitute ambient home for an explicit custom one.
2. Validate expected email and per-user subject before and after observation.
   Same email with a different subject is not a repair source.
3. Try preferred first with account/read refreshToken=false and live limits. Only
   definite rejection permits one explicit managed refresh and re-observation,
   then the alternate same-account copy. A successful preferred probe never
   speculatively refreshes the alternate.
4. Recognize explicit auth markers and the observed -32603/HTTP 401 Unauthorized
   envelope. Other failures stay unknown; never expose raw provider error text.
   Missing limits mean unknown capacity; malformed limits are unavailable.
5. Snapshot secret bytes around provider work. A change permits one re-observation
   within the same 60-second deadline and per-home refresh budget. Each request
   retains its 15-second timeout; cancellation drops the existing process-group
   guard. No monitor or unbounded retry.

Status returns usage without copying. Cached status makes no provider requests.
Readiness consumes the resolver and checks the chosen token's forwarding lease
without another forced refresh. It reuses the account snapshot from its first
identity check, then rechecks current identity after provider work. Reset uses the
resolved connection for one consume; recovery never retries that mutation.

Launch keeps the conversation home. Divergent same-login copies require verified
repair; identical copies retain cheap activation and normal provider auth. The
same helper repairs isolated profiles. Readiness and launch do not change route
policy, account choice or history placement. Replayed routes still never install.

Native lock precedes the nonblocking managed-login lock; status/reset hold only
the managed lock. Hold native through repair and spawn. Locks serialize Loopflow,
not native Codex. Recheck contents before installation and retain the actual
outgoing inode, including later writes through an open descriptor.

Stage accepted bytes as a private durable `displaced` file in a private recovery
directory on the target filesystem. Sync, then use the existing directory-fd
exchange primitive extracted from Task file save into `platform/file_exchange`.
Read back both sides; changed bytes mean concurrent update and no spawn or blind
rollback. Retain both versions after success or uncertainty. Unsupported exchange
leaves target unchanged; never fall back to destructive rename. Preservation
storage is not a third selectable credential source and has no new scanner.
`SecretVec` owns snapshot zeroization; credential Debug deliberately omits bytes.

Save-back verifies divergent Codex copies: preserve working native updates, never
save rejected native over working stored, preserve both on unknown. Different-
account switching also exchanges the actual outgoing inode after save-back;
a pre-save hardlink would miss a provider's intervening pathname replacement.
Claude semantics and unrelated credential writers remain unchanged.

Completed-Session continuation reuses `claim_session_input` and its atomic input/
attachment admission. Compare captured completion with the current row instead
of refusing every completed Session. Preserve retirement so an old primary never
becomes primary again, native identity, earlier captures, outcomes and attribution.
Existing live-owner/death checks and attachment fencing still govern replacement.
