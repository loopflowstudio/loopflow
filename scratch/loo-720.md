## Cause and change

Before the repair, `run_prompt` emitted `working` under `lf/<process>` before both native and headless
launch. Native Claude execs into the provider; Codex/OpenCode redirect launcher
diagnostics while their UI runs. Neither native path updates that initial record
on turn completion. A provider's root idle/done report cannot replace a different
id. `Output::snapshot` replays the retained lf record on fresh attachment. The
shell cannot clear it until the native application returns to a shell prompt.
This is a deterministic source reproduction, not attribution of the
unidentified terminal in Jack's screenshot.

The initial report now belongs only to the headless branch. Native byte
passthrough, structured activity reports, Graph progress, exit/error/interruption
reports and idle-owner/input safeguards remain intact. No migration or new status authority.

Jack Heart's accepted outcome covers Rex and Desktop, completed turns, pending
input, silent active work, reconnect and clear. Provider detection and fresh-viewer
restoration use the existing owner. No native hook reporter, timeout fallback,
Desktop summary-priority change or data migration is needed.
