## Prior Graph concept review — November 3, 2026

Outcome: no design change and no unresolved product choice. The implemented
repair follows Jack Heart's accepted native-passthrough and structured-reporting
contract. Existing transport usage guidance describes that experience; no new
command, user distinction or skill instruction is needed.

The interaction remains: submit a turn → Working; reach an input request →
Blocked with its kind; finish → the provider's Idle or Done; submit the next
turn → Working. Silence does not change a claim. Detach and reattach restores
the current claims without requiring another turn. Clear removes evidence;
it does not synthesize Idle or complete the Session, Task or Graph.

The consequential mismatch was assigning a turn-level Working claim to the
lifetime of the native launcher. Native and structured work still need separate
producers, but no separate launcher activity lifecycle. `run_prompt` now emits
initial Working only for structured work. Provider bytes reach Rex directly;
the owner's Ghostty callbacks reduce them into existing `Records`, and
`Output::snapshot` replaces viewer records before continuing the stream.
Desktop receives the same reports through `ProgramStatusSurface` and
`session observe-status`; the existing provider-fenced store and watch projection
supply Session presentation. No schema or execution-authority change follows.

Preserve these counterexamples through acceptance:

- A native root becoming Idle cannot retire a genuinely Working nested command.
  Changing summary priority or clearing all ids on turn completion would hide it.
- A detached provider may ask for support and then wait for input. Recovery must
  retain its Blocked claim and metadata, including when no viewer saw it live.
- A malformed report or replaced observer cannot overwrite current evidence.
  Provider replacement must not inherit the prior provider's status; neither a
  dropped viewer nor an observation failure proves the provider has exited.
- A configured provider that fails to report settlement would invalidate the
  repair's sufficiency for that path. Absence of output cannot fill that gap.

Next proof remains the configured-provider and mounted Rex/Desktop acceptance
above, with the exact tested build recorded: completion, pending input, silent
work, clear, reconnect and the next turn. Exercise only a disposable conversation;
do not send input to or stop unrelated conversations. This review changes no
implementation and reruns no tests; the recorded fixture checks remain evidence
for their existing boundaries, not installed-host acceptance.
