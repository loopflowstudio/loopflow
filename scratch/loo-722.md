# LOO-722 adaptive disk cleanup

2026-11-04 implementation design, derived from Jack Heart's current Task directive.
Scope: the existing machine cleaner and its schedule. Rex-aligned installation is
owned by the separate Infrastructure Task. No live machine cleanup or job change
is part of this implementation run. Policy choices below are implementation
assumptions, not a separately reviewed design.

## Outcome and approach

The existing `scripts/disk-cleanup.sh` entry point launches one stdlib Python
runner, preserving the installed launchd path. The public installed CLI owns
native worktree/branch/monitor pruning; inherited LF attribution is stripped.
The runner shares verification recovery's nonblocking flock, bounds candidate
inspection (30 seconds), children (at most 2 minutes), and total work (30 minutes).
Failures remain nonzero; log-write failures do not prevent reclamation. Locks
recover on death and timed-out child process groups are killed and reaped.

Ignored, untracked generated roots are measured across checkouts under the source
directory. Cargo debug/release profiles can be reclaimed separately when the
whole target is retained. Shell cwd alone does not retain output. Open output
and builders inside the checkout do. Generated output needs 4 idle hours normally,
1 hour below 64 GiB, or 15 minutes below 32 GiB; recovering free space restores
normal retention. The thresholds use the existing resource policy.

Tracked content, symlink roots/ancestors, recent output, account history, SQLite
state and the newest regular backup per database remain protected. Home/cache/
Trash retention is unchanged. Largest measured candidates go first; decisions,
removed allocation, actual free-space delta, shortfall and failures form the
latest JSON receipt. APFS sharing and concurrent writes limit attribution of
free-space changes. New direct builds racing inspection remain unsupported.

Launchd installation uses the main checkout and a clean environment, hourly at
minute 17; removes only the old marked cron entry; preserves running jobs; and
restores the previous job if bootstrap fails. Dry-run inventories without deleting
candidates or running native maintenance, and preserves log history. The existing
job remains untouched here.

## Delete — do not maintain

Removed shell `run_skill`, cron installation, mkdir locking, unchecked pipelines,
checkout-wide cwd retention, and redundant/unbounded native build pruning.
The shell path is only a launcher. Rust retains its separate completed-Task
verification recovery contract and native worktree/branch ownership.
Replaced the idle-shell retention assertion and shell-failure text assertions
with output reclamation, live builder/open-output preservation and exit-status
checks. Removed unused inventory timestamps and repeated stat calls: traversal
uses its lstat result, so nested symlinks are never followed. Candidate cleanup
has one receipt path, including reinspection failures and successful removals
whose removal-log append failed. No deletion targets remain in this scope.

## Review findings resolved

A builder at `/` no longer retains every checkout. Candidate inspections cannot
consume the whole run indefinitely. Log append and rotation failures do not
prevent cleanup or hide successful removals from the candidate receipt.
Backup-shaped directories/symlinks cannot displace the newest regular backup.
Fixture lock redirection isolates tests from real host recovery without changing
production locking. The measured reclamation fixture removes at least 128 MiB
beside retained live output and unpublished source.
