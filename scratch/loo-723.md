# LOO-723 — coherent installation

Jack Heart requested one coherent installed runtime and verified rollout to the
desktop and mini on 2026-11-04. This is one PR; the auto Graph owns delivery.
Implementation decisions below are headless choices, not additional Jack decisions.

## Design

Keep the existing receipt-backed promotion as the activation owner. On macOS an
existing release app makes the installation app-inclusive, even with CLI-only
requested. CLI-only remains useful on app-free Machines. The shell installer and
Rust stream installer acquire the complete signed bundle; direct partial promotion
adopts an existing matching bundle or refuses before mutation with the full-install
remedy. Never splice a new helper into an older signed bundle.

Freshness requires the public entry to resolve to the bundled helper, matching
candidate identity and successful store preflight, plus the release app's metadata
and executables. Equal marketing versions alone prove nothing. Scheduled installs
use exactly the same decision. Explicit install completes its own receipt-backed
promotion instead of returning success after requesting an asynchronous app update.
Sparkle's explicit bundled adoption continues through that same promotion owner.
Do not opportunistically adopt an arbitrary old app before choosing the stream.

Only the Desktop executable is quiesced/reopened for bundle replacement. Session
owners and Graphs keep their running images; existing idle rollover owns retirement.
Retain renamed bundles while processes still execute them, including during cleanup
and recovery. Preserve signed bundles, retained rollback bytes and receipt recovery.
No schema change, no helper routing fallback, no private-dev selection change.

## Delete — do not maintain

Removed in this diff; no deletion targets remain:

- `published::finish_adoption` and its exclusive test: remove eager pre-stream
  adoption; preserve explicit `adopt` through validated promotion.
- `published::updates_itself`, `app_is_running`, `APP_UPDATE_LINK` and their
  exclusive test: delete asynchronous install delegation; preserve Sparkle UI
  and adoption, complete CLI/scheduled installation through promotion.
- Version-only app freshness: replace with paired identity/store/link checks.
- App-helper paths in promotion quiescence and bundle-id-wide quit: preserve
  running Sessions; stop only exact Desktop executables.
- Unconditional superseded-bundle deletion: retain live images until idle.
- `published::preflight` and the second freshness preflight: canonical public-link
  equality proves the helper and CLI are one executable, which is checked once.

## Preservation / acceptance

Focused implementation: published-install and artifact/process Rust modules;
shell installer Python file. Gate: installation/recovery fixtures in disposable
OS accounts, existing rollover tests, architecture checks and release docs checks.
The affected Rust consumers are `lf::commands::install::`, integration
`local_promotion::`, and `global_commands` (scheduled installation). Gate also owns
`cargo clippy --all-targets -- -D warnings` and disposable-account installation
recovery; ordinary host tests must not run production preflight/promote.
Counterexamples: CLI-only with/without app; same version/different revision;
broken or incompatible helper; detached public entry; interrupted promotion;
live helper through app replacement; custom Applications directory; schedule.

After landing, publish/acquire a complete signed main build containing this change
and install via the supported path on desktop and saved Machine `mini`
(`mini-heart`, `home_87e5dc2c4d2e0cac17957a17c89c5c50`). Verify app/helper/public
CLI/gate source identity and store compatibility, run the scheduled context,
and inventory surviving old owners without interrupting their work. Both Machines
must be verified before Task completion. A merged PR alone is insufficient.

LOO-722 owns cleanup; LOO-724 owns existing-session hooks. Neither is implemented
here. No parallel cleanup or schedule change is part of implementation.
