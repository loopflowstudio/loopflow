### Public recovery contract — implemented 2026-11-04

The [Session guide](../docs/sessions.md#come-back-to-a-conversation) replaces
unconditional success and client-stop promises with retained attachment or safe
replacement: live turns, drafts and pending requests retain their provider;
attachment failure discards no work and replays no input. History and saved screens
cannot reconstruct a lost editor or request. `lf resume --help`, the execution
architecture and the Codex subscription note state the same contract; the realign
sweep found them still promising takeover. The runtime contract lives in
`rust/loopflow/src/transport/README.md`. The review links to the guide instead of
maintaining a second copy; recovery acceptance remains in this plan and the test README.

**Skill direction:** keep `demo` and `verify` unchanged; their real-path proof
requirements already apply. For this Task, the verification instruction remains:
resume an affected existing Session through its configured entry, edit and submit
the retained draft, complete the pending request where applicable, return and
complete another turn; correlate those actions with retained identity and history.
Perform live actions only within the existing parent coordination boundary.

The lifecycle remains Session → execution owner/provider → revocable viewer.
`owner_retention` is a replacement judgment shared by resume, rollover and lifetime,
not a Session status or transport-health result. `PendingInput` is the single
in-memory delivery queue; SQLite records retention evidence, not a replayable editor.

| Action | Surviving ownership and path |
|---|---|
| Open the same conversation | `LfSession` retains Work, capture and native history; `attaches` preserves protected providers, and transport grants revocable viewer control |
| Type, leave and return | The provider owns its editor/requests; `PendingInput` retains queued bytes before PTY delivery through `try_record_owner_input`, with no reconnect replay |
| Upgrade | Resume, rollover and lifetime use `owner_retention`; reachability decides whether attachment works, never whether pending work may be destroyed |
| Replace a safe owner | The launch lock and saved-thread continuation preserve Session/native identity; confirmed process/group death permits a new AgentProcess and fence |

`owner_retention` returning `None` permits the remaining replacement checks; it proves no
transport health. `Uncertain` preserves execution but stores no recoverable draft
text. Screen snapshots and native history retain their separate purposes. Compare
builds against the launch entry, not the viewer binary. Missing history can select
a fresh launch, so establish each affected Session's identity before recovery.
Unknown-live refusal and attachment fencing remain; EOF authorizes no replay.

Fixture boundaries live in `rust/loopflow/tests/README.md`. Candidate fixtures cover:

- Retained `__planning-check` reaching ContextBlock Stop with fencing, subagent
  exclusion and real delivery errors; unknown retired hooks keep their diagnostic.
- Three-second observation of dead-leader helpers without local lifeline authority;
  persistent helpers refuse replacement without signals.
- Store contention pausing input delivery while control and viewer return remain
  responsive; the sole queue retries every 100 ms and delivers once after unlock.
- Draft → upgrade → return → submit → continued turns with Session/Task/capture/
  history preserved. Only provider replacement changes AgentProcess/fence.
- Failed attachment to a paused protected owner preserving an uncertain draft and
  pending request, followed by continued turns after transport returns.

These prove candidate behavior and temporary-outage continuation, not older
wire/store compatibility, historical causes or installed recovery. Keep failed
attempts: LOO-718's frozen input despite control acknowledgement and LOO-582's later
