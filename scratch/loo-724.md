## Implemented recovery and remaining acceptance

`confirmed_group_death` releases any local lifeline, then observes group death
for up to three seconds regardless of writer ownership. Empty groups return
immediately; persistent survivors retain the exact diagnostic and no signal is
sent. The Session attachment lock still fences observation and replacement.

Two `session_record::runtime` regressions start a headless leader and helper,
observe the leader's exit, then recover through `resume_session_agent_process`
in a separate test process. A pipe-controlled helper exits naturally during the
observation window; a persistent helper remains alive and refuses replacement.
They preserve the Session, capture, Task, native identity, history and pending
steer. Successful recovery reserves a fresh AgentProcess/token and rejects stale
settlement; refusal preserves the prior attachment and Process record. This
proves the recovery entry, not an installed provider turn or released wire upgrade.

`resumed_session_completes_turns_after_build_replacement_and_viewer_return`
now runs the composed public path with a native Claude stand-in. It starts and
completes the original request, retains an unsent draft while changing the lf
entry to a different executable, then opens `session resume`. The old provider
keeps the draft and fence. Submitting that exact draft permits orderly owner
replacement; the same viewer follows the successor, completes another turn,
detaches and returns to complete a fourth turn. The provider reloads its saved
history and rejects a recreated conversation or replayed seed. Session, capture,
native identity and Task remain fixed; replacement changes AgentProcess/token,
while viewer return preserves them. Both processes end normally.

This fixture uses two candidate executables and the candidate schema/wire, not
an earlier release. Its provider-written completion receipts and native callbacks
prove the transport workflow, not configured Claude/Codex service behavior.
The separate runtime tests retain stale-settlement rejection and pending-steer
coverage; the edited-draft test retains its native editor indefinitely.

- `transport/lifetime.rs` judges executable changes and protected work, then sends

  with unknown outcome and no automatic resume.
- `human_session::attaches` checks exact owner evidence and compares its image

  an idle or unanswering superseded owner is ended before native continuation.
  `viewed_summary` probes control instead of trusting stale viewer records.
- `open_waiting` takes the launch lock and `resume_native_session` uses saved
  provider identity. Agent settlement retains fencing and rejects unknown live
  identity. Missing native history can select a fresh launch, so the affected

- `resolve_lf_binary` prefers the invoking app's helper outside a private Home;
  `superseded` compares against that resolved entry, not merely the public CLI.
  Mixed app/CLI installations therefore matter to both callbacks and takeover.
