## Contract and approach

- Preserve native drafts, pending requests, running turns/Graphs and durable
  conversation history. Executable replacement alone cannot discard input.
- Bound terminal input persistence retries: a failed store write left the writable
  PTY in poll, causing immediate retries. Keep queued input, stop polling write
  readiness until a 100 ms retry deadline, and log changed failures once. Resume
  delivery after the same store recovers. No automatic provider restart. LOO-724
  owns the final shape of this path; see Integration below.
- Expose why an obsolete executable's owner remains: native input, running Graph,
  headless Run, live turn, missing Session, output or store failure. Derive this
  from the existing retirement judgment, not a parallel classifier.
- Stop the remaining verification plan after the existing host-security pressure
  signal. Preserve not-run receipts; ordinary test failures still allow independent
  suites to run. No new machine monitor or security bypass.
- Disposable demos use a private copied runtime and a retained root outside build
  output, selected by private `LF_HOME` and copied `LF_BIN` for launch, child
  commands and teardown; teardown stops exact owned Sessions before removing generated output.
  Interrupted review retains its root and history with explicit owner evidence.
  LOO-722 owns cleanup eligibility, escalation and final liveness recheck;
  LOO-723 owns installation promotion; LOO-724 owns hooks/reconnect failure repair
  and the nonblocking input-retention path.

## Delete — do not maintain

- Immediate store-write retry through writable-PTY polling in transport::serve;
  preserve queued bytes and record-before-delivery. Blocking
  `record_owner_input` goes with LOO-724's integration.
- `SqliteStore::owner_waits_for_person` and its boolean-only SQL result;
  retirement, resume and rollover use `owner_retention` directly. Existing tests
  assert reasons and release, with no parallel classifier or compatibility wrapper.
- Numeric retention codes and their decoder: the query exposes named facts,
  and Rust selects the reason in the same priority order. No persisted encoding
  or unknown-code failure is needed for this local judgment.
- `transport::lifetime::Store` and its repeated `open` calls; the watcher caches
  one connection and attempts opening at most once per policy poll. Store errors
  use the same changed-error logger as other policy operations.
- Unconditional scheduling of later suites after host-security pressure.
- Demo instruction's blanket no-Session-close wording where it leaves disposable
  fixture owners unowned; preserve the caller's Session and Graph boundaries.
