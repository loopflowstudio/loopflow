# LOO-774: Terminal bridge endings

Implement the Task's final owner-protocol frame (`replaced`, `finished`, `retired`),
forwarding through existing bridges and discovery through `lf server describe`.

## Design (2026-11-08)

Tag `0x05` carries JSON `{ "reason": "finished" }`, outside the counted terminal
stream. The existing `child_exited` event still carries the execution exit code;
a relay waits for Close before stopping. Unknown EOF remains unknown. The owner
flushes final output with a bounded drain so a slow viewer cannot hold execution.
Natural completion sends `finished`; lifetime policy sends `retired`. Resume and
rollover ask the old owner to send `replaced` and stop before starting its successor.
An unavailable owner retains the existing signal fallback, with no invented reason.

Delete — do not maintain: no remaining targets. Lifetime shutdown no longer
uses `Control { held: false }`; replacement no longer signals unconditionally.
Viewer control transfer, child exit codes, bounded shutdown, retention judgments
and signal fallback remain.

Lifetime confirmation returns a boolean: the owner maps a confirmed policy
ending to `retired`. Close presentation shares one message between CLI and
Desktop; describe reads reason names from the generated schema.
