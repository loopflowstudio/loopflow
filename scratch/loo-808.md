# LOO-808 — Session mailbox observation

Reconciled design, 2026-11-08. Each native Session surface owns one private
mailbox. A vnode DispatchSource watches its directory so atomic replacement
of `status.json` wakes the pane. Quiet mailboxes schedule no reads; retained
hidden panes still receive changes. Observation starts before the initial read;
decoding, duplicate suppression, pending-move generation checks and explicit
Retry/Move semantics remain intact.

The 100 ms observation loop is removed. The mailbox protocol and Rust relay
are unchanged. One resource owner cancels
the source, closes its descriptor through the cancellation handler, and removes
the mailbox on stop or release. No timer fallback or directory recreation.
Use the fixed protocol filenames directly; no status-URL extension rewriting.

Acceptance: successive atomic replacements, startup publication, malformed or
missing status recovery, coalesced writes, unchanged-reading suppression, move
acknowledgement, and closure with queued events. Focused implementation check:
`ServerConnectionTests`; gate owns the full Swift suite and Xcode fallback build.

Remaining: CI, merge and completion; refresh main again before delivery if it
advances. No known implementation gaps or
open product decisions. No Wave is assigned.

Concept review, 2026-11-08: no design change or open product choice. Retaining a
pane retains observation; closing it releases the mailbox, not Session history.
Retry reconnects; Move here remains a deliberate, generation-bound request for
input. Directory events invalidate a reading rather than represent a history of
transitions: coalescing must converge on the latest status. Watching the file
inode would miss later replacements; suspending observation when hidden would
leave retained panes stale; recreating a removed mailbox would contradict Close.
The current design handles these counterexamples without new concepts or APIs.
Review screen in `scratch/concept-review.html`.
