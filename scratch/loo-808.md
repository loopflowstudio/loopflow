# LOO-808 — Session mailbox observation

Implementation design, 2026-11-08. Each native Session surface owns one private
mailbox. Watch its directory with a vnode DispatchSource so atomic replacement
of `status.json` wakes the pane, while idle and hidden panes schedule no reads.
Arm observation before an initial read; retain decoding, duplicate suppression,
pending-move generation checks and explicit Retry/Move semantics.

Delete — do not maintain: `ServerConnection.observation`'s 100 ms Task loop.
Keep the mailbox protocol and Rust relay unchanged. One resource owner cancels
the source, closes its descriptor through the cancellation handler, and removes
the mailbox on stop or release. No timer fallback or directory recreation.
Use the fixed protocol filenames directly; no status-URL extension rewriting.

Acceptance: successive atomic replacements, startup publication, malformed or
missing status recovery, coalesced writes, unchanged-reading suppression, move
acknowledgement, and closure with queued events. Focused implementation check:
`ServerConnectionTests`; gate owns the full Swift suite and Xcode fallback build.

Remaining: auto Graph review, QA, sync, delivery, CI and completion. No known
implementation gaps.
