# LOO-822: live Session state and usage from provider transcripts

Design: `docs/dev/server-first.md` (Telemetry), the maintained LOO-819 plan.
This file covers only LOO-822.

## Exists

Built, with the five items from the 2026-11-11 concept review and the five
"Pi and OpenCode as peers" items (both below):

- One `Turn` per harness reader (`transcript/{claude,codex,pi,opencode}.rs`):
  from what woke the agent until it hands back, with id, state (always set),
  start, end, model, usage, and requests and agent work as `items`. `lf
  history show --transcript` prints one line per turn. Pi and OpenCode share
  a per-call tally (`Calls`) that also sums cost.
- The line (`ops/human_session/turns.rs`): the transcript's last turn for all
  four, closed by lf's `completed` row with the same id when the transcript
  leaves it open. No time matching. One resolver finds a transcript
  (`transcript::locate`), returning a `Source` (a file, or OpenCode's store
  and conversation id) that the observation cache keys and the watch hints.
- Wire: `turn` is `{id, state, started_at, ended_at, model, usage}`; `asking`
  and `source` are gone; `id` is new; `usage` is tokens so far, also while
  running. Availability: status reports when the Session's agent process has
  a `session_activity` row, else a turn that ended or was interrupted.
- Usage rows (`transcript/facts.rs`): the transcript is the only writer for
  all four, one row per turn id, insert-if-absent, at every Stop moment
  (`lf/commands/context.rs`; Pi and OpenCode reach it with no hook name) and
  at every exit path (`native_exit`, `process/runtime.rs` finish,
  `run_native_session`). `ProviderFact::Usage` is deleted. Pi and OpenCode
  rows are `{provider, final, usage}` with `cost_usd`.
- OpenCode reads `session_message` in `opencode.db` read-only, for history
  and live alike; `opencode session export` is no longer run.
- Raw: `pi` (a `node` process whose script is Pi's) and `opencode` processes
  list too; the server watches `~/.pi/agent/sessions` and OpenCode's home.
- Raw: a recorded thread whose Session is no longer running lists raw under
  the Session's title.
- Unchanged by the review: `counted_task`, exit `completed` rows for turns
  with none recorded (`facts::covers`, by id or by time, the one place times
  still match turns).

The code and `docs/sessions.md`, `docs/surfaces.md`, `docs/telemetry.md`,
`docs/dev/server-first.md` say the rest.

## Choices made building it (2026-11-11), each reversible

- Claude `cost_usd`: kept on the stream's `completed` row (the `result`'s
  `total_cost_usd`, the process's running total). "Unrecorded" was the other
  option; the number cannot be recovered later, so it is kept. Not decided by
  a person.
- Exit `completed` rows still use `facts::covers` by time for the folded-turn
  case. Removing it would write a second completion for a turn the stream
  folded into another. Not decided by a person.
- `SessionTurn` gained `id` on the wire instead of a wrapper type carrying
  it.
- A turn's usage row is not rewritten: a turn cut off at exit and resumed
  under the same id keeps its first row.
- Turn-end writes cover every ended turn in the tail read, not only the
  last, so a turn whose end the transcript showed late is written at the
  next hook.
- OpenCode live reading: a read-only query of `session_message` (3.7 ms on
  this Machine's store, 2026-11-11) over `opencode session export` (490 ms)
  or a WAL watch alone. The watch covers OpenCode's whole home and maps
  `opencode.db-wal` writes to the store. Reads OpenCode's internal schema
  (2.2.1), which the export is the documented face of; v1 `message` rows are
  not read. Not decided by a person.
- Pi turn ids are Pi entry ids; Pi's stream names turns by lf's request uuid,
  which the session file never holds. So a Pi `usage` row and its stream
  `completed` row carry different ids, and exit completions match Pi by time
  (`facts::covers`). Making the stream adopt Pi's entry id would need Pi's
  RPC to report it. Not decided by a person.
- An OpenCode steer (a second `user` message while a turn runs) reads as two
  turns, the first `interrupted`: v2 messages carry no parent. Usage sums
  stay right; exit completions cover the second by time.
- Kept: the store's multi-receipt usage merge (`record_event_in`'s usage
  branch, `native_usage_key`, `late_usage_key`, `merge_native_usage`). No
  production writer reaches it now; retention compaction of existing rows
  and the usage-reduction tests still use it. A later cut, with retention.

## Next implement (headless concept review, 2026-11-11)

With all four harnesses' usage rows written by `record_turn_usage`,
insert-if-absent, in one shape (`{provider, final, usage}`), two pieces no
longer match the model:

1. `record_event_in` (`store/sqlite/session_events.rs`) still keys, splits
   (`late_usage_key`) and merges (`merge_native_usage`) `usage` rows written
   through `record_session_event`. No production caller writes `usage` there
   now (`fact_writer` has no Usage fact). Delete that branch so a second
   `usage` receipt is a conflict like every other kind, and write
   `record_turn_usage`'s `receipt_key` as `''` (`native_usage_key` returns
   that for every shape this branch writes). Retention's compaction and the
   `message.tokens` / Codex `total`/`last` branches in
   `session_record::native_usage` stay: they read rows written before this
   branch. Tests that wrote multiple receipts through `record_session_event`
   move to retention's tests or go.
2. `cost_usd` means two things in `session_events`: one turn's cost on Pi and
   OpenCode `usage` rows, Claude's process running total on the stream's
   `completed` row (`claude_decode.rs`, from `result.total_cost_usd`). Name
   the `completed` field `total_cost_usd`, Claude's own name, so no reader
   sums a running total as a turn's cost. Update `docs/dev/server-first.md`
   (Telemetry), the decode and `fact_writer` tests, and the PR note for
   LOO-732.

Looked at and left: Pi's two ids for one turn (stream request uuid, file
entry id) stay as recorded under the choices above; `live::locate` is the
`CurrentConversation` door onto `transcript::locate`, not a second resolver.
