## Seen while building (2026-11-10, this Machine)

- Turn ids match between the store and the transcripts: a Claude `completed`
  row's `provider_turn` (`72fe3d61…`) is the `uuid` of the request row in
  that conversation's transcript, an `<lf:skill:…>` launch message; a Codex
  row's is `task_started.turn_id`.
- Rows following an `end_turn` in the 40 newest Claude transcripts: 195
  `isMeta` "Another Claude session sent…", 53 `<task-notification>`, 6
  compaction continuations, 3 "[Cross-session idle notice]", 2
  `<local-command-caveat>`, the rest typed input. So a run starts at any row
  a model call follows, not only at typed input; a local-command row starts
  none. 3 `AskUserQuestion` calls in those 40.
- Store payloads: Claude `usage` is `{provider, final, usage:{input_tokens,
  output_tokens, total_input_tokens, cache_read_tokens, cache_write_tokens,
  model[, cost_usd…]}}`; Codex `usage` is `{baseline, last, total,
  modelContextWindow, peakInputTokens}` in camel case. Claude `completed` has
  `status, result_id, errors, subtype, context`; no `duration_ms`.

## Open

- The exit read (`native_exit::settle`) writes rows for every provider lf
  launched, including a bare run outside any Task or Wave checkout. "I only
  really want to do observability tracking on managed work" reads as no rows
  there. Either `record_transcript_turns` writes only when `counted_task`
  (or a Wave) claims the cwd, or every lf launch keeps its rows.
- LOO-732 weighs Claude quota by the `cost_usd` delta between cumulative
  usage rows. A transcript row has no cost and is per run, so it weighs
  nothing there and reads as a counter reset. LOO-732's reader has to
  handle `"source":"transcript"` rows, or these rows change shape.
- A run cut off with no end in the transcript (provider killed mid-turn) is
  never written, so its tokens are missing from the store. Either the exit
  read closes the last open run as interrupted, or it stays unwritten until a
  resume ends it.
- `counted_task` answers from the checkout alone ("worktree rule for now").
  Whether a calling Session's Task (`LF_AGENT_CALLER`) should outrank it is
  undecided.
- Typed input arriving while a run is open ends that run as `interrupted` and
  starts another, so both halves keep their tokens. The live stream folds
  such input into one turn instead; a transcript row then reads
  `interrupted` where the live row would read `completed`.
- `ExitPlanMode` waiting for approval looks like the question case (a call
  with no result) and is not treated as `asking`.
