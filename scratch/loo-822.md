# LOO-822: live Session state and usage from provider transcripts

Design: `docs/dev/server-first.md` (Telemetry), the maintained LOO-819 plan.
This file covers only LOO-822.

## Exists

Built: one reader per harness returning `Turn`s and `Run`s
(`transcript/{claude,codex}.rs`), the tail read (`live.rs`), exit-time
`usage`/`completed` rows (`facts.rs`, called from `native_exit::settle`),
`asking`, `ops::task::counted_task`, raw discovery and the watch.
`lf session card <provider-id>` answers for an open raw conversation
(`human_session::listed` falls back to `turns::raw`). The exit
read writes a last run the transcript leaves open as `interrupted`. The code and
`docs/sessions.md`, `docs/surfaces.md`, `docs/dev/server-first.md` say the rest.

conversations too, since provider transcripts expire. Report per harness which

Jack Heart, LOO-819 context:

- "If this work shows which readers still need `observed` rows, say so in the
  PR; nobody has traced it."
- "Open in the plan, not decided here: which Task a run counts toward when its
  checkout and its calling Session (`LF_AGENT_CALLER`) belong to different
  Tasks. Keep attribution in one place so either answer is a small change."

Jack Heart, in the Task conversation, 2026-11-10, after the two comments above:
"i dont think its true that we need to maintain more history than raw
transcripts. its possible that we will want to, but its also true well likely
want to expire our own data, or maybe send it elsewhere"

This loosens the LOO-732 constraint above: the rows are no longer justified
by transcripts expiring. The next quote is what keeps the exit read. Related
reading the same day: LOO-732's unit is subscription quota, and its Claude
quota weight is the `cost_usd` delta between a Session's cumulative usage
rows, so a transcript-sourced row with no cost weighs nothing there, and a
per-run row among cumulative ones is read as a counter reset.

Jack Heart, same conversation, next message: "I only really want to do
observability tracking on managed work -- tasks and waves basically -- but i
do want to include \"bare lf\" run in those worktrees [or alternatively in the
tree of sub processes of those sessions and the worker sessions] so that we
are basically including subagent work"

Read as: raw conversations get no usage or completion rows and no Session;
a bare `lf` run counted toward a Task or Wave does. Asked worktree, process tree or both, Jack Heart: "i think i prefer the
worktree rule for now". That is what is built; `ops/task.rs` `counted_task` is the one place it is decided.

Jack Heart on Claude cost, same conversation: "i dont think im really ready
to actually do good $ accounting. raw (or uncached?) tokens probably more
useful to start. $ is more of a longterm goal"

So transcript-sourced rows stay without `cost_usd`, as built. They carry
input, cache read, cache write and output separately, so raw and uncached
counts both derive from them.

Jack Heart on raw conversations in `lf session list`: "default not super
important, easy to change, as long as theres a falg either way"

Raw conversations list by default; `lf session list --no-raw` leaves them
out (`SessionFilter.raw`, read in `ops/human_session.rs` `lists_raw`). The
flag stays in the CLI: `--subscribe` carries it in its filter, not in the
server request shape, so `server_schema.json` is unchanged.

## What the transcripts carry

Read 2026-11-10 on this Machine: the 8 newest Claude 2.1.322 transcripts for
row keys, the 60 newest for `cost-state`, and 6 Codex 0.167.0 rollouts.

The per-harness table is in `docs/dev/server-first.md` (Telemetry).

Contrary to the first reading ("live `result` only"): 25 of 60 Claude
transcripts hold a `cost-state` row with `totalCostUSD`, `totalAPIDuration`,
`totalDuration` and per-model `modelUsage.<model>.costUSD`. It was the last
row in 24; one resumed transcript had six, mid-file. These are totals, not
per-turn values. Not established: what they total (process or conversation),
when Claude writes the row, and why 35 transcripts had none. An earlier pass
noted `isApiErrorMessage`; it was in none of these 8.

An unanswered `AskUserQuestion` shows as a `tool_use` with no `tool_result`.
A tool waiting on a permission prompt looks the same as a tool still running
(from the row shapes; not exercised).

## Seen while building (2026-11-10, this Machine)

- Turn ids match between the store and the transcripts: a Claude `completed`
  row's `provider_turn` (`72fe3d61…`) is the `uuid` of the request row in
  that conversation's transcript, an `<lf:skill:…>` launch message; a Codex
  row's is `task_started.turn_id`.
- Rows following an `end_turn` in the 40 newest Claude transcripts: 195
  `isMeta` "Another Claude session sent…", 53 `<task-notification>`, 6
  compaction continuations, 3 "[Cross-session idle notice]", 2
  `<local-command-caveat>`, the rest typed input. So a run starts at any row
  a model call follows, not only at typed input; a local-command row starts
  none. 3 `AskUserQuestion` calls in those 40.
- Store payloads: Claude `usage` is `{provider, final, usage:{input_tokens,
  output_tokens, total_input_tokens, cache_read_tokens, cache_write_tokens,
  model[, cost_usd…]}}`; Codex `usage` is `{baseline, last, total,
  modelContextWindow, peakInputTokens}` in camel case. Claude `completed` has
  `status, result_id, errors, subtype, context`; no `duration_ms`.

## Seen in concept review (2026-11-10, 60 newest Claude transcripts)

- Input typed while a turn runs is an `attachment` row of type
  `queued_command` (151 `prompt`, 114 `task-notification`), with
  `queue-operation` rows beside it (637 enqueue, 365 dequeue, 272 remove);
  it is no `user` row, so it splits no run. The typed `user` rows that did
  land on an open run were resumes after a cut-off ("ok", 12 minutes after
  the last row), where `interrupted` is right. A compaction summary mid-run
  (3 of 11 followed a `tool_use`) carries `isCompactSummary` and splits
  nothing. This retires the earlier worry that queued input reads
  `interrupted`; `facts::covers` still serves a prompt dequeued after
  `end_turn`, which the live stream keeps in the same turn.
- The live Claude decoder never clears `assistant_usage`
  (`harness/claude_decode.rs`), so its provisional `usage` rows grow across
  a process's turns; LOO-732's report (`telemetry_report.py`) takes deltas
  between a Session's rows and treats a drop as a reset.

## Open

- For the PR body and LOO-732, not a choice here: a `"source":"transcript"`
  usage row is one run's tokens, not a running total, and has no `cost_usd`.
  A delta reader must take such a row whole. The parent plan makes the
  transcript the record for every conversation, so per-run is the shape that
  stays.
- Parent plan's question, unchanged: whether a calling Session's Task
  (`LF_AGENT_CALLER`) outranks the checkout in `counted_task`.
- `ExitPlanMode` waiting for approval looks like the question case (a call
  with no result) and is not treated as `asking`. Needs one observed
  transcript of a plan waiting on approval before it is.
