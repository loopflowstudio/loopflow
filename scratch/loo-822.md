# LOO-822: live Session state and usage from provider transcripts

Design: `docs/dev/server-first.md` (Telemetry), the maintained LOO-819 plan.
This file covers only LOO-822.

## Exists

Built, with the five items from the 2026-11-11 concept review (below):

- One `Turn` per harness reader (`transcript/{claude,codex,pi,opencode}.rs`):
  from what woke the agent until it hands back, with id, state, start, end,
  model, usage, and requests and agent work as `items`. `lf history show
  --transcript` prints one line per turn; its `--json` has the new shape.
  Pi and OpenCode turns open at each request and have no state.
- The line (`ops/human_session/turns.rs`): the transcript's last turn, closed
  by lf's `completed` row with the same id when the transcript leaves it
  open. No time matching. Pi and OpenCode read lf's last recorded turn.
- Wire: `turn` is `{id, state, started_at, ended_at, model, usage}`; `asking`
  and `source` are gone; `id` is new; `usage` is tokens so far, also while
  running. Availability: status reports when the Session's agent process has
  a `session_activity` row, else a turn that ended or was interrupted.
- Usage rows (`transcript/facts.rs`): the transcript is the only writer for
  Claude and Codex, one row per turn id, insert-if-absent, at a Stop hook
  (ended turns in the tail read) and at every exit path (`native_exit`,
  `process/runtime.rs` finish, `run_native_session`). The stream decoders emit
  no `ProviderFact::Usage` for these two. No `"source":"transcript"` anywhere.
- Raw: a recorded thread whose Session is no longer running lists raw under
  the Session's title.
- Unchanged: the tail read, the watch, raw discovery, `counted_task`, exit
  `completed` rows for turns with none recorded (`facts::covers`, by id or by
  time, the one place times still match turns).

The code and `docs/sessions.md`, `docs/surfaces.md`, `docs/telemetry.md`,
`docs/dev/server-first.md` say the rest.

## Concept review in the Task conversation (2026-11-11)

Page: `scratch/concept-review.html`. Requirements quoted above stand as said.

Mismatch: the plan makes the transcript the record of a turn; the branch
keeps the stream's turn and the transcript's run and matches them by time in
two places (`live::combine`, `facts::covers`). `turn.source` has one reader
(`turns::waits`); `asking` can't be set by Claude 2.1.322 or Codex.

Proposed, for Claude and Codex: the turn is the transcript's last run, closed
by lf's recorded end for the same run id when the transcript has none;
availability is the Session's (status reports, else an ended turn), so
`asking` and `source` leave the wire; the transcript is the only writer of
usage rows, one per run id, at a turn-end hook and at exit.

Counterexamples: Esc on a prompt folded into an earlier stream turn has no
id match (the time rule's case); Pi and OpenCode transcripts have no turn
ends, so the stream writer stays for them; Claude `cost_usd` then lives on
`completed` or nowhere; the change reaches `fact_writer.rs` and
`claude_decode.rs`.

Jack Heart, quoting the page's three proposed bullets (the turn is the
transcript's last run, matched by id only; available is the Session's,
`asking` and `source` leave the wire; the transcript is the only writer of
usage rows, the stream keeps `started` and `completed`): "approved"

Asked where it is built and about questions 4 to 6, Jack Heart: "4c 5a 6
not sure". 4c is one `Turn` for history and live, in this Task; 5a is a
recorded thread resumed with plain `claude` listing as raw, in this Task.
Read as: the approved three bullets are built in this Task too.

Question 6 ("only managed work": rows only where a Task or Wave claims the
checkout, or for every lf launch): "not sure". Rows for every lf launch stay
as built.

Questions 1 to 6 are on the page: usage-row writer, wire fields, matching

## Choices made building it (2026-11-11), each reversible

- Claude `cost_usd`: kept on the stream's `completed` row (the `result`'s
  `total_cost_usd`, the process's running total). "Unrecorded" was the other
  option; the number cannot be recovered later, so it is kept. Not decided by
  a person.
- Exit `completed` rows still use `facts::covers` by time for the folded-turn
  case. Removing it would write a second completion for a turn the stream
  folded into another. Not decided by a person.
- `SessionTurn` gained `id` on the wire instead of a wrapper type carrying
  it.
- A turn's usage row is not rewritten: a turn cut off at exit and resumed
  under the same id keeps its first row.
- Turn-end writes cover every ended turn in the tail read, not only the
  last, so a turn whose end the transcript showed late is written at the
  next hook.
