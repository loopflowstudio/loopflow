## Exists

- One `transcript::Turn` and one reader per harness serve history and live
  state for Claude, Codex, Pi and OpenCode. Live state uses the last turn;
  a recorded completion closes it only under the same id
  (`transcript/live.rs`). Availability uses agent status when present,
  otherwise the transcript's ended/interrupted state.
- Raw processes list without creating Sessions (`transcript/raw.rs`),
  including recorded threads resumed outside lf. Provider-home watches and
  a bounded reconcile refresh subscriptions (`transcript/watch.rs`);
  subscribers in each server or CLI process share its transcript readings.
- After sync with `763da5c92f`, turn-end hooks send `session.boundary` and
  open no store. `server/boundary.rs::answer` calls
  `transcript::facts::record_session(Moment::TurnEnd)` before answering Stop,
  including Pi/OpenCode callbacks without a hook name. Bare headless runs
  have only context hooks; interactive conversations retain turn hooks.
- Exit recording remains in the launching process (`harness/native_exit.rs`,
  `process/runtime.rs`), using `Moment::Exit` without a server. It reads all
  turns, writes missing usage and completions, and marks a final open turn
  interrupted. Both reads are best-effort. The transcript alone writes new
  usage rows; the stream still writes started/completed rows. Costs and
  the exit-only time match are described below.
- Kept query changes: indexed reverse Session→Task probes (`d9e3c1f3b`),
  indexed live-agent and Task Process inventory (`761c28056`), one capacity
  read per Task detail (`d1f1caa3f7`), and one planning-scope resolution per
  repository per check (`a835f03e6f`), simplified in `8d47895760`.
  `f8b742d8c` was reverted. Measurements remain in `optimize-session-list.md`;
  these results predate the sync and do not explain the 18–75 s stall.

## Choices made building it (2026-11-11), each reversible

- Claude cost: kept on the stream's `completed` row as `total_cost_usd`
  (the `result`'s field, the process's running total). "Unrecorded" was the other
  option; the number cannot be recovered later, so it is kept. Not decided by
  a person.
- Exit `completed` rows still use `facts::covers` by time for the folded-turn
  case. Removing it would write a second completion for a turn the stream
  folded into another. Not decided by a person.
- `SessionTurn` gained `id` on the wire instead of a wrapper type carrying
  it.
- A turn's usage row is not rewritten: a turn cut off at exit and resumed
  under the same id keeps its first row.
- Turn-end writes cover every ended turn in the tail read, not only the
  last, so a turn whose end the transcript showed late is written at the
  next hook.
- OpenCode live reading: a read-only query of `session_message` (3.7 ms on
  this Machine's store, 2026-11-11) over `opencode session export` (490 ms)
  or a WAL watch alone. The watch covers OpenCode's whole home and maps
  `opencode.db-wal` writes to the store. Reads OpenCode's internal schema
  (2.2.1), which the export is the documented face of; v1 `message` rows are
  not read. Not decided by a person.
- Pi turn ids are Pi entry ids; Pi's stream names turns by lf's request uuid,
  which the session file never holds. So a Pi `usage` row and its stream
  `completed` row carry different ids, and exit completions match Pi by time
  (`facts::covers`). Making the stream adopt Pi's entry id would need Pi's
  RPC to report it. Not decided by a person.
- An OpenCode steer (a second `user` message while a turn runs) reads as two
  turns, the first `interrupted`: v2 messages carry no parent. Usage sums
  stay right; exit completions cover the second by time.
- Kept: retention's compaction of rows an earlier lf recorded per receipt
  (`late_usage_key`, `merge_native_usage`, now private to `retention.rs`).
  No writer produces such rows; a later cut, with retention.
