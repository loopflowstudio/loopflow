# LOO-826: observers become server registrations

Stacked on LOO-821 (`session.boundary`, PR #1879), merged at 838e8828c.

## Design (implement step, November 11)

A managed Session's registration is what it already has after LOO-821: its
provider context (`LF_PROVIDER_CONTEXT`) and hooks that reach the Machine
server. Nothing else is resident.

- **Task updates ride the boundary answer.** `session.boundary` answers
  `update` beside `steers` at every non-`stop` moment. The server reads the
  Session's Tasks (`harness::task_updates::read`, a pure read against the last
  recorded observation, no settle timer, no revision poll) and records the
  receipt `dispatched` as it answers. The hook prints it after the steers in
  the same `additionalContext`, so Claude, Codex, OpenCode and Pi all get it
  at their next prompt. The first read for a Session records the baseline.
- **Codex observation at turn end.** A `stop` for a Session with a recorded
  app-server connection reads the thread's turns (`recover_history`) on the
  server's after-stop worker. The first turn is submitted by lf while opening
  the thread, before the client starts, and recorded as lf's input.
- **New Codex conversations (`/new`, `/fork`)** find their hooks' delivery
  through the app-server's own `LF_CONTEXT_DELIVERY`, written when lf starts
  the app-server; the thread binding still wins when it exists. Their
  `SessionStart` selects them as the observer's `follow` did.

## Delete — do not maintain

- `lf __codex-observe`: `CodexObserver`, `spawn_observer`, `run_observer`,
  `observe`, `Recorder`, `person_started`, `turn_running`, `WATCH_INTERVAL`,
  `observe_client` (`lf/commands/util.rs`), `harness/observer_measurement.rs`,
  `performance/observer_measurement.rs` and its hook in `performance.rs`, the
  observer tests in `codex_connection.rs`.
- Task-update watchers: `harness/claude_updates.rs`, `task_updates::watch`,
  `TaskUpdates` (poller state, settling, revision polling) and its polling
  tests, the async `task-updates` hooks in `context_block.rs::hook_settings`,
  the `TaskUpdates` branch of `emit_block`, Pi's `PiTaskUpdates` child in
  `context_pi.mjs`, OpenCode's 1 s `report_task_update` tick.
- `store.task_update_revision()` reader (the shipped triggers stay; see
  questions).

Keep: receipts in Session history (`record_task_update`), report text, the
"exit and next start are separate commits" guard, comment de-dup, baseline.
