# LOO-826: observers become server registrations

Stacked on LOO-821 (`session.boundary`, PR #1879), merged at 838e8828c.

## Design (built, November 11)

- **Boundary answers.** `session.boundary` answers `update` beside `steers`
  at every non-`stop` moment (`harness::task_updates::claim`, shared with the wake). The
  read is `harness::task_updates::read`: stateless, compared against the last
  recorded update, baseline on the first. The hook prints it after the steers.
- **Idle waking** (steered; findings in `questions.md`). Managed boundaries
  register the Session in server memory (`server/wake.rs`): Claude by the
  `inbox` paths the hook sends, Codex by the recorded app-server endpoint.
  Stop marks it idle. One server thread waits on `store::changes` and the
  `task_updates` revision and wakes idle registrations with news; a turn end
  (`after_stop`) wakes its own Session. Claude: cross-session inbox, managed
  launches set `crossSessionInbound: accept`. Codex: `turn/start` with
  `toolOutput` `loopflow_task_update`.
- **Codex observation.** `after_stop` reads the thread's turns
  (`recover_history`). lf sends the first turn on the app-server before the
  client starts (`codex_connection::start_turn`). The app-server carries the
  launch's `LF_CONTEXT_DELIVERY`, and the hook prefers a thread's own binding,
  so `/new` and `/fork` threads reach lf's hooks. A client lf waits on checks
  its attachment every 2 s and stops when a mover replaces it.

## Concept review (November 11): next implement direction

- **One comment, one delivery.** A person's Task comment is saved as a steer
  (`task_comments.rs`, `comment:<id>`) and also reported by
  `task_updates::read` as "New comment from …". An idle conversation is woken
  with it as worker progress, then gets it again as a steer at its next turn.
  `task_updates::read` skips comments that have a steer
  (`is_direction_comment`); Task updates carry runs, steps and the
  non-direction comments. What wakes for a direction comment depends on open
  question 1 in `questions.md`.
- **Inbox `accept` follows registration.** `claude_args(context, managed)`
  sets `crossSessionInbound: accept` whenever the launch has turn hooks, and
  `native_args` passes `true` for every native terminal Claude, bare
  included. The server registers only `WorkSource::is_managed` Sessions, so a
  bare interactive Claude accepts any same-user peer and is never woken. Pass
  the Work's managed bit to the settings separately from "gets every hook".
