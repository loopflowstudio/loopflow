# LOO-844: finished headless Sessions read as history

Jack Heart on the Session list: "oh DEFINITELY always filter completed", then
"dont even have have a filter for non-completed. thats history suff".

## Cause (store on 2026-11-11)

Headless runs end through `finish_session_attachment` (store/sqlite/processes.rs)
like interactive ones. Its completion UPDATE skipped any Session with a Task (bound,
or by cwd inside a Task worktree via `session_tasks`), a Wave, a primary scope or a
Graph. Nearly every headless run is a Task step, so 13,559 of 14,177 headless
Sessions stayed open; the 66 unbound ones from the last day all had cwd in a Task
worktree. 487 headless exits were `failed`, which the rule also never completed.

## Change

- Exit: headless Session completes on `completed`/`interrupted`/`failed` exit without
  departure, when its launcher owned the AgentProcess, whatever Work/Graph.
  Interactive rule unchanged.
- `attach_in`: a new AgentProcess on a headless Session clears completion (not if
  moved). Covers a Graph correcting its own step; `lf -b resume` otherwise refuses Runs.
- Migration `complete_finished_headless_sessions.sql`: completes headless Sessions with
  no unfinished agent Process at their AgentProcess exit (else created_at). On a copy
  of the live store: 13,553 rows, 0.3 s; 7 left open with unfinished agent rows.
- Docs: sessions.md "Open conversations and history"; reference-models lifetime.

## Readers of `completed_at` (checked 2026-11-11)

Task/scope primaries (`task_primary_in`, `primary_session_in`), steers
(`harness/task_updates.rs`), owner retention and `running_task_conversations`
(sessions.rs) and Desktop shells all filter `interactive=1` or primaries, which
are interactive, so headless completion doesn't touch them. Program Status
(`program_status.rs`) requires an open Session, but only a live AgentProcess
reports, and reattach reopens first. No `counted_task` symbol exists in the
tree; the brief's telemetry reader wasn't found under that name.

## Concept review (2026-11-11)

One rule now says when a Session is open: someone can act on it now. Headless:
its AgentProcess is running. Interactive: not quit, or it is a Task/Wave/scope's
ongoing conversation. Done from it: `finish_repair` no longer completes the
ci-fix Session (its headless exit already did); it is one UPDATE taking only the Session id;
reference-models.md says "Interactive Task/Wave conversations…".

Accepted as-is: `rename`/Program Status refuse completed Sessions (a finished
run can't be renamed from history, same as a quit interactive one), and
`repair_task_titles_in` skips finished runs, so history keeps the title it ran under.

Second pass (2026-11-11, after compress): the `finish_repair` direction is built and
`captured` has no readers left in `pr_landing.rs`. Nothing further to change.

  whose provider was SIGKILLed: all completed at exit; `lf session list --interactive all`
  shows only the Task's interactive primary. `--history --interactive all` lists them.
- Upgrade from installed 0.15.3: its failed Task launches leave the AgentProcess row
  unfinished (`reserved`) after recording the attachment exit under the old rule. The
  migration skips them (unfinished agent row), then `lf process prune` reaps the row
  and, before this fix, left the Session open for good. Fixed: both reapers
  (`settle_agent_process`, retention `close_dead_processes`) complete the headless
  Session whose current AgentProcess they close (`complete_dead_headless_run_in`).
  Replayed the saved 0.15.3 store: the run moved to history.
- Live store, read-only: every unfinished headless agent row had a live owner and pid.
