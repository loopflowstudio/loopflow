# Use a native iOS terminal with Loopflow over host Tailscale

Jack Heart selected the existing loopflow.mobile checkout, branch and primary
conversation for LOO-718 on November 3, 2026. Preserve the research and prototypes.
The accepted minimum is existing open Tasks → selected existing Session terminal,
with typing, editing, submission and prompt responses. No Wave view, generic
shells, inspectors, changes/checks screen or second provider conversation.

Jack requested Desktop typography/colors and then reduced the default key bar
to Paste, New line and keyboard visibility. Contextual approval/Stop controls
require trustworthy program state; the HTML study does not establish that data.
Touch selection must work natively. Jack later selected describe-first new-Task
flow 1, but creation waits for recoverable shared create/start.

Jack invoked launch-plan for native client implementation here in parallel with
LOO-593's Machine service. [mobile-ios.md](mobile-ios.md) is the active design;
[mobile-task-plan.md](mobile-task-plan.md) separates local backend, native client,
live integration, full Work cutover and creation. The feature Graph stops at
interactive demo. No Auto-Ship approval.

Host-installed Tailscale, native Swift and no custom relay/required hub are
selected. Exact carrier, pairing, takeover gesture and hosting tier remain open.
The phone has no lf CLI or embedded Tailscale. The backend delegates complete
commands to lf, shares native reads/subscriptions and bridges existing owners.
App-owned automation, runtime retention and installation keep their existing
owners. A future optional webhook hub is an architectural seam, not this build.
