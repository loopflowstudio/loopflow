# T3 Code and Paseo: mobile interaction sources

Inspected November 10, 2026. Public source snapshots: T3 Code [`3a8c250`](https://github.com/pingdotgg/t3code/tree/3a8c250cb0c8056f2f563091fd412fe5db809fa1), Paseo [`33c818c`](https://github.com/getpaseo/paseo/tree/33c818cc6b73f7f5ef866a5c0719e0c7d9e75780). Findings below are inspected implementation and test intent, not hands-on judgments. Neither app was installed or exercised; tests were read, not run. Main can differ from store releases.

## What transfers to Loopflow

**Continuity is the strongest shared idea.** Open at the live end; deliberate reading takes ownership of the viewport; return to that reading position; make returning live a clear action. Keep terminal controls subordinate to reading. Both competitors also implement native terminals, but their primary agent conversations are structured chat. Copying their chat cards would change Loopflow's chosen experience; their interaction rules transfer independently.

**A smaller accessory row is justified by the phone's job, not by copying these products.** T3 uses a scrolling one-row terminal accessory; Paseo exposes two rows on phones. Neither establishes that a large key bar is desirable for Loopflow. Paseo's chat composer does demonstrate deliberate progressive disclosure: controls collapse into one model sheet as width shrinks.

## Enter, resume, return

- **T3 — inspected code:** home projects can be scoped by environment, group related projects, and sort by latest thread/pending-task activity. Its iOS workspace navigation labels include Chats and PRs. This is navigation across work, not a host-address-first landing. [Home list model](https://github.com/pingdotgg/t3code/blob/3a8c250cb0c8056f2f563091fd412fe5db809fa1/apps/mobile/src/features/home/homeThreadList.ts), [navigation labels](https://github.com/pingdotgg/t3code/blob/3a8c250cb0c8056f2f563091fd412fe5db809fa1/apps/mobile/src/features/layout/workspace/navigation-tabs.ts).
- **Paseo — inspected code:** workspace rows reserve one leading status position. Busy alone animates as a ring; needs-input uses an alert; done uses a subdued dot. The stable slot avoids title movement when state changes. [Workspace row](https://github.com/getpaseo/paseo/blob/33c818cc6b73f7f5ef866a5c0719e0c7d9e75780/packages/app/src/components/sidebar/sidebar-workspace-row-content.tsx#L191).
- **Paseo — test intent:** at a 390-point viewport, switching away and back retains an intentional reading position. A following session returns to the bottom and keeps following. Tests distinguish pointer jitter, hidden delayed scroll events, and editing keys from intentional scrolling. These are browser tests at phone width, not proof of native iPhone behavior. [Return tests](https://github.com/getpaseo/paseo/blob/33c818cc6b73f7f5ef866a5c0719e0c7d9e75780/packages/app/e2e/browser/agent-scroll-return.spec.ts).

## Streaming and scrolling

- **Paseo — inspected code:** the controller names two modes, `sticky-bottom` and `detached`. Gesture start suspends following so output cannot move rows under a finger. Release resumes following only at the actual end. Content-height changes do not themselves command a scroll. [Bottom-anchor controller](https://github.com/getpaseo/paseo/blob/33c818cc6b73f7f5ef866a5c0719e0c7d9e75780/packages/app/src/agent-stream/bottom-anchor-controller.ts#L495).
- **Paseo — inspected code:** return-to-live first fetches the current tail, then scrolls; failure has its own error path. This matters when older history has displaced the newest window. [Tail navigation](https://github.com/getpaseo/paseo/blob/33c818cc6b73f7f5ef866a5c0719e0c7d9e75780/packages/app/src/agent-stream/timeline-tail-navigation.ts).
- **T3 — inspected code:** the feed starts at the end, maintains visible content, and follows data/layout changes while following. Disclosure animation holds either the content end or the disclosure's anchor in place. Tool detail restoration stores row identity plus within-row offset rather than only absolute pixels. [Feed](https://github.com/pingdotgg/t3code/blob/3a8c250cb0c8056f2f563091fd412fe5db809fa1/apps/mobile/src/features/threads/ThreadFeed.tsx#L2590), [restoration test](https://github.com/pingdotgg/t3code/blob/3a8c250cb0c8056f2f563091fd412fe5db809fa1/apps/mobile/src/features/threads/thread-feed-scroll-position.test.ts).
- **Paseo — native test intent:** its iOS terminal test pans a recognizable marker through successive visible rows. This checks movement of actual content rather than a scroll percentage alone. It does not include simultaneous streaming. [Native terminal test](https://github.com/getpaseo/paseo/blob/33c818cc6b73f7f5ef866a5c0719e0c7d9e75780/packages/app/e2e/mobile/agent-device/native-terminal-scroll.ios.ad).

## Compose and keyboard

- **T3 — inspected terminal UI:** a Back to chat control, terminal picker/new terminal and font-size actions sit in header menus. The keyboard accessory is visible with the keyboard, contains a horizontal key scroller, and keeps Paste and Dismiss keyboard separate. With the keyboard hidden on iOS, one floating keyboard button remains. Keys include arrows, Escape, host-specific modifiers, Tab, Clear and punctuation. [Terminal screen](https://github.com/pingdotgg/t3code/blob/3a8c250cb0c8056f2f563091fd412fe5db809fa1/apps/mobile/src/features/terminal/ThreadTerminalRouteScreen.tsx#L542).
- **Paseo — inspected terminal UI:** normal compact layout uses two rows: Escape/Tab/Ctrl/Up/Shift/keyboard and Alt/Paste/Left/Down/Right/Enter. Wide layouts use one row; very narrow layouts four. Selection conditionally exposes Copy. This favors capability over minimum chrome. [Virtual keyboard](https://github.com/getpaseo/paseo/blob/33c818cc6b73f7f5ef866a5c0719e0c7d9e75780/packages/app/src/terminal/runtime/terminal-virtual-keyboard.ts).
- **Paseo — inspected chat UI:** the density ladder removes labels, then folds thinking/mode/features into the model sheet, then removes the model label. It includes hysteresis so controls do not flicker between layouts near a width threshold. [Control density](https://github.com/getpaseo/paseo/blob/33c818cc6b73f7f5ef866a5c0719e0c7d9e75780/packages/app/src/composer/agent-controls/layout.ts).
- **Paseo — inspected code:** fullscreen composition reserves keyboard space while the Send footer moves with the keyboard. Its chat history classifies a fast flick toward older messages as keyboard dismissal using the existing scroll gesture; a slow reading drag leaves the keyboard alone. That distinction is intentional, but its feel remains unverified. [Fullscreen composer](https://github.com/getpaseo/paseo/blob/33c818cc6b73f7f5ef866a5c0719e0c7d9e75780/packages/app/src/composer/dock/internal/fullscreen.native.tsx), [flick classifier](https://github.com/getpaseo/paseo/blob/33c818cc6b73f7f5ef866a5c0719e0c7d9e75780/packages/app/src/agent-stream/scroll-keyboard-dismiss/model.ts).

## Voice and control

- **T3 — inspected code:** dictation replaces the toolbar with waveform/time, Cancel and Finish. A short flip animates the transition; reduced-motion handling is present. Permission failure offers microphone settings. [Dictation controls](https://github.com/pingdotgg/t3code/blob/3a8c250cb0c8056f2f563091fd412fe5db809fa1/apps/mobile/src/features/voice-input/ComposerDictationControl.tsx).
- **Paseo — inspected code:** dictation distinguishes Insert from Insert and send, with retry and cancellation. Realtime voice is a separate volume-meter surface with mute and stop. These are distinct intentions, not one ambiguous microphone toggle. [Dictation](https://github.com/getpaseo/paseo/blob/33c818cc6b73f7f5ef866a5c0719e0c7d9e75780/packages/app/src/components/dictation-controls.tsx), [realtime controls](https://github.com/getpaseo/paseo/blob/33c818cc6b73f7f5ef866a5c0719e0c7d9e75780/packages/app/src/components/realtime-voice-overlay.tsx).
- **T3 — inspected code:** active-turn composition labels its actual dispatch action: Queue, Steer or Restart; offline delivery says Queue. Editing queued text says Update queued message. [Send presentation](https://github.com/pingdotgg/t3code/blob/3a8c250cb0c8056f2f563091fd412fe5db809fa1/apps/mobile/src/features/threads/composerSendPresentation.ts).
- **T3 — inspected code:** approval presents the requested operation and detail with full-width Allow once, Allow session and Decline choices unless the provider supplies its own options. An unavailable provider process disables response and explains why. These are structured protocol actions; they are not a reason to invent parallel approval state around Loopflow's terminal. [Approval card](https://github.com/pingdotgg/t3code/blob/3a8c250cb0c8056f2f563091fd412fe5db809fa1/apps/mobile/src/features/threads/PendingApprovalCard.tsx).

## Delight and limits

T3's list swipe has a threshold haptic, and its thread-action toast supplies Undo with swipe dismissal. Those make reversible organization feel immediate. Paseo's stable status slot and quiet non-busy states make activity legible without everything animating. These are stronger candidates than importing a large control surface. [Swipe implementation](https://github.com/pingdotgg/t3code/blob/3a8c250cb0c8056f2f563091fd412fe5db809fa1/apps/mobile/src/features/home/thread-swipe-actions.tsx), [Undo](https://github.com/pingdotgg/t3code/blob/3a8c250cb0c8056f2f563091fd412fe5db809fa1/apps/mobile/src/features/home/ThreadUndoNotice.tsx).

Both are real native terminal implementations: T3's iOS terminal uses a Ghostty surface with callback input/output; Paseo renders terminal frames through its native terminal module. This establishes technical capability, not parity in gesture quality or session ownership. [T3 terminal README](https://github.com/pingdotgg/t3code/blob/3a8c250cb0c8056f2f563091fd412fe5db809fa1/apps/mobile/modules/t3-terminal/README.md), [Paseo renderer](https://github.com/getpaseo/paseo/blob/33c818cc6b73f7f5ef866a5c0719e0c7d9e75780/packages/app/src/terminal/native-renderer/terminal-grid-view.native.tsx).

Paseo's website claims full mobile/desktop feature parity and presents interactive mobile scenes. Treat that as product positioning, not tested parity or captured live app behavior. No source inspection here proves one-handed reach, perceived latency, reconnection success, real-device smoothness, or VoiceOver quality. [Official website](https://paseo.sh/).

For Loopflow, the next physical acceptance pass should distinguish: fresh open versus retained return; follow-live versus reading; dragging versus deceleration; keyboard show/hide versus real scroll intent; visible line identity before and after output. Voice, new-session creation and richer status can follow once this foundation feels reliable.
