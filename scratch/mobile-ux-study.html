A terminal you can comfortably read and reply to.

Keep the live Session. Give reading more room, put typing within thumb reach, and keep your place when work continues.

The next design decision is a compact title and a bottom keyboard action. The Desktop colors and typography stay familiar; the phone shows one useful surface at a time.

This is a research comparison and proposed layout. Competitor code, docs and screenshots were inspected; their apps were not operated on a physical device. The illustration below is not a connected terminal.

What each product teaches us

Rex — make the terminal comfortable

A coherent background, native scroll/reflow, selective keys and secondary actions in a palette. Its small pane map represents real desktop splits; Loopflow needs a Session picker instead. iOS settings · actions

Paseo — give reading its own state

Its chat scroll controller distinguishes following the live end from intentional reading. Gestures suspend following; navigation preserves an intentional reading position. These rules transfer to a terminal even though its rendering differs. Controller · return tests

T3 Code — reveal controls when needed

Its native terminal keeps an accessory with the keyboard and a single keyboard button while reading. Menus hold less-frequent terminal actions. Its full key collection is larger than Loopflow needs. Terminal UI

Paradev — make the next reply easy

Compact identity, quiet details and bottom reply controls create a readable hierarchy. Borrow that hierarchy around the terminal; its prose/chat cards are a different interaction model. Mobile guide

A bottom keyboard action requests input control when needed. Latest appears only when you have moved away from the live end.

Continuity is the interaction

Tasks → Selected Session ⇄ Read / type

Proposed continuity rule: opening new work starts at the live end. Returning to retained work restores its chosen Session, draft and reading position. Reading-position restoration after Back/reopen remains to be built. A deliberate scroll claims the viewport; output never takes it back. A deliberate Latest action resumes following.

The illustration shows a phone-sized grid. A retained Desktop-sized grid still needs horizontal panning for wide terminal content. Rex’s swipe-between-panes gesture would conflict with that here; use the Session sheet.

Delight, without more clutter

  1. Fewer interruptions. No list jump on Back, no stale screen replacing a newer choice, no accidental keyboard takeover.
  2. Comfortable controls. Generous targets, a compact accessory only while editing, and the final line always above the keyboard.
  3. Quiet feedback. A stable activity position, short transitions that respect Reduce Motion, and light haptics for deliberate actions—not streamed output.
  4. Voice with an editable result. A future microphone can record → review → insert. Sending stays deliberate. Paseo separates dictation and conversational voice; Loopflow can do the same without adopting its backend.

What to do first

Finish native scrolling, including output during touch and deceleration, oversized Desktop geometry and keyboard changes. Then try the compact header and bottom keyboard action on the actual phone. Measure usable text area and taps to start typing.

Voice capture and focused review screens come afterward. A structured-history reader could help with long prose and tool details, but should be a deliberate view of the same Session, backed by real history.
