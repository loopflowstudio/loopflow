# Paradev session, recovery and terminal UX · 2026-11-09

Reviewed official `ParadevAI/Paradev` at **2764273b198d46b1e39d8ed954ee3eb0141b82cc** (2026-11-09 16:25 UTC): git history and named test bodies. Latest desktop release: [2.0.6](https://github.com/ParadevAI/Paradev/releases/tag/desktop-v2.0.6), November 8, tag commit `7c13c14eb3616d39d9d9021df61caab9f7251fba`. “Released” means ancestor of that tag. Tests and packaged UX were not run. Loopflow comparison: `6394e4e900` and transport/Swift tests, before the ongoing 1a implementation.

## The most useful differences

**1. Restore terminal modes in both directions, without moving the cursor. Released.** A reconnecting viewer can retain a hidden cursor, mouse tracking or bracketed-paste mode that the current program no longer wants. Paradev explicitly asserts defaults as well as enabled modes. It rebuilds its tracker from daemon output after host-service restart, even when that output should not be repainted. The [repair, #6582](https://github.com/ParadevAI/Paradev/commit/66625abd7) reports a real Cursor-agent reproduction: focused input with an invisible cursor after restart, previously healed by switching tabs. Current [mode tests](https://github.com/ParadevAI/Paradev/blob/2764273b198d46b1e39d8ed954ee3eb0141b82cc/packages/host-service/src/terminal/terminal-mode-tracker.test.ts) cover cursor visibility, SGR mouse, paste, focus, Kitty keyboard flags, fragmented sequences, fixpoint resync and a default preamble that leaves the cursor untouched. DECOM reset is specially excluded because it homes the cursor. **Loopflow:** Ghostty repaint and cleanup already cover many modes; much coverage restores into a fresh viewer. Add a dirty-viewer/default-owner case plus actual focused typing after service restart. This is an audit/test gap, not proof Ghostty has Paradev’s bug.

**2. A resize invalidates old output positions. Released.** Paradev found a phone restoring a 45-column buffer while receiving missed output laid out at 120 columns. It records the stream position of the latest resize and reanchors clients whose position precedes it. Hidden clients keep receiving output while dimensions agree; once dimensions diverge, output is withheld until resync. The [#7423 repair](https://github.com/ParadevAI/Paradev/commit/95d87b417) includes the failed initial design: withholding *all* hidden output lost hours of scrollback after its ring overflowed. Its real-PTY [sequence suite](https://github.com/ParadevAI/Paradev/blob/2764273b198d46b1e39d8ed954ee3eb0141b82cc/packages/host-service/src/terminal/terminal.seq-catchup.node-test.ts) tests resize-before-reattach and hidden-client silence. **Loopflow:** terminal recovery already uses a fresh snapshot, byte-stream recovery uses offsets, and the draft fixes first-snapshot sizing. Do not copy its protocol: test desktop-width → phone-width → hidden → desktop-width → return, including focus/cursor and long output. Also test attached passive viewers after the geometry owner changes.

**3. Snapshot and stream position are one coherent checkpoint. Released.** [#6298](https://github.com/ParadevAI/Paradev/commit/1e06887e8) only persists an anchor with a successfully written snapshot after the parser drains; failed anchor writes remove old anchors. The sequence suite exercises gapless reconnect (zero content), in-ring gaps (exact missing bytes), ring overflow, and host restart, checking against daemon output and forbidding terminal reset. [Registry tests](https://github.com/ParadevAI/Paradev/blob/2764273b198d46b1e39d8ed954ee3eb0141b82cc/apps/desktop/src/renderer/lib/terminal/terminal-runtime-registry.test.ts) keep runtimes alive if persistence fails and defer eviction during parsing. **Loopflow:** its owner snapshot and in-memory replay token differ, and it already tests offset catch-up/overflow. Useful extra cases are failure between saving screen and retirement, partial escape/image decoding during surface eviction, and repaint from an inconsistent checkpoint. Do not introduce a redundant client checkpoint solely to match Paradev.

**4. Explicit handling of sockets that look open after sleep. Released.** Its [transport tests](https://github.com/ParadevAI/Paradev/blob/2764273b198d46b1e39d8ed954ee3eb0141b82cc/apps/desktop/src/renderer/lib/terminal/terminal-ws-transport.test.ts) advance wall time two minutes while a fake socket remains OPEN and emits no close; a watchdog redials it. Tests also distinguish transient attach errors from session death, retry without replacing the socket, avoid accumulating offline diagnosis while hidden, and clear diagnosis after stable attachment. **Loopflow:** heartbeats protect owner claims, but the examined viewer loop does not impose a response deadline after attachment; `Reply::Controlled` is ignored. A server bridge that accepts writes but never delivers replies deserves a dedicated test. An unanswered heartbeat must pause input/recover the viewer without restarting its provider.

**5. Fast return without a reconnect storm. Main only, after 2.0.6.** [#9503](https://github.com/ParadevAI/Paradev/commit/d1836e455) keeps a healthy hidden remote terminal socket open so returning reuses it. Hidden socket failure or sleep instead parks it until visible, and a capacity cap still permits eviction. Its transport tests check all four cases. The commit reports ~1.2 seconds of remote redial latency per terminal, with multiple panes serialized by browser connection limits. **Loopflow:** already retains a bounded warm set, so warm surfaces are parity, not absent. Add remote tab-switch measurements and “many hidden panes lose service” tests. Avoid assuming every background terminal should reconnect immediately.

**6. One stable conversation during opening, with a useful host diagnosis. Released.** [#9332](https://github.com/ParadevAI/Paradev/commit/d49e2e361) successively removed “Starting,” “Attaching,” and “Resuming” status lines, ultimately placing actionable failed liveness checks in the host pill. A delayed-notice timer was tried and then deleted. Pending structured prompts stay as faded rows where delivery will appear; floating chips no longer resize the transcript. **Loopflow:** the duplicate workspace/relay opening display is a direct gap addressed by 1a. Borrow the stable placement and single reporting owner, not raw-input queuing. Test one visible status and unchanged viewport across preparation, attachment, recovery and failure, with Find open and narrow panes.

**7. Retain the reading position before first paint. Released.** [#8957](https://github.com/ParadevAI/Paradev/commit/70a803585) keeps transcript content during a session replacement, warms the replacement before swapping, and restores a semantic reader anchor before paint. It handles positions deep inside long replies whose preceding user row is virtualized away. The [chat session tests](https://github.com/ParadevAI/Paradev/blob/2764273b198d46b1e39d8ed954ee3eb0141b82cc/packages/chat/src/react/useChatSession/useChatSession.test.tsx) verify immediate cached display, events arriving between prefetch and mount, and keeping cached content when the journal cannot be read. **Loopflow:** retained terminal screen/scrollback is not the same as the human’s viewport position. Test returning while scrolled far up, across warm remount and cold restore, without a transient bottom-of-transcript frame. Fresh snapshot correctness alone does not prove this.

**8. Unreachable does not become empty. Released.** A newly mounted observer briefly saw no host URL and overwrote cached workspace and resume-candidate data with empty values. The final [#9373 fix](https://github.com/ParadevAI/Paradev/commit/3b5472d2f) omits unavailable observers’ query function so a reachable observer can serve the refresh. The [test](https://github.com/ParadevAI/Paradev/blob/2764273b198d46b1e39d8ed954ee3eb0141b82cc/apps/desktop/src/renderer/lib/hostQueryFn/hostQueryFn.test.ts) keeps three live rows despite an offline observer invalidating the query. **Loopflow:** test selected Session, cached screen and inventory remaining visible through a transient failed refresh and a second surface mounting. This is a relevant failure shape, not evidence Loopflow uses the same empty-result pattern.

**9. Interrupted execution gets an explicit recovery experience. Mixed release status.** [Agent-session docs](https://docs.paradev.com/agent-sessions) describe automatic resume only after unexpected death, a Resuming indicator, and failed-resume Retry/dismiss; intentional closure and clean exit stay closed. [Persistence tests](https://github.com/ParadevAI/Paradev/blob/2764273b198d46b1e39d8ed954ee3eb0141b82cc/packages/host-service/src/terminal-agents/persistence.test.ts) cover one-time claiming, unclaim-for-retry, late goodbye, and sticky disposal. Main-only [#9515](https://github.com/ParadevAI/Paradev/commit/ff716fef7) retains ended scrollback, saves it after parser completion, prevents repeated exit lines even when wrapped, and offers New shell without losing preceding output. Main-only [#9432](https://github.com/ParadevAI/Paradev/commit/1fbc5764b) settles interrupted chat turns and offers to resume them. **Loopflow:** saved previews, unknown outcomes and explicit owner transfer already exist. These are interaction/product-policy differences; automatic provider restart must not be inferred from “Retry connection.” Useful tests: intentional close never resurrects; clean vs crash exit remain distinguishable; reconnect does not duplicate exit text or erase the failed command.

**10. First-keystroke retention is a deliberate alternative. Released.** [#8456](https://github.com/ParadevAI/Paradev/commit/295bb0fc5) buffers initial attach input up to 8,192 characters and five seconds, sends it only after visibility and geometry, and discards it on park/disconnect/expiry. Tests cover early typing and expiry. It also stopped claiming unsupported Kitty identity after that choice broke copying, cursor-agent startup, and graphics. **Loopflow:** the chosen design explicitly pauses and discards input until acknowledged. Keep that policy; test the visible paused cue and immediate first valid keystroke. Audit inherited terminal identity against the capabilities actually served, including piped output.

**11. Mouse/scroll behavior survives serialization. Released code; mobile release not verified.** [#8737](https://github.com/ParadevAI/Paradev/commit/fd842e399) repaired Codex scrolling after mobile tab switches by serializing SGR/pixel mouse encoding, not only tracking mode; it also forwards safe default-encoded mouse reports. Its regression checks a real serialize/restore round trip. **Loopflow:** test scroll, selection and mouse reports after reconnect, including an initially armed mode that later turns off. Same pixels are insufficient if input modes changed.

## Launching, progress and moving between devices

**12. Launch where the person chose, despite late inventory. Released.** [#9287](https://github.com/ParadevAI/Paradev/commit/891fa1e832) stopped resetting Cloud to This device when a feature read or project list briefly disagreed. Link intent outranks saved host, which outranks local default; only an explicit picker action saves the preference. The `resolveLaunchHost` and `resolveLaunchProject` tests cover host precedence, repository identity across hosts, a just-added project missing from inventory, and holding the choice while loading. **Loopflow:** exact recorded Machine routing and no local fallback already exist. Borrow the launch-form tests: a late host/project inventory must not silently move a new Session, overwrite a preference, or substitute another project. This is a concrete multi-machine UX check, not a request to migrate a running process.

**13. Starting lasts until the destination is reachable. Released; implementation/commit reproduction, no added automated test.** [#9436](https://github.com/ParadevAI/Paradev/commit/95fe87417d) keeps the provisioning display and elapsed timer until the cloud host address arrives, instead of replacing it with a blank pane when the database first says ready. The commit reports 26 seconds of blank UI before the fix on an older cloud image. **Loopflow:** test that a Task or Process marked created does not mean the conversation is already usable. Slow remote preparation should retain the same pane and meaningful progress, and cancellation must leave its execution outcome truthful.

**14. Mobile progress is incremental and does not fight reading. Code in the desktop tag; corresponding mobile binary not verified.** [#9184](https://github.com/ParadevAI/Paradev/commit/b31e31b121) fixes native mobile chat displaying a reply only when its turn ended: streaming text becomes list data, with only changed rows replaced. `withRowText.test.ts` verifies stable identity for unchanged rows and new text for the changed row. The UI also disables following while the person drags upward; that part is implementation evidence rather than a behavioral UI test. **Loopflow:** future phone surfaces should share progress semantics while testing native rendering separately. Add “stream updates before completion,” “one active row changes,” and “drag to read older content is not pulled back down.” Terminal output and Process liveness alone do not verify progress visibility.

**15. Attachments follow the execution destination. Released feature, current-source routes checked.** [#9064](https://github.com/ParadevAI/Paradev/commit/0cb6cbe039) repaired image paste/drop races and aligned terminal, chat and mobile attachment handling. Current `sendAttachmentsToWorkspace.test.ts` verifies cloud upload/anchor/materialize, remote-host worktree writes, local copy/blob writes without storage, unique paths, rejected uploads, path-count mismatch and filenames in errors. **Loopflow:** native terminal paste/drop currently inserts paths; that can be right locally and useless when execution is elsewhere. Test dragging a local image into a remote Session and confirm the provider receives an accessible destination path, with cancellation and clear per-file progress/error. This deserves separate scope from reconnecting.

**16. Moving between chat and terminal is an explicit fork. Main-only simplified UI; underlying fork feature released.** [#8932](https://github.com/ParadevAI/Paradev/commit/c59ee232c8) waits for an agent to finish starting before fork, keeps hidden loader sessions out of automatic tab adoption, and follows a pane moved while the fork runs. It suppresses unsupported Codex CLI-to-chat conversion because the ACP adapter cannot load the held native session. [#9529](https://github.com/ParadevAI/Paradev/commit/b45ebb169e) simplifies the action to opening a fork in a new tab; the default surface setting no longer hides the other surface. **Loopflow:** this is not seamless same-thread process migration. Preserve that distinction in future Desktop/mobile product language. Tests worth borrowing: no duplicate tab from the temporary loader, startup failure terminates a pending fork, and the source conversation stays intact.

## First tests to bring home

1. **P0:** dirty viewer + current owner in default modes → correct cursor, physical typing, scrolling and paste immediately after reattach; repeat across service restart.
2. **P0:** bridge stays writable but stops replying → detect stale connection, pause input, preserve owner/turn, recover without replay.
3. **P0:** preparation → attachment → native readiness → failure/recovery has one display and stable geometry; status persistence failure cannot kill it.
4. **P1:** desktop/phone size transitions and hidden viewers cannot render old-width bytes; retain scrollback when no resize occurred.
5. **P1:** return while reading old output, including cold restore and a long virtualized reply; assert the first painted frame, not eventual state.
6. **P1:** failed cache/snapshot write and concurrent stale inventory refresh preserve the live view and selection.

Paradev has repeated repairs and reversions: [#6298](https://github.com/ParadevAI/Paradev/commit/1e06887e8) replaced a repaint approach that blanked panes after restart. Loopflow already covers replay, ownership, snapshots and process survival; compare their combined experience, not feature counts.
