# Paseo recovery and transport UX · 2026-11-09

Inspected official `getpaseo/paseo`, main **e0f545fed485d244fcd3e6308c36e5a6397eaa2e** (2026-11-09), its last 150 commits, relevant patches, production code and tests. Latest stable is [v0.15.3](https://github.com/getpaseo/paseo/releases/tag/v0.15.3), published November 6, release commit `d91ae138cb931447635e94296023414a58bedcc5`. Several strongest findings landed November 8–9 and are **main implementation, not claims about the released app**. Tests/application were not run; “test-backed” means inspected assertions.

Comparison baseline is Loopflow draft `6394e4e900`: `transport/README.md`, `transport_tests.rs`, `ServerConnection.swift`, `WorkspacePanesView.swift` and Desktop connection tests. Its detached owners, snapshot replay, no uncertain input replay, and explicit input takeover already provide much of the transport foundation.

## Concrete improvements to learn from

### 1. Returning to an unchanged conversation should do almost nothing

**Main, November 9; browser and unit tests.** [9a5b4ae](https://github.com/getpaseo/paseo/commit/9a5b4aefa46baae7c686d0dc7b7a3f6b69e48c0c) sends the cached timeline cursor with subscription, letting the daemon answer current/behind in one round trip. Unchanged chats avoid another history fetch and an Updating toast. Subscription is installed before comparing the cursor, avoiding a missing-event interval. 

The [browser resume spec](https://github.com/getpaseo/paseo/blob/e0f545f/packages/app/e2e/browser/agent-timeline-resume.spec.ts) checks background return, dropped connection and reload: no Updating toast, no unnecessary fetch, unchanged reading position. Changed history stays visible until catch-up lands.

**Loopflow:** the current patch improves geometry but still has preparation and relay status owners. Transfer the visible invariant—no redundant opening flashes or scroll movement when the conversation is unchanged—rather than transplanting structured-history RPCs into its terminal relay.

### 2. Paint cached content without pretending it is current

**Main, test-backed.** The [replica tests](https://github.com/getpaseo/paseo/blob/e0f545f/packages/app/src/timeline/replica.test.ts) cover immediate cached paint without synchronization authority, a late cache read losing to newer network state, and live output arriving during cache loading without duplicate text. The [screen-state tests](https://github.com/getpaseo/paseo/blob/e0f545f/packages/app/src/hooks/use-agent-screen-state-machine.test.ts) keep previously painted history readable through reconnect, overlapping revalidation and failed catch-up; first-load failure is distinguished from later nonblocking failure.

**Loopflow:** saved terminal preview is already history, not input permission. Missing coverage is the complete visual handoff across workspace preparation, surface mounting and relay readiness, including late callbacks and an unavailable status channel. This supports the chosen opening experience.

### 3. Show completion together with the output that explains it

**Main, November 9.** [b2b82e5](https://github.com/getpaseo/paseo/commit/b2b82e5cb0a4cf765b28a623664d6a130a285033) prevents a completed footer appearing under stale messages when the agent directory updates before transcript catch-up. The old running footer and original elapsed start time remain until the corresponding messages are committed. They deliberately removed a new “catching up” footer because it added another transient state.

The [browser turn-end tests](https://github.com/getpaseo/paseo/blob/e0f545f/packages/app/e2e/browser/agent-turn-end.spec.ts) delay catch-up under both prompt-only and partial-reply screens, and assert footer geometry on completion.

**Loopflow:** provider terminal output and Program Status/work projections are separate. Test their ordering during reconnect before concluding this exact defect exists. 

### 4. Measure recovery after suspension, not merely socket reconnection

**Main, November 8.** [f539ccf](https://github.com/getpaseo/paseo/commit/f539ccf1c00f17c2f4b8925fcd1d11d40118583e) documents a transport measurement of approximately 41.5 seconds before reconnect when an OS-suspended socket still appeared OPEN and accepted writes. Foreground recovery now uses two fresh five-second evidence windows and immediate reconnect after teardown. Repeated foreground events share the cycle. Any validated inbound progress keeps slow transfers alive; stale pre-suspension activity does not.

[Client tests](https://github.com/getpaseo/paseo/blob/e0f545f/packages/client/src/daemon-client.test.ts#L2612) exercise second suspension during verification, timer-before-AppState ordering, delayed pong behind megabytes of chunks, and healthy socket retention. They explicitly acknowledge a single frame delayed beyond both windows can still be disconnected.

**Loopflow:** existing heartbeat/bridge tests cover failure and retry, but no comparable Desktop foreground verification was found in the inspected files. Adopt wall-clock suspension tests and measure time to usable input, not just the connected label. 

### 5. A recovered connection must not be replaced by stale failover results

**Main implementation with regression tests.** [b0a8a5d](https://github.com/getpaseo/paseo/commit/b0a8a5db6d5cc64a802c0f56fa91da8ada2647a3) fixes a second reconnect: the selected connection recovered while a slower alternative probe was pending, but the old unavailable verdict still switched routes and rejected timeline catch-up. Tests cover a recovered primary with and without heartbeat RTT, and required failover.

**Loopflow:** not evidence of a missing multi-route feature. Apply the race to existing owner/location preparation and surface generations: late lookup or failed old attachment must not tear down a newly working pane. Do not add competing reconnect owners.

### 6. Preserve unsent drafts across navigation and reload

**Main, November 8.** [22f50d4](https://github.com/getpaseo/paseo/commit/22f50d4dfa6f7f4795f737e2994283e04c75d592) preserves local composer drafts when closing/archiving a root agent tab, clearing only on explicit entity deletion. Its browser test types an unsent draft, closes the tab, reloads and restores the conversation, then checks the text.

**Loopflow:** native provider editors own drafts; a saved terminal image cannot reconstruct them. Loopflow protects live drafts against owner retirement, which is useful parity. A client-owned persisted composer would be a product/architecture change, not a small relay fix. Test draft survival in surviving providers separately from crash restoration; never replay raw keys to simulate draft recovery.

### 7. Distinguish request failure from a message already accepted

**Main, unit tests.** [Submission tests](https://github.com/getpaseo/paseo/blob/e0f545f/packages/app/src/composer/submission/model.test.ts) track concurrent sends independently, keep activity until canonical acknowledgment, and refuse to roll back a provider-acknowledged prompt after a later RPC error. This avoids “my message vanished” and duplicate resend pressure.

**Loopflow:** native clients already own prompt acceptance. Its no-uncertain-byte-replay rule is correct. Transfer these tests to structured inputs, native correlation and receipt UI where identity exists; this does not justify buffering terminal typing during disconnection.

### 8. Keep long catch-up from looking frozen or breaking transport

**Main, unit/browser/integration tests.** [Viewed timeline tests](https://github.com/getpaseo/paseo/blob/e0f545f/packages/app/src/timeline/viewed-timeline-sync.test.ts) distinguish live gap recovery (page fully to current) from first return after many missed pages (one bounded catch-up then latest complete-turn tail). Older history remains accessible. They retain the old subscription until its replacement is acknowledged, preventing hidden chats dropping events during route replacement.

[01888dc](https://github.com/getpaseo/paseo/commit/01888dc5deb7c964491f784f260cb64378a7c4ed) adds end-to-end routed flow control after the final recipient drains, while concurrent small sends remain possible. Integration tests slow one consumer and verify sibling routes continue.

**Loopflow:** its bounded spool, fresh snapshots and slow-viewer isolation already cover equivalent terminal needs. Add end-to-end tests where a huge replay and control/status traffic share a remote path; unit queue bounds alone do not establish responsive input.

### 9. Terminal restoration preserves behavior, not just text

**Main, serializer and PTY tests.** [28c01ea](https://github.com/getpaseo/paseo/commit/28c01ea1cede5bf012b2bdceb1dd34bbd0bfde3e) restores mouse encoding as well as tracking after Copilot scrolling broke on conversation switches. [Terminal tests](https://github.com/getpaseo/paseo/blob/e0f545f/packages/server/src/terminal/terminal.test.ts#L1712) check emitted wheel encoding, client cursor defaults, program cursor presentation, full-width pending-wrap and primary/alternate-screen replay.

The [mobile rendering guide](https://github.com/getpaseo/paseo/blob/e0f545f/docs/terminal-rendering.md) specifies measuring grid size before attach; its reattach harness changes keyboard/fold geometry and compares actual client rows against terminal capture. It also documents Unicode-width agreement and known bidi limits.

**Loopflow:** correct-size snapshot and rich-mode replay are already present. Add physical wheel, pending-wrap, emoji-width/cursor and viewport-scroll restoration checks. 

## Launching, following work and moving across devices

### 10. The first prompt gets a usable pane before creation finishes

**Main, browser tests.** [Title/handoff tests](https://github.com/getpaseo/paseo/blob/e0f545f/packages/app/e2e/browser/workspace-agent-title-handoff.spec.ts) delay authoritative creation and history responses: the submitted prompt and optimistic tab stay visible, no history overlay appears during handoff, and the temporary prompt title becomes the generated title in place. [Navigation tests](https://github.com/getpaseo/paseo/blob/e0f545f/packages/app/e2e/browser/new-workspace-navigation-guard.spec.ts) ensure a delayed launch cannot pull someone back after they select another workspace or replace a newer draft.

**Loopflow opportunity:** test first launch as a continuous interaction, including navigating away mid-launch. Its native composer limits optimistic rendering; navigation intent still transfers.

### 11. Creation progress survives its observing connection

**Main, code and tests.** The daemon keeps cumulative creation milestones and permanent IDs under an idempotency key. The client can reobserve that operation after losing its socket. [Creation tests](https://github.com/getpaseo/paseo/blob/e0f545f/packages/client/src/creation/index.test.ts) make duplicate submissions join and prohibit progress regression; first-prompt rejection leaves an existing agent with a turn error rather than reporting creation failed and inviting another agent. Uncertain side effects are not blindly repeated.

**Loopflow:** Task/Session identity already survives; do not add another execution identity. Audit whether Desktop can distinguish “creation admitted, observation lost” from “nothing created,” then test reconnect without duplicate Session/provider launch. Paseo's journal is a different product architecture, not a drop-in requirement.

### 12. Progress remains discoverable without stealing focus

**Main, browser tests.** [Unread-work tests](https://github.com/getpaseo/paseo/blob/e0f545f/packages/app/e2e/browser/sidebar-workspace-mark-unread.spec.ts) preserve manual unread on departure, keep another agent unread when reopening a multi-agent workspace, and retain a completion across reconnect until another click acknowledges it.

**Loopflow:** Program Status and attention already exist. Transfer the invariants: reconnect/focus restoration must not count as reading; one Session's selection must not clear another's attention. The completion/footer ordering tests above add the visual half of this behavior.

### 13. Notification taps work through cold startup

**Main, model tests plus documented native verification.** [Notification-open tests](https://github.com/getpaseo/paseo/blob/e0f545f/packages/app/src/notification-open/model.test.ts) wait for navigation readiness, handle launch taps once across remounts, reject replayed launch events and handle distinct taps separately. Navigation resolves current host/agent placement instead of trusting an old workspace hint.

**Loopflow opportunity:** verify cold/warm deep links to an exact Session while inventory is loading, including moved workspaces and a second tap. This is especially useful for phone-to-desktop continuity; no claim that Loopflow's existing deep links are absent or broken.

### 14. One destination identity across direct and routed connections

**Main, integration tests.** [Connected-host tests](https://github.com/getpaseo/paseo/blob/e0f545f/packages/server/src/server/connected-hosts/hosts.e2e.test.ts) retain unreachable saved hosts until they become available, isolate sibling logical sessions, preserve destination identity on lost mutation responses and refuse automatic mutation replay. The app can open a remote child using its destination-qualified identity through direct or routed transport.

**Loopflow:** explicit Machine routing/no local fallback is parity. Test stable conversation identity across route changes, errors naming the Machine, and intact sibling panes. This is access to the same remote execution, not live migration of provider memory between machines.

### 15. Mobile navigation preserves the work under motion and resizing

**Main, interaction tests.** [Panel tests](https://github.com/getpaseo/paseo/blob/e0f545f/packages/app/src/mobile-panels/model.test.ts) keep the old panel active until motion settles, ignore a stale gesture finishing after a newer command, and preserve the latest rapid navigation. [67628b4](https://github.com/getpaseo/paseo/commit/67628b48fe4c6ec05fbaccca7be4573605c5c5b8) adds a compact-screen test so overflowing plugin navigation cannot shrink the workspace list to zero.

**Loopflow mobile direction:** stable session identity and presentation should survive keyboard, rotation, swipe cancellation and navigation. Reuse ownership and projection models; do not let transient animation states attach/detach providers. These are future-client tests rather than current desktop defects.

## Recovery limits worth preserving

Paseo's [terminal worker](https://github.com/getpaseo/paseo/blob/e0f545f/docs/terminal-worker.md) survives daemon loss and retains PTYs; Loopflow already has detached owners, so this is parity rather than a reason for another daemon. Worker replay failure is viewer-scoped, and terminal stream tests distinguish failed observation from actual PTY exit.

[Agent recovery](https://github.com/getpaseo/paseo/blob/e0f545f/docs/agent-lifecycle.md) is opt-in, reopening history and sending a continuation prompt. It documents possible loss/repetition across crashes and no exactly-once guarantee. The v0.15.3 config also defaults recovery off. Copying this would change Loopflow's no-replay contract.

## Test priorities for Loopflow

1. **Now:** one status from open to usable input; cached screen remains selectable through status-write failure; stale surface callbacks cannot enable typing.
2. **Now:** unchanged return causes no unnecessary status flash, screen clear, scroll jump or resize; complete cold/warm/reconnect paths in the real app.
3. **Next:** sleep with a silently dead bridge, repeated foreground, and slow-but-progressing output; record time to usable input and prove no replacement provider or duplicate prompt.
4. **Next:** long replay plus control traffic, later reconnect while an older attempt completes, live output during snapshot installation, and unaffected sibling viewers.
5. **Next:** provider draft retention, full-width cursor/wrap, mouse-wheel modes, alternate-screen return and emoji cursor parity; separate native-editor survival from saved-screen rendering.

Paseo pairs controlled event-order tests with browser/device assertions. These guarantees are still being repaired.
