One plan at every size

A save does the same thing whether Loopflow runs on one Machine or for half of a hundred-person company. Each step up is one person doing one thing, and nothing below it is replaced.

What to decide here: whether this replaces "the hub owns the plan", which the LOO-938 branch implements today. The ten tradeoffs are listed before the questions. Design: scratch/plan-design.md.

exists on main or on this branch. proposed not built.

The rule

  1. A save writes this Machine's store and stamps each changed field. The stamp is a counter, one more than the highest this Machine has written or seen, plus the Machine's id.
  2. The plan is the newest stamp for each field.
  3. Comments, ownership entries and new records only append. They never conflict.
  4. A claim is first-wins. Of two claims that never saw each other, the lower stamp holds the Task.

The counter is why clocks don't matter: an edit made after seeing yours always beats yours.

How values travel

Git, always proposed

Each Machine writes one ref, refs/loopflow/plan/<machine id>, holding the newest value it wrote for each field. Only that Machine pushes it, so a push never races and Git never merges. Reading is one fetch of all plan refs, on one timer per repository in the Machine's server (today: one per open Session exists).

A hub, when named exists, changed

lf machine hub mini names a reachable Machine: its own box, or one person's Machine. Values go over the server connection and come back live. The hub applies the same rule and decides nothing. When it can't be reached, Git carries everything; several people can name the same one.

Linear or Asana, between people exists

A repository's people meet through Git or through a tracker, never both. The tracker carries what it has fields for, by its own rule (keep theirs / use mine). Your own Machines still use Git and the hub for everything.

A team's Linear

Your slice proposed. A Wave links to a Linear Project. Loopflow keeps issues assigned to you and the ones you create. The rest of the Project is read when you look and never written. Taking a whole Project exists stays for one a single person owns.

$ lf task list -w growth --available
ENG-398  Email verification retries      priya   unassigned
$ lf task claim ENG-398
ENG-398 assigned to you in Linear; it is a Task now.

Data Linear has no field for

  • Which Wave a Task is in comes from the link: the Wave linked to its Project. Everyone derives the same answer; nothing is stored.
  • Backlog order is the Project's order, shared. Reordering unclaimed Tasks writes Linear's own manual order, so the whole team sees it, on Loopflow or not: "you shoudl be able to reorder tasks for other people".
  • The order of the Tasks you have claimed is yours. It is not the Project's order and changes nobody else's view.
  • Anything later that must be shared goes in one attachment on the issue. Linear's attachments take key-value metadata (reachable by API only) and are keyed by URL, so writing one again updates it. People see it as a link.

Passed over: a label per Wave, markers in the description, a Git ref beside the tracker.

What it gives up

1. A losing edit vanishes from the plan. Two people change one field; the later stamp wins and nothing marks the other. It survives only in that Machine's ref history.

2. Without a hub, two people can start the same Task. The window is one fetch interval. The later claim's run stops when it learns, keeping its work.

3. Nobody is in charge of the plan. Anyone who can push to the repository can write any field of any Task. A hub does not check or refuse.

4. The plan is as private as the repository. Every clone can fetch the plan refs.

5. One ref per Machine. Rented Machines add refs; a Machine that is gone keeps its ref until another adopts its values.

6. A fetch timer returns. Once per repository per Machine, not per Session. Without a hub the plan is fresh to within the interval.

7. Two conflict rules stay in the product. Stamps between Loopflow Machines; keep theirs / use mine with a tracker.

8. Reordering the backlog reorders it for everyone, including teammates not on Loopflow. Chosen. The order of your claimed Tasks stays yours.

9. Teammates do not see each other's runs. Only what the plan holds.

10. Part of today's build is undone. The branch deleted Git plan sync; this brings back a smaller one, and the hub stops being the home.
