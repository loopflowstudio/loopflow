# LOO-1067 · Redesign the file browser

> Jack Heart, November 22: “lets do directions 1 and 2”
>
> “4a i think --read only by defautl / easy to turn on editable”

**Done when** you can find a file in an unopened folder, preview it, jump from a call to a declaration and back to the same line, and put a comment on those lines into the Task conversation. An agent can present a finished page beside that conversation. While you read, edit or review, ordinary writes leave your place and keyboard focus alone. Desktop reads files from the Machine that owns the checkout. Both directions land in one PR. The [Round 3 prototype](explore.html), [design](design.md) and [concept review](concept-review.html) record the layout and model.

## Experience and model

Keep `Brief`, `Diff` and `Files` in the pane strip. Cleanly separate **working-tree state** from **Diff comparison state**, and decompose `TaskFilesStore` so it acts as the thin Task-inspector coordinator (transport, file watcher, working-tree changes, scratch inventory, shared `comments`) delegating to focused collaborators (`FilesBrowserState`, `DiffReviewState`, `CheckoutTree`):

- **Working-tree state vs. Diff comparison:** Keep `workingChanges: TaskChangesSnapshot?` pinned to `workingTree(base: "parent")`, independent of `DiffReviewState.comparison` (whole Task vs. a Graph step vs. a branch tab). Selecting a step in `Diff` never overwrites Files' `Changed in Task` counts, `⌘P` Changed mode, Read change marks, per-file draft Diff, or Brief's delivery head. Scratch listing comes from the checkout inventory (`task.files.find`) rather than `git diff`, so `scratch/` stays visible even on a step Diff or when a comparison base is missing.
- **Header and rail:** Files has one 32-point header with a sidebar button, jump history (`‹`/`›`), an interactive path breadcrumb and document actions. A folder segment opens its siblings; the filename switches or closes open files; the enclosing symbol follows the reading position. Open files also appear at the top of the empty `⌘P` picker (choice for review over a second tab row). Keep the recorded Machine and full path accessible from the breadcrumb.
- **Responsive rail:** The 236-point rail docks at 620 points and opens as a dismissible drawer below that width, using Diff's layout and named design tokens. **Open & Scratch** shows open files, unsaved drafts and updated paths. **Changed in Task** shows counts from `workingChanges` (the whole Task). Give each rail section distinct row IDs (`open:<path>`, `changed:<path>`, `entry:<path>`) inside the `LazyVStack` so an open changed file never collides with and vanishes from Changed in Task. **Checkout** keeps keyboard navigation, paged directories, retries and scroll position, compacts single-child directories only once their listing is complete, reveals the selected path through its ancestors, and starts a fresh listing when toggling Show Ignored (Rust directory cursors encode `show_ignored`). At 360 points the header folds actions into its menu and a file pick dismisses the drawer; the pane strip scrolls its selected tab into view so narrow panes never clip `Files`. [CheckoutTree.swift](../swift/LoopflowMac/CheckoutTree.swift) · [TaskChangesView.swift](../swift/LoopflowMac/Views/TaskChangesView.swift) · [WorkspacePanesView.swift](../swift/LoopflowMac/Views/WorkspacePanesView.swift)
- **Read default, per-file mode, lazy native editor:** Every newly opened file starts in **Read**. Code renders syntax-colored, selectable, line-numbered lines with whole-Task change marks in the gutter. Markdown and HTML render, and images open as pictures. **Read always renders `document.text`** (including unsaved draft text, with draft/save status visible) so returning to Read never hides local edits. View mode (`.read | .edit | .diff`) is **per-file** (choice 3a for review): toggling **Edit** (`⌃⌘E` or button) on one file survives jumping to another file in Read. Create `TaskFileDocument`'s `NSTextView`, `NSScrollView` and `UndoManager` **lazily on first entry into Edit** (setting `usesFindBar = false` so it never collides with Files' inline Find) and retain them across toggles so caret, undo, IME composition, 3-way merge and save recovery stay intact; while `editor == nil`, `reconcile` updates `text` directly. Changed or dirty files also offer their draft-aware **Diff**, where `[`/`]` step changes within that file only (no silent file switching). Top-level `Diff` keeps its whole-Task and step comparisons, review layouts, tour, viewed state and delivery card. Keep every current grammar, filename association and plain-text fallback. [Grammar.swift](../swift/LoopflowMac/Grammar.swift) · [LOO-1040, PR 2013](https://github.com/loopflowstudio/loopflow/pull/2013)
- **Open files vs. Jump history vs. Drafts:** Keep persisted `WorkFileTab` identity in `WorkBrowserTab.files`, but separate **Open files** from **Jump history** (`(path, line)` back/forward stack pushed only on accepted jumps or presentations). Bound clean auto-added open files (MRU cap, e.g. 12) so 2-second `gd` jumps do not flood Open & Scratch. Closing a clean file removes it from open files and drops its document; dirty drafts always remain visible in Open & Scratch until saved or discarded (never hidden as phantom autosaving buffers).
- **Unified line comments:** Click or Shift-click a line in Read or Diff to comment, copy or reference a range using the same `ReviewCommentEditor`, `ReviewCommentsStrip` and `TaskFilesStore.comments` queue. Give `ReviewSelection` a typed `Source`: `.file(draft: Bool)` (working document, anchored against `document.text` and re-anchored on edits/reconcile) vs. `.diff(side: Side, revision: String)` (comparison side, anchored against that file's diff lines). Each surface displays and re-anchors **only** its own source's comments (a Read comment never detaches on a Diff refresh or renders at the top of Diff). An ambiguous or vanished anchor keeps its original reference and notes that the lines changed. `⌘↩` formats each comment with its true source (`working file` / `unsaved draft` vs. diff side and revision) and inserts the batch into the conversation's **unsent input**. An unavailable conversation or failed insertion leaves the queue intact. [ReviewDiff.swift](../swift/LoopflowMac/ReviewDiff.swift) · [ReviewStreamView.swift](../swift/LoopflowMac/Views/ReviewStreamView.swift)

## How a file gets shown

`follow()`, `autoSelected`, the 120 s timer and passive document creation are gone (commit cd28c4baad). Three explicit paths show a file:

- **One-time initial pick:** On first entry to an empty Files pane (`!hasChosenInitialFile`, after restoring tabs and drafts), pick the newest eligible `scratch/` Markdown or HTML page (reported by modification time with a stable path tie-break from `task.files.find`), else the first changed file, else the empty picker. Mark `hasChosenInitialFile = true`. Closing the last tab, later writes, or viewing Brief/Diff never repeat this choice.
- **Passive writes and calm updates:** Both the local watcher (`TaskFilesStore.invalidate`) and the peer watcher (`watch_task_files::relevant_paths`) pass eligible `scratch/` page writes through even when `scratch/` is gitignored, refreshing the scratch list and update badges **without** triggering a `git diff` comparison reload when only gitignored scratch changed (keeping journal and build noise out). Separate **persistent rail badges** (`updated`, `presentations` in Open & Scratch) from the **ephemeral banner** (`FilesBrowserState.Notice`: `.presented(Presentation)` or `.updated(String)`): an observed write for a path **not** currently visible in Files Read badges its path in Open & Scratch and sets a dismissible (`×`) layout banner (`Updated scratch/explore.html · Open`), coalescing repeated writes to one path; writing to the file already visible in Files Read reloads it calmly in place without raising an Open banner. Switching files or leaving Edit clears stale presentation banners. Render the banner inside the layout stack (never as a bottom `.overlay` covering code, Diff, or Brief) — shown on `Files`, and on `Diff` only for `.presented` offers during Diff review. Reconcile open documents normally, including hidden dirty drafts. Key `TaskHTMLView` by `.id(document.path)` so initial opens and file switches load immediately at scroll `(0, 0)`, while writes to the **same** visible HTML document wait 800 ms of quiet before reloading once and restoring scroll. On disconnect retain drafts and offer Refresh. Keep offline HTML rules, external link handling and remote base-URL behavior. [TaskFileDocument.swift](../swift/LoopflowMac/TaskFileDocument.swift) · [workspace.rs](../rust/loopflow-execution/src/ops/task/workspace.rs)
- **Deliberate presentation.** Extend the existing `lf desktop files [PATH[:LINE[-END]]] [--mode read|diff]` beside `lf desktop browse` and `lf desktop graph-log` as the **single** presentation command, and delete the replaced `lf open --file` path (`rust/loopflow/src/lf/commands/open/files.rs`, `OpenArgs.files`, `desktop::present_files` and its old `work_open_tests.rs` cases). Keep cross-host conversation opening on `lf open`. Without a path, `lf desktop files` shows Files. A path opens in Read by default, reuses its tab, reveals the requested lines and records the prior reading position. Use `MultiplexerStore.isVisible(pane)` (not `!collapsedPaneIds.contains`) so a browser pane hidden behind a zoomed Session never silently defers a presentation; when `showBrowser(..., focus: false)` runs while another pane is zoomed, clear `zoomedPaneId` while keeping `focusedPaneId` on the terminal so the presented page appears beside the conversation without stealing terminal focus, drafts or Undo. During active visible Edit or Diff review, add the path to Open & Scratch and show a dismissible `Presented <path> · Open · ×` banner for explicit acceptance. Migrate artifact guidance in `explore`, `concept-review`, `demo`, `qa`, `write-docs`, `ship-review` and `LOOPFLOW.md` with the new command. Treat exit 4 (Desktop unattached) quietly. ## Search, symbols, focus and ownership

**One picker** has Files (`⌘P`), Grep (`⇧⌘F`) and Changed modes. Arrow keys preview without changing open files, jump history or selection. Return opens the selected line. Escape returns focus and place. Wide panes show a syntax-colored preview centered on the hit beside results; narrow panes show the list first. Grep rows highlight the matched text inside each excerpt so multiple hits on one line read distinctly, and long single-line previews reveal the hit horizontally. Fuzzy path ranking favors scratch, changed and open matches, then match quality and path. Changed reads `workingChanges` even after visiting a step Diff.

**Three peer Machine reads in `ops/task` → `Read` → `RegistryQuery`** (choice 2a for review — one verb, one JSON schema, matching `lf task file|files|changes|diff`). Keep CLI execution, SSH routing, served argv/results, generated server schema, Rust and Swift fixture decoding in agreement; required nullable keys stay present on the wire. The Mac never enumerates a peer's path. [read.rs](../rust/loopflow/src/lf/commands/read.rs) · [RegistryQuery.swift](../swift/Loopflow/Services/RegistryQuery.swift) · [served reads](../rust/loopflow/tests/served_reads.rs)

1. **`lf task find <issue> [query]` (`task.files.find`):** Enumerates tracked and nonignored untracked paths via the checkout's existing Git plus bounded `scratch/` entries (deduplicated, keeping tracked files matching ignore patterns and skipping deleted/escaping symlinks), along with `scratch` paths and `latest_scratch_page` (newest eligible `.md`/`.html` by mtime, path tie-break). Caches the checkout inventory in bounded Machine memory via `observe` (keyed by checkout + Git index/ignore/membership revisions). When `query` is omitted and the inventory fits within 2,000 paths, returns the complete list in one reply (`truncated: false`) so Desktop fuzzy-filters locally at 0 ms per keystroke. For larger checkouts (`truncated: true`), Desktop sends debounced `query` and the Machine fuzzy-matches over its **complete** cached inventory, returning the top ranked matches (`limit`, default 100) in one reply—no cursor paging loop.
2. **`lf task grep <issue> <query>` (`task.files.grep`):** Searches the same inventory using ripgrep's pure-Rust `grep-searcher` + `grep-regex` (literal by default, with `whole_word: bool` for `gr` references). Returns path, 1-based line, UTF-8 byte match span (converted to UTF-16 ranges in AppKit against the matching revision), bounded excerpt and `truncated` at 100 hits. Respects the existing 1,000,000-byte text ceiling.
3. **`lf task symbols <issue> <name> [--path <path>]` (`task.files.symbols`):** Keeps **one** Tree-sitter runtime in the codebase (choice 1a for review): Desktop's already-bundled 28-grammar `TreeSitterGrammars.xcframework` owns **open-file outline (`⇧⌘O`), sticky enclosing breadcrumb, and live same-file definitions** (0 RPC, works on dirty buffers, identical for local and remote files across all 28 languages). Cross-file definition lookup (`gd` / `⌘-click`) runs on the owning Machine via `task.files.symbols`: it checks each bounded file buffer with the same literal matcher as Grep, then scans only those few files with a pure-Rust comment/string-aware declaration matcher (Swift, Rust, TypeScript/TSX, JavaScript/JSX, Python, Go, Markdown headings, plus brace/indent enclosing-container tracking and generic fallback), capping at 100 hits with `truncated`. This avoids compiling 7–8 C/C++ Tree-sitter grammars into `lf` (preventing ~15–25 MB binary growth that slows ARM startup self-hashing and non-incremental worktree builds) while keeping a clean wire contract if AST parsing is ever added on the Machine later. In the UI, exact declarations in the live buffer win; only when it has none does Desktop query the checkout, dropping that path's disk hits while its draft is dirty. Unsaved drafts are never sent during repository search.

**Jump and reference behavior:** `⌘-click` or `gd` jumps immediately when one unambiguous declaration exists (a truncated set cannot establish uniqueness), opens an inline peek list with enclosing name, path and line when several exist, and leaves location intact on zero hits. `gr` calls `task.files.grep` with `whole_word: true` to list reference candidates inline. `⇧⌘O` opens the local Tree-sitter outline. Only accepted jumps push `(path, line)` onto jump history. Clicking an identifier in Read records a typed target (`FileJumps.Target(path, line, word, range)`) and marks that word visibly in `TaskCodeReader`; character chords (`gd`, `gr`) route through the single AppKit key router (`DesktopActionMonitor`) whenever Files is focused in `.read` mode with no picker/find open and `firstResponder` is not an editable `NSTextView` (so clicking a selectable `.textSelection(.enabled)` code line never swallows `g` `d` / `g` `r`, and `TaskCodeReader` needs no competing `@FocusState`/`.onKeyPress`). Start search/symbol reads lazily, debounce typing, cancel superseded scans, and accept replies only for the current owner, checkout, query and generation. No SQLite writes on typing or background whole-repo indexing. Empty query shows recent/open files in Files and an idle Grep; no hits, incomplete results and failed reads have distinct UI. [observe.rs](../rust/loopflow-execution/src/observe.rs)

**Focus and shortcut ownership:** Attach a **descendant-aware `PaneFocusTarget`** to `.files, .changes` in `WorkspacePanesView`—it claims `firstResponder` off `GhosttyTerminalNSView` only when the current `firstResponder` is outside the pane, so clicking directly into `NSTextView`, Find or a comment `TextField` never steals focus away. Register Files' pane shortcuts (`⌘F`, `⌘P`, `⇧⌘F`, `⇧⌘O`, `⌃⌘E`, and `files-back`/`files-forward` on `⌘[`/`⌘]`) in `DesktopAction` (choice 4a for review) instead of scattered SwiftUI hidden buttons or ad-hoc key monitors: `DesktopActionMonitor` already protects IME `hasMarkedText()`, populates Keyboard Shortcuts, and enables `lf desktop perform`. When Files is not focused (or its jump stack is empty for `⌘[`/`⌘]`), keys fall through cleanly to Terminal Find, Desktop window Back/Forward, and Open Repo. `⌘F` opens one inline find bar with count, Enter/Shift-Enter stepping, and one-click promotion to Grep (`⇧⌘F`) across Read lines, Edit (`NSTextView`), Markdown block cells, rendered HTML (`WebPage.callJavaScript` in an isolated content world, passing the needle as an argument without reloading) and visible Diff sides; images show no text matches. [WorkspacePanesView.swift](../swift/LoopflowMac/Views/WorkspacePanesView.swift) · [DesktopActions.swift](../swift/LoopflowMac/DesktopActions.swift) · [LoopflowApp.swift](../swift/LoopflowMac/LoopflowApp.swift)

## Build order

**First increment of step 1.** Opening code now uses the line-numbered reader and the existing whole-file grammar colors. Read, Edit and Diff are remembered per open path. Edit has a single-click control and a pane-scoped `⌃⌘E` action. Read, draft restoration and incoming writes can run before a native editor exists. The first Edit creates the editor, which stays with the document across file switches.

**Checkout picker increment.** `lf task find`, `task.files.find` and Files’ `⌘P` now reach unopened directories and ignored scratch pages. Arrowing through results uses the code reader beside the list at 620 points and wider. The search field owns navigation and Return opens the highlighted path. The tree only lists directories that have been opened.

**Checkout grep increment.** `lf task grep` and the Files picker’s **⇧⌘F** share the owning Machine’s checkout inventory. The picker previews the selected occurrence and Return opens its numbered source line, including in Markdown and HTML. Exact highlighting uses the revision and half-open UTF-8 byte offsets from the search. Grep reads one file at a time without populating the server’s observed byte cache.

**Jump to definition increment.** The numbered reader shares one Tree-sitter parse between colors, the enclosing symbol and the outline. `⇧⌘O` lists live declarations. Clicking an identifier followed by `gd`, or ⌘-clicking it, resolves the current document first. Cross-file lookups use `task.files.symbols` on the owning Machine. A complete single match opens immediately. A choice from the peek records the call line, and `⌘[` / `⌘]` prefer file history while it has a destination.

**Files chrome and calm updates increment.** Files and Brief read the working tree against the Task parent. Each step or branch review owns its comparison. The breadcrumb and responsive rail use that split for navigation, and the first Files visit picks from the independent scratch inventory. Local and peer watchers offer changed scratch pages and reconcile retained drafts. Presentations enter file history and offer an Open button during Edit or Diff. Same-page HTML updates settle for 800 ms. Files’ Diff steps within the selected file.

**Unified Find and line review increment.** The Files pane owns ⌘F across source, Edit, rendered Markdown and HTML, and visible per-file Diff rows or sides. ⇧⌘F carries the query to checkout Grep. Read and Diff share one comment editor and batch. Each reference keeps its original working-file, draft or comparison source. Read gutter marks follow the working patch, including deletions.

**Reference lookup and browser journey.** The focused reader accepts `gr` on the clicked identifier. The owning Machine returns whole-word occurrences with their byte ranges. Each stays in the inline list until picked, even a single hit on the current line. Picking a result records the source line and closes the list.

**Read chords after text selection.** Clicking a word underlines that occurrence. The Desktop key monitor sends `gd` and `gr` to its file and line while a selectable text view has focus. Find, the picker and editable text retain their keys. Both local and peer browser journeys now take this route for references and definitions.

**Scratch write membership.** The local journey timed out after 300 seconds waiting for `scratch/Files-Read.html`. The file existed. A served inventory can predate the write by three seconds, so checking that list discarded the only notification. Desktop now checks changed names in their parent directory on the owning Machine, including ignored entries. It drops vanished atomic-save siblings and keeps the checkout inventory for initial discovery.

**Desktop presentation.** `lf desktop files` reveals Files beside a zoomed terminal and keeps terminal focus. Pending presentations and unread scratch paths stay in the rail after dismissing the banner. Rewriting the mounted Read page reconciles it in place. Removed `lf open --file` and its separate Desktop dispatch.

**Rail, pane strip and Grep.** Each rail section identifies its rows independently. Selecting a pane tab or narrowing the pane scrolls the selected tab into view. Grep carries the excerpt’s first byte offset from the owning Machine. The picker marks the returned occurrence even when its context is cropped. The numbered reader uses that occurrence’s typeset position for horizontal scrolling at the matching revision.

Mounted focus, scroll and the 360/620-point layouts continue to gate and display QA after this pass.

**Reader width.** The code reader's scroll content is as wide as its widest line. Before this, a `LazyVStack` sized to the rows it had measured, and lines wider than line 1 were clipped and out of reach. Row margins sit inside each row, so jumping to a line's start keeps the margin. Locked-screen QA on November 23 also checked presentation beside a zoomed session, distinct rail and Grep rows, Edit offers that clear on leaving Edit, and the narrow pane strip (`scratch/qa.html`). Word and gutter taps still need a display.

**Demo fixes, November 24.** The live demo ([demo notes](demo-notes.md), [design](design.md#demo-feedback--fixes-2026-11-24)) found that ⌘-click and word underlines did nothing: selectable text took the click before the reader's tap gesture. The reader now watches its window's mouse events, counts a press released within 3 points as a click, maps it onto the row frames it records, and leaves drags to selection. Find scrolls to its match with the Grep anchor instead of the middle of the widest line. The rail uses the Diff sidebar's headings and padding, open and changed rows show name, directory and colored counts, and the tree steps 8 points per level. Find and the picker search are bordered fields under a divider; placeholders and the symbol peek read on dark themes.

**Large-file stall (design fix 6).** `LargeFileReaderTests` opens `swift/LoopflowMac/WorkModel.swift` (3,766 lines) in Read headlessly. It times main-thread work, layout included, for opening, ⌘F, a far Find step, a click and 60 scroll frames.
