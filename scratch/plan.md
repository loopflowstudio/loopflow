# LOO-1067 · Redesign the file browser

> Jack Heart, November 22: “lets do directions 1 and 2”
>
> “4a i think --read only by defautl / easy to turn on editable”

**Done when** you can find a file in an unopened folder, preview it, jump from a call to a declaration and back to the same line, and put a comment on those lines into the Task conversation. An agent can present a finished page beside that conversation. While you read, edit or review, ordinary writes leave your place and keyboard focus alone. Desktop reads files from the Machine that owns the checkout. Both directions land in one PR. The [Round 3 prototype](explore.html), [design](design.md) and [concept review](concept-review.html) record the layout and model.

## Experience and model

Keep `Brief`, `Diff` and `Files` in the pane strip. Cleanly separate **working-tree state** from **Diff comparison state**, and decompose `TaskFilesStore` so it acts as the thin Task-inspector coordinator (transport, file watcher, working-tree changes, scratch inventory, shared `comments`) delegating to focused collaborators (`FilesBrowserState`, `DiffReviewState`, `CheckoutTree`):

- **Working-tree state vs. Diff comparison:** Keep `workingChanges: TaskChangesSnapshot?` pinned to `workingTree(base: "parent")`, independent of `DiffReviewState.comparison` (whole Task vs. a Graph step vs. a branch tab). Selecting a step in `Diff` never overwrites Files' `Changed in Task` counts, `⌘P` Changed mode, Read change marks, per-file draft Diff, or Brief's delivery head. Scratch listing comes from the checkout inventory (`task.files.find`) rather than `git diff`, so `scratch/` stays visible even on a step Diff or when a comparison base is missing.
- **Header and rail:** Files has one 32-point header with a sidebar button, jump history (`‹`/`›`), an interactive path breadcrumb and document actions. A folder segment opens its siblings; the filename switches or closes open files; the enclosing symbol follows the reading position. Open files also appear at the top of the empty `⌘P` picker (choice for review over a second tab row). Keep the recorded Machine and full path accessible from the breadcrumb.
- **Responsive rail:** The 236-point rail docks at 620 points and opens as a dismissible drawer below that width, using Diff's layout and named design tokens. **Open & Scratch** shows open files, unsaved drafts and updated paths. **Changed in Task** shows counts from `workingChanges` (the whole Task). **Checkout** keeps keyboard navigation, paged directories, retries and scroll position, compacts single-child directories only once their listing is complete, reveals the selected path through its ancestors, and starts a fresh listing when toggling Show Ignored (Rust directory cursors encode `show_ignored`). At 360 points the header folds actions into its menu and a file pick dismisses the drawer. [CheckoutTree.swift](../swift/LoopflowMac/CheckoutTree.swift) · [TaskChangesView.swift](../swift/LoopflowMac/Views/TaskChangesView.swift)
- **Read default, per-file mode, lazy native editor:** Every newly opened file starts in **Read**. Code renders syntax-colored, selectable, line-numbered lines with whole-Task change marks in the gutter. Markdown and HTML render, and images open as pictures. **Read always renders `document.text`** (including unsaved draft text, with draft/save status visible) so returning to Read never hides local edits. View mode (`.read | .edit | .diff`) is **per-file** (choice 3a for review): toggling **Edit** (`⌃⌘E` or button) on one file survives jumping to another file in Read. Create `TaskFileDocument`'s `NSTextView`, `NSScrollView` and `UndoManager` **lazily on first entry into Edit** (setting `usesFindBar = false` so it never collides with Files' inline Find) and retain them across toggles so caret, undo, IME composition, 3-way merge and save recovery stay intact; while `editor == nil`, `reconcile` updates `text` directly. Changed or dirty files also offer their draft-aware **Diff**, where `[`/`]` step changes within that file only (no silent file switching). Top-level `Diff` keeps its whole-Task and step comparisons, review layouts, tour, viewed state and delivery card. Keep every current grammar, filename association and plain-text fallback. [Grammar.swift](../swift/LoopflowMac/Grammar.swift) · [LOO-1040, PR 2013](https://github.com/loopflowstudio/loopflow/pull/2013)
- **Open files vs. Jump history vs. Drafts:** Keep persisted `WorkFileTab` identity in `WorkBrowserTab.files`, but separate **Open files** from **Jump history** (`(path, line)` back/forward stack pushed only on accepted jumps or presentations). Bound clean auto-added open files (MRU cap, e.g. 12) so 2-second `gd` jumps do not flood Open & Scratch. Closing a clean file removes it from open files and drops its document; dirty drafts always remain visible in Open & Scratch until saved or discarded (never hidden as phantom autosaving buffers).
- **Unified line comments:** Click or Shift-click a line in Read or Diff to comment, copy or reference a range using the same `ReviewCommentEditor`, `ReviewCommentsStrip` and `TaskFilesStore.comments` queue. Give `ReviewSelection` a typed `Source`: `.file(draft: Bool)` (working document, anchored against `document.text` and re-anchored on edits/reconcile) vs. `.diff(side: Side, revision: String)` (comparison side, anchored against that file's diff lines). Each surface displays and re-anchors **only** its own source's comments (a Read comment never detaches on a Diff refresh or renders at the top of Diff). An ambiguous or vanished anchor keeps its original reference and notes that the lines changed. `⌘↩` formats each comment with its true source (`working file` / `unsaved draft` vs. diff side and revision) and inserts the batch into the conversation's **unsent input**. An unavailable conversation or failed insertion leaves the queue intact. [ReviewDiff.swift](../swift/LoopflowMac/ReviewDiff.swift) · [ReviewStreamView.swift](../swift/LoopflowMac/Views/ReviewStreamView.swift)

## How a file gets shown

Delete `TaskFilesStore.follow`, `autoSelected`, `quietInterval`, `lastInteraction` and passive document/tab creation. Three explicit paths replace them:

- **One-time initial pick:** On first entry to an empty Files pane (`!hasChosenInitialFile`, after restoring tabs and drafts), pick the newest eligible `scratch/` Markdown or HTML page (reported by modification time with a stable path tie-break from `task.files.find`), else the first changed file, else the empty picker. Mark `hasChosenInitialFile = true`. Closing the last tab, later writes, or viewing Brief/Diff never repeat this choice.
- **Passive writes and calm updates:** Both the local watcher (`TaskFilesStore.invalidate`) and the peer watcher (`watch_task_files::relevant_paths`) pass eligible `scratch/` page writes through even when `scratch/` is gitignored, refreshing the scratch list and update badges **without** triggering a `git diff` comparison reload when only gitignored scratch changed (keeping journal and build noise out). An observed write badges its path in Open & Scratch and shows a quiet update bar (`Updated scratch/explore.html · Open`), coalescing repeated writes to one path. Reconcile open documents normally, including hidden dirty drafts. Key `TaskHTMLView` by `.id(document.path)` so initial opens and file switches load immediately at scroll `(0, 0)`, while writes to the **same** visible HTML document wait 800 ms of quiet before reloading once and restoring scroll. On disconnect retain drafts and offer Refresh. Keep offline HTML rules, external link handling and remote base-URL behavior. [TaskFileDocument.swift](../swift/LoopflowMac/TaskFileDocument.swift) · [workspace.rs](../rust/loopflow-execution/src/ops/task/workspace.rs)
- **Deliberate presentation:** `lf open --host desktop --file <path>` explicitly presents the file in the Task Files pane (`Read` mode), reusing its entry if open, retaining all paths for repeated `--file` flags, pushing the prior file onto Files' jump stack when already on Files, preserving drafts and undo history, and never stealing terminal focus. If the person is actively typing or composing in Files' `Edit` editor, add the file to Open & Scratch and show a calm `Presented <path> · Open` bar instead of interrupting keystrokes (choice 5a for review). Follow `write-docs` in builtins that finish a review page (`explore`, `concept-review`, `demo`, `research`) to present once the artifact is ready. [open/files.rs](../rust/loopflow/src/lf/commands/open/files.rs) · [write-docs.md](../rust/loopflow-definitions/src/builtins/task/skill/write-docs.md)

## Search, symbols, focus and ownership

**One picker** has Files (`⌘P`), Grep (`⇧⌘F`) and Changed modes. Arrow keys preview without changing open files, jump history or selection. Return opens the selected line. Escape returns focus and place. Wide panes show a syntax-colored preview centered on the hit beside results; narrow panes show the list first. Fuzzy path ranking favors scratch, changed and open matches, then match quality and path. Changed reads `workingChanges` even after visiting a step Diff.

**Three peer Machine reads in `ops/task` → `Read` → `RegistryQuery`** (choice 2a for review — one verb, one JSON schema, matching `lf task file|files|changes|diff`). Keep CLI execution, SSH routing, served argv/results, generated server schema, Rust and Swift fixture decoding in agreement; required nullable keys stay present on the wire. The Mac never enumerates a peer's path. [read.rs](../rust/loopflow/src/lf/commands/read.rs) · [RegistryQuery.swift](../swift/Loopflow/Services/RegistryQuery.swift) · [served reads](../rust/loopflow/tests/served_reads.rs)

1. **`lf task find <issue> [query]` (`task.files.find`):** Enumerates tracked and nonignored untracked paths via the checkout's existing Git plus bounded `scratch/` entries (deduplicated, keeping tracked files matching ignore patterns and skipping deleted/escaping symlinks), along with `scratch` paths and `latest_scratch_page` (newest eligible `.md`/`.html` by mtime, path tie-break). Caches the checkout inventory in bounded Machine memory via `observe` (keyed by checkout + Git index/ignore/membership revisions). When `query` is omitted and the inventory fits within 2,000 paths, returns the complete list in one reply (`truncated: false`) so Desktop fuzzy-filters locally at 0 ms per keystroke. For larger checkouts (`truncated: true`), Desktop sends debounced `query` and the Machine fuzzy-matches over its **complete** cached inventory, returning the top ranked matches (`limit`, default 100) in one reply—no cursor paging loop.
2. **`lf task grep <issue> <query>` (`task.files.grep`):** Searches the same inventory using ripgrep's pure-Rust `grep-searcher` + `grep-regex` (literal by default, with `whole_word: bool` for `gr` references). Returns path, 1-based line, UTF-8 byte match span (converted to UTF-16 ranges in AppKit against the matching revision), bounded excerpt and `truncated` at 100 hits. Respects the existing 1,000,000-byte text ceiling.
3. **`lf task symbols <issue> <name> [--path <path>]` (`task.files.symbols`):** Keeps **one** Tree-sitter runtime in the codebase (choice 1a for review): Desktop's already-bundled 28-grammar `TreeSitterGrammars.xcframework` owns **open-file outline (`⇧⌘O`), sticky enclosing breadcrumb, and live same-file definitions** (0 RPC, works on dirty buffers, identical for local and remote files across all 28 languages). Cross-file definition lookup (`gd` / `⌘-click`) runs on the owning Machine via `task.files.symbols`: it pre-filters candidate files containing the identifier using `grep-searcher`, then scans only those few files with a pure-Rust comment/string-aware declaration matcher (Swift, Rust, TypeScript/TSX, JavaScript/JSX, Python, Go, Markdown headings, plus brace/indent enclosing-container tracking and generic fallback), capping at 100 hits with `truncated`. This avoids compiling 7–8 C/C++ Tree-sitter grammars into `lf` (preventing ~15–25 MB binary growth that slows ARM startup self-hashing and non-incremental worktree builds) while keeping a clean wire contract if AST parsing is ever added on the Machine later. In the UI, live AST results from the open buffer replace that path's disk results; unsaved drafts are never sent during repository search.

**Jump and reference behavior:** `⌘-click` or `gd` jumps immediately when one unambiguous declaration exists (a truncated set cannot establish uniqueness), opens an inline peek list with enclosing name, path and line when several exist, and leaves location intact on zero hits. `gr` calls `task.files.grep` with `whole_word: true` to list reference candidates inline. `⇧⌘O` opens the local Tree-sitter outline. Only accepted jumps push `(path, line)` onto jump history. Character chords (`gd`, `gr`) belong to the focused code reader. Start search/symbol reads lazily, debounce typing, cancel superseded scans, and accept replies only for the current owner, checkout, query and generation. No SQLite writes on typing or background whole-repo indexing. Empty query shows recent/open files in Files and an idle Grep; no hits, incomplete results and failed reads have distinct UI. [observe.rs](../rust/loopflow-execution/src/observe.rs)

**Focus and shortcut ownership:** Attach a **descendant-aware `PaneFocusTarget`** to `.files, .changes` in `WorkspacePanesView`—it claims `firstResponder` off `GhosttyTerminalNSView` only when the current `firstResponder` is outside the pane, so clicking directly into `NSTextView`, Find or a comment `TextField` never steals focus away. Register Files' pane shortcuts (`⌘F`, `⌘P`, `⇧⌘F`, `⇧⌘O`, `⌃⌘E`, and `files-back`/`files-forward` on `⌘[`/`⌘]`) in `DesktopAction` (choice 4a for review) instead of scattered SwiftUI hidden buttons or ad-hoc key monitors: `DesktopActionMonitor` already protects IME `hasMarkedText()`, populates Keyboard Shortcuts, and enables `lf desktop perform`. When Files is not focused (or its jump stack is empty for `⌘[`/`⌘]`), keys fall through cleanly to Terminal Find, Desktop window Back/Forward, and Open Repo. `⌘F` opens one inline find bar with count, Enter/Shift-Enter stepping, and one-click promotion to Grep (`⇧⌘F`) across Read lines, Edit (`NSTextView`), Markdown block cells, rendered HTML (`WebPage.callJavaScript` in an isolated content world, passing the needle as an argument without reloading) and visible Diff sides; images show no text matches. [WorkspacePanesView.swift](../swift/LoopflowMac/Views/WorkspacePanesView.swift) · [DesktopActions.swift](../swift/LoopflowMac/DesktopActions.swift) · [LoopflowApp.swift](../swift/LoopflowMac/LoopflowApp.swift)

## Build order

1. **Remote find, Read viewer & jump-to-definition (vertical slice):** Implement `task.files.find`, `task.files.grep` (with `whole_word`) and `task.files.symbols` (pure-Rust `grep-searcher` + comment/string-aware declaration scanner) through `ops/task` → `Read` → `RegistryQuery` + CLI + DTO fixtures. Build the Files picker (`⌘P`), Read-only syntax-colored line-numbered code viewer (with lazy `NSTextView` on `Edit` / `⌃⌘E`), local Tree-sitter outline/enclosing/same-file defs, cross-file `⌘-click`/`gd` peek, and jump stack (`⌘[`/`⌘]` via `DesktopAction`). Prove the whole remote + local architecture end to end: `⌘P` previews an unopened Rust file on a remote checkout, Return opens it in Read at a line, `⌘-click` on a method with two definitions peeks both, pick #2 and go back. Replace the old expanded-folder `⌘P` search here.
2. **State split, chrome & calm updates:** Split `TaskFilesStore` into coordinator + `FilesBrowserState` + `DiffReviewState` with separated `workingChanges` and `scratch` inventory. Land the 32-point breadcrumb header, responsive 236-point rail (Open & Scratch, Changed in Task, Checkout with compaction, auto-reveal and Show Ignored reset), per-file view mode, one-time initial choice, scratch-passing local & peer watchers, calm update bar, `.id(document.path)` 800 ms HTML settle debounce, and deliberate `lf open --host desktop --file` (plus builtin skill updates). Delete the 3-state navigator, pin shortcut, static location row, tab counter, `follow()`/`autoSelected`/120s timer and passive document creation. Move open-file readiness timing to the displayed reader and update superseded tests.
3. **Unified Find & line review:** Wire descendant-aware `PaneFocusTarget` and inline `⌘F` across Read, Edit, Markdown, HTML (`callJavaScript`) and Diff, with promotion to Grep (`⇧⌘F`) and full Changed/preview picker modes. Add typed `ReviewSelection.Source` (`.file` vs. `.diff`), Read gutter change marks, shared `ReviewCommentEditor` / `ReviewCommentsStrip` across Read and Diff, and per-file-only stepping in Files' Diff mode. Reconcile focus, edit/save and review tests and `swift/README.md`.
4. **Polish & full language/CLI coverage:** Verify all core languages + fallback in declaration scanner and local Tree-sitter outline, `gr` references, dirty-buffer live overlays, cache invalidation, truncated states, narrow/wide responsive layouts, and CLI/server reference docs. No change to iOS navigation or existing Diff comparison controls.

## Gate and demo

Planned headless gate from the repository root, with the source-built CLI and the new Swift integration scenario:

```sh
cargo build -p loopflow --bin lf
swift test --package-path swift --filter TaskFileBrowserJourneyTests
```

One isolated Task on a fixture Machine contains an unopened source file, two same-name definitions, Unicode before a hit, an ignored `scratch/` page and an excluded build artifact. Run the journey through the CLI (`lf task find`, `lf task grep`, `lf task symbols`) and through Desktop's served reads using `BuiltLf`. Repeat the Swift journey with a peer checkout absent on the presentation Mac. Expect matching path/line results, a preview that leaves open files alone, two definitions with enclosing names, a working return jump (falling through to Desktop Back once empty), whole-Task Changed intact after visiting a Diff step, scratch visible even when comparison fails, and a single batch of Read (`.file`) and Diff (`.diff`) comments in unsent conversation input. A scratch burst while reading, editing or on Brief/Diff leaves page, caret and focus in place while still updating the scratch rail and update bar. Explicit `lf open --host desktop --file` opens its page without stealing terminal focus (and preserves active Edit typing). Returning to Edit restores the lazy-retained draft and undo. Exercise real `DesktopAction` find/focus routing on reader and terminal, narrow/wide layout, and an out-of-order reply. Use deterministic event delivery for settling and a mounted native key-event check in display-capable QA.

## Demo

With a Task conversation beside Files, press `⌘P`, type part of a nested filename and preview it. Open it (Read), find a call with `⌘F`, jump to its definition (`⌘-click`), comment on two lines, then return (`⌘[`). Rewrite a scratch page twice: the call stays in view and a calm update bar appears. Present the finished page with `lf open --host desktop --file scratch/explore.html`: it opens rendered immediately and the queued comment is still ready to send with `⌘↩`.
