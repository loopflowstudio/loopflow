# LOO-1067 · Redesign the file browser

> Jack Heart, November 22: “lets do directions 1 and 2”
>
> “4a i think --read only by defautl / easy to turn on editable”

**Done when** you can find a file in an unopened folder, preview it, jump from a call to a declaration and back to the same line, and put a comment on those lines into the Task conversation. An agent can present a finished page beside that conversation. While you read, edit or review, ordinary writes leave your place and keyboard focus alone. Desktop reads files from the Machine that owns the checkout. Both directions land in one PR. The [Round 3 prototype](explore.html), [design](design.md) and [concept review](concept-review.html) record the layout and model.

## Experience and model

Keep `Brief`, `Diff` and `Files` in the pane strip. Cleanly separate **working-tree state** from **Diff comparison state**, and decompose `TaskFilesStore` so it acts as the thin Task-inspector coordinator (transport, file watcher, working-tree changes, scratch inventory, shared `comments`) delegating to focused collaborators (`FilesBrowserState`, `DiffReviewState`, `CheckoutTree`):

- **Working-tree state vs. Diff comparison:** Keep `workingChanges: TaskChangesSnapshot?` pinned to `workingTree(base: "parent")`, independent of `DiffReviewState.comparison` (whole Task vs. a Graph step vs. a branch tab). Selecting a step in `Diff` never overwrites Files' `Changed in Task` counts, `⌘P` Changed mode, Read change marks, per-file draft Diff, or Brief's delivery head. Scratch listing comes from the checkout inventory (`task.files.find`) and watch state rather than `git diff`, so `scratch/` stays visible even on a step Diff or when a comparison base is missing.
- **Header and rail:** Files has one 32-point header with a sidebar button, jump history (`‹`/`›`), an interactive path breadcrumb (`… / <folder> / <file>` before collapsing to bare filename) and document actions. A folder segment opens its siblings; the filename switches or closes open files; the enclosing symbol (`ReadingSymbol`) follows the reading position. Open files also appear at the top of the empty `⌘P` picker (choice for review over a second tab row). Keep the recorded Machine and full path accessible from the breadcrumb.
- **Responsive rail:** The 236-point rail docks at 620 points and opens as a dismissible drawer below that width, using Diff's layout and named design tokens. **Open & Scratch** shows open files, unsaved drafts and updated paths with filename over muted directory. **Changed in Task** shows counts from `workingChanges` (the whole Task). Give each rail section distinct row IDs (`open:<path>`, `changed:<path>`, `entry:<path>`) inside the `LazyVStack` so an open changed file never collides with and vanishes from Changed in Task. **Checkout** keeps keyboard navigation, paged directories, retries and scroll position, steps 8 points per level, compacts single-child directories only once their listing is complete, reveals the selected path through its ancestors, and starts a fresh listing when toggling Show Ignored (Rust directory cursors encode `show_ignored`). At 360 points the header folds actions into its menu and a file pick dismisses the drawer; the pane strip scrolls its selected tab into view so narrow panes never clip `Files`. [CheckoutTree.swift](../swift/LoopflowMac/CheckoutTree.swift) · [TaskChangesView.swift](../swift/LoopflowMac/Views/TaskChangesView.swift) · [WorkspacePanesView.swift](../swift/LoopflowMac/Views/WorkspacePanesView.swift)
- **Read default, native TextKit 2 code reader, per-file Edit/Diff:** Every newly opened file starts in **Read**. Markdown and HTML render, images open as pictures, and code opens in **one read-only TextKit 2 `NSTextView` (`CodeReaderTextView`) paired with a pinned line-number & change-mark gutter (`CodeReaderGutterView`)** inside `TaskCodeReader` (choice 1a for review):
  - **Immediate plain-text display + async syntax & outline:** Mount the file's text immediately in monospace (< 20 ms even on 3,766-line `WorkModel.swift`), then run the single Tree-sitter parse off-main to paint syntax attributes and publish `FileOutline` — eliminating the 3–6 s blank spinner and the 3,766-line `CTLine` width pre-scan.
  - **Native multi-line selection & direct click/⌘-click:** `isEditable = false, isSelectable = true`, non-wrapping with horizontal scroll while the gutter stays pinned on the left. Override `mouseDown(with:)` directly on `CodeReaderTextView`: a single `⌘-click` resolves the identifier via TextKit character hit-testing and invokes definition lookup immediately without calling `super.mouseDown` (never entering AppKit's modal `⌘-click` multi-selection loop, deleting `ReaderClicks`, `RowFrames`, `NumberedLine`, `CTLine` hit-testing, and the untestable `RunLoop.default` + `NSApp.currentEvent` workaround). A plain click runs `super.mouseDown` so native single-line and **multi-line drag-selection** + `⌘C` work untouched; if `selectedRange().length == 0` when `super.mouseDown` returns, underline the clicked identifier as `FileJumps.target` for `gd`/`gr` and clear any stale visit highlight.
  - **Temporary rendering attributes & inline review/peek slots:** Highlight `target` underline, Find current match, Grep byte hit, comment-selected lines, and `FileVisit` destination lines via TextKit temporary/rendering attributes (sub-millisecond repaints, zero `NSTextStorage` mutations). Anchor `ReviewCommentEditor`, `ReviewCommentRow`, and `FileSymbolPeek` directly beneath their line by setting `paragraphSpacing` on that line's paragraph and positioning a viewport-wide `NSHostingView` inside the opened gap so lines below shift down cleanly and inline cards stay readable while code scrolls horizontally; render detached comments in SwiftUI above the reader. Reuse the same read-only TextKit 2 reader (non-interactive) in `TaskFilePicker`'s preview so previewing large files is instant.
  - **Per-file Edit & Diff:** **Read always renders `document.text`** (including unsaved draft text, with draft/save status visible). View mode (`.read | .edit | .diff`) is **per-file**: toggling **Edit** (`⌃⌘E` or button) on one file survives jumping to another file in Read. Keep `TaskFileDocument`'s `NSTextView`, `NSScrollView` and `UndoManager` separate from the Read view, created **lazily on first entry into Edit** (`usesFindBar = false`) and retained across toggles so caret, undo, IME composition, 3-way merge and save recovery stay untouched. Changed or dirty files also offer their draft-aware **Diff**, where `[`/`]` step changes within that file only. Top-level `Diff` keeps its whole-Task and step comparisons, review layouts, tour, viewed state and delivery card. Keep every current grammar, filename association and plain-text fallback. [TaskCodeReader.swift](../swift/LoopflowMac/Views/TaskCodeReader.swift) · [TaskFileDocument.swift](../swift/LoopflowMac/TaskFileDocument.swift) · [Grammar.swift](../swift/LoopflowMac/Grammar.swift)
- **Open files vs. Jump history vs. Drafts, and explicit `FileVisit` / `FilePosition`:** Keep persisted `WorkFileTab` identity in `WorkBrowserTab.files`, separate **Open files** (MRU-capped at 12 clean auto-opened files) from **Jump history** (`FilePosition` back/forward stack pushed only on accepted jumps or presentations), and keep dirty drafts visible in Open & Scratch until saved or discarded. Separate **landing highlight** from **source-vs-rendered mode** (choice 3a for review):
  - `FilePosition(path: String, line: Int?)`: `line == nil` records a rendered Markdown/HTML view; `line: Int` records a source line. Pressing `⌘[` Back to a rendered page keeps it rendered instead of forcing raw source.
  - `FileVisit`: carry explicit `showsSource: Bool` and explicit `highlight: Highlight` (`.lines(ClosedRange<Int>)` or `.hit(TaskGrepHit)`). Definition jumps (`gd`/`⌘-click`), outline picks (`⇧⌘O`), and Back/Forward to a source line set `.lines(line...line)` so the destination line is visibly marked (even near EOF where scrolling cannot center it). Presentations with `PATH:LINE[-END]` set `.lines(start...end)` and `showsSource: true`; Grep and `gr` references set `.hit(hit)` and `showsSource: true`. Clicking a different line in Read clears the stale visit highlight. [FileJumps.swift](../swift/LoopflowMac/FileJumps.swift)
- **Unified line comments:** Click or Shift-click a line in Read's pinned gutter or Diff to comment, copy or reference a range using the same `ReviewCommentEditor`, `ReviewCommentsStrip` and `TaskFilesStore.comments` queue. `ReviewSelection.Source` separates `.file(draft: Bool)` (anchored against `document.text` and re-anchored on edits/reconcile) from `.diff(side: Side, revision: String)` (anchored against that file's diff lines). Each surface displays and re-anchors only its own source's comments. `⌘↩` formats each comment with its true source and inserts the batch into the conversation's **unsent input**. An unavailable conversation or failed insertion leaves the queue intact. [ReviewDiff.swift](../swift/LoopflowMac/ReviewDiff.swift) · [ReviewStreamView.swift](../swift/LoopflowMac/Views/ReviewStreamView.swift)

## How a file gets shown

`follow()`, `autoSelected`, the 120 s timer and passive document creation are gone. Three explicit paths show a file:

- **One-time initial pick:** On first entry to an empty Files pane (`!hasChosenInitialFile`, after restoring tabs and drafts), pick the newest eligible `scratch/` Markdown or HTML page (reported by modification time with a stable path tie-break from `task.files.find`), else the first changed file, else the empty picker. Mark `hasChosenInitialFile = true`. Closing the last tab, later writes, or viewing Brief/Diff never repeat this choice.
- **Passive writes and calm updates (unified local & peer model):** Both local checkouts (`TaskFileObservation`) and remote/peer checkouts (`TaskFilesWatch` → `task.files.watch`) separate **working-tree / Git changes** from **ignored `scratch/` page writes** so an ignored scratch write never triggers a `git diff` comparison reload and always badges Open & Scratch and raises the calm update notice (choice 2a for review):
  - **Peer watch (`TaskFilesRevision`):** Keep `revision: Option<String>` strictly for working-tree and `.git` changes (`!ignored` or `.git/` or rescan). Add `scratch_pages: Vec<TaskScratchPage>` (`{ path: String, stamp: String }` where `stamp` is derived from file mtime + byte length for existing eligible `.md`/`.html` files under `scratch/`). When only ignored scratch pages change on a peer Machine, `TaskFilesWatch` updates `scratch_pages` without bumping `revision`. Desktop diffs incoming `scratchPages` against `seenScratchStamps` (seeded on the first live reading, retained across reconnects): changed pages update `scratchPaths`, re-read only matching open documents (so visible HTML settles 800 ms and reloads in place), and call `browser.noteWrites` — surfacing the rail dot and dismissible `Updated <path> · Open ×` banner even across reconnects while automatically dropping vanished atomic-save temp siblings and skipping `git diff` over SSH. Update `TaskFilesRevision` in Rust, `swift/Loopflow/Models/TaskWorkspace.swift`, `tests/fixtures/dto/server_schema.json`, and `tests/fixtures/dto/task_files.json` (or `TaskFilesRevision` fixture), and verify peer scratch writes through the real `task.files.watch` stream (not a direct `files.invalidate([path])` shortcut).
  - **Local watch (`TaskFileObservation`):** Keeps FSEvents + vnode paths, filters via `git check-ignore`, and reconciles scratch page writes against the directory listing before calling `browser.noteWrites`, skipping `workingTree.refresh()` when only ignored scratch changed.
  - **Notice lifecycle:** Separate persistent rail badges (`updated`, `presentations` in Open & Scratch) from the ephemeral dismissible (`×`) layout banner (`FilesBrowserState.Notice`: `.presented(Presentation)` or `.updated(String)`). Suppress update banners for `visibleReadPath` (reloading calmly in place); clear stale presentation banners on open, dismiss, file switch, or leaving Edit. Render the banner inside the layout stack — shown on `Files`, and on `Diff` only for `.presented` offers. Key `TaskHTMLView` by `.id(document.path)` so initial opens load immediately at `(0, 0)` while writes to the same visible HTML page settle for 800 ms before reloading once and restoring scroll. On disconnect retain drafts and offer Refresh. Keep offline HTML rules, external link handling and remote base-URL behavior. [workspace.rs](../rust/loopflow-execution/src/ops/task/workspace.rs) · [TaskFilesStore.swift](../swift/LoopflowMac/TaskFilesStore.swift) · [TaskHTMLView.swift](../swift/LoopflowMac/Views/TaskHTMLView.swift)
- **Deliberate presentation:** `lf desktop files [PATH[:LINE[-END]]] [--mode read|diff]` is the single presentation command (`lf open --file` is deleted; `lf open` stays strictly for cross-host conversation opening). Without a path, `lf desktop files` shows Files. A path opens in Read by default (rendered for `.md`/`.html` when no line range is given, numbered source when `LINE[-END]` is given), reuses its tab, marks the requested lines and records the prior reading position. `MultiplexerStore.showBrowser(..., focus: false)` unzooms another zoomed pane while keeping `focusedPaneId` on the terminal so the presented page appears beside the conversation without stealing focus, drafts or Undo. `holdsPresentation` checks `isVisible(pane)`; during active visible Edit or Diff review, presenting adds the path to Open & Scratch and shows a dismissible `Presented <path> · Open · ×` banner. Treat exit 4 (Desktop unattached) quietly. [desktop.rs](../rust/loopflow/src/lf/commands/desktop.rs) · [MultiplexerStore.swift](../swift/LoopflowMac/MultiplexerStore.swift)

## Search, symbols, focus and ownership

**One picker** has Files (`⌘P`), Grep (`⇧⌘F`) and Changed modes inside a bordered `SearchBox` under a divider. Arrow keys preview using the fast TextKit 2 reader without changing open files, jump history or selection. Return opens the selected line. Escape returns focus and place. Wide panes show a syntax-colored preview centered on the hit beside results; narrow panes show the list first. Grep rows highlight the matched text inside each excerpt so multiple hits on one line read distinctly, and long single-line previews reveal the hit horizontally. Fuzzy path ranking favors scratch, changed and open matches, then match quality and path. Changed reads `workingChanges` even after visiting a step Diff.

**Three peer Machine reads in `ops/task` → `Read` → `RegistryQuery`** (one verb, one JSON schema, matching `lf task file|files|changes|diff`). Keep CLI execution, SSH routing, served argv/results, generated server schema, Rust and Swift fixture decoding in agreement; required nullable keys stay present on the wire. The Mac never enumerates a peer's path.

1. **`lf task find <issue> [query]` (`task.files.find`):** Enumerates tracked and nonignored untracked paths via Git plus bounded `scratch/` entries, along with `scratch` paths and `latest_scratch_page`. Caches checkout inventory via `observe` (rechecked after 3 s; bounded at 100,000 idle entries). Returns up to 2,000 paths (`truncated: false`) for local 0 ms filtering on small checkouts, or top 100 ranked matches on large checkouts.
2. **`lf task grep <issue> <query>` (`task.files.grep`):** Pure-Rust `grep-searcher` + `grep-regex` (`whole_word: bool` for `gr` references), returning path, 1-based line, UTF-8 byte offsets, `excerpt_start`, bounded excerpt, revision, and `truncated` at 100 hits. Respects the 1,000,000-byte text ceiling.
3. **`lf task symbols <issue> <name> [--path <path>]` (`task.files.symbols`):** One Tree-sitter runtime in Desktop (`TreeSitterGrammars.xcframework`) for open-file outline (`⇧⌘O`), sticky enclosing breadcrumb, and live same-file definitions; pure-Rust comment/string-aware declaration matcher on the Machine for cross-file definitions (`gd` / `⌘-click`). Live buffer declarations win; dirty drafts drop their stale disk hits and are never sent during repository search.
4. **Oversize & loading state (`lf task file` + `TaskFilesView`):** In `snapshot::file_snapshot`, check file size and sniff only a small prefix (e.g. 8 KiB) for NUL bytes before reading 1 MB into `observe::Cache`, so >1 MB non-binary files return `Truncated` immediately without buffering 1 MB of discarded bytes. In `TaskFilesView`, render a labeled loading state (`ProgressView("Loading…")`) instead of a bare spinner so unfocused or dark windows never look blank while a file loads. [snapshot.rs](../rust/loopflow-execution/src/ops/task/snapshot.rs) · [TaskFilesView.swift](../swift/LoopflowMac/Views/TaskFilesView.swift)

**Jump and reference behavior:** `⌘-click` or `gd` jumps immediately when one unambiguous declaration exists (a truncated set cannot establish uniqueness), opens an inline `FileSymbolPeek` beneath the line when several exist, and leaves location intact on zero hits. `gr` calls `task.files.grep` with `whole_word: true`. `⇧⌘O` opens the local Tree-sitter outline. Only accepted jumps push `FilePosition` onto jump history. Character chords (`gd`, `gr`) route through the single AppKit key router (`DesktopActionMonitor`) whenever Files is focused in `.read` mode with no picker/find open and `firstResponder` is not an editable `NSTextView`.

**Focus and shortcut ownership:** Attach a descendant-aware `PaneFocusTarget` to `.files, .changes` in `WorkspacePanesView`. Register Files' pane shortcuts (`⌘F`, `⌘P`, `⇧⌘F`, `⇧⌘O`, `⌃⌘E`, and `files-back`/`files-forward` on `⌘[`/`⌘]`) in `DesktopAction`. `⌘F` opens one bordered inline find bar (keeping its query across file switches until closed, choice 4a for review) across Read, Edit (`NSTextView`), Markdown blocks, rendered HTML (`WebPage.callJavaScript`), and visible per-file Diff sides.

## Demo

With a Task conversation beside Files, press `⌘P`, type part of a nested filename and preview it. Open it (Read), drag-select across lines, find a call with `⌘F`, jump to its definition (`⌘-click` — destination line highlighted), comment on two lines in the inline slot, then return (`⌘[`). Rewrite a scratch page twice (locally or on a peer Machine): the call stays in view and a calm update bar appears without triggering a diff reload. Present the finished page with `lf desktop files scratch/explore.html`: it opens rendered immediately and the queued comment is still ready to send with `⌘↩`.
