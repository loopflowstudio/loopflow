# LOO-1081 · Run and open a Task on Modal

**Done when** a Task Session can send a Linear-backed Task to a fresh Modal Machine, advance its Graph, and open its work from the laptop or paired phone. Files show the remote working copy, Changes shows its uncommitted diff, a shell starts in that checkout, and the conversation resumes the same remote Session. An idle sandbox pays the small resource floor. The quote still covers peak compute. Giving the Machine back needs neither a manual Git commit nor a database edit.

The field case was `manabot`, Wave `coverage`, Project `rules`, Tasks MTG-418 through MTG-422. For MTG-421 the Desktop Session pane reported “The conversation belongs to a different Machine or checkout; nothing was opened.” Its shell opened on the Mac. Use disposable counterparts for the demo.

## 4. Open the same checkout on CLI, Desktop and Mobile

Ownership selects the execution Machine. Its fresh `TaskLocationObservation` supplies the Task and checkout. Its Session record supplies the conversation. Neither a local checkout nor the most recently seen Session can change the route. This extends the existing Machine protocol used by `ops/task_location.rs`, `commands/open.rs`, `RegistryQuery.onMachine` and the Desktop held shell from PR #1811.

- `lf open --task <id> --tab` creates or focuses a terminal on the presentation Machine and attaches on the owner. Resolve an exact Session there via `--task <id> --session <id>` or `lf --machine <label> open --session <id> --tab` for a remote-only ID. Keep the selected Machine and repository in resume arguments, exact-ID lookup, attachment receipt and retry. This is a view of existing execution. An unavailable owner yields a retryable failure.
- Desktop already has routed file reads, a location-pinned subscription and a Machine-addressed shell. In `Views/SessionsView.swift`, resolve the owner before selecting a retained pane or Session, including cold open, restoration and tab creation. Use that observation for the file tree/content/watch, Workspace changes/diff, held shell cwd and Session prepare/attach. Keep the placement check that exposed the wrong record. Invalidate stale reads and attachments on moves, retaining unsaved drafts at their original checkout.
- Mobile’s `TaskWorkspaceView.swift` and `RemoteMobileClient.swift` currently read changes and request Session tickets from the paired Machine. Expose Files (tree and content, including unchanged files) and Shell alongside Changes and Session. The paired server resolves and forwards Task-scoped operations over its registered Machine connection. The owner serves the existing file/diff operations and holds both terminals. Bridge stream and bulk responses through the paired endpoint, which issues its own single-use, device-bound tickets. The phone needs one pairing. Reuse `session.start`, attachment, resize/input and reconnect semantics from `server/README.md`; maintain protocol fixtures and shared Swift decoding for changed operations. A Task without a checkout can show “not started”; an unreachable owner cannot appear as an empty diff or a usable local shell.

## Gate and demo

One two-Machine scenario runs through the public entry points. The fixture has a disposable Linear-backed repo, an active `rules` Project and a historical Project, a stale local checkout with different file bytes, and a fresh Linux owner without systemd or cron. The proposed named checks are:

```sh
uv run pytest python/tests/test_rental_bridge.py -k modal
cargo test -p loopflow --test integration machine_commands::modal_task_workspace
scripts/test_desktop.sh --filter RemoteTaskWorkspaceTests
uv run python scripts/test_ios.py -only-testing:LoopflowiOSTests/RemoteTaskWorkspaceTests
```

The bridge test inspects the SDK create arguments for burst and reserved. The CLI scenario quotes, rents, advances a real fixture Graph, observes one remote claim despite delayed marker delivery, rotates a fixture login, and opens the same Session twice. Both app tests exercise all four viewers against distinguishable Machine responses. Assert the remote-only **unchanged** file contents, an **uncommitted** diff hunk, shell output from `hostname` and `pwd`, and an input acknowledgement from the exact remote Session. Disconnect, reopen and move the Task while a pane is retained; each action either reaches its current owner or reports why. Run the old-store promotion and concurrent server-connect cases on Linux. Finish with ordinary `lf machine end <label>`, remote records returned and main still at the starting commit.

For the installed demo, run `lf task run <demo-task> --rent modal --quote`, then repeat without `--quote`. Open it with `lf open --task <demo-task> --tab`, Desktop and the paired phone.
