# LOO-1069 · Modifier keys in Desktop Sessions

> “Scope is Loopflow Desktop: modifier keys are not working in desktop sessions.” — Jack Heart

Done when a focused Desktop Session delivers terminal-owned chords to the running program with their modifiers intact, including after reopening the Session. Desktop shortcuts still act on the focused pane. Option text, dead keys, and IME composition still type correctly, and the same keyboard behavior applies in a Desktop Shell.

## Findings and design

The physical event starts in `GhosttyMetalView`. `WorkspacePanesView.swift` mounts it for both Session and Shell panes. A Session's Ghostty surface types through a local PTY into the held-terminal relay. `transport.rs` forwards input bytes and `transport/hosted.rs` filters terminal reports from viewers that lack the sizing lease. `rust/loopflow-terminal/src/repaint.rs` restores the program's keyboard modes on attach. The program owns those modes, Ghostty owns key encoding and keyboard configuration, and AppKit owns layout and composition.

- **Confirmed Desktop input defect.** With a US layout, a synthetic Option-B in an offscreen `NSTextInputClient` invoked `insertText("∫")`, while Option-Left and Shift-Return invoked editing selectors. `GhosttyTerminalView.swift` always sends Option through `interpretKeyEvents`, and its `insertText` writes via Ghostty's paste API. The keystroke loses its modifier before Ghostty can apply `macos-option-as-alt`. In a second probe under `scripts/desktop-headless.sb`, the pinned lf8 Ghostty surface removed Option from the text translation flags with `macos-option-as-alt = true` and retained it with `false`. The existing text route emitted `e2 88 ab` in both configurations. An Option-B key with translated text `b` emitted `1b 62` with the setting enabled. With Kitty disambiguation enabled, Ghostty emitted `1b 5b 31 33 3b 32 75` for Shift-Return, `1b 5b 31 33 3b 35 75` for Control-Return, and `0d` for plain Return. These are fixture observations. The original report gives no chord, provider, or keyboard layout. [Pinned Ghostty surface API](https://github.com/ghostty-org/ghostty/blob/a60e9e2a57f73e1eef2bd1cf2995a467f69e7fb0/src/apprt/embedded.zig#L2015-L2076)
- **One AppKit-to-Ghostty key path.** Carry the physical key, press/repeat/release, held modifiers including left/right information, and the unshifted codepoint from `characters(byApplyingModifiers: [])`. Use the surface's `ghostty_surface_key_translation_mods` for text translation and record the modifiers that produced that text. Reuse the original `NSEvent` when translation leaves it unchanged, which upstream requires for input methods such as Korean. Collect text AppKit returns during key interpretation and give it to Ghostty with the key. Keep marked text in preedit. Send text committed outside a keystroke or when finishing preedit as committed text without the triggering chord's modifiers. An IME cancellation sends no terminal edit. Preserve the direct path for ordinary printable input. [Ghostty AppKit responder](https://github.com/ghostty-org/ghostty/blob/a60e9e2a57f73e1eef2bd1cf2995a467f69e7fb0/macos/Sources/Ghostty/Surface%20View/SurfaceView_AppKit.swift#L1102-L1279) [Ghostty event fields](https://github.com/ghostty-org/ghostty/blob/a60e9e2a57f73e1eef2bd1cf2995a467f69e7fb0/macos/Sources/Ghostty/NSEvent%2BExtension.swift)
- **Keep shortcut ownership at the responder.** `DesktopActions.swift` owns its window and pane bindings, including Ctrl-Tab and Ctrl-Shift-Tab when available. Keep exact Copy, Paste, Find and macOS window cycling in `performKeyEquivalent`. Use Ghostty's binding query there to route applicable terminal bindings through the same key path as `keyDown`. Route Control-Return through that path before AppKit can treat it as a context-menu shortcut, as in Ghostty's responder. Other unbound equivalents can continue to AppKit. Cover a binding that also forwards the key and make sure it runs once. Gate on the first responder and connection as today. A view awaiting the relay or disconnected sends no input, a missing surface falls through to AppKit, and the exited child still accepts its local dismiss key. No new waits or buffer cross a keystroke. [Ghostty key equivalents](https://github.com/ghostty-org/ghostty/blob/a60e9e2a57f73e1eef2bd1cf2995a467f69e7fb0/macos/Sources/Ghostty/Surface%20View/SurfaceView_AppKit.swift#L1305-L1426)

The event adapter dates to the original Ghostty embedding (`87a8b812eb`, `cb772134c1`). #1269 retained terminal surfaces, #1559 tightened host shortcut routing, and LOO-907/#1948 restored focus across refresh. The mounted tests cover plain typing after Kitty mode restore and paste to the focused pane. This replaces the older keyboard translation and dispatch logic beneath those fixes. `_didInsertText`, `_currentKeyEventModifiers`, the control-text callback heuristic, and the separate `performKeyEquivalent` call to `ghostty_surface_key` go away with the old path. Clipboard paste, `lf desktop send`/`key`, selection, focus, and connection behavior keep their current interfaces.

The selected mechanism is the pinned Ghostty AppKit event contract. A forced Option-as-Alt default would change international typing and explicit user settings. Provider-specific escape strings would duplicate Ghostty's mode handling and only cover known chords. The favorable result is a chord that behaves the same before and after reattaching, with accented typing still working between commands. The regression to guard against is an input method that works for ASCII but leaks its commit key, duplicates the text, or submits a prompt. iPhone, Rex, CLI flags, wire formats, and provider shortcuts are outside this change.

## Build and check

1. **First slice, Option-B reaches Ghostty as a key.** In a headless test, feed a synthetic US-layout Option-B `NSEvent` through the production Desktop key handler into a pinned Ghostty surface. Use the existing `io_write_cb` to capture emitted bytes, as in the kickoff probe with a bare `NSView`. Expect `1b 62` with Option-as-Alt enabled and UTF-8 `∫` with it disabled. The enabled case fails on the old callback route. This slice proves both AppKit translation and Ghostty encoding before expanding key coverage.
2. **Use the same event path for the rest of the keyboard.** Cover different bytes for Return, Shift-Return and Control-Return after the fixture program requests Kitty mode. Include a Control letter, a modified navigation key, repeat and release under event reporting, and Option or IME text that commits once. Keep the mounted split shortcut test for focus, including an unbound Command equivalent for AppKit and a Ghostty binding dispatched once.
3. **Exercise the held Session.** Reuse the isolated provider and private Machine setup from `SessionConnectionProofTests.swift`. An input fixture switches its PTY to raw mode, requests Kitty keyboard mode, signals readiness, and reports the bytes it reads. Run the sequence through the Desktop Session surface, then reattach to that PTY and repeat after mode restore. Verify provider bytes, not the return value of a key handler. Use a readiness signal and bounded reads in both probes. The gate target is `scripts/test_desktop.sh --filter 'GhosttyModifierInputTests|SessionModifierInputTests'`, with renderer and PTY checks off-window. The focused split and physical-keyboard checks use the optional mounted lane.

**Demo.** Open the isolated Session in Loopflow Desktop. Press Return, Shift-Return and Control-Return. The fixture shows `0d`, `1b 5b 31 33 3b 32 75`, and `1b 5b 31 33 3b 35 75`, once each. Close and reopen the pane and repeat. In legacy keyboard mode, Option-B shows `1b 62` with Option-as-Alt enabled. With it disabled on a US layout, Option-B types `∫`.
