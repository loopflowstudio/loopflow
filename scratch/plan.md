# LOO-1078 · Pause a Task without giving it up

> i think we need a 'paused' state / action for tasks -- stops the task worker - and ideally e.g. any rust compiling happening becasue of it - , maybe closes the tasks session for now as well, but oesnt unassign

## Done when

During a build, `lf task pause INF-123` stops the worker, its build jobs and the Task’s primary conversation process. The Task still belongs to the same person on the same Machine. Its dirty checkout, PR, Graph position, conversation identity and history are available when they come back. Restarting the Machine server leaves the Task quiet.

The demo uses two Tasks building side by side. Pause one. Its build exits, the other keeps compiling, and `lf task list --state paused` shows the first. Mac and iPhone offer **Unpause** on that same Task. Run `lf task unpause INF-123`, then `lf task run INF-123`. A fresh worker takes up the interrupted step with the existing files. At an interactive stop, the person can instead reopen the same thread with `lf resume INF-123`.

## What makes the pause stick

- Store one hold per Task on its execution Machine. A small `task_pauses` table keyed by Task ID gives a point lookup before a launch, including before the first checkout. Absence means runnable under ordinary rules. Move carries the hold with Task Work alongside auto, before destination recovery can see it. Pause routes to the execution Machine. An unreachable owner yields an error. An unknown Task yields the ordinary missing-Task error.
- Derive `TaskState::Paused` in `sqlite/durable.rs::task_state_sql` after terminal outcomes and before run/checkout facts. The mark describes the decision to hold work. The Graph’s recorded position and running flag still describe the actual process while it drains. A keyed lookup and planning revision triggers serve point reads, lists and subscriptions. Check the board query plan on the repository’s 10,000-Task fixture. Done and abandoned Tasks remain terminal. Reopen starts without a stale hold. An idle or never-run open Task can be paused without claiming it or creating a checkout.
- `lf task interrupt` already writes a one-shot Task event for a live execution. It writes nothing while idle. The Graph watches the event during agent steps, drains an operation already in flight and exits 130 before the next step. The existing five-harness tests show a subsequent run starts a fresh worker at the interrupted step. Capture live execution identities before publishing the interrupt. Commit the hold and the interrupt in the same transaction. Keep interrupt independently available. Auto controls interactive steps and merging. Pause leaves the auto setting and existing external PR disposition alone. Sources are `ops/task.rs::task_interrupt`, `lf/commands/graph.rs`, `tests/work/task_graph_launch_tests.rs` and `docs/orchestration.md`.
- Close the race at admission. Commit the hold under the same admission ordering used to register or spawn Task work. Check it again there for a launch already selected by recovery. The checkout and Session locks exist in `store/admission.rs` and `sqlite/admission.rs`. Serialize the before-checkout case at Task run reservation. Retain outstanding process identities with the pause until their exits are confirmed. This lets a repeated pause or a restarted server finish cleanup even after the worker’s parent has exited. Release admission before waiting for processes. While cleanup is outstanding, Unpause reports what is still stopping.
- A server can independently restart a dead carrier, retry a limit wait, or open a dead or prepared conversation. All three read the hold, including the status outlooks advertising those starts. A queued steer stays available for the next turn. Opening a paused Task shows its history and the Unpause action without starting a provider. Direct runs, auto-on, operator runs and Session launch entry points respect the same hold. Reading status and app navigation have no launch side effect while paused. See `ops/task/{run_recovery,limit_recovery}.rs`, `ops/recovery.rs`, `server/recovery.rs` and the steer/continue launch paths.

## Where process ownership ends

A local probe launched a worker and a helper leading its own process group. After the worker group exited, the helper was still alive. The probe then stopped it. Killing only the step PID loses the ancestry needed to find such builds.

Capture the worker’s attached provider and descendants while their roots still exist, before delivering a stop that can orphan them. Reuse the attachment fence and PID/birth-time checks in `harness/agent_process.rs`. Its headless stop already inventories descendant group leaders. Its native stop signals the exact provider PID because the foreground group can include the terminal itself. Reuse owned-terminal job cleanup where LF created the terminal session (`os_process.rs::TerminalJobs`). Stop and confirm attributable build jobs, including a nested job-control group. The existing descendant helper logs some survivors and returns success. Surface surviving or unverifiable jobs in the pause receipt and keep the hold for a retry. A shared compiler cache daemon, another Task’s builds and a shell merely opened in the same checkout have no Task-owned execution identity.

Use the existing interrupt rule for operations already mutating external state, such as landing a PR. The receipt distinguishes an operation still finishing from a worker and jobs confirmed stopped. No later step starts. Keep the descendant scan on the stop path, and hold no SQLite write transaction across signals, network calls or waits.

## Surfaces and prior designs

Rust owns the paused state and the sentence naming the next action. CLI text and JSON, served writes, remote routing, Task detail/show/status/list, selections, Wave counts and the Swift mirrors use it. Give Paused a discoverable board section outside Working so a claimed, parked Task does not inflate the active count or get offered as unassigned backlog. Mac and iPhone use the same Pause/Unpause actions in `swift/Loopflow/Design/TaskActions.swift`. Cover the request, response and state in shared DTO fixtures, and update operator skills and Task docs.

PR #1544’s pause kept the checkout and history but deliberately left processes running. PR #1652 renamed it defer. LOO-618 / #1767 replaced defer with unassign. The legacy `tasks.paused` column is marked for removal by LOO-938 in `migrations/plan_hub.sql`. Its old bits have no authority over today’s Tasks. LOO-959 / #1972 subsequently added automatic recovery. This design replaces the current assumption that any claimed, unfinished run is eligible for recovery. It keeps the existing interrupt, ownership, Graph cursor and process records, and shares process teardown with move where their semantics coincide. Released migrations and historical receipts stay readable.

**Choices made for review.** Close the primary conversation process on pause and retain the thread. Only `lf task unpause` lifts the hold. It releases the Task for its next ordinary start without automatically replaying the interrupted work. Settle that run as deliberately stopped and retire its pending automatic restart before releasing the hold. This keeps a recovery sweep or an agent invoking ordinary `task run` from accidentally reversing a pause. A Task’s children have their own workers and holds.

## Build and gate

1. **Stop one live build and keep its neighbor running.** Through the real CLI and an isolated Machine server, give a held worker a nested build group and a second Task its own live job. Exercise pause through admission, storage, worker teardown and CLI status on one harness first. The held build and its helper must exit while the neighbor remains live.
2. **Park a conversation and pick up the work.** Close the primary attachment, reopen history without launching, queue a steer and exercise explicit unpause. Exercise all three server recovery paths. Check crash/retry between writing the hold and stopping work, simultaneous launch, an in-flight operation, a Task with no checkout, and handoff to another Machine. Extend the existing worker matrix where providers differ.
3. **Put it in the Task actions.** Serve the same mutations to CLI, Mac and iPhone, update selections, board counts, operator guidance and the interrupted-step walkthrough. Replace any UI-local guess about the next runnable action with the shared state.

The first slice adds the headless gate scenario `cargo test -p loopflow --lib task_graph_launch_tests::pause_stops_owned_build_and_keeps_claim`. It waits on fixture readiness, pauses from outside the worker, reads the CLI receipt and served Task state, and checks both job identities, the owner, dirty file, PR and cursor. It runs recovery against the persisted hold, repeats pause, unpauses, then runs the stopped step to its next interactive stop. The primary Session ID and thread survive. Shared Rust/Swift fixture and TaskActions tests use that same paused state and verify **Unpause** on both clients. The gate passes when the scenario executes and all these observations agree.
