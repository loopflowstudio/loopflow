## What it means to answer a breakpoint

A breakpoint marks a place. An arrival identifies one visit to it. A worker supplies the result and a default. The primary conversation presents them and can discuss them over several turns. The Task owns the single action that takes the next step. Delivering the result, answering a clarifying question, or closing the conversation leaves the Graph where it is.

**Choice for review.** Answering a review can change the worker’s proposed loop decision in place. If ship-review recommends delivery and someone says “2b — fix keyboard focus first”, build starts its next pass on the selected path with those words. Today `CapturedGraph::find` selects the first matching name and `Place::cursor` builds a fresh cursor. Using `--from build` for that answer can select another occurrence and starts the pass count over. Keep `--from` for someone intentionally starting elsewhere. [Captured Graph navigation](../rust/loopflow-execution/src/task_graph.rs)

Extend the existing Task run action locally and across Machine routing. Plain `lf task run <issue>` at a break accepts its saved default. The primary carries the arrival it presented into the same action (proposed `--at-arrival <id>`), uses the existing `--reason` for the reply verbatim and the selected option’s meaning, and may select `--decision advance|iterate` at a deciding break. Ordinary breaks accept direction for the next step. Questions that leave the choice open receive a conversational answer. Nobody needs to know an arrival ID to use the conversation. A blocked default keeps its reason visible until resolved, including on another plain continue. An intentional restart from a stale conversation also carries its observed arrival.

Compare and consume that arrival in the write that installs the run cursor or requests terminal settlement. Save the accepted direction with that transition so a launch retry carries the same words. Publish it as Task direction only for the winning transition. A delayed answer stays in conversation history. If the Task has moved, show its current position and leave its direction alone. Two visits to the same marker need distinct IDs even across a Graph replacement. The primary reads the stop, it never owns its lifetime.
