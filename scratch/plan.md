## The demo

Run `lf task create 'Compare two layouts for the Task list' --graph feature --run` in a disposable repository with different agents configured for explore and the Task conversation. Quit the primary while explore is working. Open the Task from Now or run `lf resume --task <issue>`. The same primary has already presented the alternatives, a link to `scratch/explore.html`, its recommended layout and numbered questions. Answer with the other layout. The conversation records the words and runs `lf task run <issue>`. Plan starts with that choice. Explore ran once. With auto on, plan starts with the worker’s written recommendation.

Creating a backlog Task still just files it. Starting a feature Task launches explore at step zero. The creation request reaches the worker through the brief and stays the first request in the primary when one was requested.

## Four passes, one change

### 1. Run a worker, park after it, recover the decision

Start with `loop: [research, break]`. Today `lf graph show research --json` shows **two** research skills, keys 0 and 1, with the second returning to 0. Simply substituting a marker fails: the compiler requires a final skill, the runner consumes its verdict before the next tick, and settling a Task clears its cursor. This is the first vertical slice. A worker recommending another pass must finish, leave the Task at the marker through a server restart, then run research a second time **only after** continue. An advancing verdict at the same marker must reach end. Batch execution takes the same two decisions without stopping. [Compiler](../rust/loopflow-execution/src/graph/mod.rs) · [Runner](../rust/loopflow-execution/src/graph/runner.rs) · [Transitions](../rust/loopflow-execution/src/graph/transitions.rs)

- A breakpoint is an authored and captured node. Scalar `break` and `break: <name>` resolve in top-level lists, composed Graphs, loops and XOR paths. It has a captured occurrence key and sources, launches zero processes and takes no agent preferences. Plain skill names and explicit `step:` references keep their lookup. Use a distinct navigation name such as `after-research` for an unnamed stop, stable occurrence suffixes for repetitions, and exact captured keys internally. `--from research` reruns the worker. `--from after-research` parks at the marker. Missing or ambiguous explicit names get the available addresses.
- For a loop ending in a skill followed by a break, the skill still produces the existing validated `advance | iterate | blocked` verdict. The break owns the outgoing edge. Checkpoint the skill’s result, step input identity and nested cursor at the marker **before** applying that edge. A bare run parks. Continue or bypass consumes the stored decision exactly once, including feedback and loop counts. Loops ending directly in a deciding skill keep their current semantics. Failed work and exhausted output corrections stay at the failing step. An automatic blocked verdict stops with its reason. At a manual loop-end break, present that reason; a reply that resolves it selects the next step with the existing run/steer controls. Explicit `--from` selects a new start and discards the previous default.
- Keep one current breakpoint on the existing `task_graphs` row. One additive migration holds a nullable breakpoint record with its parked cursor and producer reference, plus an arrival generation. The existing SQL constraint pairs `run_start` with a carrier. A parked Task has neither. The carrier-conditional settlement releases the run, installs the parked record and advances the generation in one transaction. Starting, replacing or closing the Graph invalidates eligibility for delivery. Competing continues compare the observed arrival as well as the position. A successful terminal break requests completion once when continued. Preserve auto-off landing stops, interrupt/retry at the failed step and independent PR/completion settlement. [Storage](../rust/loopflow-storage/src/sqlite/task_work.rs) · [Run selection](../rust/loopflow-execution/src/ops/task.rs)
- Auto is read on arrival. `-b` bypasses for this invocation only. Neither launches a stand-in at a marker. Keep explicit agent overrides, named-skill settings, quota fallthrough and already selected XOR routes. Direct `lf <skill>` still collaborates in the terminal. **Choice for review:** a foreground Graph with a person at its terminal presents the result there at a break and offers continuation. Task Graphs park on their Task; `-i` can bring the person to the interaction without turning each Graph worker into an interactive review. A taskless invocation with no input reports the stop and exits unless batch was selected. An ad hoc Graph in a Task checkout never moves its Task. This keeps participation available without another review Session or a third skill prompt.

### 2. Read existing work and switch the Graphs

The stored executable is serialized `ConcreteStep` JSON (including `interactive`, the older `human` alias, optional occurrence name, captured source and relative returns). It is a different format from authored YAML and from the numeric graph saved with each Graph process. The temporary decoder belongs at each input, with one normalized executable representation. Removal is filed as **LOO-1100**, after a breakpoint-capable release and conversion of outstanding legacy captures.

- Expand a legacy interactive occurrence to the original captured worker followed by a break. Keep its id, agent, occurrence settings and captured content. Capture new definitions in canonical form. At the Task-record boundary translate the definition **and position together** using an old-to-new occurrence map per body. Remap backward edges, saved indices, end-of-body cursors, nested XOR routes and repeat-counter keys. A stopped legacy run with a pending decision can proceed from its finished worker. A legacy Task parked *before* an interactive skill still owes that worker: its first continuation runs it and produces a real review. No fabricated handoff on upgrade. Switch a record to canonical coordinates atomically when the next run takes ownership. An older live carrier finishes writing in its original coordinates; a projection must never mix those with new ones.
- Keep historical process keys and recorded step IDs in their original coordinate system, including stopped runs and history imported on a Machine move. A legacy read fixture covers old YAML shorthand and mappings with id/settings, a parked Task, a nested in-flight checkpoint, and the same Task’s historical graph detail. Exercise export/import of the new parked position, too. [Captured records and transfer](../rust/loopflow-execution/src/store/task_work.rs) · [Graph process wire model](../rust/loopflow-storage/src/graph.rs)
- Convert builtin feature, code and redesign in place. Keep both nested loops in feature/code, with breaks after ship-review and verify. Replace the duplicate in research with one worker and one break. Local `.lf/graphs/kickoff-demo.yaml` becomes pursue → demo → break. Delete the interactive booleans and naming/validation branches on canonical skills, `RunningGraph::stands_in`, `stand_in_message`, interactive-start shortcuts and their old assertions. Replace the no-crossing-interactive rule with normal loop semantics: each encountered break can be visited again. Keep the legacy reader tests. The opening-step takeover from the previous branch stays historical.

### 3. Present the finished step in the primary

The worker’s final answer gives the summary, checkout-relative artifact links, numbered questions and its proposed continuation. For loop decisions the existing verdict summary/reason can carry that prose. Any choice or action the next worker needs also goes in the Task’s working notes. Reading `RunningGraph::answer` and `transcript::answer` shows that the step process identifies a particular Session input, including readback after a correction. Carry that successful input through the checkpoint. Never select the newest file or the most recent Session in the checkout. Resolve links on the Task’s execution Machine. For a command, show its recorded result; for a missing answer or artifact, show exactly what is available. A deliberately entered or leading break with no producer offers the next authored step, with no invented review. [Step readback](../rust/loopflow/src/lf/commands/graph.rs) · [Transcript answers](../rust/loopflow-execution/src/transcript/answer.rs)

- One steer per Task and arrival, addressed only to its current primary. Reuse the scoped arrival, stale-steer filtering and atomic held start from commits `3e59fc7d1d`, `83232c9b4d` and the duplicate-lookup fix `9150c3cc2a`. Replace their payload entirely. A primary presents the completed work, waits for the person and records their words before continuing or steering back to a named step. No skill lookup, skill text injection or worker replay. A later visit to the same marker gets a new generation. Quitting after presentation causes no restart. Parents still get their normal child notice; workers and sibling conversations receive no review.
- Use the Machine’s revision-driven wake and existing terminal registry. Handle arrival before primary creation, open-idle, busy at its next boundary, quit, and server restart. Claim only a current arrival, recheck on delivery/answer, and serialize held start with manual reopen. Failed launches keep the handoff pending and expose the reason. Avoid scanning every Task or reading transcripts on a quiet tick; exercise the candidate query with the storage query-plan fixture. Claude, Codex, OpenCode and Pi have idle delivery paths. [Wake](../rust/loopflow/src/server/wake.rs) · [Harness capabilities](../rust/loopflow-execution/src/harness/README.md)
- Rewrite the six skills for direct and headless use only. Explore produces its alternatives and default; design writes the proposed plan; research supplies sourced findings and a recommendation about the next action. Ship-review leaves its HTML page and tour, verify leaves merged-SHA checks and a proposed disposition in `scratch/verify.md`, demo leaves `scratch/demo.md` with a working launch command and prepares the isolated `.dev` bundle when applicable. Headless demo opens no window. Headless review proposes dispositions before downstream actions such as merge, completion or filing optional work. Machine checks, build output and worker results never imply human feedback. Update builtin and local skill overlays, task-session, task-operate and the shared headless instructions wherever their old wording conflicts.

### 4. Show where the person is needed

Rust projects the captured stop, preceding work, lawful next action and one sentence through Task status and the Work API. A breakpoint is **Active**, at the top of active work and visible in Now. LOO-1078 owns deliberate shelving: its Paused grouping can mask a breakpoint and suppress its wake while shelved, retaining the parked cursor. On this base the SQL groups all non-start/end stops as active, including a landing wait. Derive breakpoint priority from the breakpoint record, never from “active” alone. Preserve existing ordering among peers. Now currently groups by `TaskConditionState` and drops clear rows; the Rust condition/next move must identify the need for a person as well as setting the Task state. [State](../rust/loopflow-storage/src/sqlite/durable.rs) · [Condition](../rust/loopflow/src/lf/commands/waves.rs) · [Now](../swift/Loopflow/Models/NowProjection.swift)

Carry the breakpoint kind through graph show/list/catalog, composition and return arrows, preview and explain, terminal title, Task workflow line, sidebar, Now, and shared Mac/iOS Task/remote views. Replace `interactive_steps` and per-skill display flags in Rust/Swift and their shared DTO fixtures. Preserve numeric history and distinguish at-break, approaching-break, merge wait, failure and end. Update CLI help, glossary, orchestration/work/session guides, reference models, AGENTS.md and QA playbook with the same verbs.
