# Settings redesign · LOO-1066

> Visual redesign of the settings pane. make it more like a standard Apple Settings pane, sort of like Rex

Jack Heart chose “vision c” at explore. [Vision C](design.md) and its [prototype](explore.html#vision-c) define the interaction. Choices made for review are recorded in [questions.md](questions.md).

## Done when

⌘, opens native macOS Settings with a searchable sidebar and grouped forms. App contains General, Appearance, Shortcuts and Mobile. Workflow contains Agents, Context and Git & Release. Infrastructure contains Machines. Settings uses system chrome and accent with colored symbol badges. Theme cards show their own colors and the chosen theme still reaches Desktop, Ghostty and iPhone through the existing appearance path.

Search finds a pane or a control by label, catalog key, alias or description. Choosing a result opens its pane, scrolls to the control and briefly highlights it. An applicable boolean result can be changed in place with the same scope, mutation and Undo as its row. Search runs locally over the catalog and App controls. Results for a different scope identify that scope before an edit can occur.

Workflow and Machines share a scope picker for Global, personal/shared repository and personal/shared Wave. A repository picker uses `PortfolioService` and offers a checkout chooser. Wave choices use the repository’s entries from `RegistryQuery.allWaves()` and carry their authored UUID. General always edits global settings. The scoped forms distinguish what is declared here from what actually applies. A provenance badge opens an inline ladder with candidate values, their disposition and file, the YAML patch for the selected action, Reset Layer and eligible Promote. App-local controls keep their existing owners. Mobile’s readiness dot agrees with its QR and connection row. Scoped pane dots reflect declarations at the selected non-global destination, including declarations that lose.

## Configuration, from file to form

- **One scoped reading.** Add a destination-keyed `config.scope` served read beside `config.settings`, with the existing `Destination` wire shape. Resolve the destination once and read the relevant files once. Return the file locator, each catalogued row’s applicable destinations and authored value at this destination, and the resolver’s effective value and ordered candidates. The observation-backed read also drives a subscription while Settings is open so hand edits refresh the rows. Cache the catalog for the window and reuse the current reading across panes and search. Global passes no repository. Shared reads still see personal overrides in the same checkout. Rust matches canonical keys and retains typed paths for nested map entries. The Swift model uses the returned applicability and candidate reasons to render rows and layer slots. Existing `config.get`, `.settings` and `.explain` callers keep their contracts. [Resolver and facade](../rust/loopflow-execution/src/engine/config.rs), [destination and file owner](../rust/loopflow-execution/src/config/files.rs), [served reads](../rust/loopflow/src/lf/commands/read.rs).
- **Authored and effective are distinct.** Controls loaded from inherited values can create an override. A declaration at the selected layer remains visible when another layer supplies the effective value. Missing, explicit `false`, empty list and nullable/inherited choices remain distinct. The observed order for a Wave was Builtin → Shared repo → Shared Wave → Personal global → Personal repo, with Personal repo selected. Personal Wave and runtime candidates appear where applicable. An empty personal `context.docs` reported “clears earlier contributions.” The ladder shows contributors and clears as well as selections, and represents unset applicable layers as empty slots. `agent` choices, lists and `default_agent` fallbacks use the resolver’s dispositions. [Ownership and precedence](../docs/dev/settings.md), [candidate resolver](../rust/loopflow-execution/src/config/settings.rs).
- **The catalog owns the value.** Swift assigns settings to panes and supplies labels and presentation. JSON Schema drives toggles, nullable choices, pickers, numbers, text, and ordered token lists. Complex shapes open an inline YAML editor with Apply and Cancel. Rust supplies valid YAML and validates edits through the file owner. The default panes include the leaves in [the design](design.md), such as `automation.retries`, plus active catalog settings that the former pane made accessible. Duplicate parent/leaf controls collapse into the most useful editor. An Advanced disclosure preserves access to legacy spellings, dynamic keys, and existing skill/Graph-step overrides with their explanations. Inactive keys show their lifecycle. Tracker remains one tagged value. The probe returned `{git: {}}` from `config get repo.tracker` and `{provider: git}` under `planning` from `config explain`. The projection uses Rust’s existing tracker codec for that row. [Catalog](../rust/loopflow-execution/src/config/catalog.rs), [canonical keys and tracker codec](../rust/loopflow-execution/src/config/keys.rs).
- **Preview and write use the same edit.** Extend the file owner’s canonical, comment-preserving patch path to plan Set, Reset and Promote. The preview applies the draft in memory and shows the affected YAML hunks, including a removal and addition for a move. It returns only affected setting hunks. The write compares the touched authored values from that preview under the file locks. A stale write or Undo reloads and identifies the changed declaration. A committed edit registers its inverse with the Settings Undo manager and shows Undo in the window. Text commits on Return or focus loss, and Escape restores the reading. A failure retains the last confirmed values and keeps the rejected draft available for correction. A dropped response is reconciled against the file before replay.
- **Promote moves one authored declaration.** Personal Wave promotes to Personal repository, Shared Wave to Shared repository, and Personal repository to Shared repository. The button identifies its target. Rust offers it only when the destination accepts the declaration and the target slot is empty. The preview shows the projected effective value because moving an append/reset or a fallback can change it. Same-file moves use one atomic replacement. For two files, lock in path order, validate both patches, install the recipient before removing the source, and keep a recoverable operation record until both complete. Recovery recognizes the before/after values, retains the source on a conflicting recipient, and reports a partial outcome if an external edit prevents safe completion. Undo checks both slots and uses the same writer. The config engine works with the local files even if Work discovery is unavailable. [Locked file writes](../rust/loopflow-execution/src/config/files.rs), [precedent for resumable config writes](../rust/loopflow-execution/src/config/migrate.rs).

The bulk path replaces repeated per-key gets/explains for ordinary rows. Extending the existing directory-based `config.settings` alone would still leave the authored value and target path unresolved. Routing through the destination also handles two scopes in the same physical private file. A disappeared checkout or Wave yields a scope error and keeps the selector usable. A failed read keeps the last good values for that scope marked stale, with mutation suspended until refresh. Settings makes one reading per scope change and debounces active YAML previews by 150 ms. Earlier scope or selection responses are discarded. The target for a warm local scope reading is p95 under 150 ms on the gate fixture. Cached pane switches and search issue zero file requests. File settings stay useful when portfolio, Wave, Mobile or Machines status fails independently.

## App behavior and replacements

- `LoopflowApp.swift` keeps the native `Settings` scene. A SwiftUI `NavigationSplitView`, sidebar search and grouped `Form` type-checked together in a headless SDK probe. The settings scene uses native colors with the active appearance mode. The workspace’s **Choose Theme…** recovery action routes directly to Appearance. `DesignDisciplineTests` applies to explicit view measures and typography.
- `ThemeChooser` keeps the card grid, both System sides, built-ins, personal themes, imports, delete/revert and diagnostics. Cards and System/Light/Dark commit through `AppearanceStore` as soon as clicked, report failure, and offer Undo back to the prior authored `theme:` declaration. `ThemeEditor` owns a draft for multi-color, import and file edits with Apply/Cancel. Closing an editor cancels its draft. Existing `config.theme`, theme files, live workspace colors and terminal publishing continue through the same owner. Delete chooser-wide preview state, dismissal and Apply/Cancel footer where replaced. Preserve the reading/recovery path for externally edited themes.
- General moves the existing `taskFilesAutosave` binding. The Shortcuts pane and separate window use the same grouped, read-only reference and `DesktopAction` bindings. Mobile lifts `MobileSetup` to the Settings scene so the sidebar and pane share a reading. The switch retains Tailscale setup, retry, QR, copy/share, refresh and disable behavior. Refresh status while Settings is visible and reuse the latest answer across navigation.
- Machines uses the identity-checked `lf machine status` probe for visible registered Machines and retains the runtime distinction between checking, reachable, error, and ended rental. Reuse the CLI’s probe in the served path with up to four in flight, its existing 20-second deadline, and refresh while the pane is visible. Reachability loads separately from preferences. [CLI status](../rust/loopflow/src/lf/commands/machine.rs), [probe](../rust/loopflow-execution/src/machine/connection.rs).
- Delete the five-tab shell and `ConfigurationSettingsView` with its state, raw explanation formatter and key-by-key loading. Move live DTOs used by `TaskChangesView` and the new panes to their shared owner. Update declaration, theme and app-entry tests to exercise the new paths. Settings doesn’t change Mobile pairing authority, Machine placement, config precedence, file formats or launch policy. The CLI and server schema, existing Swift callers and iPhone theme/mobile readers remain covered. New request/result DTOs get required fields and Rust/Swift fixtures. Update `swift/README.md` and server operation docs as those paths change.

## Build in four slices

1. **Context from shell to launch.** Put the split shell and Context pane in the actual Settings scene. Use `context.diff` for a shared and personal repository fixture. Show the effective value, local declaration, ordered ladder, and a canonical YAML patch. Toggle, Reset and Undo through the served writer, then read the same isolated files from CLI and launch preparation. 2. **All configuration panes and scope actions.** Fill native controls and YAML disclosures from the catalog, connect the repository and Wave pickers and the advanced targets, add Promote with conflict and interruption recovery, and delete the old Configuration pane. Exercise tagged tracker settings, additive resets, personal-Wave identity and Task Diff consumers through the existing Rust owners.
3. **App panes and health.** Move General and Shortcuts, apply themes instantly with Undo, retain the ThemeEditor transaction, and wire the shared Mobile state and Machine statuses. Replace the chooser-wide preview footer and the old Mobile presentation.
4. **Search across panes.** Wire the complete search index, keyboard selection, row highlighting and in-place toggles to the same pane and mutation state. Check no-results, failed reads, accessibility labels, resizing, and both appearances.

## Gate and demo

`scripts/test_desktop.sh --filter 'SettingsWorkflowTests|ConfigurationSettingsTests|ThemeWorkflowTests|MobilePairingTests|DesignDisciplineTests'` is the headless acceptance command. `SettingsWorkflowTests` uses the branch’s real `lf`, an isolated local server and temporary checkout, following the server fixture in `ThemeWorkflowTests`. From the Context pane, search for Diff, select Personal repository and toggle `context.diff` to `false` over a shared `true`. The patch matches the private YAML while preserving its comment and unrelated key. CLI `config get/settings/explain` and actual launch preparation agree that the diff is omitted. Reset exposes `true` and restores diff input. Undo restores the private `false`. Promote a second setting to an empty shared slot and Undo it, then verify both files. A concurrent edit leaves its new value in place. The focused Rust gate covers the same file operations, schema and interrupted promotion. Swift coverage checks the real pane controls, switching scope during a read, theme selection and Undo with the staged theme editor, and matching Mobile detail/sidebar status. Run the iOS protocol and pairing gate when shared wire code changes.

Run `uv run python scripts/loopflow-dev.py run` against the branch server on a private Machine for the visual demo. Open Settings with `⌘,`, search `diff`, switch to the demo repository’s Personal scope and expand provenance. Toggle, inspect the patch and use Reset, Promote and Undo. Pick a theme and undo it in the same window, then open Mobile and compare its detail status with the sidebar dot. Check light and dark with the window resized. The headless gate uses a Mobile status fixture and inspects the views without WindowServer.
