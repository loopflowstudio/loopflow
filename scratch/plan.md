# LOO-1080 · Quiet Tailscale access on macOS

An owner can leave mobile access enabled, open a Task from their phone and keep working. On a Mac with Tailscale LocalAPI, a ready `lf server` launches zero Tailscale commands and causes zero `nehelper` configuration saves or removals. The same approval and QR address work after the daemon returns.

## What the running Mac showed

On November 23, macOS 26.7.4 had one same-user `IPNExtension` proof descriptor. An authenticated loopback GET returned 200 for full status and TCP WhoIs. Full status identified the running node and its owner. `status?peers=false` also returned 200 but lacked the information needed by the existing owner check. Use full status. Unified logs on this Mac included both “Created a new configuration delegate with name = Tailscale” and “Tailscale is removing configuration”. These were discovery probes. The branch-server churn measurement belongs at gate.

LOO-718 (#1812) introduced the five-second owner check so logout closes **already connected** phones. LOO-809 (#1897) bound terminal and bulk tickets to the device identified on each connection. Merely slowing the existing timer leaves the GUI launch in place. Removing maintenance leaves admitted connections alive. Both obligations belong in the demo. See `rust/loopflow/src/server/{mobile,remote,ticket}.rs` and `rust/loopflow/tests/transport_tests.rs`.

## One Tailscale installation per listener

1. **Find the daemon and bind from one status response.** In `mobile.rs`, replace the binary-only `Host` and the consecutive `discover()` / `identity()` status calls with a selected transport and one parsed observation containing owner, MagicDNS name and addresses. Explicit CLI setup uses one observation to propose approval. The server independently reads once to bind or restore it. Saved owner and endpoint in `mobile.yaml` remain the approval. Live Tailscale status supplies the facts.
2. **Use LocalAPI for all three operations.** Discover the App Store endpoint from the current account's live IPNExtension proof descriptor, as upstream does. Run bounded discovery once and reuse the client. The standalone macOS extension publishes the port through the `/Library/Tailscale/ipnport` symlink and the token in `sameuserproof-<port>`. Also support the native Unix socket (`/var/run/tailscaled.socket` on Darwin, `/var/run/tailscale/tailscaled.sock` on Linux). The existing reqwest client supports Unix sockets. For extension TCP use literal loopback, the LocalAPI Host header and empty-user Basic auth. Disable proxies and redirects, bound requests and keep proof names, headers, response bodies and key material out of logs, arguments and disk. [Tailscale discovery](https://github.com/tailscale/tailscale/blob/main/safesocket/safesocket_darwin.go) · [Local client](https://github.com/tailscale/tailscale/blob/main/client/local/local.go)
3. **Keep ownership and TLS on the same transport.** GET `/localapi/v0/status` at the existing five-second ready check. Every accepted socket gets a fresh `/localapi/v0/whois` with `proto=tcp` and its encoded peer IP **and port**, including IPv6. Use the existing admission predicate and same-device opt-in. GET `/localapi/v0/cert/<dns>?type=pair&min_validity=24h` at bind and six-hour renewal. The PEM pair goes straight into the existing in-memory TLS parser. Listener exit drops active remote connections. A missing peer or failed WhoIs refuses that connection. Lost identity, login, DNS approval, certificate or daemon stops the listener and reports unready. Rediscover on restoration so port/token rotation recovers. An authoritative refusal or invalid identity never triggers a second transport to override it. [Certificate API](https://github.com/tailscale/tailscale/blob/main/client/local/cert.go)
4. **Bound legacy CLI work.** When direct access is unavailable, retain PATH and both applications directories, renamed bundles, `TAILSCALE_BE_CLI=1` and the 15-second command deadline. Deduplicate equivalent binaries, reuse the selected binary and the result of its discovery probe. Reconsider direct access at the next CLI refresh. Keep WhoIs per connection. For review, use a 60-second healthy CLI status interval. An existing CLI-backed connection can take up to that interval plus one probe deadline to close after an account change. Never reuse a failed status to keep serving.

Replace `manage`'s perpetual retry interval with one deadline per enabled approval. Try immediately on startup or explicit setup. After failure, schedule from completion, at 5, 10, 20, 40 and then 60 seconds for direct access, or at 60 seconds for CLI-only/unavailable discovery. Carry the CLI cooldown across listener exit and bind failures, including missing installations. Successful restoration clears the failure history. Status reads return the manager's last result. Off cancels the pending retry. Saved-port restore, explicit setup's occupied-port repair, exact tailnet address binding and the independent local Unix service retain their current behavior.

## Build and gate

- **First slice:** restore a saved approval through a fixture LocalAPI with a counting CLI stand-in. Reach a real TLS/WebSocket welcome and a subscription reading, observe two maintenance requests, then switch the host owner. The phone must disconnect, local commands must still work and the CLI count must be zero, including certificate and WhoIs. Rotate the daemon endpoint, restore the approved owner and reconnect at the same address.
- **Second slice:** exercise CLI-only startup, steady state and failed restoration. Count probes with deterministic deadlines, including a slow attempt, repeated status reads and disable during backoff. Retain explicit setup and legacy CLI coverage. Move the existing 15-second real-time logout/recovery scenario onto the direct transport. Isolate discovery for both test paths so neither can reach the developer's daemon or GUI. Update the transport description in `rust/loopflow/src/server/README.md`.
- **Headless gate:** `cargo test -p loopflow --test transport_tests server_mobile_ < /dev/null` with inherited `LF_*` cleared. The fixture drives the foreground server, mobile CLI, private socket and a phone protocol client. Expect the first slice's counts and disconnect/reconnect, foreign-device rejection, unchanged local server instance and a disabled listener after restart. Use paused Tokio time for the fallback schedule in the library tests. Desktop's Mobile settings reads the CLI result and iOS uses the same endpoint and tickets. This needs no Swift, wire, schema or QR migration.
- **Mac demo:** run the branch binary's `lf server run` with a temporary `LF_HOME` and a copy of the approved settings using port 0 in that copy. Confirm `lf server mobile --status` against the temporary home reports ready. On a quiet App Store Mac, bracket 120 seconds of idle readiness with timestamps and query `/usr/bin/log show --info --start … --end … --predicate 'process == "nehelper" AND eventMessage CONTAINS[c] "Tailscale"'`. Count the delegate, save and removal records. Confirm log visibility against a known CLI invocation in a separate control window. Record duration, readiness and counts at gate. Unrelated Tailscale activity makes the window inconclusive. Stop only the branch server by PID. A green fixture alone cannot establish the macOS result.
