Jack Heart wants to choose an appearance that feels like one coherent Loopflow workspace, including the sidebar, headers, controls, pane surfaces and terminal content. Today the fixed cream/slate application chrome surrounds an independently dark terminal region. Design and deliver whole-app theming so people can work comfortably in a visual environment they recognize while still understanding selection, focus, activity and errors.

The main workflow is sustained coding and switching among retained Repo/Wave/Task contexts. A coherent theme should reduce visual discontinuity across those surfaces and let people bring familiar terminal colors into the app without sacrificing legibility or the Loopflow interaction model. Theme changes must be reversible and preserve the current work.

Acceptance:
- Choose and preview a theme through the existing appearance/preferences surface; the application and terminal update coherently and the preference restores on the next launch. Preserve recognizable current light/dark options and a straightforward way back to them.
- Use one theme definition/mapping for structure, text, selection, keyboard focus, links, actions, activity, terminal palette and pane chrome. Maintain explicit semantic distinctions: selection is not failure; unknown activity is not Working; terminal colors do not invent Task state.
- Exercise Repo/Wave/Task switching, collapsed/expanded sidebar, attention queue, pane focus and split layouts in each included appearance. Existing native clients, drafts, layout and identity survive applying or reverting a theme.
- Demonstrate readable ordinary text and meaningful indicators with automated palette/contrast checks and headless app/view tests. Native review judges visual coherence, including terminal output, without claiming a test proves subjective preference.
- Evaluate importing an existing Ghostty theme as a starting point. Decide how missing semantic application roles are derived and how unsupported inputs are explained; import format, catalogue size and exact built-in themes remain design decisions, not preapproved requirements.
