1. Inspect a command that ran

The following output was captured before publication from the implementation now at 51c409ab8, using the source-built CLI and a disposable Home. “lf” abbreviates that binary's path. This command was direct, so its recorded parent is null.

$ lf monitor show 28db04b5-208f-4c8d-9c45-d0899445438b --json
{
  "id": "28db04b5-208f-4c8d-9c45-d0899445438b",
  "trace_id": "922898ad-6557-452e-9110-4b80dabdcfe4",
  "parent_process_id": null,
  "via_agent": false,
  "started_at": 1791395533,
  "completed_at": 1791395533,
  "outcome": "succeeded",
  "exit_code": 0,
  "signal": null,
  "error": null
}
[Session, command and path fields omitted from this excerpt]

Exec becomes Process, and parent_exec_id becomes parent_process_id. A process ID remains the durable UUID; it is not an OS PID. No result is inferred from whether an OS process still exists.

A missing identity fails without changing history. Use lf monitor list --all --json to find the recorded identity, then inspect it. That recovery command is a suggested action; the failure below was captured.

$ lf monitor show missing-command --json
Error: Process or Session missing-command was not found
[exit 1]

The read path and authority rules already existed. This PR changes the public vocabulary and owning types. Session-only flags still reject a process record; causal parentage grants no control authority.

2. Read a Task's recorded work

The Rust and Swift wire shape changes together: execs becomes processes. Task execution state remains execution; it is a separate concept. The Desktop label is implemented below, with headless view and DTO checks passing. No interactive screenshot is claimed.

Swift's OS launch object is named explicitly as Foundation.Process. The new Loopflow.Process is the decoded durable command record. The rename adds no second store or lifecycle.

3. Change the names without losing evidence

One draft upgrades the released schema. FlowProcess describes existing append-only metadata on the Flow's lf process; its steps remain ordinary child processes. The migration retains their records and rebuilds the affected constraints and revision triggers.

The populated upgrade test compares every column before and after for processes, Flow steps, Session history, Task workflow and its move history. It also checks foreign keys, append-only restrictions, first-start preservation and revision increments. The existing migration tests passed separately.

Names embedded in retained files need a narrower boundary. Capture manifests, provider environments and receipts retain their existing encoding; old trace nodes and acceptance decisions remain readable. Released SQL, dated release notes and opaque history are unchanged.

This exception is deliberate: replacing the receipt directory or field spelling would hide retained evidence during recovery. --accept-unknown-process emits the new event field, while the historical reader also recognizes original exec_ids decisions without rewriting them. The completion test covers that released spelling.
