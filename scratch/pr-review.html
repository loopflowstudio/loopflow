01

Renaming a parent keeps its child Waves attached

Rename infrastructure to infra. Release becomes infra/release, with the same identity and plan.

Release has its own objective, plan, Tasks and schedule. Renaming its parent changes how Release is addressed; its existing work stays attached.

The code keeps a permanent ID, a name such as release, and a parent ID. It derives the full address from those names. SQLite stores the relationship; slug holds the derived address in memory.

Changing Infrastructure’s name therefore changes Release’s address without rewriting Release’s identity. The SQL view is the shared calculation used by readers.

Boundary case: copying an ID does not create a second Wave

A conflicting occupant is rejected above. If the same UUID still exists in the previous authored directory, discovery refuses to interpret the copy as a move.

The store also rejects cycles and parents in another repository: validate_wave_parent. The inspected fixture checks sibling names, duplicate IDs and a parent cycle.

Operational review point. Row reconciliation precedes the file write; the two are not one transaction. A GOAL.md write failure can leave the row changed before the operation reports failure. This is a source-derived boundary, not a newly reproduced failure.

04

Keep your own memory allowance separate from inherited memory

The selected Wave gets 8,000 tokens. Repository memory and all ancestors share another 8,000.

Local review revision, not yet published. Jack Heart requested separate allowances on 2026-09-30. This supersedes the published branch’s single pool. Jack is open to experimenting with repository memory; the implementation below tries automatic inclusion in the inherited pool.

wave/infrastructure/release/MEMORY.md8,000 tokens for Release alone

A large Infrastructure memory can no longer shrink Release’s allowance. Each pool also has a 64-KiB byte limit. Unused space in one pool is not transferred to the other.

Repository memory comes first, even without a Wave

When the executing checkout contains a root MEMORY.md, include it before ancestor and selected Wave files. Without a selected Wave, repository memory still receives the inherited allowance. Explicitly requesting the same file does not duplicate it.
