1. Start with the request

Current main uses lf -i -a claude : "Plan store migration for archived tasks" for an explicitly interactive launch. This is a source-verified example, not a rerun of the demo. The historical transcript below used an older branch binary; --tui is retired on main.

The base used a skill name or a random word pair. This PR selects an attributed user request, so injected operating instructions and the generic initial trigger do not become the name.

Product choice: by inspection, “Can you help debug cmux titles?” becomes “Can you help”. The three-word cap guarantees brevity, but it does not identify the subject. This is a source-derived counterexample, not an observed model response or an agreed redesign.
The existing Session record and the changed creation boundary

AgentSession.title and title_source already own the name. There is no new schema or terminal-name record. record_row stores the generated name before provider work, including headless starts.

2. Project the name into the terminal

For Task work, the identifier is derived from the Task record and prepended only for display. Both interactive entry points use this new projection. Headless Sessions keep their saved names without a terminal write.

The initial OSC write happens before the provider starts. Claude receives a native name; Claude/Codex title writes are disabled for lf-owned terminals. Later cmux changes use its separate control channel. Other terminals receive a changed name on reconnect.
How the projection finds its Session and Task

The integration points are engine/agent.rs::_run_agent_once and lf/commands/util.rs::session_command_status_with_env. Their wait loops refresh this observer without replacing native stdio.

3. Rename once; let cmux follow

The shared operating instructions now tell every lf surface how to improve its generated name while preserving a human-assigned name.

The CLI marks ordinary renames as human-authored and --suggest as generated. The existing API returns the authoritative Session after the write; its existing SQL prevents a generated suggestion from replacing a human name.

The new observer reads that same stored name every half-second. Driver replacement stops the old observer. A host error disables further updates for this attachment while the Session continues.

Failure and recovery: each cmux command has a one-second bound. If workspace rename succeeds but tab rename fails, the host can temporarily disagree; the SQLite name remains saved. After correcting host availability, reconnecting creates a new observer. This recovery is supported by source and the recorded fixture, not a newly induced live failure.
Bounded host command and public CLI entry
Remaining host question: rename updates workspace and tab, but emits no new OSC. The live readbacks prove those two names agree; window-bar propagation, rendered sidebar readability and the latest-message line were not observed.

4. Name plain provider conversations

These conversations remain provider-owned. The new internal callback uses the same excerpt function, skips lf-owned threads and nonempty native names, then uses the mechanism available in each provider.

Coverage boundary: shared-server Codex exposes a control socket. Inspected embedded Codex and codex exec do not expose that endpoint; no supported alternative was identified in the earlier capability audit. The read-then-set check also leaves concurrent manual-rename preservation unproved. No provider changes are included.
Hook installation and failure reporting

Published promotion adds hooks when skill sync is enabled, merges existing settings, preserves symlink destinations and permissions, and avoids duplicate callbacks. Hook errors are reported without failing the native request. Installation-entry acceptance still needs a disposable OS account; helper tests establish only file merging.
