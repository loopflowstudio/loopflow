01 / START

A separate hook layer, scoped to this launch

SessionCommand carries the executable name, argv and working directory. The existing launch API passes that command into the terminal lifecycle; this PR changes its preparation, not the Session model.

The returned NamedTempFile owns cleanup. lf creates the file in the effective Codex home and selects it by profile name; it does not edit saved config or trust records.

Change from base. The old launch inserted a whole -c hooks={…} table and the trust flag unconditionally. The new native profile layer composes with a wrapper’s CLI hooks in the recorded fixture. It requires native profile-file support; interruption can leave an unselected temporary file.
02 / TRUST FLAG

Ask the parser before the real launch

The probe uses the same PATH command, cwd and explicit environment. Its incomplete model option is meant to stop parsing before a Session starts. The actual Codex process keeps its terminal descriptors.

The main tradeoff. Setup-free launch now invokes the wrapper twice and depends on exact English parser text. An unfamiliar diagnostic or a five-second timeout blocks the real launch. The probe has no provider argv or capture profile; a wrapper whose behavior varies with those inputs is not covered by the synthetic fixture.

On an unfamiliar diagnostic, the error includes the provider text. Resolve that diagnostic before retrying the same lf command; the implementation does not silently guess which flag to send or relaunch a live provider.

03 / CAPTURE & RECONNECT

Record one native conversation, then reopen it

Only a new captured Codex launch prepares the profile. Reconnect already has a native ID, so the existing path records that ID and bypasses profile creation and the parser probe.

The hook calls the existing lf __provider-session entry. It reads the callback’s session_id and writes it against the inherited capture. The durable object stays a Session observation; no new table or “latest native history” resolver is introduced.

Follow the callback into that writer

A provider exit alone is insufficient. After the process is waited and its outcome recorded, the new completion condition checks for native identity. The Session and launch evidence survive a missing callback.

Recovery limit. Inspect the retained capture and provider hook diagnostic, repair the cause, then retry the original launch. The error does not promise reconnect without an ID. The regression deliberately seeds unrelated native history and verifies that no identity is adopted.

What the native fixture establishes

The PTY fixture checks the host’s launch-hook receipts against the exact ID stored by lf, then reopens that conversation. These are source assertions, not a new test run for this walkthrough.

Unverified product boundary. Fresh hooks did not emit on native resume, including a direct Codex reproduction without lf. Reopened identity and history are proved by the fixture; cmux agent-list tracking after launch or reconnect is not. Launch receipts must not stand in for reconnect receipts.
04 / RETAINED FLOW CHANGES

Read the work while it runs

Skills and operations call the same printer. The Flow launcher forwards verbosity once to child commands; prompt-bearing instrumentation and debug dumps are removed in both modes.

Assertions for output and prompt omission

Started is committed with the Flow

At Flow entry, execute calls this writer before any step runs. A Task whose checkout contains that Process’s cwd gets its first Started time in the same transaction as the Flow record. The separate best-effort Task update is deleted.

Checkout membership selects the Tasks; an explicitly named Task alone does not. If either write fails, the transaction does not commit. Started records work beginning, not Task completion.
