The goal is that you save a connection to another machine once, by its ssh name, and afterwards refer to it by a label. No ids are copied by hand. Credentials, detached work and reattach are later steps.

What you type

Review note. lf machine observe is gone. list and status take an optional label; rename and remove take a label only, while lf ssh accepts a label or the id.

What is saved

Review note. A connection is two nullable columns on the machine row, set together or not at all. Removing a connection keeps the row, so placements and history that point at the machine survive. No credentials are stored. Adding a machine whose id is already known replaces its destination, label and repository.

Adding and checking

Review note. The probe is one ssh call that runs lf --version && lf machine id, with batch mode (never prompts) and strict host-key checking. That matches the herdr floor you set. It finds the remote lf through a fixed PATH. Version difference is reported with a command to run; nothing is updated for you, per your no-compatibility-work stance.

Gap against the design. The design said first connect should offer to install lf on the remote when it is missing. This PR treats a remote lf and an existing checkout as prerequisites and reports an error otherwise.

Using it

Review note. Two consequences. First, lf ssh no longer accepts a raw host name: credentials now only go to a machine you added, which closes the hole noted in the design. Second, every lf ssh makes two ssh connections, the probe and then the command, where before the identity check ran inside the one connection. On a slow link that roughly doubles the start-up time of each remote command.

Open points

  • Two connections per lf ssh. Accept for now, or fold the identity and version check back into the command's own connection.
  • No offer to install on the remote. Add it here, or leave it as a prerequisite.
  • Machines you had recorded with observe are kept as rows but have no label, so lf ssh refuses them until you run lf machine add.
  • The fixed remote PATH is still how the remote lf is found.
  • This branch needs syncing onto main now that the rename has merged; that happens when landing is requested.
