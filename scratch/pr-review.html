01 / Proposed behavior

One selected file, from help to execution.

Illustrative commands — desired behavior, not captured output

lf audit "src/payment"
lf --agent codex audit "src/payment"
lf help

Given only .claude/skills/audit/SKILL.md, the first command should invoke Claude natively; the second should run a translated port of the same source. Both are pending implementation.

Source agreement is part of fidelity. Invoking a same-named slash command is insufficient when the harness selects a different file. The proposed ordering is not a recorded decision from Jack Heart.

What the replacement must delete

The external catalog in lf/discovery.rs, the rams alias, fuzzy npx lookup/fetch, recursive Markdown name scanning, and the separate Markdown resolver and late fallback in engine/flow.rs. Installed npx skills remain ordinary folders. The builtin app path and its dependency on stale exported text are now deleted.

The probe starts or resumes a native thread, submits a selected skill beside separate user context, then checks that exact turn’s input and history. Its emitted observations distinguish receipt checks from answer markers.

Recorded evidence: Codex 0.160.1 retained the same thread, selected-file expansion, and separate user context across a process restart. Context is supplied again, so the second answer does not prove recall without resupply. Loopflow’s production transport still accepts strings.

Claude preserves arguments, but the context role needs another check.

Claude 2.1.293 retained native arguments and hook context after the hook file was removed. This parser reads transcript rendering metadata; it does not inspect the final model request.

Corrected finding. renderedRole: "system" does not establish model authority. The earlier rejection of the hook on that evidence was withdrawn. Claude’s documentation describes reminders inside user messages or, for some models, system-role messages. Request mapping remains unproved.

Counterexamples and recorded checks
  • Prefixing context or supplying two Claude text blocks bypassed native expansion. Suffixing context contaminated the native arguments.
  • The retained Claude probe prevented the first answer and reasoning from repeating the context marker; the resumed answer recovered it without the hook file.
  • The design records eight offline tests and Ruff passing for unchanged probe code. Those checks were not rerun for this HTML.
  • Probe scripts use synthetic fixtures. Real third-party skill controls, bundled files, translated ports and Loopflow capture are still unproved.
03 / Existing production code + proposed interface

Keep the conversation, including its unfinished work.

Existing command, shown from source — not executed here

lf -b session resume ID "continue the audit"

Today, resume loads the Session’s stored skill and provider/model. A new skill selector would need to flow through that same conversation’s admission and capture machinery.

Proposal: lf --session ID audit "src/payment" explicitly selects an existing conversation. This syntax is not implemented or accepted. The current driver would admit the input; an active turn would finish before the new skill starts unless native skill steering is proved.

If delivery acknowledgement is lost, recovery must inspect retained input/provider evidence before submitting again. A new conversation or another writer would not preserve the intended contract.

04 / Jack Heart’s selected cut

Run in the terminal. Keep the provider identity.

Jack Heart directed removal of --ide after the installed probe. The flag, session.launch selector, app URL builders, automatic skill export, shortened skill seed and app handoff writer are deleted. Interactive execution has one terminal command path; batch execution remains headless.

Why remove it: installed 0.13.9 Claude and Codex app launches returned zero and created a Session plus a launcher Process, but neither recorded a native thread, endpoint, provider PID or birth time. Both actual session connect attempts failed. Visible app execution was not verified.

The terminal launcher passes the capture environment and provider Session ID into the existing spawn path. That path records provider process evidence and observed exit. Existing historical app records remain readable; this removal does not repair their missing identity.

Remaining design and proof

Native skills on terminal and headless harnesses.

App execution and headless-to-app handoff are out of scope under Jack Heart’s October 7 decision. The remaining design must deliver the selected source and exact arguments, separate Loopflow context, and same-conversation admission through the existing driver.
