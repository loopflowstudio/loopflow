1. One assembled launch payload

PreparedProcessPrompt is the result of assembly: launch inputs, rendered text, source components and a budget report. The existing AgentConfig carries the two provider channels; this PR changes their contents without adding a stored object.

At the base, separate Claude renderers put reference material and the request in task_prompt. At this head, the complete bounded rendering becomes system_prompt; task_prompt is the fixed 48-byte trigger. The public entry still checks the effective total, including structured reply guidance.

“All context” describes placement of assembled content, not removal of context budgets. Source boundaries, reference escaping and attribution remain; the two obsolete split renderers and unused Claude turn launcher are deleted.

3. The same writer serves persistent Sessions

The shared writer appends structured reply guidance and returns a retained path, or no path for empty instructions. It uses the existing prompt log under <cwd>/.lf/prompts/; no new database table or alternate context layout is introduced.

Codex’s existing thread ID decides start versus resume. This PR puts the instruction-file path into that request’s config, alongside the existing tool environment. Its first-turn seeding no longer copies system text into user text.

File retention is implemented and covered by a stub test. Native resume still depends on the retained checkout and file; an actual provider resume has not been demonstrated here.
