Terminal colors and command blocks in Desktop

LOO-381 · PR #1448 · base 8ea0bec9c (main) → head de0dac604 · published head equals the local checkout; no unpublished changes.

Goal: provider CLIs keep their colors however Desktop was opened, and a shell command reads as one unit with a header, a truthful failure color, and one selection at a time. The branch delivers this in three places: the environment Desktop gives its terminals, a revised Ghostty patch that keeps block status and selection inside the terminal, and a thinner Swift view that only draws what the terminal reports. Nobody has seen it on a screen yet.

1 · Desktop stops inheriting its launcher's terminal

The cause of the monochrome footer was found at kickoff: Desktop had been opened from a Codex agent's shell and carried NO_COLOR=1 into every pane. This function is the whole fix. The app applies it to itself at launch, so every child process, pane and lf read starts from the result.

Choice to look at: remove by prefix, keep by name. Everything starting CLAUDE_CODE_ or CODEX_ goes unless it is one of four names. The second commit on this branch exists because that rule first removed credentials. The same shape still removes settings that are not output policy: with CLAUDE_CODE_USE_BEDROCK=1 or CLAUDE_CODE_USE_VERTEX=1 exported in the shell that opens Desktop, a provider started by Desktop no longer sees it. That counterexample is read from source, not observed. The alternative is to name the handful of variables seen in the leak and leave the families alone.

2 · The terminal owns exit status and the one selection

Before this branch Swift kept its own (id, text) copy of the selected block, taken at click time, with an id that changed on resize. That produced the two competing highlights and stale copies. Now the facts live where the rows live. Two spare bits of row metadata hold the status:

The shell's “command finished with status N” message is written to the nearest prompt row above the cursor, once. A missing code leaves the row unknown.

One selection

select is Ghostty's existing entry point for every text selection, keyboard-made ones included, so the one added line there is what makes “never both” hold without Swift ordering events. Reading the selected block also retires it when its row has scrolled out of history or been cleared.

What Swift can ask

Removed from the previous patch: the per-block id and “read block text at row”. Swift can no longer hold a block identity or copy a block that is not the selected one.

Wrapped command lines: an upstream behavior the patch changes

Upstream copied “this row starts a prompt” onto the row a soft wrap creates, so a wrapped command line became two prompts and split its block. The patch marks the new row as a continuation and changes one upstream test that asserted the old result. This is the part most likely to conflict when the pinned Ghostty revision moves.

3 · Click, drag and copy in the view

The view keeps two pieces of state: the hovered row and where the button went down. Everything else is derived from the block list it polls every 100 ms.

Failure means any non-zero status. grep with no match (1) and a command you stopped with Ctrl-C (130) are red, the same as sdl. The Task asks for “actual exit status”; whether an interrupt should read as a failure is a product call the code has made for you.

Every plain click on a finished command selects it. That includes the click that focuses a pane and the first click of a double-click (the block flashes, then the word selection replaces it). The block stays selected while you type. Read from source; Warp's behavior here was not checked.

4 · The header is a prompt, not an overlay

Ghostty counts the prompt's rows as the top of the block, so a two-line prompt gives each block its header for free and keeps it out of copied text. The cost is that Loopflow now edits the shell's prompt.

The test for “still default” is exact string equality with %n@%m %1~ %# , checked once before the first prompt. A theme that sets its prompt later, or a default with one character changed, keeps its own prompt and gets blocks without a header. bash and fish get no header at all. Header contents (directory, branch) and the 12 pt left padding, which also applies to provider panes, are kickoff choices waiting on your demo.
