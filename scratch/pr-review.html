STOP 01

A new conversation lives beside the provider’s own conversations

Before this PR, selecting a managed account redirected the provider into that account’s private home. Now a shared launch clears credential overrides and leaves an ordinary caller-supplied home alone. An account home inherited from an isolated parent is removed so it does not become the shared home.

The active eligible account wins while it is unstrained. Otherwise routing selects another eligible account; the launch installs that account’s login before spawning. This is the new shared path through the existing account catalog and quota selection machinery.

Where the provider process takes this route

The same wrapper is used by the Claude harness, direct agent execution and terminal resume. No history is copied between homes. Existing private histories remain where they were created.

STOP 02

Switching to B preserves A’s latest login

Representative action: A is active and has refreshed its login. Jack runs lf account use codex B (A and B are illustrative stored account selectors). The command resolves B, locates the native home, and requests activation on a person’s behalf.

After validating B and acquiring the provider credential lock, activation saves the native login back to its owner. An unplaceable login is preserved beside the profiles. Only then does it install B and append a switch receipt. The command reports “now signed in”; a later plain Codex process reads B from the same home.

Saving A’s current bytes before installing B is what makes A → B → A retain a rotated login. A login with a newly learned identity becomes an explicit-only profile, so preserving it does not volunteer it for automatic work.

Save-back ownership and the already-active boundary

A missing usable profile fails with a reconnect command before changing the native store. An already-active account returns without a switch. A Codex configuration selecting another credential store is rejected before save-back.

Operational boundary: the credential write and SQLite receipt are sequential, not one transaction. If logging fails after installation, the command can report an error after the native account changed. This follows directly from the ordering above; it was not fault-injected.

STOP 03

Claude uses the same switch through its native credential store

The product action is the same for Claude. On macOS, native homes read the Keychain first; stored account homes and unit tests use files. The write path mirrors that split, so changing a file that Claude ignores is avoided.

Claude’s login does not carry a readable owner identity. If its tokens no longer match a stored profile, observing the active account asks the provider through save-back, under the credential lock. A network failure can leave ownership unknown; activation preserves the bytes and proceeds with the selected login.

Unlike Codex, a running Claude is expected to adopt the changed native login. That behavior was inferred from the inspected Claude binary in the prior research, not exercised with a running agent. The fixture proves a newly launched Claude sends the installed login.

STOP 04

An isolated conversation reopens in its account’s home

--isolate retains private account homes. --shared overrides an isolate: true default. On resume, the recorded conversation mode takes precedence over today’s launch default. A shared conversation drops its historical exact-account pin and follows the current shared account.

The database gains a mode on the existing session-account association. Old rows default to isolated, preserving their private histories without migration. New records explicitly state their mode.

How mode is recorded and resolved

Isolation separates runtime homes, but copying the same account’s login into both homes can leave two descendants of one refresh token. Whether concurrent refresh invalidates either copy remains unproven with live Codex credentials.

STOP 05

The provider’s ID finds the Loopflow conversation

lf session connect <native-id> first resolves an existing Session. If none exists, connect searches the provider’s homes and admits that conversation. Other ID-taking commands resolve recorded provider IDs but do not admit new conversations.

A recorded provider ID must name exactly one Session. Ambiguity names the competing Sessions instead of choosing one.

Admission boundaries and ownership

Admission creates a conversation with no Task, Wave or Flow assignment. It searches native and stored account homes; a conversation found in a stored home is marked isolated. Discovery checks known transcript locations, not a live provider resume request. Non-UUID names do not enter discovery.

Finding history is not sufficient to resume it immediately. The Codex fixture stops retained Loopflow engines before plain app-server resume. Prior research observed “already has an active writer” while an engine remained alive. Direct terminal codex resume under that condition is still unverified; the retained-engine lifecycle already exists in the base.

STOP 06

A switch changes future launches; “everyone now” is still absent

Jack accepted two switch strengths. This PR implements “from now on.” The command has no --now field, and activation writes only from_now_on receipts. The migration reserves an everyone_now value but does not implement agent migration.

Exhaustion also takes this activation path today. A running Codex keeps its original account until restarted or resumed; a running Claude is expected to follow the native login. Attribution reflects that distinction for rate-limit and credential-health observations.

The new launch wrapper returns a lock, and the caller drops it once the process is spawned. It does not wait for credential-read readiness or register a set of shared agents to migrate. A concurrent switch after spawn can therefore affect which login a new process reads; the design explicitly accepts that ambiguity for future launches.

Judgment still needed

  • When should a finished Codex conversation release its retained engine so plain resume can take over?
  • For “everyone now,” should an in-flight turn be interrupted immediately or allowed to finish? Research still owes terminal input, scrollback, tool replay and history continuity.
  • The account use name, explicit-only treatment of discovered logins, and the need for a Wave-level isolation default remain implementation choices or open questions in the plan.
