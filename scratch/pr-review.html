Jack Heart's model from October 5: one lf flow run is a process whose driver keeps an append-only record, FlowExec; its steps are plain commands that do not know they are part of a Flow. The outer path from start to end, TaskWorkflow, is designed in scratch/task-workflow.md and is not in this revision.

1 · Run a Flow for a Task

Unchanged from the last review. task_flow_launch_tests still runs the three launch forms and asserts identical refusals and records; it passes at this head.

2 · A step is the command you would type

A deciding step's answer format is appended to its message (lines 529–531). If the answer does not parse, the driver runs lf --batch session resume <conversation> <correction>, twice at most.

Fits the decision. Jack: “why does the skill lf exec even need to know what step position it is? just runt the right skill.” No payload, hidden argument or position variable remains. LF_FLOW_ID is still set in the step's environment so skills can share a note; lf reads it nowhere.
How the driver learns its child's Exec. It notes where the Exec table ends, starts the child, and polls every 10 ms for the first new Exec whose parent is itself. A driver killed in that gap leaves a step with no record line.

3 · The record every Flow gets

Fits the decision. “the flow driver should be responsible for maintaining the state”; “FlowExec works fine”. The record is keyed by the driver's Exec, holds no state of its own, and triggers refuse any update. No column on a Task points at a Flow.
Regained since the last review. A past Flow is drawn on the graph it launched with, not on today's YAML.

4 · Killing a Flow's process

Evidence limit. This was an operation step. A driver killed during an agent step is untested; by design the running turn is left to its conversation.

Choices the pass made that Jack has not reviewed

From scratch/questions.md, “Choices the FlowExec pass made without Jack”. The ones that change behavior beyond this model:

  • Structured output is gone for every provider. A deciding step's answer contract is message text only; the driver accepts a JSON value alone, in prose or in a code fence. How reliably real providers comply is unproven.
  • Any lf command can be a cmd: step. The in-process operation interpreter and its allowlist are deleted. cmd: pr open now opens the browser page; commit in a Flow no longer applies the guard the interpreter added.
  • Watched landings. Exit status 75 is gone; after an operation the driver stops the Flow if a landing of its checkout still awaits its merge.
  • Steers. Every step receives all of its Task's steers; per-node acknowledgement, which spared a repeated node steers it had already seen, is gone.
  • Step overrides. A step looks its skill up by name, so a mid-Flow edit applies to later steps. Only agent travels, as --model; action_style on a step is dropped. The default XOR router is now a builtin skill, xor-route.
  • lf session resume ID MESSAGE is a new optional argument, refused without -b.
