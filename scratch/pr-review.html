1. Name the thing being represented

PodiumView → RepoView, PodiumModel → WorkModel. The repository view retains per-window terminal workspaces; switching repositories changes its content without inventing another durable Work object.

TaskProjection and WaveProjection name presentation joins. WorkModel also serves Portfolio; it is not a replacement Task record. The product label is Loopflow Desktop.

TaskWorktreeSnapshot describes Git placement. SessionWorkspace and WorkspaceIdentity remain because primary conversations can use non-Git directories. Terminal layouts retain Workspace, and Apple’s NSWorkspace is unchanged.

Saved data retains its names and bytes

The file workspace.json, its envelope version, selection/layout preference keys, placement JSON fields and metric identifiers retain their existing spellings. The naming pass changes the code’s vocabulary without resetting saved state. A fixed pre-rename cache fixture checks retained Home/Task selection and unchanged file bytes.

Implemented CLI spelling (illustrative invocation):

lf monitor work --watch --json

It emits newline-delimited frames; there is no monitor workspace compatibility alias. Rust/Swift consumers and command documentation were updated together.

2. One selected Project, stored once

The previous branch used a Home-local YAML binding. Its replacement references the accepted local Project row; the external UUID remains the provider identity. Existing YAML is imported once with its original bytes retained.

One selected Project is enforced. This does not force every other Linear Project out of In Progress. With no selection or imported binding, ensure reserves a new UUID; it never searches by name for a candidate. Known existing Projects must be bound explicitly.

One-time import preserves bytes and rejects a competing selection

3. A command changes facts; the stream updates the view

Both opening surfaces call this model action. Navigation does not cancel an in-flight command. “Preparing Project…” is derived from its live handle, including before the first readiness frame. The small task dictionary prevents duplicate commands in one window; the Rust Wave lock and reservation handle concurrent callers.

Readiness is a projection of selection, accepted planning, pending transitions and the real activation Exec. It has no independent writer or state machine. A successful command does not directly replace the displayed Project; a workspace frame does.

The view still needs local transport errors when a command cannot reach recorded execution. Those are keyed by Wave; they do not select a Project or manufacture readiness. Empty Flow presentation is suppressed. The old primary-window missing-activation path is repaired in source; a full mounted reopening demonstration remains outstanding.

Inherited from LOO-382: the shared read-only workspace transport

4. Retry preserves the intended identity

Illustrative commands from the implemented interface, not an executed production repair. The first selects the exact existing Project; the second activates it. Both return Project JSON.

lf wave bind-project intelligence 999bdbdd-c045-41a6-8ffc-a97c4a40b0b3 --json
lf wave ensure intelligence --json

A failed provider read returns its error. The recovery command is the same lf wave ensure intelligence --json; it consumes the existing selection or reservation. Completed or canceled history requires explicit reconciliation.

Status-only activation preserves names, authored content and empty Flow. Creation finishes selection and reservation settlement in one SQLite transaction. Uncertain provider effects are reconciled by exact UUID; SQLite and Linear are still separate systems.

How the UI shows recorded failure and offers Retry

5. Rotation remains an explicit operation

A KR-bearing plan names exact successor UUIDs. Preflight and reservation precede provider writes; started work retains identity and unreviewed backlog stays in its predecessor. Opening a Wave never performs this rotation.

Desktop’s Realign Projects control still takes a retained JSON plan file. It keeps reviewed bytes on Apply failure. The reactive redesign removes the stale manual refresh callback; it does not add a plan editor or historical chapter metadata.
