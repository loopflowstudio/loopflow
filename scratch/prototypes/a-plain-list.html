loopflow

A software engineering CLI for your agents.

Ask your agents to build software and they can do it through this one command, breaking the work into concrete steps you can trace and pick back up.

In the terminal

For your agents

Give your agents the tools to do things the right way.

  • Every part of the work planning, designing, prototyping, implementing, testing, optimizing, researching, landing.
  • Flows A Flow is a file that puts those parts in order.
  • Steps Each step is its own session, with a commit between them.
  • Tasks Each task gets its own working copy, branch, and pull request. Its sessions stay with it.
  • Workflows A workflow names the points where you take part in a task’s conversation and the Flow that runs between each.
  • Checks Checks run on each change. After a task’s pull request is handed off for landing, a failed required check can start a repair in the same task.
  • Written down Instructions are Markdown and sequences are YAML, kept in your repository, or use the built-ins.
  • As much or as little of you Stay in one session and steer as you go, come in at design and demo, or let it run. Choose per task or per project.
  • Your models Claude Code, Codex, or OpenCode, on your own accounts.
  • Your machines Runs locally, and over SSH where you choose.
  • Your methods Skills and workflows are files in your repo (or use the built-ins). MIT licensed.
  • Your terminal lf is a command. Run it in the terminal you already use.
$ lf skill design "Add CSV export"  # one session
$ lf run ship-api                   # a Flow: sessions in order
$ lf flow list                      # the Flows you have
$ lf task create --title "Add CSV export"
$ lf task run EXP-12                # a task's next step
$ lf task status EXP-12
$ lf session list                   # every conversation
$ lf wave status exports            # the plan
$ lf pr land                        # merge it

For you

Stay in flow while you work with agents.

  • Loopflow A free, open-source podium for conducting your software orchestra, with native macOS and terminal interfaces.
  • On screen What needs your attention is on screen, and the rest is not.
  • Loopflow for Mac Laid out around your work, with each conversation filed under the task it belongs to.
  • Long-lived sessions A session stays with a workstream and its results. Come back to it and the work is where you left it.
  • Isolated jobs Routine process and autonomous development run as separate jobs, each in its own working copy.
  • Waves A lasting objective, with its plan and its memory. Have as many Waves as you like.
  • Notes Reviewed notes carry goals and lessons into later sessions, so you do not rebuild context by hand.
  • Projects What the Wave is doing now: its tasks, its key results, and the workflow its tasks follow.

FAQ

Is Loopflow a terminal?
No. A terminal is where your agents run. Loopflow is what they do there and how you follow it. lf is a command, so it runs in the terminal you already use, cmux and herdr included.
Which coding agents does it work with?
Claude Code, Codex, or OpenCode, on your own accounts. Loopflow uses the one you have installed and signed in.
What does my agent actually do with it?
It runs lf commands. There is one for each part of building software: planning, designing, prototyping, implementing, testing, optimizing, researching, landing. Each step is its own session, with a commit between them.
What is a Flow?
A file that puts those parts in order. lf flow list shows the Flows you have and lf run starts one. Flows are YAML, kept in your repository, or you can use the built-ins.
How much do I have to be involved?
Stay in one session and steer as you go, come in at design and demo, or let it run. Choose per task or per project.
Do I need the Mac app?
No. The command line tool does not need the Mac app. The Mac app includes the command line tool.
Is it free?
Yes. Loopflow is free and open source, MIT licensed. Claude Code, Codex, and OpenCode have their own cost.
Where does it run?
On macOS or Linux. It runs locally, and over SSH where you choose. The Mac app is for macOS.
What are Waves, Projects, Tasks and Workflows?
Names for how the work is kept in order. A Wave is a lasting objective, with its plan and its memory. A Project is what the Wave is doing now. A Task is one outcome, with its own working copy, branch, and pull request. A Workflow names the points where you take part in a task. Tasks and Waves ↗
