Loopflow is a software instrument

A software engineering CLI for your agents.

Ask your agents to build software and they can do it through this one command, breaking the work into concrete steps you can trace and pick back up.

$ curl -fsSL https://loopflow.studio/install.sh | sh

Free and open source. The coding agent it drives (Claude Code, Codex, or OpenCode) runs on your own account and has its own cost. Download for Mac

For your agents

Give your agents the tools to do things the right way.

01

One command covers the whole job.

lf covers each part of building software: planning, designing, prototyping, implementing, testing, optimizing, researching, landing. A Flow is a file that puts those parts in order. Each step is its own session, with a commit between them.

Write your own Flow ↗

$ lf skill design "Add CSV export"  # one session
$ lf run ship-api                   # a Flow: sessions in order
$ lf flow list                      # the Flows you have
02

Each task gets its own branch.

Each task gets its own working copy, branch, and pull request. Its sessions stay with it. Return to a task and its work is where you left it.

Worktrees and delivery ↗

$ lf task create --title "Add CSV export"
$ lf task run EXP-12                # a task's next step
$ lf task status EXP-12
03

The work is checked before it reaches you.

Checks run on each change. After a task’s pull request is handed off for landing, a failed required check can start a repair in the same task.

Review workflows ↗

$ lf pr land                        # merge it
04

Your way of working is a file.

Instructions are Markdown and sequences are YAML, kept in your repository, or use the built-ins. Your agents follow the same steps every time. A Flow is a file, so a team can review how it works with agents the way it reviews code.

Skills and workflows ↗

# .lf/workflows/feature.yaml
nodes:
  design: review-design
  demo: demo
edges:
  - { from: start,  to: design, flow: task-design }
  - { from: design, to: demo,   flow: pursue }
  - { from: demo,   to: demo,   flow: pursue }
  - { from: demo,   to: end,    flow: ship }

For you · on your Mac, or in cmux or herdr

Stay in flow while you work with agents.

Loopflow is a free, open-source podium for conducting your software orchestra, with native macOS and terminal interfaces.

Actual capture, unedited. The Mac app includes the command line tool; the command line tool does not need the Mac app.

05

What needs you is on screen.

What needs your attention is on screen, and the rest is not. Loopflow for Mac is laid out around your work, with each conversation filed under the task it belongs to, so you follow the work and not a trail of chats.

06

You choose where you step in.

Stay in one session and steer as you go, come in at design and demo, or let it run. Choose per task or per project. A workflow names the points where you take part in a task’s conversation and the Flow that runs between each.

Write a workflow ↗

# .lf/workflows/feature.yaml
nodes:
  design: review-design
  demo: demo
07

Sessions stay with the work.

Long-lived sessions

A session stays with a workstream and its results. Come back to it and the work is where you left it.

Isolated jobs

Routine process and autonomous development run as separate jobs, each in its own working copy.

08

A goal keeps its plan and its memory.

A Wave is a lasting objective, with its plan and its memory. Reviewed notes carry goals and lessons into later sessions, so you do not rebuild context by hand. Its Project is what the Wave is doing now: its tasks, its key results, and the workflow its tasks follow. Have as many Waves as you like.

Tasks and Waves ↗

$ lf --wave exports : "Review the goal"
$ lf wave status exports
$ lf task create --wave exports \
     --title "Add CSV export"
