Loopflow is how you designimplementdemoship software with agents.

Coding agents can do amazing things for you, but they ask amazing focus of you. How can you, a human with a single locus of attention, stay in sync with an entire parallel agent swarm? Shipping tens of thousands of lines is the easy part. Making them lines worth keeping — lines you don’t revert next month — is the hard part.

Loopflow helps you do that by arranging your agent sessions around clear work boundaries: long-lived areas of responsibility and objectives (Waves) and concrete outcomes (Tasks). You don’t have to keep every session window open for fear of it disappearing, or remember why you wanted to do this massive change in the first place.

Your work has defined workflows — how an idea gets researched, designed, implemented, validated, shipped, etc. — and the points at which you want to get involved: be that early on in design, later on in trying it out, both, or neither. Each Wave and Task has an associated workflow that is used to drive work forward and ensures that each session you come to in Loopflow is one where your input really matters.

Scale back as the work matures.

A new Wave starts hands-on: you design each Task and try each change. As the program matures and you trust how its work goes, you scale your involvement back, to one stop and then to none. You can zoom in and you can zoom out. Each Wave’s project sets its own, so a young one and a settled one can run side by side.

  • Hands-on

    starttask-design →designpursue →demoship →end

    The default. You are the designer, and you try every change before it ships.
  • One stop

    startpursue →demoship →end

    Design only, or demo only. You come in once and the rest runs.
  • Autonomous loop

    startoptimize ↺ →ship →end

    No stops. It runs, measures, and goes again, like the loop that speeds up Manabot’s simulator.

lf is the CLI for writing, running, sharing and studying agent workflows.

$ lf -a codex : "fix the failing test"   # launch an agent with a prompt
$ lf skill design "Add CSV export"       # a saved prompt: a Skill
$ lf run pursue                          # Skills in sequence: a Flow
$ lf flow show pursue                    # print its steps
$ lf flow customize pursue               # copy it into your repo
$ lf -b -a claude:opus run pursue        # headless, on a model you pick
$ lf resume                              # pick the last Session back up
$ lf account                             # logins and remaining capacity
$ lf usage                               # tokens and cost per Session
$ lf task create --wave exports --title "Add CSV export"
$ lf task run EXP-12                     # its own worktree, then its Flow
$ lf session ensure --task EXP-12        # back to that Task's conversation
$ lf usage --task EXP-12                 # what that Task cost
$ lf land                                # merge when checks pass
  • Launcher At its most basic, lf is an agent launcher and session manager. Use it anywhere you would launch Claude Code, Codex, or OpenCode, so every agent starts the same way.
  • Skills A Skill is a prompt saved as a Markdown file, so you stop retyping it. lf skill NAME runs one.
  • Flows lf runs Flows. A Flow is a (looping) sequence of Skills: a habit turned into a process you can run again.
  • Built-ins lf provides lots of reasonable built-in Flows for software engineering, but you are encouraged to build your own and share them with others. They are files in your repository.
  • Interactive or headless Run any Skill or Flow as a conversation or headless. Each step can use a different agent or model.
  • Sessions lf keeps every conversation it starts, whichever agent ran it, so you never lose one and can always pick it back up.
  • Accounts and usage lf manages your logins, so you can use more than one account and move to the next when one runs out. It also shows what the work cost, by Task or by Wave.
  • Waves and Tasks lf is also a project manager. It organizes your work into Waves (long-lived streams) and Tasks (concrete outcomes, i.e. PRs), and files each conversation under the one it belongs to.
  • Task = worktree = branch Each Task gets its own working copy, its own branch, and one pull request, so many agents can work without colliding.

It works wherever you work.

  • Your terminal lf can be used inside any terminal, or alongside tools like cmux and herdr.
  • Use as much as you want Use what you like and skip what you don't. The launcher needs no Task and no Linear. Flows run without Tasks, and a Task can run any Flow.
  • Change whatever you want Skills are Markdown and Flows are YAML. Edit them or use the built-ins.

Free and open source (MIT).

  • What you need A coding agent (Claude Code, Codex, or OpenCode) and a GitHub account.
  • What you get We’ll get you building whatever software you want like a software engineer, by guiding you through workflows that get the most out of you and ensure high quality software, not slop.
  • Your code It stays in your GitHub and on your Mac. Nothing is hosted, so there is nothing to move off later.
  • A native Mac terminal Every pane is a real terminal running Claude Code, Codex, or OpenCode, with lf included.
