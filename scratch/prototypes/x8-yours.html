Loopflow is a software instrument.

It doesn’t make the software for you; you make the software through it.

All you have to do is share what you want to make and how it should work. Loopflow turns that into a plan you can read and change, and carries that plan out for you, stopping to talk with you according to how you like to work.

Here is how it goes, from a rambling idea to a set of merged pull requests.

  1. Fig. 1

    A rambling idea, written down

    Say it however it comes out, typed or dictated. Loopflow writes it down as Tasks, in words you already use, each stating what will be true when it is done. Change any of it. They sit together under a Wave, our word for a persistent workstream with an objective.

    You

    ok so people keep emailing us asking for their data. I want them to just get it out themselves. csv probably, with whatever filters they have on. maybe a weekly one? oh and the dates in the old export are wrong

  2. Fig. 2

    You jam on the design.

    Your agent drafts a plan and brings it to you. You go back and forth: push on it, answer its questions, change your mind. It redrafts until the design is yours.

  3. Fig. 3

    It gets built, and you try it.

    Your agent implements the plan, tidies it, catches up with the rest of the code, and opens the pull request, each step a Session of its own. Then the Task waits, marked, until you have tried the change.

    It ships.

    Checks run, then it merges. Every Session that got it there stays under the Task, whichever agent ran it.

That was one workflow. It is a file.

Every Task ends shipped. Loopflow uses configurable workflows to ensure that Tasks are designed thoughtfully, built simply, shipped, and validated thoroughly, all automatically.

None of that process is fixed. Where you step in, what runs between, and which agent runs each step are files in your repository, set project by project. Three workflows come with it. Copy one and change it, or write your own.

# .lf/workflows/feature.yaml
nodes:
  design: { skill: review-design }
  demo:   { skill: demo }
edges:
  - { from: start,  to: design, flow: task-design }
  - { from: design, to: design, flow: task-design }
  - { from: design, to: demo,   flow: pursue }
  - { from: demo,   to: demo,   flow: pursue }
  - { from: demo,   to: end,    flow: ship }
  • feature

    starttask-design →designpursue →demoship →end

    Design, build and land. The one above.
  • code

    Any stops, any Flows between them, any agent on any step.

Free and open source (MIT).

  • What you need A coding agent (Claude Code, Codex, or OpenCode) and a GitHub account.
  • What you get We’ll get you building whatever software you want like a software engineer, by guiding you through workflows that get the most out of you and ensure high quality software, not slop.
  • Your code It stays in your GitHub and on your Mac. Nothing is hosted, so there is nothing to move off later.
  • A native Mac terminal Every pane is a real terminal running Claude Code, Codex, or OpenCode, with lf included.
