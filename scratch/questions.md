# Choices made for review

- A repeated native turn uses its recorded dispatch for Work attribution. Equivalent readings prefer the local Machine, then Machine ID order. A mixed-Machine Session drill lists its origins separately.

- A copied captured input enters the window by its capture, manifest or turn times, not by a terminal receipt or agent end alone, and it ends by its launcher's process rather than its latest turn's. A copied input with no turns that started before the window and ended inside it is left out of `--include-finished` reads.

- Transcript search keeps the existing local hit order and spends the remaining `--limit` on copies. The time window selects Sessions by inputs on the origin, so collecting an old Session today does not make it recent.

- **Unify collected rental records into `SessionHistory`, work-scoped `lf session usage`, and `lf session history search` (replacing the earlier local-only analytics split).** Passed over keeping work-scoped `lf session usage` (`--days`, `--task`, `--wave`, `--project`) and `lf session history search` local-only while exposing rental usage solely through a mutually-exclusive `lf session usage --session <id>` flag. Adding an explicit nullable `origin: Option<SessionOrigin>` (`{machine_id, label}`) to `SessionHistory` (Rust + Swift + DTO fixtures) lets CLI analytics, search, and Desktop’s Telemetry / Task History views include lost-sandbox work automatically without double-counting, while keeping `lf session usage --session <id>` for single-Session inspection.
- **Unify Session readiness (`launch_failure`) and `start_failure` across recovery, steer wakeup, and `lf machine forward`.** Passed over keeping readiness checks scoped to `TaskConversation` in `server/recovery.rs` and hiding `start_failure` on non-Task-primary Sessions, which caused steered stopped Sessions and misconfigured `lf machine forward` restarts to fail silently inside detached PTYs.
- **Settle already-terminated rentals in `lf machine end` via provider `refresh` and hide ended rentals from default `lf machine list`.** Passed over letting `lf machine end` fail SSH and demand `--force` on a sandbox the provider already killed, and passed over showing dead `modal-1..N` SSH routes alongside live Machines in `lf machine list` (while keeping the SQLite `machines` rows for `machine_records` foreign keys, `from <label>` attribution, `lf ondemand list`, and explicit `lf machine status <label>`).
- **Record `modal_sizing: burst` explicitly on newly added Modal `OnDemand` declarations.** Saving a new declaration uses the admission default in `OnDemand::rental_hardware`. Old declarations with `None` continue selecting `Burst` on their next admission. Old rentals with `None` retain their original full request and `cost_usd`. Only rentals with a recorded `burst` or `reserved` mode carry `ceiling_estimate_usd`.
- **No rental-only “carried selection” side channel for Wave Projects.** Passed over inventing rental-specific Wave Project state. Cold acquisition binds the sole In Progress Linear Project across the complete Initiative (counting across all Teams before filtering to the repository Team); when an Initiative has multiple In Progress Projects and the source Machine picked one, rental `prepare` uses the existing public `lf wave plan bind` command.
- **Use Modal’s published minimum of `0.125` core and `128 MiB` as the burst floor.** Passed over `0.25` core / `256–512 MiB`; the floor can be raised later against measured workload.
- **Resolve packaged Linux builds on the caller and pin dev builds by GitHub Actions run ID.** Passed over baking a moving stream into the shared Modal image. Recording the package workflow run ID lets a packaged caller fetch a sibling Linux artifact directly; clean source builds look up their commit, and `LF_RENT_LINUX_BIN` installs via a rootless `~/.local/bin/lf` wrapper targeting `~/.lf-dev`.
- **Make overwriting forwarded files explicit (`lf machine forward <label>`) with opt-in targeted restart (`--task <id>` or `--session <id>`).** Passed over clobbering destination files on ordinary launch or restarting all provider Sessions automatically. Refresh reads only `forward.files`; per-launch `forward.env` stays with ordinary launches.
- **Repeated explicit placement acknowledges an existing Graph on the recorded owner.** Plain `lf task run` remains the command to advance it. If the owner cannot be reached, placement stops before admitting another rental.
- **Per-setting profile retention keeps the installation stream host-local.** A first delivery that disagrees on a setting records a conflict for the file while saving non-conflicting settings in `applied` (so a dev rental keeps `stream: dev` and any local edit while receiving the caller’s skill routes).
- **Claude and Codex check login readiness through native status commands or forwarded native tokens.** Other clients own model-specific authentication at launch. A primary prepared before a login arrives keeps its Session ID and binds its first agent on first input.
- *(Moved to LOO-1083)* Server-routed Task workspace across CLI (`lf open --machine`), Desktop, and Mobile. *(Moved to LOO-1084)* Cross-Machine steering and status.
