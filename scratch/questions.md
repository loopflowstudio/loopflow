# Choices made for review

- **The Task is the only address; no `expected_owner`, no `conflict`, no client-side location (concept review).** Subscriptions re-route when ownership advances, drafts are keyed by `(Task, path, base revision)` and `task.save`'s revision check is the only write guard, terminals stay on the Machine that started them. Passed over an `expected_owner` compare-and-swap on 14 operations with drafts held at `(machine_id, checkout)`: it made each client a second router and kept the Desktop placement guard behind MTG-421. Reversible before release: adding a request field later is additive.
- **Bump server protocol to revision 10 (`REVISION = 10`, `MIN_REVISION = 10`).** Adding `task`/`machine` on `session.attach`/`continue`/`start`, and new `task.shell.*` + `task.files.watch` operations changes wire shapes under `#[serde(deny_unknown_fields)]`. Passed over keeping rev 9 with `#[serde(default)]` (violates the repo's strict DTO no-defaults rule and hides mismatched peer binaries).
- **Hide stale local `task_checkouts` from `TaskReferenceSnapshot.workspace` when another Machine owns the Task.** On a non-owning Machine, `task_reference` sets `reference.workspace = None` and relies on `runtime.owner` to identify the owning Machine; opening the Task fetches the owner's `DesktopTaskPane` via routed `task.get`, which carries the authoritative remote `reference.workspace`. Passed over fabricating a partial `TaskWorktreeSnapshot` with an empty `worktree` string on non-owners, which would break callers expecting `workspace != nil` to mean a known checkout path.
- **Route Desktop remote file watching through a subscribed `task.files.watch` server operation.** Passed over dropping live file push for remote Tasks (manual refresh only) or keeping `RegistryQueryLocal`'s `lf --machine … task watch-files` SSH subprocess. Using the same server-side peer subscription mechanism needed for `task.get` and `task.status` keeps live file invalidation working while deleting every client-side SSH subprocess path in Desktop.
- **Keep `task.shell.start`, `task.shell.attach`, and `task.shell.close` as separate `ServerOperation` variants beside `session.continue` and `session.attach`.** Passed over overloading `session.start`/`session.attach` with shell-specific optional fields or keeping `lf --machine … desktop shell` over SSH. Separate shell operations preserve the invariant that `attach` never starts a process, let both Desktop (with Ghostty `bootstrap`) and Mobile (with `bootstrap: null`) share one server-routed shell lifecycle, and reuse the exact same `Purpose::RemoteTerminal` ticket bridge.
- **Add `task` and `machine` selectors to `session.attach`, `session.continue`, and `session.start`.** A Session created natively on a remote Machine (e.g. a Modal sandbox) has no row in the laptop's `agent_sessions` table, so the local server cannot discover its owning Machine from `LfSessionId` alone. Passed over syncing remote `agent_sessions` into local SQLite (violates local-only inventory rules in `docs/dev/machines.md`).
- **Keep `lf task location --peers` as a CLI diagnostic command while deleting Desktop's `onMachine` and `pinTaskLocation` Task-view routing.** Passed over deleting `lf task location` entirely, which is documented as a separate peer-observation diagnostic tool.

- File operations follow the execution Machine during an unfinished move. `remote_ownership_writer` keeps reporting progress on the source when arrival is unconfirmed. Using it for files would expose the source checkout during a peer outage. Served reads now go through `server/peers.rs::PeerPool`; served writes (`task.save`) still open a one-shot connection until they move onto the pool with the incoming request ID.

- A peer’s per-request refusal leaves the pipe available for the next read. Only a transport disconnect on a reused pipe earns a retry. The peer pool lives with the server and serves both client transports.
