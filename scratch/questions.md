# LOO-839 open choices

- Shallow CI checkouts (rust-lint, architecture-check, task-installation, e2e-smoke, macOS ui-test) order slug migrations by name, so a migration indexing a table created by a later-named slug fails the build (`query_cost_indexes` before `task_workspace_lifetimes`, CI run 43334992755). Renamed to `workload_indexes` so it sorts last; reproduced with an empty `LOOPFLOW_MIGRATION_ORDER`. The fragility stays for future migrations: the alternative is full-history checkouts in those jobs or a dependency-aware shallow fallback in `migration_build::order_catalog`. Not changed here.
- Peer import now merges only fields with changes not yet routed from the destination, so it no longer re-ingests ownership markers of comments the store already holds. `machine_commands::task_ownership_never_routes_to_another_persons_machine` relied on that: it planted Kim's claim on mini as a raw `append_task_comment`, which never ingests markers. The test now has Kim claim on mini through `claim_task` with mini's checkout `user.email` set to kim@example.com. Every production path that brings in a marked comment (provider ingest, peer import, `lf task move`) ingests it on arrival.
