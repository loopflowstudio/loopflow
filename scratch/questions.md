# Choices made for review

- **The Task is the only address; no `expected_owner`, no `conflict`, no client-side location (concept review).** Subscriptions re-route when ownership advances, drafts are keyed by `(Task, path, base revision)` and `task.save`'s revision check is the only write guard, terminals stay on the Machine that started them. Passed over an `expected_owner` compare-and-swap on 14 operations with drafts held at `(machine_id, checkout)`: it made each client a second router and kept the Desktop placement guard behind MTG-421. Reversible before release: adding a request field later is additive.
- **Bump server protocol to revision 10 (`REVISION = 10`, `MIN_REVISION = 10`).** Adding `task`/`machine` on `session.attach` and `session.continue`, and new `task.shell.*` + `task.files.watch` operations changes wire shapes under `#[serde(deny_unknown_fields)]`. Passed over keeping rev 9 with `#[serde(default)]` (violates the repo's strict DTO no-defaults rule and hides mismatched peer binaries). The version handshake now covers every peer that can serve a plan, so the separate revision-9 hub check was removed.
- **Hide stale local `task_checkouts` from `TaskReferenceSnapshot.workspace` when another Machine owns the Task.** On a non-owning Machine, `task_reference` sets `reference.workspace = None` and relies on `runtime.owner` to identify the owning Machine; opening the Task fetches the owner's `DesktopTaskPane` via routed `task.get`, which carries the authoritative remote `reference.workspace`. Passed over fabricating a partial `TaskWorktreeSnapshot` with an empty `worktree` string on non-owners, which would break callers expecting `workspace != nil` to mean a known checkout path.
- **Route Desktop remote file watching through a subscribed `task.files.watch` server operation.** Passed over dropping live file push for remote Tasks (manual refresh only) or keeping `RegistryQueryLocal`'s `lf --machine … task watch-files` SSH subprocess. Using the same server-side peer subscription mechanism needed for `task.get` and `task.status` keeps live file invalidation working while deleting every client-side SSH subprocess path in Desktop.
- **Keep `task.shell.start`, `task.shell.attach`, and `task.shell.close` as separate `ServerOperation` variants beside `session.continue` and `session.attach`.** Passed over overloading `session.start`/`session.attach` with shell-specific optional fields or keeping `lf --machine … desktop shell` over SSH. Separate shell operations preserve the invariant that `attach` never starts a process, let both Desktop (with Ghostty `bootstrap`) and Mobile (with `bootstrap: null`) share one server-routed shell lifecycle, and reuse the exact same `Purpose::RemoteTerminal` ticket bridge.
- **Add `task` and `machine` selectors to `session.attach` and `session.continue`.** A Session created natively on a remote Machine (e.g. a Modal sandbox) has no row in the laptop's `agent_sessions` table, so the local server cannot discover its owning Machine from `LfSessionId` alone. Passed over syncing remote `agent_sessions` into local SQLite (violates local-only inventory rules in `docs/dev/machines.md`).
- **Keep `lf task location --peers` as a CLI diagnostic command while deleting Desktop's `onMachine` and `pinTaskLocation` Task-view routing.** Passed over deleting `lf task location` entirely, which is documented as a separate peer-observation diagnostic tool.

- File operations follow the execution Machine during an unfinished move. `remote_ownership_writer` keeps reporting progress on the source when arrival is unconfirmed. Using it for files would expose the source checkout during a peer outage. Served reads and saves share the peer pool.

- A peer’s per-request refusal leaves the pipe available for the next read. Only a transport disconnect on a reused pipe earns a retry. The peer pool lives with the server and serves both client transports.

- File watching returns an opaque whole-tree revision for each batch of relevant events. A slow subscriber can skip intermediate readings, so a reading containing only the last changed path could leave an earlier file stale. The CLI watcher keeps its path batches.

- `session.start` keeps no `task`/`machine`. Its `argv`, `cwd` and `env` are the caller's, so a routed start would run local paths on another Machine. A remote Session starts through `session.continue` or a Task's own launch there. The plan listed it beside attach and continue.

- A routed `session.attach` or `session.continue` waits for the peer inline, as `session.start` already waits for its holder, so other requests on that one control connection wait up to the SSH handshake (10 s). Moving terminal requests onto the request task set would end that.

- A failed peer subscription retries after five seconds without a planning change. Any planning revision wakes it sooner so it can follow a move immediately. The SSH handshake keeps its existing deadline.

- For the terminal label during a move, carry the Machine selected at attach time in the server receipt during the Desktop migration. `SessionAttached` currently carries only the ticket, terminal ID and expiry. Using the latest workspace reading for the label would let a move change the label on an existing terminal.

- Desktop Close already ends a shell. After a move, use the Machine recorded by the shell attachment for Close. The Task still addresses new shells and reattach, so an old shell ID reaching the new owner returns ended.

- A remote tab launches the public `lf open --here` with its selectors. The tab resolves the Session at startup, so the tab command can be replayed and never contains a single-use ticket. For a Machine-only Session, the retry command and Work link carry the registered Machine ID even after a rename.

- A routed continuation uses the peer Session’s harness. Revision 10 `session.continue` carries Session, request, geometry and routing selectors. Switching harnesses on a remote exact Session with `lf open -a` would need a continuation operation that carries the override.

- A Desktop shell tab keeps the Machine from the reading it was opened in, and Close passes it as `--started-on`. `SessionAttached` gained no `machine`: the tab already names its Machine, and the receipt would only differ if ownership moved between the reading and the start. Mobile can add it in Slice 4 if it needs it.
- `SessionsWorkspace.location` stays as the last known Machine and checkout (shell label, Files fallback). The plan listed it for deletion with the rest of the location stack; nothing compares or validates it now.
- Restoring saved Work no longer hides terminals until a location probe confirms them (`requiresLocationValidation`): attaching goes through the server, which attaches wherever the Session runs.
- An exact Session link to another Machine's Task is found in the Task-scoped `session.list` and must name the Task by this Mac's ID. Tracker-backed peers that gave the issue a different local Task ID fail that check ("was not found in Task"). Passed over skipping the check for remote records, which let an unrelated Session through.
- Files for a Task this Mac's plan says another Machine owns opens before its Session, from `runtime.owner`, with an empty checkout path until the first `task.files.watch` reading names it.
- `lf task watch-files` is deleted with `TaskFilesFrame`, `task_files_frames.json` and the `machine_commands` observer test. Its ignored-path rule survives in `TaskFilesWatch` and is tested on `relevant_paths` (`ops::task::workspace::tests`). `task.files.watch`'s `argv` now names the read each revision repeats (`task files <issue> . --json`); no command streams it.
- An ended shell tab decides **Not started** by asking the server `task.files` for the Task's root, typed, instead of matching the terminal's last screen. Passed over Desktop starting shells through `ServerClient` itself (typed start errors, but the terminal's size and Ghostty bootstrap would move into Swift).
- After a move, a dirty draft whose file on the new Machine is at another revision is held as a conflict, never merged, even when a merge would be clean. On this Machine, a file changing under a draft still merges as before, and an overlapping draft edit still loses to disk there ("Updated from disk"); that local merge is unchanged by this Task and may deserve the same rule.
- The iOS `RemoteTaskWorkspaceTests` reach the laptop's server over its Unix socket, not the TLS WebSocket a phone uses: the Simulator shares the Mac's Tailscale identity and has no certificate for a stand-in tailnet name. The WebSocket carrier, admission and terminal bridge are covered by `machine_commands::server_routed_task_workspace`'s paired phone. Terminal tickets are redeemed on the same socket and decoded with `OwnerStream`, so `TerminalLink` is exercised only up to its typed states (Not started); its live drawing needs the WebSocket.
- A process the Simulator starts cannot look up the OS account (`getpwuid` fails: `id -un` prints `501`), and `lf` reads its installation from it, so the iOS fixture asks `scripts/ios_fixture_host.py`, which `scripts/test_ios.py` starts beside `xcodebuild`, to run its commands. Passed over making `account_home` fall back to `HOME`, which would let a child's environment move install authority.
- Mobile's Session is the Task's primary as `task.detail`'s `current_session` reads it on the owning Machine (routed); no new wire field. The list row's `primary_session` still wins when the paired Machine knows it.
- The phone's shell is `mobile-<task id>` on every Machine and starts on first open; a shell that was live, or one the new owner never started after a move, says "This shell has ended" with **New shell**. A terminal outage keeps the Session's **Reconnect** wording rather than **Try again**.
- (Superseded in Slice 5A) `task.files.watch` stays open on a Task with no checkout and goes live when one is recorded; the phone's 5 s resubscribe loop is gone.
- QA (2026-11-24): `lf task files|file|changes|diff|save` now route to the owning Machine through `Read`/`Write`, like the server. The docs promised only `lf task status`, but the branch's new "Task … is not started" made the local-only CLI say a Task running on mini was not started. `--difftool` and `--recoveries` stay local: they need a checkout here.
- QA: `unavailable_on` keeps a message that already names an `ssh` check instead of appending `check ssh <route> lf server status` again. The check is a substring test on "`ssh "; passed over threading a typed "already advised" flag through every failure source.
- QA: the plan row now drops `task.worktree` once another Machine owns the Task (as `registered_task_status` does), so the stale checkout no longer drives local progress ("Blocked · Task has uncommitted work"), provider lookup or the PR-empty probe.
- QA (fixed in Slice 5A): routed `lf open --task -a claude` on an owner with no `default_agent` refused "No agent selected": served `session.resume` never selected its Clap spelling's settings.

## Post-build concept review (2026-11-24, at `e348359e59`)

- **Make `task.files.watch` a Task-scoped subscription that stays open when unstarted or mid-move, carrying `machine_label` and nullable `checkout`/`revision` (rev 10, unshipped).** At `HEAD`, `TaskFilesWatch::open` died with `not_found { reason: "not_started" }`, forcing Mobile into a 5-second client polling loop, dropping the watch mid-move, and leaving Desktop without `machine_label` or `localMachineId` (moving mini → laptop left `store.machine` non-nil). Passed over keeping `not_started` terminal on the watch and bolting a matching retry loop onto Desktop too. One-shot `task.files`/`task.changes`/`task.diff`/`task.file` keep returning `not_found { reason: "not_started" }`.
- **Add required-nullable `agent: Option<String>` to rev 10 `session.continue` and honor `agent` in `session.resume` / `ensure_task` / `routed_terminal`.** At `HEAD`, `lf open --task -a claude` failed with "No agent selected" on an owner without `default_agent` (QA #1), and `lf -a codex open --task` / Desktop's remote agent switcher silently re-attached to the old harness because `routed_terminal` attached before checking the override and `SessionContinue` had no `agent` field. Adding it while rev 10 is still unshipped avoids a rev 11 bump.
- **Print the calling Machine's `lf open` fallback command on leave/detach of a bridged remote Session.** At `HEAD`, the peer's `native_session.rs` printed `Continue with: lf resume <id>`, which fails on the laptop with "Session … was not found" (QA #3). Passed over teaching bare `lf resume <id>` to fan out across peer Machines (violates local-only inventory rules).
- **Let Desktop `SessionsWorkspace.newShell` resolve a Task's Machine from `location ?? runtime.owner`, matching `files(for:)`, and drop `"Changes below are local."` for remote Tasks.** Removes the last client-side conversation-first gate on Shell and fixes the misleading Diff chip on remote Tasks (QA #7).

## Slice 5 choices (2026-11-24)

- The remote leave/detach line is fixed in the viewer: `relay_socket` takes a `ReturnCommand` and replaces the owner's literal `lf resume <session>` in output bytes, `Return` and `Hint` text. A byte chunk that splits the command would show the owner's spelling; the exit line is one write in `NativeClient::finish`. Passed over sending the caller's return command to the peer (the held terminal's text is fixed when its provider launches, often before this viewer exists).
- With `--agent`, an exact remote Session (`--session`) always continues instead of attaching: the routed overview carries no provider. Same-harness continuation of a running Session is a takeover, as local `lf resume -a` is.
- A `task.files.watch` stream that ends without an error (server gone) is treated like a failure on Desktop: error shown, resubscribe with backoff. A nonexistent Task therefore retries every 30 s while its Files is open.
- Desktop `newShell` falls back to `WorkspaceIdentity(machineId: owner, worktree: "")`; shell tabs read only `machineId` from their location.

- QA (second run): `TaskFilesWatch` treats a recorded checkout without `.git` as not yet arrived. Mini records `task_checkouts` before Git makes the directory, and the watch published "mini is unavailable: No such file or directory" in that window. Passed over reordering the checkout write (the early row reserves the path for recovery).
- QA: the owner's leave line ("Continue with: lf resume <id>") is terminal output, so the viewer rewrites output bytes again, not only Return and Hint text; compress had dropped that and `open_remote_workspace` only checks the detach line.

## Post-build concept review pass 2 (2026-11-24, at `f28db78cd5`)

- **Auto-follow Task owner changes in Desktop's Session and Browser panes (Slice 6B).** When a Task and its Session move (`laptop → mini`, keeping the same `LfSessionId`), Desktop's Session pane showed `"Session location unavailable"` and both strips printed the stale laptop checkout (`scratch/qa/s5-f5b.png`). Chosen: retire the old Machine's Session viewer on owner change, clear stale `preparedTaskWorktrees` and Session/Browser locations (keeping running `ShellTab`s on their starting Machine), always sync `pane.content.location` on prepare/adopt (even when `pane(forSessionId:)` already exists), and warm-open visible started Tasks from `owner != nil` while keeping `prefetchConversations` local-only (zero list/board SSH fanout). Passed over leaving moved Sessions at a manual "Open conversation" placeholder until clicked (breaks "open Task views re-read from the new Machine on their own" and leaves the stale strip).
- **Route Desktop's `New conversation` (`newTaskSession`) on a remote Task through `entry.newShell` with `lf` (Slice 6B).** At `HEAD`, `newTaskSession` saw `reference.workspace == nil` on a remote Task and ran local `lf task checkout` on the Mac, creating a stale local checkout and local shell. Chosen: when `owner != localMachineId`, launch `TaskConversationLaunch(task: issue).arguments(lf: "lf")` in a routed shell tab (`launch.sh` already puts `LF_BIN` on `PATH` and runs in the owner's checkout). Passed over disabling "New conversation" on remote Tasks.
- **Localize remote `SessionRecord`s in one server-side helper for both `Write::SessionResume` and routed `Read::SessionList --task` (Slice 6A).** Rewrites `open_argv`, `action.help`, `outlook.command`, `status_line` to this Machine's `lf open …` command and ensures this Machine's local `TaskId` is in `task_ids`. Zero wire protocol change; fixes QA2's *Open here* tooltip (`lf resume <id>`) and tracker-backed exact-Session links at once. Passed over rewriting only `action.help` in Swift (violates "sentences about state are written once in Rust and carried on the wire").
- **Slice 6 choices (implement, 2026-11-24).** A routed `session.resume` names `lf open --task <peer_selector>` only when this Machine routed it by a Task route; a resume forwarded without one now names `lf open --machine <id> --session <id>` where it used the caller's `--task` spelling. Both open the same Session. Remote **New conversation** runs the owner's `lf` from its PATH (`lf --interactive --task …`), since this Mac's `lf` path means nothing there; a Machine whose login shell lacks `lf` on PATH shows the shell's own "command not found".

## Post-build concept review pass 3 (2026-11-24, at `45b450065a`)

- **Localize every Task ID field on remote `SessionRecord`s (`task_ids[0]`, `work.id`, `workspace.task_id`) (Slice 7A).** At `HEAD`, `localize_remote_session` appended local `task_id` to the end of `task_ids` and left `work.id` and `workspace.task_id` holding the peer's local SQLite UUID, breaking `SessionsStore.preparationWork` (`record.taskIds.first`) and `WorkspacePanesView.paneTaskId` (`record.work.id`) on tracker-backed peers (Linear/Asana). Chosen: put this Machine's `route.task_id` at index 0 of `task_ids` and rewrite `work.id` (when `kind == "task"`) and `workspace.task_id` (when non-null) to `route.task_id` at the one server-side localization boundary. Passed over working around peer UUIDs in each Swift caller.
- **Route `Write::SessionNew` (`Reset session`) through the same Task-first `remote_session` boundary as `Write::SessionResume`, adding required-nullable `task: Option<String>` in rev 10 (Slice 7A/7B).** At `HEAD`, `Write::SessionNew` called `prepare_session(remote)` with `remote` always `None`, so clicking **Reset session** (`plus.bubble`) in Desktop's Session strip ran locally on the Mac; and `work_route::forward` hit `moved_session` ahead of explicit `--task`, downgrading moved-Session `SessionResume` `open_argv` / `action.help` to `--machine`. Chosen: add `task: Option<String>` to `Write::SessionNew` while rev 10 is still unshipped, route both writes with explicit `task` resolving `TaskExecutionRoute` before `moved_session`, and translate `peer_task_id` in `Write::run_here` whenever `task` is `Some`. Passed over disabling Reset session on remote Tasks or leaving rev 10 without `task` on `session.new`.
- **Omit strip context on Task Browser panes (`showsContext` returns `false` for Task `.browser`) (Slice 7B).** At `HEAD`, clearing Browser `pane.content.location` on move while `openWarmConversation` set `workspace.location` made `showsContext` true and printed a duplicate `Files` title beside the `Files` tab (`scratch/qa/s6-final-move.png`). A Task's Browser never lives on a different checkout than its Task, and Files already prints its Machine and checkout in `files-location`.

## QA, Slice 7 (2026-11-24)

- **Open: a routed Reset's creation receipt lives only on the owner.** `session.new {request_id, task}` for a mini Task records its receipt in mini's `creation_receipts`; the laptop's `creation.get` for that ID answers `null`. Re-sending is idempotent on mini (no second launch), but Desktop's `CreationSubmissions.reconcile` re-sends on a `null` receipt, then asks the laptop again and throws "The Machine has no receipt for creation …". A Reset whose answer is lost (server restart, dropped connection) would keep that notice and re-send every 5 s until the record is cleared. Fixing it means the laptop remembering which peer took a request ID, or routing `creation.get` by the saved payload's `task`; neither is a QA-sized change.
- Chosen: `lf session list --task <id>` routes to the owner like `lf task status`, carrying only `--task`, `--headless` and paging as the served `session.list` does; `--on`, `--available`, `--search` and `--primary` are not applied to a remote Task's list.
