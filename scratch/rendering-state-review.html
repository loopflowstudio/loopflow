Refinement from the cmux source study

Read the implementation comparison. Retain terminal owners, not every mounted workspace. Resolve the destination in the first render; do not wait for a view callback. Frame/input readiness remains diagnostic, not a gate that keeps the previous Work visible. Our existing surface pool is aligned; no portal rewrite is proposed.

What the tests must prove

  • Cold opening: opening → terminal, never a transient empty or not-running screen.
  • Cached switch: same pane, surface, draft and focus target; no preparation request.
  • Delayed A reply after selecting B: may populate A, never navigate back or replace B.
  • Refresh failure: retained Workflow stays visible, actions use current authority, error is truthful.
  • Provider elsewhere: no takeover; show the explicit existing action.
  • Observe every published presentation transition, not only the final assertion. Native capture must also show header and terminal geometry.

Evidence: source inspection identifies the asynchronous handoff and independent render branches. Jack Heart reported repeated flashing and confirmed cached switching works. The exact native frame sequence has not yet been captured. The proposed APIs and tests above are not implemented.

Patterns and source reading
  • Apple: stable identity, lifetime and dependencies
  • SwiftUI Observation: data dependencies
  • GRDB: observe query values — apply at Rust’s existing reader, not a second Swift database.
  • Ice Cubes: restore cached content and position before refresh
  • Point-Free: explicit state instead of invalid optional combinations
