# Make mobile work worth returning to

Research for Jack Heart · November 3, 2026

Someone could prefer Paseo, Claude or Happy even if Loopflow's terminal connection works perfectly: those products help them **understand what happened, supply context, inspect the result and return when needed**. Replit goes further for web-app work, joining creation, preview and publication. Loopflow's proposed MVP deliberately covers a narrower interaction: open an existing Task and use its existing Session over host Tailscale. That remains valuable for continuing familiar work, but remote access and multiple providers are already available elsewhere. The comparison below distinguishes documented capabilities from ergonomic inferences; no installed-app trial measured speed, reliability, speech accuracy or accessibility. It does not expand the accepted MVP.

**Catching up can matter more than typing.** On a phone, someone often has thirty seconds to understand a completed turn. Paseo's 0.14 release added completed-turn summaries, collapsible exchanges, grouped tool calls and selectable question descriptions. Those controls explicitly reduce what must remain visible while preserving access to detail. Claude Remote Control synchronizes conversation and subagent/workflow progress between terminal and phone. A native conversation can plausibly make paragraphs easier to read and relevant activity easier to find than a terminal grid, especially beside an open keyboard. That is a design hypothesis, not a measured ranking. A microphone improves input without resolving this output problem. ([Paseo release](https://github.com/getpaseo/paseo/releases/tag/v0.14.0), [Claude Remote Control](https://code.claude.com/docs/en/remote-control))

**People need evidence before deciding.** “The agent says it fixed the bug” is different from being able to inspect the change. Paseo documents files and diffs on mobile; Claude Remote Control has a diff pane; Happy offers files and Git changes. A terminal can display a diff, but someone must request or find it and read it at the terminal's current width. Dedicated presentation can reduce that work. For visual changes, Replit supplies a stronger loop: build a website, preview it, request corrections and publish. These are different product scopes: Paseo's built-in browser is explicitly Desktop-only, and Replit directs native iOS creation/submission to its web workflow. Neither establishes a universal mobile preview for an arbitrary Loopflow checkout. ([Paseo surfaces](https://paseo.sh/docs/why), [Claude Remote Control](https://code.claude.com/docs/en/remote-control), [Happy Mobile Access](https://happy.engineering/mobile/), [Replit mobile](https://replit.com/products/mobile))

**A screenshot can be the instruction.** When someone notices an incorrect layout on their phone, attaching that image plus “move this below the title” can express more than a long typed explanation. Claude's mobile documentation supports sending photos and files into local Code sessions. Happy documents encrypted image attachments. Paseo's mobile test exercises the system photo picker, though that test alone does not prove end-to-end image understanding. This is a substantive gap in text-only terminal input: a phone file path is not a usable remote attachment. Dictation and visual context complement each other. ([Claude mobile](https://code.claude.com/docs/en/mobile), [Happy Mobile Access](https://happy.engineering/mobile/), [Paseo picker test](https://github.com/getpaseo/paseo/blob/main/packages/app/maestro/image-picker-repro.yaml))

**Notifications make intermittent work possible.** A foreground-only app asks someone to remember to check. Claude documents Remote Control notifications for completion or a decision. Paseo's notification contract routes a tap back to the relevant host and agent. Replit documents help/completion notifications and lock-screen Live Activities. Their practical benefit is being able to put the phone away without losing the opportunity to answer. These sources establish features and delivery paths, not guaranteed arrival or lock-screen approval actions. Happy documents push in its original CLI path; equivalent behavior should not be assumed across every newer harness. ([Claude mobile](https://code.claude.com/docs/en/mobile), [Paseo notifications](https://github.com/getpaseo/paseo/blob/main/docs/notifications.md), [Replit mobile documentation](https://docs.replit.com/features/platforms/mobile-app), [Happy original CLI](https://happy.engineering/docs/))

**Voice has two distinct benefits: composing and listening.** Replit's documented pattern matches the proposed Loopflow interaction: dictate, edit the text, explicitly send; it does not speak responses. Paseo supports dictation and optional conversational voice. Its inspected mobile transport sends recording segments to the daemon, so local speech models should not be described as offline iPhone recognition. Happy adds spoken completion reports and spoken permission answers through an ElevenLabs voice agent. That introduces separate usage costs and sends audio plus selected decrypted Session context to ElevenLabs. Someone walking can value hearing the answer as much as avoiding typing; a voice draft addresses only the latter. ([Replit Voice Mode](https://docs.replit.com/features/agent/voice-mode), [Paseo voice](https://paseo.sh/docs/voice), [Paseo dictation transport](https://github.com/getpaseo/paseo/blob/main/packages/app/src/dictation/dictation-stream-sender.ts), [Happy voice](https://happy.engineering/voice/))

Claude needs a surface-specific comparison. Traditional Code/Cowork supports dictation rather than two-way voice; its newer unified experience has broader voice support during tasks. Ordinary Claude voice and memory should not be attributed automatically to Remote Control. Likewise, Dispatch is currently a limited beta for existing users, not a generally available onboarding route. These distinctions matter when judging an attractive demonstration against what a particular account can use. ([Claude voice](https://support.claude.com/en/articles/11101966-use-voice-mode), [Dispatch availability](https://support.claude.com/en/articles/13947068-assign-tasks-from-anywhere-in-claude-cowork))

**New ideas do not wait for an open Task.** Paseo can create a workspace before starting an agent. Happy can start a Session in a directory. Claude cloud and Replit can originate work from the phone. The existing-Tasks-only MVP intentionally omits that moment. Claude cloud also works with the laptop closed, although its isolated environment is different from local uncommitted work and tools. Loopflow can provide availability through an always-on private Machine, at the cost of operating one. General Claude additionally offers share-menu, widget and Siri entry points; those reduce capture effort but do not necessarily target an existing Code Session. ([Paseo workspaces](https://paseo.sh/docs/workspaces), [Happy Mobile Access](https://happy.engineering/mobile/), [Claude cloud](https://support.claude.com/en/articles/12618689-use-claude-code-in-the-cloud), [Claude iOS integration](https://support.claude.com/en/articles/10263469-use-claude-app-intents-shortcuts-and-widgets-on-ios))

**Existing habits and setup can outweigh extra features.** A Claude subscriber can use Remote Control over outbound HTTPS without configuring a tailnet, while accepting Anthropic routing and transcript synchronization. Paseo offers optional relay pairing and also supports direct Tailscale. Happy already supports several providers, although its current Agent uses its own harness while the original CLI forwards provider CLIs. Loopflow's stronger potential advantage is preserving the exact Tasks, Sessions and Machine environment someone already uses. Host Tailscale expresses a deliberate trust and deployment choice; it still adds an adoption dependency for someone who only wants remote agent access. Existing assistant conversations and memory can also make another app the easiest place to explain a problem, without implying that general-chat memory transfers into its coding product. ([Claude Remote Control](https://code.claude.com/docs/en/remote-control), [Paseo connectivity](https://paseo.sh/docs/connectivity), [Happy architecture](https://happy.engineering/guides/remote-server/), [Claude memory](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context))

Three focused comparisons would sharpen the current design without adding product requirements. First, give someone thirty seconds to find the result and pending question in a realistic long Session, comparing terminal presentation with a native transcript reference. Second, dictate a substantial instruction, correct an earlier word and submit it once; compare native composition with direct terminal input on a physical phone. Third, interrupt that interaction by switching Tasks or backgrounding the app, then return and explain what ran, what needs attention and what remains unsent. These exercises test whether the selected terminal experience is comfortable enough for real work. Attachments, review views, notifications and new-work capture remain explicit scope decisions informed by the gaps they reveal.
