# Agent-to-agent communication protocols and products (as of 2026-10-24)

## What is the unit passed between agents, and is the exchange durable and readable by a person afterwards?

### Takeaway
Each layer passes a different unit. Interop protocols (A2A, which absorbed IBM ACP) pass Tasks that carry Messages and Artifacts between agents that are "opaque" to each other, over HTTP/JSON-RPC/gRPC. Coding-agent tools pass plain-text messages (Claude Code SendMessage and mailboxes, MCP Agent Mail threads) or summaries returned to a parent (Claude Code and Codex subagents). Frameworks pass conversation history (OpenAI Agents SDK handoffs). The only system found that is designed for durable, person-readable exchange records is MCP Agent Mail, which keeps messages as Markdown in a per-project Git repo. Claude Code's records are local JSON/JSONL files under `~/.claude` that are cleaned up on a retention timer. None of these treat the work product itself (commits, branches, PRs) as the medium agents communicate through.

### Cited Findings

**A2A (Agent2Agent), Google, now Linux Foundation / AAIF**
- Pitch, verbatim: "An open protocol enabling communication and interoperability between opaque agentic applications." Also: "an open standard for seamless communication and collaboration between AI agents." — [a2a-protocol.org](https://a2a-protocol.org/latest/)
- Units: an **Agent Card** is a JSON metadata "business card" for discovery (endpoint, skills, auth). A **Task** is "A stateful unit of work initiated by an agent, with a unique ID and defined lifecycle." A **Message** is one turn (role user/agent, `messageId`). A **Part** holds text, a file reference or structured data. An **Artifact** is "A tangible output generated by an agent during a task," with an `artifactId`, and can be streamed. A **contextId** groups related Tasks. Remote agents are "opaque" (black box: memory and tools hidden). Async delivery works through polling, SSE streaming or webhook push notifications. — [A2A Key Concepts](https://a2a-protocol.org/latest/topics/key-concepts/)
- On MCP, verbatim: "The Model Context Protocol (MCP) and the A2A Protocol are not competitors — they are highly complementary." MCP is framed as agent-to-tool, A2A as agent-to-agent. — [a2a-protocol.org](https://a2a-protocol.org/latest/)
- License Apache 2.0. A Technical Steering Committee includes AWS, Cisco, Google, IBM Research, Microsoft, Salesforce, SAP and ServiceNow. Official SDKs: Python, JavaScript, Java, C#/.NET, Go, Rust. The site banner reads "A2A joins the Agentic AI Foundation." — [a2a-protocol.org](https://a2a-protocol.org/latest/)
- One-year milestone, April 9, 2026 (Linux Foundation press release): more than 150 supporting organizations (up from more than 50 in April 2025), over 22,000 GitHub stars on the core repo, and SDKs in five production languages. v1.0 is the "first stable specification," with multi-protocol support, multi-tenancy, modernized security flows and **Signed Agent Cards**. It is integrated in Azure AI Foundry, Copilot Studio and Amazon Bedrock AgentCore Runtime. Quotes: Rao Surapaneni (Google Cloud), "AI agents are only as useful as their ability to collaborate." Luca Muscariello (Cisco): A2A "has emerged as the syntactic layer that makes agent‑to‑agent communication reliable and interoperable." The release also covers AP2 (Agent Payments Protocol, 60+ orgs). — [Linux Foundation press release](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year)
- History: Google launched A2A in April 2025 and donated it to the Linux Foundation in June 2025. — [Google Open Source Blog, Apr 2026](https://opensource.googleblog.com/2026/04/a-year-of-open-collaboration-celebrating-the-anniversary-of-a2a.html?m=0); [CO/AI](https://getcoai.com/news/linux-foundation-adopts-googles-agent2agent-protocol-for-ai-collaboration/)
- AAIF move, August 2026: secondary sources give conflicting dates (August 17 vs August 20, 2026). Each AAIF protocol keeps its own maintainers, spec process and release schedule. — [FlowHunt](https://www.flowhunt.io/blog/agentic-ai-foundation-a2a-mcp-standards/); [Pebblous](https://blog.pebblous.ai/blog/a2a-mcp-agentic-ai-foundation-authorization/en/); [AI Magazine](https://aimagazine.com/news/why-did-googles-a2a-join-the-agentic-ai-foundation) (403 when fetched; known only from its search snippet)

**IBM ACP (Agent Communication Protocol), merged into A2A**
- ACP merged into A2A under the Linux Foundation in August 2025. The ACP repo was archived on August 27, 2025, with a migration guide. BeeAI became A2A-compliant through A2AServer/A2AAgent adapters. Kate Blair (IBM Research) joined the A2A TSC. ACP was REST-based; A2A uses JSON-RPC 2.0 plus task lifecycle. "ACP" also names Zed's Agent Client Protocol and the Agentic Commerce Protocol, which are unrelated. — [Ry Walker research note](https://rywalker.com/research/acp-agent-communication-protocol); [Tyk guide](https://tyk.io/?p=7846); [howaiworks](https://howaiworks.ai/blog/mcp-vs-a2a-vs-acp-how-ai-agents-talk) (all secondary)

**AGNTCY (Cisco Outshift)**
- Started March 2025 by Cisco Outshift with LangChain and Galileo, and donated to the Linux Foundation in July 2025. Formative members: Cisco, Dell, Google Cloud, Oracle, Red Hat. 75+ supporting companies. Uses SLIM (Secure Low Latency Interactive Messaging) for agent messaging, including quantum-safe messaging. — [The Register, Jul 2025](https://www.theregister.com/2025/07/30/agntcy_lf_donation/); [It's FOSS](https://news.itsfoss.com/agntcy-project-joins-linux-foundation); [Cisco Outshift](https://outshift.cisco.com/the-internet-of-agents/agntcy) (all 2025)
- Contradiction to flag: one search summary claimed AGNTCY became a foundational AAIF component in Dec 2025. The AAIF founding coverage names only MCP, goose and AGENTS.md (see below). Treat the AGNTCY–AAIF link as unverified.

**MCP and the Agentic AI Foundation**
- Anthropic donated MCP on Dec 9, 2025. It became a founding project of the AAIF, "a directed fund under the Linux Foundation, co-founded by Anthropic, Block and OpenAI." The other founding projects are Block's goose and OpenAI's AGENTS.md. — [MCP blog](https://blog.modelcontextprotocol.io/tags/aaif/); [The New Stack](https://thenewstack.io/anthropic-donates-the-mcp-protocol-to-the-agentic-ai-foundation/); [InfoQ](https://infoq.com/news/2025/12/agentic-ai-foundation/)
- MCP's role in agent-to-agent work: coding-agent coordination tools (MCP Agent Mail) ride on MCP as a tool surface. Agents "talk" by calling a shared MCP server's tools (send_message, reserve files) rather than through a peer protocol. — [mcp_agent_mail](https://github.com/Dicklesworthstone/mcp_agent_mail)

**MCP Agent Mail (Jeffrey Emanuel, GitHub `Dicklesworthstone`)**
- Tagline: "Asynchronous coordination layer for AI coding agents." Pitch: "like gmail for your coding agents!" and "asynchronous email + directory + change-intent signaling for your agents." — [mcp_agent_mail (Python)](https://github.com/Dicklesworthstone/mcp_agent_mail)
- Unit: GitHub-Flavored Markdown messages in searchable threads, where replies inherit `thread_id`. **Storage: "backed by Git (for human-auditable artifacts) and SQLite (for indexing and queries)"**. Messages are markdown files in a per-project Git repo, and SQLite FTS5 handles search. Advisory file reservations (leases on globs) come with an optional pre-commit guard. A web UI at `/mail` has a "HumanOverseer" composer whose messages are high-importance and bypass contact policies. Agents named: Claude Code, Codex, Gemini CLI, Factory Droid, plus configs for Cline, Cursor, Windsurf. Python repo: ~2.2k stars, 231 forks. Its README says "This Python version is no longer maintained," pointing to the Rust successor. — [mcp_agent_mail](https://github.com/Dicklesworthstone/mcp_agent_mail)
- Rust successor `mcp_agent_mail_rust`: tagline "It's like Gmail for your coding agents!" License "MIT with an OpenAI/Anthropic Rider" (per badge). ~212 stars. Features: threaded inbox/outbox with subjects, CC/BCC, acks and importance; project-wide broadcast address; advisory file leases with TTL and a pre-commit guard that blocks commits touching another agent's reserved files; build slots (acquire/renew/release); per-project Git archive plus SQLite; a 16-screen TUI, a web UI and an `am robot` CLI; a "product bus" across linked projects. Supports Claude Code, Codex CLI, Gemini CLI, Oh My Pi, GitHub Copilot CLI. Available since October 2025. The tool count is inconsistent (34 in About, 45 in README). — [mcp_agent_mail_rust](https://github.com/Dicklesworthstone/mcp_agent_mail_rust)
- Name collision: AgentMail (agentmail.to) and Composio "Agent mail" are unrelated email-for-agents products. — [Composio](https://mcp.composio.dev/agent_mail)

**OpenAI Agents SDK handoffs**
- "The SDK represents each handoff to the LLM as a tool," e.g. `transfer_to_refund_agent`. "By default, the receiving agent sees the full conversation history." An `input_filter` can trim it, and the opt-in beta `nest_handoff_history` compacts it into summary segments. "Handoffs stay within a single run." `Agent.as_tool()` is the alternative when you want a specialist without transferring the conversation. — [OpenAI Agents SDK: Handoffs](https://openai.github.io/openai-agents-python/handoffs/)

**Microsoft Agent Framework (successor to AutoGen + Semantic Kernel)**
- 1.0 GA on April 3, 2026, for .NET and Python, with stable APIs and long-term support. It unifies Semantic Kernel and AutoGen, and both are now in maintenance mode. A2A support is included for cross-runtime collaboration, but the launch post says "A2A 1.0 support [is] coming soon." Orchestration patterns: Sequential, Concurrent, Handoff, Group Chat, Magentic (handoff GA claim from secondary sources). — [Microsoft devblog](https://devblogs.microsoft.com/agent-framework/microsoft-agent-framework-version-1-0/); [Techstrong](https://techstrong.ai/features/microsoft-ships-agent-framework-1-0-a-production-ready-foundation-for-multi-agent-ai/)

### Inferences
- The interop protocols (A2A/AGNTCY) assume agents are opaque services across organizations. The unit is a Task with Artifacts, and durability is the server's business: nothing in the core concepts requires a person-readable history.
- In the coding-agent world, the "mailbox" pattern (Agent Mail, Claude Code team inboxes) dominates. Agents coordinate *about* work through messages and advisory file locks, and the work itself lands in a shared checkout. Agent Mail is the closest prior art to "durable git artifacts," but what it commits to Git is the chatter (messages), not the work.
- Frameworks hand off conversation history, not artifacts, and their handoffs are scoped to one in-process run.

### Gaps
- MCP's own agent-to-agent features (e.g. the spec's experimental async "tasks" primitive, sampling) were not fetched. The MCP spec changelog needs checking.
- CrewAI and LangGraph were not researched in this pass (budget). Their work-sharing units (CrewAI task outputs/context, LangGraph shared state plus checkpointers, LangGraph `Command` handoffs) remain unsourced here.
- The exact date A2A joined AAIF (Aug 17 vs Aug 20, 2026) is unconfirmed by a primary source.
- A2A Task history retrieval (`tasks/get`, `historyLength`) was not confirmed from the spec page fetched.
- No adoption figures were found for AGNTCY in 2026, and none for MCP Agent Mail beyond GitHub stars.

## For Claude Code and Codex native subagents: how is history stored and surfaced; background; isolated worktrees?

### Takeaway
Claude Code (Oct 2026) has four tiers. **Subagents** keep per-agent JSONL transcripts in the session directory, return a result to the parent, default to the background, can take `isolation: worktree` and can be resumed with SendMessage. **Agent teams** (experimental) use a shared task list plus per-agent JSON mailboxes. **Cross-session messaging** passes plain text between your sessions. **Background sessions/agent view** run under a supervisor and auto-move into `.claude/worktrees/`. All history is local and retention-limited (30 days by default). Codex subagents are separate "agent threads" whose results are collected into the parent's final response. They can be switched to with `/subagents` and are stored (per community references) as rollout JSONL plus a SQLite spawn-edge table. The official docs say nothing about worktree isolation for Codex subagents.

### Cited Findings

**Claude Code subagents**
- Storage, verbatim: "find IDs in the transcript files at `~/.claude/projects/{project}/{sessionId}/subagents/`. Each transcript is stored as `agent-{agentId}.jsonl`." Subagent transcripts survive main-conversation compaction ("stored in separate files"), persist within their session, and are deleted after `cleanupPeriodDays`, "30 days by default." — [Claude Code docs: Subagents](https://code.claude.com/docs/en/sub-agents)
- Return to parent: "When a subagent completes, Claude receives its agent ID." "A background subagent's results reach Claude as a completion notification in a later turn." A report arrives "under a header marking it as subagent output." Output cut off by `maxTurns` or an API error is marked partial. — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Background: "With nothing configured, a subagent that Claude spawns from your main conversation starts in the background." Ctrl+B (or "Run in background" in VS Code) backgrounds one. A `background: true` frontmatter field keeps it there. `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` forces waiting. Permission prompts from background subagents surface in the main session. — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Worktrees: the `isolation: worktree` frontmatter field runs "the subagent in a temporary git worktree, giving it an isolated copy of the repository branched by default from your default branch rather than the parent session's `HEAD`. The worktree is automatically cleaned up if the subagent makes no changes." — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Resume: "Each subagent invocation creates a new instance rather than continuing an earlier one." "Resumed subagents retain their full conversation history." Claude resumes through `SendMessage` to the agent's ID or name, which doesn't require agent teams. The built-in Explore/Plan agents are one-shot and can't be resumed. — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Other frontmatter: `model`, `permissionMode`, `maxTurns`, `memory` (persistent memory scope user/project/local), `mcpServers`, `hooks`, `skills`, `effort`, `color`. — [Subagents](https://code.claude.com/docs/en/sub-agents)

**Claude Code agent teams (experimental)**
- Disabled by default, enabled with `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`. "One session acts as the team lead... Teammates work independently, each in its own context window, and communicate directly with each other. You can also talk to any teammate directly." — [Claude Code docs: Agent teams](https://code.claude.com/docs/en/agent-teams)
- Architecture: Team lead, Teammates, a shared **Task list** (pending / in progress / completed, with dependencies, claimed under file locking), and a **Mailbox**: "Each agent's mailbox is a JSON file at `~/.claude/teams/{team-name}/inboxes/{agent-name}.json`." Team config at `~/.claude/teams/{team-name}/config.json` is removed at session end. The task list at `~/.claude/tasks/{team-name}/` "stays on disk after the session ends" (subject to `cleanupPeriodDays`). — [Agent teams](https://code.claude.com/docs/en/agent-teams)
- Surfacing: the agent panel lists teammates, and Enter opens a teammate's transcript to message it. Split-pane mode is available via tmux/iTerm2. When a teammate finishes, it notifies the lead "and includes its final answer in the notification." "The lead's conversation history does not carry over" to teammates. — [Agent teams](https://code.claude.com/docs/en/agent-teams)
- Limitations: "/resume and /rewind do not restore in-process teammates." One team per session, no nested teams, the lead is fixed, and task status can lag. Doc guidance: "Two teammates editing the same file leads to overwrites." Hooks `TeammateIdle`, `TaskCreated` and `TaskCompleted` act as quality gates. — [Agent teams](https://code.claude.com/docs/en/agent-teams)
- Trust model: a message from another agent is marked as coming from another Claude session, "can't approve a permission prompt or supply consent on your behalf." — [Agent teams](https://code.claude.com/docs/en/agent-teams)

**Claude Code cross-session messaging**
- Requires v2.1.224+ (macOS/Linux) and is on by default. "A message is a piece of text one Claude writes to another, never the sender's conversation history or files." `ListAgents` and `SendMessage` reach local sessions over a per-session Unix socket ("never through Anthropic servers"), and reach other machines and cloud sessions via Remote Control through Anthropic servers. Plain text only, with a ~1M-character cap and loop throttling. A `notify_when_idle` subscription is available. Inbound policy `crossSessionInbound` is accept/hold/refuse. Messages show as a dim preview line in the transcript (expand with Ctrl+O). — [Claude Code docs: Cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging)

**Claude Code background sessions / agent view (research preview)**
- `claude agents` opens agent view, which lists background sessions. Dispatch with `claude --bg "<prompt>"`, `/bg`, or `/fork`. "Background sessions don't need any terminal open to keep working. A separate supervisor process runs them." Idle unattached sessions are stopped after about an hour and resume on attach. — [Claude Code docs: Agent view](https://code.claude.com/docs/en/agent-view)
- Worktrees: when a `--bg` or agent-view session starts editing, "Claude moves the session into an isolated git worktree under `.claude/worktrees/`." Deleting a session through agent view removes its worktree "including uncommitted changes." — [Agent view](https://code.claude.com/docs/en/agent-view)
- History: "The conversation transcript stays on your local machine, available through `claude --resume`." Per-session state lives in `~/.claude/jobs/<id>/state.json` ("not a stable interface"; use `claude agents --json`). States: Working, Needs input, Idle, Completed, Failed, Stopped. — [Agent view](https://code.claude.com/docs/en/agent-view)

**OpenAI Codex subagents**
- Official: Codex spawns specialized agents in parallel and "The main thread collects the subagent results into its final response". This keeps "noisy intermediate output" off the main thread, and subagents return summaries. Spawning happens only when you ask explicitly, or when project or skill instructions say so (with Ultra, ChatGPT can delegate proactively). "When many agents are running, Codex waits until all requested results are available, then returns a consolidated response." — [Codex docs: Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents) (redirected from developers.openai.com/codex/subagents)
- Surfacing: each subagent has an "Agent thread." In the CLI, "Use `/subagents` in the CLI to switch between active agent threads and inspect the ongoing thread." The desktop app has a Subagents view (Active/Done) with details and results. The IDE shows a panel above the composer. The web sidebar has no stop/steer controls. — [Codex docs: Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)
- Config: `[agents]` with `enabled` (default true), `max_concurrent_threads_per_session` (`max_threads` is a legacy alias), `default_subagent_model`, `default_subagent_reasoning_effort`. Custom agents are TOML files in `~/.codex/agents/` or `.codex/agents/` (required: `name`, `description`, `developer_instructions`). Built-ins: `default`, `worker`, `explorer`. "Subagents inherit your current sandbox policy." Custom agents can't override sandbox or approval policy. In non-interactive runs, an action needing new approval fails back to the parent. — [Codex docs: Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)
- Storage (community reference, unverified): rollout JSONL at `$CODEX_HOME/sessions/**/rollout-*.jsonl`, thread metadata in `$CODEX_HOME/state_*.sqlite`, and the parent→child link in a `thread_spawn_edges` table or the rollout's first-line `thread_spawn` metadata. Depth can exceed 1. Model-callable tools are `spawn_agent`, `send_input`, `resume_agent`, `wait`, `close_agent`. — [oh-my-opencode Codex sessions reference](https://cdn.jsdelivr.net/npm/oh-my-opencode@4.18.2/dist/skills/coding-agent-sessions/references/codex.md); [codex_sdk hexdocs](https://hexdocs.pm/codex_sdk/10-subagents.md)
- Third-party reports give `agents.max_depth` a default of 1. — [Daniel Vaughan, May 2026](https://codex.danielvaughan.com/2026/05/06/codex-subagents-official-docs-reference-patterns-csv-batch/)

### Inferences
- In both tools, a subagent's history is a sidechain transcript in the tool's private home directory. What reaches the person is the parent's summary. The raw transcript is inspectable (Claude agent panel / Ctrl+O; Codex `/subagents`) but lives outside the repo and, for Claude Code, expires after 30 days.
- Claude Code has converged on "background by default plus optional worktree isolation" for both subagents and `--bg` sessions. Its worktrees are temporary and auto-cleaned when unchanged, so the git artifact is incidental rather than the handoff medium. Codex documents no equivalent for subagents.
- Agent teams' coordination record (task list, mailbox JSON) is session-scoped and not restored on resume, which is the opposite of a persistent per-Task conversation.

### Gaps
- Whether Codex subagents can run in isolated worktrees (the Codex app has a separate worktree feature for threads; not confirmed for subagents).
- The location of the Claude Code main-session transcript file was not documented on the agent-view page (likely `~/.claude/projects/...jsonl`, unverified here).
- Codex on-disk layout comes only from third-party references.

## Who is each for; adoption/traction; license; pitch language

### Takeaway
A2A is the enterprise cross-vendor standard (150+ orgs, 22k stars, Apache 2.0, LF/AAIF, integrated into Azure, AWS and Google). AGNTCY is Cisco's LF-hosted "Internet of Agents" infrastructure (2025, 75+ companies). ACP is dead, merged into A2A. MCP Agent Mail is a solo-maintainer power-user tool for running fleets of CLI coding agents on one repo (2.2k stars for Python, now superseded by Rust). Claude Code and Codex native features are for individual developers parallelizing inside one product. Microsoft Agent Framework and the OpenAI Agents SDK are for application builders.

### Cited Findings
- A2A: Apache 2.0; 150+ orgs; 22k+ stars; Azure AI Foundry, Copilot Studio, Bedrock AgentCore. — [LF press, Apr 2026](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year); [a2a-protocol.org](https://a2a-protocol.org/latest/)
- AGNTCY: Cisco/Dell/Google Cloud/Oracle/Red Hat, 75+ companies (2025). — [The Register](https://www.theregister.com/2025/07/30/agntcy_lf_donation/)
- MCP Agent Mail: Python ~2.2k stars (unmaintained); Rust ~212 stars, "MIT with an OpenAI/Anthropic Rider." — [Python repo](https://github.com/Dicklesworthstone/mcp_agent_mail); [Rust repo](https://github.com/Dicklesworthstone/mcp_agent_mail_rust)
- Claude Code agent teams pitch: "Coordinate multiple Claude Code instances working together as a team, with shared tasks, inter-agent messaging, and centralized management." Cross-session messaging pitch: "When a change in one session breaks what another is building on, Claude can warn that session before you notice." — [Agent teams](https://code.claude.com/docs/en/agent-teams); [Cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging)
- Microsoft Agent Framework: 1.0 GA Apr 3, 2026; successor to AutoGen/Semantic Kernel (both in maintenance mode). — [Microsoft devblog](https://devblogs.microsoft.com/agent-framework/microsoft-agent-framework-version-1-0/)

### Inferences
- Contrast for positioning: every system above makes the *message* or *summary* the inter-agent unit, with history in a tool-private store (Claude/Codex homes, A2A servers, Agent Mail's side repo). A system where agents build on each other through commits/PRs in the project repo, with a persistent per-Task conversation separate from the runs, occupies a gap none of these claim. Agent Mail's "Git for human-auditable artifacts" is the nearest framing to watch.
- Claude Code's own docs steer users away from teams for same-file or sequential work ("For sequential tasks, same-file edits, or work with many dependencies, a single session or subagents are more effective"), which leaves sequential build-on-prior-work flows underserved by native features. — [Agent teams](https://code.claude.com/docs/en/agent-teams)

- No usage or adoption numbers found for Claude Code agent teams or Codex subagents.
- CrewAI, LangGraph and OpenAI Agents SDK traction figures were not gathered.
