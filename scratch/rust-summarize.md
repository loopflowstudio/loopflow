# Wave Area Summaries

Summaries provide LLM context for areas of the codebase you're not actively changing.

## Design

**Summarize is just a step.** It instructs the LLM to summarize paths. No special infrastructure.

- If content is small → preload it all into context
- If content is big → don't preload, let the agent read files as needed
- The step prompt works either way

```markdown
# summarize step

Summarize these paths for LLM context. Target: {token_budget} tokens.

Focus on: data structures, public APIs, key patterns.
Format as dense markdown.

{#if preloaded}
<source>
{content}
</source>
{#else}
Read the files in these paths and summarize:
{paths}
{/if}
```

### Flow

1. Check token count of area content
2. If small (fits in context): preload content, run step
3. If large: just pass paths, let agent read what it needs
4. Cache the result (keyed by area + source hash)

### Context Assembly

When gathering context for a wave step:
```rust
fn gather_context(wave: &Wave, areas: &[Path]) -> Context {
    for area in areas {
        docs.extend(gather_diff_files(area));

        // Load cached summary (generated by summarize step)
        if let Some(summary) = load_summary(area) {
            docs.push(summary);
        }
    }
}
```

## Implementation

### What We Need

1. **Token counting** - decide small vs big threshold
2. **Summarize step** - prompt that works with/without preload
3. **Cache** - store results keyed by (repo, area, source_hash)

### What We Don't Need

- Recursive bin-packing
- Pathset caching
- Complex splitting logic

The LLM handles large content by reading files as needed.

### Trigger: GitHub Webhooks

Summarize steps run in the background, triggered by GitHub webhooks.

**Main branch:**
1. Push to main → webhook hits lfd
2. lfd detects which areas changed
3. Queues summarize step for affected areas
4. Runs in background, caches result

**Active branches:**
- Keep summaries up-to-date for branches with open PRs
- Triggered on push to branch

**Fallback:**
- Main summaries always fresh as backup
- If branch summary missing → use main's summary

Summaries stay fresh automatically. No manual invocation.
