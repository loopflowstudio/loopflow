The API cut

Draft signatures; lifecycle ownership stays in existing owners.

Choose a conversation
Current · overlapping selectors
lf session resume [ID]
lf session connect ID

Two explicit-ID entry points reach the same connection operation. Resume additionally selects the latest interactive Session when ID is omitted.

Accepted · contextual or explicit
lf session resume
lf --task ISSUE session resume
lf --wave NAME session resume

lf session connect ID
lf connect --wave infra
lf connect --task ISSUE

Use the existing shorthand lf resume. Resume accepts no Session ID. Work-target connect finds or prepares the primary conversation and opens it in its checkout, eliminating the caller's ensure/JSON/connect sequence. Both forms use one Session connection operation.

explicit Task / Wave → its Session
active Task in worktree → Task Session
main checkout → latest across repo worktrees
other worktree → latest in this worktree
resume: no eligible Session → not found

Recency uses interactive input, not background agent activity. Main does not default to the repository primary Session. Direct Work-target connect can prepare a missing primary; contextual resume does not create one.

Intent and output
Current · behavior hidden in flags
connect ID --json → prepare only
connect ID        → connect
session replace ID
connect ID --replace

JSON currently changes effects. Replace refers both to a new primary conversation and taking over an existing connection.

Accepted separation · proposed spellings
connect ID [--json]
connect ID --prepare [--json]
connect ID --takeover
session new …

Output format does not change effects. Preparation is explicit. New conversation changes identity; takeover preserves it. Task/Desktop use the same target resolver as the CLI.

Keep these paths distinct

Sharing settings does not make every operation a new launch.

Attach to a live provider

Codex live connect adds a relay/client. Preserve the running process, settings and attachment fencing. Do not restart it to apply current defaults.

Replay a historical request

Explicit replay reproduces captured AgentProcessRequest inputs. It deliberately differs from stopped-session resume, which uses current settings.

Recover within a run

Automatic harness respawn reuses the already resolved config and native continuation token. A later explicit resume resolves settings again.

Test the contract at both seams

Every option at the provider boundary; every entry at the public boundary.

Option coverage

Provider/model, YOLO precedence, Chrome, scope and writable roots, context/hooks/skills, schema and budgets, cwd, account/home, environment and identity. Test presence, absence and meaningful interactions.

Entry coverage

Fresh and resumed native Sessions, headless continuation, Task/Desktop prepared start, Flow children, live attach, replay and recovery. Use the candidate CLI and stand-in providers.

Regression that must fail first

Claude defaults to auto; Loopflow enables YOLO. Both actual terminal launch and resume must deliver the bypass flag to the provider process.

Independent assertions

Inspect provider argv, intended non-secret environment and input. Never calculate expected options with the production builder. No real account, network or display required.
