Remote authority — accepted

The initiating LF instance supplies the personal profile; the executor supplies its environment. Forwarded work uses the origin's portable personal declarations instead of implicitly merging origin and destination personal profiles.

Keep original source/scope/target/choice strength. Shipping declarations never promotes them to CLI overrides. Host-local fields and credentials come from the destination; repository/Wave configuration remains its authored source, not copied personal intent. CLI and explicit environment retain invocation semantics; no persistence of those values. Existing account/thread continuity rules remain enforced even when a new preference cannot be applied to a resumed provider conversation.

Use and retention are distinct. A remote request can use the carried profile even when saving it would overwrite an independent remote edit. Later direct remote commands use the actual saved profile. Inspection must explain the difference and the source.

Remote retention — conservative implementation choices

The desired behavior is accepted; the following mechanics resolve the remaining routine choices for implementation. No multi-writer auto-merge, universal Home or background synchronization service is introduced.

  • Retain portable authored declarations in ordinary personal config files, preserving machine-local fields. Initial absent/equal destinations can be adopted automatically. Existing differing personal preferences are preserved and exposed for explicit adoption.
  • Record last-applied portable content/revision, origin and destination identity as operational metadata. It can live in the DB; it is not another preference source.
  • Refresh on remote request boundaries only while retained content still matches the last-applied content, or already equals the incoming content. Remote deletions count as changes. Compare coherent documents/projections, not auto-merged leaf values.
  • Serialize compare-and-write; reject stale deliveries from the same origin. Another client cannot silently take ownership of an independently retained profile. Repository identity selects the correct private file across differing filesystem paths.
  • On divergence retain remote edits, expose an inspectable diff and explicit keep/replace or import action. Forwarded work can continue with its carried profile; report that persistence was not applied. Repeated identical divergence must not repeatedly prompt.
  • Offline direct work uses last saved preferences. It cannot observe undelivered edits. Existing running steps are unaffected by delivery. No automatic reverse propagation.

Catalogue portability must distinguish authored paths/connection bindings from portable references. Account ordering is atomic, not a union. A snapshot includes removals within its declared coverage; partial delivery must not look like deletion. Delivery receipts and metadata never become a resolved-settings DB override or a second writable mirror.
