What was built

Review skills (ship-review, explore, concept-review, qa, demo) now write short body-only fragments (scratch/<name>.page.html) and compile them with lf page build into one self-contained HTML file (scratch/<name>.html). Every compiled page carries the same interaction runtime: drag across text to leave a note, pick choices or answer numbered questions, and press ⌘↩ once to deliver one formatted line across every host.

How to try it: lf page build scratch/ship-review.page.html && lf page open scratch/ship-review.html

Direct action buttons (data-lf) stay separate from the reply queue: clicking opens an inline confirmation showing the operation kind and fields, executes immediately with a fresh per-confirm request_id, and replaces the button with an in-place receipt (for example, Filed b51c7c). Clicking Clear drops unsent drafts while keeping unreported receipts; when you later send queued notes with ⌘↩, a short [already ran: …] suffix rides along once so the agent does not repeat it.

How it works

The loopback carrier in lf server binds a deterministic port per server socket (yielding to an ephemeral port if occupied) with a fresh 32-byte random in-memory token, so drafts and receipts in browser localStorage survive lf install restarts while old URLs return 404:

Derives one stable port in 49152–65535 from the server socket path so browser localStorage survives server restarts. Falls back to an ephemeral port if another process holds the preferred port. Mints a fresh 32-byte random in-memory token on every start; old URLs immediately 404.

Every loopback request reuses the existing Machine WebSocket protocol (Messages<S> and service::session) behind exact Host, constant-time token, and same-origin Origin checks:

DNS rebinding defense: every request must carry Host: 127.0.0.1:<port>, otherwise 404 with empty body. Constant-time token check; the token lives only in memory and is never printed by lf server status. Browser cross-origin WebSocket defense: foreign origins cannot upgrade even if they guess a port.

lf page open routes by caller context so headless Graph steps never pop browser windows while interactive Rex, plain-terminal, and Desktop sessions land where you already work:

Explicit --host desktop|browser short-circuits before touching SQLite or placement state. Reads session.interactive from SQLite so interactive plain-terminal sessions (Ghostty/iTerm/Terminal) open the browser instead of falling into PrintQuiet. Headless agents (session.interactive == false) always print the URL quietly, even if LF_DESKTOP is inherited. Interactive agents outside Desktop (Rex, tmux, or plain terminal) open the loopback URL in the browser.

In Loopflow Desktop, TaskFileReadingView attaches TaskHTMLBridge (a reply-capable WKScriptMessageHandlerWithReply named loopflow), while side-by-side HTML diffs in ReviewRenderedView leave it unset so historical commits stay read-only:

Swift owns page draft state keyed by (path, build_id); Desktop never touches localStorage, so peer-Machine pages on about:blank work cleanly. Peer-Machine pages swap the stamped remote checkout path for Desktop's local repository directory before forwarding to ServerClient.rawOperation.

ReviewComments stores page drafts alongside line-anchored Diff comments, skips line reconciliation for .page anchors, and retains receipts marked reported: true when sending succeeds:

A rebuild bumps build_id and automatically drops stale drafts and items from the earlier build of the same path. Sending clears unsent drafts, keeps receipts marked reported: true so remounted pages keep "Filed …" in place, and bumps pageClearGeneration.

Trade-offs and invariants going forward

  • Any Machine Operation is allowed over the loopback WebSocket (no allowlist), guarded by the 32-byte in-memory token, exact Host check, and same-origin Origin check. page.url and mobile.* remain local-Unix-socket-only, and no /ticket route is exposed on loopback.
  • The loopback token lives only in memory, while the port stays stable per server socket. Restarting lf server rotates the token (old URLs 404; open tabs show Loopflow server disconnected — run lf page open <path> and fall back to clipboard copy), and reopening via lf page open lands on the same browser origin so localStorage drafts and Filed … receipts survive lf install.
  • Task pages always steer via task.steer, never the building worker's session.steer. Headless Graph workers exit after building the page, and session.steer silently queues onto finished Sessions; task.steer reaches the Task's active work or primary interactive Session and returns delivery.sentence.
  • Desktop never touches localStorage for review pages. ReviewComments owns draft and receipt state keyed by (path, build_id), preventing SecurityError on peer-Machine about:blank pages and preventing note resurrection after sending from another file.
  • *.page.html sources are excluded from is_scratch_page in both Rust (ops/task/find.rs) and Swift (TaskFilesStore.swift), and lf page open refuses raw .page.html files with the exact lf page build command.
  • Opening beside Rex uses the OS default browser. Rex currently exposes no browser block (onboarding, terminal.shell, tunnel) and agent-browser is not installed on this Machine.
  • Not clicked through live in Dev Desktop yet. Chrome QA exercised the loopback carrier, notes, choices, receipts, disconnects, restarts, and offline copy end-to-end; the Desktop bridge was verified by headless Swift tests (TaskFilesTests, ReviewDiffTests, ServerClientTests) because QA ran headless on a Machine in use.

Findings

lf page open currently opens the OS default browser when invoked beside Rex because Rex has no browser block type and agent-browser is not installed here. Adding a dedicated browser split or agent-browser host once that surface exists is a separate outcome.

After ⌘↩, the browser strip prints the server's delivery.sentence verbatim, e.g. Saved de2b2b3a-…; nothing reads it until c56843 runs. That string comes from server steer presentation outside the page kit.

Two tabs opened on the same page share localStorage, so a receipt filed in one tab shows in the other only after reload rather than via a live storage event listener.
