1. What was built

When concept-review finds any in-scope code or test mismatch—even a small one—realign no longer patches code or tests inline and advances straight to compress and ship-review. Instead, it writes the fix into scratch/plan.md and returns iterate, so build runs sync → implement → concept-review → realign again and rewrites scratch/concept-review.html against the corrected code before advancing.

In the same change, realign keeps inline fixes for clear user-doc mismatches under docs/ and README.md (per your explore Q2 b answer), non-deciding runs (plan, refresh, standalone) leave code and tests alone and emit no loop verdict, and the shared loop-decision prompt yields to a skill's own loop rules so realign's small-fix iterate rule and optimize-plan's reverted-trial rule both win cleanly over the generic defaults.

How to try it: lf -b -a claude:haiku realign in a branch with a seeded scratch/concept-review.html (one code mismatch, one stale README.md, one separate outcome) — see the full outer-loop fixture in .lf/qa/skills.md.

2. How it works

realign.md replaces the old "fix small, clear mismatches in code, tests and docs yourself" rule with a clear split: fix plan + clear user-docs mismatches under docs/ or README.md inline, queue every other in-scope fix for implement, and return iterate when deciding a loop until no implementation work remains. QA also caught two non-deciding runs naming verdicts in replies/plans and tightened line 47 so only a step told it decides a loop names a verdict.

Honors explore Q2 b: inline fixes limited to plan plus clear docs/ and README.md mismatches. Queues even small code or test fixes for implement so concept-review runs on the final code. Added during QA after standalone and non-deciding runs wrote "Verdict: iterate" into plan.md.

DECISION_CRITERIA previously told every decider to iterate only for a "substantial next pass" and block when passes "shrink into small increments", which directly fought realign iterating on a single small review fix. It now defers to the skill's rule for the case at hand first, keeping the shared non-convergence / no-progress blocked stop as the default when a skill does not override it (so optimize-plan's reverted-trial rule keeps working too).

Skill rules take precedence over defaults for both progress (realign small-fix iterate) and stops (optimize-plan reverted trials).

  • Q2 b inline user-docs exception (narrowed to docs/ and README.md): Built to match your explore Q2 b answer, while keeping skills, goldens, AGENTS.md, .lf/qa/, and code comments routed through implement.   • DECISION_CRITERIA scope: Changing output.rs was outside the original prompt-only brief, added during Pass 2/3 because the runner's own generic "substantial next pass" / "small increments" wording contradicted realign iterating on small code fixes (and Pass 2's first wording contradicted optimize-plan).

  • Post-loop steps: compress and qa still run after the review loop and can edit code; review freshness guarantees that fixes queued by realign are re-reviewed before compress, not that concept-review re-runs after qa.
