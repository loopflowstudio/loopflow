# Subscription account policy — checked 2026-11-15

Question: whether public discussion of subscription balancing establishes a tacit policy of tolerating use while discouraging promotion. No public non-enforcement commitment found. Enforcement frequency cannot be estimated from surviving projects or self-reported account histories.

## OpenAI

- [Sign in with ChatGPT Terms](https://openai.com/policies/sign-in-with-chatgpt-terms/), effective November 4, 2026, §3.1 (ChatGPT Plan scope): apps must not enable or encourage “Creating multiple accounts, splitting usage, rotating accounts, or otherwise bypassing usage limits.” The next bullet prohibits pooling/transferring/reselling/gifting/sharing plan usage or Authentication Tokens, subject to permitted token handling. This is an explicit developer restriction for this integration, not a blanket ban on owning several accounts.
- [Accounts and sessions](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions): explicitly documents multiple saved account registrations and a user-facing picker. Credentials and client registrations remain separate. Multi-account support and the above restriction coexist.
- [Terms of Use](https://openai.com/policies/terms-of-use/), published January 1, 2026: prohibits credential sharing and circumventing rate limits/restrictions or protective measures. Exact application to a local tool launching native Codex across personally paid accounts is not resolved by the more specific SIWC clause alone.
- [Card and device limits](https://help.openai.com/en/articles/20001559-understanding-card-and-device-limits-in-chatgpt), page reported updated 16 days ago: purchases and subsequent paid-account use may be blocked; signing out does not necessarily make another account eligible. No numerical limit supplied. This establishes technical enforcement of account/device restrictions, not a measured ban rate for balancers.
- [Using ChatGPT plans in other apps](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites): participating apps can use plan allowance through supported consent/control flows. Third-party subscription use is not categorically forbidden.

## Anthropic

- [Claude Code authentication](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts): explicitly documents multiple simultaneous logins through separate `CLAUDE_CONFIG_DIR` directories, using work/personal as the example. Does not expressly approve automatic rotation across many paid subscriptions to extend one workload.
- [Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use): restricts developers offering Claude.ai login or routing through consumer subscription credentials for users; also says developers may not collect/store/intermediate Claude.ai credentials/session tokens. Explicit carve-out lets end users sign into unmodified Claude Code with their own subscriptions, including when hosted under the stated commercial conditions. Enforcement may occur without advance notice.
- [Usage Policy](https://www.anthropic.com/legal/aup), effective November 12, 2026: multi-account evasion of detection/product guardrails and ban evasion prohibited. Does not precisely classify ordinary automatic rotation among separately paid accounts as a category. Do not substitute an inference for that missing clarification.
- [Consumer Terms](https://www.anthropic.com/legal/consumer-terms), effective October 8, 2025: credentials cannot be shared; automated access requires an API key or explicit permission; bypassing protective measures prohibited. Native Code/headless usage has more specific guidance.
- [Agent SDK help](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan): October 7 update says signed-in SDK and `claude -p` usage still draws from subscriptions; June 15 update paused the announced SDK billing change and includes third-party apps. This limits any claim that all third-party automation is prohibited; it does not approve arbitrary OAuth proxies or quota pooling.
- [Login help](https://support.claude.com/en/articles/13189465-log-in-to-your-claude-account): directs developers to API keys, prohibits client misrepresentation and third-party subscription traffic; supports account switching. Read alongside the native Code and SDK carve-outs, rather than treating any one sentence as universal.

## Implication for the extraction proposal

An account picker/native launcher and an automatic subscription pool are distinct behaviors. A separate package does not alter the provider restrictions. Current credential capture, copying, refresh and direct OAuth usage polling need review independently of whether inference goes through native Code. OpenAI's supported app OAuth path provides a route for third-party plan access, with express restrictions on pooling. No production code changed and no provider contacted.
