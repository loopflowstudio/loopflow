# Why `lf transport` became public, and why its launch did nothing

## What failed

On 2026-10-20 at 03:50 UTC, an agent working for Jack wanted a detached autonomous worker.
It found `lf transport start` in `lf help --all` and ran:

```
lf transport start -- lf pursue --wt ci-path-filters "Speed up CI for docs-only changes…"
```

It printed a Process ID and nothing else happened. The agent then reported "nothing in lf
history" and switched to a Claude Code background agent. Jack never designed `lf transport`
as a public command and doesn't want it in the API.

**Recovery:** no side effects. The CI path-filter work continues in the agent's own
worktree. This branch removes the public command group.

## Causal chain

1. **The command failed in about 2s.** Ledger rows (installed lf 0.14.7, `~/.lf/loopflow.db`):
   `58d2f213 transport start` → `1a885ccc transport serve` → `5bfdccca lf pursue` →
   `0cc35385 transport serve` → `520ad563 lf pursue`, which failed with
   `no worktree found for 'ci-path-filters'`. `--wt` only selects an existing worktree.
   - Side finding: the nested serve→pursue→serve chain is the double delegation that #1604
     (LOO-522) fixed. That fix is not installed yet. It doesn't explain this failure.

2. **The agent never saw the error.** `transport start` returns as soon as the owner
   acknowledges, before the command runs. Without `--terminal` and without a viewer, the child's
   stderr goes to the owner's in-memory buffer and is lost when the owner exits.
   `transport.log` only receives the owner's own stderr, and it is empty. The ledger does record
   the error, but `lf history list` is newest-first and its first page was all
   `__context-block --moment tool` hook rows. The agent's claim of "nothing in lf history" was
   wrong, but the data really was hard to find.

3. **The agent reached for `transport` because it was listed and read like a launcher.** The
   description says "Start an independently owned command and print its Process identity".
   The agent didn't know the usual path, which is `lf pursue` in a new cmux workspace with `-a claude`.

4. **#1581 (LOO-415) shipped the owner's re-exec entry as an ordinary visible command group.**
   The detached owner needs a CLI entry because `transport::start` re-runs `lf … serve`. That
   entry came with `start` and `attach` as general-purpose subcommands. `transport_tests.rs` drove
   the owner through them, so the public surface carried test weight, which is production
   shaped for tests. The repo already has a convention for internal entries
   (`__context-block`, `__planning-check`, `#[command(hide = true)]`) and it wasn't used. The
   PR's "What changes" section listed `lf session attach` but not the `transport` group.

5. **Nothing makes a new command visible at review.** `docs/lf-reference.md` is regenerated by
   hand (`scripts/generate_cli_reference.py`) with no check. `transport` first appeared there in
   #1589, a day later, inside an unrelated PR. The reference had already drifted again
   (`--agent` help text). PR descriptions come from intent, not from the compiled CLI tree.

## Done on this branch

- Removed `lf transport start|serve|attach`. The owner entry is now the hidden
  `lf __transport-serve`, matching the other internal entries. `transport::attach` is
  crate-private and reached only through `lf session attach` and Session launch.
- `transport_tests.rs` starts the owner through `__transport-serve` and attaches through
  `lf session attach` against a fixture Session row. All 10 tests pass.
- Delegation lookup (`process_input`) and its fixture match `__transport-serve`. Rows from
  0.14.x binaries (`"transport","serve"`) no longer match. That only matters for a routing step
  that is in flight across the upgrade, which is accepted under "no slow rollouts".
- Updated the transport README, the architecture reference and the regenerated `docs/lf-reference.md`.
  The shipped release notes are left as they are.
- **CLI-tree changes are visible in PRs.** The `cli_reference` integration test fails when
  `docs/lf-reference.md` differs from the compiled Clap tree (`UPDATE_CLI_REFERENCE=1` rewrites it),
  replacing the hand-run `scripts/generate_cli_reference.py`. The repository `pr-message` skill
  lists added and removed `## lf …` headings under "What changes". This gives visibility, not a gate.

## Proposed (not approved)

- **Hide `__*` hook commands from `lf history list` by default.** They crowd out real commands, as
  they did in step 2. Proof: a fixture with 60 hook rows and one failed command shows the failure
  on page one.
- **Teach the launch path where agents look.** If agents are expected to start autonomous workers,
  the work skill should name the command (`lf pursue` in a new cmux workspace, `-a claude`).
  That is a decision for Jack.
