# W2-140 — Project Session successors

## Contract

- A terminal Project Session is history, not the permanent owner of its Linear
  Project.
- Pursuing the Project again creates one successor with a fresh pinned execution
  context; concurrent Project and Task launches converge on that row.
- A non-terminal Session remains the single current owner and is resumed rather
  than replaced.
- Status resolves the newest Session, while an explicit Session id still reads
  historical state.

## Shape

Remove the table-level `project_id` uniqueness constraint and replace it with a
partial unique index over non-terminal statuses. Reservation then becomes an
ordinary insert race: one caller wins; losers reread and adopt the winner.

The migration is `0.11.002` because the in-flight multi-PR Task work owns
`0.11.001`. This PR must not land before that migration is on main.
