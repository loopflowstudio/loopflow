# W2-146 — See and control all current and available work from the Mac

## What already exists (base 8122ee3d)

The shared contract this task depends on has already landed. This is a
**pure Swift consumption** task; no new Rust, no new wire DTO.

- `lf roadmap --json` → `RoadmapSnapshot` (Rust `waves.rs`, fixture
  `tests/fixtures/dto/roadmap_snapshot.json`). Machine-wide, daemon-less,
  renderable with zero processes running. Every Wave's plan joined to live
  Session evidence, bucketed by `RoadmapSection` (`now | needs_attention |
  available | later`). Each Task row carries the three orthogonal facts already:
  `task.completed` (PM), `runtime.status` (Session), `runtime.process_alive`
  (liveness), plus `next_move`, `active_pr`, `reference`, `section`. Carries
  `generated_at`.
- `RegistryQuery.roadmap()` → `RoadmapSnapshot`, and `RoadmapView`
  (`swift/LoopflowMac/Views/RoadmapView.swift`, PR #904) renders the **ROADMAP
  tree** (Wave › Project › Task) with per-Task Start/Attach/Resume/Interrupt +
  Worktree + PR link, and a per-Wave Start/Open button. Mounted in `WavesView`
  as the default detail when no Wave is selected.
- Home contract is fully built: `WaveHomeDto` (static address+owner+location,
  on every `WaveSnapshot.home`), `HomeRuntimeDto` (`home, state, reason,
  endpoint, action`), `HomeState` (`unreachable | stopped | running | unknown`),
  `HomeActionDto` (`attach{endpoint} | start{home} | reason{message}`). CLI:
  `lf home probe|start --json`; Start is idempotent (`started` vs already
  running) and returns the runtime with the attach `endpoint`. `lf status
  <wave> --json` already carries `home_runtime` for the focused Wave.
  Swift decode types `HomeRuntime`/`HomeState`/`HomeAction` and
  `RegistryQuery.status(wave:cwd:)` already exist.

So the roadmap read, the tree shape, the Home DTOs, and the Home readers are
done. What is missing is the **second shape (flat NOW)**, the **lens** between
them, the explicit **three-channel row + greyed-with-reason** discipline, and
**Home control wired onto the Wave/product row** (state distinction + the one
contextual action running on the configured Home, not the UI machine).

## User-visible outcome

From the Mac, with zero wave processes running, a user sees **all current and
available work across every wave in one surface** and can act on it:

- A **lens toggle: NOW ⇄ ROADMAP**, both derived from one `lf roadmap` read.
  - **NOW** — flat, cross-wave list grouped by attention: *Ready for review,
    Needs input, Working, Stopped, Failed*, ordered oldest-first within each
    group. Rows carry wave/project as context text, not as nesting. This is the
    "what needs me right now" view.
  - **ROADMAP** — the existing Wave › Project › Task tree (already shipped).
    Projects show KR proof + section badge; waves show residency + section.
- `generated_at` is always on screen (both shapes) so staleness is visible.
- Every work row shows **three orthogonal facts on independent channels, never
  collapsed into one word**: PM completion, Session status, process liveness.
  A **Stopped** row (dead process, non-terminal Session) stays **attachable and
  resumable and says why it stopped** — a dead process is not a dead task.
- **Ineligible rows are greyed with the reason attached, never hidden.** One
  hiding mechanism only; nothing silently disappears.
- Each Wave/product row shows its **Home address** and, when focused, its Home
  **state** (unreachable / unknown / reachable-but-stopped / running) with the
  **one contextual action**: *Attach/Open* when running, *Start on <home>* when
  reachable-but-stopped, an *actionable reason* otherwise. Start runs on the
  **configured Home**, not the UI machine, is idempotent, and returns the
  resident identity used to attach.

Not a kanban board. No drag. No Mac-only availability model — availability is
the **absence of a Session** (`runtime == nil`, `section == available`), read
straight off the shared snapshot.

## End-to-end proof

One scenario crossing the source of truth and every consumer:

1. With the product wave stopped, launch the Mac app. The default surface shows
   **NOW** with cross-wave rows. A Task whose PR is open appears under *Ready
   for review*; a Task whose process died mid-flight appears under *Stopped*
   with its `reason` and an enabled **Resume**; a filed-but-unstarted Task
   appears greyed under *Available* with "not started" as the reason.
2. Flip the lens to **ROADMAP**: the same Tasks appear in the Wave › Project ›
   Task tree under their section badges. `generated_at` matches in both.
3. On the product Wave row, the Home address renders. Focusing it shows state
   `running`/`stopped`/etc. and the single action; clicking **Start on <home>**
   for a reachable-but-stopped Home starts the resident **on that Home** and the
   action flips to **Attach**.

## Source of truth

- **Work plane:** `lf roadmap --json` → `RoadmapSnapshot`. Single read; both
  shapes are pure projections over it. NOW's attention groups are derived on the
  Swift side from **shared fields only** — `section`, `next_move.owner`,
  `runtime.status`, `runtime.process_alive`, `active_pr`, `task.completed` — as
  a tested pure function. No new lifecycle state, no second query.
- **Home plane:** static address from `RoadmapSnapshot`'s `wave.home`;
  live state + action from `lf home probe --json` / `lf status <wave> --json`
  (`home_runtime`). Start via `lf home start --json`. The app never does SSH.

## NOW attention bucketing (the one derivation this task adds)

A pure `func nowGroup(_ task: RoadmapTask) -> NowGroup` over shared truth:

- **Ready for review** — `active_pr != nil` and not merged, or
  `next_move.owner == .review`.
- **Needs input** — `next_move.owner == .human`.
- **Working** — `runtime.process_alive == true` and
  `runtime.status ∈ {starting, running}` (i.e. `section == now`).
- **Stopped** — `runtime != nil`, `process_alive == false`,
  `runtime.status ∈ {created, waiting, blocked}` (non-terminal) — attachable/
  resumable; carries `runtime.reason`.
- **Failed** — `runtime.status == failed` (or interrupted), process not alive.
- Everything else (no runtime, or terminal completed/abandoned, or
  `section == available/later`) is **not** a NOW row: filed/available Tasks and
  done work belong to ROADMAP. NOW is the live+stuck frontier.

Ordering: oldest `status_at` first within each group (age-first, matching the
Claude Code agent view / Conductor pattern the directive cites). This mapping is
Mac presentation over shared fields; if CLI later wants the same flat view it
reuses the identical predicate — it is not a parallel session model.

## Affected surfaces and consumers

- **Swift (this task):**
  - New: flat NOW view + lens toggle (`WorkLens { now, roadmap }`) hosted where
    `RoadmapView` is today; NOW-group derivation + tests; three-channel row cell;
    greyed-with-reason styling; `generated_at` header in both shapes.
  - Change: Wave/product card consumes Home runtime — show address always;
    on focus read `home_runtime`; render state + single action; Start calls
    `lf home start` (configured Home) instead of `LocalWaveAgentLauncher
    .launchWave` (UI machine) for remote Homes; Attach uses the returned
    `endpoint`.
  - Delete: `RegistryQuery.backlog()` and `BacklogItem` — availability is the
    absence of a Session, not `!completed` over `lf pm show`; the title-match
    join it documents is wrong and it has no production callers. Remove its unit
    test (`RegistryQueryTests.backlogDecodesOpenTasks`).
- **CLI/wire:** unchanged. `lf roadmap`, `lf home`, `lf status`, and the
  fixtures are the contract; this task only reads them. Any gap that forces a
  wire change is out of scope and gets kicked back to W2-144/W2-88.
- **iOS:** out of scope this task (Mac surface). The NOW-group predicate lives
  in `Loopflow` (shared package) so iOS can adopt it later without a re-derive.

## Absent and error states

- Roadmap read fails → keep the last snapshot, show the failure banner
  (existing `RoadmapView` pattern); never blank the surface.
- A Wave with no local PM snapshot → `projects: unavailable(reason)` renders the
  reason inline (existing), and contributes no NOW rows.
- `runtime == nil` → the Task is Available/unstarted, greyed with "not started",
  never shown as a dead process.
- Home probe fails or Home unreachable/unknown → state renders as such with the
  `reason` action; address still shows (it is a property of the Wave, not of
  reachability). Home runtime is **not** eagerly probed for every row — only for
  the focused/expanded Wave (SSH cost), matching `lf status`.
- Empty registry / empty NOW frontier → `ContentUnavailableView` ("Nothing needs
  attention"), distinct from a failed read.

## Operational boundary

- One `lf roadmap --json` spawn per refresh (~15s poll, existing cadence),
  distributed to both shapes — **not** an `lf pm show`/`lf status` fan-out per
  wave. NOW derivation is O(tasks), pure, off the render path.
- Home runtime probe is on-demand per focused Wave, never N SSH probes across
  the flat list.

## Exclusions

- No kanban/board, no drag. No new Rust or wire DTO. No SSH in Swift. No
  Mac-only session lifecycle or availability model. No iOS surface. No changes
  to how a Task is launched/resumed/interrupted beyond routing Wave **Start** to
  the configured Home. Live pubsub/SSE streaming of the roadmap stays out (poll
  refresh is the contract here).
