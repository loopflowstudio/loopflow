The CLI your agents use to get work done.

lf is the command you type and the CLI your coding agent uses. What you ask for becomes Tasks that run in the background, every agent starts where the last one left off, and no conversation is ever lost.

Give your agent the skill

$ npx skills add loopflowstudio/loopflow --skill loopflow -g -y

or install the CLI

$ curl -fsSL https://loopflow.studio/install.sh | sh

Everything your agents need to build on each other’s work.

Work

Say what you want. It becomes Tasks that run without you.

Your agent turns each piece into a Task with its own worktree, branch and pull request, so ten requests come back as ten PRs you can review one at a time.

$ lf task create --title "rent CPU pods"
$ lf -b task run ETU-14

Context

Every agent starts where the last one left off.

Each launch carries the Wave’s memory, the Task’s notes in scratch/, the docs you name and any new comments, and gets them back after compaction.

$ lf comment ETU-14 "smallest pod by default"
$ lf gate --docs docs/runpod.md

Orchestration

Work finishes while you’re doing something else.

Runs go to the agent and machine you pick, Graphs carry them step to step, Waves keep their Tasks moving, and landing repairs CI until the PR merges. Get as much as possible off the main thread: plans into code, code into verified code.

$ lf --machine mini -b -a codex graph pursue
$ lf land --wait-and-fix

Sessions

You never lose a conversation.

Every conversation outlives its terminal, and new work starts on whichever of your logins has room. Close the window and come back next week; the conversation and what it knows are still there.

$ lf resume --task ETU-14

Skill Graphs: write down how you work.

Skills are Markdown and Graphs are YAML, files in your repository reviewed like code.

Loopflow ships reasonable workflows for software engineering, and they are templates. Copy one with lf graph customize pursue, change it, or write down the way you work and share it.

$ lf audit                 # run one Skill
$ lf -b graph ship-api     # run the Graph headless

Write a Skill ↗Graphs ↗

<!-- .lf/skills/audit.md -->
Audit auth changes on this branch. Fix missing
validation and untested paths.
# .lf/graphs/ship-api.yaml
- design      # leaves scratch/<task>.md
- implement   # leaves commits on the branch
- audit
- gate        # leaves passing checks

Use what you like and skip what you don’t. The launcher needs no Task and no Linear: lf : "fix the flaky retry test" starts one agent, like starting it yourself.
