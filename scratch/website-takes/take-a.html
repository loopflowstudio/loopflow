The CLI your agents use to get work done.

Tell your coding agent to use lf. It hands the work to background runs, each on its own branch, and stays in the conversation with you, free to answer, change course, or stop a run mid-step.

Give your agent the skill

$ npx skills add loopflowstudio/loopflow --skill loopflow -g -y

or install the CLI

$ curl -fsSL https://loopflow.studio/install.sh | sh

One conversation in Claude Code. It never did the work itself, so it was free when you changed your mind, and nothing was lost when a run died.

Every phase has a contract.

A phase is a Skill: a Markdown file in your repository that says what to do and what to leave behind. A Graph puts phases in order. Workflows say where you come in.

Nothing important lives only in an agent’s context. Each phase leaves its result on disk, so when an agent stops, the next one starts from there: work that outlives your agents.

Write a Skill ↗Graphs ↗

# .lf/graphs/ship-api.yaml
- design      # leaves scratch/<task>.md
- implement   # leaves commits on the branch
- gate        # leaves passing checks
- ship        # leaves a pull request

And when it’s more than your agents: your team’s.

The same Tasks your agent files are the plan your team reads, in Linear or a shared Git ref. One owner, one worktree, one PR each, so nobody’s agents take the same work.
