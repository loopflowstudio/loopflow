Take C · hand it to your agent

Ask your agent if you should use lf.

It’s the CLI agents use to launch subagents and get work done. The docs are written for your agent to read.

Paste this into Claude Code, Codex, OpenCode or Pi

Read loopflow.studio/llms.txt. Should we use it here? If yes, try it on one small change.

What you get

Your agent stops doing everything in one conversation.

It files a Task for each piece, starts a subagent on each one in its own worktree, and comes back with pull requests. When one stops partway, another picks it up from the branch.

You get asked at the points you chose: the design, the demo, both or neither.

What your agent reads

# Loopflow
lf launches Claude Code, Codex, OpenCode or Pi
as subagents, each in its own git worktree,
and records what they did.

## Try it
lf -b implement "fix the flaky retry test"
lf pr publish

## Needs
macOS or Linux · git · a signed-in agent CLI
gh for pull requests · Linear optional

## Touches
~/.lf · .lf/ · scratch/ · worktrees beside the repo
your own provider login · no hosted server

## Not built yet
Asana and Notion planning

What it’s likely to say.

“Yes. It’s a CLI that launches me and other agents as subagents, each on its own branch, so a failure doesn’t lose the work. It works with the Claude Code you already have. The smallest test is one background run on the flaky retry test; it takes a few minutes and leaves a PR you can close. Worth trying.”

Then bring your team.

Tasks your agent files are a plan your team shares, through Linear or a Git ref.
